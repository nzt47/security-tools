## 2. 递归自进化：机制拆解、风险矩阵与护栏设计

### 2.1 机制拆解（Gödel Agent 四步循环）

原版 Gödel Agent 将自身代码视为可修改对象，通过四步循环实现运行时自改写（实证来源：arXiv:2410.04444）：

1. **内省（self_inspect）**：读取自身代码（含"自我修改算法"源码）与历史性能数据；
2. **交互（interact）**：以当前策略与环境交互，通过效用函数获得反馈（适应度评估）；
3. **自更新（self_update）**：LLM 直接生成新的 Python 代码（或 Prompt 逻辑），通过 monkey patch 在运行时内存中替换旧代码；
4. **递归进化（recursive improvement）**：更新规则本身也成为优化对象，进入下一轮循环。

其理论源头 Gödel Machine（Schmidhuber 2003）要求"每次修改前先证明该修改能提升全局效用"——该证明机制对通用程序在有限时间内不可实现（论文主张），故工程上退化为"高概率确信"的 LLM 生成+补丁替换。

**注意**：设计思路原文描述的 `π_{t+1}, I_{t+1} = I_t(π_t, I_t, r_t, g)` 公式即指更新规则 I 本身也在进化（元规则级递归）。这是本报告红线划分的核心对象。

**四步循环 × 云枢评估**（把每一步翻译为云枢语境下的可行/不可行判据）：

| 步骤 | 原版机制 | 云枢语境 | 评估 |
|---|---|---|---|
| 内省 self_inspect | 读取并分析自身代码 | 读取版本化策略工件（Skill/工作流/规则/经验）与 T03 KPI 快照 | 可行（读操作，零风险） |
| 交互 interact | 策略与环境交互、效用反馈 | 主链路执行 + feedback + T02 反思评估信号 | 可行（即现有闭环） |
| 自更新 self_update | LLM 生成代码、monkey patch 替换 | 更新策略工件（bump_version 快照）+ 强制审核链 | 可行（L2，T04/T05 管道）；替换代码=禁止（L1） |
| 递归进化 recursive | 更新规则本身再被优化 | 更新规则的变更同样走版本化+门控（G1） | 远期红线（L3），本报告不给实现建议 |

### 2.2 云枢约束下的可行性：三层翻译

云枢约束（D2D3 文档 §1.2 已列 C1-C5）：模型权重不可变、成本敏感、配置驱动可回滚、已有资产必须复用、主链路零退化。据此把"递归自进化"拆为三层，逐层判定：

| 层 | 内容 | 云枢判定 | 依据 |
|---|---|---|---|
| L1 代码级自改写 | LLM 生成并替换自身 Python 代码（monkey patch） | **不可行（禁止）** | 违反可审计/可回滚（代码与仓库漂移）；API 型 LLM 无法持有"可写代码体"；违反 TASK-08 不变式"禁止自我改写决策逻辑的实现建议" |
| L2 策略工件级自进化 | 更新外部策略工件：Skill 参数、工作流模板、规则阈值、反思经验（版本化+门控） | **可行（近期主线已覆盖大半）** | `offline_evolver` 帕累托进化（参数级）+ `workflow_learning` 在线更新 + TASK-04/05 沉淀管道 = 云枢版"最小自进化闭环"；`run_evolution_demo.py` 已演示其批量流程 |
| L3 元规则级递归 | 更新"如何更新"的规则本身（进化策略、评估阈值、变异权重） | **远期研究红线** | 需 §2.4 全部护栏 + §5.2 触发条件满足后才评估；本报告不给出实现建议 |

**项目内既有参照（阶段四·反身智能）**：`docs/zh/阶段四_整合与反身智能.md` 早于设计思路即提出"执行-暂停-反思"元认知循环与权限边界系统（危险操作二次确认、操作黑名单、操作前备份）——本报告护栏 G2/G4 与之同构，属"延续既有工程原则"而非新增激进能力。

**外部现实参照（报道级）**：肖仰华团队"政务龙虾"的 EvoLoop 采用"白天干活、晚上复盘"——夜间只做知识层面整理（SOP 沉淀、策略优化），不执行任何实际操作（来源：深圳特区报访谈，见 §7）。该模式与云枢 TASK-05"dry-run 默认 + 观察模式"完全同构，可作为"自进化只动知识、不动执行"的行业佐证（报道级，非实证）。

## 3. MAE 三角色：成本模型与云枢化降级

### 3.1 成本模型（3 次 LLM/轮 → 实际更高）

- **设计思路口径**：每轮学习 3 次 LLM 调用（Proposer 出题、Solver 解题、Judge 评判）。
- **原版 MAE 实际口径（实证：arXiv:2510.23595）**：Proposer 每出一道题，需 Solver 产出 `N_sample` 个答案求平均难度（论文用多采样），每个答案再经 Judge 评分 → 每轮实际调用 ≈ `(1 + N_sample + N_sample)` 次/题；若取 N_sample=4，即 9 次/题，且全部发生在 RL 训练迭代中（还需多轮）。
- **云枢口径说明性估算（推断，非引用外部数据）**：假设每周评估 P 道任务、每次调用平均输入 1-2k token + 输出 0.5-1k token，则周成本量级为 P×(1.5k~3k)×3（单采样）至 ×9（多采样）token。对照 `configs/models.yaml` 的 `cost_limits`（目前仅声明、无强制钩子，主文档 §3.2 D5）——**无预算护栏时成本不可控**。

**一个说明性工作示例（推断级，仅用于量级感受，不构成决策依据）**：

| 场景（P=20 题/周） | 每次调用 token 中值 | 调用次数 | 周成本量级 |
|---|---|---|---|
| 单采样（1 解 1 判） | ~2k | 3×20=60 | ~1.2×10^5 token |
| 多采样（N_sample=4，MAE 原版风格） | ~2k | 9×20=180 | ~3.6×10^5 token |
| 加 RL 迭代（原版需多轮训练） | ~2k | 逐轮累加 | 上不封顶 |

> 结论：即使按最乐观口径（单采样、周 20 题），LLM 型三角色评估的周成本也已达到 `10^5` token 量级；若叠加原版 RL 训练迭代，成本无自然上界——这正是"先建预算护栏（TASK-03），再谈引入"的唯一理由。

**结论**：MAE 三角色的"评估价值"可以保留，"训练成本"必须剥离。任何引入都必须先有 TASK-03 `learning.budget` 熔断（默认 warn_only，enforce 才拦截，守"上线即改行为"风险）。

### 3.2 云枢化降级方案（三角色映射到现有资产）

| MAE 角色 | 原版职责 | 云枢化降级实现 | 现状/归属 |
|---|---|---|---|
| Judge（评判者） | 对题目与答案打分，提供奖励信号 | 现有规则评估（零 token）：`ReflectionEngine` 6 维规则 + `feedback.py` 反馈闭环 + `reviewer` 三重审核 + TASK-07 输出验证门控；**LLM-as-Judge 仅作接口预留**（复用 `critic.py` RULE_BASED/LLM_DRIVEN 双模式惯例），默认规则路径零额外 token | `agent/cognitive/reflection.py`（休眠，TASK-02 保守接线）；TASK-07 输出验证器 |

### 3.3 引入门槛（依托 TASK-03 KPI）

> TASK-03 7 项 KPI 编号约定：KPI#1 token 复用率；KPI#2 Skill 命中率；KPI#3 工作流命中率；KPI#4 分类型失败率；KPI#5 反馈均分趋势；KPI#6 沉淀增量；KPI#7 进化采纳率。

## 4. 课程学习与生成式世界模型：云枢化降级

### 4.1 课程学习 → 难度自适应（对齐 D6）

- **原主张**：借鉴"衔远大观"平台——学习环境根据智能体当前水平自适应调整难度，通关简单模式才进入困难模式（未验证主张，外部未检索到该平台可验证公开来源）。
- **云枢化降级**：
  1. 复用 `enhanced_planner` 的任务复杂度分级（TRIVIAL→SIMPLE→NORMAL→COMPLEX）作课程阶梯——该能力已实现但无生产调用方（主文档 §4.3 差距表），TASK-01 接线后获得真实数据；
  2. 难度自适应策略（推断，方案级描述）：低分级任务优先积累成功样本与反思经验（TASK-02 沉淀），高分级任务在成功率基线达标后才提升路由概率；全部以 T03 KPI#4 分类型失败率校验"通关"与否；
  3. 零新增基建：不引入仿真环境、不新增模型，仅调度与路由调整。

### 4.2 生成式世界模型 → 评估集回归 + 沙箱回放（对齐 D6/D9）

- **原主张**：用生成式世界模型合成海量边缘案例，覆盖现实中极少发生的"黑天鹅"场景（未验证主张）。
- **云枢化降级（离线小飞轮）**：
  1. **评估集回归 = "标准环境"**：既有 1.2 万+ 回归测试即云枢的"世界模型"——任何策略/技能/工作流更新产物必须在其上不退化（G5 门禁的第一层）；
  2. **沙箱回放 = "合成边缘案例"**：在隔离环境（TASK-05 dry-run 语义天然支持）离线回放历史轨迹与失败案例（TASK-06 的 NoveltyEvent 事件、feedback 失败样本），验证更新产物对长尾场景的效果；回放不触碰生产数据（守 privacy 边界）；
  3. **对"黑天鹅"场景的务实处理**：不做合成，改做"新场景捕获"——TASK-06 新颖性管线（ChangeDetector → NoveltyEvent）持续发现真实新情境并沉淀，比生成式合成更符合云枢"真实数据驱动"约束。

> **数据隐私边界（对齐主文档 §3.3 补充项 3）**：评估集回归与沙箱回放涉及真实交互轨迹，入库前必须走既有脱敏/加密管道——复用 `memory/black_box.py`（AES-256-GCM）与脱敏管道；回放样本只允许在隔离环境访问，不进入生产检索面。

## 6. 可选 POC 方案设计（非实现）

> 依据 TASK-08 不变式：POC 只能以方案设计文档形式交付，**不写任何生产代码**。本节仅描述可行性、数据需求、成本估算、评估方式与风险，供决策层评估是否立项。

### 6.1 POC-A：最小策略工件自进化闭环（推荐）

验证"策略工件级自进化（L2）"在真实数据上的有效性，为远期决策提供项目内实证。

- **范围**：3-5 个真实 Skill 走 `offline_evolver` 帕累托进化（候选筛选→变异→评估→提交判定→谱系），全部 dry-run + 人工审核，与 TASK-05 调度解耦（手动触发）。
- **数据需求**：每 Skill ≥50 次使用记录（`usage_count` 与 `param_stats` 参数级历史）、对应 feedback 记录、T03 KPI 基线 4 周。
- **token 成本估算**：`offline_evolver` 代码内蒙特卡洛模拟标注单技能/轮约 600 tokens（±15%）；5 技能 × 3 轮 ≈ 9k tokens，远低于默认单轮预算 500k（`EVOLUTION_MAX_TOKENS_PER_ROUND`）——成本可控（推断级，依据项目内代码注释）。
- **评估方式**：成功率/延迟/满意度三维帕累托 + 评估集回归不退化（G5 第一层）+ T03 KPI#7 采纳率；对照组=未进化 Skill 同期表现。
- **风险**：样本不足致进化信号噪声（缓解：min_usage 门槛 + 真实评估器"无样本不伪造"原则）；启发式占位污染（缓解：显式注入真实评估器）；提交后回滚依赖快照（已有）。
- **决策价值**：若 POC-A 采纳率与 KPI 改善为正且可复现，则"自进化"从远期降格为中期可落地；若为负，则为"不启动 L3"提供实证依据——**无论结果都是有效决策输入**。

### 6.2 自研最小规划策略模型（评估结论：不自训）

- **可行性判定**：云枢无训练基建（GPU/数据/评测管线），"自研规划策略模型"直接落地=**不可行**；且与主文档 D2/D3 结论冲突（参数记忆/参数更新是"模型提供方"职责）。
- **替代路径（若未来确有需求）**：委托外部 API 微调/托管服务（属供应商责任，云枢只消费结果，符合 D2"云枢只做上下文工程级记忆"）——本报告不给未经验证的训练成本数字（守不变式"禁止引述未经验证来源数据"）。
- **若评估外部训练的所需数据（推断级）**：规划轨迹数据集（plan→执行→结果三元组）估计需万级起；数据质量要求（轨迹标注、失败标签）与 T02/T04 沉淀管道产物高度重合——**即"先有 T01~T05 的数据沉淀，才有模型训练的数据基础"，顺序不可颠倒**。
- **评估方式**：需独立离线评估集（规划成功率/令牌效率），与 POC-A 共用评估集回归通道。
- **风险**：数据质量不足、评测口径不一致、模型更新周期与云枢版本耦合导致回滚困难——故即便未来启用，也应优先"检索路由/模板策略"而非权重模型。

### 6.3 POC 立项评估清单（决策层用）

立项 POC-A 前逐项确认（全部为可检查项，杜绝"先做再看"）：

| # | 前置检查项 | 通过标准 | 对应章节 |
|---|---|---|---|
| 1 | 数据就绪 | 目标 Skill `usage_count≥50` 且 `param_stats` 有 ≥3 组参数历史；T03 KPI 基线 ≥4 周 | §6.1 |
| 2 | 预算护栏就绪 | `learning.budget` 已上线（enforce 或至少 warn_only+告警通道）；POC token 消耗有独立核算 | §3.1 |
| 3 | 回滚保障 | POC 目标 Skill 全部有版本快照，`rollback_version` 验证通过 | §2.4 G4 |
| 4 | 审计通道 | POC 每轮进化写入谱系（EvolutionArchive），审计日志可回溯 | §2.4 G3 |
| 5 | 评估集 | 目标 Skill 相关回归用例清单已圈定，可执行"不退化"判定 | §2.4 G5 |
| 6 | 权限边界 | POC 动作在 L1-L5 分级下权限已界定（默认 L2 及以下，越级拦截） | §5.1（T07） |
