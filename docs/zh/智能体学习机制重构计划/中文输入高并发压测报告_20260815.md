## 根因分析（LLM 层超时）

排查过程（排除法，逐一验证后排除内部串行锁）：

| 嫌疑点 | 结论 | 依据 |
|---|---|---|
| app_server.py:3534 `_lock` | 排除 | ActionTracker 权限面板锁，临界区仅毫秒级列表操作 |
| orchestrator.py:400 `_interaction_lock` | 排除 | 仅包住 `_interaction_count += 1` 整数递增 |
| LLMService / ToolCallingService | 排除 | 无锁，openai client 线程安全；12 次 LLM 调用全部发出且全部 200 OK |
| memory_manager 同步压缩 | 排除 | 压测期间后台压缩线程运行中（日志「运行中 ✓ → 等待后台处理」），请求未被同步压缩阻塞 |

**结论：不存在内部全局串行锁。** 瓶颈为双层排队：

| 层 | 证据 | 性质 |
|---|---|---|
| DeepSeek 服务端 | LLM 单调用 15-19s → 并发 6 时膨胀至 20-115s | 外部限流/排队（不可控） |
| waitress 线程池 | threads=8；Task queue depth 1-5 出现 176 次，队尾请求等待 > 120s | 线程容量不足 |

时间线证据（11:21-11:25）：12 次 `POST /v1/chat/completions` 全部 200 OK，但完成时间从 11:21:06 拖至 ~11:25:45；前 4 次完成间隔仅 0-2s（并发飞行，证明无内部互斥），后续出现 65s / 115s 大间隔（DeepSeek 端排队）。

组装层并发稳定性（本轮核心验证目标）：**12/12 请求组装完成，耗时 65-227ms，无异常、无锁、证据链完整。**
