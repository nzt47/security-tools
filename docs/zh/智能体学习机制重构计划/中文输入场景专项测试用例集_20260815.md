# 中文输入场景专项测试用例集（2026-08-15）

## 1. 背景与目标

语义层 bigram 分词修复后，中文输入不再因单字命中率虚高而误命中 persona 元技能短路返回，ContextAssembler 组装流程可正常触发，链路放行到 LLM。

本用例集覆盖三层漏斗（规则层 → 语义层 → 拒识层）+ ContextAssembler 组装 + LLM 端到端，重点验证**中文输入**场景下的行为回归，防止单字分词导致的误命中短路回归。

### 链路契约（【不易】）

- 语义层：`agent/orchestrator/orchestrator.py:_semantic_layer_match()`，`min_score=0.3`（config.yaml `orchestrator.semantic_layer`）
- 拒识层：`_should_reject()`，`reject.enabled=false` 时未知意图放行 LLM（config.yaml `orchestrator.reject`）
- 分词：`agent/skills_mgmt/loader.py:_tokenize()` / `bm25_searcher.py:_tokenize()`，中文连续串按相邻二元组（bigram）
- 组装：`agent/context/assembler.py:assemble()`，`token_budget=3000`
- 埋点：`yunshu_intent_layer_total{layer=...}`（prometheus），`layer=llm` 表示放行到 LLM

## 2. 测试用例集

### A. 分词单元层（bigram）

| 用例ID | 输入 | 预期 tokens | 断言 |
|---|---|---|---|
| ZH-TOK-01 | `费马小定理的证明思路是什么` | `费马 马小 小定 定理 的证 证明 明思 思路 是什 什么` | 不含单字；相邻二元组保留字序 |
| ZH-TOK-02 | `解析文件` | `解析 析文 文件` | 2 字短串也生成 bigram |
| ZH-TOK-03 | `hello world` | `hello world` | 英文按词，不切 bigram |
| ZH-TOK-04 | 空串 `""` / `None` | `[]` | 不抛异常 |
| ZH-TOK-05 | 单字 `好` | `好` | 孤立单字保留（守向后兼容，防短查询分词为空） |
| ZH-TOK-06 | 混合 `Python 解析` | `python 解析` | 中英混排各自处理，2 字中文串生成 1 个 bigram |

验证方式：`python -c` 直接调用两处 `_tokenize`，断言 tokens 列表。

### B. 语义层匹配（防误命中短路）

| 用例ID | 输入 | 预期 | 断言 |
|---|---|---|---|
| ZH-MATCH-01 | `费马小定理的证明思路是什么` | 语义层 top1 命中率 < 0.3 | 不命中 persona 元技能，不短路返回 |
| ZH-MATCH-02 | `请帮我总结今天的对话` | 含「总结」bigram 时才可能命中总结类技能 | 不得因单字「总」「结」命中 |
| ZH-MATCH-03 | 真实任务词 `解析`、`总结`、`证明` | bigram 有区分度 | 任务词与常用字交集不再虚高 |
| ZH-MATCH-04 | 与元技能描述高度重复的输入 | 命中率 ≥ 0.3 时允许命中 | 短路是合法行为，仅防误判 |

验证方式：直接调用 `_semantic_layer_match`（或 SkillLoader 检索），对比修复前单字切分 vs 修复后 bigram 的命中率。

## 5. 注意事项

- 配置优先级：环境变量 > .env > config.yaml > 默认值；`ORCHESTRATOR_SEMANTIC_MIN_SCORE` / `ORCHESTRATOR_REJECT_ENABLED` 可临时覆盖做负向测试
- 并行会话可能覆盖 `.env`，跑 E2E 前先确认 `LLM_API_KEY` 为真实 key（长度 35，非 `sk-secret`）
- 深度模型未配置（router=False），任务统一走待命模型 `deepseek-chat`；若配置模型路由器需同步校验 `to_llm_kwargs()` 输出
