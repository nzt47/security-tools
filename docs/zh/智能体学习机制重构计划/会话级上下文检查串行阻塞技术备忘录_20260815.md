## 2. `_check_context_usage` 与 `get_context` 实现深析

### 2.1 `_check_context_usage`（orchestrator.py L2476→，process() 入口 L435 同步调用）

每个请求**进入 process() 后第一件事**就是同步执行：

```
_check_context_usage()
 ├─ memory.get_context(token_limit)          # ① 全量上下文组装
 │    ├─ _need_compress 分支（共享标志，见 2.3）
 │    ├─ storage.load_summary()              # 文件读 ×2（summary.txt + version.txt）
 │    ├─ 窗口/file 读最近消息
 │    └─ count_messages(context) 循环裁剪    # ② O(n²) tiktoken 全量统计
 ├─ memory._token_counter.count_messages(context)   # ③ 第二次全量 tiktoken 统计
 └─ memory.compress_rounds
      └─ storage.load_summary()              # ④ 再次文件读 ×2
```

**单请求固定开销**：4 次文件读 + 2 次全量 tiktoken 统计。12 并发共享会话 → 48 次文件读 + 24 次全量 token 统计，全部落在同一份共享文件与 GIL 上，无需任何锁也能呈现"假串行"。

### 2.2 `get_context`（memory/memory_manager.py L534→）

- **裁剪循环 O(n²)**：`while len(context)>1: count_messages(context); pop()` 每轮重算全量 token。共享会话窗口 maxlen=200 → 最坏 200 次全量 tiktoken encode。该函数每请求被调用 **2 次**（`_check_context_usage` ① + `_call_llm_v2` L3209）。
- **共享 `_message_window`**：deque 无锁读改写（`add_message` append 与 `get_context` `list()` 并发）→ 读改写竞态（CPython 下 append 近似原子，但迭代与修改并发存在脏读风险）。
- **共享 `_need_compress`**：`add_message` 置位，`_execute_compression` 清除。12 并发共享会话时**每个请求都看到 `_need_compress=True`**，全部进入告警分支 → 每请求 5 行 WARNING 日志（logging 全局锁争抢）+ `request()` + `is_running()` + `start_sync()`。

### 2.3 `AsyncCompressor.start_sync`（线程泄漏隐患）

```python
def start_sync(self):
    loop = asyncio.get_running_loop()   # waitress worker 线程无运行中 loop → RuntimeError
    ...except RuntimeError:
        loop = asyncio.new_event_loop()
        threading.Thread(target=loop.run_forever, daemon=True).start()  # ← 每次调用新建线程！
```

压缩器未运行时，**每个**调用 `start_sync()` 的 waitress worker 线程都会新建一个事件循环 + 永久存活 daemon 线程（线程泄漏）；后台 `_execute_compression` 含 2 次 LLM 外呼，与 12 个请求的 LLM 并发争抢同一 DeepSeek 端点 → 服务端排队 → 请求 LLM 延迟被放大。

### 2.4 锁/同步机制审计（"锁在哪儿"）

| 锁 | 位置 | 持有时长 | 是否请求路径热点 |
|---|---|---|---|
| `Storage._write_lock` | 写路径（save_message/save_summary） | 单次文件写，毫秒级 | 否（读路径无锁） |
| `AsyncCompressor._lock` | 启停/待处理标记 | 微秒级 | 否 |
| `DialogState._lock`/`_SESSION_LOCK` | DST 状态槽/懒创建 | 微秒级；encode 在锁外 | 否 |
| `SessionManager._lock`/`_append_lock` | 会话索引/消息追加 | 单次读写，毫秒级 | 否 |
| `Orchestrator._interaction_lock` | `_interaction_count += 1` | 微秒级 | 否 |

**没有任何锁被长时间持有**。串行的本质是三类无锁资源的共享争抢：共享会话文件 IO、GIL 上的 tiktoken 全量统计、DeepSeek 外呼排队。

## 3. 根因链（session 级串行）

```
压测脚本 body 传 session_id，app_server 读 query 参数 → 12 请求全部落回默认会话
        │
        ▼
共享会话 = 共享 MemoryManager（窗口/_need_compress/摘要文件）
        │
        ├── 每请求入口 _check_context_usage 同步执行重活（4×文件读 + 2×全量 tiktoken）
        ├── get_context O(n²) 裁剪 × 2 次/请求，共享窗口被放大
        ├── _need_compress 常真 → 每请求告警盒 + request + start_sync（可泄漏线程）
        ├── 后台压缩 2 次 LLM 与请求 LLM 争抢 DeepSeek 额度 → 外呼 6–21s 被拉长
        └── logging 全局锁：12 请求 × 每步多行日志 → GIL/IO 争抢进一步放大
        ▼
请求完成时间线性爬坡：75s → 218s（[CHAT]），162s → 363s（[END]）
```

## 4. 修复实现（请求级上下文隔离 / 低频异步化）

### 4.1 `orchestrator.py` — `_check_context_usage` 低频节流（P0）

process() 入口 L435：按 `CONTEXT_USAGE_CHECK_INTERVAL`（默认 30s）节流，间隔内复用 `_last_context_warning`，不再每请求执行全量组装。

### 4.2 `memory/memory_manager.py` — 摘要内存缓存（P0）

`_load_summary_cached()`：`get_context` / `compress_rounds` 首次读文件后缓存，写入侧（`save_summary`/`clear_summary`/`_execute_compression` 成功路径）失效刷新。单写者单读者，缓存赋值原子，不引入锁。

### 4.3 `memory/memory_manager.py` — `get_context` 裁剪 O(n²)→O(n)

单次 `count_messages` 后按"消息 token + 4 格式开销"精确扣减逐条弹出，语义与旧 while 循环完全等价（已用脚本验证 `total <= limit` 且至少保留 1 条）。

### 4.4 `memory/memory_manager.py` — `AsyncCompressor.start_sync` 启动守卫

锁内同步置位 `_started`，防止 waitress 多 worker 并发重复创建事件循环线程；`stop`/`stop_sync` 复位允许重启；启动异常复位允许重试。已验证 5 次并发调用线程数零增长。

### 4.5 `app_server.py` — 请求级会话隔离（body `session_id` 优先 + 自动建会话，P0）

- **根因闭环**：压测脚本 body 传 `session_id`，原实现只读 `request.args.get("session")` → 12 请求全部收敛到默认会话（§3 根因链第一步）。本提交按 §6 推荐跟进落地：
  1. 解析优先级：body `session_id` > query `session` > 全局默认（`_get_current_session_id()`），Web 前端 query 传参向后兼容。
  2. 显式会话不存在时自动 `create_session(session_id=...)`：`SessionManager.add_message` 对不存在会话抛 `SessionNotFoundError` → 500，自动创建后外部调用方任意 `session_id` 均可用。
  3. `session_manager.create_session` 增加显式 `session_id` 参数 + 路径穿越防校验（拒绝 `/ \ .. :` 字符，非法时回退默认会话）。
  4. 验证：12 个压测请求各建独立会话目录 `stress-zh-000`~`011`，各落盘 2 条消息（user+assistant）。
