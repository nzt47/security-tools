## 1. 背景（为什么做）

设计思路的"前沿方向"提出**递归自进化**（哥德尔智能体：`π_{t+1}, I_{t+1} = I_t(π_t, I_t, r_t, g)`，更新规则本身也在进化），并提及 MAE 三角色对抗、课程学习、世界模型合成边缘案例。

主文档评估已判定：递归自进化实践风险极高（目标漂移/不可审计/不可回滚），MAE 与课程学习对云枢场景成本不现实（§3.2 D5/D6/D7/D8）。但"高风险"不等于"不值得研究"——需要一份**严谨的可行性研究报告**，把理论主张翻译为云枢可落地的渐进方案与红线清单，供决策层评估是否/何时启动。

**本任务只产出研究报告与可选 POC 方案，不写生产代码。**

## 2. 目标描述（做什么）

产出一份《云枢递归自进化与多角色评估可行性研究报告》，回答：

1. 设计思路"前沿方向"各主张在云枢约束（API 型 LLM、无训练基建、成本敏感、配置驱动可回滚）下的**可行性分级**（可行/有条件可行/不可行+原因）。
2. **递归自进化的风险矩阵**与**护栏设计**：若未来要做，必须满足的底线（更新规则本身版本化+门控、目标函数硬编码不可自改、全链路审计、一键回滚）。
3. **MAE 三角色 / 课程学习 / 世界模型**的云枢化降级方案（结合主文档 §3.2 D5/D6 的替代路径）。
4. 与 TASK-01~TASK-07 的**衔接路线图**：哪些远期能力依赖哪些主线任务的沉淀（数据/门控/度量），给出触发条件（如"当进化采纳率连续 4 周 < 5% 时考虑引入 Judge 角色"这类可度量门槛）。
5. 可选：轻量 POC 方案设计（非实现）——例如"自研最小规划策略模型"的可行性、数据需求与训练成本估算。

## 3. 不变式约束（不易——禁止触碰）

- **禁止写任何生产代码**（包括 POC 实现）；POC 只能以方案设计文档形式交付。
- **禁止**在任何地方出现"自我改写决策逻辑"的实现建议——报告只能给出护栏约束下的研究路径。
- **禁止**引述未经验证的来源数据（如框架效果数字）作为决策依据；必须标注证据等级（实证/论文主张/推断）。
- 报告必须与主文档 §3.2 的 D2/D5/D6/D7/D8 结论保持一致（若推翻需给出证据）。

## 4. 执行步骤

### Step 1：资料收集
- 重读设计思路原文件（`docs/zh/设计思路/设计理想智能体学习机制-20260812112318.json`）与主文档评估结论。
- 检索项目内既有素材：`run_evolution_demo.py`（offline_evolver 演示）、`docs/` 下相关研究报告（如 `docs/zh/项目任务分解总览.md`、`docs/zh/阶段四_整合与反身智能.md`——若存在反身智能/自进化相关内容必须纳入）。
- 可补充外部检索（设计文档提及的 MIA / MAE / Gödel Agent / 课程学习 / 世界模型），但外部证据必须标注来源与链接。

### Step 2：撰写研究报告
按以下大纲成文（预计 300-500 行）：
1. 结论摘要（可行性分级总表）。
2. 递归自进化：机制拆解 → 风险矩阵（目标漂移/不可审计/不可回滚/成本失控）→ 护栏设计（版本化+门控+目标函数硬编码+审计+回滚）→ 分级落地建议（近期/中期/远期触发条件）。
3. MAE 三角色：成本模型（3 次 LLM/轮）→ 云枢化降级（Judge=现有规则评估+feedback；Solver=workflow_learning；Proposer=课程分级）→ 引入门槛（依托 TASK-03 KPI）。
4. 课程学习/世界模型：降级为评估集回归+沙箱回放（对齐主文档 D6/D9）。
5. 与主线任务的衔接路线图（依赖 T01~T07 的哪些产物、以什么 KPI 为触发条件）。
6. 可选 POC 方案设计（自研最小规划策略模型：数据需求/token 成本/评估方式/风险）。

### Step 3：评审自检
- 逐条核对：每个结论是否与主文档 §3.2/§3.3 冲突；是否满足"护栏底线"；外部证据是否标注来源。
