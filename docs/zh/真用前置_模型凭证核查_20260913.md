## 二、影响（为什么这是「真用」的硬前置）

设计与运营清单的共同前提是「**让它真实执行工具**」，只有工具调用才会落成 Trace：

| 挂着的事项 | 是否被本问题阻塞 |
|---|---|
| 消化吞吐 / 内化转化率 / ACR / UTC | **是** —— 无 Trace 则无数据，永远是 0 |
| LLM-judge 真实评分（S8-04） | **是** —— judge 走的就是同一套模型适配器 |
| 灰度真实接管（S8-03） | 否（容器隔离是独立工程） |
| L0 锚 / 周报 / 审计链 | 否（这些不需要模型） |

> ⚠️ 特别注意：**不要**因为"周报能生成、L0 锚全过、面板能打开"就认为系统可用 ——
> 那些链路都不经过模型。**模型不通 ≠ 系统坏了，但 = 学不到任何东西。**

## 三、顺带发现的真缺陷：自检是**假绿灯**（建议立项）

`agent/orchestrator/lifecycle_manager.py::get_config()`：

```python
"api_key_set": bool(self._llm.api_key),      # ← 只看"有没有填"，不看"能不能用"
```

于是 `/api/chat` 的 `llm_state` 报 `configured: true / api_key_set: true`，
而**实际每一次调用都 401 失败**。运营清单 §九 把"面板数字不对"归因于开关默认关闭，
但没有覆盖这一类「**填了但无效**」的假绿灯 —— 看面板会以为模型是好的。

**建议修法**（与 v7.2 的"不谎报"纪律一致，可并入 S8 批次或单列小项）：
1. `llm_state` 增加**可区分**字段：`configured`（已填）与 `verified`（最近一次真实调用是否成功）；
2. 启动自检或健康检查做**一次极小的真实探针**（`max_tokens=1`），失败即如实标注原因，
   与 S8-04 的 judge 三态（`available` / `no_credentials` / `disabled`）**同款口径**；
3. 降级话术（"我暂时无法给出令人满意的回答"）**必须带上真实原因**，否则用户只知道"它变笨了"，
   不知道"是 key 失效"。

## 四、修复动作（谁做什么）

### 要 Owner 做的（只有一件）

**给一个能用的模型 API Key。** 三选一，任选其一即可：

| 方案 | 你做什么 | 代价 |
|---|---|---|
| **DeepSeek（推荐）** | 到 platform.deepseek.com 生成一个新 key，发我 | 改动最小：`.env` 只改 1 行，provider/model 都不用动 |
| OpenAI | 给一个可用的 `OPENAI_API_KEY` | 需同时把 provider 换成 openai、model 换成对应型号 |
| Claude | 给一个可用的 `ANTHROPIC_API_KEY` | 需同时把 provider 换成 claude |

> 给了之后**不需要你做别的**：填 key、对齐 provider/model、重启、复验，由我全部做完。

### 由我做的（拿到 key 之后）

1. 写入 `.env`（`LLM_API_KEY`，或对应 provider 的键），确认 `.env` 不进版本库；
2. 对齐 `LLM_PROVIDER` / `LLM_MODEL` / `LLM_BASE_URL` 与该 key 匹配（**现在 `llm_state` 报的是
   `openai/gpt-4`、`.env` 写的是 `DeepSeek/deepseek-v4-flash`，两者不一致，一并理清**）；
3. 重启 `app_server`；
4. **用同一句话复验**（"帮我列出当前工作目录下的文件"），验收标准是
   **`tool_steps` 非空 + Trace 真的落账**，而不是"它回了一句话"；
5. 顺带把 §三 的假绿灯缺陷修掉（或立项）。

## 六、口径纪律（写在这里免得以后又忘）

- **"它回话了" ≠ "它能用"**：寒暄模板也会回话。判据是 **`tool_steps` 非空 + Trace 增长**。
- **"面板说配置好了" ≠ "凭证有效"**：自检当前只看"有没有填"（见 §三）。
- **不用脚本造任务刷指标**：真实轨迹与合成轨迹在数据形状上可区分（S7-05 已证），
  造出来的流量只会让所有曲线失真。
