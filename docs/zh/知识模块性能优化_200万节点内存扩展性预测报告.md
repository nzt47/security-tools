## 4. 扩展性结论与建议

| 决策维度 | 200 万节点评估 |
|---|---|
| 内存（现状） | ≈3.7 GB（基线）～ 7.26 GB（长正文）：**回退即 OOM 高风险** |
| 内存（流式） | ≈256 MB（基线）～ 1.28 GB（高密度）：可控 |
| 耗时（全扫） | ≈7.5 分钟：**回退代价不可接受**，索引完整性是硬前提 |
| 扩展性规律 | 现状/流式均线性，降幅稳定 ≈14x |

**建议**：

1. **200 万节点 = 架构分水岭**：除流式落地（3.7 GB → 256 MB）外，需同步保证**索引健康**（污染 warning 已就位，建议加定时 rebuild 校验），否则单次索引损坏即触发 7.5 分钟回退。
2. **内存已非唯一约束**：200 万卡全扫 ≈7.5 分钟，即便流式落地，回退路径的**时间成本**也需业务预案（如后台任务执行、限流提示）。
3. **分片评估（仅当密度 ≥5 links/卡）**：refs 达 640 MB+，可评估按 slug 前缀分片存储 + 合并读，本方案不涵盖，列为独立项。
4. **数据落盘形态**：200 万规模建议复核单文件 `index_links.md` 的读改写成本（增量路径每次全文件读改写），必要时分片。
