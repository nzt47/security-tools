## 1. 架构总览

```
┌───────────────────────────── 云枢 app_server (127.0.0.1:5678) ─────────────────────────────┐
│                                                                                            │
│  ┌─────────────────────── 网关适配层 (agent/api_gateway_flask.py) ──────────────────────┐  │
│  │  before_request 拦截判定 should_gateway_handle()                                     │  │
│  │    ├── /api/open/* 端点        → ApiGateway.handle_request（X-API-Key 认证）          │  │
│  │    ├── 灰度开放内部端点         → ApiGateway.handle_request（X-API-Key 认证）          │  │
│  │    └── 其余内部端点             → Flask 原生路由（FLASK_API_TOKEN / require_token）    │  │
│  └───────────────────────────────────────────────────────────────────────────────────────┘  │
│                                                                                            │
│  多租户核心: TenantManager / QuotaManager / RateLimiter（五级） / AuditLogger              │
└────────────────────────────────────────────────────────────────────────────────────────────┘
```

**认证模型（双轨并存）**：

| 通道 | 认证方式 | 请求头 | 适用端点 |
|---|---|---|---|
| 开放 API | API Key（64 位，可绑定租户+角色） | `X-API-Key: <key>` 或 `Authorization: Bearer <key>` | `/api/open/*` + 灰度开放内部端点 |
| 内部 API | 静态令牌（生产必配） | `X-API-Token: <token>` 或 `Authorization: Bearer <token>` | 其余 `/api/*`（写操作等） |

## 2. 部署前置与配置

### 2.1 环境变量（.env，其余代码一律经环境变量读取）

| 变量 | 必填 | 说明 |
|---|---|---|
| `FLASK_API_TOKEN` | 生产必填 | 内部 API 静态令牌。**不设置则 require_token 全部放行**（危险） |
| `YUNSHU_FEATURE_SANDBOX` | 否 | 沙盒功能开关，默认 `false` |
| `PORT` / 默认 5678 | 否 | 服务端口 |

> 所有配置修改只允许在 `.env` 进行；代码/脚本通过环境变量读取，禁止硬编码。

### 2.2 启动

```bash
# 加载 .env 后启动
python app_server.py
```

启动日志应包含：
- `[APIGateway] 已扫描 N 个内部 API 路由并入文档`（N≈292）
- `[APIGateway] T8.4 已开放 8 个内部只读端点（两批）`
- `API 令牌认证已启用`（生产环境必须确认，而非"未启用"）

### 2.3 网关配置点（代码内，注册即生效）

| 配置 | 位置 | 默认 | 说明 |
|---|---|---|---|
| 网关端点前缀 | `api_gateway_flask.GATEWAY_PREFIX` | `/api/open` | 拦截前缀 |
| 开放端点批次 | `api_gateway_flask._INTERNAL_OPEN_BATCH1/2` | 两批 8 个 | 灰度列表（`path, method, scope`） |
| 租户限流桶 | `rate_limiter.register_rule("tenant", cap, rate)` | 100 令牌 / 10/s | 租户维度独立桶 |
| Key 默认配额 | `api_gateway.create_key` | 10000 次 | quota_remaining/total_quota |
| 租户配额 | `QuotaManager.set_tenant_quota(tenant_id, "api_calls", limit)` | 未配置=放行 | key 前缀 `tenant:` |
| 旧 Key 兼容期 | `scripts/migrate_api_keys_to_tenant.py --compat-days` | 90 天 | 过期后 403 引导迁移 |

## 3. 租户初始化脚本

### 3.1 全流程（创建租户 → 用户 → 角色 → Key → 验证）

```bash
BASE=http://127.0.0.1:5678

# 1) 创建租户（自动创建 owner 用户并分配 OWNER 角色）
curl -X POST $BASE/api/open/tenants -H "Content-Type: application/json" -d '{
  "name": "acme-corp",
  "type": "organization",
  "owner_email": "ops@acme.com",
  "owner_name": "Acme Ops"
}'
# → 201，返回 tenant_id（如 org_xxx）

# 2) 创建成员用户并分配角色（org_xxx / MEMBER）
curl -X POST $BASE/api/open/tenants/org_xxx/users -H "Content-Type: application/json" -d '{
  "email": "dev@acme.com", "name": "Dev", "role": "member"
}'

# 3) 为租户生成绑定 Key（角色 member → 权限走角色权限表）
curl -X POST $BASE/api/open/keys -H "Content-Type: application/json" -d '{
  "user_id": "dev@acme.com", "tenant_id": "org_xxx", "role": "member",
  "description": "acme dev key"
}'
# → 201，返回 api_key（仅此一次明文，务必保存）

# 4) 验证：带 Key 访问灰度开放端点
curl -H "X-API-Key: <api_key>" $BASE/api/audit/logs?limit=5
# → 200 {"ok":true,"logs":[...]}

# 5) 无 Key / 无权限 / 超额验证
curl $BASE/api/audit/logs                          # → 401
# 超出 scope / 配额 → 403 / 429
```

### 3.2 幂等初始化脚本（建议落库 scripts/init_tenant.py）

```python
"""租户一键初始化：幂等（存在则跳过），适合 CI 与交付"""
import os, sys
import requests

BASE = os.environ.get("YUNSHU_BASE", "http://127.0.0.1:5678")


def init_tenant(name: str, owner_email: str) -> dict:
    # 查重：已存在则复用
    r = requests.get(f"{BASE}/api/open/tenants", timeout=10)
    for t in r.json().get("tenants", []):
        if t["name"] == name:
            return t
    r = requests.post(f"{BASE}/api/open/tenants", json={
        "name": name, "type": "organization", "owner_email": owner_email,
    }, timeout=10)
    r.raise_for_status()
    return r.json()["tenant"]


def issue_key(tenant_id: str, user_id: str, role: str) -> str:
    r = requests.post(f"{BASE}/api/open/keys", json={
        "user_id": user_id, "tenant_id": tenant_id, "role": role,
    }, timeout=10)
    r.raise_for_status()
    return r.json()["api_key"]


if __name__ == "__main__":
    tenant = init_tenant(sys.argv[1], sys.argv[2])
    print("tenant:", tenant["id"])
    # 需要时生成 Key（明文仅此一次）
    # print("key:", issue_key(tenant["id"], "ops@acme.com", "admin"))
```

## 4. 开放端点目录

### 4.1 管理端点（/api/open/*，内部运维用）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST/GET | `/api/open/tenants` | 租户创建/列表 |
| GET/DELETE | `/api/open/tenants/<id>` | 租户详情/删除 |
| POST | `/api/open/tenants/<id>/users` | 创建用户+角色 |
| POST | `/api/open/tenants/<id>/users/<uid>/roles` | 分配角色 |
| GET | `/api/open/users/<uid>/tenants` | 用户所属租户 |
| GET/POST | `/api/open/tenants/<id>/config` | 租户配置（含继承） |
| GET | `/api/open/tenants/<id>/usage` | 用量统计 |
| POST/GET | `/api/open/keys` | Key 创建（仅一次明文）/列表（脱敏） |
| GET | `/api/open/stats` | 网关统计 |
| GET | `/api/docs` | 全量 Swagger 文档 |
| GET | `/api/open/echo` | 探活（无需鉴权） |

### 4.2 灰度开放端点（带 Key，scope=read）

| 批次 | 端点 | 说明 |
|---|---|---|
| 1 | `GET /api/news` | 新闻直通（外网搜索，延迟依赖上游） |
| 1 | `GET /api/search-performance/{status,history,summary}` | 搜索性能监控 |
| 2 | `GET /api/audit/logs?limit=&trace_id=&action=` | 审计日志查询（只读） |
| 2 | `GET /api/schedules` | 定时任务列表 |
| 2 | `GET /api/skills` | 技能列表 |
| 2 | `GET /api/tasks` | 异步任务列表 |

> 带 `require_token` 的内部端点（`/api/knowledge/cards`、`/api/llm/instances`、`/api/config/logs` 等）**暂不开放**：网关 Key 与 `FLASK_API_TOKEN` 双重认证冲突，需先完成认证合并（远期）。

## 5. 监控指标建议

### 5.1 内置监控入口

| 指标源 | 路径 | 用途 |
|---|---|---|
| 网关统计 | `GET /api/open/stats` | 端点数/Key 数/访问日志数/限流器状态 |
| 访问明细 | `GET /api/open/stats`（AccessLogger `_logs`） | 24h 请求量、状态码分布、端点 Top、用户 Top |
| 限流状态 | `get_stats()["rate_limiter"]` | 全局/租户/用户桶令牌余量 |
| 审计日志 | `GET /api/audit/logs` | 操作审计（Append-only，按日文件 `data/audit/audit_YYYYMMDD.jsonl`） |
| 健康看板 | `/api/health/*` | 进程/模块健康 |
| Swagger | `GET /api/docs` | 接口清单自检 |

### 5.2 建议告警阈值（采集频率 1min）

| 指标 | 阈值 | 说明 |
|---|---|---|
| 401 占比 | > 5% 持续 10min | 疑似 Key 滥用/盗用，检查 `/api/open/keys` |
| 429 次数 | > 100/min | 租户/用户超限，检查配额与限流桶 |
| 403 次数 | > 10/min | 权限配置异常 |
| 5xx | > 0 | 网关 handler 异常，查 access_log `success=False` |
| `/api/news` 延迟 | p95 > 15s | 依赖外网搜索，注意限流回退 |

### 5.3 采集建议

- **Prometheus 对接**：采集 `/api/open/stats`（JSON），用 exporter 转 metrics 标签：`endpoint`、`status_code`、`user_id`
- **CI 每日巡检**：`.github/workflows/gateway-health.yml` cron 执行 `python scripts/gateway_health_check.py --unit-only`（独立单测模式，不依赖服务）
- **日志落盘**：网关访问日志在 `AccessLogger`（内存上限 10000 条）；审计日志按日 JSONL，建议纳入统一日志采集

## 6. 故障排查

| 现象 | 状态码 | 排查路径 |
|---|---|---|
| 无 Key / Key 无效 | 401 | 确认请求头 `X-API-Key`；`GET /api/open/keys` 检查 key 尾号 |
| 权限不足 | 403 | Key 未绑定租户→检查自带 scopes；绑定租户→检查 `tenant_manager.has_permission` 角色权限链 |
| 旧 Key 兼容期已过 | 403 | 重新迁移 `migrate_api_keys_to_tenant.py --apply` 或重建 Key |
| 限流超限 | 429 "Rate limit exceeded" | 检查五级限流桶余量（`/api/open/stats`），必要时 `register_rule` 调参 |
| 配额超限 | 429 "Quota exceeded / Tenant quota exceeded" | 用户级 `QuotaManager` 或租户级 `set_tenant_quota` 调整 |
| 灰度端点 404 | 404 | 确认端点已注册（`/api/docs` 检索）；视图缺失时日志 `跳过开放` |
| 双重认证 401（开放了带 require_token 端点） | 401 | 移除该端点；先完成认证合并再开放 |

**回滚灰度端点**：从 `_INTERNAL_OPEN_BATCHx` 列表删除对应 `(path, method, scope)` 条目 → 重启 app_server → 端点回到内部认证通道（FLASK_API_TOKEN）。

## 7. 扩展指引（第三批起）

1. 新增只读端点：在 `api_gateway_flask.py` 追加 `_INTERNAL_OPEN_BATCH3`，条目 `(path, method, scope)`
2. 前置条件：端点必须 **GET + 无 require_token + 返回 JSON**
3. 每批 3-5 个，灰度观察 401/403/429 与延迟后再放下一批
4. 大批量开放前建议将批次常量重构为配置文件（开放端点注册表），经 `.env` 或独立配置读取
