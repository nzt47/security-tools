### 2.2 核心能力

1. **安全迁移**：source 只读（只读 URI 连接）、自动备份、失败回滚、断点续传
2. **向量重生成**：维度不匹配自动丢弃旧向量，本地 bge-small-zh-v1.5 重新生成（禁云端 API）
3. **性能调优**：`--workers` / `--encode-batch` 参数，默认 `workers=1 + encode_batch=64`
4. **CI 保障**：paths 过滤 + 每周一 cron + 手动触发；失败钉钉告警

## 三、遇到的问题及解决方案

| # | 问题 | 解决方案 |
|---|---|---|
| 1 | 任务文档表名（memories/memories_fts）与代码实际（memory_items/memory_fts）不一致 | 确认对齐到代码实际表名（复用 HolographicAdapter 常量） |
| 2 | ChromaDB 在 Windows 已知不兼容（Rust 后端报错） | 读取 try/except 全量捕获，失败降级全量重生成 |
| 3 | FTS 校验对含 `[]()<>` 特殊字符数据失配 | `_extract_fts_keyword` 提取干净关键词（30 边缘用例验证） |
| 4 | dry-run 退出码误判为失败 | `main()` 增加 `dry_run` 状态判定 |
| 5 | 向量重生成多 worker 无收益（torch 已占 6 线程） | 基准实测定位瓶颈为 encode_batch，改默认 `workers=1 + encode_batch=64`（2.16x） |
| 6 | CI 报 `Unknown config option: asyncio_mode` | workflow 依赖补 `pytest-asyncio`（对齐 p0-security.yml） |
| 7 | 迁移文件意外从工作区消失（未 git 跟踪） | 基于计划文档完整重建，并补充退出码/参数修复 |
