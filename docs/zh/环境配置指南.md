# 云枢环境配置指南

> 单一数据源约定：所有配置经 `.env`（环境变量）注入，代码/脚本统一读取环境变量，
> 禁止在业务代码中硬编码敏感配置。`.env` 已 gitignore，含真实密钥禁止提交。

## 一、告警密钥配置（审计日志告警）

复制 `.env.example` 的「审计日志告警配置」段到 `.env` 并填真实值：

| 键 | 必填 | 说明 |
|---|---|---|
| `SMTP_HOST` | 是 | SMTP 服务器地址（如 `smtp.exmail.qq.com`） |
| `SMTP_PORT` | 否 | 465=SSL / 587=STARTTLS / 2525=本地捕获（默认 465） |
| `SMTP_USER` | 是* | 发信账号（无认证 SMTP 可留空） |
| `SMTP_PASS` | 是* | 应用专用密码（QQ 邮箱：设置→账户→开启 SMTP 生成授权码；勿用登录密码） |
| `SMTP_TO` | 是 | 收件人；多收件人逗号分隔 |
| `SMTP_SSL` | 否 | 1=SSL（默认）/ 0=明文 |
| `AUDIT_ALERT_THRESHOLD` | 否 | 租户异常占比告警阈值（默认 5） |

本地联调（无真实 SMTP）：`SMTP_HOST=127.0.0.1` `SMTP_PORT=2525` `SMTP_SSL=0`，
配合 `scripts/dev/smtp_capture_server.py` 捕获服务器验证发信链路。

## 二、GitHub Secrets 配置脚本（CI 每日告警密钥）

### 2.1 背景

`.github/workflows/audit-alert.yml`（Job1 每日告警）运行时经 `$GITHUB_ENV` 注入以下 7 项 Secrets：
`SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `SMTP_TO` / `SMTP_SSL` / `AUDIT_ALERT_THRESHOLD`。
脚本将 `.env` 中同名键一键写入 GitHub Secrets，避免 Web 界面逐项手工添加。

### 2.2 脚本位置与前置

- `scripts/dev/setup_github_secrets.ps1`（Windows PowerShell 5.1/7+）
- `scripts/dev/setup_github_secrets.sh`（bash / Git Bash / WSL / Linux/macOS）
- 前置：已安装 [gh CLI](https://cli.github.com) 并 `gh auth login`；仓库有权限

### 2.3 用法

```powershell
# 预览将设置的密钥（不调用 gh）
powershell -ExecutionPolicy Bypass -File scripts/dev/setup_github_secrets.ps1 -Repo owner/repo -DryRun

# 实际写入（从项目根 .env 提取；repo 缺省从 git remote 推断）
powershell -ExecutionPolicy Bypass -File scripts/dev/setup_github_secrets.ps1
```

```bash
# bash 版本等价
./scripts/dev/setup_github_secrets.sh --repo owner/repo --dry-run
./scripts/dev/setup_github_secrets.sh
```

### 2.4 参数

| 参数 | 说明 |
|---|---|
| `-Repo` / `--repo` | 目标仓库 `owner/repo`；缺省从 `git remote get-url origin` 推断 |
| `-EnvFile` / `--env-file` | `.env` 路径；缺省项目根 `.env` |
| `-DryRun` / `--dry-run` | 只预览将设置的键，不调用 gh（安全起见先用） |

### 2.5 行为与安全

- 仅提取 `SMTP_*` / `AUDIT_ALERT_THRESHOLD` 键，其余键忽略
- `.env` 缺失或为空的键自动跳过（不覆盖已存在的 Secret）
- **敏感值（SMTP_PASS 等）不打印明文**；dry-run 只显示键名
- 实际执行前建议 `gh secret list --repo owner/repo` 核对

### 2.6 验证

```powershell
# 写入后核对
gh secret list --repo owner/repo
# CI 验证：push 后 Actions → Audit Log Alert → Run workflow 手动触发一次
```

## 四、已知问题与修复记录

### 4.1 [已修复] setup_github_secrets.ps1 项目根路径解析错误

- **现象**：执行时提示 `env file not found: <项目>/scripts/.env`（找不到 `.env`）。
- **根因**：`$root = Split-Path -Parent $PSScriptRoot` 仅将 `scripts/dev/` 上移一级到 `scripts/`，未到项目根。
- **修复**：改用 `$root = (Get-Item $PSScriptRoot).Parent.Parent.FullName`（上移两级）。
- **验证**：`-DryRun` 输出 `source file: C:\Users\Administrator\agent\.env`（正确指向项目根）。

### 4.2 [已确认] 当前 .env 未配置告警密钥（7 项全部 skip）

- **现象**：`setup_github_secrets.ps1 -DryRun` 输出 7 项 `[skip] ... (missing or empty in .env)`。
- **原因**：`.env` 尚未配置「审计日志告警配置」段（非脚本 bug，属配置未就绪）。
- **处理**：从 `.env.example` 复制告警段（已含示例值）到 `.env` 并替换为真实值后重跑。

### 4.3 [提示] Windows PowerShell 5.1 与 UTF-8 中文

- 含中文注释/输出的 `.ps1` 在 **PowerShell 5.1**（按 ANSI 读取无 BOM 文件）可能解析失败；
  `setup_github_secrets.ps1` 已采用英文注释/输出规避；其余脚本建议用 PowerShell 7+（pwsh）执行。
