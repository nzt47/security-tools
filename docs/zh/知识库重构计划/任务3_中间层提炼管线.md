# 任务3：中间层提炼管线（Processed/Review）

**任务ID**: T3
**阶段**: 3（提炼层）
**前置依赖**: 任务1（ingest 产物 + `logbook.append_log`）、任务0（schema 字段约定）
**预计工作量**: 2-3 天
**输出类型**: Python 模块 + 提示词模板 + 测试

---

## 一、目标描述

实现"原文 → 结构化笔记"的 AI 提炼管线：消费任务1 的 inbox 素材，经 LLM 提炼为结构化笔记落入 `processed/`，人工或自动确认后作为任务2 产卡输入。本阶段是知识系统的"降噪缓冲层"，防止原文噪声直接污染 wiki。

【不易】约束：LLM 不可用（离线/超时/无 API Key）时**必须降级而非失败**——产出最小骨架笔记，不抛异常。遵循项目既有降级铁律。

### Step 2：提示词模板

新建 `agent/knowledge/prompts.py`：

```python
DISTILL_SYSTEM_PROMPT = """你是一位严谨的知识提炼者。将输入素材提炼为结构化笔记。
要求：
1. 提炼核心观点（3-8 条），每条约 30 字以内，只保留有信息量的陈述。
2. 标注知识要点与启发。
3. 必须提供至少一个反面案例或适用边界（防止断言过强）。
4. 建议 1-5 个可能相关的既有概念（用 slug）。
5. 用一句话概括全文核心洞见。
禁止添加素材中不存在的内容。"""

DISTILL_USER_TEMPLATE = """素材标题: {title}
素材来源: {source}
素材内容:
{content}
请输出 JSON（字段: core_points, knowledge_points, inspirations, counter_examples, suggested_links, one_line_insight）。"""
```

要求：`one_line_insight` 在产卡阶段（任务7）映射为 Card 的 `insight` 字段。

### Step 3：笔记持久化

笔记写入 `knowledge/processed/<slug>.md`，frontmatter 含：

```yaml
---
title: <标题>
slug: <slug>
source: <相对源路径>
source_hash: <sha256>
distilled: true
status: draft
distill_date: 2026-08-02
llm_model: <model>
confidence: 0.0-1.0
---
```

- 幂等：基于 `source_hash` 去重，同一素材重复 distill 只产生一条笔记（返回已存在笔记）。
- 敏感素材：meta 中 `sensitive=true` 的素材跳过提炼（不调用 LLM），记录 `distilled=false` + `reason=sensitive`。

### Step 4：LLM 服务接入

- 优先复用 `memory.llm_service.LLMService`（若可用），超时/异常捕获后降级。
- 无 API Key 或 `llm=None` 时直接返回骨架笔记。
- JSON 解析失败时：降级为骨架笔记（`distilled=false`），不崩溃。

### Step 5：编写单元测试

新建 `tests/unit/test_knowledge_distill.py`，覆盖：
- 正常提炼（mock LLM 返回合法 JSON）。
- LLM 抛异常/超时 → 骨架降级（`distilled=False`，不抛异常）。
- 无 API Key / llm=None → 骨架降级。
- JSON 解析失败 → 骨架降级。
- 重复提炼幂等（同 source_hash 不重复写）。
- 敏感素材跳过提炼（`reason=sensitive`）。
- `approve_note`/`reject_note` 状态变更。

运行命令：
