## 1. 修复的 Bug

### 1.1 【P0】删除有入链卡片不报 409（用户实测发现）

- **现象**：通过 UI 新建含 `[[双链]]` 的卡片后，删除被引用卡未返回 409。
- **根因**：`CardStore.create`（[card.py](file:///c:/Users/Administrator/agent/agent/knowledge/card.py)）原本**不解析正文双链**（仅 `update` 解析），新建卡 `links` 为空 → 入链索引（`index_links.md`）未登记 → 删除时 `_has_incoming_links` 查索引为空 → 删除成功而非 409。路由层 DELETE 逻辑本身正确。
- **修复**：`create()` 中 `if not card.links: card.links = parse_links(card.content)`（显式传入优先，与 `update` 语义对齐）。
- **回归验证**：新增 3 个单元测试 + 409 路由测试 + E2E 用例（见 §3）。

### 1.2 【P0】知识库 API 全部 404

- **根因**：`app_server.py` 从未注册 `/api/knowledge/*` 路由（`register_all_routes` 无调用方，知识库被遗漏）。
- **修复**：补注册 [routes_knowledge.py](file:///c:/Users/Administrator/agent/agent/server_routes/routes_knowledge.py)，并在启动时接线 `_Yunshu._card_store = CardStore("knowledge/wiki")`（此前运行时知识库 API 全 503）。

### 1.3 【P0】前端知识库视图整体丢失

- **现象**：`pages/Knowledge.tsx`、`components/Knowledge/*`、`api/knowledge.ts`、App.tsx 入口、组件测试全部缺失（与 `routes_knowledge.py` 一样遭受外部回滚丢失）。
- **修复**：完整重建（见 §2）。

### 1.4 【P1】两个预存 TypeScript 错误

| 文件 | 报错 | 根因 | 修复 |

| [useContextMonitor.ts](file:///c:/Users/Administrator/agent/yunshu-ui/src/hooks/useContextMonitor.ts) | TS2307 Cannot find module './usePolling' | `usePolling.ts` 模块缺失（同遭回滚） | 新建 [usePolling.ts](file:///c:/Users/Administrator/agent/yunshu-ui/src/hooks/usePolling.ts)（新增 Hook，见 §2.2） |

### 1.5 【P1】前端 409 提示显示"引用方: 未知"（E2E 验证时发现）

- **根因**：后端 409 响应的 `incoming_links` 为**顶层字段**，而 [apiClient.ts](file:///c:/Users/Administrator/agent/yunshu-ui/src/lib/apiClient.ts) 构造 `ApiError` 时只取 `p.details`（undefined），引用方列表丢失。
- **修复**：将完整错误 body 作为 `details` 传入（`violations`/`incoming_links` 等顶层字段均可达）。

### 1.6 【P2】演示数据静默创建失败

- **根因**：前端演示卡 `title='演示母卡' / slug='demo-母卡'` 不满足 `slug == slugify(title)` 校验 → 后端 422，前端 catch 仅吞 409，演示数据一直在静默失败。
- **处理**：随"移除自动带出逻辑"一并移除，不再存在（E2E 预置数据已修正 title/slug 一致）。

### 1.7 【P2】openDetail 详情竞态（性能检查发现）

- **现象**：快速连续点击 A→B 卡片时，若 A 的详情响应晚于 B 到达，`setDetailCard` 会用 A 覆盖 B 的详情。
- **根因**：`openDetail` 无并发守卫，异步响应无条件写入 state。
- **修复**：加请求序号守卫（[Knowledge.tsx](file:///c:/Users/Administrator/agent/yunshu-ui/src/pages/Knowledge.tsx#L134-L152)）：`detailSeqRef` 递增，响应到达时序号不匹配则丢弃（含成功与失败分支，`setDetailLoading(false)` 同样受守卫）。
- **回归验证**：新增测试「快速切换卡片时丢弃过期详情响应（竞态守卫）」。
