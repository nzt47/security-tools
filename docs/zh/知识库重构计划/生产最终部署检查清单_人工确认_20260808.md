# 生产最终部署检查清单（人工确认项）

> 适用范围：生产服务器正式上线 Alertmanager → 139 邮箱 SMTP 告警链路前，由运维人员**逐项人工确认**的清单。
> 与脚本自动检查（`verify_prod_alertmanager.sh`）互补：**本清单聚焦无法自动探测、需人工核实的服务端配置与组织级策略**。

- 建议归档到验证报告中（遗留问题表）。

## A. 防火墙 / 网络策略（人工核实项）

> ⚠️ 网络层的"放行是否已生效"可由 `verify` 自动探测；但**策略是否已申请、审批、生效范围、出网路径**必须人工确认。

| # | 检查项 | 确认方法 | 期望 | 确认 |
|---|---|---|---|---|
| A1 | 云安全组出站规则 | 云控制台 → 安全组 → 出方向规则 | 已放行目标 TCP **587**（可指定目的地址 `smtp.139.com` 解析的 IP 段） | ☐ |
| A2 | 云安全组入站规则 | 云控制台 → 入方向规则 | **无需**放行 587 入站（139 邮箱为纯出站需求） | ☐ |
| A3 | 宿主机 firewalld | `firewall-cmd --list-all` | 出站 587 未被 DROP/REJECT；若有白名单策略需含 587 | ☐ |
| A4 | 宿主机 iptables OUTPUT | `iptables -L OUTPUT -n` | 无 `DROP/REJECT` 全量策略，或已 `-A OUTPUT -p tcp --dport 587 -j ACCEPT` | ☐ |
| A5 | 宿主机 ufw | `ufw status verbose` | 出站 587 允许（或默认出站 allow） | ☐ |
| A6 | 中间链路（ISP/VPC 防火墙） | 在服务器 `nc -vz smtp.139.com 587` | TCP 握手成功（`Connection succeeded`） | ☐ |
| A7 | DNS 解析（smtp.139.com） | `getent hosts smtp.139.com` | 解析出 139 邮箱 SMTP 网关 IP（如 `120.232.169.x`），非内网 DNS 污染值 | ☐ |
| A8 | 容器网络出网 | `docker exec yunshu-prod-alertmanager sh -c 'exec 3<>/dev/tcp/smtp.139.com/587'` | 容器内可握手（monitoring-net → NAT 出网正常） | ☐ |
| A9 | 变更管理 | 安全组/防火墙变更记录 | 变更已按变更流程审批并留痕 | ☐ |
