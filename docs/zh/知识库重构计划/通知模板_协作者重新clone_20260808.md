## 邮件正文

各位协作者：

因仓库历史中曾包含敏感凭据文件（`_edge_profile`，浏览器本地配置，含真实账号数据），我们已于 2026-08-08 完成 **GitHub 与 Gitee 双远端的历史重写（git filter-repo）**，将相关路径从全部历史提交中移除，并强制推送了所有分支与标签。

### 需要你配合的操作（必做）

1. **本地旧仓库立即停止使用**（旧 clone 中仍含敏感数据，请勿再 push / 共享 / 归档）：
   ```bash
   # 旧仓库备份所需文件后，本地删除即可：
   # cp -r 需要的未提交文件到新目录，然后删除旧 .git 目录
   ```
2. **重新 clone 仓库**（或强制重置到新历史）：
   ```bash
   # 方式 A：重新 clone（推荐；GitHub 与 Gitee 历史一致，任选其一）
   git clone git@github.com:nzt47/security-tools.git    # GitHub
   # 或 git clone git@gitee.com:nzt47/security-tools.git  # Gitee
   cd security-tools

   # 方式 B：已有本地仓库强制重置
   cd <旧仓库目录>
   git fetch --all --prune
   git fetch --tags --force              # 重写后 tag 已更新，需强制拉取
   git reset --hard origin/<你的分支>      # 逐分支执行
   git push --force-with-lease origin <你的分支>
   ```
3. **核对远端 hash 已更新**（master 应等于 `ecd9a9cd`）：
   ```bash
   git ls-remote origin refs/heads/master
   # 期望: ecd9a9cdad5cdd10e672ac495727732128c17d64  refs/heads/master
   ```

### 注意事项

- ⚠️ **旧分支/旧 tag 的历史 commit 已不可达**，请勿基于旧 commit 创建新分支。
- 已合并 PR 的变更已保留在新历史中（重写仅移除敏感路径，不删除功能代码）；未合并 PR 的 head 分支已更新到新历史，GitHub 会自动重算 diff，合并前请在 PR 页复核。
- **安全提醒**：泄露的凭据已无法通过"删历史"完全消除，请相关人员尽快按《待办事项_账号轮换清单》轮换受影响的账号密码（139 邮箱、云平台 AK、GitHub/Gitee 会话等）。

如有问题请联系值班运维。
