# 紧急响应预案：_edge_profile 凭据泄露（已推送远端场景）

> 触发条件：确认 `_edge_profile`（Edge 浏览器本地配置）曾随仓库 push 到远端。历史中的真实凭据视为**已泄露**。
> 配套工具：[历史重写脚本](../../../scripts/rewrite_history_filter_repo.sh)（filter-repo 清历史 + 强推）。
> 处置时限：**30 分钟内完成账号轮换声明与强登出**（历史重写可随后，止损优先）。

## 0. 先判定：是否真的泄露

| 检查 | 命令 | 含义 |
|---|---|---|
| 是否有远端 | `git remote -v` | 无远端 → 未泄露，只需本地清历史/忽略 |
| 远端是否含旧历史 | `git ls-remote origin | head` 对照本地历史 hash | hash 一致 → 已推送 |
| 远端最近推送时间 | 云平台提交记录 | 若 push 发生在 2026-06-29（凭据入库）之后 → 泄露 |

> 不确定时按【已泄露】处置——历史不可撤销，宁可高估影响面。

## 1. 泄露影响面评估（Edge 配置数据类别）

`_edge_profile/` 泄露数据的风险分级：

| 数据类别 | 文件 | 风险 | 说明 |
|---|---|---|---|
| 会话 Cookies | `Default/Cookies` | 🔴 **极高** | session token 多为明文/Base64，**无需解密即可劫持会话**（免密登录态） |
| 本地存储 | `Default/Local Storage` | 🔴 高 | 含各站点 localStorage 里的 access token 快照 |
| 登录凭据 | `Default/Login Data` | 🟠 中-高 | Windows 下受 DPAPI 加密（需同机器同用户解密），但浏览器版本差异不可依赖；**仍视为泄露** |
| Vpn Tokens | `Default/Vpn Tokens` | 🔴 高 | VPN 会话令牌，可直连内网 |
| Trust Tokens / 网络配置 | `Network/*` | 🟠 中 | 可能含代理凭据等 |

## 4. 强制登出步骤（会话止损，优先于改密码）

> 原理：泄露的是**会话凭证**而非密码——改密码可能不失效已有会话，必须显式登出。

| 平台 | 强制登出操作 |
|---|---|
| 139/网易邮箱 | 设置 → 安全中心 → 登录设备管理 → 全部登出 |
| 云平台（阿里云/腾讯云/AWS） | 控制台 → 安全设置 → 会话管理 → 强制登出所有会话；AK 立即禁用 |
| GitHub | Settings → Security → Sessions → 逐条 Revoke；同时撤销 PAT/SSH key |
| 企业 SSO（钉钉/飞书/OA） | 管理后台 → 设备/会话管理 → 远程登出该设备 |
| 微信/支付宝 | 设置 → 账号与安全 → 登录设备管理 → 删除全部设备 |
| 通用 Web 站点 | 逐站「登出所有设备」功能；无此功能则改密码（多数平台改密码会使旧会话失效） |

**强制登出后**：本地浏览器清除全部 Cookie/缓存，或直接重置该 Edge 配置目录（备份后删除重建）。

## 5. 历史重写与协作者处置

1. 执行 [rewrite_history_filter_repo.sh](../../../scripts/rewrite_history_filter_repo.sh)（先阶段 1 验证，再 `--push --yes` 强推）。
2. 强推后通知协作者：
   ```bash
   # 各协作者本地（保留本地新提交前先 rebase 到新历史）
   git fetch --all --prune
   git reset --hard origin/<branch>
   # 或直接删除本地仓库重新 clone（最干净）
   ```
3. **原始本地仓库禁止再次 push**（旧对象仍在本地，`git push --force` 无法清除对象库，但正常 push 不会带旧对象；风险在于协作分支混杂）。稳妥做法：删除本地 `.git` 后重新 clone。
4. 重写后复检：`python scripts/recheck_sensitive_cleanup.py` 应全 PASS。
