## 4. 强推前注意事项

1. **冻结远端**：重写+强推窗口内，通知团队禁止 push（被覆盖的新提交将丢失）。
2. **PR 影响**：GitHub 存在 40+ PR refs（`refs/pull/*`）。重写后 PR 分支 hash 变化，未合并 PR 需重新推送或重建。
3. **Tags**：强推需同时推送 tags（脚本已含 `--tags`）。
4. **双远端顺序**：先重写+强推一个远端并验证，再处理第二个，降低双端同时出错的恢复成本。
5. **重写后**：所有协作者本地须强制重置或重新 clone（旧 hash 作废）。
