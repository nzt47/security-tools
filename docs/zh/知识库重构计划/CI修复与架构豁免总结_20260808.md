## 一、修复的 CI 缺陷

### 1. 工具模块测试：Windows runner 多行命令解析失败

- **文件**：`.github/workflows/tool-tests.yml`
- **提交**：`324a2e85`
- **症状**：Windows runner（默认 shell 为 PowerShell）解析多行 pytest 命令时报 `ParserError: Missing expression after unary operator '--'`
- **根因**：workflow 中多行命令使用 bash 的 `\` 行尾续行，PowerShell 不支持该语法
- **修复**：在"运行工具模块测试"步骤显式声明 `shell: bash`（git-bash 随 GitHub Windows runner 预装，行为与 Linux 一致）

### 2. 系统工具测试：过期 mock 目标

- **文件**：`agent/tests/test_system_tools.py`
- **提交**：`324a2e85`
- **根因**：`agent/system_tools.py` 已重构为门面（从 `agent.tools.shell_tools` / `agent.tools.process_tools` 重新导出），模块内不再存在 `subprocess`，但测试仍 patch 旧的 `agent.system_tools.subprocess`，导致 Linux runner 上 `AttributeError`
- **修复**（共 3 处）：
  - `agent.system_tools.subprocess.run` → `agent.tools.shell_tools.subprocess.run`
  - `agent.system_tools.subprocess.Popen` → `agent.tools.process_tools.subprocess.Popen`
  - `agent.system_tools._save_custom_whitelist` → `agent.tools.process_tools._save_custom_whitelist`

## 二、架构规则豁免登记

### ARCH-DEBT-008：links_index ↔ card 循环依赖

- **文件**：`docs/architecture/legacy_exemptions.json`
- **提交**：`324a2e85`
- **详情**：`agent.knowledge.links_index` → `agent.knowledge.card`
- **根因**：`links_index.py:88` 的 `rebuild_links_index` 函数内延迟 `import CardStore`，运行期安全（`card.py` 顶层导入 `links_index` 的 `read_links_index/update_links_delta` 时不会触发循环），但 `arch_rules` 静态分析仍检测到函数内 `from` 语句。与 ARCH-DEBT-003~006 同模式（commit `cea078d3` 的惰性导入修复，当时漏登此豁免）
- **后续消除**：将 CardStore 实例作为参数传入 `rebuild_links_index`，彻底消除静态依赖边

### ARCH-DEBT-009：card ↔ index 循环依赖

- **文件**：`docs/architecture/legacy_exemptions.json`
- **提交**：`43079c9a`
- **详情**：`agent.knowledge.card` → `agent.knowledge.index`
- **根因**：`index.py` 的 `update_links_delta/read_links_index` 相关函数内延迟 `import CardStore`，运行期安全（`card.py` 顶层导入 `index` 的 `update_index_delta` 时不会触发循环），静态分析仍标记，与 ARCH-DEBT-008 同模式
- **后续消除**：将 CardStore 实例作为参数传入相关函数，彻底消除静态依赖边
