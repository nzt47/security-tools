## 四、复盘教训（供后续参考）

1. **并行会话活跃时，主工作区任何 git 重写操作（rebase/stash）都有打断他人工作的风险**。本次 stash 期间并行会话持续写入文件，导致 pop 冲突与多次重试。正确做法：重写操作一律放独立 worktree。
2. **冲突解决时效性**：develop 在解决期间被并行会话推进 5 次（tracing/docs/perf/to_dict），每次都要重新同步；若并行会话持续活跃，应等其停止推送后再做合并，避免重复返工。
3. **merge-tree 预评估价值**：同步前用 `git merge-tree --write-tree` 预判新 commit 是否触及冲突文件，可避免盲目合并。
4. **CI 失败≠合并缺陷**：性能断言（206us vs 200us）与覆盖率口径问题均为环境/阈值类，需先定位失败 job 日志再下结论，避免误改代码。
