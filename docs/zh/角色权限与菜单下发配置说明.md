# 角色权限与菜单下发配置说明

> 适用范围：管理后台（yunshu-ui 前端 + app_server.py 后端）
> 最后更新：2026-08-21

## 1. 权限模型总览

- **权限码**：细粒度的权限标识（如 `system:user:view`），前端路由 `meta.authority` 与后端菜单节点 `authority` 共用同一套命名（契约）。
- **菜单下发**：`GET /api/auth/menus` 由后端按登录用户的角色/权限码过滤全量菜单目录（`_MENU_CATALOG`）后下发；前端仅负责渲染，不再参与权限判定。
- **过滤规则**（后端 `_filter_menus_for_user`，与前端 `filterMenus` 语义一致）：
  1. `admin` 角色通配——全量下发；
  2. 其余角色按权限码命中过滤（`authority in permissions`）；
  3. 子项全部被过滤的分组整体剔除；有部分子项可见时分组保留。
- **路由守卫**：前端 `AuthRoute` 校验当前路径是否在后端下发菜单的可达集合内，未下发 → 403。

## 2. 三角色配置对比

账号凭据（后端登录注册表 `api_auth_login`，密码均 `123456`）：

| 角色 | 登录账号 | 凭据来源 | 定位 |
|---|---|---|---|
| admin | 由环境变量 `YUNSHU_ADMIN_USERNAME`（默认 `admin`） | `YUNSHU_ADMIN_PASSWORD`（默认 `admin123`） | 超级管理员，全权限 |
| manager | `manager` | 内置 `_MOCK_MANAGER_PASSWORD` | 运营管理员，部分系统管理权限 |
| user | `user` | 内置 `_MOCK_USER_PASSWORD` | 普通用户，基础权限 |

权限码与可见菜单（`/api/auth/menus` 下发结果）：

| 权限码 | 对应菜单 | admin | manager | user |
|---|---|---|---|---|
| —（公开） | 仪表盘 `/`、工作台 `/workbench`、组件演示 `/demo`、数据导出 `/export` | ✅ | ✅ | ✅ |
| `system:view` | 系统管理分组 `/system` | ✅ | ✅ | ✅ |
| `system:user:view` | 用户列表 `/system/user` | ✅ | ❌ | ❌ |
| `system:role:view` | 角色权限 `/system/role`、菜单管理 `/system/menu` | ✅ | ✅ | ❌ |
| `system:audit:view` | 操作审计 `/system/audit` | ✅ | ✅ | ❌ |
| `system:notification:view` | 消息中心 `/system/notification` | ✅ | ✅ | ✅ |
| `system:view`（子项复用） | 系统日志 `/system/log` | ✅ | ✅ | ✅ |
| `system:log:export`（操作级） | 系统日志导出（按钮级控制） | ✅ | ❌ | ❌ |

关键区别：
- **admin**：无需权限码，`role == 'admin'` 直接通配全量菜单（即使 `permissions` 为空）；另显式持有操作级权限码 `system:log:export`（系统日志导出）。
- **manager**：拥有系统管理分组 + 角色权限/菜单管理/操作审计/消息中心/系统日志；**无**用户列表（`system:user:view`）与系统日志导出。
- **user**：拥有系统管理分组 + 系统日志（`system:view`）+ 消息中心（`system:notification:view`）；无用户列表/角色权限/操作审计。

## 3. 配置位置

| 项 | 后端（app_server.py） | 前端（yunshu-ui/src） |
|---|---|---|
| 全量菜单目录 | `_MENU_CATALOG`（传入 `PermissionManager`） | 路由注册用 `router/routes.tsx` 的 `appRoutes`（页面集合，非菜单源） |
| 过滤/判定逻辑 | `agent/permission_tool.py` 的 `PermissionManager`（`filter_menus` / `has_permission` / `register_role`） | 无（菜单直接渲染后端下发结果） |
| 账号权限 | `_MOCK_USER_ACCOUNT` / `_MOCK_MANAGER_ACCOUNT` / `_ADMIN_USER` | `mocks/devMock.ts` 的 `MOCK_USER` / `MOCK_ADMIN`（dev mock 兜底，无 manager） |
| 菜单接口 | `GET /api/auth/menus`（`api_auth_menus`） | `api/user.ts` 的 `getMenus()` |

## 4. 如何调整某个角色的可见菜单

给角色对应的账号 `permissions` 数组增删对应权限码即可（过滤逻辑无需改动）：

```python
# 例：给 manager 增加"消息中心"查看权限（已实施，见 app_server.py _MOCK_MANAGER_ACCOUNT）
_MOCK_MANAGER_ACCOUNT = {
    ...
    "permissions": [
        "dashboard:view", "workbench:use",
        "system:view", "system:role:view", "system:audit:view",
        "system:notification:view",   # 新增：消息中心可见
    ],
}
```

注意：改 `app_server.py` 后需重启后端进程生效；若前端使用 dev mock（`VITE_MOCK_API=true`），需同步改 `devMock.ts` 对应账号。
