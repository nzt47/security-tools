## 一、门槛裁定（演示门槛 vs 正式门槛 —— 两者不可混用）

| 门槛 | 值 | 定义位置（单点） | 适用 | 标注要求 |
|---|---|---|---|---|
| **正式门槛** | 每能力 **≥20 条同类轨迹** | `agent/digestion/models.py::MIN_SAME_KIND_TRACES = 20`（§3.3） | `borrowed → mirrored` 的**唯一**准入条件；**本演示不修改** | 报告中凡引用"是否满足 §3.3"处必须写"正式门槛 ≥20" |
| **演示门槛** | 每能力 **≥5 条同类轨迹** | 本方案（Owner 2026-09-12 默认授权，可在开工前覆盖） | **仅用于"演示声明"**：说明"样本量足以演示链路"，**不构成任何 stage 准入依据** | 所有演示输出（脚本 stdout、报告、UI 数据旁）必须显式标注"**演示门槛 ≥5**" |

**其余门槛一律取模块常量，不因演示下调**（这是本任务"不得调参刷过"的落点）：

| 门槛 | 值 | 单点定义 |
|---|---|---|
| 验收门回放条数 | ≥20 且逐例通过率 100% | `agent/digestion/gate.py::GATE_REPLAY_MIN = 20` |
| 验收门成功率 | ≥ 基线 × 0.98 | `agent/digestion/gate.py::GATE_SUCCESS_RATE_RATIO = 0.98` |
| 验收门 p99 | ≤ 上游（倍数 1.0） | `agent/digestion/gate.py::GATE_P99_RATIO = 1.0` |
| 内化①消化次数 | ≥50 | `agent/digestion/internalize.py::DIGEST_COUNT_MIN = 50` |
| 内化②月样本 | ≥200 | `agent/digestion/internalize.py::MONTHLY_SAMPLES_MIN = 200` |
| 内化④成功率 | ≥ 上游 × 0.98 | `internalize.SUCCESS_RATE_RATIO = 0.98` |
| 内化⑤p99（**一票否决**） | ≤ 上游 | `internalize.P99_RATIO = 1.0` |
| 内化⑥隐私闸门（**一票否决**） | `data_class ∈ {public, internal}` 且不出域 | `internalize.PRIVACY_OPEN_CLASSES` |
| 判定集规模 | 30–100 组 | `agent/digestion/cases.py::MIN_CASE_SET_SIZE / MAX_CASE_SET_SIZE` |
| 灰度每日预算 | `min(日均 × 15%, 50)`，低流量保底 | `shadow.SHADOW_BUDGET_RATIO / _CAP / _MIN_BUDGET` |

**两者在报告与 UI 数据旁的区分方式（硬性）**

1. **脚本 stdout**：采集阶段同时打印 `同类轨迹（正式门槛 ≥20）` 与 `同类轨迹（演示门槛 ≥5）` 两行，
   且各自带 `达标=` 布尔；
2. **报告**：凡出现"条数"的地方，第一次出现时必须带门槛归属（如"27 条 ≥ 正式门槛 20"）；
3. **UI 数据旁**：面板本身**不填任何演示数据**（S6-01 的正向行为）；演示门槛声明以
   **本次任务的验收报告与演示记录**为准，面板数字一律是真实事件数与真实 stage 分布；
4. **禁止表述**：不得写"已实现真实能力内化"；正确表述为"**在真实数据上按正式门槛跑通内化链路，
   并产出可人工合入的 `stage.promote` PR（本地）**"。

## 二、演示目标能力（建议 2–3 个，本次取 1 个主能力）

| 能力 | 选择理由 | 副作用 | 是否本次主演示 |
|---|---|---|---|

| `cp.builtin.write_file` | 报告产出 | 可控（写入专用 `out/` 目录，可逆） | ✅ 作为**链内步骤**参与（不单独验收） |

**任务链设计**（真实、可回放、副作用可控）：

```
真实任务指令（同一句，只有目标模块在变）：
  「审计模块的公开行为并产出审计报告：读取源码，运行它的真实测试，仅当测试通过时写出审计报告」

① read_file(src/mod_NNNN.py)                        ← 只读
② shell_execute("python -m pytest tests/test_mod_NNNN.py -q")   ← 真实子进程
③ write_file(out/audit_NNNN.md, <由真实结果拼出的审计报告>)      ← 仅当①真实测试通过
```

- 被测工作区含 **240 个真实模块**（真实源码 + 真实 pytest 用例）；每 10 个注入 **1 个真实缺陷** →
  其真实测试**真的失败** ⇒ 任务级 Trace 落 `error`（这是真负样本，不是编造的分支）；
- 同一句任务指令经 `cleaning.normalize_intent()` 归一后**抹掉具体数字/路径** ⇒ 不同目标模块的同类任务

## 三、开关演示期配置与快照（合规前置）

| 开关 | 默认 | 演示期 | 理由 |
|---|---|---|---|
| `CP_DIGESTION_SHADOW_ENABLED` | **false（默认关闭）** | **true（显式开启）** | shadow 自动运行必须显式开（§4.5）；演示期开、结束**必须复位** |
| `CP_DIGESTION_SHADOW_BUDGET_RATIO` | 0.15 | 不动（0.15） | 每日预算由引擎算：`min(日均 × 15%, 50)` ⇒ **小预算**由引擎保证 |

| `CP_DIGESTION_GRAY_ENABLED` | false | 不动（false）；灰度比例走**能力级** `shadow_config={"enabled": true, "gray_ratio": 0.05}` | 不改全局开关；灰度只"记录选中"，`real_takeover=False` |
| `CP_DIGESTION_JUDGE` | auto | 不动（auto） | 本环境无 LLM-judge 凭证 ⇒ 引擎**如实回落** `deterministic_local(llm_unavailable)` 并标注 `judge_kind` |
| `CP_DIGESTION_REPROBE_ENABLED` | false | 不动（false） | 漂移重探不在本演示范围 |
| `CP_DIGESTION_INTERNALIZE_ENABLED` | false | 不动（false） | 内化调度不自动跑；演示由脚本显式驱动 |
| `CP_DIGESTION_SANDBOX_DENY_EXTERNAL` | 未设置 | **删除**（=允许沙箱内"模拟外部调用"） | 回放只记账不真实执行（record-and-replay）；真实执行发生在采集期 |
| `AUDIT_CHAIN_ENABLED` | 1 | 不动 | 链式审计保持开启（内化①digest_count 的数据源） |

**快照方式**：`agent/digestion/switch_snapshot.py::switch_snapshot()` 同时记录
**原始 env 值**与**引擎算出的生效值**（含非法值回退说明），并在演示前 / 演示期 / 演示后各打一次，
`diff_snapshots()` 给出**机器可判的复位结论**（`identical=true` 即已复位）。

**运行时目录（显式传入，不使用隐式默认）**

| 用途 | 目录 | 覆盖方式 |

| ToolDescriptor 台账 | `<部署根>/data/descriptors.json` | `DescriptorRegistry(path=...)` |

## 五、风险与预案（与任务书 §五 对齐）

| 风险 | 预案 |
|---|---|
| 真实任务量不足以产生 ≥5 条同类轨迹 | 本轮实测远超：正式门槛 ≥20 亦达标；若未达则如实记录"未能完成真实内化演示"并给出所需条数，**绝不用合成数据补足** |
| 副作用操作在真实环境有风险 | 主能力为只读 `read_file`；`shell_execute` 只在受控工作区内跑 `pytest`；`write_file` 只写 `out/` 目录（可逆） |

| 演示被误读为"已实现真实内化" | 口径纪律：所有输出旁标注门槛归属；报告首页写明确认声明（§零） |
| 灰度 p99 为噪声翻转（条件⑤一票否决） | **如实记录**为"未通过"并给出所需条件（增加真实样本量/延长观测窗口）；**不调参放行** |
