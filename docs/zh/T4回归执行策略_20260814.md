# T-4 回归执行策略（重规划，2026-08-14）

**背景**：2026-08-14 两轮 T-4 全量回归均未完整覆盖——
1. 单进程全量（`--randomly-seed=20260813`）：63% 被 e2e 热更用例 `t.join()` 卡死（thread 超时无法中断）
2. 分块 4×1（all 模式）：chunk_0/1/2 被 D 类慢测试（importlib `_path_stat` / pydantic_settings）触发 pytest-timeout **强制终止**（`os._exit(1)` 无汇总），仅 chunk_3 完整（3662 passed 全绿）
3. 并行会话 pytest（PID 13156 并发跑 tests/unit）显著放大慢路径 → 凌晨全绿的 chunk 白天崩溃

**前置**：P1 A3 slow 分流已实施（`run_full_pytest.py` fast/slow/all 三模式 + 4 处 slow 标注），本策略依赖 A3。

## 一、避开并行会话（执行前检查）

| 检查项 | 命令 | 判定 |
|---|---|---|
| 并行会话 python 进程 | `Get-Process python \| Select Id, StartTime, CPU` | 存在 StartTime 接近当前且 CPU 持续增长 → 并行会话活跃，**等待其结束** |
| 并行 worktree | `git worktree list` | 多 worktree 且 index 共享 → 会话活跃，避免同时提交 |
| 工作区漂移 | `git status --short` 两次间隔对比 | 文件集合变化 → 并行会话在写入，等待 |
| 建议窗口 | 凌晨 02:00-06:00 或并行会话完成后 | 负载低，D 类慢测试可正常完成 |

> 【不易】记忆教训：并行会话活跃时共享 index 会被清空（git add 后 diff --cached 为 0）；回归期间禁止跨会话提交。

## 二、完整 523 文件覆盖编排（A3 分流后）

fast（排除 4 处 slow 标注）+ slow 单独 = 完整覆盖，且 chunk 不再被 D 类卡死。

### Phase 1: fast 分块回归（519 文件，覆盖主体）

```bash
python scripts/run_full_pytest.py 4 1 fast
```

- 4 块 × 1 worker 串行；每块 `-m "not slow"`（排除 4 处 slow）
- 预期：各 chunk 完整输出 `=+ N passed` 汇总；预计总时长 25-40 分钟
- **判定标准（重要）**：不能只看 rc——chunk 被强杀时 rc=1 且**无 `passed` 汇总行**；必须逐 chunk 核验汇总行存在（记忆教训：判定 chunk 完整性须查汇总行而非仅 rc）

### Phase 2: slow 单独跑（4 文件，D 类监控）

```bash
python scripts/run_full_pytest.py 1 1 slow
```

- 单块 `-m slow --runslow --timeout=300`
- 覆盖：weekly_report_generator / task_scheduler / task_scheduler_integration / e2e 热更用例
- 容忍 os.stat/importlib 慢路径（300s 余量），超时标记但进程不再被 60s 强杀
- 预期：Timeouts 记录为 D 类已知项，非失败判定

### Phase 3（可选）: T-4 固定 seed 顺序污染验证（fast 语义）

```bash
python -m pytest tests/ -q --randomly-seed=20260813 -m "not slow"
```

- **不能用分块模式**（破坏 pytest-randomly 全局随机顺序）；单进程命令行保持固定 seed 语义
- 排除 slow 避免撞 D 类卡死；B 类顺序污染验证仍完整（B 类用例均非 slow）
- 预计 25-35 分钟
