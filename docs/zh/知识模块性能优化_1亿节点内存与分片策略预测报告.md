## 2. 1 亿节点分片策略

### 2.1 片数权衡（5000 万 → 1 亿演进）

| 片数 | 单片 refs 驻留 | 并行全扫（理想） | 判定 |
|---|---|---|---|
| 256 | ≈50 MB | ≈88 秒 | 5000 万基线，1 亿单片内存偏高 |
| **512** | **≈25 MB** | **≈44 秒** | **推荐（可跨机分布）** |
| 1024 | ≈12.5 MB | ≈22 秒 | 过度分片（元数据/路由成本主导） |

**推荐 512 片**：单片 25 MB 可整片常驻单机内存；512 片可分布到 8–64 台节点（每机 8–64 片），refs 12.8 GB 总量跨机承载。

### 2.2 分布式分片拓扑

```
ref_slug_hash = hash(ref_slug) % 512
shard_file = index_links/<shard_id>.md      # 分布式存储/对象存储
shard_owner = shard_id // 每机片数           # 分片归属节点
```

- 写路径：add/remove 路由到片 owner 节点（单片读写，无跨机事务）；
- 读路径：`_has_incoming_links` 需跨片合并查询——**必须配二级前缀索引**（`<shard>/<prefix>.idx`）或将入链倒排预聚合（读时只查目标 slug 相关前缀）；
- 一致性：跨片无原子性 → 最终一致（写补偿/重放），与现有「增量叠加 == 全量重建」不变量按片改写对齐。

### 2.3 降级机制映射（1 亿）

| 降级机制 | 5000 万（256 片单机） | 1 亿（512 片分布式） |
|---|---|---|
| 索引损坏回退 | 单片秒级 | 单片秒级 + 远程重拉（节点故障时） |
| 写失败不阻断 | 不变 | 不变（片级隔离 + 重放队列） |
| 全量重建 | 并行 44 秒（理想） | 分布式并行（Map-Reduce 形态），分钟级 |
| 全局一致性校验 | 片级断言 | 片级 + 跨片对账任务 |

## 3. 存储层：1 亿文件数的必然性

| 项 | 数值 | 影响 |
|---|---|---|
| 卡片文件 | 1 亿个 `.md` | 单机文件系统不可行 |
| 目录策略 | `wiki/<type>/<slug 前 2 字符>/` | 仍约 256×3 子目录、每目录 ≈13 万文件（偏高） |
| 最终形态 | **对象存储**（key = `cards/<type>/<slug>.md`） | 无限扩展、无目录深度限制 |

**结论**：1 亿节点下对象存储不是可选项而是必须项；「全库 list()/重建」的遍历基准（0.225 ms/卡）在对象存储上需重新标定（批量 list + 前缀扫描）。

## 6. 结论与建议

| 决策维度 | 1 亿节点评估 |
|---|---|
| 内存（现状） | ≈185.8 GB：完全不可行 |
| 内存（流式单机） | ≈12.8 GB：refs 本体即超单机内存 |
| 内存（分片 512 片分布式） | ≈25 MB/片：可控，跨机分布 |
| 耗时（全扫） | 流式 6.25 小时 vs 分片并行理想 44 秒 |
| 存储 | 1 亿文件数 → **对象存储必须** |
| 架构判定 | **分布式架构执行线**（跨机分片 + 对象存储） |

**建议**：

1. **512 片分布式分片为 1 亿基线**：单片 25 MB 常驻单机、512 片跨 8–64 节点分布；写路径单片路由无跨机事务，读路径配二级前缀索引/入链预聚合。
2. **对象存储落地前置**：1 亿卡片文件在单机文件系统下不可行；存储层改造优先于索引层（索引分片依赖存储能力）。
3. **一致性与可观测**：分布式下引入最终一致（写补偿/重放）+ 跨片对账任务；「各片叠加 == 对应片重建」片级断言自动化扩展为分布式对账。
4. **监控阈值更新**：refs > 2 GB（≈1600 万卡）评估 128+ 片；refs > 8 GB（≈6000 万卡）评估分布式 512 片；文件数 > 1000 万启动存储层改造，> 1 亿必须对象存储。
5. **架构落地节奏**：先流式（≤200 万执行）→ 单机分片（200 万–5000 万）→ 分布式分片 + 对象存储（5000 万–1 亿），每步独立可回滚、均有既有测试基线。
