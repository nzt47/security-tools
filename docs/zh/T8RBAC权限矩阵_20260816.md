## 1. 双层认证模型（先看这节再读矩阵）

| 层 | 通道 | 认证 | 适用端点 | 判定逻辑 |
|---|---|---|---|---|
| **内部管理层** | `/api/open/tenants*`、`/api/open/keys`、`/api/open/stats`、`/api/docs` | `FLASK_API_TOKEN`（`X-API-Token` / `Bearer`，`require_token` 装饰器） | 租户/Key/配置管理等**管理操作** | 静态令牌比对（`secrets.compare_digest`）；**不适用角色矩阵** |
| **开放 API 层** | 灰度开放内部端点（`/api/news` 等 8 个） | API Key（`X-API-Key` / `Bearer`） | 只读业务端点 | `check_scopes`：绑定租户 → 角色权限表（本矩阵）；未绑定 → 自带 scopes 白名单 |

> 管理端点在 T8.2 后仍保持 `FLASK_API_TOKEN` 内部通道（守【不易】：管理操作不外放）；RBAC 矩阵作用于开放 API 层的 scope 校验。

## 2. 角色 × 权限矩阵（真实映射）

来源：`multi_tenant.has_permission` 的 `permission_map`（[multi_tenant.py L262-267](file:///c:/Users/Administrator/agent/agent/multi_tenant.py#L262-L267)）：

| 角色 | read | write | delete | manage | admin |
|---|---|---|---|---|---|
| **owner**（租户拥有者） | ● | ● | ● | ● | ● |
| **admin**（管理员） | ● | ● | ● | ● | ○ |
| **member**（成员） | ● | ● | ○ | ○ | ○ |
| **viewer**（只读） | ● | ○ | ○ | ○ | ○ |

- ● = 有权 · ○ = 无权
- 多角色取并集：用户在某租户被分配多个角色时，任一角色含该权限即放行
- **租户链继承**：`get_user_roles` 沿 `tenant.parent_id` 向根方向收集角色（组织→工作空间），子租户继承父租户角色权限

### 2.1 scope → PermissionType 映射（check_scopes）

来源：[api_gateway.py L422-425](file:///c:/Users/Administrator/agent/agent/api_gateway.py#L422-L425)

| scope | PermissionType |
|---|---|
| `read` | READ |
| `write` | WRITE |
| `delete` | DELETE |
| `manage` | MANAGE |
| `admin` | ADMIN |

**判定规则**（`check_scopes`）：
- 端点要求 scope 集 = 全部通过（AND 语义）
- Key 绑定 `tenant_id`：逐 scope 映射为 PermissionType，调 `tenant_manager.has_permission(user_id, tenant_id, perm)`（支持租户链继承）
- Key 未绑定（旧 Key 兼容期）：回退 Key 自带 `scopes` 白名单，不做角色判定

## 3. 端点访问控制矩阵

### 3.1 内部管理端点（FLASK_API_TOKEN，角色矩阵不适用）

| 方法 | 路径 | 说明 | 认证 |
|---|---|---|---|
| POST | `/api/open/tenants` | 创建组织租户（自动 owner） | require_token |
| GET | `/api/open/tenants` | 租户列表 | require_token |
| GET/DELETE | `/api/open/tenants/<id>` | 租户详情/删除 | require_token |
| POST | `/api/open/tenants/<id>/users` | 创建用户+角色 | require_token |
| POST | `/api/open/tenants/<id>/users/<uid>/roles` | 分配角色 | require_token |
| GET | `/api/open/users/<uid>/tenants` | 用户所属租户 | require_token |
| GET/POST | `/api/open/tenants/<id>/config` | 租户配置（含继承） | require_token |
| GET | `/api/open/tenants/<id>/usage` | 用量统计 | require_token |
| POST/GET | `/api/open/keys` | Key 创建（单次明文）/列表（脱敏） | require_token（POST 创建走网关原生路由，无 require_token；见 §4 例外） |
| GET | `/api/open/stats` | 网关统计 | 无（信息泄露风险低） |
| GET | `/api/docs` | 全量 Swagger | 无 |

### 3.2 开放 API 端点（API Key + scope，按角色判定）

当前 8 个灰度端点**全部只读**，要求 `scope=read` → 判定为 `PermissionType.READ`：

| 端点 | scope | owner | admin | member | viewer | 未绑定 Key |
|---|---|---|---|---|---|---|
| `GET /api/news` | read | ● | ● | ● | ● | ●（自带 scopes 含 read） |
| `GET /api/search-performance/status` | read | ● | ● | ● | ● | ● |
| `GET /api/search-performance/history` | read | ● | ● | ● | ● | ● |
| `GET /api/search-performance/summary` | read | ● | ● | ● | ● | ● |
| `GET /api/audit/logs` | read | ● | ● | ● | ● | ● |
| `GET /api/schedules` | read | ● | ● | ● | ● | ● |
| `GET /api/skills` | read | ● | ● | ● | ● | ● |
| `GET /api/tasks` | read | ● | ● | ● | ● | ● |

- 所有角色均含 READ → 8 个只读端点对全部角色开放
- **无 Key → 401**；**scope 不足 → 403**；**限流/配额超限 → 429**
- ⚠ 数据隔离注意：`/api/audit/logs` 当前为**全局日志未按租户过滤**（故障演练剧本场景 B 已确认中风险），租户 A 的 Key 可读到全部审计记录；缓解排期见剧本 B.3

### 3.3 写操作 / 内部业务端点（双轨制）

| 类别 | 路径示例 | 认证 |
|---|---|---|
| 内部写操作（POST/PUT/DELETE） | `/api/search/instances`、`/api/knowledge/cards`、`/api/llm/instances` 等 | `FLASK_API_TOKEN`（require_token） |
| 内部只读（含 require_token） | `/api/llm/instances` GET、`/api/config/logs`、`/api/knowledge/cards` GET | `FLASK_API_TOKEN`（require_token） |
| 内部只读（无 require_token，未开放） | `/api/sessions`、`/api/personality` 等 | 无（内网语义，未开放） |

> 带 `require_token` 的内部端点**不得直接灰度开放**：网关 Key 与 `FLASK_API_TOKEN` 双重认证冲突（`_wrap_internal_view` 会二次触发 require_token → 生产 401）。开放前须先做认证合并（远期）。

## 4. 边界与例外

| 项 | 规则 |
|---|---|
| 旧 Key 兼容期 | 未绑定租户 Key 走自带 scopes 白名单；`compat_until` 过期后返回 403「请迁移至租户绑定 Key」（90 天窗口，`scripts/migrate_api_keys_to_tenant.py`） |
| `/api/open/keys` POST | 网关原生路由（未注册进 `gw._endpoints`），当前**无 require_token**；建议补内部令牌保护（管理语义） |
| 配额/限流 | 与 RBAC 正交：用户级 + 租户级配额独立计数；五级限流（全局→接口→租户→用户→并发） |
| 角色分配入口 | 仅管理端点（内部令牌）；开放 API 不提供自服务角色变更 |
| `echo` 探活 | `/api/open/echo` 无鉴权（仅返回存活状态，无业务数据） |

## 5. 建议（第三批灰度时的 scope 设计）

| 端点类型 | 建议 scope | 允许角色 |
|---|---|---|
| 只读业务数据 | `read` | viewer+（全角色） |
| 用户私有数据（会话/记忆） | `read` + **服务端按租户过滤** | viewer+（须过数据隔离检查单） |
| 写操作（远期认证合并后） | `write` | member+（owner/admin/member） |
| 删除操作 | `delete` | owner/admin |
| 配置变更（远期） | `manage` | owner/admin |
| 全局管理 | `admin` | owner |
