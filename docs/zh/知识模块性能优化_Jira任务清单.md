## KN-101 流式扫描落地（iter_cards）

- **组件**：`agent/knowledge/card.py`、`agent/knowledge/links_index.py`
- **描述**：实现 `iter_cards()` 生成器（逐卡扫描，免全库 Card 对象驻留），重构 `rebuild_links_index` 全量重建与 `delete_many` 回退全扫为流式读取；内存 O(N) → O(U)。
- **背景**：实测 3000 卡全峰值 5.6 MB；100 万卡外推 ≈1.8 GB（list()）vs ≈128 MB（流式）。方案详见《流式扫描优化方案草稿》。
- **验收标准（DoD）**：
  1. `iter_cards()` 逐卡产出 Card，单次驻留 ≤1 张 + refs 映射；
  2. 重建/回退路径改用流式，**入链判定结果与 list() 版本逐字节一致**；
  3. 索引缺失回退全扫路径内存峰值下降 ≥10x（10 万卡基准）；
  4. links_index 11 项一致性/幂等测试 + 回归 70+ 全绿。
- **依赖**：无（可在 ≤200 万卡执行线内独立落地）
- **风险**：损坏卡容错（跳过 + 计数告警）需保持现有语义

## KN-102 容量监控埋点落地

- **组件**：`agent/knowledge/links_index.py`、`agent/knowledge/card.py`、`.env`
- **描述**：落实复盘遗留项「监控阈值未落地代码」——refs > 512 MB（≈400 万卡）触发分片评估告警；文件数 > 1000 万触发存储层改造告警。阈值经 `.env` 配置。实现方案见《监控埋点实现方案草案》。
- **验收标准（DoD）**：
  1. `read_links_index` / `rebuild_links_index` 解析后统计 refs 条目数并输出 info 日志；
  2. 超阈值时输出可检索 WARNING（含 refs 估算/文件数/阈值）；
  3. 阈值经 `.env`（`KNOWLEDGE_LINKS_REFS_ALERT_MB` / `KNOWLEDGE_CARD_FILE_ALERT_COUNT`），缺省回落 512 / 1000 万；
  4. 新增 ≥3 项单测（超阈值告警、未超阈值静默、env 覆盖），回归全绿。
- **依赖**：无

## KN-103 分片架构前置设计

- **组件**：`docs/zh/`（设计文档）
- **描述**：≥500 万卡前置准备——分片路由（`hash(ref_slug) % N`）、跨片一致性（补偿/重放/对账）、重建并行化。片数基线：64 片/2000 万、256 片/5000 万、512 片/1 亿、4096 片/10 亿。
- **验收标准（DoD）**：
  1. 输出分片设计文档（路由、写路径、读路径、对账、不变量改写「各片叠加 == 对应片重建」）；
  2. 明确分片与流式（KN-101）的关系——流式为分片的基础形态；
  3. 评审通过后归档。
- **依赖**：KN-101（先落地流式形态）
- **风险**：容量模型已验证 2^20 片后边际收益收敛，设计需说明分片上限

## KN-104 存储层二级目录/对象存储评估

- **组件**：调研任务
- **描述**：≥5000 万卡文件数瓶颈评估——二级目录分层（`<type>/<前缀>/<slug>.md`）、对象存储（分桶）可行性、遍历基准重新标定（现有 0.225 ms/卡 在 5000 万文件规模失效）。
- **验收标准（DoD）**：
  1. 输出存储层改造评估报告（成本/性能/迁移/回滚）；
  2. 给出阈值建议（文件数 > 1000 万 触发，与 KN-102 联动）。
- **依赖**：无

## KN-105 Confluence 推送

- **组件**：文档运维
- **描述**：将《第二批对比报告》《架构演进总结》推送至 Confluence。缺凭据（`CONFLUENCE_BASE_URL` / `CONFLUENCE_USER` / `CONFLUENCE_TOKEN`），待提供后执行；备选：团队 Wiki 已覆盖（`docs/wiki/`）。
- **验收标准（DoD）**：两页面成功创建（Space 确认 + 链接回填）。
- **依赖**：凭据提供
