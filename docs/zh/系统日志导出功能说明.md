# 系统日志导出功能说明（最小落地版）

> 更新：2026-08-21
> 关联：[角色权限与菜单下发配置说明](./角色权限与菜单下发配置说明.md)

## 1. 当前实现（最小落地版）

### 权限判定链路

```
后端 /api/auth/menus（按角色下发可见菜单 + user.permissions）
        ↓
前端 userStore.userInfo（登录强制刷新拉取，含 role + permissions）
        ↓
usePermission('system:log:export')        ← src/hooks/usePermission.ts
        ↓（复用 hasAuthority，语义与后端 PermissionManager.has_permission 一致）
导出按钮显隐（admin 通配 / 命中权限码）
```

- 权限码：`system:log:export`（操作级，非菜单权限码）
- 持有者：admin（`_ADMIN_USER.permissions` / devMock `MOCK_ADMIN`）；manager、user 无

### 导出实现（src/pages/system/SystemLog.tsx）

- 数据：本地 `MOCK_LOGS`（6 条占位日志，表格展示）
- 导出：`handleExport()` 将表格生成 CSV（带 BOM，Excel 中文不乱码），Blob + `<a download>` 下载，文件名 `system-log-YYYY-MM-DD.csv`
- 按钮：`usePermission('system:log:export')` 为真才渲染

### 相关文件

| 文件 | 职责 |
|---|---|
| `src/hooks/usePermission.ts` | 操作级权限判定 hook（复用 `hasAuthority`） |
| `src/pages/system/SystemLog.tsx` | 页面：mock 表格 + 导出按钮 + CSV 导出 |
| `src/hooks/usePermission.test.tsx` | hook 单测（5 用例） |
| `src/pages/system/SystemLog.test.tsx` | 组件单测（5 用例：渲染/权限显隐/导出链路） |

## 2. 后续接入真实后端日志数据

### 方案 A：前端拉取数据，前端导出（改动最小）

1. **后端新增查询接口**：`GET /api/system/logs?page=&pageSize=&keyword=`，返回 `{list, total}`（日志表结构：`time/operator/action/result`，与前端表格列对齐）
2. **前端替换数据源**：`MOCK_LOGS` → `getSystemLogs()` 接口（新增 `src/api/systemLog.ts`），页面改为「拉取 → 表格渲染」；导出逻辑不变（导出当前已加载数据）
3. **注意**：导出仅覆盖已加载页（分页数据），大数据量需导出全部时走方案 B

### 方案 B：后端导出（大数据量推荐）

1. 后端新增 `POST /api/system/log/export`，服务端按查询条件生成 CSV 流返回
2. 前端导出按钮改为：`usePermission` 控制显隐 → 调导出接口 → 以 Blob 接收并触发下载
3. 权限校验：后端接口内校验 `system:log:export`（`PermissionManager.has_permission(user, 'system:log:export')`），与菜单接口同源

### 接入检查单

- [ ] 后端日志表/数据源就绪（表结构对齐 `time/operator/action/result`）
- [ ] `GET /api/system/logs`（方案 A）或 `POST /api/system/log/export`（方案 B）实现
- [ ] 后端接口测试：登录鉴权 + 权限码校验（参考 `tests/unit/test_auth_menus_login.py` 风格）
- [ ] 前端 `src/api/systemLog.ts` + 页面数据源替换
