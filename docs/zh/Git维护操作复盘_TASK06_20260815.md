## 二、git gc 执行与数据对比

### 执行策略（已沉淀为 SOP §三-E）

1. **前置检查**：`Get-Process git` 计数期望 0（并行会话空闲确认）
2. **轮询等待空闲窗口**：每 15s 检查，无活跃 git 进程才执行（本次 0s 即空闲）
3. **默认参数** `git gc --quiet`：仅清理 2 周前不可达对象；**禁 `--prune=now`**（reflog 可达对象受 90 天保留期保护，防误伤并行会话中间产物）
4. **gc 后验证**：HEAD / worktree 数 / 并行会话均不受影响

### gc 前后数据对比（`git count-objects -vH`）

| 指标 | gc 前 | gc 后 | 变化 |
|---|---|---|---|
| loose objects (count) | 673 | **0** | -673 |
| loose size | 3.09 MiB | **0 bytes** | -3.09 MiB |
| in-pack objects | 39100 | 39775 | +675（被重新打包） |
| packs | 3 | **2** | -1（合并） |
| size-pack | 57.57 MiB | **56.37 MiB** | -1.20 MiB |
| prune-packable | 0 | 0 | — |
| garbage | 0 | 0 | — |

**收益**：loose 对象清零（主要收益）+ pack 合并；size-pack 压缩有限（打包算法所致，符合预期）。
