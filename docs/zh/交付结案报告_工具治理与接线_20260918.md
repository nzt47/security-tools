## 二、核心成果

### 2.1 治理：审批边界从"看得见拦不住"变成"能走通的闭环"

**问题**：闸门的审批步骤默认只告警，而唯一 fail-closed 的 `HITLManager.assess` **在生产代码里零调用方**（只有测试引用）⇒ 91 个工具里 10 个 `needs_approval`（含 `shell_execute`/`generate_tool`/`run_sandbox` 三个 critical）**无人确认即可执行**。

**交付**：命中 ⇒ 幂等挂单（与审批收件箱同库同源）⇒ 返回 `APPROVAL_REQUIRED` + `approval_id` + 恢复指引 ⇒ 人工批准 ⇒ **原样重试即放行**（单次有效、参数与会话绑定、TTL 900s 自**裁决时刻**起算）⇒ 驳回返回 `APPROVAL_REJECTED` + 理由。默认开关反转为开，回滚＝一处环境变量。

过程中修掉 6 个真缺陷（详见 2.4）。

### 2.2 端点：9 条"曾经 404"的 API 全部上岗（真 HTTP 实测）

| 端点 | 症状 | 根因 | 处置 |
|---|---|---|---|
| `/api/vector/stats|recent|add|batch_add|item/<id>|clear`、`/api/knowledge/add`、`/api/memory/review`（8 条） | 线上 404，而 `/legacy` 页面正在调它们 | `routes_memory` 从未注册，而 `app_server.py:970` 的注释写着"旧版 index.html 已归档、不再调用"——**该前提是假的** | 只把缺失的 8 条补进 `plugins/memory.py`（**不能整模块注册**：22 条里 14 条已活，整注册会同路径重复），退役旧模块 |
| `/api/orchestrator/semantic-config`（GET+POST） | 线上 404 | orchestrator 在读 `_SEM_API_OVERRIDE` 最高优先级覆盖，写入侧却不存在 | 两条 handler 摘到新模块 `routes_semantic_config.py` 单独接线 |

## 三、遇到的问题与解决方案（方法层面，值得复用）

1. **静态阅读会同时高估与低估不可达性**——两次实证：
   - `probe_trend` 按**符号**查 0 引用，按 **URL 路径**查有 3 个真实消费方（连字符导致符号口径漏判）⇒ 差一步就误删活代码；
   - `learning_metrics_view` 因 Blueprint 装饰器掩盖 `__module__`、`RuleEngine/StatsEngine` 因 `self.x.` 调用不重复类名 ⇒ 纯文本计数必然误判。
   **结论**：删代码前必须换口径再验一次；审计报告里"其实是活的"一节比清单本身更有价值。
2. **"测试绿、线上 404"是本仓的重复病灶**：`/api/agent-lines`、`/api/approval/*`、8 条 memory 端点都是同一坑（测试手搓 `Flask(__name__)`，生产走 `app_server.py`）。
   **结论**：验证必须走**真实入口**（`import app_server` + url_map），必要时真起服务发 HTTP。已固化为守门测试。
3. **"路径存在"≠"行为等价"**：审计据"MISSING=0"建议删 10 个模块，我不采纳——`routes_memory` 正是反例（14 条活着、8 条缺口）。
4. **脚本化删除必须有边界**：我用 `\nclass X[\s\S]*?(?=\nclass |\ndef )` 删一个异常类，把紧随其后的 3 个模块常量一起吞掉，49 条测试当场炸红。**教训**：脚本删除要按**行号区间 + 断言**，不要用开放式正则；且删完必须跑相关测试。
5. **治理默认值的方向**：安全判据（审批/HITL）**默认收紧**并给可诊断的出路；性能/吞吐判据**默认宽松**（限流读不到元数据不能 fail-closed，否则把可观测性问题升级成可用性事故）。
