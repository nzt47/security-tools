## 一、读法（先看这四条）

1. **"已验证"的定义**：有**机器可复现的证据**——指向存在的代码符号 **且** 指向跑得过的单测/验收报告。
   仅"代码写了"不算已验证。
2. **"未验证"的定义**：机制存在但**无实测/无覆盖**，或**能力本身未实现**。本表**不把未验证写成已验证**（诚信底线；
   与 [`PERF_BUDGET_REBASED.md`](../PERF_BUDGET_REBASED.md) §五 的 ❓ 标注同一纪律）。
3. **"降级"不是"等价"**：单机实现在**语义**上覆盖了要求，但在**不变量强度**上通常弱于集群/外部组件版本
   （例如"本地受保护文件"弱于"WORM 只追加"）。差异逐项写在"边界/已知缺口"列，**不做等价宣称**。
4. **可追溯清单见 §三**：每条断言给出 `代码位置::符号` 与证据，便于逐条复核（并有本地单测
   `tests/unit/test_s7_06_degradation_table.py` 机器校验路径存在性）。

## 二、设施表（7 项）

### 1. Watchdog（单例与分裂脑防护）

| 项 | v7.2 要求 | 云枢单机实现 | 边界/已知缺口 | 升级路径（P5） |
|---|---|---|---|---|
| Watchdog | 集群 + OS 服务注册 + 互 watch（多实例互检、领导者选举） | `watchdog_singleton.py`：进程内单例 + **非阻塞 OS 文件锁**（Windows `msvcrt` / POSIX `fcntl`），持锁者信息（pid/主机/启动时间）写在锁文件同一句柄的固定槽位，**同机第二实例启动即被拒绝**；`SplitBrainError` 显式区分"锁不可得"与"锁内主键冲突" | ① **仅同机**互斥：跨机靠共享文件系统才有意义，本机无集群仲裁；② 持锁进程崩溃后的**接管时延未实测**（R5，见 §三 #1c）；③ 无 OS 服务注册（开机自启靠部署侧） | 领导者租约（`LEASE_BACKEND_CLUSTER = "leader_lease"`，常量与接口已留）→ 奇数节点仲裁 → P5 |

### 2. 审计存储（防篡改与只追加）

| 项 | v7.2 要求 | 云枢单机实现 | 边界/已知缺口 | 升级路径（P5） |
|---|---|---|---|---|
| 审计存储 | 每日 Merkle 根 → **外部只追加**存储（WORM / S3 Object Lock）+ 跨机锚定 | 本地 SQLite 链式审计（`self_hash = sha256(seq+ts+actor+action+subject+payload_hash+prev_hash)`，`prev_hash` 串联）+ **ed25519 签名**（库缺失/无密钥时降级为自签哈希并**如实标注 scheme**）+ 每日根记录 `DailyRoot` 追加到 `data/audit/daily_roots.jsonl`（**外层根链**：根记录自身也串联校验） | **删除链尾不可检出**（无外部锚点，删掉最后 N 条后链仍自洽）——**如实标注**，不声称"不可篡改存储"；② 无 WORM/对象锁，文件权限是唯一物理防线；③ 无跨机锚定（单机无双副本） | `DailyRoot.signature_scheme` / `signer_public_key` 接口已定型 → 接 WORM 或 S3 Object Lock + 跨机锚定 → P5 |

### 3. 出域控制（egress guard）

|---|---|---|---|---|
