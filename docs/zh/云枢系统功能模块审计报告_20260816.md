# 云枢系统功能模块审计报告（2026-08-16）

> 审计范围：`agent/`、`sensor/`、`memory/`、`planning/`、`cognitive/`、`lifetrace/`、`app_server.py`、`agent/server_routes/`、`templates/`、`static/`、`yunshu-ui/`、`config.yaml`、`configs/`。
> 审计方法：目录结构全量扫描 + 关键模块源码阅读 + 后端路由清单统计 + 交付验收报告交叉核对。

## 一、总体架构与层级关系

云枢（Yunshu）是一个"感知—认知—记忆—行动"闭环的数字生命体，外围包裹 Web 服务层与运维保障层，上层为前端展现层。整体共 **6 大功能域 + 前端层**：

```
┌─────────────────────────────────────────────────────────────┐
│  前端展现层  templates/（主控台/日志/健康/可观测看板）            │
│              yunshu-ui/（Electron+React 工作台）              │
├─────────────────────────────────────────────────────────────┤
│  服务层      app_server.py（Flask 主服务 299+ 路由）            │
│              agent/server_routes/（21 个路由模块）             │
│              api_gateway_flask.py（API 网关/限流/配额）         │
├─────────────────────────────────────────────────────────────┤
│  行动层      agent/（DigitalLife 主循环、工具、技能、扩展、      │
│              子智能体、规划、进化）                            │
├─────────────────────────────────────────────────────────────┤
│  记忆层      memory/ + agent/memory + agent/knowledge          │
│              + agent/context + lifetrace/                    │
├─────────────────────────────────────────────────────────────┤
│  认知层      cognitive/ + planning/ + agent/cognitive/         │
├─────────────────────────────────────────────────────────────┤
│  感知层      sensor/（18+ 传感器）+ agent/learning/             │
├─────────────────────────────────────────────────────────────┤
│  运维保障层  agent/health + monitoring + log_system            │
│              + 安全/限流/熔断/调度                             │
└─────────────────────────────────────────────────────────────┘
```

**关键事实**：主服务 `app_server.py` 现有路由约 299 个（287 API + 11 页面 + 1 监控），服务依赖已收敛为 2 个 HTTP 服务（Flask 主服务 + API 网关），前端 13 个 404 接口已全部接线修复（据《交付验收报告_20260816.md》）。

## 五、审计结论

1. **模块规模**：云枢共 6 大功能域 + 前端层 + 部署 CI，后端模块文件 180+，前端页面/组件 60+，功能覆盖面广。
2. **数据源完备**：运行状态（健康五层探针、心跳、传感器、全景指标）与干预入口（权限/工具/技能/扩展/任务/记忆/配置）均已存在，但**分散在 50+ 个 API 中，无统一拓扑视图与聚合接口**。
3. **干预能力充分但缺统一入口**：紧急停止等关键操作已具备 API，但前端主控台缺少"按模块定位 → 查看状态 → 一键干预"的联动界面。
4. **演进方向**：在既有数据源之上设计统一「模块拓扑 + 状态聚合 + 干预适配」层，即可实现可视化管理与实时干预，无需改动既有模块内部实现（符合不易原则）。
