## 1. 背景与目标

知识模块批量/高频写路径存在三类可预见的性能退化，本批逐一落地：

| 编号 | 事项 | 优化前 | 优化后 |
|---|---|---|---|
| 2.2 | 批量删除 | K 次 delete = O(K·N) 全扫 | 一次扫描 O(N+K) |
| 2.3 | index.md 高频写 | 每次写按字典序扫描定位 O(index) | 追加 O(1) 定位 + 定期重整 |
| 2.1 | 入链判定 | 每次 O(N) 全库扫描 | 查表 O(1) |

三项按「低风险 → 高风险」顺序落地，每步独立验证、可独立回滚。

## 2. 变更点清单

### 2.1 新增模块 `agent/knowledge/links_index.py`（P0-2 入链索引）

`index_links.md` 的读/建/增量三件套，对齐 `index.py` 模式：

| 函数 | 职责 |
|---|---|
| `read_links_index(index_path) -> dict[str, list[str]]` | 解析入链索引（段 + 引用方列表，保序去重） |
| `rebuild_links_index(wiki_root, index_path) -> int` | 全量重建：一次 `list()` 构建全部入链，返回被引用数 |
| `update_links_delta(target, ref, index_path, *, add) -> int` | 增量单条：add 添加 / add=False 移除；幂等，空段自动删除 |

写路径统一 `_atomic_write`（同目录 tmp + `os.replace`），段与引用方按 slug 字典序渲染（结果可复现）。`rebuild_links_index` 用 importlib 惰性导入 `CardStore`，不产生 card↔links_index 的 AST 依赖边。

### 2.3 `agent/knowledge/index.py`

`update_index_delta(slug, card, index_path, *, append: bool = False)`：

- `append=True`：新条目追加到 section 末尾（遇空行/下一 section 头停止），**幂等判定不变**（slug 已存在则原位更新，不产生重复条目）。
- `append=False`（默认）：保持原字典序扫描定位，**逐字节不变式保留**（现有 `test_rebuild_index_matches_delta_accumulation` 继续守护）。

## 3. delete_many 语义（与单删一致）

```python
def delete_many(self, slugs: list[str]) -> dict[str, bool]:
    with self._rwlock.write():                      # 一次写锁，整体原子
        incoming = {}                               # 一次 O(N) 全扫构建入链映射
        for card in self.list():
            for link in card.links:
                if not link.startswith(ARCHIVES_PREFIX):
                    incoming.setdefault(link, []).append(card.slug)
        pending = set(slugs)
        for slug in slugs:
            refs = [r for r in incoming.get(slug, []) if r not in pending]
            if refs:                                # 集合外仍有引用 → 拒绝
                result[slug] = False
                continue
            ...                                     # unlink + index + log + 索引同步
```

**【不易】判定语义**：待删集合**外**的引用方仍指向 slug → 拒绝；集合**内部**互相引用 → 不阻止（整批同时消失，无残留断链）。由 `test_delete_many_external_ref_rejected` / `test_delete_many_internal_refs_allowed` / `test_delete_many_matches_sequential_delete` / `test_delete_many_index_missing_fallback` 锁定与单删判定一致。

> ✅ 入链映射构建复用入链索引：优先 `read_links_index` 一次解析（O(M)），索引缺失/损坏时回退全库扫描（O(N)），降级铁律与 `_has_incoming_links` 一致。修复前每次全扫 O(N)，索引存在场景比逐次 delete 慢 13.5x；修复后 3000 卡删 50 张 2342.9 ms → 134.1 ms（≈17.5x）。

## 4. CRUD 挂接同步时序（入链索引一致性）

| 操作 | 时序 | 前置数据 |
|---|---|---|
| `create(card)` | 写盘 → index → log → **add 引用** | 新卡 `links`（create 不解析正文，links 来自传入字段） |
| `update(card)` | **remove 旧引用**（读旧卡 links，损坏卡容错为空）→ `card.links = parse_links(content)` → 写盘 → **add 新引用** | 需读旧卡一次（多一次解析，可接受） |
| `delete(slug)` | 入链校验（查表）→ **读被删卡 links** → unlink → index → log → **remove 引用** | 被删卡 links（损坏卡容错为空，仍可删除） |
| `delete_many` | 逐张：unlink → index → log → **remove 引用** | 同上 |

**不变量**：任意 create/update/delete 序列后，增量叠加的索引表 == `rebuild_links_index` 全量重建结果。由 `test_crud_hooks_keep_delta_in_sync` / `test_delete_many_hooks_keep_delta_in_sync` 锁定。

## 5. 数据格式契约（index_links.md）

```
# 知识库入链索引
> 此文件由 AI 自动维护，请勿手动修改。更新时间: YYYY-MM-DD

## <被引用slug>          ← 段 = 被引用卡片 slug
- [[<引用方slug>]]        ← 引用方列表（段内、段间均字典序）
```

- 只记录指向 wiki 的**纯 slug** 入链；`archives/...` 不入表（对齐 `find_orphans` 语义）。
- 引用清空后对应段移除（不残留空段）。
- 与 index.md 同目录、同原子写机制；**索引可随时删除重建，无数据丢失风险**。

## 6. 容错与降级

| 场景 | 行为 |
|---|---|
| 索引文件缺失 | `_has_incoming_links` 回退全库扫描（行为与优化前一致，不退化） |
| 索引文件解析失败 | 同上，logger.warning 记录后回退 |
| 被删/被改卡片损坏 | 读 links 容错为空（`except (ValueError, TypeError)`），删除仍可进行 |
| update 旧卡损坏 | 旧引用按空处理，仅登记新引用（不会因旧卡损坏阻塞更新） |

降级铁律：**任何容错路径保证行为不劣于优化前**，测试用例覆盖（`test_get_corrupted_card_returns_none` 等）。

## 7. 已知问题与后续

1. ~~`delete_many` 未复用入链索引~~ → **已修复**（§3）：优先读 `index_links.md` 一次构建 incoming，索引缺失回退全扫，判定语义不变；3000 卡删 50 张 17.5x。

3. **append 收敛策略**：append 模式依赖定期 `rebuild_index` 重整排序（收敛不变式已锁定）；若长期不重整，index 内同 section 顺序将非字典序（内容集合正确）。
