# 云枢架构重构总结报告（2026-08-16）

> 汇总自「API 审计 → 清理 → 接线 → 网关适配 → CI 守护 → 遗留重构 T1-T7」全链路的变更点与量化收益。相关文档：[交付验收报告](交付验收报告_20260816.md)、[接口变更与鉴权差异说明](接口变更与鉴权差异说明_20260816.md)、[架构演进与依赖对比](架构演进与依赖对比_20260816.md)、[遗留重构任务清单](架构收口遗留重构任务清单_20260816.md)。

## 一、总览

本轮从一次 API 全面审计出发，识别四大架构问题（死服务 / 188 个未挂载定义 / 前端 404 / 网关孤岛），经五阶段收敛为**双服务 + 网关适配层**的干净架构，遗留重构 T1-T7 全部落地。

## 二、变更点清单（按阶段）

### 阶段 1：审计
- 全量扫描：主服务 299 路由定义（287 API + 11 页面 + 1 监控）、sensor_server 13、file_monitor 5
- 定位 16 个未挂载路由模块（188 定义）、13 个前端 404 接口、零引用网关

### 阶段 2：清理（消除死代码）
| 项 | 明细 |
|---|---|
| B 类路由模块 | 删除 10 个（8 重复 + 2 占位），-188 定义 |
| 测试文件 | 删除 test_extensions_api.py |
| 死服务 | 删除 sensor_server.py（端口冲突/零引用/无消费者） |
| 文档归档 | 5 份历史文档 → docs/archive/sensor_server_retired_20260816/ |
| 同步更新 | server_routes/__init__.py、app_server.py、2 个测试/契约文件、extension-health-check.yml |

### 阶段 3：接线（修复 404 + 暴露能力）
| 批次 | 接口 | 说明 |
|---|---|---|
| 前期 | replay 6 + vector 7 | 前端 replayRecorder/memory.js 依赖 |
| T2 | feedback 7 | 后端能力 HTTP 化 |
| T3 | business_dashboard 5 | Prometheus 告警源 |
| T4 | health 8 | HealthScore 体系 |
| T5 | dashboard 5 | 质量/链路追踪 |
| T6 | semantic-config 2 | orchestrator 热更（子函数提取） |
| T7 | handoff 1 | 会话交接（子函数提取） |
| **合计** | **+41 接口** | 全部实测 200/业务符合预期 |

### 阶段 4：网关适配（组件复活 + 全量文档）
- 新增 `agent/api_gateway_flask.py`：/api/open/echo|keys×2|stats + /api/docs
- `_scan_internal_routes` 自动扫描 → **/api/docs 143 → 292 路径**（+149）
- 修复缺陷：网关挂载位置调整（移文件末尾），确保扫描覆盖全部路由

### 阶段 5：CI 与工具
- 新增 `.github/workflows/gateway-health.yml`（cron 每日 + workflow_dispatch）
- 独立 CLI `yunshu-gateway-check`（pyproject `[project.scripts]`，Windows 实测可用）
- 修复：pyproject packages.find bug、extension-health-check 引用已删测试

### 阶段 6：遗留重构 T1-T7
- T1 删 register_all_routes；T2-T5 直接接线；T6/T7 子函数提取（经方案确认）
