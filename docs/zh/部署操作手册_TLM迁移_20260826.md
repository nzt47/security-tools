# TLM 数据迁移脚本部署操作手册

> 适用：一次性迁移旧 SQLite（holographic.db）+ 旧 ChromaDB → 新 memory_tlm.db（TLM 三表统一记忆层）。
> 关联：`scripts/migrate_to_tlm.py`（迁移）、`scripts/seed_mock_source.py`（mock 数据）、`scripts/benchmark_tlm_regen.py`（性能基准）。
> 生成日期：2026-08-26

## 一、前置条件

| 项 | 要求 |
|---|---|
| Python | `>=3.10,<3.13`（项目 `requires-python` 约束） |
| `.env` | `TLM_EMBEDDING_MODEL`（默认 `BAAI/bge-small-zh-v1.5`）、`TLM_EMBEDDING_DIM`（默认 `512`） |
| 模型 | 本地缓存 bge-small-zh-v1.5（512 维）。无网络时需预下载，见"模型预下载" |
| 数据 | 旧 `data/memory/holographic.db`（schema：memory_items + memory_fts）+ 旧 `data/chroma`（可选，Windows 不可用时自动降级） |

> ⚠️ 迁移脚本**不修改** source-db / source-chroma（只读 URI 连接 + 只读目录），迁移前自动备份到 backup-dir。

## 二、依赖安装

```bash
# 1) 运行时依赖（sentence-transformers 提供 bge 编码；sqlite-vec 提供向量检索）
pip install sentence-transformers sqlite-vec

# 2) chromadb 为可选（读取旧向量用；Windows 已知不兼容，缺失时自动全量重生成向量）
pip install chromadb          # 可选，安装失败不影响迁移

# 3) 模型预下载（离线环境先执行，避免迁移时联网）
python scripts/predownload_model.py --model BAAI/bge-small-zh-v1.5

# 4) 验证安装
python -c "import sentence_transformers, sqlite_vec; print('deps OK')"
```

## 三、Mock 数据演练（推荐先跑通）

```bash
# 构造 500 条 mock source 数据（含 50 条 384 维 chroma 向量，验证重生成）
python scripts/seed_mock_source.py --clean --n-main 500 --n-vec 50 --vec-dim 384

# 干跑（只打印计划，不写库）
python scripts/migrate_to_tlm.py --dry-run --no-encoder \
    --source-db data/mock/holographic.db --source-chroma data/mock/chroma

# 真实迁移（伪 embedding 快速验证流程）
python scripts/migrate_to_tlm.py --no-encoder \
    --source-db data/mock/holographic.db --source-chroma data/mock/chroma \
    --target-db data/mock/memory_tlm.db --backup-dir data/mock/backup
```

## 四、真实迁移

### 4.1 全量迁移（生产）

```bash
# 默认路径（./data/memory/holographic.db → ./data/memory/memory_tlm.db）
python scripts/migrate_to_tlm.py

# 显式指定路径 + 批量大小
python scripts/migrate_to_tlm.py \
    --source-db ./data/memory/holographic.db \
    --source-chroma ./data/chroma \
    --target-db ./data/memory/memory_tlm.db \
    --backup-dir ./data/memory/backup_20260826 \
    --batch-size 100
```

### 4.2 断点续传

```bash
# 中断/失败后重跑，自动跳过已迁移记录（主表 + 向量表）
python scripts/migrate_to_tlm.py --resume
```

> resume 模式失败时**不删除** target-db（保留已迁移数据供下次续传）；仅首次迁移失败才回滚删除 target-db。

### 4.3 向量重生成性能调优

```bash
# 默认最优配置已生效：--workers 1 --encode-batch 64
# 如需覆盖（基准见 scripts/benchmark_tlm_regen.py）：
python scripts/migrate_to_tlm.py --workers 1 --encode-batch 64
```

## 五、验证与结果解读

### 5.1 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 迁移成功（或 dry-run 计划打印完成） |
| 1 | 迁移失败（已自动回滚 / resume 模式保留现场） |

### 5.2 stdout JSON 报告

```json
{
  "status": "success",
  "main": {"total": 500, "migrated": 500, "skipped": 0, "failed": 0},
  "vectors": {"total": 500, "reused": 0, "regenerated": 500, "failed": 0},
  "validation": {"row_count_ok": true, "sample_ok": true, "fts_ok": true, "knn_ok": true},
  "elapsed_sec": 8.5,
  "throughput_ops": 58.8,
  "vec_throughput_ops": 11.7
}
```

- `throughput_ops`：主表迁移吞吐（不含向量重生成）
- `vec_throughput_ops`：向量重生成吞吐
- `validation.knn_ok` 为 `null` 表示向量层不可用（降级纯 FTS）

### 5.3 手动校验

```bash
# 行数对比
python -c "
import sqlite3
a = sqlite3.connect('data/memory/holographic.db').execute('SELECT COUNT(*) FROM memory_items').fetchone()[0]
b = sqlite3.connect('data/memory/memory_tlm.db').execute('SELECT COUNT(*) FROM memory_items').fetchone()[0]
print(f'source={a} target={b} {\"OK\" if a==b else \"MISMATCH\"}')"
```

## 六、常见报错处理

| 报错 | 原因 | 处理 |
|---|---|---|
| `source-db 不存在: ./data/memory/holographic.db` | 路径错误或数据未就位 | 确认路径，用 `--source-db` 显式指定 |
| `--resume 需要 target-db 已存在` | resume 但 target 尚未创建 | 首次用全量模式（不带 --resume）创建 |
| `ChromaDB 读取失败（Windows 已知不兼容）` | chromadb Rust 后端在 Windows 不兼容 | 无需处理，自动降级为全量重生成向量 |
| `sqlite_vec 未安装/加载失败` | sqlite-vec 扩展缺失 | 主表迁移继续，向量层降级纯 FTS；安装 `sqlite-vec` 后重跑 |
| `sentence_transformers 加载失败 ... 回退到伪 embedding` | 模型未缓存 / 无网络 | 先跑 `predownload_model.py` 预下载；测试可用 `--no-encoder` |
| `维度不匹配 key=...: 期望 512, 实际 384` | 旧 chroma 向量维度与目标不一致 | 正常行为：自动丢弃旧向量并用 bge 重生成 |
| `WinError 32 ... 回滚本身失败` | Windows 文件锁占用 target-db | 关闭占用进程（数据库工具/编辑器）后重试；脚本已先关连接再回滚 |
| `SQLITE_BUSY` | 并发访问 | 脚本已设 `PRAGMA busy_timeout=5000`；避免迁移期间其他进程写库 |
| `[batch N] 已迁移 X 条, 失败 Y 条` 中失败>0 | 批次异常 | 看日志定位；失败记录写入 `memories_vec_failed` 表，不中断迁移 |

## 七、CI/CD 集成

- Workflow：`.github/workflows/tlm-migration.yml`
- 触发：修改迁移相关文件时（push/PR）+ 每周一 06:00 定时 + 手动 `workflow_dispatch`
- 失败告警：钉钉 webhook（`DINGTALK_WEBHOOK` secret）自动通知，见 `scripts/observability_dingtalk_notify.py`

## 八、回滚说明

- **首次迁移失败**：自动删除 target-db（含 -wal/-shm），保留 backup 目录，退出码 1。原 source 不受影响（只读）。
- **resume 模式失败**：保留 target-db 已迁移数据，退出码 1，重跑 `--resume` 续传。
- **人工回滚**：删除 `memory_tlm.db` 即回到迁移前状态（source 始终只读，无需恢复）。
