## 一、根因分析

D2 症状：ReAct 路径的步骤反思永远失效（`reflection_history` 恒空）。

[react.py L80](file:///c:/Users/Administrator/agent/planning/react.py#L80)：

```python
async def run(self, task: str, context: Dict = None) -> ReActResult:
```

`task` 为**字符串**（用户消息）。L177 直接透传给反思引擎：

```python
reflection = await self.reflector.step_reflect(task, action_result, context)
```

[reflector.py L147-159](file:///c:/Users/Administrator/agent/planning/reflector.py#L147-L159) 的 `step_reflect(task: Task, ...)` 访问 `task.description`（L148）/ `task.id`（L159）→ 字符串无这些属性 → `AttributeError` → 被 [react.py L182](file:///c:/Users/Administrator/agent/planning/react.py#L182) `except Exception` **静默吞掉** → 反思结果从不记录。

（对比：`core.execute_plan` 路径传真 `Task` 对象，反思正常；D2 仅 ReAct 路径缺陷。）

## 二、三义分析

- **【不易】** 反思契约：`step_reflect` 需要 `Task` 对象（描述/ID），契约不应改变。
- **【变易】** ReAct 的 `task` 本质是用户消息字符串，可能被 `_think`/`_act` 多处用作提示词；仅反思调用点需要 Task 对象。
- **【简易】** 最小充分解：在唯一调用点（L177）将字符串包装为 `Task` 对象，`reflector` 零改动。

## 三、修复方案（推荐方案 A）

### 调用点包装（react.py L177 附近）

```python
# D2 修复：step_reflect 需要 Task 对象；ReAct 路径 task 为字符串 → 包装转换
reflect_task = task if isinstance(task, Task) else Task(
    id=f"react_step_{iteration}", description=str(task)
)
reflection = await self.reflector.step_reflect(reflect_task, action_result, context)
```

补充 import（react.py 顶部）：`from .models import Task`。

依据：
- `Task(id=..., description=...)` 为最小字段构造（[models/task.py](file:///c:/Users/Administrator/agent/planning/models/task.py)），`step_reflect` 仅用这两字段；
- 反射的 `task_description` 语义 = 用户消息，与 executor 路径传子任务描述行为一致；
- `isinstance` 守卫兼容未来传入 Task 对象（如 executor 路径复用）。

## 四、方案对比（备选）

| 方案 | 说明 | 取舍 |
|------|------|------|
| **A（推荐）** | 调用点包装 Task | 最小改动，reflector 契约不动，无副作用 |

| C | `run()` 入口统一转 Task 后传全局 | `_think`/`_act` 多处按字符串使用 task，改动面大，违简易 |
