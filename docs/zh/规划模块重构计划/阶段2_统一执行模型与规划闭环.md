# 任务提示词 · 阶段 2：统一执行模型与规划闭环

> **关联文档**：`docs/zh/规划模块重构计划/规划模块理想设计.md`（缺陷 D4/D5/D9/D11/D12 详见第四节）
> **前置阶段**：阶段 1 已完成。

---

## 目标描述

消除双路径割裂（D4/D12）：将 ReAct 的"思考-行动-观察"步骤纳入统一的执行记录模型；实现并行执行（D5）；新增规划验证机制（D11）；实现计划持久化与崩溃恢复（D9）；升级 LLM 输出解析鲁棒性。本阶段是重构的"骨架"阶段，完成后阶段 3/4 均建立在此之上。

## 前置依赖

- 阶段 1 已完成。

## 执行步骤

1. **统一执行记录模型**（D4/D12）：
   - 扩展 `planning/models/record.py` 的 `ExecutionRecord`：增加 `thought`、`observation`、`reasoning` 字段（保持 `to_dict()` 向后兼容，新增字段追加而非替换）。
   - `ReActLoop` 每步写入统一 `ExecutionRecord`（经 `PlanningCore` 的执行记录仓库），使 `execute_plan` 路径与 ReAct 路径共享同一份执行历史。
   - **反思闭环应用**：`react.py` 中反思 `adjustments` 不再只打日志——步骤级调整写入 `context` 的 `_hints` 命名空间；计划级调整调用 `decomposer.refine()`（首次激活该能力）生成新任务集合并更新 Plan。
2. **实现并行执行**（D5）：
   - `PlanExecutor` 支持从 `plan.tasks` 中取**全部**当前可执行任务（`get_next_executable_tasks()` 已支持多返回），对互不依赖者用 `asyncio.gather` 并发执行；`parallel_groups` 由分解器写入 `plan.metadata["parallel_groups"]` 供执行器参考；保留串行配置开关 `executor.parallel_execution`（默认 false，配置 true 才启用，降低回归风险）。
   - 为并发共享状态（如 `file_contents` 类工具）明确"并发任务不得写同一资源"的校验警告。
3. **规划验证机制**（D11）：
   - 新增 `planning/validator.py`：`validate_plan(plan, tool_registry)` 检查——①依赖完整性（依赖 ID 必须存在）；②循环依赖检测（DFS）；③工具可用性（每任务 `find_tool` 或标记为 LLM 任务，均可执行）；④任务描述非空。验证失败返回结构化错误并标记 Plan 为 `FAILED` 且 `error` 指明原因，而不是执行期卡死。
   - 在 `PlanningCore.plan()` 与 `execute_plan()` 入口调用验证器。
4. **计划持久化与崩溃恢复**（D9）：
   - 新增 `planning/storage.py`：基于 SQLite（复用系统已有的 `sqlite3` 用法与 `data/` 目录惯例）持久化 Plan、Task、ExecutionRecord、状态转换历史；存储路径配置 `planning.storage.path`（默认 `./data/planning/plans.db`）。
   - `PlanningCore` 启动时加载状态为 `EXECUTING/PAUSED` 的未完成计划到 `_active_plans`，并打日志提示恢复。
   - 每次状态转换、任务完成时增量落库（非整树序列化，控制 IO）。
5. **LLM 输出鲁棒性升级**：
   - 将 `decomposer._extract_json_from_response` 抽为 `planning/llm_json.py` 公共函数：支持 markdown 围栏、裸 JSON、前后噪音剥离；增加 `jsonschema` 校验（或轻量手写校验函数，避免新增重依赖）；解析失败自动重试 1 次并附错误反馈提示；仍失败回退规则分解。
6. 为以上能力补测试：并行执行、验证器（悬空依赖/环/空描述）、持久化-重启-恢复、JSON 解析容错（畸形输出）。
7. 全量回归。

## 预期成果

- Plan 路径与 ReAct 路径共用同一执行记录与反思闭环；`refine()` 首次生效。
- 配置开启后并行执行可用；验证器阻止坏计划进入执行期。
- 重启后未完成计划可恢复，执行状态不丢。
- LLM 输出解析失败率下降（以阶段 0 基线对比畸形输入用例）。

## 评估标准

1. 新增测试覆盖：并行（≥2 任务并发完成且结果正确）、验证器 3 类失败场景、持久化→重启→恢复（模拟新 `PlanningCore` 实例读取）、JSON 畸形输入（含 markdown 围栏/裸 JSON/带噪文本）。
2. 阶段 0 全部基线测试仍通过（无回归）；ReAct 反思闭环测试断言 `reflection_history` 有记录且 `adjustments` 生效。
3. 持久化文件可被独立读取校验（提供 `scripts/planning_db_inspect.py` 或说明读取方法）。
4. 默认配置下行为与重构前一致（`parallel_execution=false`、存储可关闭开关 `planning.storage.enabled`）。

## 回滚方式

新增 `validator.py`、`storage.py`、`llm_json.py` 可整体移除；执行器/ReAct 改动集中在少数文件，可单独 revert。
