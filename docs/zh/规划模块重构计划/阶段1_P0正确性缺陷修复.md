# 任务提示词 · 阶段 1：P0 正确性缺陷修复

> **关联文档**：`docs/zh/规划模块重构计划/规划模块理想设计.md`（缺陷 D1/D2/D3 详见第四节）
> **前置阶段**：阶段 0（已有复现测试与基线）。

---

## 目标描述

修复规划模块三个 P0 级正确性缺陷（D1 成功判定短路、D2 ReAct 反思参数错误、D3 ask_user 伪实现），恢复"反思→执行→判定"闭环的基本正确性。**只修复正确性，不引入新功能**（并行执行、持久化等留待阶段 2）。

## 前置依赖

- 阶段 0 已完成（已有复现测试与基线）。

## 执行步骤

1. **修复 D1（成功判定短路）**：在 `planning/executor.py::execute_plan` 末尾，先基于任务状态计算 `all_completed` 与 `any_failed`，再据此设置 `COMPLETED` 与 `result`；同步修正 `planning/models/plan.py::is_success`，使其可被执行器正确调用（例如增加 `is_success(consider_state=False)` 语义或调整状态判定顺序，任选，但必须保持 `to_dict()` 输出格式不变）。
2. **修复 D2（反思参数错误）**：`planning/react.py` 不再直接传字符串 `task`，改为构造最小 `Task(description=task)` 传入 `reflector.step_reflect`；或在 `reflector.step_reflect` 增加字符串入参兼容（推荐前者，保持签名严格）。修复后确保 ReAct 循环中反思真实执行且异常不再被静默吞掉（将日志级别从 warning 提升为 error 并记录 trace_id 信息）。
3. **修复 D3（ask_user 语义）**：定义 `AskUserResult`/`UserInputWaiter` 语义——`ask_user` 行动返回 `success=False` + 专用观察标记（如 `observation="awaiting_user_input"`），ReAct 循环检测到该标记即**终止当前循环**并以 `ReActResult(success=False, error="等待用户输入")` 返回，由上层（orchestrator）负责向用户询问与后续恢复（恢复机制在阶段 2 统一执行模型中落地）。保留 `ask_user` 对外行为：返回文案提示用户。
4. 为三个修复分别更新/新增单元测试（复用阶段 0 的复现测试，将其从"预期失败"翻转为"预期通过"）。
5. 全量回归：运行 `python -m pytest tests/unit tests/integration -q`，确认规划模块相关全部通过且无其他回归。

## 预期成果

- D1：全成功计划正确进入 `COMPLETED` 且 `result` 为成功语义。
- D2：ReAct 路径反思真实执行，反思结果写入 `reflection_history`。
- D3：`ask_user` 不再假装成功，循环正确停止并返回等待用户语义。
- 三个复现测试从失败翻转为通过。

## 评估标准

1. 阶段 0 的 3 个 P0 复现测试全部翻转为通过。
2. 现有规划模块测试（`test_planning_core.py`、`test_planning_react.py`、`test_planning_state_machine.py`）全部通过，无回归。
3. 公开 API 签名未破坏（`plan/execute_plan/chat/cancel_plan/get_plan_status` 及模型字段不变）。
4. 无 LLM 依赖的测试可在离线环境通过（不要求真实 LLM）。

## 回滚方式

修复集中在 3 个文件（`executor.py`、`plan.py`、`react.py`、`reflector.py`），如有回归 `git revert` 对应 commit 即可。
