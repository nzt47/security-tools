## 一、systemd 服务部署（灰度环境变量注入）

### 1.1 Service 单元文件 `/etc/systemd/system/yunshu.service`

```ini
[Unit]
Description=Yunshu Digital Life Agent
After=network-online.target docker.service
Wants=network-online.target

[Service]
Type=simple
# 工作目录 = 仓库根（含 .env / config.yaml / data/）
WorkingDirectory=/opt/yunshu
# 推荐容器方式运行（挂载式发布，见工程约定）
ExecStart=/usr/bin/docker run --rm --name yunshu \
  --env-file /opt/yunshu/.env \
  -v /opt/yunshu/agent:/app/agent:ro \
  -v /opt/yunshu/config.yaml:/app/config.yaml:ro \
  -v /opt/yunshu/data:/app/data \
  -p 5678:5678 \
  yunshu:v1.2.0-rc4-final
# 或原生方式（无容器环境时）:
# ExecStart=/opt/yunshu/.venv/bin/python -m agent.main

Restart=on-failure
RestartSec=10

# 日志限制（防磁盘写满）
StandardOutput=journal
StandardError=journal
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

### 1.2 灰度放量 = 仅改环境变量（不改代码不重建镜像）

```bash

sudo systemctl stop yunshu
sudo systemctl set-environment PLANNING_ENABLED=false
sudo systemctl start yunshu

# ② 小流量 5%：仅目标实例开启
sudo systemctl stop yunshu
sudo systemctl set-environment PLANNING_ENABLED=true
sudo systemctl start yunshu
# 观察 3~5 天，记录看板基线（见 §四）

# ③ 全量：所有实例 set-environment PLANNING_ENABLED=true 并重启

# ④ 稳定观察 7 天无回退事件
```

## 二、Prometheus 抓取配置（指标源 5678）

### 2.1 `prometheus.yml`（部署目录 `monitoring/prometheus/prometheus.yml`）

```yaml
global:
  scrape_interval: 15s
  evaluation_interval: 30s

rule_files:
  # 规则目录挂载（含 lock_watchdog_alerts.yml 等全部规则）
  - /etc/prometheus/rules/*.yml

scrape_configs:
  - job_name: yunshu
    metrics_path: /metrics
    static_configs:
      - targets: ['host.docker.internal:5678']
        labels:
          instance: yunshu-prod
```

### 2.2 规则文件挂载

```bash
# 仓库规则目录 → Prometheus 容器（挂载式，不 COPY 进镜像——工程约定）
mkdir -p /etc/prometheus/rules
cp monitoring/prometheus/rules/*.yml /etc/prometheus/rules/

# 规则校验（部署前必须 0 错误）
promtool check rules /etc/prometheus/rules/*.yml

# 热加载（无需重启 Prometheus）
curl -X POST http://localhost:9090/-/reload
# 验证: curl 'http://localhost:9090/api/v1/rules' 应含 LockHoldTimeout/LockWaitTimeout
```

## 三、Grafana 告警与看板挂载

### 3.1 数据源（datasource）

```json
{
  "name": "Prometheus-Yunshu",
  "type": "prometheus",
  "url": "http://host.docker.internal:9090",
  "access": "proxy",
  "isDefault": true
}
```

### 3.2 看板 4 Panel（JSON 导入 `monitoring/grafana_dashboards/` 已有模板可复用）

| Panel | 指标 | 类型 |
|---|---|---|
| 规划流量 | `sum(rate(yunshu_intent_layer_total{layer="planning"}[5m]))` | timeseries |
| 成功/失败 | `sum by (result)(rate(yunshu_intent_layer_total{layer="planning"}[5m]))` | timeseries |
| 单计划成本 | `sum(rate(yunshu_planning_cost_total[5m]))` | stat |
| LLM 错误率 | `rate(llm_call_errors_total[5m]) / clamp_min(rate(llm_call_total[5m]), 1)` | gauge |

### 3.3 告警规则已就绪（monitoring/prometheus/rules/）

- `planning_alerts.yml`：PlanningTrafficDrop（流量骤降）+ PlanningFailureRateHigh（失败率升高）
- `lock_watchdog_alerts.yml`：LockHoldTimeout（critical，持锁超时）+ LockWaitTimeout（warning，等待超时）
