# 规划模块 D5 修复方案草案：并行执行

> **关联**：`docs/zh/规划模块重构计划/规划模块缺陷清单.md`（D5，P1，阶段 2）
> **状态**：草案（未实施）
> **日期**：2026-08-10

## 一、根因分析

[executor.py L207-212](file:///c:/Users/Administrator/agent/planning/executor.py#L207-L212)：

```python
next_tasks = plan.get_next_executable_tasks()
...
task = next_tasks[0]   # 只取第一个，互不依赖的任务被串行执行
```

`TaskType.PARALLEL` / 分解器 `parallel_groups` 从未生效，独立任务无法并发。

## 二、三义分析

- **【不易】** 依赖语义：仅互不依赖的任务可并行（`get_next_executable_tasks` 已按依赖过滤，天然给出可并行集合）。
- **【变易】** 并发规模需可配置（`max_concurrency`），避免任务过多时资源失控。
- **【简易】** 利用现成的"可执行任务集合"，对同批任务 `asyncio.gather` 并发。

## 三、修复方案（推荐方案 A）

[executor.py L207-212](file:///c:/Users/Administrator/agent/planning/executor.py#L207-L212) 改为批量调度：

```python
next_tasks = plan.get_next_executable_tasks()
if not next_tasks:
    logger.warning("无可执行任务,但计划未完成")
    break

if len(next_tasks) > 1:
    # D5 修复：互不依赖的任务并行执行
    results = await asyncio.gather(
        *[self._execute_task_with_retry(t) for t in next_tasks]
    )
    for task, result in zip(next_tasks, results):
        self._record_execution(plan, task, result)
        if result.success:
            task.mark_completed(result.output)
            await self._trigger_callbacks("on_task_complete", task, result)
        else:
            task.mark_failed(result.error or "未知错误")
            await self._trigger_callbacks("on_task_fail", task, result)
            if task.priority >= 4:
                logger.error(f"高优先级任务失败: {task.id}")
    step_count += len(next_tasks)
    plan.current_step += len(next_tasks)
else:
    task = next_tasks[0]
    result = await self._execute_task_with_retry(task)
    self._record_execution(plan, task, result)
    if result.success:
        task.mark_completed(result.output)
        await self._trigger_callbacks("on_task_complete", task, result)
    else:
        task.mark_failed(result.error or "未知错误")
        await self._trigger_callbacks("on_task_fail", task, result)
        if task.priority >= 4:
            logger.error(f"高优先级任务失败: {task.id}")
            break
    step_count += 1
    plan.current_step += 1
plan.updated_at = datetime.now()
```

要点：
- 收尾判定（`all_tasks_succeeded` / `is_complete`）在循环外统一处理，无需改动；
- 高优先级失败在批量分支中不 `break`（同批并行任务已完成执行，记录后自然进入下一轮；若需立即停止可后续加 `_cancel_batch` 标志）；
- 并发上限：若需控制，可加 `max_concurrency`（`asyncio.Semaphore`），本轮先不做（互不依赖任务一般有限，保持最小）。

## 四、方案对比

| 方案 | 说明 | 取舍 |
|------|------|------|
| **A（推荐）** | 同批可执行任务 gather | 复用现有依赖过滤，最小改动 |
| B | 依赖 `TaskType.PARALLEL` 标记分组 | 分解器不产出该标记（`parallel_groups` 已丢弃），不可行 |
| C | 线程池并行同步工具 | 与 asyncio 冲突，违简易 |

## 五、验证预期

- D5 复现测试 `test_independent_tasks_execute_in_parallel` **转绿**：全量失败数 14 → 13（若 D4 已修则 13 → 12）；
- 既有测试无回归：串行依赖链（test_planning_state_machine_flow 等）行为不变（单任务分支保持原逻辑）。

## 六、风险与回滚

- **风险 1**：批量分支共享同一 `plan.current_step`/`step_count` 递增——已按 `len(next_tasks)` 递增，计数准确；
- **风险 2**：并行失败任务同时触发回调——回调需幂等（现有 `_trigger_callbacks` 顺序触发，无共享状态）；
- **回滚**：仅 executor.py 单文件。
