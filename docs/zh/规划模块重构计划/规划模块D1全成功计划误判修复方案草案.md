## 一、根因分析

D1 症状：全成功计划被错误标记为"部分任务失败"。

[plan.py L73-77](../../../planning/models/plan.py#L73-L77)：

```python
def is_success(self) -> bool:
    """检查计划是否成功"""
    if self.state != PlanState.COMPLETED:
        return False
    return all(t.status == TaskStatus.COMPLETED for t in self.tasks)
```

`is_success()` 带状态前置条件：仅 `state == COMPLETED` 时返回任务判定结果。

[executor.py L234-239](../../../planning/executor.py#L234-L239) 收尾判定时序：

```python
elif plan.is_success():                          # ① 判定时 state 仍为 EXECUTING
    ...COMPLETED...
elif plan.is_complete():                         # ② 全成功计划落入此分支
    plan.result = "计划执行完成,但部分任务失败"    # ← D1 症状
```

关键：`_finalize_state(plan, COMPLETED, ...)` 在 ① 判定**之后**才执行，收尾判定时 `plan.state` 仍是 EXECUTING → `is_success()` 因 `state != COMPLETED` **恒返回 False** → 全成功计划进入"部分任务失败"分支。

（C1 修复已让收尾改走状态机，但判定顺序未变，D1 主缺陷独立存在；C1 钩子测试点已转绿，D1 主测试点仍按预期失败。）

## 二、三义分析

- **【不易】** 成功语义：计划成功 = 所有任务全部成功完成。收尾文案与状态必须正确反映该语义。
- **【变易】** `is_success()` 对外契约（仅终态 COMPLETED 才为 True）被外部查询依赖，不应改变；收尾判定需要与状态无关的判定能力。
- **【简易】** 最小充分解：新增一个状态无关的判定方法供收尾使用，`is_success()` 契约不动。

## 三、修复方案（推荐方案 A）

### 1. 新增状态无关判定（plan.py）

```python
def all_tasks_succeeded(self) -> bool:
    """所有任务均成功完成（与计划状态无关，供执行收尾判定使用）"""
    return len(self.tasks) > 0 and all(t.status == TaskStatus.COMPLETED for t in self.tasks)
```

### 2. 收尾判定改用新方法（executor.py L235）

```python
elif plan.all_tasks_succeeded():
    self._finalize_state(plan, PlanState.COMPLETED, reason="所有任务执行成功")
    plan.result = "所有任务执行成功"
elif plan.is_complete():
    self._finalize_state(plan, PlanState.COMPLETED, reason="部分任务失败但计划完成")
    plan.result = "计划执行完成,但部分任务失败"
```

### 3. 契约不变

`is_success()` 保留对外语义（COMPLETED 终态才 True），供外部/测试查询使用，不受影响。

## 四、方案对比（备选）

| 方案 | 说明 | 取舍 |
|------|------|------|
| **A（推荐）** | 新增 `all_tasks_succeeded()`，收尾改用它 | 最小改动，语义清晰，契约不变 |
| B | 放宽 `is_success()`（EXECUTING 时也判任务） | 改变对外契约：外部查询"执行中"计划会得到 True，语义混乱 |
| C | 收尾先 `_finalize_state(COMPLETED)` 再判定 | 循环依赖：finalize 决策依赖判定结果，不可行 |
| D | 收尾前临时置 `plan.state = COMPLETED` 再判定 | 副作用状态篡改，违不易 |

- **风险 2**：若其他模块依赖"EXECUTING 状态成功判定"语义——已核查 `is_success` 全库唯一调用点为 executor L235，无其他依赖；
