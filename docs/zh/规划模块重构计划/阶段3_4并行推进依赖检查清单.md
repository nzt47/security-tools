# 阶段 3/4 并行推进依赖检查清单

> **用途**：阶段 3（约束、预算与容错降级）与阶段 4（经验回灌与可观测性）均依赖阶段 2 且相互独立，可并行推进。本清单是二者**并行入场门禁 + 并行隔离检查**：先各自通过能力验收（B/C 类），再确认无文件冲突、回滚独立（D 类），确保并行不出错。

> **关联文档**：[规划模块理想设计.md](规划模块理想设计.md)（主文档）、[阶段3_约束预算与容错降级.md](阶段3_约束预算与容错降级.md)、[阶段4_经验回灌与可观测性.md](阶段4_经验回灌与可观测性.md)、[阶段2_3依赖检查清单.md](阶段2_3依赖检查清单.md)（阶段 2 入场门禁）
>
> **关联工具**：[planning_stage3_check.py](../../../scripts/planning_stage3_check.py)（阶段 3 能力验证，T1–T6）、[planning_stage4_check.py](../../../scripts/planning_stage4_check.py)（阶段 4 能力验证，U1–U5）、[planning_baseline_check.py](../../../scripts/planning_baseline_check.py)（阶段 0 基线回归）

## 一、并行推进模型

```
阶段 2（统一执行模型）✅ 已完成
        ├──► 阶段 3（预算+容错）──► 并行合并点
        └──► 阶段 4（经验+观测）──┘         ──► 阶段 5（接入+收口）
```

- **共享依赖**：阶段 2 的统一执行记录模型（`ExecutionRecord` + 持久化）——阶段 3/4 均读它，只读不改。
- **并行窗口**：阶段 2 验收通过后，阶段 3 与阶段 4 可同时开工；**合并（merge）前双方各自验收必须 PASS**。
- **冲突热点**：二者都会触碰 `planning/react.py` 与 `planning/core.py`（见 D-2 冲突规避）。

## 三、一键检查命令

并行推进期间的检查节奏：

```bash
# 阶段 3 分支：入场验收（B 类）
python scripts/planning_stage3_check.py

# 阶段 4 分支：入场验收（C 类）
python scripts/planning_stage4_check.py

# 合并到主线前：双方改动面核对（D-1/D-2）
git diff --name-only HEAD -- planning/ tests/ config.yaml

# 合并后：阶段 2 不变量复核（D-5/E 类）
python scripts/planning_stage2_check.py --static-only
python scripts/planning_baseline_check.py
```

> 并行期间任一方 FAIL 只阻断自身合入，不阻断对方；合并后四脚本全 PASS 方可进入阶段 5。
