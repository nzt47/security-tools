# 规划模块 D9 修复方案草案：计划持久化与恢复

> **关联**：`docs/zh/规划模块重构计划/规划模块缺陷清单.md`（D9，P1，阶段 2）
> **状态**：草案（未实施）
> **日期**：2026-08-10

## 一、根因分析

- [core.py L112](../../../planning/core.py#L112) `_active_plans` 纯内存，进程重启即失；
- `Plan` 有 `to_dict()`（[models/plan.py L101](../../../planning/models/plan.py#L101)）但**无 `from_dict`**；`PlanningCore` 无任何 save/load 接口；
- 计划执行中（EXECUTING/READY/PAUSED）无法跨进程恢复。

## 二、三义分析

- **【不易】** 中断可恢复：未完成计划必须能跨实例恢复（重启后 `_active_plans` 重建）。
- **【变易】** 持久化介质可替换（JSON 检查点起步，后续可换 SQLite），目录可配置。
- **【简易】** JSON 检查点文件 + `from_dict` 对称还原，无新依赖。

## 三、修复方案（推荐方案 A：JSON 检查点）

### 1. `Plan.from_dict`（models/plan.py）

对称还原 `to_dict`：id、original_task、state、tasks（含 Task 各字段）、result、error、current_step、max_steps、execution_graph。

### 2. 持久化目录（core.py __init__）

```python
self.persist_dir = (self.config.get("planning", {}) or {}).get("persist_dir") \
    or self.config.get("persist_dir") or os.path.join("data", "plans")
os.makedirs(self.persist_dir, exist_ok=True)
```

（config 兼容 `{"planning": {"persist_dir": ...}}` 与顶层 `persist_dir` 两种风格；D9 复现测试仅传 `reflector.persist_dir`，走默认目录，两个 core 实例共享同一默认目录即可恢复。）

### 3. 保存/恢复

```python
def save_plan_checkpoint(self, plan: Plan) -> str:
    """保存计划检查点，返回文件路径"""
    path = os.path.join(self.persist_dir, f"{plan.id}.json")
    with open(path, "w", encoding="utf-8") as f:
        json.dump(plan.to_dict(), f, ensure_ascii=False, indent=2)
    return path

def _load_plans_from_disk(self) -> Dict[str, Plan]:
    """从检查点目录恢复计划"""
    plans = {}
    for fname in os.listdir(self.persist_dir):
        if not fname.endswith(".json"):
            continue
        try:
            with open(os.path.join(self.persist_dir, fname), encoding="utf-8") as f:
                data = json.load(f)
            plan = Plan.from_dict(data)
            if plan.state in (PlanState.INIT, PlanState.DECOMPOSING,
                              PlanState.READY, PlanState.EXECUTING, PlanState.PAUSED):
                plans[plan.id] = plan
        except Exception as e:
            logger.warning(f"加载计划检查点失败 {fname}: {e}")
    return plans
```

- `plan()` 成功后（L151）调用 `save_plan_checkpoint(plan)`；
- `__init__` 中 `self._active_plans = self._load_plans_from_disk()`。

## 四、方案对比

| 方案 | 说明 | 取舍 |
|------|------|------|
| **A（推荐）** | JSON 检查点 + from_dict | 最小依赖，对称还原，目录可配置 |
| B | SQLite 持久化 | 引入依赖，重（本轮 P1 不需要） |
| C | pickle 序列化 | 版本脆弱、安全风险，违不易 |

## 五、验证预期

- D9 复现测试 `test_unfinished_plan_recovered_after_restart` **转绿**：新实例恢复未完成计划；
- 既有测试无回归（`plan()` 增加一次写盘，不影响执行语义；`_active_plans` 初始化从磁盘加载，无既有依赖冲突）。

## 六、风险与回滚

- **风险 1**：检查点文件残留（多次测试）——以随机 plan.id 命名，无冲突；测试目录隔离问题：D9 测试用默认目录，多次运行累积文件，可接受（后续可在测试用 tmp 目录配置 persist_dir）；
- **风险 2**：`from_dict` 字段兼容——严格按 `to_dict` 输出还原，缺字段降级为默认值并警告；
- **回滚**：core.py + plan.py 两个文件。
