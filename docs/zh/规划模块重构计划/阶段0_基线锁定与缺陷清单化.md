# 任务提示词 · 阶段 0：基线锁定与缺陷清单化

> **关联文档**：`docs/zh/规划模块重构计划/规划模块理想设计.md`（总体审计结论、缺陷清单 D1–D19、阶段路线图）
> **任务性质**：只读基线任务，可独立立即执行，无代码改动风险。

---

## 目标描述

为云枢 `planning/` 规划模块建立重构前的回归基线与已知缺陷清单，防止后续阶段引入回归，并为本阶段识别的缺陷建立可追踪条目。不得修改任何业务逻辑代码，仅允许新增/修改测试与文档。

## 前置依赖

- 无（本阶段可独立立即执行）。
- 工作目录：`c:\Users\Administrator\agent`。

## 执行步骤

1. 盘点现有规划模块测试：`tests/integration/test_planning_core.py`、`tests/unit/test_planning_react.py`、`tests/unit/test_planning_state_machine.py`，运行并记录通过率基线。
2. 按主文档第四节缺陷清单（D1–D19）逐一编写**复现测试**（新增到 `tests/unit/` 或 `tests/integration/`，命名 `test_planning_defect_d*.py`）：
   - D1：构造全成功计划，断言 `plan.is_success() is True` 且 `result` 不含"部分任务失败"（预期失败=复现成功）。
   - D2：mock LLM 返回 `finish`，调用 ReAct 循环并断言 `reflector.step_reflect` 被调用且无 `AttributeError`（预期失败=复现成功）。
   - D3：`ask_user` 类型行动后断言循环停止等待用户（预期失败=复现成功）。
   - 其余 D4–D19 至少为每个缺陷添加一个"可验证行为描述"级别的测试占位或断言（可在阶段对应任务中完善）。
3. 为规划模块补测缺失能力基线：并行执行、计划验证、持久化恢复、预算超限、降级链（先以 `pytest.mark.skip` 标注"待实现"）。
4. 生成缺陷追踪清单：`docs/zh/规划模块重构计划/规划模块缺陷清单.md`，每条缺陷含：编号、标题、严重级、复现测试路径、影响、建议修复阶段。
5. 记录测试基线报告：全量运行 `python -m pytest tests/unit tests/integration -k planning -q --tb=short`，输出通过/失败/跳过统计与耗时，存档到上述文档。

## 预期成果

- 规划模块测试基线报告（含每个缺陷的复现测试，明确"当前失败数 = 缺陷数"）。
- 缺陷清单文档（D1–D19 全部编号建档）。
- 一份"待实现能力"的 skip 测试清单。

## 评估标准

1. 所有复现测试**按预期失败**，且失败原因与缺陷描述一一对应（不允许意外失败）。
2. 缺陷清单 19 项全部建档，严重级、影响、修复阶段字段非空。
3. 未修改 `planning/` 目录下任何生产代码（`git diff --stat planning/` 为空）。
4. 基线报告记录了各测试文件运行时长，供后续对比。

## 回滚方式

新增的测试文件可直接删除；本阶段不触碰生产代码，无回滚风险。
