|---|---|---|---|
| 基线（2026-08-13） | **1.0** | 3 / 3 | 仅 LLM 分解路径计入；规则分解不检索 |
| 第 2 次运行 | **1.0** | 3 / 3 | 与基线一致 |
| 第 3 次运行 | **1.0** | 3 / 3 | 与基线一致 |

## 3. 指标埋点数据

`PlanningMetrics` 双通道：
- 无标签指标 → `MetricsCollector`（Prometheus 可导出）：`planning.plans.total/success/failed`、`planning.iterations_avg`、`planning.cost_total`、`planning.duration_ms`
- 带 `task_type` 标签 → `BusinessMetricsCollector`：`planning.experience_hit_rate`
- 开关：`planning.metrics.enabled`（默认 true，关闭时全部静默跳过——回滚开关）

## 6. 已知问题与阶段 5 建议

1. **`data/reflection` 环境耦合**：单测/验证脚本依赖 `persist_dir` 覆盖生效；若系统运行积累 create 类经验，`test_decompose_prompt_no_experience_no_injection` 等断言可能失效。建议单测改用不可变 fixture 目录。
2. **成本口径**：`cost_total` 恒 0.0 的根因是 Plan 路径 [executor.py](../../../planning/executor.py) 只 `record_step`、从不 `record_text`/`record_tokens`，budget 快照 `cost=0.0`（ReAct 路径 `react.py:_think` 已有记账），而评测集恰好全部走 Plan 路径。**阶段 5 接入 token 计费前的预演数据**（`scripts/pilot_cost_forecast.py`，估算口径 token=字符数/3、单价 0.002 USD/1k，产出 `cost_pilot_forecast.json`）：

   | 维度 | 预演结果 |
   |---|---|
   | 全量成本（13 用例） | **≈ $0.0032**（9 次 LLM 调用，输入 1195.3 + 输出 411.5 token） |
   | parallel ×3 | $0.003162（占 ~98%，6 次调用主导） |
   | multi_step ×4 / failure_injection ×3 | $0（规则分解 0 调用） |
   | simple ×3 | $0.000052（chat 直答，不计入 plan 埋点） |

   阶段 5 接入计费（executor 补 `record_text` 记账）后评测基线需重跑回填，预期量级 $0.001~0.01 / 13 用例。
3. **规则分解不检索经验**：命中率仅统计 LLM 分解路径（规则分解不查询经验库，不改变行为）；阶段 5 若要让规则分解受益，需额外注入点。
