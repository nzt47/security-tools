### 1.2 核心业务调用方现状（改动前已确认）

| 调用方 | 位置 | 消费内容 | 阶段 3/4 影响风险 |

## 二、优先级定义

- **P0**：核心链路（orchestrator 聊天 / lifecycle 初始化）行为变化或异常崩溃 → 阻塞发布
- **P1**：能力边界行为（预算/降级/经验注入的边界场景）回归 → 应当覆盖
- **P2**：可观测与序列化兼容 → 建议覆盖

## 三、回归测试建议清单

### P0 · 核心链路（阻塞项，必须通过）

| # | 检查项 | 风险点 | 建议验证方式 |
|---|--------|--------|--------------|
| R-1 | **lifecycle 初始化无异常**：`_initialize_planning_engine()` 全流程（含监控组件未就绪场景） | `PlanningMetrics.__init__` 调用 `get_metrics_collector()` 失败会否冒泡到初始化崩溃 | 在无监控初始化环境跑 lifecycle_manager 初始化测试；断言 `self._planner` 正常实例化且不抛异常 |
| R-2 | **orchestrator 聊天主链路回归**：简单任务走 LLM 直答、复杂任务走 `_planner.chat()` 后进入既有 OutputGuard/记忆链路 | 规划入口判定/逃生通道被改动破坏 | 跑 `tests/integration/test_orchestrator*.py` 全量；构造复杂任务断言 `used_planning=True` 且响应非空 |
| R-3 | **逃生通道**：规划调用失败/超时（`timeout_seconds`）回退 LLM 直答 | 预算超限/LLM 异常时是否静默降级而非抛错 | 注入会抛异常的 planner mock，断言 orchestrator 仍返回直答响应 |

### P1 · 能力边界行为（重要项）

| # | 检查项 | 风险点 | 建议验证方式 |
|---|--------|--------|--------------|
| R-4 | **默认配置行为不变**：`budget.enabled`/`replan_on_failure`/`metrics.enabled` 未显式开启时行为与重构前一致 | 新策略默认值误改既有路径（如预算极小值导致计划过早收尾） | 用重构前配置跑既有规划集成测试（`tests/integration/test_planning_core.py`），断言结果与阶段 1 基线一致 |
| R-5 | **预算超限语义**：`steps/seconds` 超限 → 正常收尾返回部分结果；`tokens/cost` 超限 → 停止 LLM 降级摘要 | 预算检查是否在每任务/每步正确接线，超限路径不抛异常 | 运行 `test_planning_stage3.py` + `test_planning_budget_degrade_concurrency.py`（已覆盖）；补充：预算超限时 `plan.metadata` 含预算快照 |
| R-6 | **ask_user 恢复语义**：`awaiting_user_input` 暂停 → `resume_plan` 携带用户答案恢复 | orchestrator 消费 `chat()` 返回时，暂停态响应会被当普通文本发出 | 运行 `test_planning_stage3.py` 中 ask_user 恢复/超时用例；检查 orchestrator 对 `awaiting_user_input` 观察的处理（若缺失属阶段 5 遗留，记录不阻塞） |
| R-7 | **降级链/重规划触发条件**：仅重试耗尽/高优先级失败才触发，成功路径零影响 | 误触发导致正常任务被改写 | 运行 D13/D14/D18 复现测试 + 正常成功计划断言任务原样执行 |
| R-8 | **经验回灌空库行为**：经验库为空时不注入"历史经验"段（不改变无经验场景行为） | `get_advice_for_task` 在空库/损坏库下抛异常破坏 decompose/_think | 运行 `test_planning_stage4.py`（含空库静默断言）；用临时空目录构造 Reflector 复跑 |
| R-9 | **埋点失败隔离**：metrics 收集器抛异常不阻断主流程 | `record_*` 方法内 try/except 是否覆盖全部埋点点 | mock 收集器抛异常，断言 plan/chat 正常返回 |

### P2 · 可观测与序列化兼容（建议项）

| # | 检查项 | 风险点 | 建议验证方式 |
|---|--------|--------|--------------|
| R-10 | **`Task.to_dict()` / `ChatResult.to_dict()` 键追加兼容** | 新增键 `fallback_actions` / `plan_summary` 不破坏既有消费者（严格键匹配的序列化测试） | grep 全仓 `to_dict()` 消费者（`planning/persistence.py`、`agent/` 追踪日志）；跑既有序列化断言测试 |
| R-11 | **`get_planning_metrics()` 汇总可用**：状态面板/健康检查复用无异常 | 新接口在 metrics 关闭时返回 `{"enabled": False}` | 调用 `core.get_planning_metrics()` 断言键结构稳定；关闭开关后断言返回 enabled=False |
| R-12 | **`plan_summary` 字段兼容**：`ChatResult` 未走规划路径时为 None，不破坏既有调用 | 反序列化/日志消费 `plan_summary` 缺失时的容错 | 跑既有 `test_planning_core.py` 中 chat 相关断言（to_dict 键不缺失） |
