# 任务提示词 · 阶段 4：经验回灌与可观测性

> **关联文档**：`docs/zh/规划模块重构计划/规划模块理想设计.md`（缺陷 D15/D16/D17 详见第四节）
> **前置阶段**：阶段 2（统一执行记录）已完成；阶段 3 的失败归因数据可用。

---

## 目标描述

让规划模块"会用历史经验"且"可被观测"：实现规划前经验检索（D17）、规划指标埋点（D16）、结构化计划摘要（D15），并建立规划质量评测基线。为阶段 5 的运行时接入做好可观测前提。

## 前置依赖

- 阶段 2（统一执行记录）已完成；阶段 3 的失败归因数据可用。

## 执行步骤

1. **经验回灌（D17）**：
   - 在 `TaskDecomposer.decompose()` 与 `ReActLoop._think()` 的提示词构建前，调用 `reflector.get_advice_for_task(task_description)`，将命中的成功模式/常见陷阱注入提示词上下文（注入段标注"历史经验"）。
   - 在 `ReActLoop._act` 工具失败时优先从 `lessons_db` 查询同类教训，若存在则给出基于教训的下一步提示（写入 `next_hint`）。
   - 增加 `reflector` 数据管理：`reflection` 经验去重上限（避免经验库无限膨胀）、按任务类型统计命中率。
2. **规划指标埋点（D16）**：
   - 复用系统 `agent/monitoring/` 的 metrics 收集器与 `agent/logging_utils.py` 的结构化日志规范，新增规划指标：`planning.plans.total`、`planning.plans.success`、`planning.plans.failed`、`planning.iterations_avg`、`planning.cost_total`、`planning.duration_ms`、`planning.experience_hit_rate`（带 `task_type` 标签）。
   - 埋点位置：`PlanningCore.plan/execute_plan/chat` 出口、`ReActLoop` 结束点。
   - 观测输出：提供 `get_planning_metrics()` 汇总接口（供现有状态面板/健康检查复用）。
3. **结构化计划摘要（D15）**：
   - 新增 `planning/summary.py`：`build_plan_summary(plan) -> dict` 输出：目标、策略、任务列表（含依赖/状态/耗时）、预算消耗、失败原因、反思结论；同时生成 `markdown` 文本版供响应追加。
   - `ChatResult` 增加 `plan_summary` 字段（`to_dict()` 追加输出，兼容）。
4. **规划质量评测基线**：
   - 在 `tests/eval/` 下建立规划评测集（10–15 个代表性任务：简单/多步/并行/失败注入），脚本 `scripts/eval_planning.py` 运行并输出 KPI 报告（成功率、平均迭代、平均成本、失败原因分布）。
   - 将评测结果存档 `docs/zh/规划模块重构计划/规划评测基线.md`，作为阶段 5 前后对比基准。
5. 测试与回归：经验注入提示词断言（mock LLM 捕获 prompt 含"历史经验"段）、埋点计数器断言、summary 输出断言。

## 预期成果

- 规划前经验可用、失败后教训可引导下一步；指标可查询；响应可携带结构化计划摘要；评测基线确立。

## 评估标准

1. 经验回灌测试：mock LLM 断言收到的 prompt 在经验库非空时包含经验段；经验库为空时不包含（不改变无经验场景行为）。
2. 埋点测试：一次完整 plan+execute 后，`planning.plans.total/success/duration_ms` 计数符合预期（通过 metrics 收集器断言）。
3. 评测脚本可运行且输出完整 KPI 报告；基线存档。
4. 既有测试无回归；`ChatResult.to_dict()` 新增字段不破坏已有断言（检查现有测试）。

## 回滚方式

新增 `summary.py`、评测脚本、埋点均为增量；埋点可通过配置关闭（`planning.metrics.enabled`，默认 true，关闭时静默跳过）。
