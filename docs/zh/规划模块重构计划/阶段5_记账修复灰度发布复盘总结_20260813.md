## 五、经验教训（沉淀）

1. **【不易】记账口径是契约**：token/cost 记账（字符/3 估算 + 单价透传 + 双记）应作为跨模块统一契约，任何 LLM 调用点缺记账都是缺陷（executor、decomposer、reflector 三处口径需一致——TD-4）
2. **【变易】收尾路径要统一**：`execute_plan` 的 finally 统一回填是正确形态——"所有退出路径都可观测"优于"关键分支单独处理"
3. **【简易】测试先行**：P1 测试 2/4 预存失败直接定位根因；全量测试捕获子集外回归。验证手段不因沙箱限制打折
4. **回滚预案要实测**：`git revert` 早期提交在提交累积后会冲突——回滚 SOP 必须包含"dry-run/补丁方案"，首选配置级回滚
5. **不编造数据**：评测 cost=0、灰度未放量等如实标注，验收结论"有条件通过"而非虚报"通过"
