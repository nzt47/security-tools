# 规划模块低危未修项任务单

> 来源：2026-08-12 规划模块漏洞检查（P0/P2 修复与边界补全收尾时发现）
> 状态：待排期，均不影响当前功能正确性（core 集成路径不受影响）

| # | 严重度 | 模块 | 问题描述 | 影响 | 建议修复方案 | 验收标准 |
|---|--------|------|----------|------|--------------|----------|
| L1 | 低 | `reflector.py` `plan_reflect` | 使用 `is_success()` 默认语义（require `state==COMPLETED`）。executor 独立使用且收尾前调用时，全部任务成功但 state 仍为 EXECUTING，会被误判为"部分失败" | 仅影响 executor 独立使用场景的反思评估文案；core 集成路径收尾先于反思，不受影响 | `plan_reflect` 改用 `is_success(consider_state=False)`，或约定在收尾后调用 | 独立执行场景下全成功计划返回成功评估 |
| L2 | 低 | `decomposer.py` `_parse_subtasks` | 对 LLM 返回的重复 task id 无去重：`get_task(id)` 只命中第一个，同 id 任务会导致依赖判定混乱 | LLM 异常输出概率低；异常时行为不可预测 | 解析时校验 id 唯一，重复 id 自动重命名或丢弃 | 输入含重复 id 时，任务列表无重复 id 且依赖可解析 |
| L3 | 中 | `executor.py` `execute_plan` | PAUSED 状态不被主循环尊重：状态机支持 EXECUTING→PAUSED→EXECUTING，但主循环从不检查 `plan.state == PAUSED`，外部置 PAUSED 后任务仍继续调度 | 当前无上层调用方置 PAUSED；引入暂停能力前需先补此边界 | 循环开头检查 PAUSED 并进入等待/退出分支；明确恢复语义 | 置 PAUSED 后主循环不再调度新任务，恢复后继续 |

## 排期建议

- **L1 / L2**：随下次对应模块（reflector / decomposer）相关改动顺手修复，无需单独排期。
- **L3**：需单独评估——涉及执行语义变更（暂停/恢复），需先设计语义与测试再实施。
