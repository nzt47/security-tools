## 一、根因分析

D19 含两个独立质量缺陷：

**D19a — `reflector.py` 中 `learn_from_experience` 重复定义（死代码）**

- [reflector.py L212-259](../../../planning/reflector.py#L212-L259)：旧版实现，写入 `learned_patterns`/`learned_lessons`（dict 结构），不写 `experiences`/`lessons_db`、不持久化；
- [reflector.py L403-452](../../../planning/reflector.py#L403-L452)：新版实现（Python 后定义覆盖前定义，**当前生效**），写 `Experience`/`Lesson` 对象 + `_save_to_persistence()` + memory 保存。

旧版为历史遗留死代码，无任何调用方（同名方法已被覆盖）。

**D19b — `react.py` 中 context 无限累积**

[react.py L196-199](../../../planning/react.py#L196-L199)：每次迭代成功写入 `context[f"_last_result_{iteration}"]`，key 随迭代递增，**永不清理**。context 持续膨胀，LLM 提示词上下文无限增长（token 成本与失真风险）。

## 二、三义分析

- **【不易】** 经验学习语义：成功→经验、失败→教训，必须持久化并供后续复用（`experiences`/`lessons_db` 为当前事实标准）。
- **【变易】** context 中历史结果缓存若未来被下游读取，需保留最近若干条（滑动窗口），而非一次性删光。
- **【简易】** 最小充分解：删旧版死代码 + 滑动窗口保留最近 2 条结果缓存。

## 三、修复方案（推荐方案 A）

### 1. D19a：删除旧版 `learn_from_experience`

删除 [reflector.py L212-259](../../../planning/reflector.py#L212-L259) 的旧版定义。

依据（删除安全）：
- 同名方法 Python 后定义覆盖，旧版从未被调用；
- 旧版独有逻辑（`learned_patterns` dict 写入）已被新版等价覆盖（L425-427 写入 `experience.to_dict()`）；
- 保留新版（Experience/Lesson 对象 + 持久化 + memory），语义完备。

### 2. D19b：context 结果缓存滑动窗口

[react.py L196-199](../../../planning/react.py#L196-L199) 修改：

```python
if action_result.success:
    key = f"_last_result_{iteration}"
    context[key] = action_result.output
    # D19b：仅保留最近 2 条结果缓存，防止 context 无限膨胀
    stale_key = f"_last_result_{iteration - 2}"
    if stale_key in context:
        context.pop(stale_key, None)
    logger.info(f"   💾 结果已缓存到上下文: {key}")
```

依据：
- 循环检测依赖 `steps`（[react.py L190](../../../planning/react.py#L190)），不依赖 `_last_result_*`；
- 全代码库无任何 `_last_result_{i}` 的历史读取点（仅写入），保留最近 2 条为未来读取留足缓冲。
