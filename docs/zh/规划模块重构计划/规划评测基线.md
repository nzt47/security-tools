# 规划质量评测基线（阶段 4）

> 建立时间：2026-08-13
> 用途：**阶段 5 前后对比基准**。阶段 5 运行时接入完成后，重跑 `python scripts/eval_planning.py`，
> 与本基线对比成功率 / 平均迭代 / 平均成本 / 平均耗时 / 经验命中率。
> 本文件为任务提示词要求的评测结果存档；原始 JSON 数据可用 `--output` 重新生成。

## 1. 运行方式

```bash
python scripts/eval_planning.py [--category <分类>] [--quiet] [--output <json路径>]
```

- `--category`：仅运行指定分类（simple / multi_step / parallel / failure_injection）
- `--output`：KPI 报告与逐用例结果写入 JSON
- 评测集：`tests/eval/planning_eval_set.py`（13 用例）

## 4. 口径说明

- **用例成功 vs 计划成功**：计划收尾允许"部分任务失败但计划 COMPLETED"（D1 语义），
  故失败注入用例 `metrics.plans.success=1` 但用例判定 `success=False`（`is_success()` 要求
  全部任务 COMPLETED）。两者口径不同，阶段 5 对比以**用例成功率**为准。
- **经验命中率**：仅 LLM 分解路径（decompose 提示词注入）触发检索并计入命中率；
  规则分解（无 LLM）不查询经验库，不计入。
- **成本**：当前无 token 计费接入，预算快照 cost 恒为 0.0；阶段 5 接入计费后需回填对比。

## 5. 可复现性

- 每用例独立 `PlanningCore` + 独立临时目录，`planning.storage.enabled=false`（不落库，
  无 data/plans 残留）；
- 工具为 lambda，任务描述含工具英文名保证 `find_tool` 确定性匹配；
  write_file / send_email 等工具接受 `**kwargs`（与 `executor._extract_params` 注入的
  filename/content、to/subject/body 参数签名一致）；
- mock LLM 按序消费 `llm_responses`（parallel）；multi / failure 无 LLM 走规则分解。
