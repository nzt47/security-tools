## 二、修复内容摘要

### 1. P0 正确性缺陷（`90b63e70`）
- **D1 成功判定短路**：收尾期 `is_success` 误要求 `state==COMPLETED`，全成功计划被误判"部分任务失败"→ 增加 `consider_state` 语义（`3c82f554` 完善）。
- **D2 ReAct 反思参数错误**：反射调用传参错误 → 修正为正确的任务/结果参数。
- **D3 ask_user 伪实现**：循环检测到 ask_user 即终止（`success=False + observation="awaiting_user_input"`），交由上层 orchestrator 恢复。

### 2. P2 逻辑漏洞（`cb98a02d` / `5ee1038d` / `61b14ca4`）
- **依赖悬挂误报超时**：依赖 FAILED/SKIPPED 的下游任务永远 PENDING 且无法 SKIPPED → 新增 `_resolve_deadlocked_tasks` 死锁消解（迭代至不动点），循环内"无可执行任务"分支 + 收尾期兜底双调用。
- **终止原因不可区分**：timeout / loop_detected / iteration_error 三种语义，post-loop 按原因返回不同错误文案。
- **finish 空值崩溃**：`thought.result` 判空兜底。
- **预算迭代计数一致**：deadline/token/cost 预算终止路径迭代数统一 1-based。

### 3. 边界测试补全（`949a95f8`）
- 并行批部分失败 → 下游悬挂消解 SKIPPED，计划判 COMPLETED(部分失败) 非超时。
- 悬挂引用（依赖不存在的 id）→ D11 前置结构校验拦截，计划 FAILED(计划验证失败)。

### 4. 漏洞 F / G（`f4ddac5a`）
- **F 交替循环检测不到**：`_detect_loop` 原只判"最近 N 步完全相同"，A/B/A/B 振荡漏检 → 增加周期振荡检测（窗口内各位置与其同余周期位置动作一致），终止原因正确报 loop_detected。
- **G `_hints` 无上限膨胀**：D12 反思建议持续追加 → 写回后截断到最近 20 条。

### 5. 漏洞 H 终态覆盖（`625c9dc8`）
- 已完成计划被重复执行时，`transition(COMPLETED→EXECUTING)` 非法进入异常路径，`_finalize_state` 降级赋值把成功计划错误覆盖为 FAILED → 终态保护扩展（COMPLETED/FAILED/CANCELLED 均不被后续收尾覆盖）。

## 四、阶段 2：统一执行模型与规划闭环

> 规格：`阶段2_统一执行模型与规划闭环.md`；目标缺陷 D4/D5/D9/D11/D12。
> 回滚：`planning/validator.py`、`planning/storage.py`、`planning/llm_json.py` 可整体移除；执行器/ReAct 改动集中在少数文件可单独 revert。

### 4.1 统一执行记录模型（D4/D12）
- `ExecutionRecord` 新增 `thought`/`observation` 字段（带默认值）；`to_dict()` 仅追加新键，`observation` 语义升级为"显式字段优先、回落 `result.observation`"——未显式赋值时与重构前行为完全一致（向后兼容）。
- `core.py` `_plan_chat` 的 ReAct 每步写入统一 `ExecutionRecord`（含一步 finish 边界 case），Plan 路径与 ReAct 路径共享同一执行历史。
- 反思闭环激活：步骤级调整写入 `context["_hints"]` 命名空间（已实现）；计划级调整经 `_reflect_to_feedback` 提取 feedback → `decomposer.refine()`（首次激活该能力）生成新任务集合并更新 Plan。

### 4.2 并行执行（D5）
- `PlanExecutor` 从 `plan.tasks` 取全部可执行任务（`get_next_executable_tasks()` 多返回），互不依赖者 `asyncio.gather` 并发；`parallel_groups` 由分解器写入 `plan.metadata["parallel_groups"]`。
- 配置门控 `executor.parallel_execution`（默认 false，配置 true 才启用）——默认行为与重构前一致。
- 并发共享状态校验：`_warn_parallel_resource_conflicts` 对"并发任务写同一资源"输出警告。

### 4.3 规划验证机制（D11）
- 新增 `planning/validator.py`：`validate_plan(plan, tool_registry, llm)` 检查①依赖完整性②循环依赖（DFS）③工具可用性④任务描述非空；`validate_plan_or_raise` 聚合消息抛 `PlanValidationError`。
- `PlanningCore.plan()` 创建期拦截仅判 fatal（dangling/circular/empty），`tool_unavailable` 仅告警交由执行期——避免误拦规则分解任务。
- `execute_plan()` 执行前调用，失败标记 Plan `FAILED` + `error`，不再执行期卡死。

### 4.4 计划持久化与崩溃恢复（D9）
- 新增 `planning/storage.py`（`PlanningStorage extends PlanDB`）：路径解析优先级 `storage.path > persist_db > persist_dir/plans.db > ./data/planning/plans.db`（存量配置零迁移）；`planning.storage.enabled`（默认 true）可整体关闭。
- `persistence.py` 补 `metadata` 列与 `transition_history` 表（幂等迁移补列）；`load_unfinished_plans` 修复 `sqlite3.Row` 无 `.get()` 的恢复崩溃。
- `PlanningCore` 启动加载 `EXECUTING/PAUSED` 未完成计划到 `_active_plans`；每次状态转换、任务完成增量落库（成功/降级路径统一落 `transition_history`）。
- 独立校验工具 `scripts/planning_db_inspect.py`（不依赖 planning 包，`--db/--tasks/--logs/--transitions`）。

### 4.5 LLM 输出鲁棒性
- `decomposer._extract_json_from_response` 抽为 `planning/llm_json.py` 公共函数：markdown 围栏 / 裸 JSON / 噪音剥离；轻量结构校验；失败自动重试 1 次并附错误反馈；仍失败回退规则分解。
