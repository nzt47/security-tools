## 一、根因分析

D3 症状：`ask_user` 行动是伪实现，不真正暂停等待用户。

[react.py L279-284](../../../planning/react.py#L279-L284)：

```python
if thought.action_type == "ask_user":
    logger.info("   [行动] 行动类型: 询问用户")
    return ActionResult.success_result(
        output=thought.result or "需要用户确认",
        observation="等待用户输入"
    )
```

`ask_user` 返回**成功结果**（observation="等待用户输入"），ReAct 循环（[L104 for iteration](../../../planning/react.py#L104)）无感知 → 继续下一轮 `_think` → **不真正等待用户**，人机协同名存实亡。

目标行为（D3 复现测试 `test_planning_defect_d3.py` 定义）：ask_user 后**循环立即停止**，返回 `success=False` + `error="等待用户输入"` + `iterations==1`，由调用方询问用户后再恢复。

## 二、三义分析

- **【不易】** 人机协同语义：`ask_user` 必须暂停执行并返回"等待用户输入"信号，绝不能继续执行后续行动。
- **【变易】** `ReActResult` 已有 `error` 字段可承载"等待用户输入"语义，无需新增字段；调用方（`core.chat`）按 error 识别暂停态。
- **【简易】** 最小充分解：循环内检测 ask_user → 记录步骤 → 立即返回暂停态结果，复用现有字段。

## 三、修复方案（推荐方案 A）

### 循环内检测 ask_user（react.py L170 步骤记录之后）

```python
if thought.action_type == "ask_user":
    # D3 修复：ask_user 为暂停信号——停止循环，返回"等待用户输入"，
    # 由调用方询问用户后恢复（不再继续执行后续行动）。
    logger.info("   ⏸️ 检测到 ask_user：暂停执行，等待用户输入")
    duration = (datetime.now() - start_time).total_seconds() * 1000
    return ReActResult(
        success=False,
        result=thought.result or "需要用户确认",
        error="等待用户输入",
        steps=steps,
        iterations=iteration + 1,
        total_duration_ms=int(duration)
    )
```

插入位置：`steps.append(step)`（L169）之后、反思阶段（L172）之前——ask_user 的步骤已记录，且**跳过反思**（暂停点无需反思）。

依据：
- 复用 `ReActResult.error` 表达暂停语义，`to_dict()`/`__str__` 自动兼容（[models/react.py L59-72](../../../planning/models/react.py#L59-L72)）；
- 与 D3 复现测试断言完全对齐（success=False / error="等待用户输入" / iterations==1）；
- 调用方（`core.chat`）无需改动即可感知暂停（error 字段已有）。
