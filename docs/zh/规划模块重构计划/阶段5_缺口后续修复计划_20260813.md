## 缺口 1（P1 优先）：decomposer / reflector 记账缺失（TD-4）

**背景**：`decomposer.py`（L167/L300）、`reflector.py`（L219/L251）的 LLM 调用**无 token/cost 记账**，与已对齐的 executor/react.py 口径形成双轨漂移（验收报告 §六"LLM 分解记账 $0.0006"的来源需核实，可能来自 executor LLM_REASONING 而非 decompose 本身）。

**前置梳理（必须先做）**：**BudgetManager 实例归属**——decomposer/reflector 与 ReActLoop/executor 是否为同一 BudgetManager 实例？若共享实例，补记账可能导致**重复计费**；若独立实例，需确认计费口径汇总。现状：`planning/core.py` 创建 `BudgetManager` 实例的传参链需核查（`_execute_plan/_build_budget_manager`）。

**修复步骤**：
1. 梳理 core.py 中 BudgetManager 实例创建与透传链（`PlanBudget.from_config` + `token_price_per_1k`）
2. 在 `decomposer.py` 两处 LLM 调用后补 `budget_manager.record_text(prompt)` + `record_text(response)`（与 executor `_execute_llm_reasoning` 同构：字符/3 估算 + 同单价 + 双记）
3. `reflector.py` 同理（advice/classify 两处）
4. 验证无重复计费：单任务成本 = decompose + execute + reflect 之和，与 ReAct 路径口径一致

**验收**：
- 新增 P1 测试：含分解的计划任务 `cost_total > 0`；decompose 路径 token 计数与 ReAct 口径一致（`test_planning_p1_cost_billing.py` 扩展）
- `eval_planning.py` 复跑：`cost_total` 非 0 且包含分解成本（对照基线记录）
- 全量回归：规划子集 + P1 计费 4/4 不回归

**受影响文件**：`planning/decomposer.py`、`planning/reflector.py`、`planning/core.py`（实例透传，如需）、`tests/unit/test_planning_p1_cost_billing.py`
**Jira 卡片**：`Jira_TD4_补充记账逻辑_20260813.md` 已生成
**排期建议**：灰度放量前完成（P1 计费口径是灰度监控的前提）
