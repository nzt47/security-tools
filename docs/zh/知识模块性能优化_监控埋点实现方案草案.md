# 知识模块入链索引 · 容量监控埋点实现方案草案

> 状态：实现方案草案（对应 Jira KN-102）
> 来源：复盘遗留项「监控阈值未落地代码」——refs > 512 MB / 文件数 > 1000 万 阈值停留在文档，需落地为代码埋点
> 生成：2026-08-08

---

## 1. 目标与不变量

**目标**：让「容量接近架构分档线」成为**可观测告警**而非文档假设，在性能退化前触发评估。

【不易】不变量（本方案必须保持）：

1. 埋点**不改变任何读写行为与返回值**（纯观察，零副作用）；
2. 索引缺失/损坏的既有回退降级逻辑**不变**（埋点只叠加统计）；
3. 所有配置经 `.env`（项目约定：配置文件唯一数据源），代码只读环境变量。

---

## 2. 阈值与配置（.env）

```ini
# 知识模块容量监控（缺省值见括号）
KNOWLEDGE_LINKS_REFS_ALERT_MB=512      # refs 入链条目估算总量（MB）超阈值告警，触发分片评估
KNOWLEDGE_CARD_FILE_ALERT_COUNT=10000000  # wiki 卡片文件总数超阈值告警，触发存储层改造
KNOWLEDGE_CAPACITY_ALERT_COOLDOWN_S=3600  # 同一阈值维度告警冷却（秒），防刷屏
```

读取方式（与项目 env 约定一致）：

```python
import os

def _env_int(name: str, default: int) -> int:
    try:
        return int(os.environ.get(name, "") or default)
    except ValueError:
        logger.warning("环境变量 %s 非法，使用默认值 %d", name, default)
        return default
```

## 3. 埋点位置与实现

### 3.1 refs 条目数统计（入链索引规模）

| 埋点位置 | 触发时机 | 统计内容 |
|---|---|---|
| `links_index.read_links_index` | 每次查表读索引 | 解析出的「引用关系条目数」→ 估算 MB |
| `links_index.rebuild_links_index` | 全量重建 | 重建后 refs 条目数 → 估算 MB |
| `card._has_incoming_links` 回退全扫 | 索引缺失/损坏回退 | 扫描构建的 incoming 条目数 → 估算 MB |

实现（`links_index.py` 内新增纯函数，便于单测）：

```python
# 每条约目 ≈ 46 B（key + value 引用的平均开销，按 refs 合成实验 12.8 MB/20 万条目校准）
_REFS_BYTES_PER_ENTRY = 64  # 含 dict 开销的保守估计（46 B 实测值向上取整）

def estimate_refs_size_mb(entry_count: int) -> float:
    """估算 refs 入链映射驻留内存（MB）。纯函数，零副作用。"""
    return entry_count * _REFS_BYTES_PER_ENTRY / 1024 / 1024

def _check_refs_capacity(entry_count: int, *, index_path) -> None:
    """refs 总量超阈值 → WARNING（带冷却）。观察型埋点，不抛异常。"""
    threshold_mb = _env_int("KNOWLEDGE_LINKS_REFS_ALERT_MB", 512)
    est_mb = estimate_refs_size_mb(entry_count)
    logger.info(
        "容量监控: index=%s refs 条目=%d 估算≈%.1f MB（阈值 %.0f MB）",
        index_path, entry_count, est_mb, threshold_mb,
    )
    if est_mb <= threshold_mb:
        return
    now = time.monotonic()
    if now - _refs_last_warn.get(index_path, 0.0) < _env_int(
        "KNOWLEDGE_CAPACITY_ALERT_COOLDOWN_S", 3600
    ):
        return
    _refs_last_warn[index_path] = now
    logger.warning(
        "容量预警: 入链索引 refs 估算≈%.1f MB 超过阈值 %.0f MB（≈%d 万卡量级），"
        "请启动分片架构评估（见架构演进总结决策边界 ≥500 万卡）",
        est_mb, threshold_mb, entry_count // 200000,
    )
```

> `_refs_last_warn: dict[Path, float]` 模块级冷却表（进程内，与 `_LOG_RECENT` 同风格，简单直白）。

### 3.2 卡片文件数统计（存储层规模）

| 埋点位置 | 触发时机 | 统计内容 |
|---|---|---|
| `card.rebuild_index` 全量重建 | 重建入口 | `list(wiki_root.glob("*/**/*.md"))` 计数 |
| `card.list()` 调用侧（低频工具） | 全库列举 | 复用返回值计数（不额外扫描） |

实现（`card.py`，观察型，不新增 I/O 到热路径）：

```python
def _check_card_file_capacity(card_count: int, *, wiki_root) -> None:
    threshold = _env_int("KNOWLEDGE_CARD_FILE_ALERT_COUNT", 10_000_000)
    logger.info(
        "容量监控: wiki_root=%s 卡片文件=%d（阈值 %d）", wiki_root, card_count, threshold,
    )
    if card_count <= threshold:
        return
    ...  # 同冷却 + WARNING「请评估存储层二级目录/对象存储改造」
```

> 说明：文件数计数只在**已有全库列举结果**时顺带检查（`rebuild_index` 本身即全库扫描，零额外成本），不新增独立扫描（守【简易】：不做热路径无谓 I/O）。

## 4. 告警输出格式（可检索）

统一前缀 `容量监控:`（info）与 `容量预警:`（warning），附**索引路径 / 阈值 / 估算值 / 行动提示**，便于日志检索：

```
INFO  容量监控: index=knowledge/index_links.md refs 条目=200000 估算≈12.8 MB（阈值 512 MB）
WARNING 容量预警: 入链索引 refs 估算≈524.0 MB 超过阈值 512 MB（≈268 万卡量级），请启动分片架构评估...
```

## 5. 测试方案（TDD，先写测试）

| 用例 | 验证点 |
|---|---|
| `test_estimate_refs_size_mb` | 纯函数计算正确（0 条目 → 0 MB；20 万条目 → ≈12.2 MB） |
| `test_refs_below_threshold_no_warning` | refs 未超阈值：无 WARNING（有 info） |
| `test_refs_above_threshold_warns_once` | 超阈值：WARNING 且冷却期内不重复告警 |
| `test_refs_above_threshold_cooldown_elapsed` | 冷却期过后可再次告警 |
| `test_env_threshold_override` | `.env` 覆盖阈值生效（monkeypatch env） |
| `test_env_invalid_value_fallback` | 非法 env 值回落默认值并告警 |
| `test_card_file_capacity_warns` | 卡片文件数超阈值 → WARNING |
| `test_capacity_hook_zero_side_effect` | 埋点存在时 `read_links_index`/`rebuild_links_index` 返回值与未埋点逐字节一致 |

回归：links_index 11 项 + card 回归全部保持绿色（埋点零副作用由 `test_capacity_hook_zero_side_effect` 锁定）。

## 6. 验收标准（DoD）

1. 3.1 / 3.2 埋点落地，阈值与冷却全部 `.env` 配置（缺省 512 MB / 1000 万 / 3600 s）；
2. 超阈值 WARNING 可检索（格式 §4）；未超阈值仅 info；
3. 新增 ≥8 项单测全绿，含「零副作用」锁定用例；
4. 回归 70+ 全绿，一致性不变量未破坏；
5. 更新 `.env.example` / 环境变量对照表（`docs/CONFIG_ENV_REFERENCE.md`）。

## 7. 明确不包含（守【简易】）

- ❌ 不引入第三方付费监控/告警平台（日志告警即可，符合可观测性最小原则）；
- ❌ 不在 `_has_incoming_links` 查表热路径（O(1) 命中）增加额外 I/O——refs 计数只挂在已有解析点；
- ❌ 不自动触发分片/迁移（告警 → 人工评估，防自动化误操作）。
