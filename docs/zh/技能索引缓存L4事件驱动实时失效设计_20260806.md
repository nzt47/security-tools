- **日期**: 2026-08-06
- **模块**: `agent/skills_mgmt/index_cache_watcher.py`（SkillIndexCacheWatcher）
- **关联文档**: [技能索引缓存失效策略与并发排查指南_20260806.md](./技能索引缓存失效策略与并发排查指南_20260806.md) / [技能索引缓存TTL行为边界与规避方案_20260806.md](./技能索引缓存TTL行为边界与规避方案_20260806.md)

---

## 1. 背景与目标

L3 TTL 窗口内"外部直接修改文件"不可见（可见延迟 = 窗口）。L4 用 watchdog
监听技能仓库目录树，**文件变更事件 → 精确失效对应技能（O(k)，k=实际变更数）**，
彻底解决实时性问题，同时保留 L3 快路径性能。

实测对比（1000 技能，TTL 窗口 60s）：

| 指标 | L3 TTL（无 watcher） | L4 事件驱动 |
|---|---|---|
| 外部修改可见延迟（get_all_metadata 旧值消失） | 60s 窗口内不可见 | **avg 27.5ms / p99 33.8ms** |
| 窗口内 get_all_metadata | 0.002ms（快路径） | 0.002ms（快路径，不变） |
| file_store 写操作 | 即时失效 | 即时失效（invalidate） |
| 外部依赖 | 无 | watchdog（可选，缺失自动降级） |

## 2. 架构

```text
watchdog Observer（recursive=True）
        │  文件创建/修改/删除/移动事件
        ▼
_SkillIndexEventHandler  ── _skill_id_from(path) ──► skill_id
        │  submit(skill_id)   ← 事件回调线程，O(1) set.add，不阻塞 observer
        ▼
_SkillEventProcessor._pending（去重集合，背压核心，有界 ≤ 技能数）
        │  后台 drain 线程（每 debounce 秒批量取出）
        ▼
cache.invalidate(skill_id)（纯内存，守持锁不 I/O）
        ▼
下次 get_metadata / get_all_metadata → 回源解析最新磁盘状态
```

### 2.1 事件 → skill_id 映射

- 顶层目录名以 `.` 或 `_` 开头（如 `.index`）→ 忽略
- 技能目录下任意子文件（skill.md / scripts / temp）→ 归并到技能目录名
- moved 事件 → 源路径与目标路径分别提取，各失效一次（幂等）

### 2.2 背压机制（事件风暴防护）

| 机制 | 说明 |
|---|---|
| **去重集合** | `_pending` 为 `set`，同一技能窗口内多次事件只保留一次（上限 = 技能数，天然有界，不 OOM） |
| **回调零阻塞** | 事件回调只做 `set.add`（O(1) 加锁），不持有任何 I/O，observer 事件队列不积压 |
| **批量 drain** | 后台线程每 `debounce` 秒（默认 50ms）批量取出并逐技能 `invalidate`，`debounce` 可配置 |
| **幂等失效** | `invalidate` 对不存在的缓存项是幂等 no-op；stop 时收尾 drain 保证事件不丢 |

高并发实测：800 事件（8 线程 × 100，20 技能）→ pending 有界 ≤ 20，
合并后 invalidate 次数 ≤ 20（同一技能多事件只失效一次），最终缓存一致。

## 3. 降级与可靠性

- **watchdog 不可用 / 启动失败**：`start()` 返回 False，记录 `start.watchdog_missing` /
  `start.failed` 日志，**回退到既有 mtime/hash 校验路径**（功能不受影响，守【不易】）
- **事件延迟处理期间**：`get_metadata` 的 stat+size+hash 校验兜底，仍保证最终一致
- **事件失效 + 校验双保险**：事件驱动是"主动失效"，校验是"被动兜底"，两者不冲突
- **进程内多实例**：各自 observer，互不干扰；跨进程以磁盘为最终事实

## 4. 用法

```python
from agent.skills_mgmt.index_cache_watcher import SkillIndexCacheWatcher

cache = SkillIndexCache(fs, validate_interval=60.0)  # L3 快路径
watcher = SkillIndexCacheWatcher(cache, repo_path, debounce=0.05)
if watcher.start():        # watchdog 缺失/失败 → False，降级
    ...                    # 外部修改 → ~28ms 内可见
    watcher.stop()
```

压测命令：

```powershell
python scripts/bench_skill_index_cache.py --count 1000 --ttl 60 --watch --watch-samples 15
```

## 5. 决策建议（L3 vs L4）

| 场景 | 建议 |
|---|---|
| 应用内 `file_store` 管理技能 | L3 足够（写路径已即时失效） |
| 外部脚本/部署直接写文件，需快速可见 | **L3 + L4**（快路径性能 + 事件实时性） |
| 实时性要求极高（秒级内可见） | L3 + L4，debounce 调小（如 10ms） |
| watchdog 不可用环境 | 仅 L3（可见延迟 = 窗口），或关闭 TTL 走 L1 校验 |

**铁律**：【不易】L4 只做"精确失效"，不直接写缓存数据；失效必须回源。
watchdog 降级不破坏任何既有语义。
