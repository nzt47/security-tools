# memory 模块读写锁重构（方案 A）变更摘要

- 日期：2026-08-24
- 分支：develop
- 提交：`45274291`（fix(memory): 方案A 读写锁重构 — get() 访问统计修复 + reviewer 弃裸连 db）
- 关联：`28f0ffe5`（Loki 异步批量推送 + BM25 索引缓存，同批推送待发）

## 一、背景与目标

memory 模块存在三处读写锁相关风险：

1. **get() 访问统计从未生效**：访问统计 UPDATE 语句写在 `with self._get_conn() as conn:` 块**之外**（连接已关闭），每次执行抛 `ProgrammingError: Cannot operate on a closed database`，被 except 静默吞掉。后果：`access_count` 恒为 0、`last_accessed` 永不刷新，且**每次 get 都走错误日志路径**。
2. **reviewer 绕过 LongTermMemory 内部锁**：`MemoryReviewer._find_stale_entries` / `_find_duplicate_entries` 直接 `sqlite3.connect(self._ltm.db_path)` 裸连读库，绕过锁与 `busy_timeout`，且访问私有成员 `_TABLE_NAME`，与写并发时无兜底。
3. **连接未设 busy_timeout**：违反项目硬约束（SQLite connections must set PRAGMA busy_timeout=5000），写锁竞争时直接抛 `SQLITE_BUSY`。

## 二、变更内容

### 1. long_term_memory.py — busy_timeout 兜底
`_get_conn()` / `_init_db()` / `_get_vec_conn()` 三处连接统一执行 `PRAGMA busy_timeout=5000`：写锁竞争时等待而非立即报错，配合 reviewer 并发读场景兜底。

### 2. long_term_memory.py — 修复 get() 隐藏 bug
访问统计 UPDATE（`last_accessed` / `access_count + 1`）移进连接块内，随 SELECT 同连接执行。修复后：
- `access_count` 按次真实递增
- `last_accessed` 每次 get 刷新
- 消除每次 get 的错误日志噪音

### 3. reviewer.py — 弃裸连，走公开 API
`_find_stale_entries` / `_find_duplicate_entries` 改为调用 `self._ltm.list_recent(limit=_SCAN_LIMIT)`，语义等价：
- 陈旧判定：`last_accessed < threshold AND importance < 4`（原 SQL 等价）
- 重复判定：`md5(content)` 同哈希后续条目标记重复（保留首条）
- 新增模块常量 `_SCAN_LIMIT = 10000`（list_recent 无分页参数，大 limit 近似全量，防漏检）

消除了：绕过锁、私有成员 `_TABLE_NAME` 耦合、无 busy_timeout 兜底的裸连接。
