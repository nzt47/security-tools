## 2. 5000 万节点分片策略

### 2.1 片数权衡（2000 万 → 5000 万演进）

| 片数 | 单片 refs 驻留 | 并行全扫（理想） | 文件数 | 判定 |
|---|---|---|---|---|
| 64 | ≈100 MB | ≈2.9 分钟 | 64+ | 2000 万基线，5000 万已偏高 |
| 128 | ≈50 MB | ≈1.5 分钟 | 128+ | 可行 |
| **256** | **≈25 MB** | **≈44 秒** | 256+ | **推荐** |
| 512 | ≈12.5 MB | ≈22 秒 | 512+ | 过度分片（合并/IO 成本主导） |

**推荐 256 片**：单片 25 MB 回到常驻内存个位数区间；并行全扫理想 44 秒，使「索引损坏回退」从小时级降到分钟级内可接受。

### 2.2 分片路由（同 2000 万设计，片数升级）

```
ref_slug_hash = hash(ref_slug) % 256
shard_file = index_links/<shard_id>.md
```

读侧查表需合并 256 片（总 refs 6.4 GB 仍过大）——**5000 万读路径需二级索引**：单片内按目标 slug 前缀建倒排（`<shard>/<prefix>.idx`），`_has_incoming_links` 只读相关前缀文件。

### 2.3 降级机制映射（5000 万）

| 降级机制 | 2000 万（64 片） | 5000 万（256 片） |
|---|---|---|
| 索引损坏回退 | 全库 75 分钟 → 单片秒级 | 全库 3.1 小时 → 单片秒级（必须后台化） |
| 写失败不阻断 | 不变 | 不变（片级隔离） |
| 全量重建 | 并行 1.2 分钟 | 并行 44 秒（理想），仍需后台任务 |

## 3. 存储层瓶颈：5000 万文件数

| 项 | 数值 | 影响 |
|---|---|---|
| 卡片文件 | 5000 万个 `.md` | 目录 inode 膨胀、遍历/重命名变慢 |
| 单目录文件数 | 约 1667 万/type 目录（极限） | 超出常见文件系统单目录高效区（数千级） |
| 索引分片文件 | 256 + 二级前缀索引 | 可控 |

**结论**：5000 万节点必须引入**二级目录分层**（如 `wiki/<type>/<slug 前 2 字符>/<slug>.md`）或对象存储；否则全库 `list()`/重建遍历将受文件系统目录扫描拖累，实测基准（0.225 ms/卡）不再成立。

## 6. 结论与建议

| 决策维度 | 5000 万节点评估 |
|---|---|
| 内存（现状） | ≈92.9 GB：完全不可行 |
| 内存（流式单机） | ≈6.4 GB：不可行（且 refs 本体即超内存） |
| 内存（分片 256 片） | ≈25 MB/片：可控 |
| 耗时（全扫） | 流式 3.1 小时 vs 分片并行理想 44 秒 |
| **新增瓶颈** | **存储层 5000 万文件数（inode/目录深度）** |
| 架构判定 | **分布式/对象存储线（单机分片已到极限）** |

**建议**：

1. **分片升级到 256 片**（5000 万基线），读路径配二级前缀索引（总 refs 6.4 GB 无法整表合并读）。
2. **存储层改造前置**：5000 万文件数决定必须 `wiki/<type>/<slug 前 2 字符>/` 二级目录分层或对象存储，**否则 0.225 ms/卡 实测基准失效**、遍历/重建整体劣化。
3. **回退/重建彻底后台化**：全库回退 3.1 小时 / 并行 44 秒均不可同步阻塞，需任务队列 + 状态提示。
4. **监控阈值更新**：refs > 512 MB（≈400 万卡）评估分片；refs > 2 GB（≈1600 万卡）评估 128+ 片；文件数 > 1000 万启动存储层分层改造。
5. **一致性验证**：既有「增量叠加 == 全量重建」不变量测试按 256 片改写为片级断言（覆盖矩阵基线：links_index 11 项 + card 降级 7 项）。

## 7. 数据来源与口径

- 实测：3000 卡 rebuild 全峰值 5.6 MB；入链判定全扫 2249 ms/1 万卡、查表 1.07 ms（《第二批对比报告》）
- 合成实验：refs dict 10 万 key/20 万条目 = 12.8 MB（tracemalloc，2026-08-08）
- 外推：线性；分片并行时间为理想化下界，未计调度/合并/路由开销，真实约 2–4x 上浮；存储层影响为定性评估（常见文件系统单目录高效区经验值）
