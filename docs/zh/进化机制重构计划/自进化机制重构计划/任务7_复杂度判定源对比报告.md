# 任务7 复杂度判定源对比报告（wire 启发式 vs enhanced_planner 分级）

> 所属计划：`docs/zh/进化机制重构计划/自进化机制重构计划/进化机制理想设计.md`（阶段三·任务7）
> 成文日期：2026-08-22
> 数据复现：`python scripts/complexity_source_compare.py`（明细落盘 `data/complexity_compare_result.json`）

---

## 1. 背景与目的

TASK-08 报告 §4.1 课程学习降级方案复用 `enhanced_planner` 的任务复杂度分级
（TRIVIAL→SIMPLE→NORMAL→COMPLEX）作课程阶梯。审计发现**复杂度判定双源并存**：

| 判定源 | 实现 | 生产状态 |
|---|---|---|
| wire 启发式 | `agent/orchestrator/orchestrator.py` `_judge_wire_complexity`：score = 复杂指示词数 + 0.5×动作词数；≥1.5→COMPLEX / ≥1.0→NORMAL / ≥0.5→SIMPLE / 其余 TRIVIAL | **生产在用**（`planning.wire_enabled=false` 灰度态，判定随 wire 分支 inert） |
| enhanced_planner 分级 | `agent/task_planner/enhanced_planner.py` `EnhancedTaskPlanner._evaluate_complexity`：关键词高→低匹配（COMPLEX→MODERATE→SIMPLE→TRIVIAL），无命中默认 SIMPLE | **无任何生产调用方**（仅测试引用） |

课程难度自适应若直接依赖 enhanced_planner，与生产 wire 判定可能不一致，形成"双源口径"。
本报告在抽样集上量化两源的一致性与分歧形态，为判定源统一选型提供**数据支撑（非主观）**。

## 2. 抽样集

| 构成 | 数量 | 说明 |
|---|---|---|
| 任务1 评估集（`data/evals/`） | 50 | search/code/chat/tool/planning 五类，含人工难度标注 `metadata.difficulty`（作参考锚点） |
| 生产对话风格抽样（`data/complexity_samples.json`） | 150 | 数字生活助手常见用户语句（查询/文案/分析/设计/架构/迁移/多步骤/完整方案等），无参考标注 |
| **合计** | **200** | 判定文本 = 评估集 `task` 字段 / 抽样 `message` 字段 |

复现：`python scripts/complexity_source_compare.py`（两判定源各跑 200 条，输出一致率/分布/交叉表/符合率/分歧样例，落盘 JSON）。

## 3. 一致率（核心结论①：双源严重不一致）

**两判定源在 200 条抽样上一致率 = 59/200 = 29.50%。**

双源并非"细微口径差异"，而是系统性分歧：约 70% 的样本两源给出不同分档。这证实了任务背景的判断
——课程难度自适应若分别依赖两源，会产生口径完全不同的课程阶梯。

## 5. 与人工难度标注符合率（评估集 50 条子集）

以任务1 评估集人工标注 `difficulty` 为参考锚点（标注语义按评估集 README 声明"复用 enhanced_planner 复杂度语义"）：

| 判定源 | 符合数/总数 | 符合率 |
|---|---|---|
| wire 启发式 | 10/50 | **20.00%** |
| enhanced_planner | 16/50 | **32.00%** |

解读：

- enhanced_planner 符合率高于 wire（32% vs 20%），与其"标注语义同源"的预期一致，但**绝对值仍然很低**
  ——评估集样本为任务描述文本（含"实现/查询/规划"等指令性前缀），与生产 wire 输入（用户原句）形态不同；
  50 条标注样本统计功效有限，不宜据此单独做选型。
- 两个判定源都不能被视为"贴近人工难度标注"的成熟口径，课程阶梯启用前需更大规模人工标注校准
  （任务1 评估集扩充管道 `data/evals/_pending/` 正是该通道）。

## 7. 选型结论（核心结论②）

对照任务7 Step 1 的三个候选结论：

| 候选 | 评估 | 是否采纳 |
|---|---|---|
| ① 统一到 enhanced_planner | 一致率仅 29.5%；绝对符合率 32% 仍低；切换将改变 wire 判定语义（默认态行为变化，违反"wire 默认态不变"不变式）；且 enhanced_planner 词表对生产用户语句覆盖同样有限 | **不采纳（当前）** |
| ② 统一到 wire 启发式并升级为独立模块 | wire 已是生产现状，升级为独立模块零行为变化，但放弃 enhanced_planner 对齐（课程阶梯与规划分支口径需后续校准） | **部分采纳（作为默认实现）** |
| ③ 封装统一接口 `ComplexityClassifier`，内部实现可切换 | 单一入口消除双源；默认 wire（最小 diff、主链路零退化）；enhanced_planner 作为灰度候选可经 `COMPLEXITY_SOURCE` 切换复评 | **采纳（推荐）** |

**最终结论：采用 ③ —— 封装统一接口 `ComplexityClassifier`（`agent/task_planner/complexity_classifier.py`），
默认实现 = wire 启发式（与生产现状逐字节等价），内部实现可按 `COMPLEXITY_SOURCE`（默认 `wire`）切换。**

决策依据（数据支撑）：

1. **双源一致性仅 29.5%**，任何"直接复用 enhanced_planner 作课程阶梯"的接线都会与生产 wire 判定
   系统性不一致——必须先统一入口，而不是任选一源接线。
2. **两个判定源对人工标注符合率均低（20%/32%）**，说明当前阶段没有"明显更优"的实现：
   用最小 diff 的 wire 作默认（零行为变化），把 enhanced_planner 保留为可切换候选，
   待课程阶梯启用决策时（需任务1 评估集扩充 + 更大样本人工标注 + 任务2 KPI 监控数据）再定最终实现。
3. **守不变式**：wire 分支默认态（`planning.wire_enabled=false`）行为不变（默认 wire 实现逐字节等价）；
   `enhanced_planner.py` 内部实现未修改（适配器只封装调用）；统一接口异常兜底不影响主链路。

## 8. 局限性（数据口径披露）

- 抽样集 200 条中 150 条为人工构造的生产风格样本（curated_prod），非真实生产日志脱敏采样——
  因无真实对话日志接入（任务1 `_pending/` 回流管道默认关闭）；如需更严格口径，应在评估集扩充
  与真实日志脱敏回流就绪后重跑本脚本。
- 评估集 50 条样本文本为**任务描述**（含"实现/查询/规划"指令前缀），与生产 wire 输入（用户原句）
  形态不同，两源在真实输入上的分歧形态可能与本报告略有出入。
- 人工参考标注仅 50 条，符合率统计功效有限；LLM-as-Judge 对照属任务5 范畴，不在本报告内。

## 9. 变更对照

| 项 | 变更前 | 变更后 |
|---|---|---|
| 复杂度判定实现位置 | orchestrator 内联 `_judge_wire_complexity` + enhanced_planner 无生产调用方（双源） | 统一模块 `agent/task_planner/complexity_classifier.py`（单一入口，默认 wire，可切换 enhanced_planner） |
| wire 层实现 | 自实现分级逻辑 | 薄委托统一接口（代码审计可证单一入口） |
| 默认行为 | wire 启发式 | 与任务7 之前**逐字节等价**（抽样集 200 条全量断言一致） |
| 配置 | 无 | `COMPLEXITY_SOURCE`（env）/ `learning.complexity.source`（config.yaml），默认 `wire` |
