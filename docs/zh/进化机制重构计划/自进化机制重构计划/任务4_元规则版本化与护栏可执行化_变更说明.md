## 一、背景（为什么做）

TASK-08 护栏 G1 要求："更新规则本身（变异策略、评估阈值、进化权重、触发条件）
必须进入版本管理，任何变更走 bump_version + 门控；禁止运行时无版本修改"。
元审计（T5）确认：进化参数散落 `.env` / `config.yaml` / 代码默认值**三层且无版本化**，
G1 无落地载体；同时 G2-G5 构件（`value_guard.py` / `EvolutionArchive` / `approval.py` /
`rollback.py` / `StagedEvaluator` / 任务1 回归门禁）均已存在但**分散**，决策层无法随时回答
"当前护栏是否全就绪、最近一次元规则变更是什么、如何回滚"。

本任务建立**元规则版本化存储 + 变更门控 + 回滚**，并把 G1-G5 收口为统一只读护栏状态服务。

### 2. 版本化存储与 CLI `agent/learning/meta_policy.py`

存储布局（`data/learning/meta_policy/`，默认只读）：

| 文件 | 语义 |
| --- | --- |
| `schema.json` | 元规则登记表（本任务交付物 1） |
| `current.json` | 当前生效版本指针与值快照（仅审批链 merge 时更新） |
| `pending.json` | 待审批变更（**单槽串行**：pending 期间拒绝新变更，防覆盖） |
| `versions/vN.json` | 不可变版本快照（v1=初始登记默认值；bump/rollback 只追加） |
| `audit.jsonl` | G3 审计（ts/event/change_id/param/old/new/approver/actor/status/approval_record_id/rollback_command） |

CLI（`python -m agent.learning.meta_policy`）：`list` / `show` / `status` / `bump` /
`rollback` / `diff` / `validate` / `approve` / `reject` / `migrate` / `audit`。

- `bump`：schema 校验（非法值**回退默认**，沿用 EVO 总览 §六.2）→ 快照当前 → 写新版本
  （pending）→ 进入审批队列（复用 `approval.py`，`object_type=meta_policy`，
  `action=bump_version`，级别默认 L1）；批准并 merge 后生效，拒绝保持当前版本。
- `rollback`：回滚到目标版本（默认上一版本）——**回滚本身也是受控变更**
  （走同款 bump + 审批 + 审计，G1：更新规则本身也是被管制的对象）。
- `diff`：版本间差异（默认当前 vs 上一版本）。
- `migrate`：迁移预演（默认 dry-run，仅报告 .env/config 运行时值与存储快照的差异；
  apply 受 `META_POLICY_MIGRATE_DRY_RUN_ONLY` 门控，且仍走审批链）。
- 变更失败**绝不阻断主流程**：所有写操作异常 → 告警 + 返回错误结果。

### 3. 变更门控（Step 3）

- 审批链复用 `approval.py` **公开 API**（submit/approve/reject/merge/mark_manual_executed），
  未修改其接口；跨进程 CLI 审批（无进程内 applier）时降级为 store 直接激活 + 归档，
  状态迁移保持合法（approved → merged / approved → archived）。
- 生效前 schema 校验：未登记参数 → 拒绝；非法值 → 回退默认 + 告警。
- 每次 bump/rollback/approve/reject/apply 写 G3 审计（字段齐备，含 `rollback_command`）。

### 4. 护栏状态服务 `agent/learning/guard_status.py` + `/api/learning/guards`

聚合 G1-G5（每项含 `enabled/status/最近变更/回滚命令`），数据来源全部为既有模块只读查询：

| 护栏 | 数据源 | 状态语义 |
| --- | --- | --- |
| G1 元规则版本化 | `MetaPolicyStore.status()` | ready（版本/待审批/回滚命令） |
| G2 价值观红线 | `ValueGuard`（启用/LLM/红线规则数） | ready/degraded |
| G3 谱系完整性 | `EvolutionArchive`（记录数/决策分布/父代链接/最近记录） | ready/empty |
| G4 回滚与预算 | `AutoRollback` 阈值 + `LearningBudget` 模式 | ready |
| G5 回归与观察期 | `eval_regression` 配置/基线数/评估集规模 + `learning.metrics.trigger_monitoring` 观察窗口 | ready/watching/disabled |

只读端点：`GET /api/learning/guards`（注册于 `agent/learning_metrics_api.py` 的
`learning_metrics_bp`，`app_server.py` 已注册该蓝图，零额外接线）。
`summary.all_ready` 提供 L3 里程碑门"G1-G5 全就绪"判定。

## 五、使用示例

```bash
# 1. 查询护栏状态（只读端点）
curl http://127.0.0.1:3080/api/learning/guards

# 2. 元规则状态与版本
python -m agent.learning.meta_policy status
python -m agent.learning.meta_policy list

# 3. 提出元规则变更（→ 审批队列，未批准零生效）
python -m agent.learning.meta_policy bump \
    --param schedule.evolver_interval_days=14 \
    --description "调整周期进化间隔为 14 天"

# 4. 审批/驳回（CLI 可跨进程；批准后版本生效）
python -m agent.learning.meta_policy approve --record appr-20260822xxxx
python -m agent.learning.meta_policy reject --record appr-20260822xxxx --reason "暂缓"

# 5. 回滚到上一版本（本身走审批链 + 审计）
python -m agent.learning.meta_policy rollback

# 6. 迁移预演（默认 dry-run，仅报告差异）
python -m agent.learning.meta_policy migrate

# 7. 审计回溯（G3）
python -m agent.learning.meta_policy audit
```
