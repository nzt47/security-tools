## 1. 本次变更内容

### 1.1 复杂度判定源统一（Step 1-2）

- **新增** `agent/task_planner/complexity_classifier.py`：复杂度判定统一接口
  `ComplexityClassifier`（单一入口），内部实现可切换：
  - `WireHeuristicClassifier`：生产 wire 启发式的独立模块化形态（公式/关键词/阈值与
    任务7 之前 `_judge_wire_complexity` **逐字节等价**，默认实现）；
  - `EnhancedPlannerClassifier`：enhanced_planner 分级适配器（**只封装调用
    `_evaluate_complexity` 纯函数，不修改 `enhanced_planner.py` 内部实现**；
    MODERATE 归一到 canonical NORMAL）；
  - 判定源配置：`COMPLEXITY_SOURCE`（环境变量）> `config.yaml learning.complexity.source`
    > 默认 `wire`（非法值回退 wire）。
- **改造** `agent/orchestrator/orchestrator.py`：`_judge_wire_complexity` /
  `_wire_complexity_detail` / `_wire_complexity_meets` 改为**薄委托统一接口**
  （wire 层不再自行实现分级逻辑，代码审计可证单一入口）；兼容别名
  `_WIRE_COMPLEXITY_LEVELS` 等指向统一模块常量；
  **`judged_complexity` 写入路由元数据**：最终路由决策 `emit_route_decision` basis_extra
  与响应 `metadata.judged_complexity`（wire 开启时；关闭时为 None 零影响），
  与任务1 评估集 `difficulty` 字段同口径（TRIVIAL/SIMPLE/NORMAL/COMPLEX）。
- **不变式**：`planning.wire_enabled=false`（默认）时 wire 分支行为与现状完全一致
  （默认 wire 实现逐字节等价，抽样集 200 条全量断言 + 既有 wire 单测回归通过）。

### 1.2 复杂度维度 KPI（Step 3）

- **改造** `agent/learning_metrics.py`：`record_task_result` 的 `judged_complexity`
  扩展键升级为 **task_type × complexity 双维度**：
  - `get_snapshot()` 新增 `failure_rate_by_task_type_complexity`
    （嵌套 task_type → complexity → {total, failed, rate}）；
  - `get_weekly_kpis()` 周行同口径（事件 key `task_type::complexity`）；
  - 持久化重启恢复（`_load_from_db` 支持新事件 kind）；
  - `MODERATE` 别名归一到 `NORMAL`（与统一判定源口径一致）；
  - **向后兼容**：task_type 既有口径、单维度复杂度桶（任务2 预留）、既有 kpis 键全部保留
    （新增键为纯增量）。
- KPI#4 双维度口径为课程难度自适应策略的数据源（"通关"判据）。

### 1.3 课程难度自适应策略（Step 4，默认关闭）

- **新增** `agent/learning/curriculum.py`：`CurriculumStrategy` 只读建议引擎
  - 输入：KPI#4 双维度（`get_weekly_kpis()` 周行 或 `get_snapshot()["kpis"]`）；
  - 输出：各复杂度档成功率基线 + 低档稳定性门槛判定 + 路由概率调整建议 + 审计；
  - 规则（推断级，方案先落地）：
    - 低复杂度档（TRIVIAL/SIMPLE）失败率 > 门槛（默认 0.30）→ **封锁**高复杂度档提升；
    - 高复杂度档（NORMAL/COMPLEX）成功率 ≥ 基线（默认 0.70）且样本 ≥ min_samples（默认 5）
      → 建议 +max_step（默认 0.1）；
    - 样本不足 → insufficient_data，不输出建议；
  - 审计：`observe` → decision=preview / `active` → decision=apply（JSONL）；
  - **默认关闭**：`LEARNING_CURRICULUM_ENABLED=false`（config.yaml `learning.curriculum.enabled: false`）
    ——enabled=false 时 `evaluate()` 零建议、零审计，路由行为与现状一致（测试证明）。
  - **本任务不接线任何路由层调整**：建议仅供人工/后续决策消费（启用属后续人工决策）。

### 1.4 配置与文档

- `config.yaml`：新增 `learning.complexity.source`（默认 wire）与 `learning.curriculum.*`
  （默认关闭）配置段；

- 对比报告：`任务7_复杂度判定源对比报告.md`（抽样集 200 条，数据支撑选型结论）。
