## 一、结案总论

**任务6 全部验收达标，沙箱回放与评估隔离加固可结案。** 本任务落地 TASK-08 报告 §4.2
"沙箱回放 = 合成边缘案例"的**安全前提**：针对审计确认的"软隔离（同进程执行、黑名单
可绕过、资源限制不 enforcement）"与"无回放基础设施"两个断点，建立评估回放隔离层
（`agent/learning/replay.py`）——不可信轨迹/候选产物在**全新解释器进程**执行，
受限 builtins + 受限 import（危险模块惰性代理）+ 环境白名单 + 墙钟超时强杀 +
输出/并发上限，fail-closed；并提供回放管道（复用任务1 评估集回归通道，样本走
black_box 脱敏管道）。**默认关闭（`EVAL_REPLAY_ENABLED=false`），零行为变化。**

**验收核心结论**：
- 危险样本安全用例 **6/6 被拦截/超时**（5 escape + 1 timeout 真实进程强杀），宿主零残留
  （无新文件/无残留进程/无 scratch 残留，psutil + 文件集差异断言）；
- **fail-closed**：spawn/docker/后端不可用 → `ReplayIsolationError` 显式失败，
  绝不降级同进程执行（单测证明）；回放默认关闭（`ReplayDisabledError` 显式拒绝）；
- **脱敏**：PII 样本端到端断言明文不出隔离环境（证据/审计/工作目录均无明文）；
- **零共享写路径**：独立 scratch（系统临时区）+ 素材目录 hash 回放前后不变；
- **性能基准**：单样本墙钟 94–125ms（avg 109ms）、RSS ≈16.6MB，与 EVO-T2 §3
  （60–98ms 子进程冷启动）同量级；
- 不变式守约：`SkillExecutor`/`evaluator.py` **零修改**（git diff 为空）。

## 五、问题与解决方案（收尾阶段）

| 问题 | 解决方案 |
|---|---|
| 本沙箱禁命名/匿名管道（`multiprocessing.Queue`/`subprocess` pipes → WinError 5），默认 spawn 执行器无法本地验证 | 新增 `subprocess` 文件交换执行器（零管道依赖，仍为全新解释器进程隔离）；`EVAL_REPLAY_RUNNER=subprocess` 显式启用；spawn 不可用时 fail-closed（含提示信息） |
| Windows 下子进程 CWD 目录句柄延迟释放（约 1s），scratch 目录删除失败 | worker cwd 改为引擎工作根（持久目录），scratch 仅承载数据文件；删除重试兜底 + 空容器目录清理 |
| 旧版 bootstrap 缓存文件导致 worker 逻辑漂移（早期调试实测） | bootstrap 内嵌 `__REPLAY_BOOTSTRAP_VERSION__` 版本标记，引擎按标记重新生成（单测锁定） |
| 全量回归 87 failed / 14 errors | 逐一归因：全部为环境性（沙箱禁管道 → WinError 5 的 `subprocess.run(capture_output=True)` 类用例、`sqlite_vec` 被 conftest 禁用、CLI 子进程类）或既有问题；grep 审计证明 `EVAL_REPLAY`/`learning.replay` 仅存在于本任务两个文件，零耦合 |
| `config.yaml`/`.env.example` 与并行会话共享文件 | config.yaml（含本任务 replay 块）已随并行会话提交入库；`.env.example` 的 `EVAL_REPLAY_*` 登记在本收尾提交中 |
