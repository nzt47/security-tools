## 一、结案总论

**任务7 全部验收达标，课程难度自适应与复杂度判定源统一可结案。** 本任务解决元审计
断点"复杂度判定双源并存：生产 wire 用 `_judge_wire_complexity` 启发式，`enhanced_planner`
无生产调用方"（计划 §4.3-5）与"复杂度维度无 KPI 数据"（KPI#4 COMPLEX 为 T01 接线后扩展项），
为 TASK-08 报告 F4"课程学习降级为难度自适应"落地提供数据源与判定基础。

**验收核心结论**：

- **复杂度判定源统一为单一入口**：`agent/task_planner/complexity_classifier.py`
  `ComplexityClassifier`（默认 wire 实现，与任务7 之前启发式**逐字节等价**；
  enhanced_planner 分级保留为可切换灰度候选）；wire 层改为薄委托（代码审计可证单一入口）；
- **对比报告数据支撑选型**：抽样集 200 条（评估集 50 + 生产风格 150）实测
  **两判定源一致率仅 29.50%**、与人工标注符合率 wire 20% / enhanced 32% ——
  采纳"统一接口、默认 wire、内部可切换"（候选③），以最小 diff 与主链路零退化为准；
- **KPI#4 支持 task_type × complexity 双维度**：`failure_rate_by_task_type_complexity`
  入快照与周级滚动统计，持久化重启可恢复，既有 task_type 口径向后兼容；
- **难度自适应策略默认关闭**：`agent/learning/curriculum.py` 读 KPI#4 双维度 →
  各复杂度档成功率基线 → 低档失败率超门槛封锁提升 / 高档成功率 ≥70% 且样本达标才建议
  +步长；`LEARNING_CURRICULUM_ENABLED=false`（观察模式）零建议零审计零副作用，
  本任务**未接线任何路由层**（启用属后续人工决策，不进入本任务生产启用范围）。

## 五、问题与解决方案

| # | 问题 | 解决方案 |
|---|---|---|
| 1 | **双源一致性极低（29.50%）**：wire 与 enhanced_planner 系统性分歧（TRIVIAL↔SIMPLE 74 例、NORMAL↔COMPLEX 35 例等），任何"直接复用 enhanced_planner 作课程阶梯"都会与生产判定不一致 | 不任选一源接线，先统一入口（候选③）；默认 wire 零行为变化，enhanced_planner 保留可切换灰度，待更大样本人工标注后再定最终实现 |
| 2 | 两源对人工标注符合率均低（20%/32%）：评估集样本为任务描述文本（含指令性前缀），非原始用户语句，统计功效有限 | 报告 §8 局限性披露；课程阶梯启用前需任务1 评估集扩充 + 更大样本人工标注 + 任务2 KPI 监控数据（启用属后续人工决策） |
| 3 | **多会话并行工作区**：任务5 提交（`f076467c`）以 `add -A` 捎带入库了本任务 learning_metrics.py/config.yaml/.env.example/learning/__init__.py 的修改（git 历史归属为任务5，代码内容正确且自洽） | 本任务提交时精确 add 剩余文件（`beb7521e` + `af7304db`），未触碰任何其他并行任务（任务6/T8/M2/yunshu-ui）的未提交工作；历史归属问题在结案报告中如实披露 |
| 4 | 沙箱环境限制：pytest 子进程 spawn（命名管道）被沙箱阻止（EPERM），pre-commit guard 的 git 同步检查与部分测试（knowledge_cli/mcp_executor/probe 等）无法在本地跑通 | 判定为环境性失败（与代码无关），在回归报告中如实披露；CI 环境无此限制 |
| 5 | 课程策略测试若写默认审计路径会污染工作区（data/learning/curriculum_audit.jsonl 被测试追加 27KB） | 单测全部改用 tmp_path 审计文件；占位文件重置为 0 字节入库（与 rollout_audit.jsonl 惯例一致） |
