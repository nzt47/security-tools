## 一、背景（为什么做）

TASK-08 报告"中期"结论：开启策略工件级自进化（L2）需要**受控放行机制**。审计确认
大部分构件已存在（`feedback_agent` / `evolution_scheduler` / `lifecycle` 均
`enabled=true, dry_run=true`；EVO-T1~T6 谱系/审批/回滚齐备），但只有"dry-run
（零副作用）"与"关闭"两态，缺少渐进台阶：

- **observe**：执行真实评估与建议生成但零提交（积累"若放行会怎样"的数据）；
- **confirm**：产物进审批队列，人工批准后提交（复用 `approval.py`）；
- **rollout**：按比例命中新版本 + KPI 无劣化自动回退（任务2 监控判据）；
- 以及统一的放行判据与一键总开关。

本任务建立 **dry_run → observe → confirm → rollout 四态放行框架**，把三类进化动作
（feedback 晋升/淘汰、evolver 提交、lifecycle 迁移）纳入统一管控，接任务1 回归门禁
（G5 第一层）与任务2 KPI 监控（G5 第二层）。

## 二、交付内容

### 1. 放行状态机 `agent/learning/rollout_controller.py`（新增）

- 四态：`dry_run`（默认，零副作用）/ `observe` / `confirm` / `rollout`；
- 每类动作独立配置模式，环境变量可覆盖（`LEARNING_ROLLOUT_<ACTION>_MODE`）；
- 统一 API：`mode_for(action)` / `can_commit(action)` / `record_preview(action, report)`
  / `enqueue_confirm(action, report, run_real)` / `approve(action, approval_record_id)`
  / `reject(...)` / `run_rollout(action, dry_runner, run_real)` / `rollback(action, candidate_id)`
  / `run_scheduled(action, dry_runner, run_real)`（调度出口统一入口）/ `status()`；
- **一键总开关** `LEARNING_ROLLOUT_MASTER_ENABLED`（默认 false）：false 时所有动作
  强制 dry_run（`mode_for` 直接短路，越级拦截的第一道闸）。

### 2. 四态行为

| 模式 | 调度出口行为 | 副作用 |
| --- | --- | --- |
| `dry_run` | 以 dry_run=True 调用执行体（候选生成/预演） | 零（与现状一致） |
| `observe` | dry_run 预演 → 逐候选写谱系 `decision=preview` + 放行审计 | 仅谱系 preview + 审计 JSONL，零提交/零 KPI/零版本变更 |
| `confirm` | 候选入审批队列（`approval.py` L1）→ 人工批准 → merge 时提交 | 未审批零提交；提交前强制回归门禁 |
| `rollout` | KPI 观察期判据 → 比例命中（`rollout_ratio`）→ 真实提交 | 未命中零提交；命中后 KPI 连续恶化自动回退 |

- **observe 预演采纳率**：`preview_stats(action)` 从放行审计统计 preview 候选数
  （与任务2 `evolution_adoption_rate` 真实采纳率区分），作为任务2 监控的
  "预演采纳率"数据源（消费 `data/learning/rollout_audit.jsonl`）。

### 3. confirm 态：审批队列 + 提交前回归门禁

- 候选批量生成审批记录（`ApprovalFlow`，level=L1，`object_type=rollout:<action>`）；
- 入队前记录 before 版本 + 参数快照 + 回归门禁预检（任务1），提交时强制复核；
- `approve()`：`approval_flow.approve → merge`；merge 前回归门禁
  （`LEARNING_ROLLOUT_REGRESSION_GATE`，默认 `enforce`）——
  **FAIL/NO_SAMPLES → RolloutGateError 拦截，审批记录归档，审计 decision=rejected，
  零提交**；PASS → 提交生效，审计 decision=approved（含 before/after 版本号）；
- `reject()`：人工驳回，审计 decision=rejected；
- **越级拦截**：`approve()` 首先校验 `can_commit(action)`（非 confirm/rollout 或
  总开关关闭一律 RolloutGateError）。

### 4. rollout 态：比例命中 + KPI 自动回退

- G5 第二层判据（纯函数 `judge_kpi_degradation(weekly_rows, window_weeks)`）：
  任一 KPI（token 复用率 / skill 命中率 / workflow 命中率 / 分类型失败率 /
  feedback 均分 / 进化采纳率 / 沉淀增量）连续 `kpi_rollback_window_weeks`（默认 2）
  个评估周期恶化 → 触发；数据缺失周不判恶化（保守防误回退）；
- 触发后 `auto_rollback()` 对最近 approved 候选逐条 `rollback()`（回滚上一版本 +
  参数快照恢复）+ 告警 + 审计 `decision=rolled_back`（含 `rollback_command`）；
- 未触发则按 `rollout_ratio` 比例命中：未命中 → 预演零提交（审计
  `skipped_by_ratio`）；命中 → 候选回归门禁预检 → `run_real()` 真实提交 →
  审计 `decision=approved`（含 before/after 版本与 KPI 快照）。

### 5. 回滚（快照比对一致）

- `rollback(action, candidate_id)`：按审计记录定位候选 → `rollback_version` 回滚
  内容 + `params_snapshot` 恢复 default_params → 行为与旧版本一致；
- 回滚命令写入审计 `rollback_command`，供人工复核与复现。

### 6. 调度出口接线 `agent/skills_mgmt/learning_scheduler.py`（修改）

- `register_learning_schedulers()` 注册后，把三类进化动作的已注册任务 func
  （"反馈建议执行"/"周期进化"/"生命周期检查"）替换为放行包装器
  （`_make_rollout_wrapper` → `controller.run_scheduled`）；
- 包装器以 dry_run=True 调用执行体（observe/confirm/rollout 预检保证零提交，
  不受模块自身 dry_run 配置影响）；
- **默认零行为变化**：总开关关闭 → 全部 dry_run，与既有
  `learning.<模块>.dry_run=true` 语义一致；包装失败回退原 func；
- `behavior_drift`（感知侧）不属进化动作，不接入放行框架。

### 7. 配置开关（优先级：环境变量 > config.yaml > 硬编码默认值）

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| `LEARNING_ROLLOUT_MASTER_ENABLED` | `false` | 一键总开关；关闭时全部强制 dry_run |
| `LEARNING_ROLLOUT_AUDIT_FILE` | `./data/learning/rollout_audit.jsonl` | 放行审计日志 |
| `LEARNING_ROLLOUT_REGRESSION_GATE` | `enforce` | 回归门禁模式（enforce/warn_only/off） |
| `LEARNING_ROLLOUT_<ACTION>_MODE` | `dry_run` | 各动作放行模式 |
| `LEARNING_ROLLOUT_<ACTION>_ROLLOUT_RATIO` | `0.1` | rollout 命中比例（0-1） |
| `LEARNING_ROLLOUT_<ACTION>_KPI_ROLLBACK_WINDOW_WEEKS` | `2` | KPI 连续恶化回退窗口（周） |

config.yaml 对应节点：`learning.rollout.*`（master_enabled / regression_gate /
audit_file / feedback / evolution / lifecycle 三段）。

### 8. 审计字段（统一，`rollout_audit.jsonl` 逐条 JSONL）

`ts / event / action / mode / candidate_id / object_id / parent_record_id /
approval_record_id / decision(preview|approved|rejected|rolled_back) /
before_version / after_version / regression_result / kpi_snapshot /
rollback_command / detail`

### 9. 最小必要扩展（披露）

- `agent/skills_mgmt/lineage.py`：`DECISIONS` 元组**追加 `"preview"`**（1 行）。
  背景：验收要求 observe 结果写 `EvolutionArchive（decision=preview）`，而
  `EvolutionArchive.append` 校验 decision 必须 ∈ DECISIONS。该扩展为**纯增量**：
  不触碰任何进化算法/建议生成逻辑/既有记录，仅使新决策值可落库；
  既有 `committed/rejected/skipped/pending_review/rolled_back/batch_run` 语义不变。
- 如后续不接受该扩展，observe 预演将退化为"仅放行审计留痕、不写谱系"，
  需在本任务验收时说明。

## 五、使用示例（放行操作手册见 `任务3_放行操作手册.md`）

```bash
# 1. 查看放行状态（默认全 dry_run）
python -m agent.learning.rollout_controller --status

# 2. 手动触发一轮调度（按当前模式执行，等价调度出口）
python -m agent.learning.rollout_controller --action evolution --run-scheduled

# 3. observe 预演（显式，写谱系 preview + 审计）
python -m agent.learning.rollout_controller --action feedback --preview

# 4. 预演采纳率统计（喂任务2 监控）
python -m agent.learning.rollout_controller --preview-stats --action feedback

# 5. 人工确认（confirm 态）：批准 / 驳回审批记录
python -m agent.learning.rollout_controller --action feedback --approve <approval_record_id>
python -m agent.learning.rollout_controller --action feedback --reject <approval_record_id> --reason "暂缓"

# 6. 一键回滚
python -m agent.learning.rollout_controller --action evolution --rollback --candidate <candidate_id>
```
