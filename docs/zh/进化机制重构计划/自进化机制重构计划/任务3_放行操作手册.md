# 任务3：放行操作手册（人工确认流程）

> 适用对象：决策层 / 运维 / 审批人
> 目标：按"dry-run → observe → confirm → rollout"逐级放行三类进化动作
> （feedback 晋升/淘汰、evolver 提交、lifecycle 迁移），任何一级均有
> 审计留痕、可一键回退、可一键总关。
> 配套：`任务3_L2自进化闭环受控放行_变更说明.md`

---

## 0. 安全底线（先读）

1. **默认全部 dry_run**：`LEARNING_ROLLOUT_MASTER_ENABLED=false`（config.yaml
   `learning.rollout.master_enabled=false`）。总开关关闭时，无论单动作模式配成什么，
   调度出口一律强制 dry_run（零提交）。
2. **总开关是最后一道闸**：任何时刻 `LEARNING_ROLLOUT_MASTER_ENABLED=false` 即可
   一键回到零提交状态（下一次调度触发即生效，无需重启）。
3. **rollout 前置条件**：回归门禁 PASS + 审批通过（confirm 路径）双门槛；
   `LEARNING_ROLLOUT_REGRESSION_GATE` 默认 `enforce`（FAIL/NO_SAMPLES 拦截提交）。
4. **启用放行 = 人工决策**：本手册仅为操作流程；是否放行、放行到哪一级由决策层
   书面决定，并记录到 `data/learning/rollout_audit.jsonl`（人工操作本身也应留痕）。

## 1. 第一步：查看当前放行状态

```bash
python -m agent.learning.rollout_controller --status
```

输出示例（默认态）：

```json
{
  "master_enabled": false,
  "regression_gate": "enforce",
  "actions": {
    "feedback":  { "mode": "dry_run", "can_commit": false, "rollout_ratio": 0.1, "kpi_rollback_window_weeks": 2 },
    "evolution": { "mode": "dry_run", "can_commit": false, "rollout_ratio": 0.1, "kpi_rollback_window_weeks": 2 },
    "lifecycle": { "mode": "dry_run", "can_commit": false, "rollout_ratio": 0.1, "kpi_rollback_window_weeks": 2 }
  }
}
```

`can_commit=false` 表示当前不可提交（越级拦截生效）。

## 2. 逐级放行流程

放行顺序建议（每级稳定运行 ≥ 1 个评估周期后再升一级）：

### 级别 0：dry_run（默认，零副作用）

什么都不用做。调度照常注册（`learning.<模块>.enabled=true`），但全部只做
预演/候选生成，零提交、零 KPI、零版本变更——与放行框架引入前的行为完全一致。

### 级别 1：observe（观察，真实评估 + 零提交）

目的：积累"若放行会怎样"的数据（谱系 `decision=preview` + 放行审计）。

开启方式（示例：feedback；evolution/lifecycle 同理）：

```bash
# config.yaml learning.rollout.feedback.mode: observe
# 或环境变量覆盖（优先级更高）：
LEARNING_ROLLOUT_MASTER_ENABLED=true
LEARNING_ROLLOUT_FEEDBACK_MODE=observe
```

- 调度触发后：执行体以 dry_run=True 跑完整分析 → 每个候选写
  `EvolutionArchive`（decision=preview）+ `data/learning/rollout_audit.jsonl`
  （decision=preview，含 before_version）；
- 验证：`python -m agent.learning.rollout_controller --preview-stats --action feedback`
  应看到 preview 计数增长；技能版本号不变；
- 退出：关闭环境变量或改回 `mode: dry_run`。

### 级别 2：confirm（人工确认，审批后提交）

目的：候选进入审批队列，人工逐批批准后才提交；提交前强制回归门禁。

开启方式（示例：evolution）：

```bash
LEARNING_ROLLOUT_MASTER_ENABLED=true
LEARNING_ROLLOUT_EVOLUTION_MODE=confirm
```

日常操作（审批人）：

```bash
# 1. 查看待审批记录（data/approval_records.jsonl，state=pending_review）
#    或从放行审计里按 approval_record_id 追溯候选明细

# 2. 批准（merge 时自动执行：回归门禁复核 → 提交 → 审计 approved）
python -m agent.learning.rollout_controller --action evolution --approve <approval_record_id>

# 3. 驳回（必须给 reason，审计要求）
python -m agent.learning.rollout_controller --action evolution --reject <approval_record_id> --reason "暂缓，待评估集扩充"
```

行为说明：

- 未审批 → 零提交（候选仅入队）；
- 审批通过但回归门禁 FAIL/NO_SAMPLES（enforce 模式）→ 提交被拦截、审批记录归档、
  审计 decision=rejected，零提交；
- 审批通过且回归 PASS → 提交生效，审计 decision=approved（含 before/after 版本号）。

### 级别 3：rollout（小流量，KPI 无劣化自动回退）

目的：新版本按 `rollout_ratio` 比例命中；任一 KPI 连续 N 周恶化自动回退上一版本。

开启方式（示例：evolution）：

```bash
LEARNING_ROLLOUT_MASTER_ENABLED=true
LEARNING_ROLLOUT_EVOLUTION_MODE=rollout
LEARNING_ROLLOUT_EVOLUTION_ROLLOUT_RATIO=0.1      # 默认 0.1
LEARNING_ROLLOUT_EVOLUTION_KPI_ROLLBACK_WINDOW_WEEKS=2  # 默认 2
```

行为说明：

- 每次调度触发先做 KPI 观察期判据（任务2 周级 KPI，`get_weekly_kpis`）：
  任一 KPI 连续 2 个评估周期恶化 → 自动回退最近 approved 候选 + 告警 +
  审计 decision=rolled_back（含 `rollback_command`），本轮不再新提交；
- KPI 健康 → 按比例命中：未命中 → 预演零提交（审计 skipped_by_ratio）；
  命中 → 候选回归门禁预检（enforce）→ 真实提交 → 审计 approved；
- 回退后行为与旧版本一致（版本 + default_params + 内容快照比对）。

## 3. 一键回滚（任何放行后的提交）

```bash
# 从审计日志找到 candidate_id
python -m agent.learning.rollout_controller --action evolution --rollback --candidate <candidate_id>
```

- 回滚 = `rollback_version`（内容）+ `params_snapshot`（default_params）恢复；
- 审计追加 decision=rolled_back + `rollback_command`（可复现）；
- 回滚后建议人工复核技能库（`svc.get(<skill_id>)` 版本/参数/内容）。

---

## 4. 一键总关（紧急回退到零提交）

```bash
LEARNING_ROLLOUT_MASTER_ENABLED=false
```

- 下一次调度触发即全部强制 dry_run（无需重启）；
- 已提交内容不受影响（如需撤销请走第 3 节一键回滚）；
- 审批队列中未处理记录保持 pending_review（不自动提交、不自动丢弃）。

## 5. 审计与追溯

统一审计文件：`data/learning/rollout_audit.jsonl`（逐条 JSONL）。

| 字段 | 含义 |
| --- | --- |
| `action` | feedback / evolution / lifecycle |
| `mode` | observe / confirm / rollout |
| `candidate_id` | 候选 ID（回滚定位依据） |
| `parent_record_id` | 谱系 preview 记录 ID（observe） |
| `approval_record_id` | 审批记录 ID（confirm） |
| `decision` | preview / approved / rejected / rolled_back |
| `before_version` / `after_version` | 提交前后版本号 |
| `regression_result` | 任务1 回归门禁结果（PASS/FAIL/NO_SAMPLES/...） |
| `kpi_snapshot` | 判据命中时最新周 KPI 快照 |
| `rollback_command` | 可复现的回滚命令 |

追溯示例：

```bash
# 查某候选的全生命周期
python -c "import json; [print(json.dumps(r, ensure_ascii=False)) for r in map(json.loads, open('data/learning/rollout_audit.jsonl', encoding='utf-8')) if r.get('candidate_id')=='<candidate_id>']"
```

## 6. 注意事项 / 边界

1. **成本提示**：observe/confirm/rollout 的候选预检会调用任务1 回归门禁（真实评估），
   有 token/执行成本；`LEARNING_ROLLOUT_REGRESSION_GATE=warn_only` 可降为只读告警，
   `off` 可完全关闭（不推荐在 confirm/rollout 下使用）。
2. **批次粒度**：调度放行在批次级生效（一次调度 = 一批候选）；单候选的细粒度
   放行需通过审批记录的 payload 人工甄别。
3. **KPI 数据**：G5 第二层判据依赖任务2 周级 KPI（`get_weekly_kpis`）；数据不足时
   保守不触发回退。请确保 `learning.metrics` 数据源正常。
4. **多动作独立**：feedback / evolution / lifecycle 三动作模式互不影响，可分别
   处于不同级别；建议先小动作（lifecycle 状态迁移）验证流程，再升 feedback，
   最后 evolution。
