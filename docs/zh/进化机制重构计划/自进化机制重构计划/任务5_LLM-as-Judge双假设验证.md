## 1. 背景（为什么做）

TASK-08 报告 §3.3 给出 LLM-as-Judge 引入门槛："KPI#7 进化采纳率连续 4 周 <5% 且 KPI#1 token 复用率环比无提升"→ 先 dry-run 记录 2 周，KPI 改善才启用。

审计发现该逻辑存在**因果歧义（理论缺陷 T3）**：低采纳率有两种互斥归因——

- 假设 A：**评估不精细**——规则评估无法区分候选质量，好候选被误拒 → 需要更精细的 Judge；
- 假设 B：**候选质量差**——变异/生成环节产出本身就差，评估正确拒绝 → 需要改进候选生成，而非引入 Judge。

报告只设计了"dry-run 记录 2 周"，但没有设计**如何在 A/B 之间判别**。若真实原因是 B，引入 Judge 只会增加 token 成本且无收益。另外，预算护栏 `learning.budget.mode=warn_only`（不强制）时，任何 LLM 型评估角色一律不应引入（报告 §3.3 否决条件）。

本任务：① 把预算模式提升为 enforce（仅学习动作，灰度）；② 设计并实现**双假设判别实验**（同候选集双通道评估：规则评估 vs LLM-as-Judge，比较分歧率与采纳率差异）；③ 运行 2 周 dry-run 数据采集；④ 产出判别结论报告（启用/不启用 + 依据）。

## 2. 目标描述（做什么）

1. **预算 enforce 前置**：`learning.budget.mode` 灰度提升为 `enforce`（仅作用于学习动作，主链路不受影响；超限拒绝 + 告警），作为 Judge 通道存在的必要条件。
2. **Judge 通道实现（dry-run 语义）**：复用 `critic.py` RULE_BASED/LLM_DRIVEN 双模式惯例，新增 LLM_DRIVEN 评估通道；**只写 metrics/审计，不干预任何提交/采纳决策**。
3. **双假设判别实验设计**：同一候选集同时过"规则评估通道"与"Judge 通道"，记录指标：分歧率（两通道判定不一致的候选占比）、采纳率差异（若按 Judge 判定会采纳/拒绝多少）、KPI#1 变化；2 周采集。
4. **判别规则**（预设，写入任务文档）：若分歧率 < 阈值（默认 10%）→ 规则评估与 Judge 高度一致，低采纳率主要归因 B（候选质量）→ 不引入 Judge，转向改进候选生成；若分歧率 ≥ 阈值 且 按 Judge 判定的采纳率显著高于规则通道（默认 +10pp）→ 支持假设 A → 按报告 §3.3 流程评估启用。
5. **决策文档**：产出《LLM-as-Judge 双假设判别报告》（含数据、判别结论、成本核算、启用建议）。

## 3. 不变式约束（不易——禁止触碰）

- Judge 通道**零干预**：任何情况下不改变提交/采纳/回滚决策（dry-run 只记录）；审计可证。
- 预算 enforce 仅作用于学习动作，不得拦截主链路 LLM 调用（范围限定测试证明）。
- 禁止修改既有规则评估器（`ReflectionEngine` 6 维规则、`feedback.py`、`reviewer`）行为；Judge 为新增旁路通道。
- 成本受熔断保护：Judge 通道调用全部计入 `learning.budget`，超限熔断（不伪造指标、不部分执行）。
- 触发条件未满足前，Judge 通道不得转为"干预模式"（决策属于远期里程碑门）。

## 4. 执行步骤

### Step 1：预算 enforce 前置
- 阅读 `agent/learning_budget.py`（LearningBudget 熔断实现），确认 enforce 模式语义与告警通道。
- 灰度方案：`learning.budget.mode=enforce` 只对"学习动作"（进化评估/沉淀/反思类）生效；主链路排除清单明确（代码审计可证）。
- 测试：超限学习动作被拒 + 主链路 LLM 调用不受影响。

### Step 2：Judge 通道实现
- 新增 `agent/learning/judge_channel.py`：输入候选集（任务3 observe/confirm 产出的真实候选）→ 调用 LLM 判定（复用现有 LLM 客户端与脱敏管道）→ 输出与规则通道对齐的判定结构。
- 通道开关 `LEARNING_JUDGE_DRYRUN_ENABLED`（默认 true，只写不干预）；所有调用经 `learning_budget` 记账。

### Step 3：双通道评估与指标采集
- 对同一候选集并行跑规则通道与 Judge 通道；指标写任务2 监控扩展字段（`judge_disagreement_rate` / `judge_implied_adoption_rate`）与审计。
- 采集周期 2 周（或候选数 ≥ 阈值 N，取先到者），数据源需任务3 observe 态已积累真实候选。

### Step 4：判别报告
- 按预设判别规则计算结论；报告包含：样本量与分布、分歧率、两通道采纳率差异、token 成本核算（对照 §3.1 成本模型）、置信度说明（样本不足时的判定限制）。

### Step 5：测试与文档
- 新增单测：Judge 通道零干预（审计证明）、预算 enforce 拦截、分歧率计算、判别规则逻辑（构造 A/B 两类数据验证结论方向）。
- 产出《LLM-as-Judge 双假设判别报告》+ 变更说明。
