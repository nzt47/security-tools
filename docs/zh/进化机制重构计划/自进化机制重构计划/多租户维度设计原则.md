# 多租户维度设计原则（复查补充 · P2-7）

> 定位：为"自进化/学习机制"在**多租户演进下的隔离设计**提供原则与字段预留，防止未来 T8 多租户开放 API 落地时进化工件跨租户污染。
> 关联：`agent/multi_tenant.py`（用户→组织→工作空间三级体系 + RBAC）、`docs/zh/T8多租户开放API技术实施方案_草稿.md`、自进化机制重构计划（任务1~7）。
> 版本：2026-08-23 v1.0（复查补充；**仅原则与预留，不含实现**）

---

## 一、现状与风险

**现状（2026-08-23 审计）**：
- `agent/multi_tenant.py` 已实现三级租户（用户→组织→工作空间）、数据隔离（Memory/配置/日志）、RBAC、用量计费框架；`docs/zh/T8多租户开放API*` 系列文档表明多租户开放 API 正在推进。
- 自进化/学习机制的**全部资产当前为全局作用域**：评估集（`data/evals/`）、进化工件（Skill/工作流/经验）、反馈信号（`feedback.py`）、KPI 聚合（`learning_metrics.py`）、回放审计（`replay_audit.jsonl`）、元规则（`meta_policy/`）均无租户维度字段。

**风险（若不加设计直接演进）**：
1. **跨租户学习污染**：租户 A 的失败案例被提炼为 Skill 后服务租户 B（行为/业务语义错配）；
2. **反馈信号串扰**：KPI#5 反馈均分混合多租户口径，触发条件误判；
3. **进化参数互相踩踏**：元规则/进化权重全局共享，无法按租户灰度；
4. **隐私越界**：评估集/回放样本若含租户 A 的真实轨迹，脱敏边界失效。

## 二、设计原则（5 条，全部为"预留 + 声明"，不改变现有全局行为）

### 原则1：作用域字段预留（最小侵入）
- 所有学习/进化资产的数据结构**预留 `tenant_id` 字段**（默认 `None` = 全局/单租户，行为与现状逐字节等价）。
- 涉及位置（清单，供后续任务接线）：
  - 反馈记录：`feedback.py` 的反馈行；
  - 学习信号：`learning_metrics.py` 的 `record_interaction/record_feedback/record_task_result`（KPI 聚合键可扩展 `tenant` 维度）；
  - 进化工件：Skill/工作流/经验的元数据（`skills_mgmt/models.py` 可扩展字段）；
  - 评估样本：`data/evals/` 样本 `metadata`（可加 `tenant_source`，仅作来源标记，入库仍走脱敏）；
  - 回放审计：`replay_audit.jsonl` 条目；
  - 元规则：`meta_policy/` 版本条目（租户级策略预留）。
- **字段预留规则**：可空、默认 None、不影响既有 schema 校验与序列化（守"既有契约零破坏"）。

### 原则2：跨租户禁止（默认隔离）
- 学习信号的消费（Skill 沉淀、进化候选、反思经验注入）**默认不跨租户**：无 `tenant_id` 的信号视为全局（现状语义），有租户的信号只能在该租户作用域内被学习管线消费。
- 租户 A 的进化产物**不得**被路由/检索服务租户 B 的请求（除非显式声明为"全局/公共"资产，如通用工具类 Skill）。

### 原则3：KPI 分租户聚合（口径扩展）
- 触发条件与 KPI（任务2 监控）默认保持全局口径（现状）；**多租户启用后**增加 `tenant` 聚合维度，触发判定按"全局 或 指定租户"两种口径可切换。
- 阈值/窗口参数沿用同一套（不按租户放宽门槛，防"租户间竞争性放松"）。

### 原则4：进化护栏租户化（G1-G5 逐项检查）
- G2 价值观红线、G3 审计、G4 回滚：**租户无关，全局强制**（任何租户的进化产物都过同一红线与审计）。
- G1 元规则版本化：元规则可租户级覆盖（`meta_policy` 版本条目带租户字段），但**审批链不降级**（L1 人工批准仍适用于租户级变更）。
- G5 评估门禁：评估集基线**按租户分池**（租户 A 的技能用租户 A 的评估集版本）；全局评估集仅服务全局资产。

### 原则5：数据脱敏优先于租户隔离
- 租户隔离是**业务边界**，脱敏是**数据安全底线**：任何含真实交互轨迹的学习样本（无论租户）入库前必须走 `memory/black_box.py` 脱敏/加密管道（既有不变式，多租户不放松）。
- 回放素材（任务6）在多租户下同样遵守"明文不出隔离环境"。

## 三、与 T8 多租户开放 API 的衔接建议

1. **时序**：T8 开放 API 落地时，本原则的字段预留应同步落地（作为 T8 的一个前置/并行小项）；**自进化的租户隔离接线**则可在 T8 上线后再做（当前全局语义不破坏）。
2. **不阻塞现状**：本原则零代码改动、零行为变化，仅为后续任务提供决策依据与字段预留清单。
3. **风险登记**：若多租户先行而本预留未做，跨租户学习污染风险等级记为 **高**，需在 T8 需求评审中显式评估。
