> 阶段三 · 任务6 | 前置依赖：任务1（评估集与回放素材）| 下游：报告 F5/F6"沙箱回放 = 合成边缘案例"落地
> 变更日期：2026-08-22

## 1. 本变更解决什么问题

TASK-08 报告 §4.2 提出"沙箱回放 = 合成边缘案例"，但审计确认两个前提问题：

1. **沙箱为软隔离**：既有扩展/技能执行沙箱是"同进程执行、黑名单可绕过、资源限制
   不 enforcement"；回放的是**不可信**历史轨迹与候选产物（LLM 生成的变异参数、
   工具调用序列），软隔离下执行存在逃逸风险——dry-run 只保证"不提交工件"，
   不保证"执行安全"。
2. **无回放基础设施**：没有"轨迹记录 → 隔离回放 → 结果比对"的现成管道。

本变更新增 **评估回放隔离层 + 回放管道**（`agent/learning/replay.py`），使
"沙箱回放"具备真实安全边界，并默认关闭（`EVAL_REPLAY_ENABLED=false`）。

## 3. 设计决策（Step 2 方案选型）

按【简易】最小充分选型，隔离边界分层：

1. **进程级隔离（主后端 `process`）**：不可信代码在**全新解释器进程**执行，与父进程
   零共享内存/写路径。
   - `runner=spawn`（默认）：`multiprocessing` spawn 上下文（与仓库既有
     `agent/system_tools.run_sandbox` 同模式，生产首选）。
   - `runner=subprocess`（受限环境备选）：文件交换的独立 python 进程（stdin/out
     零管道依赖），适配无命名管道/匿名管道的受限运行环境（如本 CI 沙箱实测
     `multiprocessing.Queue` 建管道被 OS 拒绝，文件交换路径可正常工作）。
   - **fail-closed**：`spawn` 不可用（Queue 创建失败）→ `ReplayIsolationError` 显式
     失败，绝不静默降级为同进程执行；改用 `subprocess` 需显式配置
     `EVAL_REPLAY_RUNNER=subprocess`（仍是进程级隔离，非同进程降级）。
2. **受限执行环境（worker 内）**：
   - 受限 builtins：无 `open/eval/exec/compile/type/getattr/globals/...`；
   - 受限 import：白名单 stdlib 子集放行（json/re/math/...）；危险模块
     （os/socket/subprocess/ctypes/shutil/pathlib/requests/urllib/http/...）
     返回**惰性代理**，任何属性访问/调用即判 `escape`；`sys` 仅暴露
     stdin/stdout/stderr（其余属性访问判逃逸）；
   - 静态逃逸预扫描（spawn 前拦截）：危险 import/属性/dunder 遍历/反射调用。
3. **网络禁断**：worker 环境变量**白名单**（PATH/PYTHONUTF8/SYSTEMROOT/TEMP/...），
   显式剔除一切 `API_KEY/TOKEN/SECRET/PASSWORD/PROXY` 变量（正则双保险）；
   无网络模块可导入 → 无外联路径。
4. **只读数据面**：回放素材（`data/evals`）只读——样本以**脱敏后内存数据**经
   params.json 注入 worker，worker 无文件访问能力（无 `open`），素材目录从不写入；
   验证方式：素材目录 hash 回放前后不变（测试断言）。
5. **资源限制**：墙钟超时（默认 30s，超时 terminate→kill 强杀）、stdout/stderr
   有界捕获（超限判逃逸，防内存炸弹）、并发上限（默认 1 串行，防并发放大；
   不可信代码无法创建子进程 → fork 炸弹无路径）、POSIX 内存上限
   （setrlimit，Windows 仅记录）。
6. **容器化后端（可选 `docker`）**：`docker run --rm --read-only --network none
   --memory --cpus`，素材/输入只读挂载。默认不引入运行依赖；不可用（无 docker/
   镜像）→ 显式失败（fail-closed）。降级路径：移除配置回到 process 后端。

## 4. 回放管道（Step 3）

```
输入：ReplayJob（样本集 + 候选产物 + 预算）
  │  样本走 black_box 脱敏管道（agent.security_utils.DataSanitizer，明文不出隔离环境）
  ▼
静态逃逸预扫描 → 命中 = escape（不 spawn）
  ▼
隔离执行（process 后端：全新解释器进程；docker 后端：只读容器）
  ▼
ReplayResult：success / failed / timeout / escape + 结果快照 + resource_usage
  ▼
ReplayReport（比对结论 + 审计字段）
  ▼
审计 JSONL：data/learning/replay_audit.jsonl
  replay_id / samples / candidate_id / verdict / duration / resource_usage /
  evidence(截断) / rollback_command
```

- **复用任务1 通道**：`run_replay_regression()` 复用 `SamplesetRegistry`
  （manifest 版本登记）与 `EvalSamplePool`（样本加载）**只读**解析样本集 →
  脱敏 → 隔离回放 → 输出 success_rate 与判定明细；不写基线、不修改
  manifest/样本文件。
- **候选产物来源**：`candidate_from_code()`（原始代码/工具调用序列）与
  `candidate_from_skill()`（技能 `scripts/main.py`，只读）。
- **脚本协议与 SkillExecutor 一致**：stdin=参数 JSON，stdout 最后一行为结果 JSON
  （隔离层在 SkillExecutor **外部**新增边界，未修改其接口与算法）。

## 5. 配置（Step 6；优先级：环境变量 > config.yaml > 硬编码）

见 `config.yaml` → `learning.replay` 全量注释。核心开关：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `EVAL_REPLAY_ENABLED` | `false` | 总开关（安全底线，默认关闭） |
| `EVAL_REPLAY_BACKEND` | `process` | process / docker |
| `EVAL_REPLAY_RUNNER` | `spawn` | spawn / subprocess（受限环境备选） |
| `EVAL_REPLAY_TIMEOUT_S` | `30` | 单样本墙钟超时（超时强杀） |
| `EVAL_REPLAY_MAX_OUTPUT_BYTES` | `1048576` | stdout 捕获上限 |
| `EVAL_REPLAY_MAX_STDERR_BYTES` | `262144` | stderr 捕获上限 |
| `EVAL_REPLAY_MAX_CONCURRENT` | `1` | 并发上限（防并发放大） |
| `EVAL_REPLAY_MAX_SAMPLES` | `200` | 单 job 样本数上限 |
| `EVAL_REPLAY_WORK_DIR` | 系统临时/`yunshu_replay` | scratch 根（零共享写路径） |
| `EVAL_REPLAY_MATERIAL_DIR` | `data/evals` | 回放素材只读目录 |
| `EVAL_REPLAY_AUDIT_FILE` | `data/learning/replay_audit.jsonl` | 审计 JSONL |
| `EVAL_REPLAY_DOCKER_IMAGE` | `python:3.12-slim` | docker 后端镜像 |
| `EVAL_REPLAY_MAX_RSS_MB` | `0` | POSIX 内存上限 |

## 8. 已知边界与后续

- Windows 无 `resource.setrlimit` → 进程后端内存上限仅记录不强制；强内存隔离
  建议使用 docker 后端（`--memory`）。
- 静态预扫描为保守黑名单（与 run_sandbox 同风格），可能误伤含
  `eval(`/`open(` 文本的合法候选——回放场景下按"逃逸"保守处理并给出证据。
- 容器化后端未在本仓库 CI 实测（默认不引入运行依赖）；命令构造有单测覆盖，
  实际启用需镜像 `python:3.12-slim` 可用（降级路径见 §3-6）。
