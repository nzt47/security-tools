## 一、为什么需要这份路线图

复查确认：重构计划 7 个任务已全部结案，但 **9 个学习/进化开关全部处于关闭或 dry-run 态**（安全底线使然）。结果是：

- KPI#7 进化采纳率永远 `insufficient_data`（无真实候选）；
- L2 自进化闭环从未真实运行（evolver/feedback/lifecycle 均为 dry-run 预演）；
- 报告 §5.2 的远期触发条件因无数据而无法判真。

开关保持关闭是**正确**的默认（守【不易】）；但没有"按什么数据条件、什么顺序、如何回滚"的启用路线，系统将停留在"代码就绪但能力休眠"。本路线图给出**三波启用**：先积累度量数据 → 再开观察闭环 → 最后受控放行。任何一波的开关启用都必须满足前置数据条件，且每个开关都有回滚预案。

## 四、启用纪律（所有开关通用）

1. **一次只开一个开关**：验证通过后再开下一个；禁止并行启用多个波次开关（隔离回滚面）。
2. **先 dry-run/observe 再 confirm/rollout**：任何写操作类开关必须先观察 2 周。
3. **回滚优先于修复**：启用后任一监控指标异常 → 立即回退该开关（配置一键回退），再排查根因。
4. **审计不缺席**：每次开关变更写审计（变更人/时间/理由/回滚命令）；放行动作走谱系。
5. **配置即记录**：所有开关状态以 `config.yaml`/`.env` 为准，禁止运行时直接改代码常量。
6. **无真实候选不统计**：KPI#7 等指标在候选基数不足时保持 `insufficient_data`，绝不编造（"绝不伪造指标"不变式）。
