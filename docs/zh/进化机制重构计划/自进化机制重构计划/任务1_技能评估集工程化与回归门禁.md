## 1. 背景（为什么做）

TASK-08 报告护栏 G5 要求"进化产物先过离线评估集回归（标准集不退化）→ 再进入在线保守观察期"。但审计发现：

1. **评估集概念错位**：报告称"1.2 万+ 回归测试 = 评估集"，实际那 1.2 万+ 是**代码库单元/集成测试**（`tests/`，约 14987 个测试函数），不是技能/策略工件的行为评估样本——无法直接用于判定"Skill 参数变异后行为是否退化"。
2. **真实技能评估集过小**：`data/evals/` 仅 15 条样本（search/code/chat 各 5）。EVO-T2 的 `StagedEvaluator` 遇到无样本类别返回 `no_samples → score=0.0`（"绝不伪造指标"语义正确），但意味着多数 Skill 的进化产物**无法获得有效评估**，G5 门禁在样本不足时形同虚设。
3. **无扩充管道**：反思产物（TASK-02）、失败案例（feedback quality_cases、TASK-06 NoveltyEvent）本可回流为评估样本，但无任何管道。

本任务把"技能评估集"建设为**一等资产**：定义 schema 与目录规范、建立扩充管道、提供可执行回归门禁 CLI，并把门禁接入 `offline_evolver` 提交判定与 TASK-04 发布审核链。

## 2. 目标描述（做什么）

1. 建立**技能评估集 v1**：样本 ≥50 条、类别覆盖 ≥3 类（search/code/chat，扩展可含 tool/planning），全部通过 schema 校验与人工审核。
2. 实现**评估集回归门禁**：CLI/接口输入（评估集版本、被评估工件、预算）→ 输出 PASS/FAIL/NO_SAMPLES，复用 `StagedEvaluator` 分阶段评估与 TokenBudget 熔断，守"绝不伪造指标"。
3. 建立**扩充管道**：从反思产物、feedback 失败案例、TASK-06 新颖事件、人工标注回流生成新样本（全部走 DRAFT → 审核 → 入评估集，人工把关）。
4. **接线**：`offline_evolver` 提交判定增加"回归不退化"门槛（improvement≥0.05 且评估集回归 PASS）；TASK-04 发布审核链前置门禁。

## 3. 不变式约束（不易——禁止触碰）

- 禁止修改 `evaluator.py` 的评估算法与 `EvalSample`/`EvaluationResult` 数据结构（EVO-T2 契约）；门禁在其**之上**新增编排层。
- 禁止修改 `offline_evolver.py` 的进化算法与 `BatchEvolutionReport` 结构；只在提交判定处**新增**门禁调用（可开关）。
- 评估集样本入库存放走 `data/evals/` 既有目录规范；涉及真实交互轨迹的样本入库前必须走脱敏/加密管道（复用 `memory/black_box.py` AES-256-GCM 与脱敏管道）。
- "绝不伪造指标"不变式：样本不足/预算熔断时显式返回 `no_samples`/`budget_exceeded`，不编造分数。
- 门禁默认**只读告警**（不拦截提交），正式拦截需显式配置开启（守"上线即改行为"风险）。

## 4. 执行步骤

### Step 1：现状盘点与契约确认
- 阅读 `agent/skills_mgmt/evaluator.py`（SkillExecutorEvaluator / StagedEvaluator / TokenBudget）与 `data/evals/README.md`，确认 `EvalSample` 字段契约（`id/task/category/expected_output/metadata`）。
- 盘点可回流素材：`agent/cognitive/reflection.py` 反思产物、`agent/feedback.py` quality_cases、`agent/learning/novelty_hooks.py` 新颖事件、`data/evals/` 现有 15 条样本格式。

### Step 2：评估集 schema 与目录规范 v1
- 在 `data/evals/README.md` 基础上补充：类别（search/code/chat/tool/planning）、难度字段（复用 `enhanced_planner` 复杂度语义 TRIVIAL/SIMPLE/NORMAL/COMPLEX，为任务7 提供元数据）、来源字段（reflection/feedback/novelty/manual）、版本与变更记录。
- 新增样本校验脚本（`scripts/eval_samples_validate.py`）：逐条校验字段合法性与去重（input_hash）。

### Step 3：扩充管道
- 新增 `agent/skills_mgmt/eval_sample_ingest.py`：从反思/feedback/novelty 素材中按规则提取候选样本 → 写入 `data/evals/_pending/`（DRAFT）→ 人工/半自动审核（复用 `reviewer` 安全扫描）→ 批准后入对应类别 JSON。
- 管道默认关闭（`EVAL_SAMPLE_INGEST_ENABLED=false`），显式开启后也只产生 DRAFT。

### Step 4：回归门禁
- 新增 `agent/skills_mgmt/eval_regression.py`：`evaluate_regression(skill, sampleset_version, budget) -> RegressionResult(PASS/FAIL/NO_SAMPLES, score, delta_vs_baseline, used_tokens)`。
- 基线语义：首次评估时记录该 Skill 在评估集上的 baseline 分数（谱系记录），后续进化产物必须"不退化"（退化阈值可配置，默认 delta ≥ -0.05 判 FAIL）。
- 提供 CLI：`python -m agent.skills_mgmt.eval_regression --skill <id> --set v1 --budget 500k`。

### Step 5：接线
- `offline_evolver` 提交判定处新增回归门禁钩子（配置 `EVOLUTION_REGRESSION_GATE`，默认 `warn_only`）：进化候选需通过门禁方可提交；FAIL/NO_SAMPLES 时记录谱系 decision 并跳过。
- TASK-04 发布审核链：`enforce_before_publish` 前置回归门禁查询（只读）。

### Step 6：测试与文档
- 新增单测：schema 校验、门禁 PASS/FAIL/NO_SAMPLES/预算熔断四分支、扩充管道 DRAFT 审核流、evolver 门禁接线（退化被拒）。
- 产出变更说明（参考 `docs/zh/` 既有风格）。

## 5. 预期成果（交付物）

1. `data/evals/` 评估集 v1：≥50 条有效样本、≥3 类覆盖、难度与来源元数据齐备、全部通过校验。
2. `scripts/eval_samples_validate.py` 校验脚本 + `agent/skills_mgmt/eval_regression.py` 门禁 + `agent/skills_mgmt/eval_sample_ingest.py` 扩充管道。
3. `offline_evolver` 回归门禁接线（默认 warn_only，可配置拦截）。
4. 变更说明文档 + 新增单测全部通过。

## 6. 评估标准（验收条件）

### 内容验收
- [ ] 评估集 v1 样本数 ≥50 且每类 ≥5；校验脚本 100% 通过（0 非法）。
- [ ] 回归门禁四分支（PASS/FAIL/NO_SAMPLES/budget_exceeded）均有测试证明，行为符合"绝不伪造指标"。
- [ ] 扩充管道在 DRAFT 态零副作用（不产生入评估集写操作），审核通过后才入库（测试证明）。
- [ ] evolver 提交在"回归退化"时被拒（单测证明：构造退化候选 → decision=rejected 且谱系有记录）。
- [ ] 涉及真实轨迹的样本均走脱敏/加密管道（代码审计可证）。

### 过程验收
- [ ] 未修改 `evaluator.py` 算法与数据结构、未修改 `offline_evolver.py` 进化算法与报告结构（git diff 审计）。
- [ ] 门禁与扩充管道默认关闭/只读告警，零行为变化（配置默认值审计）。
- [ ] 全量回归通过：`python -m pytest tests/unit -q` 全绿。
