# 任务 T3：系统管理页统一抽象

> 所属计划：[14_前端封装理想设计_审计与重构总览.md](14_前端封装理想设计_审计与重构总览.md)
> 任务 ID：EVO-FE-T3 | 依赖：T1 + T2 | 工作量：大

---

## 一、目标描述

以 T2 组件基座 + 新增 `useTablePage` hook 重构 5 个系统管理页（UserList / RoleList / AuditList / NotificationCenter / MenuList），消除 4 处重复分页搜索骨架、4 处表格壳、4 处分页 UI、3 处删除确认、3 处弹窗表单三元组；弹窗统一改走 ModalBase。重构后页面只保留"业务专属"代码（列定义、表单字段、接口调用），行数预计减半。

**【不易】边界**：页面对外行为不变（路由、菜单权限码、接口 URL/入参/返回结构、按钮文案、Toast 提示文案）；`frontend-rules.md` 的 401 规范不受影响；不改变既有测试覆盖的交互语义（UserList.test / RoleList.test / MenuList.test / AuditList.test / NotificationCenter.test / DataScopeDialog.test 若断言内部 DOM 结构需同步更新断言，但用户可见行为不变）。

## 二、前置依赖

- T1（storage/async 工具可用）；
- T2（Table / Pagination / ModalBase / PageContainer / Empty / Loading 就绪并经 `index.ts` 导出）。

## 三、执行步骤

1. **新增 `src/hooks/useTablePage.ts`**：统一"分页 + 搜索 + 列表 + loading"生命周期：
   - 入参：`fetcher(params: P) => Promise<{ list: T[]; total: number }>`、`defaultQuery`、`pageSizeOptions?`；
   - 返回：`{ query, setQuery, list, total, loading, page, pageSize, fetchList, handleSearch, handleReset }`；
   - 行为：`page`/`pageSize` 变化自动重拉（`useEffect` 防抖 300ms 搜索输入）、并发竞态防护（请求序号或 AbortController，过期响应丢弃，对齐 useLayoutStore 的流式竞态处理思路）、组件卸载取消在途请求；
   - hook 内调用 T1 的 debounce 与 abort 工具。
2. **重构 UserList.tsx（样板页，先行）**：
   - 替换骨架为 `useTablePage` + `PageContainer` + `Table` + `Pagination` + `ConfirmDialog`（删除确认）+ `ModalBase`（用户表单弹窗）；
   - 弹窗表单（UserFormDialog）内部外壳替换为 ModalBase，仅留字段与提交逻辑；
   - 验证页面行为与既有测试语义一致后，再推进其余页面。
3. **按样板依次重构** RoleList（含 3 弹窗：RoleFormDialog / DataScopeDialog / PermissionAssignDialog 全部改 ModalBase）、AuditList、NotificationCenter、MenuList（树形页：表壳用 Table 或单独保留树渲染，删除确认用 ConfirmDialog）。
4. **弹窗组件瘦身**：UserFormDialog / RoleFormDialog / MenuFormDialog / DataScopeDialog / PermissionAssignDialog 删除各自的 portal/Esc/遮罩样板代码，只保留业务内容 + 统一 `onSubmit/onCancel/loading` 契约（与 ModalBase footer 对齐）。
5. **清理死代码**：重构完成后 Grep 确认无页面残留旧的分页/表格/弹窗外壳片段；SystemLog.tsx（22 行占位页）如无实际需求保持占位，不纳入重构。
6. **测试更新与补充**：
   - 更新既有 5 个页面测试中的 DOM 结构断言（如 `td` 数量、按钮结构变化）；
   - 新增 `useTablePage.test.ts`（防抖、竞态丢弃、分页重置）；
   - 各页保留核心交互测试（搜索 → 列表刷新；删除确认 → 删除；分页切换）。
7. **回归验证**：`npm run check` / `npm run lint` / `npm test` / `npm run build:flask`，并手工过一遍 5 个页面的增删改查 + 空态 + loading 态（截图留档）。

## 四、预期成果（交付物）

- 新增 `src/hooks/useTablePage.ts` + `src/hooks/README.md`（hooks 索引，T6 并入总索引）；
- 5 个系统管理页重构完成（用户可见行为不变）；
- 5 个弹窗组件完成 ModalBase 迁移与瘦身；
- 更新/新增的 vitest 测试；
- 任务报告：重构前后行数与重复模式消除率统计。

## 五、评估标准（验收条件）

1. `useTablePage` 有单元测试（防抖、竞态丢弃、卸载取消、分页重置），覆盖率 ≥ 80%；
2. 5 个页面无重复的分页/表格/弹窗样板代码（Grep 页面文件确认）；
3. 用户可见行为回归通过：5 页增删改查 / 搜索 / 分页 / 空态 / loading 与重构前一致（对照测试用例 + 手工验证记录）；
4. 权限菜单（`system:user:view` 等）与路由跳转不受影响；
5. 既有页面测试全部通过（结构断言已同步更新），`npm run check` 无类型错误、`npm run lint` 无新增告警；
6. 页面行数较重构前至少下降 30%（以任务报告统计数据为准）；
7. 未修改后端接口契约与 `frontend-rules.md` 既有规范。
