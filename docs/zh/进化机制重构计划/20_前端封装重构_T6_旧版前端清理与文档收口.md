# 任务 T6：旧版前端清理与文档收口

## 一、目标描述

清理云枢旧版 Flask 前端的死文件与重复工具函数，补齐前端封装索引文档（组件 / hooks / 工具三层），更新 `frontend-rules.md` 补充封装边界规则，完成本轮前端封装重构的收口与全量回归。

**【不易】边界**：`/legacy` 与 `/` 等既有路由**默认保留运行**（下线属业务决策，不在本任务范围）；删除任何文件前必须 `git ls-files <path>` 核对是否 HEAD 已跟踪（历史教训：曾误删已跟踪文件）；`app_server.py` 的路由渲染逻辑除死文件引用外不修改；`static/css` 与 `static/js` 中**仍被引用的文件一律不动**。

## 二、前置依赖

- T2（组件体系就绪，确认 React 侧无对旧版资源的引用）；
- T3 / T4 / T5（页面重构完成，避免清理时误删新代码仍引用的模块）；
- 全部分支测试基线记录（作为清理前对照）。

## 三、执行步骤

1. **死文件清理（先核对后删除）**：
   - 逐文件 `git ls-files <path>` 核对跟踪状态 + Grep 全仓引用（`rg` 限定 `templates/`、`static/`、`app_server.py`、`yunshu-ui/`）；
   - 确认无引用的死文件：`templates/yunshu.html`、`templates/lingxi.html`、`templates/spa.html`、`static/js/health.js`、`static/js/mascot-test.js`；
   - 删除前先 `git mv` 到 `docs/archive/前端清理_20260821/`（或备份目录）留痕，确认无回归后再 `git rm`（两步式，防误删不可恢复）；
   - `app_server.py:5528` 的"spa.html 已删除"注释随文件删除一并清理。
2. **旧版重复工具函数合并（仅安全项）**：
   - `refreshAll` 在 `static/js/nav.js:53` 与 `static/js/sidebar/sidebar.js:6` 重复定义：保留一个实现，另一处改为引用（或按 `app.js` 全局对象收敛）；
   - `showToast` / `showConfirm` / `escapeHtml` 在 `app.js`（109-135 / 102-106）与 `sidebar.js`（11-23）重复：以 `app.js` 为准，`sidebar.js` 删除重复定义并确认调用点路径正确；
   - 上述改动后手工过 `/legacy` 页面导航与刷新行为（若旧版 UI 已不可达则记录现状，不做无谓改动）；
   - **不做**：不重构 memory.js/tools.js/skills.js 的硬编码 fetch（避免扩大范围，仅登记到任务报告）。
3. **索引文档收口**：
   - `src/components/README.md`（T2/T4 已建）：核对完整性，补充 T3 后页面使用的组合模式示例（useTablePage + Table + Pagination 标准页骨架）；
   - `src/hooks/README.md`（T3 已建）：补录 T5 的 cancelRequest/requestWithRetry 用法；
   - `src/lib/README.md`（T1 已建）：核对与 `src/utils/` 的分工说明（lib = 领域模型/跨层模块，utils = 通用工具，明确归属判定）。
4. **`frontend-rules.md` 补充封装边界规则**：
   - "重复 ≥ 2 次必抽象为组件/hook；Props > 6 拆分子组件；新增基础组件先评审再进 ui/"；
   - 反模式清单（万能组件 / props 爆炸 / 为复用而抽象 / 接口频繁变更）与"组件接口冻结后向后兼容"约定；
   - 工具函数归属规则（lib vs utils）。
5. **全量回归与报告**：
   - `npm run check` / `npm run lint` / `npm test` / `npm run build:flask`；后端侧跑既有 pytest 快速回归（`pytest -m "not slow"`，确认 app_server 模板改动无回归）；
   - 输出 `重构收口报告`：死文件清单与处置记录、重复函数合并 diff、三层索引核对结果、全量回归结果、遗留项（`/legacy` 下线决策、旧版 JS 硬编码 fetch 登记）。
