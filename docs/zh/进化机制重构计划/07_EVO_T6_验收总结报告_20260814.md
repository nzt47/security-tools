## 四、验证过程要点

1. **双保险防误生效**：未审批 is_effective=False → approve 后仍未生效 → **merge 才生效**（L1 applier 回调）；L2 approve 后禁止自动 merge（`test_l2_only_suggestion` 中 merge 抛 `ApprovalStateError`）——代码级 + 数据级双重证明。
2. **回滚窗口过滤**：`ROLLBACK_WINDOW_MIN` 只认窗口内 committed 基线；超窗跳过、窗口内无记录按无基线处理（不误触发）。
3. **异常率相对阈值**：`ROLLBACK_ERROR_RISE_PCT`（默认 50%）复用相对阈值模式，与 success/latency 三路劣化判定并行。
4. **HITL 风险分级**：low_risk 自动放行 / high/critical 需人工 / dangerous 阻断 / safe 放行。
5. **服务重启语义**：pending/approved 记录无 applier 时 merge 抛 `ApprovalStateError` → 由人工在 UI/CLI 侧执行（与 L2 人工执行语义一致）。
