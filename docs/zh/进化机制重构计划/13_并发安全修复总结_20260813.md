## 1. 背景与目标

云枢系统存在大量**模块级单例**被多路 HTTP 路由/后台线程并发调用的场景。CPython 下「`get` → `判断` → `赋值`」等读-改-写操作在字节码层面**非原子**，多线程并发会产生：

- **丢计数/丢更新**：`counter += 1`、`dict[k] = v` 并发交错，部分写入被覆盖
- **TOCTOU**（检查-写入竞态）：check-then-create 并发创建重复实例
- **RuntimeError**：遍历容器（list/dict）期间被其他线程并发增删
- **KeyError**：并发执行「if in → del」时第二个线程删除已不存在的键

审计结论（详见 `docs/observability/redis_failure_bucket_draft.md`）：系统已有进化原型，但存在 3 个致命缺口——评估失真（计数竞态）、无自动触发、人机边界不一致。

## 4. 关键变更点详解

### 4.1 锁选型：`threading.RLock` vs `threading.Lock`

- **RLock（可重入）**：存在嵌套调用场景时使用——`dialog_state.update` 锁内 logger 读字段、`network_config._load` 调 `_save`、`memory/router.to_dict` 调 `list_adapters`
- **Lock（不可重入）**：无嵌套场景——`assessor`、`optimized_metrics` fallback 单例

### 4.2 锁纪律（三义权衡）

| 原则 | 实践 |
|------|------|
| 锁内仅内存状态变更 | I/O、网络请求、`time.sleep`、logger 移出锁外 |
| 例外 | `network_config._save` 文件写入与缓存更新必须同锁（一致性不变式，配置写为低频本地 I/O 可接受） |
| 防死锁 | `BatchMetricsWriter.write` 原代码锁内调 `_flush()`（再次获取同一 Lock）→ **重入死锁**，改为锁内 append + 锁外触发 flush |

### 4.3 典型修复模式

```python
# ① 读-改-写原子化（丢计数）
with self._lock:
    self._check_count += 1          # monitoring/search
    self.turn_count += 1            # dialog_state
    self._stats['sampled_records'] += 1  # optimized_metrics

# ② TOCTOU check-then-create（重复实例）
with self._lock:
    if self._sensitive_filter is None:
        self._sensitive_filter = _get_sensitive_filter()   # memory/router
    if name not in self._histograms:
        self._histograms[name] = LockFreeHistogram()       # optimized_metrics

# ③ 遍历快照（并发写 RuntimeError）
with self._lock:
    adapters = list(self._adapters.items())                # memory/router
    return self._performance_history[-limit:]              # monitoring/search

# ④ 双重检查锁（network_config._load，I/O 出锁）
#   第一段锁读缓存 → miss 锁外读文件 → 第二段锁双检后写缓存

# ⑤ 锁内取 ID + 锁外 I/O + 锁内 append（monitoring/search._perform_check）
with self._lock:
    self._check_count += 1
    check_id = self._check_count
# ... 网络请求（最长可达 timeout 秒级，绝不持锁）...
with self._lock:
    self._performance_history.append(check_result)
```

### 4.4 高并发验证方法

- **Barrier 同步起跑**：`threading.Barrier(N)` 让 N 线程同时开始，放大竞争窗口
- **确定性断言**（GIL 下无锁场景未必复现竞态，加锁后由单元测试保证确定性正确）：
  - 计数精确：`turn_count == N`、`sampled_records == N`
  - 唯一性：`len({id(s)}) == 1`、`len(set(check_ids)) == N`
  - 无异常：并发读写混合不抛 RuntimeError / KeyError
- **测试自包含**：`tempfile.mkdtemp(prefix=...)` + teardown 清理，不污染仓库；mock 网络（`patch("requests.post/get")`）、mock 数据文件路径
