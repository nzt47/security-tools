## 一、目标描述

落地设计文档的**谱系追踪（Lineage Tracking）护栏**：为所有进化事件（提交/拒绝/跳过/审批/回滚）建立可追溯档案，支持审计与父代选择。核心为两个数据结构：

- **`EvolutionRecord`**：一条进化事件记录（对象类型/对象 ID/父记录 ID/新旧版本/策略/变更摘要/评估结果/决策/成本/时间戳等）；
- **`EvolutionArchive`**：JSONL 持久化档案库 + 分层保留策略（活跃 N 代完整保留，更早压缩为摘要归档）+ 并发安全 + 损坏容错。

**【不易】边界**：谱系记录失败绝不阻断版本升级（记录尽力而为）；不得删除或改变 `bump_version` 既有返回类型与行为。

## 三、执行步骤

1. 定义 `EvolutionRecord` 数据模型（object_type/object_id/parent_record_id/parent_version/new_version/strategy/change_summary/eval_result/decision/decision_reason/trigger/actor/cost/params/created_at/record_id/schema_version/archived）；record_id 格式 `evt-<timestamp>-<hash>`。
2. 实现 `EvolutionArchive.append(record) -> record_id`（原子写入：tempfile + os.replace，Windows 锁重试）。
3. 实现分层保留：每对象超过 `active_generations`（默认 10）的最老记录压缩为摘要移入归档文件。
4. 实现查询：`get` / `list_by_object`（活跃+归档按 created_at 升序）/ `get_lineage(object_id)`（沿 parent_record_id 回溯全链，容错断链）/ `query` / `count` / `import_records`（批量/去重/摘要恢复）。
5. 并发安全：`threading.RLock` 保护所有公开方法；并发 append 不丢记录。
6. 损坏容错：坏行跳过、整文件损坏备份为 `.corrupted` 后重建。
7. 在 `SkillEnhancer.bump_version` 增加可选谱系钩子：`set_lineage_hook()` + 内置自动记录（`EVOLUTION_ARCHIVE_AUTO_RECORD` 环境变量控制，默认开启，可配置关闭；失败仅告警不阻断）。
8. 单元测试（覆盖率 ≥ 80%）+ conftest 隔离 fixture（monkeypatch env 路径 + 复位单例）。
