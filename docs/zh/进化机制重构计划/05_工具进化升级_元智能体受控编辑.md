## 一、目标描述

落地设计文档的**工具进化（Tool Evolution）维度**：让元智能体（meta-agent）能**受控地修改工具代码/文档**以提升工具质量，全程经审核、评估、审批、合并回滚多重护栏——**绝不自动合并**（守不易：工具代码是系统能力边界，任何修改必须人工放行）。

**要解决的缺陷（来自审计）**：
1. 工具/技能代码只进不退，无自动改进回路；
2. 无受控编辑边界（哪些文件可改、哪些禁改、内容黑名单缺失）；
3. 修改无评估验证（不知道改完是变好还是变坏）。

**【不易】边界**：
- **绝不自动合并**：所有编辑产物必经 Reviewer 三重审核 + 人工审批，评估达标才合并；
- **编辑白名单**：`edit_policy.py` 定义可编辑目录/禁改路径（lineage.py/evaluator.py 等核心契约文件在禁改清单）、扩展名黑名单（可执行/脚本）、内容黑名单正则；
- 谱系 decision 必须与 `lineage.DECISIONS` 对齐（pending_review / rejected / committed）。

## 二、执行管线（与任务 6 approval.py 状态机对齐）

```
元智能体生成 diff/patch 提案（EditProposal）
    → Reviewer 三重审核（critical 缺陷直接拒绝，不进入评估）
    → 进程级沙盒真实评估（复用 EVO-T2 评估器）
    → 谱系写入 pending_review（含真实评估快照，parent=上一有效代）
    → 人工审批（approval.py 状态机 draft → submitted → approved/rejected）
    → 通过后 git 合并 + 可回滚
任一环节拒绝：状态机 → rejected，写谱系 decision="rejected"
```

## 三、核心组件

1. **`agent/skills_mgmt/edit_policy.py`**：
   - `EditType`（文件类型）/ `EditStatus`（draft/submitted/approved/rejected 等状态机）；
   - 路径白名单（`META_EDIT_WHITELIST_DIRS`，默认仅白名单目录可写）+ 禁改路径（lineage.py/evaluator.py 等在 `_BLOCKED_PATTERNS`）；
   - 扩展名黑名单（与 `file_tools.BLOCKED_WRITE_EXTENSIONS` 对齐）；
   - 内容黑名单正则（`META_EDIT_BLOCKED_PATTERNS` 环境变量追加到内置默认）；
   - `EditProposal`：diff 生成、submit/approve 状态迁移（`_transition` 校验合法迁移）。
2. **`agent/skills_mgmt/meta_editor.py`**：
   - 元智能体编辑器提示词（`_META_EDIT_PROMPT`，参考进化谱系评分与评估样本生成 diff）；
   - Reviewer 三重审核（critical 直接拒绝）；
   - 进程级沙盒真实评估 → 谱系 pending_review（**绝不自动合并**）；
   - 配置：`META_EDIT_MAX_SKILLS_PER_ROUND`（默认 1）/ `META_EDIT_MAX_TOKENS_PER_ROUND`（默认 50000，0=熔断）/ `META_EDIT_STALL_ROUNDS`（默认 3，连续无提升暂停）/ `META_EDIT_EVAL_MIN_SCORE`（默认 0.3）。

## 五、评估标准（验收条件）

1. 编辑提案状态机完整：draft → submitted → approved/rejected，非法迁移被拒绝（测试证明）；
2. 白名单/黑名单生效：禁改路径、禁写扩展名、内容黑名单均被拒绝并抛 `EditPolicyError`；
3. Reviewer 三重审核：critical 缺陷直接拒绝，不进入评估；
4. （重建补充）评估不达标不合并：真实评估 score < `META_EDIT_EVAL_MIN_SCORE` 时提案拒绝；
5. （重建补充）谱系记录对齐：pending_review/rejected/committed 与 `lineage.DECISIONS` 一致，含评估快照；
6. （重建补充）既有测试全部通过，新增测试覆盖率 ≥ 80%；
7. （重建补充）**绝不自动合并**：无自动 apply/merge 路径（测试证明）。
