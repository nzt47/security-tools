# 任务 T1：基础工具与存储封装

> 所属计划：[14_前端封装理想设计_审计与重构总览.md](14_前端封装理想设计_审计与重构总览.md)
> 任务 ID：EVO-FE-T1 | 依赖：无 | 工作量：小

---

## 一、目标描述

补齐云枢前端工具函数与浏览器存储的统一封装，消除散落的裸 `localStorage` 调用与高频工具缺位，为后续 T2~T5 提供稳定基座。

**【不易】边界**：不修改既有导出签名（`src/lib/cn.ts` 的 `cn()`、`src/utils/logger.ts` 的 `logger`、`src/utils/system.ts` 的 `downloadFile`）；不改变现有持久化键值与行为（`yunshu-user-store` / `yunshu:prompt-lab:v1` / `yunshu:mosaic:layout:v1` / `yunshu-theme`）；存储封装为**新增能力 + 渐进替换**，既有调用点仅在新代码中采用，禁止一次性大面积改写（改多少验多少）。

## 二、前置依赖

无（首任务，可与 T2 并行）。

## 三、执行步骤

1. **新增 `src/utils/storage.ts`（浏览器存储增强封装）**：
   - 统一前缀：写读删均自动加 `yunshu:` 前缀，键名收敛到注册表常量（`STORAGE_KEYS = { THEME: 'yunshu-theme', TOKEN: 'token', ... }`），新键先注册再用；
   - API：`storage.get<T>(key, fallback)` / `storage.set(key, value)` / `storage.remove(key)` / `storage.has(key)`；自动 `JSON.stringify/parse`，解析失败返回 fallback 且 `logger.warn`（对齐 usePromptLabStore 的 sanitize 防御思路）；
   - 兼容：对既有裸键（如 `token`、`yunshu-theme`）提供无前缀直读路径说明，避免迁移期双写冲突。
2. **新增 `src/utils/async.ts`**：
   - `debounce(fn, delay)` / `throttle(fn, interval)`：类型保留（泛型），返回带 `cancel()` 的包装函数；用于搜索框防抖与高频事件节流；
   - `createAbortController()` + `abortable(fn, signal)`：统一 AbortController 生命周期管理（对齐 sse.ts / useLayoutStore 中止语义），导出 `isAbortError(err)` 判定工具。
3. **新增 `src/utils/format.ts`**：`formatDate(ts, pattern)`（Y/M/D h:m:s）、`formatBytes(n)`（导出页用）、`formatNumber(n)`（千分位）；实现必须零依赖、纯函数。
4. **新增 `src/utils/clipboard.ts`**：`copyText(text): Promise<boolean>`（navigator.clipboard 优先，降级 textarea + execCommand，失败返回 false 由调用方提示）。
5. **存量调用点渐进替换（仅限安全项）**：
   - `src/utils/request.ts` 的 `getToken/setToken/clearToken` 内部改走 storage 封装（保持对外签名不变）；
   - `src/main.tsx` 主题读取保留裸读（关键路径，改动最小化），不强制替换；
   - 其余裸 `localStorage` 调用点登记到任务报告，不强行改写。
6. **单元测试**（vitest + jsdom）：
   - storage：set/get/remove 前缀正确、JSON 容错回退、键注册表校验；
   - debounce/throttle：时间推进验证触发次数与 cancel；
   - format/clipboard：纯函数断言 + 降级分支 mock。
7. **新增 `src/lib/README.md` 工具索引**（T6 将并入总索引）：每工具一行签名 + 用途 + 示例。

## 四、预期成果（交付物）

- `src/utils/storage.ts`、`src/utils/async.ts`、`src/utils/format.ts`、`src/utils/clipboard.ts`（新增）。
- `src/lib/README.md`（工具索引）。
- 单元测试 `src/utils/*.test.ts`（或 tests 目录对应文件）。
- 测试：`npm run check` / `npm run lint` / `npm test` 全绿。

## 五、评估标准（验收条件）

1. 四个工具模块均有单元测试，关键路径覆盖率 ≥ 80%；
2. storage 封装：解析损坏 JSON 返回 fallback 且不抛异常；键自动带 `yunshu:` 前缀；
3. debounce/throttle 泛型类型正确（tsc 严格模式通过），cancel 生效；
4. `request.ts` 的 token 读写迁移后行为不变（401 登出 / 拦截器注入回归用例通过）；
5. 既有测试全部通过（`npm test`），`npm run check` 无类型错误，`npm run lint` 无新增告警；
6. 未修改 `cn.ts` / `logger.ts` / `system.ts` 的导出签名；
7. 存量裸 localStorage 调用点已在任务报告中登记清单与替换决策。
