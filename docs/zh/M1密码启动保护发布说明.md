## 1. 概述

M1 为 Gitleaks 治理的首个里程碑，核心目标：**消除管理后台硬编码默认密码 `admin123`**，通过环境变量注入 + 生产环境强制校验，杜绝生产部署静默使用弱口令的安全风险。

涉及代码：`agent/server_auth.py`（新增 `load_admin_credentials`）、`app_server.py`（接入 + 启动日志）、`tests/unit/test_admin_password_guard.py`（验收测试）。

## 2. 密码启动保护机制（重点）

### 2.1 加载优先级

```
1. 环境变量注入（YUNSHU_ADMIN_PASSWORD）          → 任何环境均生效
2. 生产环境强制（YUNSHU_ENV=production + 无密码） → 拒绝启动（RuntimeError）
3. 本地联调兜底（无 YUNSHU_ENV）                  → 默认 admin / admin123
```

实现位于 `agent/server_auth.py` 的 `load_admin_credentials()`，app_server 启动时模块级调用。

### 2.2 生产环境拒绝启动（行为变化 ⚠️）

- **旧行为**：生产缺密码时静默使用默认密码 `admin123`，仅打 warning
- **新行为**：`YUNSHU_ENV=production` 且未设置 `YUNSHU_ADMIN_PASSWORD` → **启动即抛错退出**，禁止带默认弱口令运行
- **运维影响**：生产部署必须显式设置 `YUNSHU_ENV=production` 与 `YUNSHU_ADMIN_PASSWORD`，否则无法启动（这是**有意为之**的安全门禁）

### 2.3 本地联调行为不变

未设置 `YUNSHU_ENV`（或 development）时，缺密码仍使用 `admin/admin123` 兜底——本地开发无需额外配置，行为与历史完全一致。

### 2.4 启动日志

启动时记录运行环境与凭证来源，便于排查：

```
[WARNING] 管理后台使用默认密码（admin123），仅限本地联调；生产请设置 YUNSHU_ADMIN_PASSWORD
[INFO]    管理后台凭证加载成功：env=production，username=admin，密码来自环境变量（非默认值）
```

## 3. 部署要求（运维必读）

| 环境 | 必设环境变量 | 缺失后果 |
|---|---|---|
| 生产 | `YUNSHU_ENV=production` + `YUNSHU_ADMIN_PASSWORD=<强密码>` | 拒绝启动（安全门禁） |
| 测试/预发 | 建议同上（按环境规范） | 若未设 `YUNSHU_ENV` 则走本地兜底，不阻断 |
| 本地开发 | 无需设置 | 默认 admin/admin123 |

密码强度建议：≥12 位，含大小写字母、数字与符号（示例 `Str0ng-P@ss-2026`）。

## 5. 风险与回滚

- **回滚**：还原 `app_server.py` 凭证加载块与 `server_auth.py` 即可回退到旧逻辑（env 优先 + 默认值 + warning）
- **注意**：如生产环境因缺密码启动失败，属**预期安全拦截**，补充环境变量即可，无需回滚
