# 云枢运营观察清单（真实使用期 · 可执行版）

> 目的：让云枢在**真实工作**中积累数据，用数据回答三个问题——**它有没有变懂你？值不值这个成本？该不该继续投？**
> 适用前提：S0–S7 全部结案（v7.2 计划 18 任务 + S7 补完 6 任务），设施齐备，**只缺真实使用量**。
> 生成：2026-09-12｜配套：[`PARALLEL_S8批次总表.md`](PARALLEL_S8批次总表.md)（生产化加固，可并行）

---

## 一、为什么必须"真用"（而不是继续加功能）

收官审计与 S7 的结论高度一致：**剩余所有未完成项的根因都是"真实使用量不足"**——

| 挂着的事项 | 真正缺的东西 |
|---|---|
| 真实能力内化、消化吞吐、ACR/UTC 曲线 | **真实轨迹** |
| 成本系数校准（S7-03 已建实测能力） | **真实跨模型成本数据** |
| 灰度真实接管 | 容器隔离（S8-03） |
| LLM-judge 真实评分 | 凭证配置（S8-04） |

> **纪律**：**不要用脚本造任务来刷指标**。合成流量会让所有曲线失真，等于把仪表盘变成装饰。S7-05 已经证明"真实轨迹"与"合成轨迹"在数据形状上可区分（真实失败就是真失败）。

---

## 二、怎么"真用"（开始动作）

1. **用云枢做你本来就要做的活**：读代码、定位 bug、改文件、写/跑测试、提交前检查、写文档。
2. **关键：让它真实执行工具**（`read_file` / `shell_execute` / `write_file` 等），而不是只在对话框里聊天——**只有工具调用才会落账成 Trace**。
3. **确认轨迹在落**：`agent/data/tool_trace.db`（工具级）与统一台账 `unified_traces`（任务级）应随使用增长。
4. **别做的事**：
   - 用脚本批量造任务刷数据（污染指标）；
   - 为了让某个数字好看而手工补轨迹；
   - 把演示门槛（≥5 条）当正式门槛（≥20 条）。

## 四、看哪些指标（含义 / 健康线 / 警戒线）

> 口径纪律（全程遵守）：**样本 <20 只披露不考核**；数据源缺位记 `None`（**不以 0 冒充**）；每个数字须能溯源。

| 指标 | 含义 | 健康线（目标） | 警戒线 |
|---|---|---|---|
| **ACR**（北极星） | 介入次数 / 任务，越低越"懂你" | 自主率 ≥55%（W10–W14 档）→ 长期 ≥80% | 连续 2 周无改善 |
| **UTC** | 单位任务成本 / 基线 | ≤1.0× | >1.3× → 触发**断食**；日超预算 → **熔断** |
| **消化吞吐** | 日增 `mirrored` 能力 | ≥2/周（W10 起） | 连续 3 周为 0（说明没在学） |
| **内化转化率** | (internalized+native)/总能力 | ≥10% | 长期 0 且无手动 promote |
| **技能成功率** | 灰度期通过率 | ≥上游×0.98 | 出现连续负例（学错能力） |
| **委派回收率** | 三件套齐全占比 | 100% | <100% 即有"白花的钱" |
| **审批衰减率** | 策略自动消化占比 | ≥70% | 长期停滞 → 审批在膨胀 |
| **MTTD / MTTR** | 发现 / 恢复时间 | <3s / <30s | MTTR 上升说明自愈在退化 |
| **路由准确率** | Router 选择 vs 事后最优 | >85%（W10 起） | 若仍 `framework_only` → 数据不足，如实标注 |
| **弃单率 / 逃逸率** | 放弃的任务 / 用户自己动手 | **披露不考核** | 逃逸率上升是体验警报 |

## 五、四档判据（一眼判断当前状态）

| 档位 | 判据 | 该做什么 |
|---|---|---|
| **成功** | L0 锚全过 + ACR 下降趋势 + UTC ≤1.0× + 消化吞吐 ≥2/周 | 维持；考虑进入下一阶段评估 |
| **健康** | L0 锚全过 + 指标持平或有改善 | 继续观察，不必动作 |
| **警告** | 任一：UTC >1.3× / 消化吞吐连续 3 周 0 / MTTD 或 MTTR 超标 / 审批积压增长 | 查告警与自愈事故卡；必要时手动介入 |
| **失败** | L0 锚通过率下降 / 自查出回归 / 成本失控 / 连续负例 | **立即停新内化与灰度**，先恢复既有能力（回退 + 事故卡） |

## 六、止损线（v7.2 §1.4 战略撤退点，触发即评估退出）

| 触发条件 | 检查点 | 撤退动作 |
|---|---|---|
| **委派成功率 <60% 持续 2 周** | 委派回收率/成功率指标 | 放弃通用委派，只保留 MCP 工具 + 单一上游 |
| **Skill 候选人工否决率 >70%** | 手动 promote / 抽检否决比例 | 消化降级为"提示词模板沉淀"，停自动产 Skill |
| **维护成本超承受** | 你每周维护耗时 | 冻结消化与进化模块，只保留透明化助手 |
| **日成本超预算 / 周 UTC 持续 >1.3×** | 熔断与断食记录 | 收紧预算；关掉影子与重探 |
| **L0 锚通过率下降** | 周度 `run_eval.py --layer L0` | 立即停用近期内化产物，回退到上一 active |

> 止损不是失败，是**方案自带的设计**——v7.2 一开始就写了这些触发条件。

## 七、观察期节奏与出口

- **周期建议：4 周为一段**（与 v7.2 §6.3 的 W 档对齐）。
- **第 1 周**：只求"轨迹在涨、L0 锚全过"——不看 ACR（样本不足）。
- **第 2–4 周**：看趋势（ACR 是否下降、UTC 是否受控、消化是否 ≥2/周）。
- **出口条件（满足才谈下一步，例如 L2 自修复/自动化加码）**：
  1. L0 锚连续 4 周全过；
  2. ACR 有可解释的下降趋势（不是噪声）；
  3. UTC ≤1.0×；
  4. 消化吞吐 ≥2/周 或已明确"当前任务类型不值得内化"；
  5. 无"学错能力"负例累积；
  6. 自修复 L1 至少成功产出过 1 个被采纳的补丁 PR。

## 九、常见误判（别把噪声当信号）

1. **面板某列为 0**：八成是**对应开关默认关闭**（设计内的安全底线），不是坏了——先查开关中心。
2. **成本数字对不上**：未实测校准的模型走**价格锚定系数**（`calibrated=False`）；看 `calibration` 块确认口径版本。
3. **judge_kind = deterministic_local**：说明**没有 LLM-judge 凭证**，评分是本地确定性打分器（机制正常，配置缺失）。
4. **门槛混淆**：演示门槛 ≥5 ≠ 正式门槛 ≥20；报告与面板数据旁必须标明。
5. **小样本**：<20 条一律只披露不考核（S5-02 口径）——不要用它做决策。
6. **审计链报红**：若为既有单点 `seq=17 prev_hash_mismatch`（非本计划引入），如实记录即可；面板报红是**正向行为**。
7. **"它没在学"**：先确认是"没流量"还是"没开关"——消化/灰度/重探调度全部默认关闭。

## 十、周报已挂进云枢调度（2026-09-13 落地）

周报不再需要你手动跑：已挂进云枢自己的调度器，**每周一 09:00 自动生成并存档**。

| 项 | 说明 |
|---|---|
| 模块 | `agent/monitoring/slo_report_scheduler.py`（**默认关闭**，安全底线） |
| 注册点 | `app_server` 启动调度器时自动注册（失败不阻断主流程） |
| 存档 | `docs/zh/周报存档/slo_weekly_<YYYYMMDD>.md` / `.json` |
| 审计 | `data/slo_report_audit.jsonl`（每次运行追加：时间/状态/输出路径） |
| 已实测 | ✅ `slo_weekly_20260913.md` 已生成（首次手动验证） |

**怎么开**（二选一）：
```yaml
# config.yaml
slo_report:
  enabled: true
```
或环境变量：`CP_SLO_SCHEDULE_ENABLED=true`

**可调**：`day_of_week`（0=周一…6）/ `hour` / `minute` / `days`（env 前缀 `CP_SLO_SCHEDULE_`，如 `CP_SLO_SCHEDULE_HOUR=20`）

> ⚠️ 依赖 `app_server` 在运行（调度 daemon 随它启动）。服务没跑时可手动：
> `python scripts/report_slo_weekly.py`
