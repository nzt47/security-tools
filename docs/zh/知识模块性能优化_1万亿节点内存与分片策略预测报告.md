## 2. 1 万亿节点分片策略（理论推导）

### 2.1 片数权衡（理论区间）

| 片数 | 单片 refs 驻留 | 并行全扫（理想） | 节点规模（每机 32–128 片） |
|---|---|---|---|
| 131072（2^17） | ≈977 MB | ≈28.6 分钟 | 1024–4096 |
| 524288（2^19） | ≈244 MB | ≈7.2 分钟 | 4096–16384 |
| **1048576（2^20）** | **≈122 MB** | **≈3.6 分钟** | **8192–32768** |
| 2097152（2^21） | ≈61 MB | ≈1.8 分钟 | 16384–65536（元数据成本主导） |

**推荐 1048576 片（2^20）**：单片 122 MB 可整片常驻单机；片数达百万级，路由/元数据本身成为新问题（见 §2.2）。

### 2.2 百万片数的路由困境（理论问题）

| 问题 | 影响 |
|---|---|
| 路由元数据 | 百万片映射表 + 一致性哈希环上的节点管理，需分层路由服务（region → 集群 → shard） |
| 分片均衡 | 哈希分布 + 热点再平衡，运维复杂度指数上升 |
| 跨片对账 | 百万片两两对账不可行 → 树形/抽样对账 |
| 写放大 | 区域副本 + 重放队列，写入带宽成本主导 |

**结论**：1 万亿节点已超出**单片常驻 + 一致性哈希**模型的合理上限；理论形态应为**联邦式多租户架构**（每租户/域独立索引，域间对账），而非单一全局索引的无限分片。

## 6. 结论：容量模型的极限与启示

| 决策维度 | 1 万亿节点评估 |
|---|---|
| 内存（现状/流式） | 1.86 PB / 128 TB：远超现实机群 |
| 内存（分片 2^20） | ≈122 MB/片：单片仍可控，但百万片路由/对账成为新瓶颈 |
| 耗时（全扫） | 单机 7.1 年：单机串行模型彻底失效 |
| 存储 | 1.73 PB 正文：多区域对象存储，成本不可估量 |
| 架构判定 | **联邦式多租户架构（理论极限形态）** |

**启示**（对工程有实际价值的部分）：

1. **外推模型的终结**：线性外推在 1 万亿处失去工程意义——现实上限在 100 亿（区域级多集群）量级，1 万亿为上限锚点。
2. **分片数的收敛点**：2^20 片后「继续加片」的边际收益被路由/对账成本吞没——**分片不是万能解**，超大规模应走联邦/多租户切分。
3. **对当前工程的确认**：≤200 万卡流式执行线非常充裕，本系列外推结论不影响近期实施范围；容量监控阈值（refs > 512 MB ≈ 400 万卡）仍为当前唯一需要落地的护栏。
