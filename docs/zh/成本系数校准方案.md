## 一、要解决的问题（为什么价格锚定不够）

价格锚定的假设是"模型 A 单价是 B 的 3 倍 ⇒ 成本是 3 倍"。该假设**只对 token 单价成立**，
对**单位任务成本**不成立——真实成本还取决于：

| 失真来源 | 机制 | 对单位任务成本的方向 |
|---|---|---|
| 重试次数 | 高失败率模型反复重试，计费 token 成倍 | 抬高 |
| 失败率 | 失败调用不产出可用结果，但钱已经花了 | 抬高 |
| 输出冗长 | 同一任务输出 token 差异可达数倍 | 抬高（output 单价通常更高） |
| 缓存命中 | 命中不计 token（P7.1-18） | 压低 |
| 提示膨胀 | 工具/上下文注入使 in-token 与任务难度脱钩 | 不定 |

**结论**：`coefficient_table()` 决定 UTC 断食阈值（S5-03）、ROI 判断（`digestion.internalize.ROIReport`）
与审批衰减率的输入量。若系数按标价锚定而实际成本比偏离，则刹车会**在该刹时不刹、不该刹时刹**。

## 四、指标（Metrics）

每模型逐项采集（每个数字必须能溯源到事件流文件或导入 CSV 的行）：

| # | 指标 | 定义 | 来源 |
|---|---|---|---|
| M1 | `tokens_in` / `tokens_out` 总量 | 该模型全部调用的计费前 token 合计 | `cost` 事件 payload |
| M2 | **单位任务 token** | `(tokens_in + tokens_out) / 任务数`；任务口径 = 完成该批用例的 `task_id` 去重数 | 同上 |
| M3 | **重试次数** | `Σ retries`；`retries/调用数` 为每调用重试率 | 同上 |
| M4 | **成功率** | `无 error 的调用数 / 总调用数`（**调用级**，非用例级——成本只看调用的钱） | 同上（`error` 字段） |
| M5 | **正常化成本** | `Σ cost_normalized_cents`（统一到锚价口径，跨模型可比） | 同上 |
| M6 | **单位任务正常化成本** | `M5 / 任务数`（cents/任务） | 计算 |
| M7 | 缓存命中率 | `Σ cache_hit / 调用数`（命中不计 token） | 同上 |
| M8 | 用例通过率（S1/S2/S3 分列） | `passed / assessed` | `EvalReport`（**仅路径 A 可得**；`assessed=0` → `None`，不虚报 0%） |

**M5 的口径纪律**：`cost_normalized_cents` 是**归一化**口径（锚价 × 系数），
而校准要量的是**同尺度**的真实成本比，故：

```
单位任务真实成本(model) = Σ cost_raw_cents / 任务数      # 未归一、真金白银
实测系数(推导用)         = 单位任务真实成本(model) / 单位任务真实成本(anchor)
```

**反身性问题（必须显式处理）**：若直接用 `cost_normalized_cents` 反推系数，
而该字段又是用**待校准的系数**算出来的，则 `Σnorm_model / Σnorm_anchor ≡ Σraw_model / Σraw_anchor`
——看起来"自洽"，但**用错误系数写出的历史事件会污染校准**。因此：

1. 校准取值一律基于 **`cost_raw_cents`**（或由 `tokens × 单价` 重算，两者应一致，脚本会断言）；
2. 历史归一化字段仅作**对账佐证**，不作校准输入；
3. 旧事件的 `coefficient_source` 若为 `price_ratio`，脚本在报告中标注该事件属"价格口径产出"。

## 五、对照与偏差（Control & Deviation）

```
价格系数(price_coef) = coefficient(model) 在 source="price_ratio" 下的 in/out 二元组
实测系数(measured)   = 单位任务正常化成本(model) / 单位任务正常化成本(anchor)     ← 标量
偏差率(deviation)    = (measured - price_coef_effective) / price_coef_effective
```

其中 `price_coef_effective` 是把二元组压在**本批样本真实 in/out token 构成**上的标量：

```
price_coef_effective(model) = (in_tokens×k_in + out_tokens×k_out) / (in_tokens + out_tokens)
```

**为什么必须压成标量**：`coefficient()` 返回 `{in, out}` 两维（单价不同），
而实测给出的是一维经验比。不做加权压缩就直接相减，等于把"输入输出构成差异"误记为"模型成本偏差"。
加权权重取**锚模型的 token 构成**，保证两边同尺度、可复现。

**偏差表字段**（每模型一行）：

| 模型 | 价格系数(有效标量) | 实测系数 | 偏差率 | 样本量(成本记录数) | 置信度 |
|---|---|---|---|---|---|

**置信度分级**（不设"我觉得"档，只按样本量与来源机械判）：

| 档位 | 条件 | 允许的说法 |
|---|---|---|
| `adequate` | 样本量 ≥ 20 **且** 路径 A | 可用于替换系数 |
| `insufficient` | 样本量 < 20 | **只披露不结论**：不给实测系数、不进工件 |
| `n/a` | 无可用样本 | 只登记"暂无" |

**异常识别（点名规则）**：若某模型 `|偏差率| ≥ 30%` **且** 置信度为 `adequate`，
在报告中**点名**并给出归因方向（重试/失败率/输出长度/缓存），这正是校准的价值所在。
若"实测与标价偏差可忽略"（全部 `|偏差率| < 10%`），**这本身就是有效结论**——
如实记录"价格锚定够用"，**不强行改系数**（任务书 §五）。

## 六、本地模型的成本口径（不得与 API 计价混算）

本地模型的货币成本不是 API 账单，必须**折算机时/能耗**并**单独成栏**：

```
本地模型成本(分/1k token) = (机时单价 元/小时 × 该批实测机时 小时) × 100 / (该批 token/1000)
```

硬约束：

1. **单列**：本地模型永远不出现在 `coefficient_table()` 的 API 计价列中，其口径在报告中
   以 `cost_basis="local_machine_time"` 显式标注；
2. **缺机时单价 → 记 `None`**（不以 0 冒充，也不以 API 价顶替）；
3. **不参与**"实测显著偏离标价"的点名（无标价可比）。

## 七、执行路径（A 有凭证 / B 无凭证降级）

两者共用同一套指标与偏差计算，**只有数据来源不同**。

### 路径 A —— 实跑（有凭证）

1. 对 L2 Core-50 的每条用例，用同一份提示与同一套判定器，在**每个参与模型**上跑一次；
2. 每次调用后立即 `utc.record_cost(...)` 落 `cost` 事件（`interaction_id` 幂等，重放不重复计）；
3. 采集 `UnifiedTraceStore` 的 cost 字段作为**第二来源对账**（同一次交互两处金额应一致）；
4. 汇总 M1–M8 → 偏差表。

**预算与安全（真实调用会产生真实费用）**：

* `--max-cases` 限制用例数（默认 50，可降到 e.g. 10 做冒烟）；
* `--max-cost-cents` 硬预算上限：**累计花费达到上限立即停止**并在报告中记"因预算截断"；
* 优先小模型与短提示；`--dry-run` 只打印将要发起的调用数与预估上限，不真调。

### 路径 B —— 降级（无凭证）

1. **离线重放** `data/events/` 中的历史 `cost` 事件，**按模型分组**统计 M1–M7；
2. **允许人工导入外部实测 CSV**（`--import-csv`，schema 见 §八），作为补充样本；
3. 产出"部分校准"工件与偏差表；
4. **报告中必须显式写明**：

   > **未完成完整实测校准，结论置信度受限**：本批数据的来源为
   > **历史事件流离线重放（+ 导入 CSV）**，**不是**在 L2 Core-50 上对多模型的同批实跑；
   > 样本量与任务口径与 §二 的设计不一致，故**不作为系数替换依据**。

5. 降级下**默认不写实测系数工件**（`--write` 才写），且写出的工件 `method` 字段为
   `offline_replay`、`calibrated` 保持 `False`——**不得用价格系数冒充实测**。

## 八、外部导入 CSV schema（人工实测数据入口）

```
model,task_id,tokens_in,tokens_out,cost_raw_cents,retries,error,cache_hit,ts
gpt-4,L2-S1-01,1200,340,0.42,0,,false,2026-09-12T10:00:00+08:00
```

| 列 | 必填 | 说明 |
|---|---|---|
| `model` | ✅ | 模型名（须与 `coefficient_table()` 中的名字一致，否则脚本报错而非静默丢弃） |
| `task_id` | ✅ | 任务标识（用于"单位任务"分母；同一 task 可多行=该任务的多次调用） |
| `tokens_in` / `tokens_out` | ✅ | 计费前 token |
| `cost_raw_cents` | ✅ | 该次调用的**实际金额（分）**；缺列则该行作废并计数披露 |
| `retries` | ⬜ | 默认 0 |
| `error` | ⬜ | 非空 = 该次调用失败（计入成功率分母） |
| `cache_hit` | ⬜ | `true/false/1/0`；命中则 token 不计费 |
| `ts` | ⬜ | ISO 时间；缺省用文件 mtime 不成立 → 置空并在报告标注"时间戳缺失" |

**行级纪律**：任何一行无法解析 → **跳过并计数**（`rows_skipped`），
报告披露"导入 N 行、采用 M 行、跳过 K 行（原因分布）"，**不插值、不补零**。

## 九、复校周期与触发条件

| 项 | 取值 |
|---|---|
| **周期** | **季度复校**（与 S5-03 `CALIBRATION_TRIGGER` 一致） |
| 提前触发 ① | 模型单价变更（`MODEL_COSTS` 或 `CP_UTC_PRICES` 改动） |
| 提前触发 ② | 锚模型变更（`config.yaml:llm.model` 或 `CP_UTC_ANCHOR_MODEL` 改动）→ 分母换了，历史系数作废 |

## 十、口径落地（版本化，不追溯历史）

| 项 | 设计 |
|---|---|
| 系数来源 | `source ∈ {override, measured, price_ratio}`（`price_anchor` 家族即 `price_ratio`） |
| 优先级 | `CP_UTC_COEFFICIENTS`（override，人工兜底） **>** 实测工件（measured） **>** 价格锚定（price_ratio 回落） |
| 回落保证 | 未实测 / 实测样本不足 / 工件过期 → **逐模型**回落价格系数，`source` 字段如实标注；**不产生行为回归**（S5-03 断食判定不变） |
| 版本标注 | 工件版本 `measured.v1`（完整实测）／`measured.partial.v1`（降级部分校准）；`calibration` 块输出 `calibrated` / `calibration_version` / `measured_models` / `calibrated_at` / `coefficient_sources` |
| **历史不追溯** | 旧 `cost` 事件保留其**写入时的** `coefficient_*` 与 `coefficient_source` 字段，**任何聚合都不按新系数重算历史**（`utc_daily/window/weekly/snapshot` 均为"读事件字段求和"，不重算）；新系数只影响**生效之后**新写入的事件。审计上以"事件自带口径字段"为准，故历史成本数字**不会被改写** |

## 十一、本方案的自我边界（诚实声明）

1. 本方案**不声称**校准已完成：完成与否由 §七 的实际执行路径与 §五 的样本量共同决定；
2. 路径 B 的产出**只是"部分校准"**，其价值是**证明管线可用 + 暴露数据缺口**，不是替换依据；
3. 全部数字必须可溯源（事件流路径 + 行号级定位 或 CSV 文件 + 行号）；
4. 样本不足时**只披露不结论**：不给系数、不写工件、不声称"偏差为 X%"；
5. 若结论是"偏差可忽略"，如实记录，**不为了交差而改系数**。
