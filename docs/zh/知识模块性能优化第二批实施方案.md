## 1. 第一步：批量删除 `delete_many`（低风险）

### 1.1 现状缺陷

[card.py](file:///c:/Users/Administrator/agent/agent/knowledge/card.py#L317-L332) `delete` 每次调用都走 `_has_incoming_links`（L247-251）→ `self.list()` 全库解析一遍 + 遍历所有卡片 links。批量删 K 张 = K 次 O(N) 全扫。

### 1.2 改动设计

新增方法（与 `delete` 同写锁内，复用现有 unlink/index/log 逻辑）：

```python
def delete_many(self, slugs: list[str]) -> dict[str, bool]:
    """批量删除；返回 {slug: 是否删除成功}。

    【不易】入链语义与单删一致：待删集合外的引用方仍指向 slug → 拒绝；
    待删集合内部的互相引用不阻止删除（整批同时消失，无残留断链）。
    """
    with self._rwlock.write():
        # 1. 一次全库扫描构建「被引用 slug → 引用方列表」
        incoming: dict[str, list[str]] = {}
        for card in self.list():                      # 唯一一次 O(N)
            for link in card.links:
                if not link.startswith("archives/"):
                    incoming.setdefault(link, []).append(card.slug)
        pending = set(slugs)
        result: dict[str, bool] = {}
        for slug in slugs:
            refs = [r for r in incoming.get(slug, []) if r not in pending]
            if refs:
                logger.warning("批量删除被拒: slug=%s 存在外部入链=%s", slug, refs)
                result[slug] = False
                continue
            path = self._find_path(slug)
            if path is None:
                result[slug] = False
                continue
            path.unlink()
            update_index_delta(slug, None, self._index_path)
            append_log("delete", slug, "batch", log_path=self._log_path)
            result[slug] = True
        return result
```

### 1.3 不变量与测试

- 不变量：批量删除的拒绝判定 == 逐次 `delete` 的判定（外部引用集合一致）。
- 新增单测：
  1. 50 张卡中删 10 张（无外部引用）→ 全 True，文件/索引/log 全清除；
  2. 待删集合互相引用 → 全部删除成功；
  3. 外部引用仍指向某张 → 该张 False 且文件保留；
  4. 批量结果与逐次调用 delete 结果逐一相等（一致性）。
- 验证指标：`delete_many(50)` vs 50 次 `delete` 耗时对比（基准脚本）。

### 1.4 回滚

纯新增方法，不触碰 `delete` 语义；删除新方法即可回滚。

### 2.3 不变式的重新定义（关键，须同步测试）

现有不变式「追加叠加结果 == 全量重建结果」在追加模式下**位置不同**。定义升级：

- 内容集合不变式：追加叠加后每个 section 的 slug 集合 == 全量重建集合（**幂等**：不重复、不遗漏）。
- 收敛不变式：对追加模式的 index 执行一次 `rebuild_index` 后，结果 == 直接全量重建（排序收敛）。
- 原「逐卡有序叠加 == 全量重建（逐字节一致）」保留给默认 `append=False` 路径。

### 2.4 测试与验证

- 改造现有一致性测试：`test_update_index_delta_matches_rebuild` 增加 append 模式的「集合相等 + 重整收敛」断言。
- 新增：append 模式重复写同 slug → 不产生重复条目（幂等）。
- 验证指标：高频写路径（append）写耗时 vs 现有序插入耗时对比。

### 2.5 回滚

## 3. 第三步：入链索引 index_links.md（高风险，须一致性测试先行）

### 3.1 现状缺陷

`_has_incoming_links`（L247-251）每次 `self.list()` 全库解析（含损坏卡跳过）→ 遍历所有 links，O(N)；`delete` 每次删除都触发。

### 3.2 新持久化产物契约

新文件 `wiki/index_links.md`（与 index.md 同目录、同原子写机制），格式：

```
# 知识库入链索引
> 此文件由 AI 自动维护，请勿手动修改。更新时间: YYYY-MM-DD

## slug-a
- [[slug-b]]
- [[slug-c]]
```

- `## <被引用slug>` 段 + `- [[<引用方slug>]]` 列表；段与引用方均按 slug 字典序（可复现）。
- 只记录指向 wiki 的纯 slug 入链；`archives/...` 不入表（对齐 `find_orphans` 语义）。
- 新模块 `agent/knowledge/links_index.py`（对齐 index.py 模式，避免 card.py 膨胀）：

```python
def rebuild_links_index(wiki_root, index_path) -> int:
    """全量重建：list() 一次构建全部入链关系，返回被引用 slug 数。"""

def update_links_delta(

    """为 ref_slug 的每个 target 添加/移除一条引用记录；返回变更数。
```

### 3.3 同步时机（挂到 CRUD 写锁内）

| 操作 | 索引变更 | 前置数据 |
|---|---|---|
| `create(card)` | 为 card.links 每个 target 添加 `target → card.slug` | 新卡 links（create 不解析正文，links 来自传入字段） |
| `update(card)` | 先移除旧 links 引用、再添加新 links 引用（diff） | **需读旧卡**：update 前 `self._md_to_card(old_path)` 取 old_links（多一次解析，可接受） |
| `delete(slug)` | 移除 slug 作为被引用方的整段 + 移除 slug 卡片的 links 产生的引用 | 需读被删卡 links：delete 前解析一次 |
| `_rewrite_incoming_links` | 被改名 slug 作为被引用方 → 改段名 | 现有重写逻辑旁追加 |

### 3.4 读路径替换

```python
def _has_incoming_links(self, slug: str) -> bool:
    """查入链索引（O(1)）；索引缺失/损坏时回退全库扫描（容错）。"""
    if self._links_index_path.exists():
        return _read_refs(self._links_index_path).get(slug)
    return any(slug in card.links for card in self.list() if card.slug != slug)
```

### 3.5 一致性测试（前置，先写测试后实现）

1. 全量一致性：`rebuild_links_index` 结果 == 全库扫描逐卡 links 聚合结果（集合相等）。
2. 增量一致性：任意 create/update/delete 序列后，`update_links_delta` 叠加结果 == `rebuild_links_index` 结果。
3. 幂等：重复执行 update_links_delta(add=True) 不产生重复引用。
4. 容错：索引文件被删后 `_has_incoming_links` 回退全扫，行为与重建一致。
5. 回归：`test_delete_rejects_incoming_links`（现有）在查表路径下保持绿。

### 3.6 验证指标与回滚

- 指标：`delete` 耗时（对照 1 万卡库：O(N) 全扫 vs O(1) 查表）；入链索引一致性测试全绿。
- 回滚：删除索引文件 + `_has_incoming_links` 回退全扫分支保留，即恢复现状；索引可随时重建，无数据丢失风险。
