# Phase 2 / Phase 3 稳定性验证执行计划（2026-08-14）

**背景**：Phase 1 首轮 fast 4x1 因两个叠加因素**全部 4 块被 Timeout 强杀**（0/4 无汇总 FAIL）：
1. **并行会话并发**：PID 18700 退出后，并行会话持续派生 pytest（18708/16744/11732/15312/15484…），D 类慢路径在并发负载下显著恶化（与 2026-08-14 T-4 教训一致）
2. **fast 集合标注不全**：残留 4 个未标注 slow 的 D 类慢文件

**已修复**：4 处 slow 标注已追加（2026-08-14，文件级 `pytestmark`，135 用例验证 fast 排除 / slow 选中），累计 8 处 slow 文件。

> 本计划验证 slow 分流后 Phase 2（slow 单独跑）与 Phase 3（固定 seed 顺序污染）的稳定性，
> 依赖前置条件：并行会话 python 全部退出（等待链自动判定）后执行。

## 一、前置条件（守不易）

| 条件 | 校验 | 不满足时 |
|---|---|---|
| 并行会话清空 | `Get-Process python` 为空且 60s 内无新派生 | 等待链持续等待，不启动任何测试 |
| 工作区回归可判定 | `run_full_pytest.py` 内置 guard（提示模式放行 / `REGRESSION_REQUIRE_CLEAN=1` 强制） | 按 guard 提示处理 |
| 无新增 slow 点 | Phase 2 结果中 Timeout 计数归因 | 新卡点 → 追加标注或转修复 |

## 二、Phase 2：slow 模式稳定性验证（8 个 slow 文件）

```bash
python scripts/run_full_pytest.py 1 1 slow
```

- 单块直跑 `-m slow --runslow --timeout=300`，产物 `pytest_chunks/chunk_0.log`
- **覆盖 8 处 slow 文件**：
  | 批次 | 文件 | 根因 |
  |---|---|---|
  | 原 4 处 | weekly_report_generator / task_scheduler / task_scheduler_integration（文件级）+ e2e 热更（用例级） | pydantic_settings/importlib 扫描、t.join 卡死 |
  | 新 4 处 | permission_system_concurrency / task_scheduler_comprehensive / memory_module / memory_optimized（文件级） | 线程 join 死锁、dotenv/transformers/pydantic_settings 扫描 |

- **验证点**：
  1. `--runslow` 门控用例被激活（16 个 `--runslow` 门控用例不 skip）
  2. 300s 超时余量下，D 类扫描路径可完成（os.stat/importlib 慢路径 >60s）
  3. **高风险**：`test_permission_system_concurrency.py::test_concurrent_confirm_no_crash` 的
     `t.join()` 在 Windows 阻塞 `_wait_for_tstate_lock`，thread 超时无法中断——若 300s 仍被强杀，
     **该用例转 `@pytest.mark.skip`（Windows 环境性）** 或实施 P2 修复（`t.join(timeout)` + daemon 线程）
- **判定**：Timeout 记录为 D 类已知项（不判失败）；非 Timeout 失败按失败处理 → 转 B/C 类

## 三、Phase 3：固定 seed 顺序污染验证（B 类收敛）

```bash
python -m pytest tests/ -q --randomly-seed=20260813 -m "not slow"
```

- **必须单进程直接命令行**（分块模式破坏 pytest-randomly 全局随机顺序，记忆教训）
- **语义边界**：fast 集合现为 519 文件（527 收集 - 8 slow），与 rc3 的 523 全集**集合不同**——
  固定 seed 仅保证**相同集合**可复现；本阶段验证目标是 B 类顺序污染收敛，非复现 rc3 历史顺序
- **验证点**：
  1. `0 failed / 0 errors`（skipped/xfailed 不计）
  2. B-2 collect ERROR 不复现（与 `--co` 证据链一致）
  3. 单进程下无 chunk 分块干扰，D 类已排除，预期 25-35 分钟完成

## 四、稳定性验证维度（变易）

| 维度 | 措施 |
|---|---|
| 环境噪声 | 并行会话清空后才执行；Phase 2/3 全程不派生新测试 |
| 超时余量 | slow 300s / fast 默认 120s；卡死点用 monitor 汇总行判定而非 rc |
| 可观测性 | `scripts/monitor_phase1.py` 逐 chunk 抓 `=+ N passed` 汇总行，全卡死时 all_settled 立即收尾 |
| 顺序语义 | 分块仅定位功能失败；顺序污染仅 Phase 3 单进程验证 |
