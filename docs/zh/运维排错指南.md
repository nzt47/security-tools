## 一、SSH 连接与认证故障（simulate_ssh_deploy.sh 模式 B）

脚本连接测试始终 `ssh -v` 且**输出已过滤**（仅保留超时/认证失败/成功关键行），失败时打印带时间戳诊断日志：

```
[ssh] debug1: Connecting to 10.255.255.1 [10.255.255.1] port 22.
[ssh] debug1: connect to address 10.255.255.1 port 22: Connection timed out
[ssh] ssh: connect to host 10.255.255.1 port 22: Connection timed out
[FAIL] SSH 连接失败（exit=255，耗时 Ns 内未建立）
```

| 现象 | 排查步骤 |
|---|---|
| `Connection timed out`（exit 255，网络层） | ① `ping <host>` 网络可达性 ② 防火墙/安全组放行 `--ssh-port`（默认 22）③ 确认公网 IP/内网 VPN |
| `Permission denied` / `No more authentication methods`（认证失败） | ① 密钥是否正确（`--key` 指向私钥）② 私钥权限需 600：`chmod 600 <key>` ③ 用户名拼写（`root`/`ubuntu` 等）④ 服务端是否允许密钥登录 |
| `Host key verification failed` | 脚本已用 `StrictHostKeyChecking=accept-new` 自动接受；仍失败检查本机 `known_hosts` 冲突 |
| 非标准端口连接失败 | 用 `--ssh-port <端口>` 指定；确认服务端 sshd 监听端口 |
| `Connection closed by <host> port 22` | 服务端 sshd 拒绝（配置/防火墙）；`ssh -vvv` 看服务端响应 |

> 需要完整调试输出时：手动 `ssh -vvv -p <port> -i <key> user@host`（不过滤）。
> 自动执行版：`bash scripts/dev/diagnose_ssh.sh --host <ip> [--port 22] [--user root] [--key <私钥>]`
> Windows 原生：`powershell -File scripts/dev/diagnose_ssh.ps1 -Target <ip> [-Port 22] [-User root] [-Key <私钥>]`
> 一键入口：`powershell -File scripts/dev/local_ops.ps1 diag -Target <ip> -User root -Key <私钥>`

### 5 层诊断逻辑流程图

```
                SSH 连接失败
                     │
                     ▼
      ┌─────────────────────────────┐
      │ 1/5 DNS 解析                │────FAIL──► 域名拼写 / DNS 配置（getent/nslookup）
      └─────────────┬───────────────┘
                    │ PASS
                    ▼
      ┌─────────────────────────────┐
      │ 2/5 ping 可达性             │────FAIL──► 路由 / VPN / 防火墙
      └─────────────┬───────────────┘           （ICMP 被禁时以 3/5 为准）
                    │ PASS
                    ▼
      ┌─────────────────────────────┐
      │ 3/5 TCP 端口（默认 22）      │────FAIL──► 安全组/防火墙放行 / sshd 监听
      └─────────────┬───────────────┘            / --port 对齐
                    │ PASS
                    ▼
      ┌─────────────────────────────┐
      │ 4/5 SSH banner（SSH-2.0）     │────FAIL──► 端口非 SSH / sshd 未运行
      └─────────────┬───────────────┘
                    │ PASS
                    ▼
      ┌─────────────────────────────┐
      │ 5/5 SSH 认证                 │────FAIL──► 密钥正确性 / 权限600 / 用户名
      └─────────────┬───────────────┘            / 服务端密钥登录配置
                    │ PASS
                    ▼
             连接成功（服务可访问）
```

> 规则：任一层 FAIL 即停止并输出该层建议；后续层不再执行（PASS 才继续下一层）。

> **⚠ 警示：Banner 判断逻辑变更（2026-08-16）**
> `diagnose_ssh.sh` / `.ps1` 第 4 层 banner 判断已由 `220` 前缀修复为 **`SSH-` 前缀（RFC 4253 §4.2）**，并修复 PS 版 Substring 越界。勿改回 `220`——那是 SMTP 响应前缀（RFC 5321），会导致所有正常 sshd 被误判 FAIL、认证层永不执行。
> 变更明细见 `docs/zh/变更说明_banner判断修复_20260816.md`；回归保护见 `scripts/dev/regress_ssh_diag.py`。

## 二、服务启动与健康检查

| 现象 | 处理 |
|---|---|
| `check_service_ready.sh` 报不可达 | 确认服务监听端口（裸机 5678 / 容器映射 `${YUNSHU_PORT:-5678}:5678`） |
| 容器反复重启 / 健康检查不过 | `docker logs <container> --tail 100` 排查；确认 `.env` LLM 4 项已配置 |
| 5678 不通 | `check_service_ready.sh --container ...`；确认 compose 端口映射与 `env_file` 注入 |
| 首次启动慢 | AI 依赖（torch/chromadb）加载，healthcheck `start_period 90s`；可调 `start_period` |

## 三、告警与邮件

| 现象 | 处理 |
|---|---|
| 告警未发信 | `.env` 缺 `SMTP_HOST/SMTP_TO`（降级仅打印，见 analyze WARN） |
| 真实发信失败 | `python scripts/test_smtp_send.py --to <收件人>` 复现；检查 SMTP_PORT/SSL 配置（465=SSL/587=STARTTLS）与授权码 |
| 本地链路验证 | `python scripts/test_smtp_alarm_e2e.py`（捕获服务器 7 断言）；`python scripts/test_smtp_alarm_e2e.py --external-host <host> --external-out <path>`（外部服务器） |

## 四、测试与 CI 环境

| 现象 | 处理 |
|---|---|
| pytest 报 `unrecognized arguments: --timeout` | 缺 `pytest-timeout` 插件：`pip install -e ".[dev]"` |
| Windows 下 py launcher 解析到另一解释器（缺依赖） | 脚本已按 `python → py → python3` 探测；或 `-Python <路径>` 显式指定 |
| 单测过慢 | `test_open_api_endpoints.py` 每个用例重建网关；可拆组运行或 `-Quick` 跳过 |
| 沙盒/Git Bash 网络隔离（curl 连不上本机） | 脚本已加 python urllib 回退；真机无此限制 |

## 五、快速定位思路

1. **先健康后日志**：`check_service_ready.sh` → `docker logs`（容器）或服务 stdout
2. **先链路后配置**：`test_smtp_alarm_e2e.py`（本地链路）→ `test_smtp_send.py`（真实发信）→ 检查 `.env`
3. **先自检后联调**：`run_ci_test_local.ps1 -Quick`（自检+单测）→ `open_api_client.py`（开放接口）
