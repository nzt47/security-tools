## 3. 发现的问题

### 3.1 【P0 #3】`_audit_draft` 并发写损坏（本次核心缺陷）

- **现象**：S2 首跑 FAIL——审计 JSONL 出现 UTF-8 多字节字符截断损坏、解码异常
- **根因**：Windows 上 Python `open(path, "a")` 的 append 模式由 CRT 模拟为「lseek 到 EOF 再 write」。**多句柄并发写非原子**：后写者基于过期 EOF 定位，覆盖/截断先写者已落盘内容；多字节 UTF-8 字符在写交错时被拦腰截断
- **隔离实验**：单文件多线程 append 复现 → 确认与业务逻辑无关，属平台 append 语义问题

### 3.2 【P0 #1】slugify 校验约束（测试构造坑）

`CardStore.create()` 校验 `slug == slugify(title)`，连字符会被剥离（如 `wr1-1000` ≠ `wr1`）。压测构造卡片必须用**纯字母数字 slug**（`seed{i:04d}` / `wr{tid}{base+i:04d}`），否则 create 被拒。

## 4. 修复方案

在 [precipitate.py](file:///c:/Users/Administrator/agent/agent/skills_mgmt/precipitate.py) 增加模块级写锁，串行化审计 JSONL 的 append 写：

```python
import threading

# 审计 JSONL 并发写锁（Why: Windows 上 append 模式由 CRT 模拟
# 「lseek 到 EOF 再写」，多句柄并发写非原子，会相互覆盖截断导致
# 多字节 UTF-8 字符损坏——2026-08-14 P0 #3 高并发压力测试发现；
# 进程内锁串行化写后完整）
_audit_write_lock = threading.Lock()
```

写入路径统一进锁：

```python
try:
    with _audit_write_lock:  # 串行化 append 写（Windows 非原子，见模块注释）
        path = Path(self._audit_path or _audit_file())
        path.parent.mkdir(parents=True, exist_ok=True)
        with open(path, "a", encoding="utf-8") as f:
            f.write(json.dumps(rec, ensure_ascii=False) + "\n")
    ...
except OSError as e:
    logger.warning("[Precipitate] 审计日志写入失败: %s", e)
```

**设计要点**：
- 锁只保护文件写本身（临界区极小，无外部回调），遵循「锁内仅保护必要状态变更」
- 失败仍走 OSError 兜底告警，审计功能降级不崩溃

## 6. 局限与后续建议

- **锁为进程内锁**：仅串行化单进程内多线程写。多进程写同一审计文件仍需跨进程互斥（如 `msvcrt.locking` / `fcntl.flock` 或独立文件/队列）
- Windows 下若未来引入多进程沉淀任务，建议审计文件按进程分片或引入文件锁再收敛
