# SSR 相关遗留问题清单（下一迭代）

> 项目：云枢 · AI 智能体桌面工作台
> 关联：SSR 兼容性加固（已完成，见 `docs/zh/SSR兼容性加固变更说明.md`）
> 日期：2026-08-21
> 目标：规划下一迭代 SSR 方向待办，明确优先级、依赖与验收标准

---

## 1. 背景

本轮已完成 SSR 兼容性加固的**最小必要项**：渲染期 `localStorage` 读取的窗口守卫（`safeGetLocalStorage`）与回归测试。以下为评估后**暂不实施**或**需进一步决策**的遗留事项，供下一迭代规划。

## 2. 遗留问题清单

| 编号 | 事项 | 现状 | 优先级 | 依赖 | 验收标准 |
|---|---|---|---|---|---|
| SSR-1 | 服务端场景还原决策 | 守卫回退「未选中」，服务端首屏不还原用户已选场景 | P1（决策先行） | 产品确认 | 明确「是否需要首屏还原」结论并记录到 ADR |
| SSR-2 | 渲染期 window/localStorage 访问全量审计 | 仅 `MockScenarioMenu` 已加固；全仓未审计 | P1 | — | 输出全仓审计清单，标注每个访问点的运行时机（渲染期/effect/事件） |
| SSR-3 | 新代码规范强制化 | 无 lint/CI 强制 | P2 | SSR-2 审计结论 | eslint 规则（如 `no-restricted-globals` 禁止渲染期裸访问）或提交检查落地 |
| SSR-4 | storage 层服务端抽象 | `safeGetLocalStorage` 仅提供「SSR 不崩溃」语义，无服务端数据通道 | P2 | SSR-1 若选「需还原」则升 P1 | 存储接口支持服务端注入（如 cookie 读写），场景选择可跨端透传 |

| SSR-6 | 组件级 SSR 渲染测试 | 已测工具函数，未覆盖组件在 `react-dom/server` 下渲染 | P3 | SSR-2 | `renderToString(<MainLayout/>)` 冒烟用例（mock store/路由）不崩溃 |

## 3. 优先级说明

- **P1（下一迭代核心）**：SSR-1 决策 + SSR-2 审计——先摸清全量风险面，再定方案，避免"只加固一处"的盲区。
- **P2（紧跟 P1）**：SSR-3 规范强制化（防新增隐患）、SSR-4 存储抽象（若 SSR-1 需要）。
- **P3（按需）**：SSR-5 框架选型、SSR-6 组件级渲染测试——仅在正式启动 SSR 改造时排期。

## 4. 风险与注意

1. **SSR-1 是决策项而非技术项**：若产品明确"无需服务端还原场景"，则 SSR-2/3/4 均可大幅简化（当前守卫 + 规范防新增即可）。
2. **Electron 特殊性**：桌面端无 SSR 概念（`file://` 加载本地构建产物），SSR 相关改造主要服务 **Web 部署形态**（Nginx/Flask 同域），评估时需区分两种形态的影响面。
3. **既有 CI 基线问题独立跟进**（Gitleaks / 文档链接 / 硬编码边界值），不属于 SSR 范畴，勿混入本清单排期。

## 5. 建议执行顺序

```
SSR-1 决策 → SSR-2 审计 → （决策结果）→ SSR-3 强制化 / SSR-4 抽象
                                        ↘ SSR-5 选型评估（并行可选）
```
