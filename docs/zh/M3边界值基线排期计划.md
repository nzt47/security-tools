## 3. 配套：自动化验收测试

已就绪（随 PR #754 提供）：`tests/unit/test_m3_boundary_baseline.py`（5 用例）

- 扫描器识别 timeout / retry / capacity 三类边界值（样例驱动）
- 基线文件结构有效（high_risk / configured_modules）
- 扫描发现关联被扫文件（防误扫/漏扫）

**防回归意义**：M3 完成后，若未来提交新增未配置化边界值并超基线，CI 立即失败；若有人破坏扫描器识别逻辑或基线文件，本测试立即失败。

## 4. 验收标准

1. CI「硬编码边界值扫描」通过（Boundary Guard 绿）
2. 基线文件更新有归属说明（新增基线项可追溯来源）
3. M3 验收测试 5/5 通过
4. 无新增未配置化边界值（配置化优先于盲目扩基线）

## 5. 风险与注意

1. **基线更新需评审**：新增基线必须带归属说明，防止掩盖真实新增硬编码（安全底线）
2. **配置化优先**：对可配置项优先抽取配置，避免基线无限膨胀
3. **与 M1/M2 解耦**：M3 独立排期，不阻塞功能发布；工作区未提交改动需先确认是否纳入（建议先提交或暂存，避免污染基线比对）
4. 完成 M3 后，3 项 CI 基线失败中 Gitleaks（M1+M2 已清零命中）与边界值（M3）均解决，仅剩 ChromaDB 容器环境类问题单独跟踪
