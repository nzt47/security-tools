## A-2 / A-3：本地 pre-commit hook 未同步 TLM 体系（统一根因，最高优先）

### 实测证据

- A-2：`test_real_git_commit_blocked_by_hook` → `AssertionError: No .pre-commit-config.yaml file was found`
- A-3：`simulate_ci_guard_pipeline.py --json` returncode=1 (0x00000001)，stdout 含
  `[BLOCK] [D1] .git/hooks/pre-commit: 部署的 hook 含编码检查段 缺少模式: ENCODING_CHECK\s*=`

### 根因

两个测试都依赖**本机 `.git/hooks/pre-commit` 的当前状态**：

1. `test_precommit_hook_blocking.py::_install_local_hook`（L118-153）**优先采用** `REPO_ROOT/.git/hooks/pre-commit`（L33 `LOCAL_HOOK`），仅当其**缺失**时才回退 `hook_fail_safe.psm1` 生成。本机 hook 是旧版 pre-commit 框架 hook → 复制到临时仓库后 commit 报 "No .pre-commit-config.yaml file was found"。
2. `simulate_ci_guard_pipeline.py` 的 D1 编码检查段直接检查 `.git/hooks/pre-commit` 是否含 `ENCODING_CHECK\s*=` 模式 → 本地旧 hook 不含 → [BLOCK] → exit 1。

### 修复方案

**步骤 1（治本，本地部署）**：重新部署 TLM hook 体系
```powershell
powershell -ExecutionPolicy Bypass -File scripts/dev/sync_precommit_hook.ps1
```
验证：`Get-Content .git/hooks/pre-commit | Select-String "TLM_HOOK_SOURCE_REPO|ENCODING_CHECK"` 有命中。

**步骤 2（测试加固，【不易】测试不得依赖本地 .git/hooks 状态）**：
- `test_precommit_hook_blocking.py::_install_local_hook`：`LOCAL_HOOK` 分支增加 **marker 校验**——内容含 `b"TLM_HOOK_SOURCE_REPO"`（或 `b"ENCODING_CHECK"`）才采用；否则打印 WARN 并走 `hook_fail_safe.psm1` 生成路径。**验收**：删除/破坏本地 `.git/hooks/pre-commit` 后测试仍通过。
- `simulate_ci_guard_pipeline.py` D1 段：待检查内容改用 `hook_fail_safe.psm1` 的 `Get-HookContent -SourceRepo <repo>` 生成（对齐 A-2 的 psm1 回退），不再直接读 `.git/hooks/pre-commit` 文件。

**步骤 3（回退）**：如 psm1 生成路径本身有缺陷，退回到"步骤 1 本地部署 + 测试前置断言 hook 已同步"（fail-fast 提示而非静默假绿）。

**验收**：A-2/A-3 单文件 + 全量均通过；本地 hook 被删除时 A-2 走回退路径仍绿。

## A-1：impact_analysis_cache 符号链接降级分支残留

### 实测证据

`test_collect_test_files_symlink_resolution`（L1355-1401）→
`AssertionError: 符号链接创建失败时应仅收集 1 个真实文件，实际 2`

### 根因

`os.symlink(real_file, symlink_file)` 在 Windows 无特权时抛异常（实测 `FileNotFoundError [WinError 2]`，被 `except (OSError, NotImplementedError, PermissionError)` 捕获 → `symlink_created=False`），但 **os.symlink 失败后磁盘上残留了 link 文件**（rglob 跟随收集到 real + link 共 2 个），与"降级仅 1 个"断言冲突。测试假设"异常 = 无链接文件"，Windows 上不成立。

### 修复方案

`test_collect_test_files_symlink_resolution` 捕获异常分支补残留清理：
```python
except (OSError, NotImplementedError, PermissionError):
    # 【不易】Windows 上 os.symlink 失败可能残留无效链接文件
    #（实测 WinError 2 后 link.txt 仍在），必须清理否则 rglob 仍收集到。
    if symlink_file.exists():
        try:
            symlink_file.unlink()
        except OSError:
            pass
    symlink_created = False
```

### 验收

- Windows 无管理员/开发者模式：收集 1 个（降级分支），通过
- Linux / Windows 有权限：收集 2 个（symlink 分支），通过

## A-4 / A-5：system_tools_core 符号链接权限异常未捕获

### 实测证据

`test_get_file_info_symlink`（L1515）/ `test_get_file_info_symlink_error`（L3605）→
`FileNotFoundError: [WinError 2] ... 'target.txt' -> 'link.txt'`（测试直接崩溃）

### 根因

两处仅 `if hasattr(os, "symlink"):` 判断后直接 `os.symlink(...)`，**未捕获 Windows 无符号链接权限的运行时异常**（WinError 2/1314），测试崩溃而非 skip。

### 修复方案

两处统一改为安全创建 + 权限失败 skip：
```python
if hasattr(os, "symlink"):
    try:
        os.symlink(target_path, link_path)
    except (OSError, NotImplementedError):
        pytest.skip("Windows 无符号链接权限/未启用开发者模式")
```
（`FileNotFoundError` 是 `OSError` 子类，一并覆盖）

### 验收

- Windows 无权限：pytest.skip（不计失败）
- Linux/有权限：`result["ok"] is True` 断言保持
