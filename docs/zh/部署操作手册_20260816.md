## 三、Docker 构建与运行（方式二：容器化）

### 3.1 构建镜像

Dockerfile 位于 `deploy/t8-gateway/`（依赖打包：CPU 版 torch + `pip install -e .`；启动：entrypoint → `python app_server.py`）。

```bash
cd deploy/t8-gateway
# 构建上下文已用 .dockerignore 瘦身（排除 venv/.git/data 等）
docker build -t yunshu:latest .
```

> 首次构建含 torch/chromadb 等 AI 依赖，约 10-20 分钟；`deploy/t8-gateway/.dockerignore`
> 已排除 venv/.git/data/__pycache__ 等避免上下文膨胀。

### 3.2 运行容器

```bash
# 方式一：docker run（.env 注入 + data 卷持久化）
docker run -d --name yunshu \
  -p 5678:5678 \
  --env-file .env \
  -v "$(pwd)/data:/app/data" \
  -e FLASK_API_TOKEN=your-internal-token \
  yunshu:latest

# 方式二：compose（deploy/t8-gateway/docker-compose.yml）
cd deploy/t8-gateway
docker compose up -d
```

启动时 entrypoint 自动执行（幂等）：
1. `.env` 缺失则生成 `FLASK_API_TOKEN`
2. 历史审计日志租户归属补全（`migrate_audit_logs_tenant.py --apply --yes`，自动备份 `.bak_*`）
3. `INIT_TENANT=1` 时执行租户初始化

### 3.3 验证

```bash
curl http://127.0.0.1:5678/api/health
python scripts/examples/open_api_client.py --user-id demo@example.com --base-url http://127.0.0.1:5678
```

## 五、常见问题

- **服务启动失败（缺 LLM key）**：`.env` 需 `LLM_PROVIDER/LLM_API_KEY/LLM_MODEL/LLM_BASE_URL`（可用 `scripts/guard_llm_api_key.py --check` 检测）
- **告警未发信**：`.env` 缺 `SMTP_HOST/SMTP_TO` 时降级仅打印（见 `analyze_audit_logs.py` WARN）
- **容器 5678 不通**：检查 `docker ps` 端口映射与 `--env-file .env` 是否生效
