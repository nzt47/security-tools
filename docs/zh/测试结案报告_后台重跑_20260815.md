## 2. 核心结论

### 2.1 0xC0000005 崩溃：✅ 确认缓解

- 4 块日志扫描 **0 处** `0xC0000005` / `AccessViolation` / `Fatal Python error`
- 此前崩溃点 `test_resource_monitor_persist.py`（chunk_1，psutil `Process.open_files()` 原生 ACCESS_VIOLATION）本轮所在 chunk_1 **完整执行且有汇总行**
- 缓解措施：workers 4→2（降低并行文件 I/O 负载）。结论：崩溃为高并行负载下 psutil 原生崩溃，非代码缺陷，由 workers 减半有效规避

### 2.2 UnicodeEncodeError（emoji 日志丢失）：✅ 根因修复

- 现象：`memory.memory_manager`（🔁 `\U0001F504`）、`memory.vector_store.sqlite_vec_backend`（✅ `\u2705`）日志在 Windows GBK 代码页下 emit 抛 UnicodeEncodeError，日志行丢失并污染 "Logging error" 追踪
- 根因：`scripts/run_full_pytest.py` 漏设 `PYTHONIOENCODING=utf-8`（项目其他 47 处脚本均已设置）→ pytest chunk 子进程（ProcessPoolExecutor spawn）stdio 为 GBK
- 修复：run_full_pytest.py 顶层 `os.environ.setdefault("PYTHONIOENCODING", "utf-8")`（子进程继承）；已验证 spawn 子进程 emoji 正常输出、pytest 实测无 "Logging error"
- 提交：`0cf96f64`

### 2.3 报告解析 bug：✅ 已修复

- 现象：report_20260815_095009.md 表格 4 块全部误显示"无(疑似强杀)"，但日志实际有汇总行
- 根因：`parse_summary` 正则要求 `passed` 在行首且不兼容 `deselected/warnings/(M:SS) 后缀` 字段
- 修复：改为"数字+字段名"顺序无关提取（`SUMMARY_LINE_RE` + `FIELD_RE`），4 块日志实测解析结果与真实汇总一致
- 提交：`35a08fbc`
