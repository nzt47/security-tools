## 3. 关键修复点

### 3.1 端到端脚本重复运行兼容（`scripts/simulate_evolution_flow.py`，提交 `0d1a69ad`）

背景：脚本对同一真实库二次运行时出现 FAIL/IndexError。排查结论：**不存在"注入器与库数据不一致"**（直接 SQL 与 `list_strategies()` 逐条对比一致），真正根因是重复运行的去重/状态叠加：

- **案例去重**：`record_failure_case` 按 `trace_id + failure_type` 去重，重复运行时 `saved_a/b/c=[]`，原断言引用空列表 → IndexError/FALSE。
- **deprecated 状态叠加**：阶段 3/4 的失败模拟会把**所有** `tool:web_search` 策略推进 deprecated，重复运行时无 active 策略可供路由注入，`web_scrape` 后备失效。
- **`--storage` 模式崩溃**：`AutoTuner(storage_path=os.path.join(tmp, ...))` 引用仅在非 storage 分支定义的 `tmp` → `UnboundLocalError`（预存 bug，此前从未跑到结果行）。

修复：

1. **确定性 sid + 幂等 seed**：`seed_strategy` 的 strategy_id 由进程随机 `hash()` 改为 `hashlib.md5(prompt_patch)` 稳定派生；命中已有策略直接返回既有 sid，不重复入库（保持"只追加不删除"语义，杜绝演示污染真实库——此前 3 次验证运行已留下 6 条重复 preset）。
2. **断言库内回退**：案例 A/B/C 与 ReAct 命中检查增加"库内已存在匹配 scope 策略"的二级条件，重复运行时 `saved=[]` 仍能验证闭环。
3. **职责分离**：`fb_sid`（web_search 备用路径）保持 active 专供路由注入；新增 `dep_sid` 专用策略承载 deprecated 判定演示（按设计被标记 deprecated）。阶段 3 对重复运行走"核验既有 deprecated 状态"分支。
4. **`tmp` 提升**：临时目录在 `main()` 顶部统一定义；auto_tuner 的 auto_tuning.db 走隔离临时目录，不混入策略库。

### 3.2 清理脚本 dry-run 友好性（`scripts/cleanup_deprecated_strategies.py`，提交 `a153539a`）

- evolution.db 不存在时输出 `[库不存在] ... 当前无 evolution.db —— 策略库尚未使用 SQLite 后端或尚无数据，无需清理`，**非异常**，dry-run 安全退出。
- 默认 dry-run，`--execute` 才物理 DELETE；deprecated 超 30 天才清理（30 天内 deprecated 与 active 均保留）。

### 3.3 测试套件补充（`tests/integration/test_evolution_integration.py`）

- **新增** `test_trace_id_empty_fallback_no_none_in_logs`：无 TraceContext（`get_trace_id()` 返回 None）时，ReAct/Critic/tool_router 三处注入不抛异常且策略仍生效（容错 ≠ 吞功能）；日志绝不打印 `trace_id=None`（`or ""` 兜底生效）；命中日志 `trace_id=` 后为空值（注入链路仍可追溯）。
- auto_tuner 建议生成逻辑已有覆盖：`test_auto_tuner_strategy_linked_suggestion_hitl`（高失败率 → 下调并发/上调超时 → HITL 批准应用）、`test_auto_tuner_strategy_suggestion_none_without_high_failure`、`test_auto_tuner_strategy_weekly_report`。
