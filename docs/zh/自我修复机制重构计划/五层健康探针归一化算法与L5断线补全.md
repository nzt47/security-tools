## 一、背景与问题

云枢健康评估存在三个致命缺陷：

1. **评估失真**：`HealthAssessor.assess()` 无指标时返回默认满分 `1.0`，系统"假装健康"；
2. **无自动触发**：健康采集与 Dashboard 探针趋势 API 依赖的 `probes.py`/`storage.py`/`collector.py`
   三个模块从未提交（引用存在、文件缺失），导致 `import agent.health.dashboard` 直接失败；
3. **人机边界不一致**：探针数据缺失时旧代码仍参与加权平均，拉低/虚高整体分。

本文档记录修复后的**归一化算法契约**与**断线补全机制**，作为后续演进的不动点。

---

## 二、五层探针模型

| 层 | 标识 | 含义 | 默认权重 | 数据源 |
|----|------|------|----------|--------|
| L1 | `l1_process` | 进程资源 | 0.25 | psutil（CPU/内存/线程/磁盘） |
| L2 | `l2_dependency` | 依赖服务 | 0.20 | configs 核心配置可读性 |
| L3 | `l3_llm_tool` | LLM/工具链路 | 0.25 | metrics 错误率 + 熔断器状态 |
| L4 | `l4_business` | 业务接口 | 0.20 | metrics 请求/成功率 |
| L5 | `l5_semantic` | 语义质量 | 0.10 | feedback 满意度 |

**【不易】权重不可变**：权重 = 业务重要性，不由故障频率动态调整（规避 D3）。
定义见 `agent/health/assessor.py` 的 `DEFAULT_WEIGHTS`。

`ProbeResult` 契约（`agent/health/probes.py`）：

```python
@dataclass
class ProbeResult:
    layer: str
    score: Optional[float]   # 0.0~1.0；无数据必须为 None
    detail: str
    available: bool          # False = 未采集到真实数据
```

## 三、归一化算法（核心契约）

`HealthAssessor.assess_with_probes(probes)`（`agent/health/assessor.py`）：

```
输入：probes = {layer: ProbeResult}
规则：
  1. available=True 的层集合记为 A；available=False 的层不参与加权
  2. overall = Σ(w_i × score_i) / Σ(w_i)  其中 i ∈ A
  3. A 为空 → overall = None，issues 追加 "无数据"
  4. 每个 unavailable 层在 issues 中注明 "{layer} 无数据"
  5. overall 保留完整精度，不 round
```

**关键性质（禁假满分）**：

- 任一探针无数据 → 该层分数 `score=None`，**不参与归一化分母**；
- 全部无数据 → `overall=None`（JSON 序列化为 `null`），Dashboard 渲染断线而非 0 分或 1 分；
- `assess()` 无参调用保留历史兼容（返回默认 1.0），显式 `None`/空 dict 返回 `overall=None`。

### 手算验证样例

**L5 缺失（仅 L1-L4 可用）**：
```
w:    0.25  0.20  0.25  0.20  0.10(L5 缺失)
s:    0.9   1.0   1.0   0.2   -
overall = (0.25×0.9 + 0.20×1.0 + 0.25×1.0 + 0.20×0.2) / (0.25+0.20+0.25+0.20)
        = 0.715 / 0.90 = 0.7944444...
```

**L3+L5 缺失（仅 L1/L2/L4 可用）**：
```
overall = (0.25×0.9 + 0.20×1.0 + 0.20×0.2) / (0.25+0.20+0.20)
        = 0.465 / 0.65 ≈ 0.71538...
```

**全部缺失**：`overall = None`，`issues = ["无数据"]`。

## 四、L5 断线补全机制

"断线"指时间序列上某采样点因数据缺失而 `overall=null`。

### 4.1 后端数据流

```
collector.py  _collect_once()
  → run_all_probes()                     # 五层采集，缺数据的层 available=False
  → health_assessor.assess_with_probes() # 归一化，缺失层不参与
  → health_storage.append(record)        # JSONL 落盘 data/health/history-YYYY-MM-DD.jsonl
```

Dashboard API：

```
GET /api/health/probe-trend?hours=N
  → get_probe_trend(hours)
  → storage.query_history()   # 跨日聚合，含 timestamp/overall/dimensions/probe_details
```

### 4.2 断线语义（前端消费约定）

`probe-trend` 响应中 `points[].overall` 与 `probe_details[layer].score` 为 `null` 时：

- **前端图表应断线**（跳过一个点，不连线），不得补 0 或补 1；
- `probe_details[layer].available=false` 明确告知前端该层无数据，可灰显/标注；
- `issues` 数组附带人类可读原因（如 `"l5_semantic 无数据"`）。

> 说明：当前 web 端（`templates/observability_dashboard.html` 等）尚未消费
> `probe-trend` 明细；前端接入时按上节语义渲染即可，后端契约已稳定。

### 4.3 L5 特有场景

L5 权重仅 0.10，即使缺失对整体分影响也小；但其 `available` 状态必须如实上报——
**禁止用 "无反馈=满分" 或 "无反馈=0分" 等隐含假设**，无反馈就是无数据（`score=None`）。

## 八、不动点（【不易】约束）

1. 权重 `DEFAULT_WEIGHTS` 为业务常量，禁动态调整；
2. `ProbeResult.available=False` ⇔ `score=None`，缺失层禁参与归一化；
3. 全部缺失 → `overall=None`，禁假满分；
4. `HealthScore` 公开字段（`overall`/`dimensions`/`issues`/`probe_details`）不变；
5. `assess()` 无参调用保持返回默认 1.0（向后兼容），显式无数据返回 None。
