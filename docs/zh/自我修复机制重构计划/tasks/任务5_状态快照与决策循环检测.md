> 所属阶段：阶段三（认知层补强） ｜ 依赖：任务 4（弱，可并行） ｜ 工作量：中

> 关联缺陷：D4（裁剪）、M3 ｜ 关联既有代码：`planning/react.py`、`agent/state_manager.py`、`agent/p6/snapshot.py`

## 一、目标描述

按云枢现实（单机、无 etcd）裁剪实现设计文档的"快照回滚"与"循环检测"两项能力：

1. **决策循环检测（补 M3）**：ReAct 循环中计算"状态哈希"（上下文关键特征摘要），同一哈希重复出现 ≥3 次时注入终止信号并生成解释性摘要（对应文档恢复策略表最后一行）；
2. **轻量快照回滚（修 D4 的落地）**：每轮任务执行前将上下文快照写入本地 JSON（复用 `state_manager`/`p6_snapshot` 的存储），故障时从快照还原，实现进程内"秒级回滚"——不引入 etcd；
3. **快照治理**：快照轮转（保留最近 N 份）、大小上限、恢复点标记（`good/bad/unknown`），避免无限膨胀。

**【不易】约束**：快照仅覆盖"可序列化上下文"（任务上下文、步骤历史、token 使用），不试图快照 LLM 内部状态；回滚后必须输出"已回滚到第 N 步"的结构化日志；不改变 ReAct 循环对外结果语义。

- `LoopSignal` 含 `repeated_hash`、`occurrences`、`summary`（人类可读：重复的动作序列与参数摘要）；
- 在 `ReActLoop.run` 每轮行动前调用 `check`；检测到循环时：
  - 记录 `terminated_by_loop=True`；
  - 生成解释性摘要写入结果与日志；
  - **不直接异常退出**——返回 `ReActResult(success=False, reason="决策循环: ...")`，由上层决定降级/人工（衔接任务 7）。

### 步骤 2：轻量快照

新建 `planning/context_snapshot.py`：

- `save_snapshot(session_id, step_index, context) -> snapshot_id`：序列化任务上下文（task/context/steps 摘要/token 使用/时间戳）为 JSON，存 `data/snapshots/{session_id}/step_{index}.json`；
- `restore_snapshot(snapshot_id) -> context`：读取并还原；恢复点标记由调用方写入 `meta.json`；
- 轮转策略：每会话保留最近 20 份（配置可调），超出即删；单文件 > 256KB 时降级为"仅存摘要"（避免快照本身成为负担）；
- 复用 `agent/state_manager.py` 的读写工具与 `agent/p6/snapshot.py` 的命名规范，不重复造轮子。

### 步骤 3：接入 ReAct 循环

- 在 `ReActLoop.run` 迭代头保存快照（`config.snapshot_every_step` 默认 True；`config` 缺省时保持旧行为——默认开启但可关闭）；
- 在任务 4 的失败反思升级路径（反思超限）中：尝试从最近快照还原上下文后重试一次（`restore_retry`，默认开启）；还原失败则继续走降级路径；
- 快照保存失败不阻断主循环（吞异常 + 单次告警）。

### 步骤 4：快照 API 与观测

- 提供 `list_snapshots(session_id)` 与 `purge_snapshots(session_id, keep=N)` 供运维与测试；
- 快照事件写结构化日志：`module_name: context_snapshot, action: saved/restored/purged, step_index, size_bytes, duration_ms`。

### 步骤 5：测试

- 单元测试：状态哈希对相同动作序列稳定、对参数值变化敏感；`check` 达到阈值返回 LoopSignal；
- 单元测试：快照保存/还原 round-trip 一致；轮转删除旧快照；大上下文降级摘要模式；
- 集成测试：mock 循环动作序列触发终止；快照还原后上下文可继续驱动下一轮。
