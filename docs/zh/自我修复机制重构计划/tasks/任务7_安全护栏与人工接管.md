# 任务 7：安全护栏与人工接管（沙箱策略 + 升级告警 + 人工接管队列）

> 所属阶段：阶段四（进化与运营） ｜ 依赖：任务 2（弱，可并行） ｜ 工作量：中
> 对应设计文档章节：第五层「安全护栏与人工兜底」+ 沙箱执行技术选型
> 关联缺陷：M5、D1（沙箱部分裁剪） ｜ 关联既有代码：`agent/subagent/sandbox.py`、`agent/permission_system.py`、`agent/monitoring/alert_manager.py`、`agent/human_in_the_loop/hitl.py`

---

## 一、目标描述

补齐自愈体系的安全兜底与人工协作边界：

1. **沙箱执行策略落地（裁剪 D1/Docker 方案）**：云枢不引入 Docker 容器集群，将 `subagent/sandbox.py` 从"权限声明骨架"升级为**进程级执行隔离**——默认拒绝 + 路径白名单 + 危险命令拦截 + 资源限制，为"代码/脚本执行类工具"提供真实约束；
2. **升级告警（补 M5 前段）**：自动恢复失败（含任务 2 的验证失败、任务 5 的循环终止、任务 6 的 deprecated 事件）时，告警自动升级（P1→P0）并通知；
3. **人工接管队列（补 M5 后段）**：为升级告警建立"人工接管队列"状态机：`open → assigned → resolved`，支持查询与闭环；高风险动作复用 `hitl.py` 的审批流；
4. **危险操作防线核对**：自愈动作（清理缓存/重启）与 `permission_system` 黑名单交叉校验，双保险。

**【不易】约束**：不新增 Docker/Wasm 依赖（守【简易】）；沙箱默认拒绝语义不变；人工接管不自动"批准"任何高危动作——仅记录、通知、等待处置。

---

## 二、执行步骤

### 步骤 1：沙箱执行隔离升级

修改 `agent/subagent/sandbox.py`（或新建 `agent/subagent/sandbox_runner.py`）：

- 在 `check_permission`/`check_path` 之上增加**执行校验**接口：
  - `validate_command(cmd: str) -> CommandVerdict`：危险命令识别（复用 `permission_system` 黑名单正则 + 补充 `rm -rf /`、格式化、注册表写等），拒绝时返回 `{allowed: False, reason}`；
  - `validate_network(url, method)`：默认拒绝外网写操作，白名单域名放行；
  - 资源限制：`resource_limits(timeout_s=30, max_memory_mb=256)` 由调用方传入，执行器强制；
- 执行器（`run_sandboxed(cmd, limits, allowed_paths)`）：子进程 + 超时 kill + 输出截断（默认 64KB），不引入容器；
- 与 `subagent/container.py`/`lifecycle.py` 对齐：分身工具调用统一走沙箱校验再放行。

### 步骤 2：升级告警

修改 `agent/monitoring/alert_manager.py`：

- 新增 `escalate(alert, to_level)`：P1→P0 升级，触发 notifier 通知（复用既有通知渠道）；
- 升级触发源接线：
  - 任务 2：`verify_heal` 连续 2 次失败 → 升级；
  - 任务 5：`loop_terminated` → 升级；
  - 任务 6：策略 deprecated 事件 → P2 通知（不升级，仅记录）；
- 升级事件写结构化日志：`module_name: alert_manager, action: alert_escalated, alert, from_level, to_level`。

### 步骤 3：人工接管队列

新建 `agent/human_in_the_loop/takeover_queue.py`：

```python
class TakeoverStatus(str, Enum):
    OPEN = "open"            # 待接管
    ASSIGNED = "assigned"    # 已指派处置人
    RESOLVED = "resolved"    # 已解决
    TIMED_OUT = "timed_out"  # 超时未处置（二次升级）
```

- `create_takeover(alert, reason, evidence)` → 入队 + 通知；
- `assign(takeover_id, owner)` / `resolve(takeover_id, resolution)`；
- 超时策略：OPEN 超过 `takeover_timeout`（默认 30 分钟）自动转 TIMED_OUT 并二次通知；
- 查询：`list_takeovers(status=None)` 供运维与 web 界面；
- 与 `hitl.py` 既有审批流的关系：接管 ≠ 审批；高危动作仍需 `hitl` 单独审批，接管队列只负责"有人看"。

### 步骤 4：自愈动作安全双保险

- `self_healer.execute_action` 的 `restart_service`/`clear_cache`/`clear_memory` 动作执行前，调用 `permission_system` 的危险操作校验；命中黑名单直接 `SKIPPED("危险操作拦截")`；
- 校验结果写入自愈记录 `security_blocked` 字段。

### 步骤 5：测试

- 单元测试：`validate_command` 对 `rm -rf`/`DROP TABLE`/`os.system` 拒绝；`run_sandboxed` 超时 kill 且输出截断；外网写操作默认拒绝；
- 单元测试：接管队列状态机流转（open→assigned→resolved / open→timed_out）；
- 集成测试：verify_heal 失败 2 次 → 告警升级 → 创建接管条目 → 人工 resolve 的完整链路；
- 回归测试：既有 subagent/permission/hitl 测试零回归。
