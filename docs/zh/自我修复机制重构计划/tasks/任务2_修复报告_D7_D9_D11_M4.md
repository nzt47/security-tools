## 二、D7 验证真实化 — 已修复 ✅

**问题**：`verify_heal` 依赖无参 `assess()`（默认满分 1.0），健康分永远"合格"，自愈闭环"执行→验证"名存实亡。

**修复**（[self_healer.py](../../../../agent/monitoring/self_healer.py) `verify_heal` / `verify_action`）：
1. `verify_action(action)` 按动作分发专属验证器（restart_service→端口可连、clear_cache→目录大小下降、recover_circuit_breaker→状态非 OPEN、gc/clear_memory→RSS 下降）；
2. 健康分改读 `health_assessor.get_history(1)` 最新持久化评分，`None`/空 history 视为"无数据"直接验证失败（禁假满分）；
3. `overall >= 0.7`（`_verify_score_threshold`）才通过；轮询超时走 `_verify_timeout` 配置。

**验证证据**：
- `TestVerifyHeal::test_verify_health_none_fails`（健康分 None → False）✅
- `TestVerifyHeal::test_verify_low_health_timeout`（0.3 < 0.7 → False）✅
- `TestVerifyHeal::test_verify_action_fails_returns_false`（动作验证失败优先拦截）✅
- `TestVerifyAction` 13 个验证器分支用例全过 ✅

**新增排查日志**：`verify_action.dispatch` / `verify_action.result` / `verify_health.read` / `verify_health.no_data` / `heal_verified` / `heal_verify_timeout`。

## 三、D9 动作补全 — 已修复 ✅

**问题**：
- `restart_service` Windows 分支直接 `Restart-Service 'yunshu'`（大概率无此服务）→ 假 SUCCESS；
- `restart_component`（进程内模块热重启）动作缺失。

**修复**（`_restart_service` / 新增 `_restart_component`）：
1. Windows：context 未传 `restart_command` → `SKIPPED("未提供可执行的重启方式")`，不再假成功；
2. `restart_command` 执行后必须经 `verify_action("restart_service")` 确认端口恢复，未验证 → `FAILED` 并携带退出码/端口证据；
3. Linux：探测 systemctl/service，同样以验证结果为准；
4. 新增 `restart_component`：`importlib.import_module` + `reload` 进程内热重启，失败 → `FAILED` 带错误信息。

**验证证据**：
- `test_windows_no_restart_command_skipped`（Windows 无命令 → SKIPPED）✅
- `test_windows_restart_command_failure`（退出码非 0 → FAILED 带证据）✅
- `test_windows_restart_command_unverified`（执行成功但端口未恢复 → FAILED）✅
- `test_windows_restart_command_verified`（端口恢复 → SUCCESS verified=True）✅
- `TestRestartComponent` 4 个用例全过 ✅

**新增排查日志**：`restart_service.run_command` / `.command_ok` / `.command_failed` / `.command_error` / `.no_command_windows` / `.linux_ok` / `.linux_probe_failed` / `.no_tool_found` / `.verified` / `.unverified`。
