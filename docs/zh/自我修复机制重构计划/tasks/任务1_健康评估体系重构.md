# 任务 1：健康评估体系重构（五层探针 + 评分真实化 + 持久化）

> 所属阶段：阶段一（地基） ｜ 依赖：无 ｜ 工作量：高
> 对应设计文档章节：第一层「故障检测与诊断」（五级健康探针 L1-L5）
> 关联缺陷：D2、D3、M1 ｜ 关联既有代码：`agent/health/assessor.py`、`agent/health/dashboard.py`、`agent/monitoring/metrics.py`

---

## 一、目标描述

将云枢现有的"形同虚设"的健康评估升级为**真实数据驱动的五层探针体系**：

1. **修复硬伤**：`HealthAssessor.assess()` 无指标时返回默认满分 1.0 的问题——无数据必须报"未知/降权"，禁止假装健康；
2. **建立五层探针**（按云枢实际分层，而非照搬通用五层）：L1 进程资源 → L2 依赖服务 → L3 LLM/工具链路 → L4 业务接口 → L5 语义质量；
3. **评分持久化**：健康历史写入本地存储，支持趋势查询与故障复盘（补 M1）；
4. **Dashboard 可视化**：将真实评分与探针明细接入 `agent/health/dashboard.py` 与 web 界面。

**【不易】约束**：不改变 `HealthScore` 的公开字段名（`overall`/`dimensions`/`issues`）；`assess()` 签名向后兼容（`metrics` 仍为可选参数）。

---

## 二、执行步骤

### 步骤 1：定义五层探针模型

新建 `agent/health/probes.py`：

```python
class ProbeLayer(str, Enum):
    L1_PROCESS = "l1_process"        # 进程资源：CPU/内存/磁盘/线程数
    L2_DEPENDENCY = "l2_dependency"  # 依赖服务：数据库/缓存/配置文件可读
    L3_LLM_TOOL = "l3_llm_tool"      # LLM 调用 + 工具链路：延迟/错误率/熔断状态
    L4_BUSINESS = "l4_business"      # 业务接口：最近请求成功率/响应时间
    L5_SEMANTIC = "l5_semantic"      # 语义质量：Critic 评分/用户负面反馈率
```

- 每层实现一个探针函数 `probe() -> ProbeResult`，`ProbeResult` 含 `layer`、`score(0-1)`、`detail`、`available(是否采集到真实数据)`；
- L1 用 psutil 采集（云枢 `sensor/` 已有同类能力，可直接复用其读取逻辑）；
- L2 检查核心配置文件（`configs/app.yaml` 等）可读性 + 可选 DB 心跳；
- L3 读取 `circuit_breaker` 状态 + `metrics.py` 中 LLM/工具调用的延迟与错误率；
- L4 读取最近业务请求窗口（复用 `agent/monitoring/metrics.py` 已有计数器）；
- L5 读取 Critic 评估历史与 `agent/feedback.py` 用户反馈统计。

### 步骤 2：重构 HealthAssessor 评分逻辑

修改 `agent/health/assessor.py`：

- 新增 `assess_with_probes(probes: dict[str, ProbeResult]) -> HealthScore`：按层加权汇总（权重从配置读，缺省 L1=0.25/L2=0.2/L3=0.25/L4=0.2/L5=0.1），**权重 = 业务重要性，不由故障频率动态调整**（规避 D3）；
- `assess(metrics=None)` 保留但行为修正：`metrics=None` 时返回 `overall=None + issues=["无数据"]`，并将维度分数置为 `None` 而非 1.0；
- 任一探针 `available=False` 时，该层不参与平均（按其余层重新归一化），并在 `issues` 中注明"Lx 无数据"；
- `HealthScore` 增加 `probe_details` 与 `overall` 为 `Optional[float]` 的兼容字段（不破坏旧调用方）。

### 步骤 3：评分持久化

- 新建 `agent/health/storage.py`：JSONL 追加写 + 按日滚动（`data/health/history.jsonl`），单条含 timestamp/overall/各层分/probe_details；
- 提供 `query_history(start, end, layer=None)` 供 Dashboard 与任务 6 复用；
- 写入失败不得影响主流程（降级为内存记录并告警一次）。

### 步骤 4：接入监控循环

- 在 `agent/monitoring/self_healer.py` 或新建 `agent/health/collector.py` 中增加后台采集线程（间隔可配，默认 60s），调用五层探针 → 评分 → 落盘；
- **关键**：`self_healer.verify_heal()` 的验证数据源改为读本任务产出的最新持久化评分（由任务 2 完成接线，本任务只需保证"无参 assess() 不再返回满分"）。

### 步骤 5：Dashboard 接入

- 扩展 `agent/health/dashboard.py`：增加 `get_probe_overview()`（五层实时分数）与 `get_trend(days=7)`（历史趋势）；
- 若 web 前端（`app_server.py` 的 health 相关路由 / `yunshu-ui`）已有健康页，补充探针明细与趋势图数据字段。

### 步骤 6：测试

- 单元测试：无指标时 assess() 不返回满分；探针 available=False 时归一化正确；持久化读写与滚动正确；
- 契约测试：`HealthScore` 公开字段兼容性（旧调用方 `overall`/`dimensions`/`issues` 不破）；
- 集成测试：mock 探针注入后 `assess_with_probes` 输出符合加权预期。
