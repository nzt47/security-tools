## 七、性能与成本

- 状态哈希：sha1 前 16 位 + 参数/上下文截断，单次 O(上下文大小)，窗口为定长 deque——每轮额外开销微秒级；
- 快照：仅每轮迭代头一次 JSON 序列化（>256KB 自动降级摘要），旁路观测不阻塞主循环；
- 还原重试：仅反思超限且 `restore_retry=True` 时触发一次（`_restore_attempted` 硬约束），不会放大成本。

## 八、已知问题与后续

1. **快照存储为单机 JSON**（`data/snapshots/{session_id}/step_{N}.json`）——设计文档的 etcd 多副本留白，符合云枢单机现实（任务文档明确裁剪）；
2. **还原与循环检测交互**：C12 场景（还原重试轮状态重复 → 仍触发 loop_detected）由单元层覆盖，未做集成断言（`continue` 跳过当轮检测属既有语义）；
3. **`snapshot_root` 动态化**：当前构造期固定、save/restore 单一来源（`self._snapshot_root`）——若未来 per-session 动态 root，须收敛为单一解析函数，防"save/restore 路径不一致"重演（本报告 Bug 2 教训）；
4. **待衔接**：循环终止与还原失败的"转人工"升级路径，属任务 7 范围（本任务仅保证不阻断、语义清晰）。
