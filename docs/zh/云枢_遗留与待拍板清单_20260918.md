1. **`data/tools_config.json` / `data/system_prompt_config.json` 未提交**（工作区里它们显示为 modified）：
   它们是**运行期状态**（工具开关 / 最后应用时间戳），写入方只有 `plugins/skills.py`（UI 触发），
   **没有任何测试会写它们**。本仓约定也是"运行期漂移不入库"（pre-commit 钩子会主动还原
   `data/learned_workflows.json` 的统计漂移，同款处理）。**故刻意不提交。**
   当前值：4 个工具开关全为 `true`（`get_status`/`get_sensor_summary`/`get_preferences`/`get_persona_info`）——
   若这不是你的预期，去「设置/工具」页改回去即可。
2. **`/legacy` 老 UI 保留**（你说是"做个纪念"）：它仍在服务 `templates/index.html`，
   其 `static/js/sidebar/memory.js` 调用的 8 条端点本次已全部补齐（原来 404）。
   若哪天要退役：删 `/legacy` 路由 + `templates/index.html` + `static/js/**`，**别只删端点**（否则页面按钮点了没反应）。
3. **`barrier.py::ContextBoundaryError` 刻意保留**：实测 0 引用，但它是该模块公开声明的异常类型；
   我在脚本清理它时正则过贪，把紧随其后的 `_BACKOFF_BASE_SECONDS` 等三个常量一并删掉（49 条测试当场失败），
   已从 git 还原 ⇒ 一个 3 行的公开异常不值得再冒一次误删风险。
4. **伦理规则是"升级为需审批"而非硬拒**：`EthicsEngine` 的 6 条规则是**子串匹配**
   （`grep "shutdown" logs/` 也会命中 E003），硬拒会把误报变成"工作卡死"。
   若将来要把某几条（如含 `rm -rf /` 的 E001）做成**不可覆盖的硬拒**：改
   `agent/tool_gate.py::_ethics_boundary` 一处即可，调用方不动。
5. **审批边界在测试里默认关闭**（`tests/conftest.py` 会话级 `CP_TOOL_GATE_APPROVAL_ENFORCE=0`）：
   大量单测用"无 YAML 探针工具"验证工具机制，基线开着会被治理网拦下。
   边界/兜底行为由 `test_tool_gate.py`、`test_tool_gate_fallback.py`、`test_tool_approval*.py` **显式开启**。
   **新写"探针工具"测试时不用再手动关边界。**
