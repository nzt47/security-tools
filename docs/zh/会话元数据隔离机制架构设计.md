# 会话元数据隔离机制 — 架构设计

> 版本：v2.1（2026-07-31）
> 状态：已实施并通过高并发验证（凭证见 [audit-evidence/README.md](audit-evidence/README.md)）
> 关联能力：用户时区/设备/语言环境驱动的说话风格与临场感调整（Agent 记忆系统"会话元数据"层）
>
> 变更记录：
> - v1.0：显式传参解耦（chat → process → _call_llm_v2 → _get_user_context），移除路由层全局赋值
> - v2.0：SessionManager `_current_id` 全访问点加锁、DST 状态 key 显式化、三层日志埋点、兜底校验
> - v2.1：SessionManager 读方法加锁（get_messages / get_message_count / get_session_metadata），消除读-写竞态

## 1. 背景与问题

### 1.1 功能需求

云枢通过会话元数据（时区、设备类型、语言环境）调整说话风格与临场感。调用链：

```
HTTP 请求头 → _extract_session_meta → SessionManager 持久化
→ Orchestrator._get_user_context() → PersonaInjector 注入系统提示词
```

### 1.2 缺陷：全局状态覆盖竞态

修复前，路由层在每次对话前对全局单例 `Yunshu` 实例赋值：

```python
Yunshu._session_id = session_id      # routes_chat.py（修复前）
Yunshu._session_mgr = session_mgr    # 跨请求共享的可变全局状态
```

Flask 多线程处理并发请求时，用户 A 的赋值会被用户 B 覆盖，导致 `_get_user_context()` 读到"最后写入者"的会话元数据——**用户上下文互相串扰**。

**实测复现**（8 用户 × 300 迭代）：2400 次读取中 2050 次读到他人上下文，**误配率 85.42%**。

## 2. 设计目标

| 目标 | 说明 |
|------|------|
| 根治竞态 | 会话上下文不再经由跨线程共享的实例属性传递 |
| 向后兼容 | CLI / 语音 / 脚本等未接入 SessionManager 的调用方不受影响 |
| 最小侵入 | 不动 `_session_id` 的既有语义（get_dialog_state 状态 key 等） |
| 可观测 | 来源判定（显式/回退）与生成结果均有结构化日志 |

## 3. 核心设计：显式传参解耦

### 3.1 原则

**会话上下文只走调用参数传递，永不写入全局实例属性。** 路由层不再承担"同步全局状态"职责，改为把上下文沿调用链显式下传。

### 3.2 调用链（修复后）

```
routes_chat.py / app_server.py
  └─ Yunshu.chat(user_input, session_id=sess_xxx, session_mgr=sm)
       └─ process(user_input, session_id=..., session_mgr=...)   # kwargs 透传
            └─ _call_llm_v2(user_input, body_status,
                            session_id=..., session_mgr=...)
                 └─ _get_user_context(session_id=..., session_mgr=...)
                      └─ SessionManager.get_session_metadata(session_id)
                      └─ PersonaInjector.build_system_prompt(user_context=...)
```

### 3.3 接口签名

```python
# Orchestrator（chat 为对外唯一入口）
def chat(self, user_input: str, *,
         session_id: Optional[str] = None,
         session_mgr=None) -> str

# 内部
def _call_llm_v2(self, user_input: str, body_status: str, *,
                 session_id: Optional[str] = None,
                 session_mgr=None) -> str

def _get_user_context(self, session_id: Optional[str] = None,
                      session_mgr=None) -> Optional[str]
```

### 3.4 来源判定与回退策略

`_get_user_context` 采用**显式参数优先，未传才回退实例属性**（见 [orchestrator.py](../../agent/orchestrator/orchestrator.py)）：

```
session_mgr 来源：显式参数 → 实例回退(getattr self._session_mgr) → 无则跳过注入
session_id   来源：显式参数 → 实例回退(getattr self._session_id)  → 无则跳过注入
```

回退路径保留是为了兼容 CLI（`main.py`）、语音/视觉通道（`voice_vision.py`）等无 Web 会话上下文的调用方。这些场景下实例属性在 DigitalLife 构造时初始化一次、此后不被写入，**单会话场景下回退路径同样无竞态**。

### 3.5 降级策略

| 场景 | 行为 |
|------|------|
| 无 session_mgr | 返回 None，不注入（对话链路不受影响） |
| 会话不存在 | 返回 None，优雅降级 |
| 元数据字段为空 | 返回 None |
| 元数据读取异常 | 捕获异常返回 None，仅 debug 日志 |

## 4. 并发安全分析

### 4.1 为什么根治

- **共享可变状态消除**：路由层删除 `Yunshu._session_id = ...` / `Yunshu._session_mgr = ...` 两行写入。经全库扫描，活跃代码中 `_session_id` 仅在 DigitalLife 构造时初始化（lifecycle_manager / v2_performance_patch），此后无任何运行时写入。
- **上下文线程私有**：每个请求的 `session_id`/`session_mgr` 是栈上局部变量，随调用链传递，线程间零共享。
- **实例属性只读**：回退路径的 `getattr(self, '_session_id')` 读到的值恒定（构造时确定），无并发写即无竞态。

### 4.2 验证

16 并发用户 × 500 迭代（8000 次上下文读取）：误配率 0.0%（修复前 85.42%）。凭证见 [audit-evidence](audit-evidence/README.md)。

## 5.1 v2.0 增量设计（会话状态隔离加固）

### 5.1.1 SessionManager `_current_id` 加锁

`_current_id`（UI"当前选中会话"）是 SessionManager 实例级可变状态，此前 `set_current`/`get_current_id` 为无锁裸读写。v2.0 全访问点加锁：

| 方法 | 锁 |
|------|-----|
| `create_session`（赋值移入索引写入块） | ✅ |
| `set_current` | ✅（存在性校验在锁外，避免非重入锁嵌套死锁） |
| `get_current` / `get_current_id` | ✅ |
| `delete_session` | ✅ |
| `get_messages` / `get_message_count` | ✅（v2.1 读锁，与写锁互斥） |
| `get_session_metadata` | ✅（v2.1：文件读取锁内、`get_session` 合并移出锁外，避免死锁） |

**关键教训**：`threading.Lock` 非重入，锁内调用 `get_session`（其内部再次取锁）会导致死锁（Timeout）。校验类操作须移出锁外。

### 5.1.5 已知边界（不纳入本次修复）

- **`_CHAT_HISTORY`**（app_server.py，L322 注释"向后兼容缓存"）：旧版 `/api/chat` 端点的 UI 历史展示缓存，单用户 UI 语义，不在会话元数据链路内。多用户并发时历史展示可能互相污染，建议前端完全迁移到新版路由后移除，**不做增量改造**（避免扩大风险面）。
- **启动期单例**（`_api_gateway`/`_global_executor`/`_global_ab_test_manager`/`_global_auto_tuner`/etcd watcher）：懒加载后只读，非每请求写入，符合单例模式，无会话竞态。

### 5.1.2 `_current_id` 边界声明

- **Web 前端始终显式传 session_id**（localStorage 持久化 + `?session=` query 参数，见 [sse.ts](../../yunshu-ui/src/lib/sse.ts) 的 `createChatStream`）。
- `_current_id` 仅承担 UI"选中会话"展示语义，**不参与对话链路的会话归属与元数据注入决策**。
- 无显式 session 的兜底路径（`_get_current_session_id`）增加 `get_session` 存在性校验，避免读到脏值。

### 5.1.3 DST 状态 key 显式化

`get_dialog_state(_sid)`：对话状态（DST）key 从固定"启动时间戳"改为**真实会话 ID**（sess_*），多会话 DST 相互隔离，指代消解不再跨会话污染。CLI 无显式会话时回退实例时间戳，行为不变。

### 5.1.4 三层日志埋点

| 埋点 | action | 用途 |
|------|--------|------|
| chat 入口 | `orchestrator.chat.session_ctx` | 记录收到的 session_id / session_mgr 是否传入 |
| process 入口 | `orchestrator.process.session_ctx` | 记录 `_sid` 来源判定（显式参数/实例回退） |
| 元数据读取 | `orchestrator.user_context.source/generated/skip/empty` | 来源判定 + 生成结果/跳过原因 |

## 6. 后续演进建议

1. **请求级上下文（可选强化）**：若未来引入 gunicorn 多 worker 或 async 协程，可在路由层用 `threading.local` / contextvars 承载 `session_id`，进一步消除"回退路径依赖实例属性"的隐式约定。
2. **元数据索引同步**：`update_session_metadata` 目前不同步 `sessions.json` 索引（仅 meta.json），列表页如需展示元数据需补充同步逻辑。
3. **缓存**：高频场景可对 `get_session_metadata` 增加 TTL 缓存（当前每次对话一次文件 IO，属可接受范围）。
