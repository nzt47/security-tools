# Windows 并行测试编码隔离最佳实践

> 归档日期：2026-08-15
> 适用范围：Windows（GBK 默认 ANSI 代码页）+ pytest 并行分块 + 跨进程共享文件
> 关联结案报告：[测试结案报告_后台重跑_20260815.md](测试结案报告_后台重跑_20260815.md)

## 1. 背景与根因

全量测试后台重跑（4 chunk 并行，`ProcessPoolExecutor`）时，chunk_0 首个失败测试的 teardown 抛出：

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xcd in position 133
```

**根因链**（一次完整的「GBK 写 / UTF-8 读」错配）：

1. Python 3 在 Windows 上，`open()` 未显式指定 `encoding` 时**默认使用 ANSI 代码页（中文系统 = GBK/cp936）**；
2. 并行 chunk A 的某进程用 GBK 写入共享文件（含中文/emoji）；
3. 并行 chunk B 的进程以 UTF-8 读取同一文件（`PYTHONIOENCODING=utf-8` 下 stdio 为 UTF-8），GBK 字节 `0xcd` 无法解码 → `UnicodeDecodeError`；
4. 该异常发生在 teardown 阶段 → 单个失败**级联污染**同一 chunk 后续所有测试（1617 errors / 14 failed 均由此类环境污染导致，单独运行全部通过）。

**要点**：这不是代码缺陷，而是**并行环境 + 默认编码陷阱**的组合。单进程运行不会暴露。

## 2. 三道防线（缺一不可）

### 防线 1：进程级 stdio 强制 UTF-8

在入口脚本顶层（`subprocess` 子进程可继承）设置：

```python
import os
os.environ.setdefault("PYTHONIOENCODING", "utf-8")
```

参考实现：`scripts/run_full_pytest.py`（顶层）+ `scripts/run_full_pytest_bg.py`。

注意：不要在 `conftest.py` 里 reconfig `sys.stdout/stderr`，会与 pytest 的 capture 模块冲突（已在 `tests/conftest.py` 注释中说明）。

### 防线 2：所有文本模式 open() 显式 encoding="utf-8"【本次加固】

**规则**：凡是写**文本**内容的 `open()`（模式 `w/a/x/w+/a+/x+` 及其 `t` 变体），一律显式 `encoding="utf-8"`；对应读同一文件的 `open()` 也要显式 `utf-8`，保证读写对称。

```python
# ❌ 错误：Windows 上默认 GBK，写入方与读取方一旦不一致即崩溃
with open(cfg_file, "w") as f:
    json.dump(config, f, indent=2)

# ✅ 正确：读写两侧均显式 UTF-8
with open(cfg_file, "w", encoding="utf-8") as f:
    json.dump(config, f, indent=2)
...
with open(cfg_file, "r", encoding="utf-8") as f:
    cfg = json.load(f)
```

本次已加固 **71 处文本写调用**（15 个文件）+ `scripts/setup_llm.py` 3 处对称读，覆盖：

| 类别 | 文件 | 说明 |
|---|---|---|
| 业务代码 | `agent/tools/workspace_tools.py` | `.gitkeep` 中文注释写 |
| 业务代码 | `agent/extensions/security_checker.py`、`security_check_skill.py` | 临时技能文件写 |
| 业务代码 | `scripts/setup_llm.py` | `llm_config.json` 写 + 读对称 |
| 测试 | `tests/unit/test_system_tools_core.py` 等 11 个测试文件 | 中文/JSON 内容临时文件写 |

**例外（不要加，加了反而错）**：

- `open(path, "w")` 目标是 **cmd.exe 解析的 .bat**（如 `scripts/setup_llm.py` 生成的启动脚本）：cmd 按 ANSI/GBK 解析，强制 UTF-8 会乱码中文注释；
- `/proc/...` 伪文件写（如 `agent/monitoring/self_healer.py` 的 `drop_caches`）：无文本编码语义，内容为 ASCII 数字。

**判定技巧**：判断标准是「**目标消费者以什么编码读**」。Python 读 → 必须 UTF-8；cmd/旧系统工具读 → 保持 ANSI。

### 防线 3：共享写路径隔离

即使编码统一，并行进程**共享同一物理文件**仍是竞态源：

1. 测试临时文件一律走 `tempfile.TemporaryDirectory()` / `pytest tmp_path`（进程唯一），禁止写固定路径的共享输出文件；
2. 业务代码写共享配置文件时，写入与读取须在同一编码契约内（见防线 2）；
3. 并行分块之间不得依赖彼此的 teardown 结果（级联污染根因之一）。

## 3. 并行分块运行规范

- 入口统一走 `scripts/run_full_pytest_bg.py`，分块数默认 4，出现原生崩溃（0xC0000005）时降为 2（psutil 原生访问冲突，与编码无关但同属并行负载问题）；
- 汇总行解析用 `parse_summary`（字段顺序无关正则，勿改回顺序敏感写法）；
- 模型加载类测试（transformers `from_pretrained` 等）打 `slow` 标记单独跑，避免在全量并行中超时挂起 chunk。

## 4. 排查手段

| 场景 | 手段 |
|---|---|
| 定位未加固的文本写 open | AST 扫描：找 `open(...)` 且 mode 为文本写且无 `encoding=` 的调用（参考 `scripts/dev/codemod_add_encoding_tmp.py`，已删除的临时脚本同思路） |
| 定位 0xcd 等 GBK 字节文件 | 扫描文件字节流中 `0xcd` 等 GBK 独有字节，结合位置 133 缩小范围 |
| 判断是否环境问题 | 将失败用例**单独运行**；单独全绿 = 并行环境污染（本案 125 例单独运行全绿的判据） |

## 5. 第二轮全量扫描结论（2026-08-15）

覆盖 1655 个源文件（agent/scripts/tests/memory/utils 等 13 目录），按类别扫描 open 读写 / Path 方法 / 序列化 / 日志 Handler / subprocess / tempfile 六类。

**已修复（真实隐患）**：

| 位置 | 问题 | 修复 |
|---|---|---|
| `agent/model_router/cost_tracker.py:69` | 写侧 utf-8 + `ensure_ascii=False`（可能含中文），读侧默认 GBK → 0xcd 同型错配 | 读侧补 `encoding="utf-8"` |
| `tests/unit/test_system_tools_core.py:2245/5496` | 读/写侧未显式编码（5496 为 codemod 漏网） | 补 `encoding="utf-8"` |
| `sensor/test_body_sensor.py:217/222` | sensor/ 目录不在首轮 codemod 范围 | 补 `encoding="utf-8"` |
| `scripts/setup_llm.py:324` | 首轮提交时被 pre-commit 挂起强杀回滚丢失 | 重新补回 |

**系统性模式（建议后续统一治理，勿逐个硬改）**：

- **subprocess 文本模式（161 处）**：`subprocess.run(..., text=True / universal_newlines=True)` 未传 `encoding` 时，Windows 上用 GBK 解码子进程输出；子进程若输出 UTF-8 非 ASCII（中文文件名、emoji 日志）→ `UnicodeDecodeError`。推荐统一写法：
  ```python
  subprocess.run(cmd, capture_output=True, text=True,
                 encoding="utf-8", errors="replace")
  ```
  本项目测试链路入口（`run_full_pytest.py` / `run_full_pytest_bg.py`）已满足此规范，脚本类工具未强制（多为 ASCII 输出，条件触发）。

**低风险（刻意不动）**：

- `open()` 默认读系统/外部 ASCII 文件：`diagnose.py`、`release_checklist.py`、`sensor/board_sensor.py`（sysfs）、`behavior_sensor.py`（/etc/hosts）；
- 测试中 `Path.write_text/read_text`（63 处，全 ASCII 内容，GBK/UTF-8 字节一致）；
- 混沌测试 `test_disk_io_chaos.py` 读损坏二进制文件为文本（刻意验证解码行为）。
