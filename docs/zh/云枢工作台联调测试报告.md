## 3. SSE 流式链路验证（断流/乱序日志体系）

### 3.1 日志体系

**传输层**（[src/lib/sse.ts](../../yunshu-ui/src/lib/sse.ts)，console.debug）：

| 日志 | 关键字段 | 用途 |
|---|---|---|
| `请求发出` | url、ts | 建连起点 |
| `连接建立` | httpStatus、connectMs | 排查"建连慢"（实测 25-40ms） |
| `流结束` | bytesReceived、durationMs | 传输层字节对账（`finally` 保证中断路径必达） |

**业务层**（[src/stores/useLayoutStore.ts](../../yunshu-ui/src/stores/useLayoutStore.ts) 事件 + [src/components/workbench/panels/ChatPanel.tsx](../../yunshu-ui/src/components/workbench/panels/ChatPanel.tsx) 打印）：

| kind | 检测逻辑 | 级别 |
|---|---|---|
| send / thinking / chunk | 逐片打印 seq、len、accumulated、gapMs | debug |
| chunk 断流检测 | `gapMs > 3000` → `⚠ 疑似断流` | warn |
| chunk 乱序检测 | `seq <= lastSeq` → 乱序/重复；`seq` 跳变 → 疑似丢包 | warn |
| done | chunks、totalChars、durationMs、rateCharsPerSec | info |
| error / abort | `❌ 流式错误` / `⏹ 用户中止` | error / warn |

## 4. 双标签页联调（mock Electron 独立窗口同步）

命令：`$env:VITE_MOCK_ELECTRON="1"; npm run dev`，打开主标签页 + 点击"独立窗口"弹出 `#/detached/chat`。

机制（[src/electron/mockElectron.ts](../../yunshu-ui/src/electron/mockElectron.ts)）：BroadcastChannel 模拟主进程事件总线、localStorage 暂存分离快照、`window.open` 模拟建窗；同步逻辑复用真实 [sync.ts](../../yunshu-ui/src/electron/sync.ts)（150ms 节流全量快照 + JSON 对比防回环）。

| 验证项 | 结果 |
|---|---|
| mock 生效（"桌面模式"胶囊） | ✅ |
| "独立窗口"按钮弹出新标签页 | ✅ |
| A→B 同步（消息 + 流式回复） | ✅ |
| B→A 同步 | ✅ |
| 防回环（双向广播无死循环） | ✅ |
| 业务 error / ⚠ / ❌ | 0 |

观察项（非阻断）：
- detach 为"移出"语义：对话面板从主窗口移除，需"重置布局"恢复。
- B 中 A 发起消息的"意图识别"可能停在"进行中"（thinking 事件 running 快照被广播），不影响消息/回复同步。

### 4.1 复测（2026-08-16，修复回归）

| 验证项 | 结果 |
|---|---|
| mock 生效（"桌面模式"胶囊） | ✅ |
| A→B 同步（消息 + 流式回复，SSE 4005ms） | ✅ |
| B→A 同步（SSE 4034ms） | ✅ |
| 防回环（双向各渲染 1 份，无重复无死循环） | ✅ |
| 控制台 ⚠/❌ | 0（两条流完整渲染，未触发任何告警条件） |

**修复 1：重复开窗（重要）**
- 现象：点击一次"独立窗口"打开 2 个相同 `#/detached/chat` 标签页。
- 根因：[DetachButton.tsx](../../yunshu-ui/src/components/workbench/DetachButton.tsx) 内部先调用 `api.detachPanel`（开窗第 1 次），随后调用 `onDetached`（上层 WorkbenchApp 的 `detachPanel` 又调一次 `api.detachPanel`，开窗第 2 次）→ IPC 双重调用。
- 修复：DetachButton 不再内部调用 IPC，仅回调 `onDetached`，由上层统一执行 IPC 建窗 + 布局摘除。
- 回归：修复后单次点击恰好打开 1 个标签页 ✅

**修复 2：layout=null 时摘除失效（边界）**
- 现象：未自定义布局（store 中 layout 为 null，渲染走 `DEFAULT_LAYOUT` 兜底）时 detach 后对话面板不移除。
- 根因：`detachPanel` 用 `getState().layout`（可能 null）调 `removePanelFromLayout`，null 输入直接返回 null → `setLayout(null)` 无变化。
- 修复：以实际渲染的布局树为基准 `removePanelFromLayout(layout ?? DEFAULT_LAYOUT, panelId)`（[WorkbenchApp.tsx](../../yunshu-ui/src/WorkbenchApp.tsx#L80-L83)）。
- 对照实验：布局自定义后 detach 成功，主窗口仅剩 nav|think 并持久化 ✅

### 5.1 沙盒内打包排障记录（用户本机无需此步骤）

沙盒限制逐层绕过（均不影响产物正确性，仅打包机环境问题）：

| 现象 | 根因 | 绕法 |
|---|---|---|
| 安装包收尾 EPERM | 项目目录内 rename 被沙盒禁 | `directories.output` 改 `${env.TEMP}/yunshu-release` |
| winCodeSign/electron zip 下载超时 | GitHub/Azure 被墙 | `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`、`ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/` |
| `AppData\Local\electron-builder` EPERM | NSIS 工具缓存写入被沙盒拦 | `ELECTRON_BUILDER_CACHE=<TEMP>/eb-cache`（`allowEnvVarOverride:true`） |
| `AppData\Local\electron\Cache` EPERM | @electron/get 默认缓存目录被沙盒拦 | `electronDownload.cache` 指 `${env.TEMP}/eb-cache/electron` |
| 安装包生成后 exit 1 | Windows「最近文件」目录（Recent）写入被沙盒拦 | 安装包已完整写出（98.6MB + blockmap），仅收尾动作失败，产物可用 |

恢复项（本机打包配置已还原）：`directories.output="release"`、移除 `signAndEditExecutable:false`（本机可正常签名/编辑图标，建议保留默认 `true`）。

### 5.2 体积优化（2026-08-16，已落地）

按 [Electron打包体积优化建议](Electron打包体积优化建议.md) 实施两项低风险高收益优化：

| 优化项 | 配置 | 效果 |
|---|---|---|
| 排除 node_modules 依赖树 | `build.files` 加 `"!node_modules/**"` | `app.asar` **64.9MB → 0.88MB（-98.6%）** |
| 关闭 sourcemap | `build.sourcemap: false`（原 `'hidden'`） | 3.4MB `.map` 不再产出 |
| 合计 | | 安装包 **98.6MB → 91.5MB** |

> 说明：安装包压缩比小于 asar（NSIS/LZMA 对 JS 文本压缩率高，node_modules 源码在压缩包内占比本就小）；`win-unpacked` 目录瘦身 64MB，显著减少解压后磁盘占用与首启 IO。
