## 1. 概述

本 PR 完成 Dashboard 仪表盘接口联调的**收尾工作**：真实接口切换后的配套能力（错误模拟、日志可观测、生产裁剪、测试与文档），并完成首个 SSR 兼容性加固（含回归测试）与下一迭代规划。

## 2. 功能与变更

### 2.1 Dashboard 接口联调（真实接口已生效）

| 项 | 说明 |
|---|---|
| 后端接口 | 新增 `GET /api/dashboard/summary`（`routes_dashboard_summary.py`），返回 `{code, data{stats, trend, roles}, message}`，数据为 Mock，契约稳定待接真实统计 |
| 前端切换 | `api/dashboard.ts` 封装请求 + 数据完整性校验（`validateDashboardSummary`） |
| 跨域 | 复用 Vite `/api` 代理 → `127.0.0.1:5678`，无新增配置 |

### 2.2 接口错误模拟场景（开发专用）

- devMock 参数化拦截：`?mock_error=business|empty|invalid`，无参数放行真实后端
- Header「接口场景」下拉（仅 dev）：正常数据 / 业务错误(500) / 空数据 / 畸形数据，一键切换并刷新
- 经 `import.meta.env.DEV` 静态替换，**生产构建不含此逻辑**

### 2.3 生产环境日志裁剪

- `logger.ts`：`import.meta.env.PROD` 下 debug/info 编译期 noop（esbuild 消除），warn/error 保留供生产排障
- `request.ts`：`perfEnabled` 编译期常量，`[perf]` 计时与日志分支生产零开销

### 2.4 SSR 兼容性加固

- `storage.ts` 新增 `safeGetLocalStorage`（`typeof window` 守卫，SSR 回退 null）
- `MainLayout` 渲染期读取复用该守卫，避免未来 SSR 服务端崩溃与 hydration 不一致
- 回归测试 `storage.ssr.test.ts`（3 用例）防退化

### 2.5 测试与文档

- `Dashboard.test.tsx`：数据加载链路单测（成功 / 失败 / 加载中），3 用例通过
- `docs/zh/Dashboard接口联调测试报告.md`：契约 + 实测结果 + 排查机制
- `docs/zh/SSR兼容性加固变更说明.md`：含决策项清单与边界定义

## 3. SSR 遗留问题规划（下一迭代）

详见 `docs/zh/SSR遗留问题清单_下一迭代.md`，6 项按优先级：

- **P1**：SSR-1 服务端场景还原决策、SSR-2 全仓渲染期访问审计
