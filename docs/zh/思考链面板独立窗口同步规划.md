## 2. 现状评估：think 面板与 CodeEditor 面板的链路对比

### 2.1 相同部分（detach 出窗链路，两者共用一套架构）

| 环节 | 实现位置 | think 是否已接入 |
|---|---|---|
| 面板 ID 白名单 | [ipc.ts](c:\Users\Administrator\agent\yunshu-ui\src\electron\ipc.ts#L25-L32) `DETACHABLE_PANELS.THINK` | ✅ |
| 主进程 detach 校验 | [main.ts](c:\Users\Administrator\agent\yunshu-ui\electron\main.ts) `ipcMain.handle('window:detach-panel')` 白名单校验 | ✅ |
| hash 路由分发 | [main.tsx](c:\Users\Administrator\agent\yunshu-ui\src\main.tsx#L34-L40) `#/detached/think` 白名单 | ✅ |
| 独立窗口渲染分支 | [DetachedChatApp.tsx](c:\Users\Administrator\agent\yunshu-ui\src\DetachedChatApp.tsx#L33-L45) `renderDetachedPanel` 的 `THINK` 分支 + 顶栏"云枢 · 思考过程" | ✅ |
| 面板组件 | [ThinkingPanel.tsx](c:\Users\Administrator\agent\yunshu-ui\src\components\workbench\panels\ThinkingPanel.tsx)：读 `useLayoutStore(s => s.thinking)` 渲染节点流 | ✅ |

> 面板 detach 由通用组件统一提供（DetachButton / Mosaic 拖拽边缘拦截），不因面板类型区分，故 think 面板与 chat / code 面板一样天然具备拖拽出窗能力。

### 2.2 差异部分（同步通道：think 走实时 IPC，code 走 localStorage 隐式同步）

| 维度 | 思考链（think） | 代码编辑器（code） |
|---|---|---|
| 同步通道 | **IPC 实时广播**（StateSyncPayload 全量快照） | localStorage 隐式共享（同 session 多窗口） |
| 数据特征 | 高频动态事件流（意图识别→检索→规划→工具调用，SSE 过程中实时变化） | 低频持久化文档（{lang, content}，编辑防抖写盘） |
| 广播载荷 | [ipc.ts](c:\Users\Administrator\agent\yunshu-ui\src\electron\ipc.ts#L59-L63) `StateSyncPayload.thinking` 字段 | 不占广播载荷（仅 localStorage key） |
| 时序补偿 | detach 瞬间快照 `initialSnapshot.thinking` → `GetInitialState` 拉取 | 冷启动读 localStorage（天然持久） |
| 防回环 | 主进程源过滤 + 接收端 JSON 对比 | 无需（写读模型天然无环） |

**为什么不用 localStorage 方案给 think**：思考链是**实时流**，独立窗口应在事件发生瞬间看到节点推进；若走 localStorage 写读，需新增防抖写盘逻辑且失去实时性，反而不如复用已就位的 `thinking` IPC 广播——这正是现有架构"thinking 已在全量快照中"的原因（【简易】：一次广播同时覆盖 messages + thinking，不新增通道）。

## 4. 与 CodeEditor 面板实现路径的对照结论

CodeEditor 面板此前新增的三步（组件 + 布局 + detach/同步接入）中，**thinking 面板全部已具备**：

1. **组件**：ThinkingPanel.tsx 自项目初期即存在（渲染 store.thinking）；
2. **布局**：think 一直是默认布局成员（`nav | chat | think`，v0.1.1 后为 `nav | chat | (think/code)`）；
3. **detach + 同步**：think 在 detach 白名单、hash 路由白名单、DetachedChatApp 渲染分支均已在列；`thinking` 字段自 StateSyncPayload 设计之初就在实时广播载荷内。

因此不存在"还需要实现什么"的缺口，与 CodeEditor 的差距仅在于：CodeEditor 是新增面板（从无到有），thinking 是既有面板的既有能力（无需再动）。
