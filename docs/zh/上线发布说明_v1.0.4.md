## 一、本次新增功能

### M4 系统日志与操作审计
- **前端**：操作审计页（`/system/audit`）——操作人 / 操作类型 / 关键字筛选 + 分页 + 结果与详情展示（[AuditList.tsx](file:///c:/Users/Administrator/agent/yunshu-ui/src/pages/system/AuditList.tsx)），权限码 `system:audit:view`
- **后端**：`GET /api/audit/logs` 管理后台契约（分页 + 操作人/类型/关键字筛选，`{code, data:{list,total}}`），数据持久化 `data/manager_audit.json`；同时保留 T8.4 开放 API 双轨（API Key 客户端走网关，租户隔离不变）

### M5 系统通知与消息中心
- **前端**：消息中心页（`/system/notification`）——通知列表（系统公告/审计提醒/审批任务/安全告警）+ 未读计数 + 单条/全部已读 + 分页（[NotificationCenter.tsx](file:///c:/Users/Administrator/agent/yunshu-ui/src/pages/system/NotificationCenter.tsx)），权限码 `system:notification:view`
- **后端**：`/api/notification/*` 四端点（列表/未读计数/单条已读/全部已读），种子 24 条 + 持久化 `data/manager_notifications.json`

### 关键修复
- **操作审计 401 鉴权异常**：`/api/audit/logs` 此前被网关灰度接管（只认 API Key）导致管理后台用户 token 被拒（401→前端 403）。已实现网关 `before_request` 双轨认证——用户 token 放行原生路由，API Key 客户端仍走网关（T8.4 契约不变，回归 90/90）
- **API 前缀契约**：`VITE_API_BASE` 空串回退 `/api`（`||` 替代 `??`），确保请求形如 `/api/auth/login` 与 Nginx 代理匹配

## 三、已知限制

1. **角色/菜单接口未实现**：`/api/role*`、`/api/menu*` 真实后端未提供，测试环境角色/菜单页需 `VITE_MOCK_API=true`（devMock 兜底）或后端补齐
2. **Electron 桌面版构建**：需命令行注入 `VITE_API_BASE=http://127.0.0.1:5678`（Web 模式必须留空走 `/api`，见 [.env.production](file:///c:/Users/Administrator/agent/yunshu-ui/.env.production) 注释）
3. **审计/通知持久化**：数据存于 `data/manager_audit.json` / `data/manager_notifications.json`（已 gitignore，运行时生成；删除文件即恢复种子数据）
4. **通知接口鉴权**：需登录 token（`Authorization: Bearer`），未登录返回业务 401
5. **部署文档**：见 [测试环境部署手册](file:///c:/Users/Administrator/agent/docs/zh/测试环境部署手册_feat_continue_dev.md)（方式 A/B、Nginx 配置、常见问题）
