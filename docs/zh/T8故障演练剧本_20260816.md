# 云枢 T8 架构故障演练剧本

**版本**: 2026-08-16
**演练范围**: 网关宕机恢复 · 租户数据隔离验证
**前置条件**: app_server 运行中（127.0.0.1:5678）；已执行 `scripts/deploy_t8_gateway.py`（.env 含 `FLASK_API_TOKEN` / `YUNSHU_API_KEY`）

---

## 总则

- 演练采用**真实故障注入**（停/启服务、跨租户访问），不 mock。
- 每场景输出一份演练记录（见文末），含时间轴、预期 vs 实际、RTO/RPO。
- 辅助工具：
  - 一键部署/基线：`python scripts/deploy_t8_gateway.py`
  - 401/403/429 复现：`python scripts/simulate_gateway_errors.py`
  - 日志定位：响应体 error → `/api/open/stats` → app_server 结构化日志 → `/api/audit/logs`

## 场景 A：网关宕机（Gateway Down）

### A.0 演练前基线（必做）

```powershell
# 记录基线
$r = Invoke-RestMethod http://127.0.0.1:5678/api/open/stats
"基线: echo=200 | stats.endpoints=$($r.stats.endpoints) | access_logs=$($r.stats.access_logs)"
# 正常链路自检（带 Key）
$key = (Get-Content .env | Where-Object {$_ -like 'YUNSHU_API_KEY=*'}) -split '=',2 | Select-Object -Last 1
Invoke-WebRequest -Uri "http://127.0.0.1:5678/api/audit/logs?limit=1" -Headers @{"X-API-Key"=$key} -UseBasicParsing
```

**预期**：echo 200；audit/logs 200。

### A.1 故障注入（停服务模拟宕机）

```powershell
# 终止 app_server 进程（演示环境）
Get-Process python -ErrorAction SilentlyContinue | Where-Object {$_.Id -eq <PID>} | Stop-Process -Force
```

**预期**：进程退出；端口 5678 无监听。

### A.2 故障探测与影响面判定

```powershell
# 开放 API
try { Invoke-WebRequest http://127.0.0.1:5678/api/open/echo -UseBasicParsing -TimeoutSec 3 } catch { "开放API: 连接失败（$($_.Exception.Message)）" }
# 内部 API
try { Invoke-WebRequest http://127.0.0.1:5678/api/sessions -UseBasicParsing -TimeoutSec 3 } catch { "内部API: 连接失败" }
```

**判定（影响面）**：
- 云枢为**单进程架构**：网关适配层与内部 API 同进程。宕机 = 开放 API 与内部 API **全部不可用**（全挂，非部分降级）。
- 数据安全：租户/Key 数据在 `agent/data/*.json`（磁盘持久化），宕机**不丢数据**（RPO≈0）；审计日志 Append-only 落盘 `data/audit/audit_*.jsonl`，同样不丢。
- 限流/配额状态在**内存**（TokenBucket/QuotaManager），重启后重置为满桶/配额清零（计数丢失，RPO 影响面=配额计数，可接受）。

### A.3 恢复（重启服务）

```powershell
python app_server.py   # 前台或服务托管
```

### A.4 恢复验证（判定标准）

```powershell
# 1) 探活
Invoke-WebRequest http://127.0.0.1:5678/api/open/echo -UseBasicParsing      # 期望 200
# 2) 开放端点带 Key
Invoke-WebRequest http://127.0.0.1:5678/api/audit/logs?limit=3 -Headers @{"X-API-Key"=$key} -UseBasicParsing   # 期望 200
# 3) 数据持久性：租户仍在、审计日志仍在
Invoke-RestMethod http://127.0.0.1:5678/api/open/tenants -Headers @{"X-API-Token"=$env:FLASK_API_TOKEN}
# 4) 限流桶重置（stats 全局桶余量恢复 100.0）
(Invoke-RestMethod http://127.0.0.1:5678/api/open/stats).stats.rate_limiter.global_bucket.tokens
```

**判定标准**：
| 检查项 | 通过标准 |
|---|---|
| 探活 | echo 200 |
| 认证链路 | 带 Key 开放端点 200 |
| 数据持久性 | 租户列表完整；审计日志可查（落盘恢复） |
| 限流状态 | 全局桶重置 100.0（内存态，符合预期） |
| 启动日志 | 含 `[APIGateway] T8.4 已开放 8 个内部只读端点（两批）` |

## 场景 B：租户数据隔离演练（含潜在泄露验证）

> 目的：验证「租户 A 的 Key 不能读取租户 B 的数据」。**本场景会暴露真实风险点**，请按 B.3 判定与缓解执行。

### B.0 准备：两个租户 + 各自绑定 Key

```powershell
# 租户 A / 租户 B（管理端点，FLASK_API_TOKEN）
$h = @{"X-API-Token"=$env:FLASK_API_TOKEN}
$ta = Invoke-RestMethod -Method Post http://127.0.0.1:5678/api/open/tenants -Headers $h -ContentType 'application/json' -Body '{"name":"drill-tenant-a","type":"organization","owner_email":"a@drill.local"}'
$tb = Invoke-RestMethod -Method Post http://127.0.0.1:5678/api/open/tenants -Headers $h -ContentType 'application/json' -Body '{"name":"drill-tenant-b","type":"organization","owner_email":"b@drill.local"}'
# 各自签发绑定 Key（owner 角色）
$ka = (Invoke-RestMethod -Method Post http://127.0.0.1:5678/api/open/keys -ContentType 'application/json' -Body ('{"user_id":"' + $ta.organization.id + '","tenant_id":"' + $ta.organization.id + '","role":"owner"}')).api_key
$kb = (Invoke-RestMethod -Method Post http://127.0.0.1:5678/api/open/keys -ContentType 'application/json' -Body ('{"user_id":"' + $tb.organization.id + '","tenant_id":"' + $tb.organization.id + '","role":"owner"}')).api_key
```

### B.1 隔离正向验证（预期通过）

```powershell
# 租户 B 的 Key 访问只读端点（scope=read → READ 权限，owner 有）→ 200
Invoke-WebRequest http://127.0.0.1:5678/api/audit/logs?limit=1 -Headers @{"X-API-Key"=$kb} -UseBasicParsing
# 无 Key → 401；伪造 Key → 401（可复用 simulate_gateway_errors.py）
```

**预期**：200 / 401。

### B.2 跨租户读取验证（潜在泄露探测）

```powershell
# 用租户 A 的 Key 查询审计日志，观察是否能读到 B 租户产生的记录
$a1 = Invoke-RestMethod http://127.0.0.1:5678/api/audit/logs?limit=20 -Headers @{"X-API-Key"=$ka}
"租户A看到日志条数: $($a1.count)"
$a1.logs | ForEach-Object { $_.metadata }  # 检查是否存在租户 B 的操作记录
```

**预期（当前实现）**：**200 且可读到跨租户记录** —— `/api/audit/logs` 为全局 Append-only 日志，**未按租户维度过滤**。这是演练要暴露的真实缺陷。

### B.3 判定与风险定级

| 判定 | 说明 | 风险 |
|---|---|---|
| 跨租户可读审计日志 | audit/logs 无 tenant 过滤；含 trace_id/action/metadata（input/output 为哈希） | **中**（元数据级；凭据哈希不可逆） |
| 其余灰度端点 | news/schedules/skills/tasks/search-perf 为全局只读信息，无租户私有数据 | 低 |

**缓解措施（按序执行）**：
1. **短期（已落地 ✅）**：`/api/audit/logs` 服务端按 Key 租户过滤——网关认证后注入 `request._gateway_key_info`，视图经 `AuditLogger.filter_by_key` 仅返回本租户记录；未绑定 Key 返回空集 + warning。
2. **中期（已落地 ✅）**：审计记录落盘带 `tenant_id` 字段（`AuditLogger.log(tenant_id=...)`，未显式传时从请求上下文自动注入）；历史记录经 `scripts/migrate_audit_logs_tenant.py` 补全为 `system` 归属（228 条已迁移，自动备份，幂等）。
3. **长期**：敏感管理端点（tenants/keys/stats）已走 `FLASK_API_TOKEN` 内部通道，保持不变；如需开放，须走 RBAC `manage`/`admin` scope 且按租户收敛。

> 隔离修复验证（2026-08-16 实测）：租户 B owner Key 查询 count=1（仅本租户）、跨租户 0；未绑定 Key count=0 + warning。401/429/403 五场景日志定位步骤经 `scripts/simulate_gateway_errors.py` 复现通过。

### B.4 RBAC 负向验证（对照权限矩阵）

```powershell
# 角色权限矩阵（真实映射，multi_tenant.has_permission）：
#   owner  : read/write/delete/manage/admin
#   admin  : read/write/delete/manage（无 admin）
#   member : read/write
#   viewer : read
# 演示：member 无 delete/manage → 若存在开放管理端点应 403（当前管理端点走内部 Token，RBAC 作用于开放端点 scope 校验）
python scripts/simulate_gateway_errors.py --only 403
```

**预期**：403 `Forbidden`（scope 不足演示端点）。

|---|---|
| 隔离正向（B.1） | 通过：401/200 符合 |
| 跨租户读取（B.2） | **泄露确认**：A 可读全局审计日志 |
| 风险定级 | 中（元数据级） |
| 缓解落地 | 短期过滤已排期 / 中期 tenant_id 字段 / 长期 RBAC 收敛 |
