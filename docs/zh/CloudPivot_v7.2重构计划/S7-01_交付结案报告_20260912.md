**下游可直接复用的落点**：
- `agent/settings/registry.py::get_spec(key)` / `all_specs()`：任何模块要"知道某个开关属于哪个子系统/什么风险"时直接用；
- `agent/settings/resolver.py::resolve(key)`：任何面板要显示"这个值的真实来源"时直接用（**勿自建来源推断**）；
- `scripts/scan_settings.py --check`：新增任何开关读取点后作为 CI 门跑一次，缺口即失败。

**复核期发现并已处置（四类，详见验收报告 §5.6 / §5.7）**：① `panel` 台账未走 `schema.panel_map()`（改为登记 + 复用）；② `counts` 无出处说明（新增 `counts_provenance` + 用例断言与注册表逐项相等）；③ 前端 `SettingsShell` / `CategoryGroup` 是对 `index.tsx` 私有组件的**平行实现**（已把 `Collapsible`/`PanelShell` 上移到共享的 `components.tsx`，两文件均复用，**既无重复也无环**，eslint 零告警）；④ **前后端拒绝契约未实证**（前端声明未与真实后端联调）→ 新增 `TestDenialContractForFrontend` 逐条断言拒绝响应的 `message` 存在且非空，**并由该组用例反查出一处真实缺陷**：`_second_factor_ok` 先判凭据、后判会话，导致"运维还没开审批会话"的人只看到「需二次认证」却看不到「必须先开审批会话」，已改为**先判会话**；同时把 `counts.overridden` 与前端"只看已覆盖"筛选的等价关系钉成用例（前端点名的最需复核项）。另如实登记一处"假绿"：`untraceable_scan()` 在本响应上是空扫（`checked=0`），用例显式断言该事实以防误读为"已通过口径自检"。
