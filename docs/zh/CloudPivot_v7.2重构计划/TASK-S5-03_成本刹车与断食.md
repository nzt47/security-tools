## 一、目标描述

落地 v7.2 **成本治理自动化**与性能预算修正：

1. **日级硬熔断（P7.2-06 新增）**：当日成本 > budget.daily_cents → 立即停非关键 outbound，次日自动恢复。
2. **周级断食（滞后规则）**：进 UTC>1.3×（日均成本/基线）→ 降本模式；出需连续 24h ≤1.1×；冷却 12h。
3. **θ 分阶段（§6.3）**：按阶段启用 UTC 上限（W1-W4 不设 → W5-W9 ≤1.5×→1.3× → W10-W14 ≤1.0× → M4+ ≤0.8×→0.6× → M7+ ≤0.5×）——配置化 + 披露。
4. **性能预算重定（P8 修正）**：以云枢实测基线替换 §11.2 假设值（reranker/embedding 内存、RRF 技能库检索、向量库/etcd P99 实测——引用既有压测报告）；输出 `PERF_BUDGET_REBASED.md`。
5. **审批衰减率目标（§6.7）**：策略自动消化占比 ≥70% 的度量（消费 S2-03 审批事件，仅披露不考核起步）。

## 二、执行步骤

### 步骤 1：成本数据源与基线（含接收 S2-03 移交的裁定项）
- 消费 S2-03 已交付的成本接口：`agent/observability/utc.py::record_cost()` 写入、`utc_daily()`/`utc_weekly()`/`utc_window()` 聚合、`coefficient_table()`/`anchor_prices_cents()`/`resolve_anchor_model()` 取系数与锚价；定义 UTC 基线（近 7 日滚动日均成本或 budget 配置）。
- 复用既有成本监控脚本（verify_budget_break.py 等）数据源，归一为 `data/cost_daily.json`。
- **【S2-03 遗留 #5 —— 归一化系数校准：Owner 已裁定 2026-09-11，采用「沿用锚价系数表」】** 裁定内容：**本次不启用校准流程**，继续使用 `utc.py::coefficient_table()`/`anchor_prices_cents()` 的价格锚定系数（以主力模型为锚 + 各模型价格比例）。
  - **理由**：校准需要「同一批标准任务在多模型实跑」的经验成本比，其量尺是 **L2 Core-50 基线**，而 L2 由 S5-02 产出、当前尚不存在——没有尺子无法校准。
  - **后续触发条件（写入本任务文档，勿丢）**：待 **S5-02 L2 Core-50 基线就绪后**，启动校准评估（跨模型成本-效果实测 → 经验系数 → 替换价格系数），届时须定义校准数据来源与复校周期（建议季度）。
  - **本任务只需**：在成本文档与 `PERF_BUDGET_REBASED.md` 中显式标注「当前口径＝价格锚定系数，待 L2 基线后校准」，并在指标输出中标注口径版本。
- **【S2-03 遗留 #9 —— 双成本轨：Owner 已裁定 2026-09-11，采用「收敛到事件流单一数据源」】** 既有 `data/cost_log.jsonl`（`CostTracker.record()` **生产零调用方**、仅测试调用，`reconcile_cost_log()` 多为 rows=0）与 S2-03 事件流成本轨并存。
  - **裁定内容**：**收敛到事件流唯一数据源**——S2-03 事件流（`utc.record_cost()` → `data/events/`）为成本唯一写入与查询来源；旧轨**停写**，保留只读解析兼容 ≤1 minor（按仓库惯例，旧文件归档不删除）；`reconcile_cost_log()` 降级为纯对账工具或下线，并在文档标注「成本唯一数据源＝事件流」。
  - **落地**：本任务内完成停写与兼容读，加单测断言"新写入只落事件流"；若发现仍有生产调用方，先补报警再收敛（不得静默丢账）。

### 步骤 2：日级硬熔断
- `daily_breaker`：当日累计成本 > budget.daily_cents → 停非关键 outbound（关键=用户显式请求/审批中任务），次日 00:00 自动恢复；熔断触发记录审计 + metrics.delta/healing 事件。
- 配置：`.env` `CP_BUDGET_DAILY_CENTS`/`CP_BUDGET_WEEKLY_UTC_HIGH` 等，非法值回退默认。

### 步骤 3：周级断食
- `fasting` 状态机：进（日均 UTC>1.3× 持续判定）→ 降本模式（限制非关键 LLM/消化/影子任务）→ 出（连续 24h ≤1.1×）→ 冷却 12h 后恢复。
- 与 S3 shadow 预算联动（断食期 shadow 预算归零/减半——对齐 §4.5 每日预算）。

### 步骤 4：θ 分阶段与性能预算
- θ 阈值按阶段配置表（§6.3）落地；当前阶段推断（W/M 周次配置化）。
- 性能预算重定：引用云枢实测（RRF 5000 技能压测、向量库 P99、ONNX 内存、events 吞吐现有量级），产出 `PERF_BUDGET_REBASED.md` 并在相关模块文档登记（§13.3 联动）。

### 步骤 5：回归与归档
- 回归：成本监控/预算相关套件零回归；新增单测（日熔断触发与次日恢复、断食进出/冷却、θ 阶段阈值、性能预算加载）≥25 例、覆盖率 ≥80%。
- 演练：模拟日成本超限 → 熔断触发 → 次日恢复；UTC 超限 → 断食进出。
- 撰写 `TASK-S5-03_验收报告.md`。
