# TASK-S5-02 L0-L3 评测锚与基线（对齐 §6.5）

> 所属阶段：S5 记忆与评测｜依赖：S2-03（指标事件）、S3（流水线产物）｜预估：4–6 人日

## 一、目标描述

建立 v7.2 **评测分层 L0-L3**，打破"自验收循环"，为消化/进化/路由提供系统不可写的客观标尺：

1. **L0 锚（20 条人工冻结用例）**：人工编写、哈希锚定、**系统不可写**（对齐云枢既有教训"外部评测锚"）；W1 起即建立——作为所有自动评估的对照基准。
2. **L1 最小集（10 条）**：W2-W4 用（本任务补建/对齐现有测试集）。
3. **L2 Core-50**：W10+ 起，UTC 基线唯一依据（覆盖核心链路：S1 修 bug/S2 懂代码库/S3 提交三类种子场景）。
4. **L3 Golden-80**：W15+（延后，本任务仅定义框架与占位）。
5. **指标口径（§6.7）**：消化吞吐 ≥2/周（W10 起）、内化转化率 ≥10%、委派回收率 100%、技能成功率 ≥上游×0.98、路由准确率 >85%（W10 起）——定义可计算指标并挂数据源（S2-03/S2-01）。

## 二、执行步骤

### 步骤 1：L0 锚冻结用例
- 人工编写 20 条冻结用例（覆盖：S1 修 bug 端到端、S2 代码库问答、S3 提交生成、Router 决策、审批拦截、回滚——每类 ≥2 条）；用例含输入 + 期望结果 + 判定标准（机械可验优先）。
- **系统不可写机制**：用例存储独立于系统数据目录（只读位置/签名校验），自动化流程无权修改；哈希锚定（用例集整体 hash 入 release manifest）。
- 提供 `run_l0()` 执行器：输出 pass/fail 与对照基线。

### 步骤 2：L1/L2 分层
- L1 最小集：从既有测试（如规划/学习/技能验收套件）抽取或新增 10 条快路径用例（回归用）。
- L2 Core-50：围绕三类种子场景扩展至 50 条（可复用既有验收/E2E 用例 + 新增）；作为 UTC 基线唯一依据（与 S5-03 对接）。
- L3 Golden-80：定义框架（用例目录 + 运行器接口 + 周期），实际扩充入 M7+ 后。

### 步骤 3：指标字典与数据源接线
- 落地 §6.7 可计算指标（消化吞吐/内化转化率/委派回收率/技能成功率/路由准确率）：定义 SQL/查询（S2-01 台账 + S2-03 事件 + S3 stage 数据），产出周报脚本 `scripts/report_slo_weekly.py`。
- 路由准确率基线：Router 决策与事后最优一致率（需要 shadow 事后标注——定义标注源：人工/结果回测，先做框架与占位数据）。

### 步骤 4：回归与归档
- 回归：评测/验收相关套件零回归；新增单测（L0 不可写、run_l0 判定、L2 基线快照、指标计算）≥30 例、覆盖率 ≥80%。
- 撰写 `TASK-S5-02_验收报告.md`（含 L0 20 条清单与首次 run 结果）。

## 三、预期成果

1. L0 锚 20 条冻结用例（独立只读存储 + 哈希锚定 + run_l0）。
2. L1 最小集 10 条 + L2 Core-50（UTC 基线）+ L3 框架。
3. §6.7 指标计算脚本（周报）。
4. `TASK-S5-02_验收报告.md`。

## 四、评估标准（验收清单）

- [ ] L0 20 条用例人工冻结、系统不可写（写入尝试被拒/校验失败用例）
- [ ] run_l0 输出可复现 pass/fail；基线对照记录
- [ ] L2 Core-50 覆盖三类种子场景且有明确清单；作为 UTC 基线数据源
- [ ] L3 框架定义（目录/运行器/周期）可扩展
- [ ] 指标脚本可计算 ≥5 项 §6.7 指标（含数据源引用）
- [ ] 既有评测/验收套件零回归；新增单测全绿、覆盖率 ≥80%
- [ ] L0 首次运行结果在验收报告记录
