## 二、根因（代码行级）

### 2.1 主根因：平移工具的伪影（54 里的 49 个）

**工具侧**：`tests/_date_shift_plugin.py`（改前）`_make_fakes()` 里
`FakeDatetime.now()` = `_REAL_DATETIME.now(tz) + delta` ——
**"真实类实例 + timedelta" 得到的仍是真实类实例**；而模块属性
`datetime.datetime` 此刻已被指向子类 `FakeDatetime`，且 `FakeDatetime` 也**没有**
声明 `__module__` / `__qualname__`。

**产品侧触发点（无需改动）**：`agent/p6/snapshot.py`
* `:345` `created_at=datetime.now()` → 得到**真实类**实例
* `:169` `data = pickle.dumps(snapshot)`

`pickle` 序列化实例时走 `save_type → save_global`，按 `obj.__class__` 的
`__module__`/`__qualname__` 回查模块属性，并**要求"查到的对象就是那个类"**；
查到 `FakeDatetime`、要 pickle 的却是真实类 ⇒

```
_pickle.PicklingError: Can't pickle <class 'datetime.datetime'>:
                       it's not the same object as datetime.datetime
```

⇒ 任何"把 `datetime` 放进快照/缓存/队列"的用例都成片报红，**与"今天是哪天"无关**。

### 2.2 决定性实验（S11-06 缺的那一步）

用**旧插件本身**跑 3 个快照文件（`test_snapshot_comprehensive.py` /
`test_p6_snapshot_advanced.py` / `test_p6_snapshot.py`）：

| 模式 | 结果 |
|---|---|
| 旧插件 + `delta=0`（**只替换、一天都不挪**） | **49 failed / 192 passed** |
| 旧插件 + `+400` | **49 failed / 192 passed**（逐条相同） |
| 新插件 + `delta=0` | **241 passed** |
| 新插件 + `+400` | **241 passed** |

⇒ 一步都没挪就崩 49 个 ⇒ **是工具伪影，不是炸弹**。
S11-06 的"不平移 / +1 / +400"三档**全是平移档**，原理上无法区分这两者。

### 2.3 修工具时**自伤**一次（如实记录）

盲区收窄（按**值**替换以覆盖 `from datetime import datetime as dt`）的首版把
`tests.*` 也纳入 ⇒ `tests._date_shift_plugin._REAL_DATETIME` 被换成假类 ⇒
`FakeDatetime.now()` 里 `_REAL_DATETIME.now()` **无限递归**：

```
RecursionError: maximum recursion depth exceeded
  return cls._wrap(_REAL_DATETIME.now(tz) + delta)     ← 重复 950 次
```

且对照模式出现 **4 failed 假红**（`control=1` 本应 5 passed）。
⇒ 限定为**只对 `agent.*`** 按值替换；此后 `control=1 → 5 passed`。

### 2.4 真残留之一：时钟口径不一致（2 个，已修）

**产品口径**：`agent/knowledge/card.py`
* `:719` `ts = since.timestamp()`
* `:736` `if st.st_mtime < ts: ...` —— 过滤依据是**文件系统 mtime**

**用例原写法**（两文件同形）：只显式写旧卡 mtime，新卡 mtime 靠"刚 `create`
恰好等于 `datetime.now()`"的**隐含假设**。Python 时钟与 OS 时钟不同源
（整体平移 / NTP 校时 / 跨时区 / 网络盘）时新卡被判成"早于 since"而漏掉。

### 2.5 真残留之二：跨零点（导入期取时钟 vs 运行期取时钟，5 个，已修）

**这是 S11-06 与平移工具都查不出的一类**：平移对"导入期"和"运行期"是**同步**挪的，
永远不会制造两者的分歧；只有**整库跑真的跨越 00:00** 才会。

* `tests/unit/test_events_write_hardening.py:47`（改前）
  `_TODAY = date.today().isoformat()` —— **导入期**求值；
  而被测 `agent/skills_mgmt/log_archiver.py:394 today = date.today().isoformat()`
  在**运行期**取，`:434 if day is None or day >= today` 用它判"今日行"。
* `tests/unit/test_s5_03_cost_brake.py:41`（改前）
  `BASE = datetime.now().astimezone().replace(hour=10, ...)` —— **导入期**求值；
  而被测 `agent/monitoring/cost_brake.py:1661 moment = now or self._clock()`
  在**运行期**读真实时钟。

**实测后果（基线跑 23:57 开始、00:54 结束，真的跨了零点）**：
`8 failed`，其中 5 个是这一类（见 §3.3）。
