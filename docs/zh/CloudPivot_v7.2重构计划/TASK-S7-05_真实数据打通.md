# TASK-S7-05 真实数据打通（真实内化演示 + 面板出真数）

> 所属阶段：**S7 稳态运营补完批次**｜依赖：S3 全链（S3-01/02/03）、S6-01（治理面板）、S2（Trace/审计/事件）｜预估：5–7 人日
> 来源：收官审计 §九 第 1、2 条（未声称真实能力内化 / 面板三列为 0）+ Owner 决策 2026-09-12 选择推进
> 验收报告归档于本目录 `docs/zh/CloudPivot_v7.2重构计划/`

## 一、目标描述

S3 全链（清洗 → 挖掘 → 判定集 → 回放/验收门 → 灰度 → 内化决策 → PR）**设施齐备但从未在真实数据上跑通**；S6-01 的治理面板中「灰度 / 内化 / 验收」三列因此**显示 0**（面板拒绝填充演示数据，这是正向行为）。

本任务的目标是**打通这条"最后一公里"**，让系统第一次基于**真实任务轨迹**跑完消化链，并让面板显示**真实数字**：

1. **真实数据**：来自**真实任务执行**（真实指令 + 真实工具调用 + 真实结果），**不是合成/回放数据**；
2. **真实内化演示**：至少 1 个能力走完 `borrowed → mirrored →（判定集/验收门）→ shadow 灰度 → 内化决策 → stage.promote PR`；
3. **面板出真数**：三列显示真实事件数量与真实 stage 迁移（非 0、非演示填充）。

**门槛裁定（建议默认，Owner 可覆盖）**：
- **正式门槛不动**（`borrowed → mirrored` 仍需每能力 **≥20 条同类轨迹**）；
- 为演示引入 **"演示门槛" ≥5 条**，且**必须在报告中、UI 数据旁显式标注"演示门槛"**，避免把演示结果误读为正式内化。

## 二、执行步骤

### 步骤 1：门槛与合规前置（先写清再跑）
- 产出 `docs/zh/真实内化演示方案.md`：演示目标能力（建议选 2–3 个高频、可回放、副作用可控的能力）、演示门槛（≥5 条）、正式门槛（≥20 条）、**两者在报告与 UI 中的区分方式**；
- 确认 `CP_DIGESTION_SHADOW_ENABLED` 等开关的**演示期配置**（画布式显式开启 + 小预算 + 结束后关闭），并记录开关快照（便于复核）。

### 步骤 2：真实轨迹采集
- 明确"真实"的定义并写进报告：**真实任务指令 / 真实工具调用（真实副作用需要审批）/ 真实结果状态**；
- 采集方式（任选其一或组合，**不得使用合成轨迹**）：
  - **真实使用**：在受控工作区执行若干真实开发任务（读→测→改→验），让 S2-01 统一 Trace 自然落账；
  - **脚本化真实任务**：用 `scripts/` 驱动**真实工具**执行真实操作（同样是真实轨迹，只是触发方式是脚本）；
- 采集后核对：`UnifiedTraceStore` 中该能力的同类轨迹条数（按 `same_task_key()` 归组），并记录**未达门槛的能力清单**（如实保留，不硬凑）。

### 步骤 3：跑通消化链（含灰度）
- 依次执行并对每步留证：
  1. `DigestionService.pipeline()`（清洗 → 挖掘 → 候选模式 → draft SKILL.md）；
  2. 判定集构建（S3-02：Seed Pack + 真实轨迹生成用例，带 `origin_trace_id`）；
  3. 回放与验收门（`ReplaySandbox` 三层比对 + `GateResult` 四条件 → 通行证）；
  4. **shadow 灰度**（显式开开关 + 每日预算上限；`ShadowReport` 记录通过率/真实墙钟 p99/`judge_kind`）；
  5. 内化决策（`InternalizeEngine` 六条件；低样本走**手动 promote 通道**或如实标注"未达六条件"）；
  6. 产出 `stage.promote` PR（**本地可审阅，人工合入**）。
- **诚实要求**：任一环节不通过（如 ⑤ 隐私闸门、⑥ p99 回归、判定集不足）**必须如实记录为"未通过"**，不得调参刷过；演示的价值在于暴露真实瓶颈。

### 步骤 4：面板出真数
- 打开治理面板核对三列：**灰度 / 内化 / 验收** 是否显示**真实事件数量与真实 stage 变化**；
- 若仍为 0 或数据不完整 → 定位是"事件未落"还是"面板未消费"，修复并留证；
- 核对口径纪律（S5-02/S6-01）：样本 <20 只披露；缺数据记 `None`；**不出现不可追溯数字**。

### 步骤 5：报告与归档
- 产出 `TASK-S7-05_验收报告.md` + `真实内化演示记录.md`：
  - 端到端命令与关键输出（可复现）；
  - **门槛声明**（演示门槛 vs 正式门槛，逐能力标注）；
  - **真实数据证据**（轨迹条数、事件 id、Trace id）；
  - **未通过项与所需条件**（诚实边界）；
  - 演示结束后开关已复位（附快照对比）。

## 三、预期成果

- [ ] 轨迹为**真实执行**（含真实指令/工具调用/结果状态），报告中给出判定依据；**未使用合成轨迹**

- [ ] 演示期开关快照已记录，**结束后已复位**（对比证据）
- [ ] 报告中含"未完成事项与所需条件"（诚实边界）；未达标能力清单保留
- [ ] 相关套件（`digestion`/`ui_panels`/`eval`）零回归；新增/改动单测全绿、覆盖率 ≥80%

## 五、风险与预案

| 风险 | 预案 |
|---|---|
| 真实任务量不足以产生 ≥5 条同类轨迹 | 如实记录"未能完成真实内化演示"并给出**所需条件（需多少真实任务）**；不得用合成数据补足 |
| 副作用操作在真实环境有风险 | 优先选**只读/可回滚**能力（如检索、读取、分析类）作为首批演示对象 |
| 灰度开关忘记复位 | 步骤 1 记录开关快照 + 步骤 5 强制对比；用例断言复位 |
| 演示被误读为"已实现真实内化" | 口径纪律：所有输出旁标注"演示门槛"，报告首页写明确认声明 |
