      E  AssertionError: {'archived': 3, 'files': [...], ...}
  · 同文件其余用例全过：`1 failed, 57 passed`（2026-09-14 实测）。

**根因（已定位到行）**：该用例把"今天"**硬编码**成 2026-09-13：
  L1186-1190 写入三条记录，日期分别是 2026-09-10 / 2026-09-11 / **2026-09-13**；

  （注释写"两条历史日被移入分片" —— 即"09-13 是今天，留在活动文件"）。
  · 2026-09-13 当天跑 ⇒ 历史日只有 09-10、09-11 ⇒ archived=2 ✅
  · 2026-09-14 及以后跑 ⇒ 09-13 也成了历史日 ⇒ archived=3 ❌
  ⇒ 它是**"编写当天才通过"的定时炸弹**，不是我方任何改动引入的，但**确实是真缺陷**。

**注意**：`agent/skills_mgmt/log_archiver.py::archive_daily_file(path)` 的签名**只有 path**，
没有可注入的 `today`/`now`（内部用真实当前日期）。

**修法（按优先级，任选其一，但必须说明选择理由）**：
  (a) **首选：把日期改为相对当前日期推导**（零产品改动、最稳）
      —— 例如 `today = datetime.now(timezone.utc).date()`，三条记录取
      `today-3 / today-2 / today`（保持"2 条历史 + 1 条今日"的语义），
      于是 `archived == 2` **在任何日期都成立**。
      ⚠️ 注意 **UTC vs 本地时区**：`archive_daily_file` 用哪种口径判定"今天"？
      实现时必须与被测代码**同一口径**，否则会变成"时区定时炸弹"（更隐蔽）。
  (b) 备选：给 `archive_daily_file` 增加**可选**注入参数（如 `today: date | None = None`），
      默认 None = 现状；用例传固定日期 ⇒ 完全确定性。
      这属**产品签名变更**（虽是向后兼容的可选参数），须在报告里显式声明：
      变更点、影响面、以及"默认行为逐字不变"的证据。
  ⚠️ **禁止**：只把硬编码日期往后挪（如改成 2026-09-14）—— 那是把炸弹延后一天，
     明天照样炸。**必须消除对"今天"的依赖**。
