# TASK-S8-01 数据生命周期治理（TTL / 保留策略 / 冷归档 / 可还原）

> 所属阶段：**S8 生产化加固批次**｜依赖：S2（trace/audit/events）、S3（判定集/草稿/灰度台账）、S5（记忆/评测）｜预估：5–7 人日
> 来源：收官审计 §8.2（生产化类）+ S2-01 #7、S2-02 #4、S2-03 #10、S3-01 #5、S3-02 #6、S3-03 #8 多源同源遗留
> 验收报告归档于本目录 `docs/zh/CloudPivot_v7.2重构计划/`

---

## 一、目标描述

云枢已有**至少 7 类只有追加、没有清理**的运行时数据（台账/事件/审计/判定集/草稿/灰度台账/决策日志）。短期无害，长期会让"跑得久"变成风险：磁盘膨胀、查询变慢、归档不可控。本任务建立**统一的数据生命周期治理**：

1. **成文策略**：每类数据明确 `保留期 / 归档方式 / 删除方式 / 可否删除 / 谁来执行`；
2. **分层**：热（近期可查）→ 温（压缩归档，可查）→ 冷（打包导出，离线可还原）→ 删（仅限可删类）；
3. **可还原**：归档必须能被还原（抽样验证），**历史指标必须仍可复算**；
4. **不可越界**：**审计链永久保留、只归档不删除**；记忆删除走 S5-01 的"删记忆不删证据"路径。

## 二、执行步骤

### 步骤 1：数据资产普查与策略表
- 普查现有运行时数据（建议以 `scripts/scan_data_assets.py` 机械扫描 `data/`、`agent/data/`、各模块默认落点）：
  - `unified_traces`（S2-01）、链式审计链 + 每日根（S2-02）、事件流按日分片（S2-03）、
    判定集 `CaseStore` 历史版本（S3-02）、消化草稿 `data/digestion/drafts/`（S3-01）、
    灰度/抽检台账（S3-03）、策略决策日志 `decisions`（S4-02）、技能审计分片、`cost_daily.json` 等；
- 产出 `docs/zh/数据生命周期策略.md`：策略表（类别 / 路径 / 现体积 / 保留期 / 归档方式 / **可否删除** / 执行者 / 依据）。
- **红线标注**：审计链与每日 Merkle 根 = **永久保留、只归档**（并在表中显式写"禁止删除"）。

### 步骤 2：分层与归档机制
- 新增 `agent/retention/`：`RetentionPolicy`（每类策略）、`Archiver`（温/冷归档实现）、`Restorer`（还原）、`PurgeGuard`（删除前校验：是否触碰红线、是否有引用）；
- 归档格式：**自描述**（含 schema 版本、时间范围、记录数、校验和），压缩后落地 `data/archive/<class>/<period>.jsonl.zst`（或项目既定格式）；
- **还原**：`restore(archive, target)` 支持抽样还原到临时目录（不改线上），供验证与复盘；
- **首次运行必须 dry-run**（列出将归档/删除的清单与体积），确认后才执行。

### 步骤 3：调度与开关（默认保守）
- 清理/归档任务：`register_retention_job()`（建议每周），**默认关闭**（`CP_RETENTION_ENABLED=true` 才注册）；
- 策略可配置（`.env` / config），非法值回退默认；**默认策略 = 只归档不删除**（除显式标"可删"的类，如草稿、临时门禁产物）；
- 每次执行：入链式审计（`action="retention.run"`，记归档/删除条数与体积）+ 事件。

### 步骤 4：指标口径可复算验证（防"篡改历史"）
- 选 2–3 个既有指标（如 UTC 周成本、消化吞吐），在**归档前后**各计算一次，断言**结果一致**；
- 若某类数据被归档后指标无法复算 → 该类的归档方式不合格，需改为"保留聚合摘要 + 明细归档"双轨。

### 步骤 5：回归与归档
- 新增单测：策略解析、dry-run 不落盘、归档→还原往返一致、红线类禁止删除、PurgeGuard 拦截、指标复算一致、默认关闭；
- 回归：`observability`（trace/events/utc）、`audit`、`digestion` 邻接套件零回归；
- 撰写 `TASK-S8-01_验收报告.md`（含策略表、dry-run 输出、还原抽样证据、指标复算对照）。

## 三、预期成果

1. `docs/zh/数据生命周期策略.md`（含"禁止删除"红线标注）。
2. `agent/retention/`（Policy / Archiver / Restorer / PurgeGuard）+ `scripts/scan_data_assets.py`。

4. 指标复算一致性验证报告。
5. `TASK-S8-01_验收报告.md`。

## 四、评估标准（验收清单）

- [ ] 7 类以上运行时数据均有成文策略（保留期/归档/删除/执行者/依据）
- [ ] **审计链与每日根标注"禁止删除"**，且 `PurgeGuard` 有拦截用例（含"误传审计类即拒"）
- [ ] dry-run 默认先跑、不落盘；输出将被处理的数据清单与体积
- [ ] 归档**可还原**：抽样还原往返一致（逐条比对或校验和一致）
- [ ] **归档前后指标一致**（至少 2 个指标复算对照，口径未变）
- [ ] 调度**默认关闭**，需显式开关；每次执行入链式审计（含条数与体积）
- [ ] 记忆类删除走 S5-01 的"删记忆不删证据"（审计匿名化、链保留）
- [ ] 既有 `observability`/`audit`/`digestion` 套件零回归；新增单测全绿、覆盖率 ≥80%

## 五、明确不做

- ❌ 不实现"审计链裁剪/轮转"（永久保留是设计约束）
- ❌ 不改变任何既有统计口径（只做归档，不动聚合逻辑）
- ❌ 不实现跨机/对象存储归档（属 P5 Backlog；本任务只做本地归档 + 可选导出打包）
