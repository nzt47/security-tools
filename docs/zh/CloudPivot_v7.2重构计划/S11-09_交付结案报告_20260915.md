### 2.2 真凶：循环依赖检测器的输出依赖**遍历顺序**

代码级根因链：

1. `agent/observability/arch_rules.py:500-549` `_check_circular_dependencies` 用**三色 DFS**，报告哪条边取决于 `adj` 的遍历次序；`reported_cycles` 只按"首次发现"去重。

3. `agent/observability/arch_rules.py:566-567` 该仓库**自己承认**这一点：注释逐字"对循环依赖…**双向匹配**，**因 DFS 遍历方向不确定**，source/target 可能与豁免清单顺序相反"。

**对照臂实验**（`.tmp-s1109/order_experiment.py`，含 CONTROL，纪律要求）：

### 2.4 为什么"逐条修 or 逐条豁免"两条路**在本任务内都走不通**

- **路线 (i) 修**：要真正消除环，必须打断 4 个 SCC 的**全部**环边（否则任一遍历顺序仍可能报出）。核心手段只有"让包的 `__init__` 不再急切导入子模块"（PEP 562 惰性再导出）或依赖倒置——**涉及 30 个模块**（含 `audit`/`observability`/`skills_mgmt` 核心路径），且因为**任何** `from pkg.sub import x` 在运行期都会执行 `pkg/__init__`，改 `import` 写法并不能真正消除运行期耦合（那只是"隐瞒形状"）。属多日重构，**远超"收口"范围**，且回归风险高。
- **路线 (ii) 豁免**：若只豁免**本地这一次抽样**报出的 11 条 ⇒ 换个遍历顺序（CI 的 ext4）就有 9 条**未被豁免**的边冒出来 ⇒ **假绿灯**（本任务明令禁止）。若豁免**全集**（43 对 / 78 条环内边）⇒ 等于把 4 个 SCC 从 `no_circular_dependency` 规则中整体摘除 = **批量豁免**（本任务明令禁止）。

> **附加发现（文档与实现不符）**：规则自身的建议是"通过依赖倒置或中间层解耦，**或使用 `lazy_loader` 延迟加载**"，但 `agent/observability/dependency_graph.py:680-685` 对动态 import 的处理是**空分支**：

>     target_short = target.split(".")[-1]

> 且 `_check_circular_dependencies` 使用**全部**边（不筛 `is_dynamic`）⇒ **`lazy_loader` 延迟加载对循环依赖规则完全无效**。即该建议在 Cycles 规则上不可执行，这也是"看起来有官方出口、实际走了没用"的陷阱。

## 五、任务 3：全量计数口径差 ±1 —— **口径差，不是 bug**

### 5.1 先更正一个数字

提示词写"同一棵树 `--collect-only` = **18481**（基线 a16afb6b 为 18463 + 本任务新增守卫 18 条）"。**本树实测 = 18483**：

```
python -m pytest tests/unit -q --collect-only -p no:randomly -p tests._date_shift_plugin
→ SKIPPED [1] tests\unit\test_query_pattern.py:31: _QUERY_PATTERNS + _match_query_pattern
                 已于 commit 1159d88f 删除（TLM 三层路由取代 v6.1 规则），整个测试文件前提失效
→ 18483 tests collected in 11.10s
```

原因可完全对上：`726b121e` 的提交信息明写"守卫套件 **18 → 20**"，而该文件在本树恰贡献 **20** 条 ⇒ `18463 + 20 = 18483`。即提示词那次是 **18481 collect / 18482 outcome**，本树是 **18483 / 18484**，**差值恒为 +1**。

### 5.2 根因（代码行级）

**不是 conftest 的统计钩子**。`tests/conftest.py:942-954` 与 `tests/_date_shift_plugin.py:272-297` 两个 `pytest_terminal_summary` 都**只读取/打印**、不改 `stats`（且都不打印 xfailed/xpassed ⇒ 18482 是人工相加的）。真正决定计数的是 pytest 自身 `_pytest/terminal.py:800-806`：

```python
    def pytest_collectreport(self, report: CollectReport) -> None:
        if report.failed:
            self._add_stats("error", [report])
        elif report.skipped:
            self._add_stats("skipped", [report])   # ← 非用例条目也进 stats
        items = [x for x in report.result if isinstance(x, Item)]
        self._numcollected += len(items)           # ← 收集条目数只数 Item
```

- `tests/unit/test_query_pattern.py:31` 用 `pytest.skip(..., allow_module_level=True)`，在 **import 期**抛 `Skipped` ⇒ 该文件产生一条 **outcome=skipped 且 `result` 里没有任何 Item** 的 `CollectReport`。
- 于是：`stats["skipped"] += 1`（**+1**），而 `_numcollected += 0`（**+0**）。
- 结尾行合计走 `stats`（`terminal.py:1450-1467`），且 `reports.py:168` 的 `count_towards_summary` 对 `BaseReport` 恒 `True`、`CollectReport` 未覆写 ⇒ 该收集级 skip 被计入合计。

⇒ **合计 = 收集条目数 + 1**，差的**恰好 1**；且 `18482 - 1 = 18481` 与收集数**完全相等**，说明逐条 1:1，**没有用例丢失、也没有重复执行**。

**唯一性已证**：AST 扫描 `tests/**` 共 **612 个文件**，import 期会执行的模块级 skip **恰好 1 处**。已排除：xpass 双计（会 +4）、`--continue-on-collection-errors`（本套件 0 收集错误，`pytest.ini:35` 虽设置但无 error）、`pytest_generate_tests`（无）、rerun/subtests 插件（未安装）、日期平移插件（未设 `CP_DATE_SHIFT_*` ⇒ 惰性）。

**同形微型复现**（直接证明 1+1 机制）：

| 命令 | 结果 |
|---|---|
| `pytest <该文件> --collect-only` | `no tests collected` |
| `pytest <该文件>` | `collected 0 items / 1 skipped` → 合计 **1** |
| `pytest <110 用例文件> + <该文件> --collect-only` / 实跑 | **112** collected / `112 passed, 1 skipped` = **113** |

真实 CI 日志独立佐证：`.ci_logs/py312_ubuntu.log:22003` 存在**无 `::` 的** `SKIPPED [1] tests/unit/test_query_pattern.py:31`；其 JUnit XML 把它写成 `<testcase classname="" ...><skipped message="collection skipped">`。

### 5.3 判定与处置

**结论：口径差（pytest 报告器口径），不是真 bug。** 危害仅是可审计性——"outcome 合计 − collected" 会产生 ±1 假信号。

**未修改任何代码**，理由：本任务该条的修复授权是"**若是 conftest 统计口径问题**，顺手修好并给改前/改后数字"，而定位结果是**并非 conftest 钩子问题**（conftest 只读不写、pytest 的 `CollectReport` 计入 summary 是其既定行为）。擅自改测试文件去"消掉"这个差值，会把一个**度量口径现象**当成缺陷去修，属超出授权范围。

**若 Owner 要求消除，两个可选最小方案（均未执行，数字为推算、非实测）**：

| 方案 | 改动 | collect | outcome 合计 | 差 |
|---|---|---|---|---|
| A. 换占位用例 | `tests/unit/test_query_pattern.py:30-35` 把模块级 skip 换成一条"运行期 skip 的占位用例"（该文件被测对象已于 `1159d88f` 删除，整文件是死代码，墓碑仍会出现在 `-ra`） | 18483 → 18484 | 18484 | **0** |
