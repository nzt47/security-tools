## 一、结案结论

**TASK-S8-01 已交付并结案（验收 8/8 + 三条不可越界原则逐条机器化自证）。**

云枢原有 **12 类"只有追加、没有清理"** 的运行时数据。本任务把它们从"没人说得清"
变成"**每类都有成文策略 + 归档可还原 + 删除有闸门**"：

| 项 | 交付 | 判定 |
|---|---|---|
| **成文策略** | 12 类 × `保留期 / 分层 / 归档方式 / 可否删除 / 执行者 / 依据`，与代码**同源守护** | ✅ |
| **红线** | `audit_chain`（链 + 每日 Merkle 根）、`skills_audit`、`legacy_audit_archive` = **禁止删除**；`PurgeGuard` 无条件拦截（含"误传审计类"） | ✅ |
| **可还原** | 冷归档自描述（schema 版本 / 时间范围 / 记录数 / 校验和）；还原**逐字节**一致（SQLite 用一致性备份 + 行级摘要）；真实数据实测 2/2 通过 | ✅ |
| **口径不变** | `utc.weekly` / `digestion.throughput` / `audit.chain` 三个既有指标归档前后**逐字段一致** | ✅ |
| **默认保守** | `delete_source=false`（只归档不删除）+ 调度默认关闭 + **首跑强制 dry-run** | ✅ |
| **留痕** | 每次执行入链式审计（`action="retention.run"`，记条数与体积）+ 发 `retention.run` 事件；**两次连续 CLI 执行留下 2 条独立链上记录** | ✅ |
| **记忆删除** | 走 S5-01「删记忆不删证据」：`PurgeGuard` 拒绝并把调用方转给 `ForgettingEngine` | ✅ |

**批次出口标准第 ①② 条达成**：

* ① 每类数据都有成文保留策略且可配置；审计链**只归档不删** ⇒ 本任务交付。
* ② 归档**可还原**（抽样还原验证通过），历史指标**可复算**（口径不变）⇒ 本任务交付。

## 四、实现期发现并修复的真实缺陷

| # | 缺陷 | 影响 | 修复 + 防线 |
|---|---|---|---|
| D1 | **审计链未 flush ⇒ 留痕丢失**：链写入是后台批量线程（批 100 / 轮询 0.5s），CLI 几百毫秒即退出 ⇒ 两次连续执行只留 1 条（覆盖同一 `seq`） | 直接违背验收 #6 | append 后显式 `chain.flush(timeout=5.0)`；用例改为**独立只读链**读到才算数 |
| D2 | **SQLite 还原漏传表名**：用"全库行摘要"比"某表行摘要" ⇒ 多表库（`tool_trace.db`）**误报 mismatch** | 真实数据被判"归档不可还原" | 还原时传 `manifest.sqlite_table`；单测库加第二张表并**反向断言**"全库摘要必须不同"，否则用例无法发现该缺陷 |
| D3 | **测试写进真实审计链**：`AUDIT_DB_PATH` 环境变量对进程级 `audit = AuditFacade()` 无效（门面在导入时读走环境） | 污染本机链；并使断言假失败 | 测试改为 `audit.bind(AuditChain(tmp_path))` 显式注入临时链（autouse） |
| D4 | 两个**测试收集陷阱**：`python_functions = test_* verify_*` 会收集测试模块里导入的 `test_class` / `verify_roundtrip_metrics` | 出现"无名 ERROR"用例 | 改名 `retention_class` / `check_roundtrip_metrics`，并把坑写进注释 |
| D5 | 测试把清单写到工作目录（`write()` 缺省落到 `<archive_file>.manifest.json` 的相对路径） | 仓库根出现 `p.gz.manifest.json` 噪声 | 用例显式传 `tmp_path` 并断言工作目录不产生该文件 |
