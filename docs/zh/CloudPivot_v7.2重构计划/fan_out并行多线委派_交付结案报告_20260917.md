## 二、行为契约（交付即此口径）

### 2.1 签名与入参

```
fan_out(tasks, max_concurrency=4)
```

`tasks[]` 每项：`line`（可选）+ **八要素**（`goal` / `constraints` / `prior_artifacts` /
`prohibitions` / `artifact_format` / `budget_tokens` / `timeout_seconds` / `callback_url`）。

- `line` 缺省链：`task.line` → 全局激活主线（`data/agent_lines/_active.json`）→ **只读默认集**
  （`read_file / search_files / list_directory / get_file_info / grep`，写入与 Shell 不在内）。
- `max_concurrency` clamp 到 `[1, DEFAULT_MAX_CONCURRENCY]`（当前 4，§4.2），越界在 `notes` 说明。

### 2.2 返回信封

| 字段 | 语义 |
|---|---|
| `ok` | **至少有一个子任务成功**（见 §五-10 裁定） |
| `status` | `all_succeeded` / `partial` / `all_failed` |
| `partial` | 布尔位：`0 < succeeded < total` |
| `total` / `succeeded` / `failed` | 计数 |
| `results[]` | 逐任务：`index` / `line` / `status` / `summary` / `outcome` / `error_code` / `error` / `tools_granted` / `needs_approval` / `executed` / `budget_tokens` / `timeout_seconds` / `tokens_used` / `toolset_note` |
| `budget` | `allotted_tokens`（总额度）/ `executed_allotted_tokens` / `consumed_tokens`（实际消耗）/ `allotted_timeout_seconds` |
| `needs_approval` / `govern_tools_granted` | 汇总视图（后者只在主线显式 `allow_govern: true` 时非空） |
| `error_summary` | 有失败时逐条点名「第 N 个（错误码：原因）」 |
| `error_code` / `error` | **全部失败时**才给，口径对齐 `delegate` |

### 2.3 授权链（唯一防线）

```
task.line → LineProfile → assemble()（effect 上限 / mute / 平面权重 / 平面保底）
          → 剔除 govern（未 allow_govern 时）
          → SubAgentToolset.build(申请 ∩ 授权 − §7.0 矩阵拒绝)
          → tools_for / authorized_for（逐任务工厂）  ⇒ 子代理**真正可见**的工具集
```

- `toolset._TOOL_OPERATION_RULES` 只认 `memory.read` 这类抽象点名，对真实工具名（`write_file`）**不设防**
  ⇒ **授权清单本身就是防线**：本工具只授予"主线装配出来的那一份"。
- **fail-closed**：主线不存在 / 已停用 / 档案损坏 ⇒ **该任务失败**并说明原因，**绝不**回退成全量授权。
- `govern` 平面双保险：装配器按 `allow_govern` 剔除一次，再按 YAML 声明（唯一权威）过滤一次；
  显式 `allow_govern: true` 的线放行时，逐项进 `needs_approval` 并在 `govern_tools_granted` 标注。

## 三、上游补齐（两处，均为**加法式**，缺省行为不变）

| # | 缺口 | 补齐 | 为什么必须补（不是绕） |
|---|---|---|---|
| A1 | `execute_many(delegations, *, tools=…, authorized_capabilities=…)` 是**整批共用单值** ⇒ 无法"每个子代理各按自己主线装配" | 新增 `tools_for(ctx)` / `authorized_for(ctx)` 工厂参数（与既有 `credentials_for` **同款**语义；缺省 `None` ⇒ 退回整批单值） | 逐任务授权若走 `ctx.metadata` 侧信道，语义隐式且依赖执行器内部读取顺序；工厂参数是显式契约，且天然对"工厂自身抛异常"做了单条收敛 |
| A3 | `SubagentLifecycleManager` 只有**单发** `delegate()`，没有批量入口 ⇒ 直接调 `execute_many` 会绕过 `max_subagents` 容量上限与分身回收 | 新增 `delegate_many(specs, …)`：逐任务建分身 → `execute_many` 并发 → `finally` 统一回收；结果与入参**等长同序**；建分身失败就地收敛为 `E_SUBAGENT_UNAVAILABLE` | 分身纪律（容量 / TTL 取契约⑦ / 命名消歧 / 回收）属生命周期管理器；不从那里走，`fan_out` 就是"看不见的子代理 + 不受控的并发数" |

A3 顺带把 `delegate` 里内联的"TTL 取契约⑦ + 名称冲突消歧"抽成 `_prepare_config`，**单发与批量共用同一实现**
（单一权威）。批量路径逐任务**复制**模板，因此同一模板复用多条任务时各取各自的 TTL，且**不改写调用方模板**。
