# TASK-S7-02 自动诊断与补丁 PR（自修复 L1：能修，但不自动落地）

> 所属阶段：**S7 稳态运营补完批次**｜依赖：S4-04（真子代理委派）、S5-02（L0 锚 + 评测）、S3-02（回放沙箱/判定集）、S2-01/S2-02（Trace/审计）｜预估：8–12 人日
> 来源：Owner 决策 2026-09-12「先做 L1：自动诊断 + 补丁 PR（合入仍人工）」
> 验收报告归档于本目录 `docs/zh/CloudPivot_v7.2重构计划/`

---

## 一、目标描述

把云枢**已经具备但彼此孤立**的零件串成一条受控的自动修复流水线：

```
体检（L0 锚 + 回归） → 定位（失败用例 + Trace + 审计 + 源码切片）
  → 派工（S4-04 八要素委派，子代理产出补丁）
  → 隔离验证（打补丁到临时 worktree → 目标用例 + L0 锚 + 邻接回归）
  → 产出（本地分支 + 补丁 + PR 描述 + 证据链） → 【人工合入】
```

**边界（本任务的宪法）**：
1. **绝不自动 push 到远端、绝不自动合并**——产物止于本地分支/补丁与 PR 描述（延续 S3-03 的 PR 边界）；
2. **绝不触碰只读区**：`core/auth/`、`core/audit/`、`schema/`、`agent/audit/chain.py`、`agent/security/`、审计与签名相关代码；
3. **验证不过就不产出**：补丁必须同时通过"目标用例 + L0 锚"才允许生成 PR；否则如实产出"未修复"报告；
4. **预算与轮次上限**：单次修复有 token 预算与最多 N 轮（防止无限自我修改）；
5. **全程可审计**：体检/定位/派工/验证/产出每步都写 Trace（`actor=sub_agent` 或 `human`）与链式审计，**不许出现不可见动作**（八条不变量之五）。

> 说明：本任务交付的是**"能修、但不自己落地"**的能力。L2（白名单内自动合入）与 L3（熔炉核心自改写）**不在本任务范围**（见收官审计 §一 分级路线）。

## 二、执行步骤

### 步骤 1：体检器（发现问题）
- 新增 `agent/repair/` 包 + 入口 `scripts/self_repair.py`：
  - `diagnose()`：执行**体检三件套** —— ① L0 锚（`agent/eval` + `run_eval.py --layer L0`）② 目标测试套件（`pytest --junitxml`）③ 可选：审计链/告警快照（复用 S2-02 `verify_chain()` 与 `monitoring` 告警）；
  - 产出 `DiagnosisReport`：失败项清单（用例 id / 断言摘要 / 堆栈指纹 / 最近改动文件）+ **明确"无失败"也算结果**（不编造问题）。
- **触发方式**：本任务只提供**手动触发**（命令 + 参数），以及"体检报告"的产出；**不接自动触发**（自动化开关默认关闭纪律）。

### 步骤 2：定位器（把上下文打包成可委派的工单）
- 复用 S2-01 台账与审计链，为每个失败项聚合：**相关 Trace 链**（`UnifiedTraceStore.chain()`）、**涉及 capability**（descriptor）、**最近改动**（git 局部历史，只读 git，不写）；
- 生成源码切片（失败点 ±N 行的最小上下文，避免整仓塞进提示词）；
- 组装 **§3.9 八要素**任务包（目标/约束/已有成果/禁止事项/产物格式/预算/超时/回调）+ TraceContext；**缺任一即拒绝派工**（复用 S4-04 的准入闸门）。

### 步骤 3：派工与补丁生成
- 走 **S4-04 委派通道**（`agent/subagent/delegation.py`）：预算令牌 + 超时 + **工具裁剪**（子代理只读源码 + 只能产出补丁文本，**不给写权限、不给审批权、不给记忆读写**）；
- 产物格式：统一 diff（`unified diff`）+ 变更理由 + 涉及文件清单 + 自评；
- **范围护栏**（硬闸，违反即丢弃本次产出）：
  - 单次改动文件数 ≤ N（默认 3）、单文件改行数 ≤ M（默认 120）；
  - 命中**只读区黑名单**即拒；
  - 不得修改测试断言以"骗过"测试（若改测试，必须在 PR 描述中显式标注"修改了测试断言"并给出理由，供人工重点审）。

### 步骤 4：隔离验证（关键：不过不许产出）
- 在**临时副本/临时 worktree** 应用补丁（**绝不在主工作区或本会话 worktree 直接改**）：
  - 跑目标用例（必须从 fail → pass）；
  - 跑 **L0 锚**（`run_eval.py --layer L0`，系统不可写标尺，必须全过）；
  - 跑邻接回归（按改动文件映射的测试子集）；
- 三关全过 → 生成产物；任一不过 → 记录失败原因并**丢弃补丁**（不得把未验证补丁交给人工）；
- 记录 `verification` 证据（命令 + 输出摘要 + 退出码）供 PR 描述引用。

### 步骤 5：产出 PR（人工合入）
- 产出物（**全部本地**）：
  - 分支 `repair/<date>-<issue-slug>`（或补丁文件，视项目惯例）；
  - **PR 描述**：问题摘要 / 根因分析（引用 Trace+审计证据）/ 补丁说明 / 验证证据（三关结果）/ 风险与回滚（`undo_hint`）/ **人工复核重点**；
  - 复现命令与体检报告路径；
- **明确不执行**：`git push`、远端 PR 创建、合并、rebase 主分支；
- 全流程审计：`audit.record(action="repair.propose"...)` + 事件（复用 `events.py`），审计链可验签。

### 步骤 6：回归与归档
- 新增单测：体检器（造失败用例）、八要素准入、范围护栏（只读区/文件数/行数）、隔离验证三关（含"故意不过→丢弃"）、只读区拒绝、预算与轮次上限、**无 push 断言**（可用 fake git 或对 `subprocess` 的探针）、审计留痕；
- 端到端演示：**人为注入一个真实小 bug**（如在 `tests/` 或非只读 `agent/` 模块引入一个断言错误）→ 跑 `self_repair.py` → 产出补丁 PR → 人工合入后 L0 锚通过；
- 撰写 `TASK-S7-02_验收报告.md`（含该端到端样例的完整证据链）。

## 三、预期成果

1. `agent/repair/`（diagnose / locate / delegate / verify / propose）+ `scripts/self_repair.py` 入口。
2. 隔离验证三关（目标用例 + L0 锚 + 邻接回归）与"不过即丢弃"机制。
3. 范围护栏（只读区黑名单 / 文件数与行数上限 / 改测试标注）与预算轮次上限。
4. 本地补丁 PR 产物（分支/补丁 + PR 描述 + 证据链）——**不 push、不合并**。
5. 端到端演示记录 + `TASK-S7-02_验收报告.md`。

## 四、评估标准（验收清单）

- [ ] 人为注入的真实小 bug 能被体检器发现，并产出 `DiagnosisReport`（含失败指纹与相关改动）
- [ ] 八要素不全时**拒绝派工**（用例）
- [ ] 子代理无写权限/审批权（工具裁剪断言）
- [ ] 只读区改动被拒；文件数/行数超限被拒；改测试断言会在 PR 描述中显式标注
- [ ] **补丁未通过"目标用例 + L0 锚 + 邻接回归"则不产出**（含"故意失败即丢弃"用例）
- [ ] 产出物仅本地（**代码级断言无 push/无 merge 调用**）
- [ ] 全流程 Trace + 链式审计可查（体检/定位/派工/验证/产出五步都有记录），审计链 `verify_chain` 通过
- [ ] 单次修复预算与轮次上限生效（超限即停并留证）
- [ ] 端到端样例可复现（注入 bug → 产出 PR → 合入后 L0 通过）
- [ ] 既有 `subagent`/`eval`/`digestion` 套件零回归；新增单测全绿、覆盖率 ≥80%

## 五、明确不做（防范围蔓延）

- ❌ 自动触发（定时/告警驱动）——**留给后续版本**，本任务只做手动 + 报告；
- ❌ 自动 push / 自动合并 / 自动开远端 PR；
- ❌ 核心自改写（v7.2 §5.2 熔炉 Forge/Vault）——属 L3，未实现；
- ❌ 修改只读区与审计/签名相关代码。
