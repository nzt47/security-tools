## 3. 遇到的问题与解决方案

| # | 问题 | 解决方案 |
|---|---|---|
| 1 | §3.2 无 risk/data_class 的 "unknown" 取值，而存量资产 trust/evolution 全缺（S0-02 摸底）——默认低风险/低敏感会造成"假安全"污染 | 云枢裁定 D1：**None=未评估/未分级/未入轨**（模型允许 None，校验器出 warning 不出 error），S1-02 回填后收敛；destructive/secret/borrowed 不变量仅在显式声明时生效 |
| 2 | §3.2 约束行要求 "secret ⇒ 禁外部端点 / borrowed ⇒ 必记完整轨迹"，但字段组无对应字段落点 | 显式化补充字段并文档化（裁定 D2/D3）：`origin.external_endpoint`（sse 远端 MCP 默认 True）、`evolution.trace_policy`（borrowed 必填；S2 Trace 台账前置声明） |
| 3 | 冲突处置规则（schema 相同合并/不同 variant）缺乏可执行的量化口径，且"宁可冗余，不可误合"（P7.2-05） | 三路投票 = input/output 结构签名 F1 相似度 + name_or_description；schema 同门（双双 ≥0.9）∧ 均值 ≥0.9 ∧ 名称 ≥0.55 才合并；同名不同 schema → variant；跨租户禁合并（不变量 #7）；保守合并字段规则（D5/D6） |
| 4 | 空 schema（{}）的相似度语义：默认补全 type/additionalProperties 使 {} 与复杂 schema 被误判相同 | 显式声明原则：仅计入 schema 中出现的键；{} 签名为空 → "空对空=1、空对非空=0"；差异清单（schema_diff_keys）供 variant 记录 |
| 5 | 同 id 重复注册的时间戳使内容等价判断失真（每次构造 created_at/updated_at 都变） | 内容等价判定剥离 meta 时间戳后再比较 → unchanged/updated 判定稳定 |
| 6 | 桥接失败不得阻断技能中心主流程（advisory 语义）需可测 | BridgeBatchResult/BridgeRunSummary 收集 item 级错误（转换/校验/注册失败各自归位）；registry.load() 非法条目 advisory 跳过记 invalid_entries；单测覆盖"畸形 tool 仅记 error，其余正常入库" |
| 7 | 单测目标 ≥40 例 / 覆盖率 ≥80% 且须可复核 | 四文件 124 例（models 26/validator 26/registry 42/bridge 30），包覆盖率 91%（models 96/validator 93/registry 90/bridge 89） |
