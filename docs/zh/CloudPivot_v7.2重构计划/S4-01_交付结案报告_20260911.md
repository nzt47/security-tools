## 四、实现期发现并修复的真实缺陷（4 项，均带回归用例）

| # | 缺陷 | 影响 | 修复 | 回归用例 |
|---|---|---|---|---|
| 1 | 越权事件幂等键不含尝试序号 | 同操作/同对象的重复越权被事件存储判为重放，链上只剩第一条 ⇒「同一来源多次越权」分析失真 | 加 `attempt_seq` 并入幂等键 | `test_repeated_violations_each_leave_one_audit_record` |
| 2 | 幂等键跨进程撞键（`seq` 每进程从 1 重启） | 进程重启后第一条越权与上一进程首条撞键被丢弃 ⇒ 审计静默缺条 | 幂等键加**进程命名空间**（pid + 随机盐） | `test_denial_key_resists_cross_process_collision` |
| 3 | 审批审计载荷中的 `record_id` 被脱敏启发式掩码 | 链上形如 `appr-202609********…`，按 record_id 查链失效 | 关联键改走 `technical=` 通道（S2-02 既定口径） | `test_record_id_queryable_on_chain` |
| 4 | `require_token` 把 actor 写入审计 ContextVar 却无法安全复位 | 身份泄漏到此后所有同线程请求；**既有** `test_audit_facade` 2 例失败（全量回归实测发现） | 只写 `flask.g`（复位的唯一正确挂点 `teardown_request` 被 Flask 3 禁止后注册；`after_this_request` 早于审计落账） | `TestNoIdentityLeak`（2 例） |

> 缺陷 4 的发现过程即「全量回归不可省」的直接证据：单元套件独立运行时 2 例失败不可复现，
> 只有全量顺序执行才暴露 ContextVar 泄漏。

## 六、S4 轨下游解锁（第二波就绪）

本任务交付的两项稳定接口，供 **S4-03 / S4-04** 直接消费：

### 6.1 审批落点（S4-03 熔断回滚与 Saga）

| 接口 | 形状 |
|---|---|
| 判定入口 | `agent.security.approval_guard.authorize(operation=..., actor_ctx=..., object_type=..., object_id=..., reason=..., second_factor_ok=..., risk=...) -> PermissionDecision` |
| 操作常量 | `OP_APPROVE / OP_DENY / OP_SWITCH_FORGE / OP_MODIFY_POLICY / OP_FORCE_STAGE / OP_REMOVE_SOURCE / OP_EXECUTE_CAPABILITY / OP_WRITE_MEMORY` |
| 扩展点 | `register_object_operation(object_type, operation)`（加行不改逻辑）、`register_rule(operation, actor_type, rule, override=)` |
| 结果对象 | `PermissionDecision.to_dict()`：`allowed / reason / operation / actor_type / matrix_hit / denied_by_matrix / requires_second_factor / requires_reason` |
| 回滚场景接线点 | 补偿/回滚属「治理写」⇒ 用 `OP_FORCE_STAGE` 行（human + reason 必填）；审批会话 token 可直接复用 `approval_session.get_session_store()` |

### 6.2 授权清单接口（S4-04 subagent 真实现）

| 接口 | 形状 |
|---|---|
| 执行体上下文 | `ActorContext(actor, actor_type="sub_agent", authorized_capabilities=frozenset({...}), scope=...)` |
| 判定语义 | `SCOPE_AUTHORIZED_SUBSET`：`capability_id ∉ authorized_capabilities` ⇒ 拒绝（`reason` 明示「仅限授权子集」），**未声明 capability 亦拒绝**（不默认放行） |
| 其余行 | 查看轨迹/记忆/面板 ❌；审批 ❌；写入记忆 ❌；提交审批提案 ❌ |
| 裁剪本体 | **不在本任务**：S4-04 负责生成 `authorized_capabilities` 与真实现工具裁剪；本任务只保证「清单外的调用一律被拒」 |
