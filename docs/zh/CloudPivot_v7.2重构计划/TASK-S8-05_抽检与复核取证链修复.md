# TASK-S8-05 抽检与复核取证链修复（队列完整性 / 适用性 / 归组键 / 裁定留痕）

> 所属阶段：**S8 生产化加固批次**｜依赖：S3-01（清洗与归组）、S3-02（判定集/沙箱）、S3-03（灰度与人工队列）、S1-02（backfill needs）｜预估：4–6 人日
> 来源：**2026-09-12 人工复核实操中暴露的 4 个机制缺陷 D1–D4** —— 详见 [`../人工复核裁定记录_20260912.md`](../人工复核裁定记录_20260912.md) §四

## 一、目标描述

2026-09-12 的人工复核实践中，**10 条抽检没有一条能真正裁决**（只能全部记 `uncertain`），暴露出"**取证链**"上的 4 个机制缺陷。本任务把它们修好，使**下一次人工复核是可裁决的**——这是"人工监督"能否真正成立的前提（v7.2 §7.0 审批矩阵依赖有效的人工判断，而非走过场）。

| # | 缺陷 | 现症 | 修复目标 |
|---|---|---|---|
| **D1** | 判定集重生成产生**孤儿引用**，队列不校验 | 3/10 条引用的 case 在判定集 5 个版本中均不存在（入队 09-11，判定集 09-12 重建） | 入队与读取时校验 case 存活；孤儿**显式标注失效**而非静默留在队列 |
| **D2** | **case↔capability 适用性未落地**：多能力任务链被归入单能力 | 7/10 条挂在 `cp.builtin.read_file`，实为 `read_file → shell_execute → write_file` 三步链路；`expected_output_schema` 为空 | 显式适用性判定（S3-02 遗留 #5 / M4）落地；**抽检取样按形状过滤** |
| **D3** | **`intent_key` 无区分度**：CJK 按字切分拼接 | 7 条 intent_key 完全相同（`产+仅+公+写+出+…`） | 归组键加入**结构性维度**（能力集合 + 步骤数档位），使"同类轨迹"判定可用 |
| **D4** | **人工裁定无留痕反馈**：规则重算不读已写入的 trust 值 | 2 条 data_class 已写入 `internal`，重算清单**仍报** DC-2；而 RK-5 因"改了内容"而**消失** → 清单**永久无法清空**，引发**复核疲劳**（v7.2 **R11**） | 引入**裁定留痕台账**，规则重算跳过已裁定项；已裁定项不再重复提醒 |

> **关键对比（D4 的本质）**：**"改内容"能被规则识别，"改 trust 值"不能。** 修复方向是让"人工裁定"成为规则可读的一等输入，而不是靠改内容绕开。

## 二、执行步骤

### 步骤 1（D1）队列完整性校验
- 在 `ManualReviewQueue`（`agent/digestion/shadow.py`）入队与读取路径加**存活校验**：
  - 入队时：case 不存在 → **拒绝入队**并记录事件（不得静默入队）；
  - 读取时：对已入队但 case 已消失的项，标记 `stale=true` + `stale_reason`（如 `case_missing_after_regeneration`），**保留记录但明确标为失效**（不得直接删除——留痕优先）；
- 判定集**重生成**路径（`CaseStore` 版本切换）联动：重生成后扫描队列，把受影响项转为 `stale`（并计入事件/审计）；
- 验收：造一个"入队后重生成判定集"的场景，断言该 case 被标为 `stale` 而非静默消失。

### 步骤 2（D2）适用性判定落地
- 为 `EquivalenceCase` 引入**显式适用性**：由 case 的 `upstream` 步骤集合推导 `applicable_capabilities`（本案：三步链 ⇒ 不适用于单能力 `read_file` 的等价判定）；
- 判定规则（写文档并单测）：
  - case 的 capability 集合 ⊋ 被评能力 → **不适用**（形状不匹配）；
  - `expected_output_schema` 为空且无 `expected_output` → 层① 无依据 → 标 `weak_contract`；
  - 多能力链仅在**链路级**评估中可用；
- **抽检取样按适用性过滤**：`sampling` 只从"与所评能力形状匹配"的用例中抽取（避免再次问错问题）；
- 验收：对 `cp.builtin.read_file` 重新采样，断言采出的用例均为单能力形状。

### 步骤 3（D3）归组键改进
- 现状 `intent_key`（`agent/digestion/cleaning.py::intent_key_for_trace` / `normalize_intent`）：CJK **按字切分**导致几乎所有任务同键；
- 改进方向（择一并说明取舍）：
  1. **结构化键优先**：`intent_key = hash(capability 集合) + 步骤数档位 + 结果状态`，把文本意图降为辅助维度；
  2. **受控词表**：若引入受控词典，需版本化并在报告中披露（S3-01 遗留 #3 的取舍理由需重新评估）；
  3. 若保留按字切分，则**必须**加结构维度兜底，避免"同键不同任务"。
- 验收：用 S7-05 的 7 条真实用例回归，断言它们**不再与无关任务同键**；并给出"改进前后同键冲突率"对比。

### 步骤 4（D4）裁定留痕台账
- 新增 `agent/digestion/resolutions.py`（或 `agent/descriptors/resolutions.py`）：
  - `ResolutionRecord`：`{scope, asset_id/case_id, rule, verdict, decided_by, decided_at, reason, evidence}`；
  - `ResolutionStore`：追加写（JSONL）+ 查询（按 `scope+asset_id+rule` 判定"是否已裁定"）；
- 接入两处：
  1. **needs 重算**（`agent/descriptors/backfill.py`）：规则命中但**已有人工裁定** → 不再列入 `needs_review`，改为在报告中单列"已裁定（N 条）/ 依据记录"；
  2. **抽检队列**：已裁定项不再重复入队；
- **审计联动**：每次裁定写 `audit.record(action="resolution.record", ...)`（可追溯、可验签）；
- **回执**：`--review-sheet` 与 needs 报告都要显示"已裁定项及其依据"，避免"看不清为什么消失"；
- 验收：把本次 6 条（4 provenance 保持 unknown + 2 data_class 已写入 internal）登记为已裁定 → 重算后 `needs_review` **应为 0 条**，且报告中能看到这 6 条的裁定依据。

### 步骤 5：回归与归档
- 新增单测：D1（孤儿标注/重生成联动）、D2（适用性规则/取样过滤）、D3（结构键/冲突率）、D4（台账写读/规则跳过/审计留痕）；
- 邻接回归：`digestion`（cleaning/cases/shadow/gate/service）、`descriptors`（backfill/registry）套件零回归；
- 端到端演示：**模拟一次完整的"入队 → 裁定 → 重算"闭环**，证明清单可被真实清空；
- 撰写 `TASK-S8-05_验收报告.md`。

## 三、预期成果

1. 队列完整性校验（`stale` 标注 + 重生成联动）。
2. 显式适用性判定 + 抽检取样过滤（不再问"错误的问题"）。
3. 归组键改进（结构维度）+ 冲突率对比数据。
4. `ResolutionStore` 裁定留痕台账 + needs/队列接入 + 审计联动。
5. 本次 6 条已裁定项登记并验证清单清空。
6. `TASK-S8-05_验收报告.md`（含"入队→裁定→重算"闭环演示）。

## 四、评估标准（验收清单）

- [ ] 【D1】入队时 case 不存在 → 拒绝并记事件；已入队但 case 消失 → 标 `stale` 且**不删除记录**
- [ ] 【D1】判定集重生成后，受影响队列项自动转 `stale`（含事件/审计），有单测
- [ ] 【D2】适用性字段可由 `upstream` 步骤集合推导；多能力链**不再**用于单能力等价判定
- [ ] 【D2】抽检取样按适用性过滤：对 `cp.builtin.read_file` 重新采样，采出用例均为单能力形状
- [ ] 【D3】归组键含结构维度；给出改进前后**同键冲突率**对比；S7-05 的 7 条不再与无关任务同键
- [ ] 【D4】`ResolutionStore` 可写可查；裁定记录入审计（`resolution.record`）
- [ ] 【D4】needs 重算跳过已裁定项，并在报告中**列出已裁定项与依据**（不得静默消失）
- [ ] 【D4】登记本次 6 条后，重算 `needs_review` = 0；抽检队列同样不重复提醒
- [ ] 端到端闭环演示可复现（入队 → 裁定 → 重算 → 清单清空）
- [ ] 既有 `digestion`/`descriptors` 套件零回归；新增单测全绿、覆盖率 ≥80%

## 五、明确不做

- ❌ 不修改既有已裁定结论（本次 6 条按裁定记录登记，**不得改写**）；
- ❌ 不为"清空清单"而放宽规则（规则该报的仍要报——只是**已裁定的不再重复报**）；
- ❌ 不引入外部依赖（分词库等）；若确需受控词表，须版本化并披露。
