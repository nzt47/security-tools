# TASK-S8-02 并发与运维加固（跨进程锁 + 决策日志轮转 + 多写者正确性）

> 所属阶段：**S8 生产化加固批次**｜依赖：S2-01（trace）、S2-02（审计链）、S2-03（events）、S3-01（消化）、S4-02（决策日志）｜预估：5–7 人日
> 来源：收官审计 §8.2 + S2-01 #6、S2-02 #5、S2-03 #11（跨进程并发写）、S3-01 #6（离线批处理无跨进程锁）、S4-02 L9/L10（决策日志无轮转）
> 验收报告归档于本目录 `docs/zh/CloudPivot_v7.2重构计划/`

## 一、目标描述

S2/S3/S4 的写入设施都建立在**"进程内单写者 + `busy_timeout` 兜底"**的假设上（生产 waitress 单进程时成立）。一旦出现**多进程**（开发脚本 + 服务同时跑、多个 worker、离线批处理并发），就可能出现重复 seq、写丢失、文件损坏、锁竞争。

本任务把"单进程假设"升级为**可证明的多进程安全**，并补上**决策日志轮转**这个纯运维缺口：

1. **统一跨进程锁原语**（复用既有实现，**不建第二套锁**）；
2. **覆盖全部写入路径**：统一 Trace 台账、链式审计、事件流、成本/决策日志；
3. **多写者正确性**：seq 分配、写丢失防护、损坏防护（有并发测试证明）；
4. **决策日志轮转**（按大小/日期 + 保留策略与 S8-01 联动 + 读分片兼容）；
5. **可观测**：锁等待/冲突/超时可度量（否则"加固了但不知道有没有生效"）。

## 二、执行步骤

### 步骤 1：写入路径盘点与风险分级
- 盘点全部写入点（含后台 writer 线程、离线脚本、批处理）：`UnifiedTraceStore`、`AuditChain`、`EventStore`、`DecisionLog`、`cost` 落盘、技能审计分片；
- 对每条路径标注：当前并发模型（进程内单写者 / 追加写 / WAL）/ 已有保护（`busy_timeout`、锁）/ **多进程下的失效模式**；
- 产出 `docs/zh/并发与写入路径盘点.md`（含失效模式与优先级）。

### 步骤 2：统一跨进程锁原语
- 复用既有原语：`agent/env_config_manager` / `knowledge.ingest` / `self_healing/watchdog_singleton` 已使用**非阻塞 OS 文件锁**模式——**统一到该模式**（提取为共享工具，勿复制第 N 份实现）；
- 提供两种语义：`try_lock()`（非阻塞，失败即退避/降级）与 `locked(timeout)`（有限等待）；
- **降级路径**：无法取锁时不得静默丢数据（写入队列 + 退避重试 + 超限后显式失败并告警/审计）。

### 步骤 3：多写者正确性
- **seq 分配**：审计链 seq 必须全局单调（跨进程）；实现方式（锁内分配 / 预留区间 / DB 事务）需说明取舍与失败语义；
- **写丢失防护**：队列满、进程崩溃、锁超时三种场景各有明确行为（记为事件/审计，不静默）；
- **损坏防护**：写入原子性（临时文件 + rename / DB 事务），校验和不匹配即隔离并告警。

### 步骤 4：决策日志轮转
- `DecisionLog` 增加轮转：按大小（阈值可配）或按日切分；**读侧已支持分片，保持兼容**；
- 轮转后的旧分片纳入 S8-01 的保留策略（归档而非删除）；
- 轮转不得改变决策统计口径（与 S8-01 步骤 4 同一验证方法）。

### 步骤 5：并发测试与回归
- **并发测试**（核心验收）：多进程（≥4）同时写入 → 断言：无重复 seq、无缺口（或缺口有据可查）、无损坏、总数守恒；
- 冲突场景：持锁进程被杀 → 锁可恢复（无死锁）；锁超时 → 显式失败并留痕；
- 性能：单进程写入 p99 **不退化**（与基线对比，允许小幅波动并标注 clock 口径）；
- 回归：`observability`/`audit`/`policy`/`digestion` 邻接套件零回归；
- 撰写 `TASK-S8-02_验收报告.md`。

## 四、评估标准（验收清单）

- [ ] 写入路径盘点覆盖全部落盘点，失效模式逐条标注

- [ ] 单进程写入 p99 不退化（附对照数据与 clock 口径）

- [ ] 既有 `observability`/`audit`/`policy`/`digestion` 套件零回归；新增单测全绿、覆盖率 ≥80%

## 五、说明

- 若审计 seq 采用"预留区间"方案，**必须**说明崩溃后区间空洞的语义（空洞可见、可解释，不得造成"链断"误判）——链式哈希校验必须仍能通过。
- 本任务**不引入外部依赖**（Redis/etcd 锁等）；单机文件锁 + 队列即可满足当前形态。
