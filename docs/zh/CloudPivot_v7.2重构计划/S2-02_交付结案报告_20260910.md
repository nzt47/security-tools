## 4. 遇到的问题与解决方案

### 4.1 问题 1：`reset_audit_chains()` 竞态导致 seq 撞车（自测暴露，已修复）

- **现象**：回归运行中出现 `UNIQUE constraint failed: audit_chain.seq`，链被迫降级到 ring buffer。
- **根因**：`reset_audit_chains()` 原实现「先清空登记表、再逐个 close」，期间另一处
  （Agent 侧钩子）可创建**新 writer**，而旧 writer 尚在 flush 未落盘记录 → 新旧 writer
  各自按不同 max(seq) 起链，并发写同一路径。
- **修复**：改为**先关闭、后清登记**，且全程持登记锁（`_REGISTRY_LOCK`），
  `get_audit_chain()` / `_acquire_writer_slot()` 与之串行化；另加
  `_resync_seq()` + `sqlite3.IntegrityError` 专分支（记录进 ring buffer + **显式 error 告警**，
  不静默丢弃、不永久降级）。
- **回归护栏**：`test_concurrent_appends_unique_seqs_no_race`（8 线程 × 25 条）、
  `TestSingleWriter` 6 例。

### 4.2 问题 2：文件库常驻 sqlite 连接占住台账 + 破坏既有集成测试 teardown（回归，已修复）

- **现象**：`tests/integration/test_audit_trace.py` 的 `teardown_method`（`shutil.rmtree`
  删除 `./test_audit_integration`）在 Windows 上报 `PermissionError [WinError 32]`，
  2 个既有用例由 pass 变 ERROR。
- **根因**：① 链式台账原用**线程本地常驻连接**，空闲时仍占住 `audit_chain.db`；
  ② 双写路径为纯异步，`AuditLogger.log()` 返回时后台 writer 可能正在写（句柄瞬时占用）；
  ③ 后台 `auto_seal` 每批都开库查询。
- **修复**：① 文件库**用完即关**（`_connect()` 上下文，仅 `:memory:` 常驻）；
  ② `AuditLogger` 双写后 `flush_on_write=True`（写入即耐久，返回即无句柄）；
  ③ `_maybe_auto_seal()` 改用**内存内最后一条 ts** 判定跨日，不再每批开库。
- **验收**：该集成用例恢复 2 passed；本轮 1373 例回归 0 failed；新增
  `test_no_persistent_file_handle_when_idle`（close 后可直接删除台账文件）。

### 4.3 问题 3：脱敏启发式误伤关联键，双写两轨无法对齐（自测暴露，已修复）

- **现象**：`LegacyTrack.verify_consistency()` 一致率仅 40%（5 条里 2 条匹配）。
- **根因**：`sensitive_data_filter` 会把 **24 位 hex 随机串**部分掩码
  （实测 `71420114895d4c9997****ef`），而 `audit_ref` 关联键正是 24 位 hex →
  旧轨键与新链键不再相等。
- **修复**：门面新增 `technical` 通道（**不经脱敏**，仅放内部生成的技术键），
  `audit_ref`/`audit_track` 走该通道；并加不变性测试
  `test_correlation_key_not_mangled_by_redaction`（断言键内无 `*`）。
- **文档化**：列入验收报告 §五 D6 与遗留 #6（`technical` 通道须代码评审守住"只放内部生成值"）。

### 4.4 问题 4：每日根「封印后追加」造成误报（CLI 实跑暴露，语义修正）

- **现象**：演示台账先封印 13 条、再追加 200 条性能探针 → CLI 报
  `每日根 FAILED（root_hash_mismatch）`，退出码 1。
- **根因**：原重放按「当日全部记录」重算，而封印本质是**当时链头的前缀快照**。
- **修复**：根记录已含 `first_seq/last_seq`，重放改为**只覆盖封印区间**；并补
  `leaf_count` 一致性校验（区间内被删/插入 → `leaf_count_mismatch`）。
- **结果**：封印后追加不再误报（CLI exit 0），区间内删改仍必检出
  （`root_hash_mismatch` / `leaf_count_mismatch` / `entry_hash_mismatch`）；
  另加「攻击者重算外层根链仍无法伪造 ed25519 签名」的对抗用例。

### 4.5 问题 5：盘点遗漏两个审计写入面（后台盘点复查暴露，已补齐）

- **现象**：首轮盘点把 `logging_utils.AuditLogger`（7 个敏感操作方法，写文本 `logs/audit.log`）
  与 `env_config_manager._audit_log`（写 `logs/config_audit.jsonl`）笼统归入"其他 JSONL"。
- **影响**：两者正对应任务书点名的「**策略变更 / 设置修改**」面——配置访问/修改、权限变更、
  认证尝试、加密密钥访问、`.env` 变更此前**不在链上**。
- **修复**：`logging_utils.AuditLogger` 新增 `_chain_audit()` 助手并接入 7 个方法
  （`config.access`/`config.modify`/`config.secure_access`/`config.encryption_key_access`/
  `permission.change`/`auth.attempt`/`sensitive.operation`）；`env_config_manager._audit_log`
  接入（`config.env_set`/`config.env_delete`）；演示脚本同步补演；报告盘点表由 8 行扩至
  **12 行**（含未接链项的显式口径与理由）。
- **验证**：新增 3 例集成测试（含"只记字段名不记值"与 IP 沿用仓库脱敏口径断言）。

### 4.6 问题 6：`@audit_action` 落账时机与状态码提取（自测暴露，已修正）

- **现象**：① 显式装饰器在视图**之前**落账 → 审计记不到结果（成功/4xx/5xx 全军覆没为 `ok`）；
  ② Flask 视图返回 `(body, 500)` 元组时状态码提取为 0。
- **修复**：装饰器改为**先执行视图、再按结果落账**（`ok`/`rejected`/`error`/`exception` +
  `status_code`），异常时记 `exception` 后原样抛出；新增 `_response_status_code()`
  兼容 `Response` 对象 / 元组 / 状态串三种返回形态。
