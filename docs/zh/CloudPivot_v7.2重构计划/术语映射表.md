## 1. 消化对象三层说明（对应 T8 与 TASK-S0-02）

v7.2 状态机主语（Tool/Capability）与 SKILL.md 编排对象分层不清；云枢把"被消化/被固化"资产
明确为三层（详细盘点与状态机作用域见 TASK-S0-02 及其验收报告）：

| 层 | 云枢载体 | 现状生命周期 | 与 v7.2 对应 | 状态机适用 |
|---|---|---|---|---|
| L1 原子工具/Capability | 运行时技能/工具、MCP 工具（`mcp_adapter.py`）、内置 capability | 启用/停用 | ToolDescriptor 对象（cp.<source>.<upstream>） | 最接近七态主体；borrowed→mirrored 门槛（轨迹≥20）在此层可测 |
| L2 工作流序列 | `workflow_learning` LearnedWorkflow（`data/learned_workflows.json`）+ `process_distill` 产物 | workflow→Skill 升格（skill_converter 质量门控） | "轨迹→Skill"中间形态 | 建议**不入七态**，作为 L1→L3 过渡轨（轨迹/模式挖掘的原料层） |
| L3 SKILL.md 编排资产 | `skills_mgmt` Skill（JSON 轨 + skills_repo 文件轨） | DRAFT→PENDING_REVIEW→APPROVED/PUBLISHED→DEPRECATED→ARCHIVED | v7.2 SKILL.md（§3.7）最终编排单元 | 发布轨与七态**正交**（evolution.stage 叠加，详 TASK-S0-02 结论 §3.4）；draft≈borrowed 仅对外来导入近似成立；shadow/灰度窗插 published 之前、internalized/native 为 evolution.stage 值，均由 S3 增补；不破坏现有语义 |

> 术语纪律：v7.2 的七态消化统一称**内化流水线（Internalization）**；不再使用 digest 一词。

## 3. digest 更名裁定（用户已确认方向）与实施对照

### 3.1 一句话裁定

> 云枢现有 **digest（评审语义）** 全面更名为 **review / assess 系**；v7.2 **digest（七态内化语义）**
> 后续统一称**内化流水线（Internalization）**——**digest 一词从此不再表示任何评审/内化语义**，
> 全库仅剩兼容别名与注释说明（TASK-S0-01 验收 #3 口径）。

### 3.2 更名对照表（实施基准）

| # | 旧名（digest=评审） | 新名（canonical） | 兼容策略 |
|---|---|---|---|
| 1 | `SkillDigestAssessor`（assessor.py 类） | `SkillAssessor` | 模块级别名 `SkillDigestAssessor = SkillAssessor`（deprecated） |
| 2 | `DigestAssessment`（assessor.py dataclass） | `AssessmentResult` | 模块级别名 `DigestAssessment = AssessmentResult` |
| 3 | `digest_flag/digest_int/digest_list/digest_blocking_severities` | `assess_flag/assess_int/assess_list/blocking_severities` | 旧函数保留为 deprecated 别名（委托新函数） |
| 4 | 开关环境变量前缀 `SKILLS_DIGEST_<KEY>` | `SKILLS_ASSESS_<KEY>` | 读取时旧前缀兜底；旧键名经 `auto_digest_after_workflow_convert`→`auto_review_after_workflow_convert` 映射 |
| 5 | 配置节 `config.yaml skills_mgmt.digest.<key>` | `skills_mgmt.assess.<key>` | 读取时旧节兜底 |
| 6 | `svc.digest_skill()` | `svc.review_skill()`（权威评审，含三审+扩展评估） | `digest_skill()` 保留为 deprecated 别名（docstring 标注"评审语义，与 v7.2 内化语义无关"） |
| 7 | `svc.digest_all()` | `svc.assess_all()`（批量咨询性自动评估） | `digest_all()` deprecated 别名 |
| 8 | `svc.digest_events()/digest_events_since()/digest_feed()` | `svc.assessment_events()/assessment_events_since()/assessment_feed()` | 旧方法 deprecated 别名 |
| 9 | `svc._advisory_digest/_emit_digest_event` | `svc._advisory_assess/_emit_assessment_event` | 私有方法，内部全量改用新名（不留别名） |
| 10 | `ReviewResult.digest_verdict`（字段/JSON 键） | `ReviewResult.review_verdict`（ok/block） | 旧数据读入兼容（model_validator 映射）；Python property `digest_verdict` 读写别名；评审/评估端点响应双发 `review_verdict`+`digest_verdict` ≤1 minor |
| 11 | 事件文件 `data/skills_digest_events.jsonl`（+按日归档 `-YYYY-MM-DD.jsonl`） | `data/skills_assessment_events.jsonl` | 首用迁移（copy 旧→新，旧文件只读保留）；读取旧兜底；归档旧档只读兼容 |
| 12 | 路由组 `/api/skills-mgmt/digest/*`（run-all/curate/merge-safe/merge-backups/feed/merge-undo/events/stream/<skill_id>） | `/api/skills-mgmt/assess/*` | 新旧路由同 handler 双注册（旧路由 deprecated，响应不变）；前端切换新路由 |
| 13 | 工作流转换参数/结果 `auto_digest` / `digest:{verdict,status}` / `digest_verdict` 视图 | `auto_review` / `review:{verdict,status}` / `review_verdict` 视图 | 入参同时接受旧键；结果双发 `review`+`digest` ≤1 minor |
| 14 | UI 组件 `SkillDigestManager`（`skill-digest-manager.tsx`） | `SkillAssessManager`（`skill-assess-manager.tsx`） | 更新 import/引用；UI 文案"评审-消化/消化动态"→"评审-评估/评估动态" |
| 15 | 分类关键词 `digest`（categorizer：generic token 与"记忆与知识"种子关键词） | 保持不变 | **非评审语义使用点**（摘要/通用词），加注释说明；不在更名范围 |

### 3.3 兼容窗口与移除时机

- 对外（路由/方法/JSON 兼容键/存储旧档）：**新名为主 + 旧名别名双通**，至少一个 minor
  版本（本提交起 ≥1 个 minor）后再择机移除旧名；移除前须先发 Deprecation 公告。
- 内部（私有方法/注释/UI 文案）：本提交即收敛，不留旧名。
- 事件文件：≤1 版本内双读；迁移后旧文件只读保留，不删除。

## 4. 兼容验证要点（对应 TASK-S0-01 验收 #4）

1. 旧 Python 名（`SkillDigestAssessor`/`digest_skill`/`digest_all`/`digest_events`/`digest_feed`/
   `digest_verdict` 属性）在 `SkillAssessor`/`review_skill`/`assess_all`/`assessment_*`/`review_verdict`
   新名存在时仍可调用。
2. 旧路由 `/api/skills-mgmt/digest/*` 仍 200 且响应与新路由一致（同 handler）。
3. 旧存储：含 `review.digest_verdict` 的技能 JSON 可正常读入（归一为 `review_verdict`）；
   `skills_digest_events.jsonl` 内容在改名后可读（首用迁移/兜底读）。
4. 新代码写出的数据只含新键（`review_verdict` / `skills_assessment_events.jsonl`）。

## 5. 术语纪律（后续任务引用规则）

1. 正文/UI/提交消息一律使用本表新名；`digest` 仅允许出现在：兼容别名定义、deprecated
   注释（含"与 v7.2 内化语义无关"标注）、历史文档加注、归档文件名/旧档。
2. "内化"一词专指 v7.2 七态内化流水线（Internalization）方向，禁止与"评审/评估"混用。
3. 新增机制命名先查本表；未覆盖的概念走 RFC（v7.2 §13.1 引用规范）。
