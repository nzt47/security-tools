## 二、交付物与落点

```
agent/repair/
  policy.py      只读区黑名单 + 范围/预算阈值（唯一权威；CP_REPAIR_* 可覆盖，非法值回退）
  models.py      五步数据模型（14 个 dataclass；审计载荷只放叶子字段）
  gitio.py       只读 git 白名单 + 唯一写操作 create_local_branch()
  trace.py       RepairRunLogger：五步各一条 Trace + 链式审计（成功/失败/异常三路径）
  budget.py      预算令牌与轮次上限（超限抛异常硬停）
  diagnose.py    体检三件套：pytest+junitxml / L0 锚 / 可选审计快照
  locate.py      源码切片（带真实行号）+ import 反推实现 + Trace/descriptor/近期改动聚合
  guardrails.py  统一 diff 解析 + 只读区/文件数/行数硬闸 + 改测试机械识别
  delegate.py    八要素组装 + 委派通道复用 + 工具裁剪断言 + 取补丁后立刻过护栏
  patchapply.py  统一 diff 应用器（内存全成功才落盘；不做模糊匹配）
  verify.py      临时副本 + 三关（before 必须失败 / target fail→pass / L0 锚 / 邻接回归）
  propose.py     本地分支 + 补丁 + PR 描述（含强制披露与 undo_hint）；未验证即结构性拒绝
  pipeline.py    五步编排 + 预算轮次闸门 + 审计完整性判定 + 报告渲染
scripts/
  self_repair.py          手动入口（体检 / 完整流程；--channel stub 供无凭据环境）
  demo_s7_02_repair.py    端到端演示（inject / apply 两阶段）
  repair_demo_support.py  演示沙箱构造（**刻意不在 agent/repair 内**：见下）
```

**为什么演示沙箱工具放在 `scripts/` 而不是生产包**：演示需要 `git init/add/commit` 造数，而生产包的
"无 push / 无 merge"源码扫描是**全包**级别的。把造数代码放进生产包，要么误报、要么被迫放宽扫描。
边界因此明确：`agent/repair/` = 只读 git + 唯一本地分支写操作；`scripts/` = 可造数，但绝不触碰交付工作区。

## 三、四条宪法式边界的落点（概要，逐条证据见验收报告 §三）

| 边界 | 落点 | 反向证据 |
|---|---|---|
| ① 不自动 push / 合并 | 只读子命令白名单；唯一写操作只建**本地引用**；`pushed/merged` 恒 False；数据类里不存在 remote/pr_url 字段 | `test_repair_no_push.py` 22 例（源码扫描 + 运行时探针 + 数据模型三重自证） |
| ② 不碰只读区 | `core/auth/`·`core/audit/`·`schema/`·`agent/security/`·`agent/audit/chain.py`·`eval/l0_anchor/` + 审计/签名文件名模式（fail-closed）；命中即整包丢弃 | `test_repair_guards.py` 参数化 8 命中 / 6 不命中；护栏拒绝的补丁**不进验证**（`run_anchor` 零调用） |
| ③ 验证不过不产出 | `propose()` 未验证即抛 `ProposalNotVerified`（结构性拒绝，pipeline 无法绕过）；未运行/跳过一律 fail-closed | `TestProposalGate` 3 例（异常 + **零产物落盘**）；`test_verification_failure_discards_everything` |
| ④ 全程可审计 | `run_step()` 三路径必留痕；`record_step()` 缺省自生成 trace_id；`audit_completeness()` 机械判定 | 端到端五步 seq 324→329 连续、`chain_ok=true`；异常路径也留痕且原样重抛 |

## 四、实现期修复的真实缺陷（5 处）

| # | 缺陷 | 表现 | 修复 |
|---|---|---|---|
| 1 | junit `classname` 不是 pytest 节点 id | 目标用例闸门恒"失败"（实为 `no tests ran` 选不中） | `verify.node_target()`：点分名 → `文件路径::函数名` |
| 2 | 旧 `__pycache__` 串味 | 沙箱复用时 pytest `collection failure`（导入到上一版模块） | `repair_demo_support.purge_pycache()` 复制后清理 |
| 3 | Windows 被占用目录 `rmtree` 静默失败 | `shutil.move` 把副本**嵌套**进已存在目录，后续路径全错 | 沙箱构建对已存在目标根显式报错 + 移动后结构校验 |
| 4 | 指纹归一化过度 | `assert x == 2` 与 `== 3` 撞同一指纹，归并视图失效 | 只抹跨机器不稳定片段（路径/地址/耗时），保留数字 |
| 5 | Trace 查询看不到本次运行记录 | `UnifiedTraceStore` 入队即返回、后台批量写；不 flush 查询恒空 | `locate.trace_chain_leaf()` 查询前 `flush()` |

## 八、提交与双远端

- worktree：`.worktrees/s702`，分支 `s702/main`
- 合并方式：回主工作区 `git merge s702/main`（**仅 fast-forward / 无毒合并**）
- 双远端：`git push origin master` + `git push gitee master`（同点 SHA 见回报）

> 本任务**自身**不执行任何 push 到远端分支的自动动作；推送是**人工交付步骤**，与产品内的
> 「不自动 push」边界是两件事（前者是本次交付，后者是本任务所交付能力的边界）。
