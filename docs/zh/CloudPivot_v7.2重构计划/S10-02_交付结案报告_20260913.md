## 三、口径声明（任务书第 4 条：先报告、再动）

接入是否会改变既有灰度统计口径？**分三种情形，前两种已实测，第三种是明确的行为差异、在此显式声明**：

1. **开关关（默认）**：**零口径变化**。注入器返回 `None`，`ShadowRunner` 走的代码路径与接入前完全一致；
   实测两份规范化报告 JSON 的 SHA256 **完全相同**（§四.2）。
2. **开关开 + 判定器全程可用**：`judge_kind` 由既有的**粗标签** `llm_judge`（`resolve_judge("auto")`
   的 LLM 分支，**没有**预算护栏）变为**精确标签** `llm:<provider>:<model>`，并新增三件事：
   每日预算前置拦截、UTC `source="judge"` 分栏计费、judge 判定独立存档。
   `is_llm_kind()` 把两者归同一族，故**族级统计（是否 LLM-judge）不变**；变的只是"可复盘到哪个模型"
   与"成本有护栏"。这正是 S8-04 已声明的设计，也是本任务的**目标**。
3. **开关开 + 批内回落**（需要显式声明的差异）：预算超限 / 断食 / 通道故障会在**批内**把
   `judge_kind` 切换为 `deterministic_local(<原因码>)`，且**逐样本如实同步**。
   因此同一次灰度可能出现**不止一个** `judge_kind` 取值，层③软性判定从而可能变化 ⇒
   `pass_rate`／劣化信号与"全 LLM 判定"不再逐字等价。
   本次 3 样本实测中三条路径的 `pass_rate` 均为 1.0（未观察到差异），但该可能性**必须**被告知：
   这是"预算护栏生效"的**必然结果**（省的是钱、不是标签），若要"要么全 LLM 要么整批不用"的
   另一种口径，属于**新的口径决策**，本批不做。

**另一条未动的既有行为（如实披露）**：开关关时，灰度判定器仍由既有 `resolve_judge("auto")` 决定 ——
若部署级 `LLM_*` 环境齐备，**既有 auto 路径仍可能选中 LLM 且没有预算护栏**。
实测（§四.4）确认这条路径的语义**未因本次改动而变化**。收紧它属于口径变更，需另行声明，本批不做。
