## 4. 遇到的问题与解决方案（实现期实测）

> 全部为**实现/联调期真实踩到**的问题，逐条附根因与回归证据。

### 4.1 问题 1：judge 通道一断，整批样本被误判成"负例"（已修复）

| 项 | 内容 |
|---|---|
| 现象 | LLM-judge 通道异常（无凭证/限流）时，`diff_judge` 把每次异常都记成**层③失败** ⇒ 全部样本成负例 ⇒ 触发**虚假的劣化信号**（R4 误报） |
| 根因 | `diff_judge` 的语义是"judge 失败 = 该层不通过"，而灰度期的"通道不可用"与"语义不等价"是两件事 |
| 修复 | 新增 `JudgeGuard`：灰度**开始前**一次端到端探针（`probe()`），失败即回落确定性打分器并把 `judge_kind` 标注为 `deterministic_local(llm_unavailable)`；运行中再失败同样回落并计数 |
| 验证 | `test_runner_uses_fallback_label_without_false_negatives`（回落 + **负例=0**）、`test_judge_guard_probe_falls_back_on_broken_llm`、`test_judge_guard_falls_back_mid_run`；`test_runner_uses_llm_label_with_healthy_channel`（正常通道走 `llm_judge`） |

### 4.2 问题 2：手动通道"人工批准后仍不放行"——`evidence_for_stage()` 未按决策键包裹（已修复）

| 项 | 内容 |
|---|---|
| 现象 | 演示首跑：`confirm_manual_promote` 成功（state=approved），但 `apply_manual_promote` 返回 `applied=False`，理由是"shadow → internalized 的门控属…不越权推进" |
| 根因 | `stage.evaluate_migration()` 只在**显式带上** `INTERNALIZE_DECISION_KEY` 时走 opt-in 分支；而首版 `evidence_for_stage()` 返回的是**决策载荷本身**，没有外层键 ⇒ stage 门视为"无证据" |
| 修复 | `evidence_for_stage()` 改为返回 `{stage.INTERNALIZE_DECISION_KEY: {...}}`；同时给决策载荷加 `manual_allowed_failed` 字段，让 stage 门对人工路径做**严格**校验（只允许约定条件未通过，列表外任何失败一律拒绝） |
| 验证 | `test_manual_with_approval_applies`、`test_manual_cannot_smuggle_unlisted_failure`、`test_manual_without_approval_is_refused`；演示步骤 6 打印 `applied=True` 与放行理由 |
| 经验 | 这是"**opt-in 证据门**"这类设计的典型接缝：**键名层级的错误会让门静默地退回默认行为**（宁可拒绝，也不误合——方向是对的，但必须被用例钉住） |

### 4.3 问题 3：适用性匹配过宽 ⇒ 排除清单会"误伤同类细粒度候选"（已修复）

| 项 | 内容 |
|---|---|
| 现象 | 单测发现 `implementation:upstream` 与 `implementation:candidate` **互相匹配**（都被归到基类 `implementation`） |
| 根因 | 首版规则"任一侧带 `:` 即按基类比较"过宽：两个**不同的具体实现**被判为同一候选 |
| 修复 | 规则收紧为：**基类标签 ↔ 细粒度标签**匹配；**两个细粒度标签**必须**完全相同**才匹配 |
| 验证 | `test_candidate_kind_matches_rules`、`test_detailed_kind_matches_base` |

### 4.4 问题 4：ROI 的"上游单位成本"拿不到（已修复 + 口径收紧）

| 项 | 内容 |
|---|---|
| 现象 | 演示首跑 ROI 报告显示"上游单位成本不可得 ⇒ ROI 不可判定"，而 S2-03 的 `cost_normalized_cents` 明明有值 |
| 根因 | `utc.utc_window()` 的 UTC 分母是 `task.closed/failed` 事件数；演示只埋了 `cost` 事件、**没埋任务闭合事件** ⇒ 分母 0 ⇒ `utc_cents_per_task=None` |
| 修复 | 演示按 S2-03 **双轨接线**补埋 `acr.record_task_closed()`；同时保留"缺值即**不给正值结论**"的诚实口径（`build_roi_report` 在缺上游成本时 `assumptions` 明写"不可判定"） |
| 验证 | `test_missing_upstream_cost_is_not_positive`、`test_formula_is_reproducible`；演示 ROI 表打印 UTC=0.042 分/任务与数据源 |
