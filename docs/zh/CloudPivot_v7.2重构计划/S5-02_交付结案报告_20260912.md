## 4. 关键设计决策（可追溯）

| # | 决策 | 理由 | 证据 |
|---|---|---|---|
| D1 | L0 锚放在仓库 `eval/` 而非 `data/` | "独立于系统数据目录"必须机器可验：锚与 6 个系统目录**双向互不包含** | `anchor.assert_independent_of_system_data()` + 6 条参数化单测 |
| D2 | 三层不可写（位置/API/哈希）而非只靠 OS 只读 | 仓库工作区无法施加 OS 级只读（git 要能改写），且 OS 只读不防"改了再改回来"；哈希锚定提供**内容级**证据 | `test_eval_anchor.py::TestSystemCannotWrite`（11 例）+ 篡改 5 类对照 |
| D3 | 参考解与能力成绩**物理分离**（`reference.json` + `solver` 字段 + 披露） | 防止"用参考解冒充模型成绩"这一自欺路径 | `run_l0(reference=True)` 强制追加披露；基线带 `solver` 字段 |
| D4 | 默认解算器 = `null`（未评测），而非参考解 | 无凭证环境下"未评测"才是事实；`pass_rate` 分母只含已评测用例 | `run_l0()` 缺省 → 20 unassessed / `pass_rate=None` |
| D5 | 变异解**参数感知**（读判定条目参数构造必然违反的取值） | 随机变异无法证明"每条判定都在干活"；参数感知变异使"逐条判负"成为可断言不变量 | `solvers.break_value()` + 310 条判定条目幸存 0 |
| D6 | 判定条目**路径不可解析即判负** | "答案里没有这个字段"就是不合格，不允许静默跳过 | `run_check()` fail-closed + 单测 |
| D7 | `python_probes` 受限命名空间（白名单内置） | 判定不执行任意代码 / 不触网 / 不调模型（无凭证环境下也能给出机械结论） | `SAFE_BUILTINS` + `import` 不可用单测 |
| D8 | 指标一律复用 `acr.py`/`utc.py`，不自建计数 | 口径只允许一个来源（换地方重算 = 制造第二个真相） | `metrics.py` 直接调 `acr_summary`/`utc_window`；`grep` 无新增权重表 |
| D9 | 样本 < 20 只披露不考核；数据源缺位记 `None` | 把"没数据"写成 0 会让报告说谎（审计 T5/T6 结论） | `_metric()` 的 `MIN_SAMPLES_FOR_ASSESSMENT` + 多例断言 |
| D10 | 难度权重切换需**四闸全绿**且默认关闭 | 口径纪律要求"先有基线数据再考核"；开关走 env，可零代码回滚 | `switch_status()` + `switch_checklist()`（5 步含回滚） |
| D11 | 符号检索改为**剪枝 + 语料缓存** | 首次全量抽查暴露"逐符号全树遍历"在并发负载下超时；改成一次遍历 + 内存检索 | 实测：语料 1.20s/4091 文件，后续检索 0.02s；相关套件由超时→6.00s 全绿 |
| D12 | 包内一律 `import agent.eval.<mod> as X`（禁 `from agent.eval import x`） | AST 依赖图把后者记为依赖**包根**，而包根导入子模块 → 被架构规则判为循环依赖（CI 阻断） | CI「架构规则校验」实测 4 处未豁免违规 → 修复后 passed=True/0；`TestPackageHygiene` 固化守护 |
| D13 | 锚哈希口径 = canonical JSON + **文本 LF 归一** | 本仓库 `core.autocrlf=true`：用原始字节会让"参考解被改动"的校验在 Windows/Linux 之间假阳性 | `anchor.text_sha256()` + `.gitattributes` 的 `eval/** text eol=lf` + `test_text_sha256_is_line_ending_independent` |
