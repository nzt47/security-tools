## 二、执行步骤

### 步骤 1（R1）：判定集构建成本计入 ROI
- 现状：`agent/digestion/internalize.py::ROIReport` 消费 `utc.utc_window()` 的成本，**不含**判定集构建开销（生成用例的 LLM 调用、人工抽检工时、回放算力）；
- 采集：判定集构建期间的成本事件（若未埋点则**补埋点**：`CaseStore` 构建路径记录 `cost` 事件，标注 `stage=case_build`）；
- 扩展 `ROIReport`：
  - 新增字段 `case_build_cost_cents`（可区间估计，须标注估计方法与样本）；
  - ROI 公式二选一并写清：**① 计入 `自研一次性投入` 参与摊销**；**② 单列披露不参与摊销**（避免污染"是否内化"的判断）——**建议 ②**，理由：判定集是一次性资产，混入摊销会扭曲月成本比较；
  - 报告与 PR 描述中同时给出不含/含判定集成本的两种 ROI（透明可对比）。
- 文档：在 `TASK-S7-...`/`PERF_BUDGET`/ROI 说明处更新公式与口径。

### 步骤 2（R4）：委派成功率机械信号清单
- 定义**机械可验信号**（优先级从高到低，写进 `agent/eval` 指标字典并在复评中执行）：
  1. **产物结构**：`task_file` 声明的产物格式是否**结构性通过**（schema/必需字段）；
  2. **测试/校验**：委派任务若涉代码，**目标用例是否从 fail→pass**（可执行的直接证据）；
  3. **副作用核对**：声明副作用 vs 实际副作用集合是否一致（复用 S3-02 `ReplaySandbox` 的比对能力）；
  4. **可回放性**：产物是否可被**重放复现**（同一输入同结果）；
  5. **LLM 复评（兜底）**：以上均不适用时使用，且**必须标注 `judge_kind`**、抽样人工校准（沿用 S3-02 M1 口径）。
- 接入：
  - `agent/subagent/` 回收三件套的**复评半边**改为"机械信号优先 + LLM 兜底"，并在 `Reflection` 结果中标注 `signal_kind`；
  - `agent/eval` 的委派回收率/成功率指标**区分口径**（`mechanical` / `llm` 两列，不得混算）；
  - 样本 <20 → 只披露不考核（S5-02 口径）。

### 步骤 3（R7）：单机降级设施表
- 产出 `docs/zh/单机降级设施表.md`，逐项列明：**v7.2 要求 → 单机实现 → 边界与已知缺口 → 升级路径（P5）**：

| 项 | v7.2 要求 | 云枢单机实现 | 缺口 / 升级 |
|---|---|---|---|
| Watchdog | 集群 + OS 服务注册 + 互 watch | `watchdog_singleton.py`（既有 SingletonManager + 非阻塞 OS 文件锁） | 集群仲裁 → P5 |
| 审计存储 | 每日 Merkle 根 → **外部只追加** | 本地受保护文件 + ed25519 签名 + 外层根链 | WORM/S3 Object Lock → P5；**删除链尾不可检出**如实标注 |
| 出域控制 | egress guard（进程外网络代理） | `guardrails/egress_guard.py`（进程内执行点）+ 网络层白名单 | 独立代理 → 部署侧 |
| 生成代码执行 | Docker 沙箱 | 进程内确定性回放模型（`ReplaySandbox`）+ 子进程环境隔离 | **真实执行型产物未容器化**（如实标注） |
| 策略引擎 | OPA/Rego + WASM | 等效声明式引擎（接口形状兼容替换） | 换 OPA → 按需 |
| 多租户 | 隔离验证 | workspace-hash 逻辑租户 + `.env` 单实例 | 真正的多租户 → P5 |
| 台账保留 | TTL / 冷归档 / 分库 | 现状无 TTL（多处同源遗留） | 生产化批次 |

- 表中每项都要指向**代码位置或验收报告**（可追溯），并标注"已验证/未验证"。
