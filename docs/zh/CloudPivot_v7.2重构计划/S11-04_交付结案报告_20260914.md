## 三、根因（代码行级）

1. **`agent/digestion/shadow.py:1281`（改前）** —— `resolve_judge` 的 `auto` 分支：
   ```python
   if llm.is_available():
       return ResolvedJudge(scorer=llm, kind=JUDGE_KIND_LLM, ...)
   ```
   判定依据只有"通道能否构造出来"，**从不读** `CP_DIGESTION_JUDGE_ENABLED`。同函数 `llm` 分支（`:1270-1274`）亦然。

2. **`agent/digestion/shadow.py:1269`（改前）** —— `llm = LLMJudge(invoke=invoke, provider=provider, model=model, base_url=base_url)`：既不传 `api_key`（不走 `judge_runtime` 的 SecretStore→env→.env 三级解析），也不挂 `JudgeBudgetGuard`（护栏此前**只**在 `judge_runtime.build_judge_runtime:1106` 建）。

3. **`agent/digestion/shadow.py:2433-2446`（改前）** —— `ShadowRunner.__init__`：开关关闭 ⇒ `judge_runtime_from_env()` 返回 `None` ⇒ 落回 `resolve_judge(...)`。也就是说 **"未启用"降级到的不是"更安全的确定性打分器"，而是"无护栏的真实通道"**。同一处 `:2469-2471` 用 `JudgeGuard(self.judge.scorer, kind_primary=self.judge.kind)` 建守卫，**没有** `precheck` / `on_call` / `kind_fallback_for`。

4. **注册表语义被旁路** —— `agent/settings/registry.py:1657` 把 `CP_DIGESTION_JUDGE_ENABLED` 定为 **`_b`（需二次认证的"真实 LLM-judge 总开关"）**，而 `:1669`/`:1672` 把 `CP_DIGESTION_JUDGE_PROVIDER`/`_MODEL` 定为 **`_a`（可直接切）**。代码却让一个 `_a` 键**单独**就能让真实调用开跑 ⇒ **总开关承诺失效**，且这条路径连成本都不入账。

## 四、口径变更声明（**必须先声明**，验收第 3 条附带要求）

**变更点 1（安全底线收紧）**：`resolve_judge` 在 `auto` 与显式 `llm` 两种模式下，**由适配器自建的真实通道**必须 `CP_DIGESTION_JUDGE_ENABLED=true` 才可入选；否则回落确定性打分器并**如实标注** `deterministic_local(disabled)`（原因取自既有词表）。
**变更点 2（护栏前移）**：入选链选中的真实通道现在同时受 `CP_DIGESTION_JUDGE_DAILY_BUDGET_CENTS` 约束 —— ①**入选时**先做一次前置检查（超预算/读不到/断食期 ⇒ 干脆不入选）；②入选后随附**调用前拦截 + UTC 记账 + 按原因精确回落**的接线（批内花光预算 ⇒ 逐样本标签跟着实际判定器走）。

**影响面（只影响"本来会开跑"的配置）**：

| 配置 | 改前 | 改后 |
|---|---|---|
| 无 `CP_DIGESTION_JUDGE_PROVIDER`/`_MODEL`（**含本部署**） | `deterministic_local(llm_unavailable)` | **逐字不变**（受 `test_s10_02_judge_wiring.py::test_flag_off_keeps_legacy_path` 与 `verify_shadow_judge_wiring.py` 双重看护） |
