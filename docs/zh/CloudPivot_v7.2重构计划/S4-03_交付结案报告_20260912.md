## 四、实现期发现并修复的真实缺陷（8 项 + 3 项判据修正）

| # | 缺陷 | 严重度 | 修复 |
|---|---|---|---|
| 1 | `boundary_words` 参数 `ttl_seconds` 遮蔽同名模块函数 → 机制 5 签发即崩 | 阻断级 | 别名 `_default_ttl_seconds`；回归用例 |
| 2 | `issue_to_ui()` 不接受 `ttl_seconds` | 接口缺陷 | 补参数（仍受 60s 硬上限） |
| 3 | `safe_render` 用 `convert_charrefs=True` 把实体解码后**原样输出** → `&#60;script&#62;` 还原为可执行 `<script>` | **真实 XSS** | `handle_data` 恒转义；5 变体严格用例（无 xfail） |
| 4 | 被禁标签区间内白名单子标签被原样输出（`<form><p>x</p></form>`） | 中 | 三个回调一律先看 `_escape_depth` |
| 5 | 上条修复第一版嵌套计数不平衡（`</script>` 不递减）→ 之后内容被无限期转义 | 中（修复引入） | 增减严格对称 + `handle_startendtag` 净零 + `TestEscapeDepthBalance`（10 例） |
| 6 | `foreign_taint` 标记存**规范化明文**，违反自身"只存摘要"隐私声明 | 中（契约违反） | 字段改 `digests`（`sha256:…`），明文只在调用栈内存活 |
| 7 | Windows 字节锁拒读被锁字节 → 持有期内 `read_holder()` 为空（恰最需要时） | 中 | 身份定长槽移字节 1 起，读取 `seek(1)` 跳过锁区间 |
| 8 | `open(path,"a+")` 追加模式使 `seek()` 对写无效 → 身份被追加到 EOF、`read_holder()` 返回上一个持有者、文件每次 acquire 增长 513B | 中 | `os.open(O_RDWR[|O_CREAT])` + `os.fdopen(fd,"r+b")`；实测 513B 恒定、pid 正确覆写 |

**判据修正 3 项**（由独立测试会话报告、经复核后修正代码而非测试）：
`levels.escalate()` 未知输入曾回退 **L5**（最重动作）→ 改回退 L1；
`saga.state_from_journal()` 固定优先级致"confirm 后又被补偿"反推为 `confirmed` → 改逆序扫描（最新一步说了算）；
`saga.recover()` 会补偿**已 confirm** 的事务 → 改终态跳过（不撤销已提交事务）；
`saga.compensate(escalate_on_failure=False)` 三处事实互相矛盾 → 新增 `COMPENSATION_FAILED` 状态；
`watchdog.is_stale()` 的 pid 门槛使 Windows 永远判不出陈旧 → 改以"能否拿到 OS 锁"为权威；
`stale_evidence()` 在锁文件缺失时**创建文件**并自相矛盾 → 诊断路径 `create=False`。

> 这些"由测试会话发现、由实现会话修复"的往返本身是可复用经验：
> **缺陷报告里最值钱的是"能复现 + 能说清影响"**，而不是修好的代码。
