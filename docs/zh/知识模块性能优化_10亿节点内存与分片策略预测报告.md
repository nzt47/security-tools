## 2. 10 亿节点分片策略

### 2.1 片数权衡（1 亿 → 10 亿演进）

| 片数 | 单片 refs 驻留 | 并行全扫（理想） | 判定 |
|---|---|---|---|
| 1024 | ≈125 MB | ≈220 秒 | 单片偏高 |
| 2048 | ≈62.5 MB | ≈110 秒 | 可行 |
| **4096** | **≈31 MB** | **≈55 秒** | **推荐** |
| 8192 | ≈15.6 MB | ≈27 秒 | 过度分片（路由/元数据成本主导） |

**推荐 4096 片**：单片 31 MB 可整片常驻单机；4096 片可分布到 64–256 台节点（每机 16–64 片），承载 refs 128 GB 总量。

### 2.2 集群拓扑（两级路由）

```
shard_id     = hash(ref_slug) % 4096        # 一级：逻辑分片
node_owner   = consistent_hash(shard_id)    # 二级：一致性哈希 → 物理节点
```

- 两级路由解耦「逻辑分片数」与「物理节点数」，节点扩缩容只影响二级映射（一致性哈希最小迁移）；
- 写路径：add/remove → 一级路由 → 二级定位节点，单片读写；
- 读路径：`_has_incoming_links` 跨片合并 → 依赖**入链预聚合层**（倒排索引服务，如 KV/列存），查表 O(1) 语义保留；
- 一致性：最终一致（写重放 + 对账任务），片级「叠加 == 重建」断言 + 跨片对账双保险。

### 2.3 降级机制映射（10 亿）

| 降级机制 | 1 亿（512 片分布式） | 10 亿（4096 片集群） |
|---|---|---|
| 索引损坏回退 | 单片秒级 | 单片秒级 + 副本重拉（建议每片 2–3 副本） |
| 写失败不阻断 | 不变 | 不变（重放队列 + 幂等写，保持「增量叠加 == 重建」） |
| 全量重建 | Map-Reduce 分钟级 | Map-Reduce 并行（Map 按片分发、Reduce 全局合并） |
| 全局对账 | 片级 + 跨片 | 分布式对账任务（定期抽样核对） |

## 3. 存储层：10 亿文件的必然形态

| 项 | 数值 | 影响 |
|---|---|---|
| 卡片文件 | 10 亿个 `.md` | 单机文件系统不可行，必须对象存储 |
| 对象存储 key | `cards/<type>/<slug 前 2>/<slug>.md` | 前缀分桶（256×3 桶），list/遍历走前缀扫描 |
| refs 索引 | 4096 片对象 + 副本 | 片上二级前缀索引（`<shard>/<prefix>.idx`） |
| 遍历基准 | 0.225 ms/卡 失效 | 对象存储 list 需批量 API + 分页，基准待实测标定 |

**结论**：10 亿节点存储 = 对象存储（分桶）+ 副本（2–3），「全库 list()/重建」改为对象存储前缀扫描，遍历基准需重新建立（预计远大于单机外推，真实全扫时间以实测为准）。

## 6. 结论与建议

| 决策维度 | 10 亿节点评估 |
|---|---|
| 内存（现状） | ≈1.86 TB：完全不可行 |
| 内存（流式单机） | ≈128 GB：refs 总量超单机 |
| 内存（分片 4096 集群） | ≈31 MB/片：可控 |
| 耗时（全扫） | 流式 2.6 天 vs 分片并行理想 55 秒 |
| 存储 | 10 亿文件 → **对象存储（分桶）+ 副本** |
| 架构判定 | **集群化分布式架构（互联网规模）** |

**建议**：

1. **4096 片 + 一致性哈希二级路由**：逻辑分片与物理节点解耦，扩缩容最小迁移；写路径单片路由、读路径入链预聚合层（倒排索引服务）。
2. **存储对象化 + 副本**：对象存储分桶（`cards/<type>/<前缀>/<slug>`）；索引片 2–3 副本，节点故障由副本接管。
3. **一致性工程化**：最终一致 + 写重放（幂等）+ 分布式对账；片级「增量叠加 == 重建」断言自动化扩展为集群对账任务。
4. **可观测与运维**：分片健康监控（每片损坏/滞后告警）、容量水位（refs 总量/片均负载）、重建任务调度与进度可视化。
5. **架构落地节奏**：流式（≤200 万）→ 单机分片（200 万–5000 万）→ 分布式（5000 万–1 亿）→ 集群化 + 对象存储（1 亿–10 亿）。10 亿为互联网规模，属前瞻规划，当前工程按 ≤200 万执行线落地流式即可。

- 实测：3000 卡 rebuild 全峰值 5.6 MB；入链判定全扫 2249 ms/1 万卡、查表 1.07 ms（《第二批对比报告》）
- 合成实验：refs dict 10 万 key/20 万条目 = 12.8 MB（tracemalloc，2026-08-08）
- 外推：线性；分片并行/集群时间为理想化下界，未计网络/调度/合并/对账开销，真实约 2–4x 上浮；对象存储遍历与预聚合层读延迟待实测标定
