# 并行会话 Worktree 隔离规范（团队约定）

> 事件复盘：2026-08-15 并行会话误切分支导致工作区文件丢失与多次提交失败
> 规范生效：2026-08-15
> 适用范围：所有在共享仓库 `c:\Users\Administrator\agent` 上开展的并行开发/修复会话

## 2. 根因分析

共享仓库的 `.git` 目录存在**全局单例状态**，并行会话并发操作时互相干扰：

| 共享状态 | 竞争现象 |
|---|---|
| `.git/index`（暂存区） | 会话 A `git add` 后被会话 B 的 commit/reset 覆盖或清空 → "no changes added to commit"；已 staged 内容被对方连带提交 |
| `HEAD` / 分支引用 | 会话 B `git checkout master` 移动 HEAD → 会话 A 的工作区文件被 git 按目标分支重建（跟踪文件被删/回退） |
| `.git/worktrees` 注册 | worktree add/remove 非原子 → "分支已存在但 reflog 显示是自己创建的" |
| 工作区文件（共享） | `checkout`/`reset --hard` 直接改写磁盘文件，覆盖他人未提交修改 |
| pre-commit stash | 未暂存文件被 stash 打包，运行期间若被并行进程修改 → 恢复时 `patch does not apply` |

**核心教训：并行会话不得在共享主工作区执行任何 `checkout`/`reset`/`commit` 操作。**

---

## 3. 团队规范（必须遵守）

### 3.1 新会话一律使用 Worktree 隔离（强制）

每个并行会话通过仓库脚本创建**专属 worktree**，在独立目录内工作：

```powershell
# 在主工作区执行一次，创建专属会话工作区
python scripts/dev/new_session_worktree.py create --id s7 --base develop
```

- worktree 目录：`<repo>/.worktrees/s7`（已入 `.gitignore`，不入版本库）
- 初始分支：`s7/main`（前缀 `s7/` 为本会话专属）
- **独立 index 与 HEAD**：本会话的 `git add`/`commit`/`checkout` 全部在自己的 worktree 内，不影响主工作区与他人
- 共享对象库：commit 后对象仍在共享 `.git/objects`，可随时被主工作区 merge/cherry-pick 回收

**此后所有 git 操作都在 `.worktrees/sN/` 目录内执行。**

### 3.2 禁令（共享主工作区）

| 禁止操作 | 原因 | 替代方案 |
|---|---|---|
| `git checkout <branch>` | 移动共享 HEAD，重建他人工作区文件 | worktree 内操作 |
| `git reset --hard` / `reset HEAD~N` | 丢弃他人未提交修改 | 仅在自己的 worktree 内 reset |
| `git add -A` / `git add .` | 可能把他人 worktree 之外的运行时数据一并提交 | `git add <具体文件>` |
| 轮询空闲后自动切分支的脚本（如 `wait_checkout_master.ps1` 模式） | 空闲判据不可靠，触发即误切 | 直接用 `new_session_worktree.py` 建独立 worktree |
| 在 pre-commit 运行期间让进程写未暂存文件 | 触发 stash 恢复冲突 | hook 运行前暂停写入，或先 `git stash -u` 手动收敛 |

### 3.3 提交流程（worktree 内）

```powershell
cd .worktrees/s7
# 1. 只暂存本次意图的文件
git add <具体文件>
# 2. 提交（pre-commit 正常执行；若 index 被清空，check-index-isolation hook 会拦截并提示）
git commit -m "fix(xxx): ..."
# 3. 回主工作区回收
cd <repo>
git merge s7/main          # 或 git cherry-pick <commit>
python scripts/dev/new_session_worktree.py cleanup s7   # 任务完成后清理
```

### 3.4 冲突时的处理顺序

1. 先 `git worktree list` / `new_session_worktree.py list` 确认其他会话在哪个 worktree；
2. 绝不直接改共享 HEAD/index，改用 cherry-pick/merge 在各自 worktree 内完成；
3. 提交被 pre-commit stash 冲突阻塞时：先 `git stash -u` 手动收敛未暂存文件，再提交，最后 `git stash pop`；
4. 确需绕过 pre-commit 时：记录原因（如 stash 冲突非代码问题），用 `SKIP=<hook>` 定向跳过，**严禁无说明的 `--no-verify`**。

## 4. 工具清单

### 4.1 `scripts/dev/new_session_worktree.py`（主工具，已在 develop 主线）

```powershell
python scripts/dev/new_session_worktree.py create --id s7 --base develop   # 创建（--id 省略则自动分配）
python scripts/dev/new_session_worktree.py list                             # 列出所有会话
python scripts/dev/new_session_worktree.py cleanup s7                       # 清理 worktree + s7/ 前缀分支
python scripts/dev/new_session_worktree.py guard s7/fix-x                   # 校验分支归属会话前缀
```

### 4.2 `check-index-isolation` pre-commit hook（自动防线）

提交前自动校验：
- index 为空但工作区有改动 → 拦截（提示重新 `git add`）；
- index 混入运行时文件（`data/sessions/`、`data/lifetrace/`、`data/reflection/`、`backup/`、`.env` 等）→ 拦截。

注意：手动 `pre-commit run --all-files` 时若 index 为空会误报（该 hook 设计用于提交语境），以真实提交为准。

### 4.3 退役脚本

`scripts/dev/wait_checkout_master.ps1`（并行会话旧方案：轮询空闲后切 master）——**停止使用**，其"自动切换共享分支"模式正是本次事故的成因。
