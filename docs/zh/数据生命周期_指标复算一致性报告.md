# 数据生命周期：指标口径复算一致性报告（TASK-S8-01 §二.4）

> 目的：证明**归档不改变既有统计口径**（S8 批次总表 §二③）。归档若把读端看不见的数据
> 搬走，指标就会变小 —— 那等于**篡改历史**。故"归档前后指标一致"不是锦上添花，
> 而是**归档方式是否合格的判据**。
> 复算环境：`2026-09-13`，根 = 真实数据的**临时副本**（`%TEMP%\s801_accept\root`，
> 由主工作区 `data/` 与 `agent/data/` 复制而来），**全程未触碰线上数据**。

## 一、受守护的三个既有指标（**未新建任何口径**）

| 指标 | 事实源（直接调用既有函数） | 读什么 |
|---|---|---|
| `utc.weekly` | `agent.observability.utc.utc_weekly(anchor_day, directory)` | 事件流明细（活动文件 + 按日分片） |
| `digestion.throughput` | `ShadowLedger.rows()` + `ManualReviewQueue.summary()` | 灰度台账 + 人工复核队列 |
| `audit.chain` | `AuditChain.reader().verify_chain()` + `count()` + `read_daily_roots()` | 链式台账本体 |

`agent/retention/metrics.py` **只做读取与比对**，不定义新的聚合口径 —— 这是"不改变既有
统计口径"的第一层保证（口径只有一处，改不了它）。

采集纪律：全部在**存在性守卫**下进行，缺失的事实源返回 `available=False` 而**不是 0**：
"没有事件目录"与"成本为 0"是两件事，混同会让口径失去意义。

## 三、判据的"牙齿"：不一致时必须报出来

只有"一致"的用例会退化成**永远通过的摆设**。故 `tests/unit/test_retention_metrics.py`
另有一组反向用例：把事件明细整份搬出读端视野后再复算，**必须**检测到不一致。

实测（`test_metric_check_has_teeth`）：搬走 `events.jsonl` 后
`llm_calls` 由 3 变 0，`compare_metrics` 给出
`consistent = false`、`changed_fields = ["llm_calls", ...]`，并输出处置提示：

> 存在指标不一致：该类归档方式不合格，须改为「保留聚合摘要 + 明细归档」双轨（TASK-S8-01 §二.4）

这正是任务书要求的兜底规则：**某类归档后指标无法复算 ⇒ 该类归档方式不合格**。

## 四、结构性保证：为什么"默认只归档不删除"之外还需要温层口径检查

默认 `CP_RETENTION_DELETE_SOURCE=false` ⇒ 归档只**复制**，源文件不动 ⇒ 指标天然不变。
但**温层**会真实改变文件布局（历史行移入按日分片），所以温层另有一条硬约束：

| 数据类 | 读端分片感知 | 证据 | 温层 |
|---|---|---|---|
| `events` | ✅ | `event_files()` 收 `events-*.jsonl`；跨分片按 `event_id` 去重 | 开 |
| `policy_decisions` | ✅ | `_candidate_files()` 收 `<stem>.<any>.jsonl` | 开 |
| `shadow_ledger` | ❌ | `ShadowLedger.rows()` 只读单文件 | **关** |
| `skills_audit` 等 | ❌ | 无分片约定 | **关** |

**端到端实测**（真实数据副本）：执行一次归档后，源树 `before/after` 指纹对照如下 ——

```
移除： data\policies\decisions.jsonl          sha256 FD2CCA63…FC42
新增： data\policies\decisions-2026-09-12.jsonl  sha256 FD2CCA63…FC42
变更： （无）
删除文件数：0
```

即温层是**纯移动**（内容逐字节相同、sha256 一致），且移动后的分片仍被读端识别 ——
这正是"温层不得改变统计口径"的可判定形式。
