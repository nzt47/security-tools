## 2. 100 亿节点分片策略

### 2.1 片数权衡（10 亿 → 100 亿演进）

| 片数 | 单片 refs 驻留 | 并行全扫（理想） | 判定 |
|---|---|---|---|
| 4096 | ≈312 MB | ≈9 分钟 | 单片内存偏高 |
| 8192 | ≈156 MB | ≈4.6 分钟 | 可行 |
| 16384 | ≈78 MB | ≈2.3 分钟 | 推荐候选 |
| **32768** | **≈39 MB** | **≈69 秒** | **推荐** |
| 65536 | ≈19.5 MB | ≈34 秒 | 过度分片（路由/元数据成本主导） |

**推荐 32768 片**：单片 39 MB 可整片常驻单机；32768 片可分布到 256–1024 台节点（每机 32–128 片），承载 refs 1.28 TB 总量。

### 2.2 区域级两级路由（region + shard）

```
region_id   = hash(ref_slug) % REGION_N     # 一级：区域（跨机房/可用区）
shard_id    = hash(ref_slug) % 32768        # 二级：逻辑分片（区域内）
node_owner  = consistent_hash(region_id, shard_id)  # 一致性哈希 → 物理节点
```

- 区域级解耦容灾：REGION_N 个区域互为冗余，区域故障只影响其分片（副本接管）；
- 写路径：add/remove → 两级路由 → 节点，单片读写 + 区域副本复制；
- 读路径：`_has_incoming_links` 依赖**全局入链预聚合服务**（跨区域倒排索引，如 KV/列存集群），O(1) 查表语义保留；
- 一致性：最终一致（写重放 + 跨区域对账）；片级「叠加 == 重建」断言 + 区域抽样对账双保险。

### 2.3 降级机制映射（100 亿）

| 降级机制 | 10 亿（4096 片集群） | 100 亿（32768 片多集群） |
|---|---|---|
| 索引损坏回退 | 单片秒级 + 副本重拉 | 单片秒级 + 跨区域副本重拉 |
| 写失败不阻断 | 不变 | 不变（重放队列 + 幂等写） |
| 全量重建 | Map-Reduce 分钟级 | 区域级 Map-Reduce（区域并行 + 全局合并） |
| 全局对账 | 分布式对账 | 跨区域对账任务（区域互为校验） |

## 3. 存储层：100 亿文件的必然形态

| 项 | 数值 | 影响 |
|---|---|---|
| 卡片文件 | 100 亿个 `.md` | 对象存储 + **多区域/桶分片**（`region/<type>/<slug 前 2>/<slug>.md`） |
| refs 索引 | 32768 片 + 区域副本 | 片上二级前缀索引 |
| 遍历基准 | 0.225 ms/卡 彻底失效 | 区域级前缀扫描 + 批量 list API，基准需实测标定 |
| 网络 | 跨区域复制/对账流量 | 区域间带宽成为约束（写放大 2–3x） |

**结论**：100 亿节点存储 = 多区域对象存储 + 分片副本；「全库 list()/重建」为区域级并行任务，遍历基准以实测为准（预计远大于单机外推）。

## 6. 结论与建议

| 决策维度 | 100 亿节点评估 |
|---|---|
| 内存（现状） | ≈18.6 TB：完全不可行 |
| 内存（流式单机） | ≈1.28 TB：refs 总量超单机 |
| 内存（分片 32768 多集群） | ≈39 MB/片：可控 |
| 耗时（全扫） | 流式 26 天 vs 分片并行理想 69 秒 |
| 存储 | 100 亿文件 → **多区域对象存储 + 分片副本** |
| 架构判定 | **区域级多集群架构（全球/国家级规模）** |

**建议**：

1. **32768 片 + 区域/分片两级路由**：区域级容灾解耦、一致性哈希最小迁移；写路径单片读写 + 区域副本，读路径全局预聚合服务保留 O(1) 查表。
2. **多区域对象存储**：区域分桶 + 副本 2–3；区域间带宽是硬约束，写放大 2–3x 需成本核算。
3. **一致性工程化**：最终一致 + 写重放（幂等）+ 跨区域对账；片级断言扩展为区域互为校验。
4. **可观测与运维**：区域级健康监控、分片滞后/损坏告警、重建任务调度与跨区域进度可视化。
5. **现实定位**：100 亿节点属**前瞻规划（全球/国家级规模）**，当前工程按 ≤200 万卡执行线落地流式即可；本系列报告为架构演进路线图，不改变近期实施范围。
