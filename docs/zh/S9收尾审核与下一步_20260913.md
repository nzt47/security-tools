## 二、下一步（按优先级）

### P0 · 立即处理：测试会覆盖真实 `.env`（**新查出的根因**）

**现象**：S9-01 报告称"运行期有组件把 `.env` 的 `LLM_API_KEY` 改写成 `sk-test-key`"，
导致 DeepSeek 401、全部 LLM 调用失败、响应退化成兜底文案 ⇒
**极易把「答得对」误判为「不达成」**（S9-01 就被这样误导过）。

**根因（代码行级，本次查清）**：
- `tests/unit/test_network_config.py::TestNetworkConfigEncryption::test_no_secure_manager_warning`
  调 `manager.update({'llm': {'api_key': 'sk-test-key'}})`；
- 它的 `setup_method/teardown_method` **隔离了 `network_config.json`（临时文件）与进程环境变量，
  但没有隔离 `.env` 文件本身**；
- `agent/network_config.py:221` → `self._env_config = get_env_config_manager()`，
  而 `agent/env_config_manager.py:623-631` 是**懒加载单例、无路径覆盖参数、无 reset**
  ⇒ `_save_secure()` 永远写**仓库根的真实 `.env`**。

**为什么必须当 P0**：任何一次测试运行都可能静默打断正在运行的服务；
`.env.backups/` 已有数百次覆盖记录（2026-08-15 事故），**复发问题**。
仓库里 `scripts/guard_llm_api_key.py`（`--check/--restore/--watch`）是缓解，但**目前是手动**的。

**建议修法**：
1. 给 `EnvConfigManager` / `get_env_config_manager()` 增加**路径覆盖**
   （如环境变量 `CP_ENV_FILE` 或工厂参数）+ `reset_for_tests()`；
2. 该测试（及相关用例）隔离到 `tmp_path`；
3. 在 `tests/conftest.py` 加 autouse 保护：测试期间**断言 `.env` 不被写**（或指向 tmp）；
4. 把 `guard_llm_api_key.py --check` 纳入**服务启动自检**或计划任务（非手动）。

**验收**：跑完整 `tests/unit` 后，`.env` 的 mtime 与 `LLM_API_KEY` 不变；且有一条用例锁死这一点。
