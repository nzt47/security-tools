# 全量测试后台脚本运维手册（run_full_pytest / run_full_pytest_bg）

> 更新：2026-08-15（含 PYTHONIOENCODING 修复与 parse_summary 逻辑说明）
> 适用：Windows 环境全量 pytest 后台/前台运行；产物在 `pytest_bg/` 目录

## 1. 脚本概览

| 脚本 | 职责 | 产物 |
|---|---|---|
| `scripts/run_full_pytest.py` | 全量 pytest 分块/并行/离线规避运行（前台，复用基础逻辑） | chunk 日志 |
| `scripts/run_full_pytest_bg.py` | 后台静默运行 + 进度状态 + 聚合报告（复用 run_full_pytest 的分块逻辑） | `pytest_bg/` 下 chunk_{i}.log、report_{ts}.md/.json、state.json |

用法：
```powershell
python scripts/run_full_pytest_bg.py [--bg] [--chunks N] [--workers N] [--mode fast|slow|all]
# --bg：Popen 启动子进程后台运行（注意：并行会话活跃时子进程会被回收，改用 schtasks 更稳）
```

**判定约定（T-4 教训）**：每块是否完整执行以日志中的 `=+ N passed` 汇总行为准，而非仅看 rc——pytest-timeout 强杀时 rc=1 且无汇总，不能把"无 passed 汇总"误判为成功。

## 2. PYTHONIOENCODING 修复（emoji 日志丢失，2026-08-15）

### 现象
后台全量运行日志中出现大量 `UnicodeEncodeError` + `Logging error` 追踪输出，日志行丢失。典型来源：
- `memory.memory_manager` 的 WARNING 分隔线（含 🔁 `\U0001F504`）
- `memory.vector_store.sqlite_vec_backend` 的 INFO（含 ✅ `\u2705`）

### 根因
Windows 下 Python 解释器 stdio 默认使用系统 ANSI 代码页（GBK）。GBK 无法编码 emoji 等非 BMP 字符，`logging.StreamHandler.emit` 写 stderr 时抛 `UnicodeEncodeError`。
全项目 47 处脚本均设置了 `PYTHONIOENCODING=utf-8`，唯独 `scripts/run_full_pytest.py` 漏设；而 pytest chunk 运行在 **ProcessPoolExecutor 子进程**（Windows spawn）中，子进程继承父进程环境变量，stdio 即为 GBK。

### 修复
在 `scripts/run_full_pytest.py` 顶层（import 后、任何 subprocess 之前）：
```python
import os
# Windows GBK 代码页无法编码 emoji 等非 BMP 字符，logging.StreamHandler.emit 会抛
# UnicodeEncodeError 并丢失日志行。pytest chunk 运行在 ProcessPoolExecutor 子进程，
# spawn 继承本环境变量 → 子进程 stdio 使用 UTF-8，emoji 日志不再丢失。
os.environ.setdefault("PYTHONIOENCODING", "utf-8")
```

要点：
- **必须在解释器启动后的模块顶层设置，但只对"之后创建的进程"生效**——当前进程的 stdio 编码已固定，改变的是 spawn 子进程
- `run_full_pytest_bg.py` 通过 `import run_full_pytest as rfp` 复用，顶层代码随 import 执行，无需重复设置
- 修复提交：`0cf96f64`

### 验证方法
```powershell
# 1) 机制验证：父进程 setdefault 后 spawn 子进程，emoji 正常输出、无 UnicodeEncodeError
python -c "import os,sys; os.environ.setdefault('PYTHONIOENCODING','utf-8'); import subprocess; r=subprocess.run([sys.executable,'-c','import logging; logging.warning(chr(0x1F504))'],capture_output=True); print('has_unicode_error=', b'UnicodeEncodeError' in r.stderr)"

# 2) 实测：pytest 输出中无 "Logging error" 且 emoji 可见
$env:PYTHONIOENCODING="utf-8"; python -m pytest tests/unit/test_xxx.py -q --no-header
```

## 3. parse_summary 逻辑说明（报告汇总行解析）

### 作用
`run_full_pytest_bg.py::parse_summary(log_path)` 解析每块 chunk 日志中的 pytest 汇总行，产出聚合报告字段。

### 实现（2026-08-15 修复后）
```python
# 汇总行各字段顺序不固定（如 "6 failed, 2528 passed" 时 passed 不在行首），
# 可能含 deselected/warnings 等额外字段，且 in Ns 后还带 (M:SS) 时长后缀
# → 按"数字+字段名"对提取，顺序无关；in 后秒数带 s 单位，行尾不做严格锚定
SUMMARY_LINE_RE = re.compile(r"^=+.*\b(\d+) passed\b.*\bin\s[\d.]+s\s")
FIELD_RE = re.compile(r"(\d+)\s+(passed|failed|error|skipped|xfailed|xpassed|deselected|warnings)")

def parse_summary(log_path):
    ...
    for line in text.splitlines():
        line = line.strip()
        if not SUMMARY_LINE_RE.match(line):
            continue
        pairs = FIELD_RE.findall(line)
        if pairs:
            fields = {name: int(n) for n, name in pairs}
        m = re.search(r" in ([\d.]+)s", line)
        if m:
            duration_s = float(m.group(1))
    ...
```

### 已知坑（后续维护必读）
| 坑 | 说明 |
|---|---|
| `passed` 不一定在行首 | 有 failed 时汇总行是 `= 6 failed, 2528 passed, ...`，行首正则需用 `.*` 越过 |
| `in Ns` 后可能有 `(M:SS)` | 如 `in 1197.10s (0:19:57) =`，行尾不能严格锚定 `=+$` |
| 秒数带 `s` 单位 | 正则必须写 `[\d.]+s\s`，写成 `[\d.]+\s` 会匹配失败 |
| 额外字段 | `deselected` / `warnings` 会插入字段序列，需纳入 FIELD_RE |
| 有汇总 vs rc | 无汇总行（timeout 强杀）返回 `{"summary": None, "has_passed_line": False}` |

### 验证命令（4 块日志解析结果应与真实汇总一致）
```powershell
python -c "import sys; sys.path.insert(0,'scripts'); from run_full_pytest_bg import parse_summary; from pathlib import Path; [print('chunk_'+str(i)+':', parse_summary(Path('pytest_bg/chunk_'+str(i)+'.log'))['summary']) for i in range(4)]"
```
