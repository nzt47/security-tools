# 知识模块性能优化落地实施计划

> 生成时间：2026-08-07
> 依据：《知识模块性能优化建议》（热点分级 P0-P2）
> 基线：回归测试 **347 passed / 0 失败**（含链路追踪新增 8 项）
> 原则（不易）：每一批改动保持幂等、只读素材（sha256 校验）、降级铁律（LLM 不可用不抛异常）三类不变量不被破坏；改动分可回滚小步，禁止一次性大改。

## 一、实施总览

| 批次 | 编号 | 优先级 | 事项 | 预估收益 | 验证指标 | 涉及文件 |
|---|---|---|---|---|---|---|
| 第一批（低成本高收益，不触碰持久化契约） | 1.1 | P0 | log.md 判重短路（进程内 LRU） | 写操作 O(L) → 命中时 O(1)；批量入库场景写耗时预期降 **70%+** | logbook 写操作 duration_ms P99 对比 | ingest.py `_append_log_line` / `_line_exists` |
| 第一批 | 1.2 | P1 | 卡片 lazy 解析（存在性检查免 YAML） | get/冲突检查路径省 100% frontmatter 解析 | card.get 单测断言 + 基准调用耗时 | card.py `_md_to_card` / get |
| 第一批 | 1.3 | P2 | KnowledgeSearch BM25 索引缓存 | 重复构造 O(N·词) → O(1)（缓存命中） | KnowledgeSearch 构造耗时对比（基准脚本） | search.py `_build_index` |
| 第二批（引入可持久化产物，须补一致性测试） | 2.1 | P0 | 入链索引 index_links.md | delete 入链检查 O(N) → O(1)；批量删除 O(N²) → O(N) | `_has_incoming_links` 耗时对比 + 索引一致性测试 | card.py L171-L175 / 新增 index_links 维护 |
| 第二批 | 2.2 | P1 | 批量删除接口 | 多删场景 N 次全扫 → 1 次扫描 | 基准脚本：删除 N 张卡耗时 | card.py delete |
| 第二批 | 2.3 | P1 | index.md 追加 + 定期重整 | 高频写 O(index) → O(1) 追加；保持「增量=全量」不变式 | 增量叠加 vs 全量重建 diff 为空 + 写耗时 | index.py `update_index_delta` |
| 第三批（外部依赖治理，先量化再动） | 3.1 | P2 | LLM 产物级缓存（source_hash+prompt 键） | 重复入库 LLM 开销 → 0（缓存命中）；闭环 P99 从秒级 → <50ms | `distill.llm_ok` duration_ms P99 / 缓存命中率 | distill.py / discuss.py |
| 第三批 | 3.2 | P2 | 讨论并行化 + LLM 有界超时 | 多素材讨论串行 → 并发（上限 3）；极端超时不再拖长链路 | `discuss.llm_ok` 耗时分布 / TimeoutLLM 回归测试保持绿 | discuss.py / tools.py |

## 二、第一批（低成本高收益）

### 1.1 log.md 判重短路
- **改动**：`_append_log_line` 进入持锁读文件前，先查进程内 `(action, slug, date)` LRU（容量 100）；命中直接跳过 `_line_exists` 全量读改写。
- **收益量化**：log.md 1 万行时，读改写约 2-5ms/次 → 命中时约 0.01ms；批量入库（同 slug 重复写入）命中率最高。
- **验证指标**：`kb_capture` → 批量入库基准：总耗时、logbook 写段 duration_ms；`test_knowledge_ingest.py` 幂等用例保持绿。
- **回滚**：纯进程内缓存，无持久化产物，删缓存行即可回滚。

### 1.2 卡片 lazy 解析
- **改动**：`get` / 冲突检查先验证文件存在，仅在真正构造 Card 时才 `yaml.safe_load` frontmatter。
- **验证指标**：新增单测：文件不存在 / metadata 为空时不触发 YAML 解析（mock safe_load 断言未调用）。
- **回滚**：局部函数级改动，无格式变更。

### 1.3 KnowledgeSearch 索引缓存
- **改动**：模块级 `(wiki_root, 卡片集合签名)` → BM25Index 缓存；签名含卡片数 + mtime 聚合。
- **验证指标**：基准脚本对比连续 100 次 `KnowledgeSearch()` 构造耗时；`test_knowledge_search.py` 保持绿。
- **回滚**：缓存失效即重建，无正确性风险。

## 三、第二批（需一致性测试）

### 2.1 入链索引 index_links.md
- **改动**：与 index.md 同机制增量维护 `slug → 入链 slug 列表`；card create/update/delete 时同步；`_has_incoming_links` 改查表。
- **前置**：先落地 1.2（lazy 解析）降低建索引成本。
- **验证指标**：新增一致性测试（索引表 vs 全库扫描结果一致）；`delete` 入链拒绝场景单测保持绿。
- **回滚**：索引文件可删，`_has_incoming_links` 回退全扫逻辑保留。

### 2.2 批量删除接口
- **改动**：新增 `delete_many(slugs)`，一次扫描维护引用计数，并行校验待删 slug。
- **验证指标**：基准脚本：删除 50 张卡 vs 50 次单删耗时对比；删除不变量（孤儿、断链）单测保持绿。

### 2.3 index.md 追加 + 定期重整
- **改动**：`update_index_delta` 条目追加至 section 末尾（幂等判定保持）；每 100 次写或每日触发 `rebuild_index` 重整排序。
- **验证指标**：一致性断言「增量叠加结果 == 全量重建结果」（现有测试已锁定，扩充为追加模式）；写路径 duration_ms。
- **回滚**：追加标志位关闭即回退现行为。

## 四、第三批（外部依赖治理）

### 3.1 LLM 产物级缓存
- **改动**：以 `(source_hash, system_prompt)` 为键缓存 distill/discuss 产物；重复入库直接复用，零 LLM 开销。
- **前置**：须先有耗时埋点量化基线（已完成，`distill.llm_ok` 等）。
- **验证指标**：`distill.llm_ok` duration_ms P99 前后对比 + 缓存命中率 > 90%；降级路径（FakeLLM 超时）测试保持绿。

### 3.2 讨论并行化 + 有界超时
- **改动**：多素材讨论 ThreadPoolExecutor（上限 3）；`kb_*` 工具侧 LLM 有界超时 10s。
- **验证指标**：TimeoutLLM 极端场景回归（不抛异常）；`discuss.llm_ok` 耗时分布收窄。
- **风险**：并发引入的日志乱序由 trace_id（128 bit）链路聚合兜底——已具备。

## 五、验证指标统一口径

| 指标 | 采集方式 | 基线 | 目标 |
|---|---|---|---|
| 写路径耗时 | Loki `quantile_over_time(0.99, [1h])`（action=promote.card_ok 等） | 见回归报告 | 第一批落地后 P99 降 ≥50% |
| LLM 调用耗时 | `distill.llm_ok` / `discuss.llm_ok` duration_ms | 秒级（外部延迟） | 缓存命中时 <50ms |
| 回归 | 14 个 `test_knowledge_*.py` | 347 passed | 每批落地后 ≥347 且 0 失败 |
| 不变量 | 幂等 / sha256 / 降级铁律三类专项测试 | 全绿 | 全程保持绿 |
| 一致性 | 「增量叠加 vs 全量重建」diff | 空 | 2.3 落地后仍为空 |

## 六、实施节奏与风险

- **顺序**：第一批（1-2 天内不涉及外部依赖）→ 第二批（补一致性测试后）→ 第三批（量化基线稳定后）。
- **风险表**：
  | 风险 | 缓解 |
  |---|---|
  | LRU 短路漏判真重复 | 短路仅覆盖进程内近期写入，跨进程仍走全量判重，不破坏幂等 |
  | index_links 与全库漂移 | 一致性测试 + rebuild 兜底 |
  | LLM 缓存命中错误 | 键含 source_hash（sha256）与 prompt 双因子 |
  | 并发讨论日志错乱 | trace_id 链路聚合兜底（本批次已具备） |

## 七、结论

第一批三件事即可释放主要收益（写路径 O(L)→O(1)、解析路径免 YAML、索引构造 O(1)），
且不触碰持久化契约与三类核心不变量；第二、三批在量化基线稳定后按表推进。
