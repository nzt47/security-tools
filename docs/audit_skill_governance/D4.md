## 3. 实现设计（含为什么这样落点）

### 3.1 落点

D2 §5.1 已定位：`routes_skills_mgmt.py:736-745`（PATCH）→ `service.update()`（service.py:1505-1523）` 全函数无 `facade.record`，而字段白名单含 `enabled` ⇒ 第二条无痕启停通路。

本卡按主审计采纳的 E1/E2 口径，在 `update()` 内 `self.store.upsert(updated)` **之后**、`_advisory_assess` **之前**接入：

```python
changed = sorted(k for k in patch if k in allowed
                 and getattr(skill, k, None) != getattr(updated, k, None))
self.store.upsert(updated)
if changed:
    self._record_update_audit(skill, updated, changed)
self._advisory_assess(updated.id)
```

- `skill`（`_require` 取出的旧值）与 `updated`（待落库新值）做**白名单字段 diff**；
- 白名单外的键本来就被忽略（不落库）⇒ 不算变更、不写记录；**同值 patch 也不算变更**（避免审计噪音），单测覆盖；
- 先落库再入链：审计只描述「已经发生的事实」，与 D2 在 `enhancer.set_enabled` 的口径一致。

### 3.2 动作名与 payload（要求 1）

| 变更内容 | 动作名 | payload |
|---|---|---|
| 一般字段（description/content/tags/…） | `skill.update` | `{"skill_id": …, "changed": [字段名…], "origin": "skills_mgmt.update"}` |
| 含 `enabled` | `skill.registry.set_enabled`（复用 D2 动作族） | `{"skill_id": …, "previous_enabled": …, "enabled": …, "track": "main", "origin": "skills_mgmt.update"}` |

- 启停记录**不另开动作名**（照要求 1）：实现上直接复用 `enhancer.record_enabled_audit(AUDIT_ACTION_ENABLED_SET, …)`，
  与 `SkillRegistry` / `SkillEnhancer` 走同一函数，payload 键集合与 D2 逐键相同（单测断言），只把 `origin` 换成 `skills_mgmt.update`、track 固定 `main`（本通路写主轨 JSON）；
- 一次 patch 同时改 description + enabled ⇒ **两个动作族各 1 条**（字段变更族 + 启停族），字段变更族的 `changed` **不含 enabled**（enabled 归启停族）⇒ 启停动作名在链上仍是「一动作一记录」，不被拆散；
- `skill.update` 是新增动作名，不在 `AUDIT_MIRROR_TYPES`（事件镜像白名单）内，且本实现不走事件总线 ⇒ 无双写。

### 3.3 只记字段名、不记字段值（要求 4）

照 `agent/audit/facade.py:392-398` `record_redact_event` 的先例（只记 `field_count`/`kinds`，
并显式落 `values_recorded: False`），本实现 payload **只有字段名列表**，不放任何字段值：
description 可能很长、也可能含用户内容，记值会把审计台账变成内容仓库（并踩 S6 敏感数据）。

### 3.4 best-effort 但不静默（要求 3）

```python
def _record_update_audit(self, skill, updated, changed) -> None:
    if "enabled" in changed:
        try:
            from .enhancer import AUDIT_ACTION_ENABLED_SET, record_enabled_audit
            record_enabled_audit(AUDIT_ACTION_ENABLED_SET, str(updated.id), …)
        except Exception as e:  # noqa: BLE001 审计失败不得影响更新
            logger.warning("[Service] 启停变更审计留痕失败（更新已生效） skill=%s: %s", …)
    …
    try:
        entry = _audit_facade.record("skill.update", …, status="ok")
    except Exception as e:  # noqa: BLE001
        logger.warning("[Service] 技能字段变更审计留痕失败（更新已生效） skill=%s changed=%s: %s", …)
        return
    if entry is None:
        logger.warning("[Service] 技能字段变更审计未落链（门面返回 None：审计被关闭或静默失败）…")
```

- `facade.record` 本身 best-effort（失败只加 `failure_count` 并返回 None，facade.py:335-342）⇒ 因此单测**真读链**断言，
  不满足于「没抛异常」；
- 门面返回 `None`（审计关闭 / 静默失败）也必须留 WARNING，避免「完全静默」——这一分支单测有专门用例（`test_audit_disabled_writes_nothing_but_logs`）；
- `enabled` 分支的「失败/未落链」日志由 D2 的 `enhancer.record_enabled_audit` 负责，本卡不重复实现。

### 3.5 注释与实现一致性（铁律 5 自检）

| 注释声明 | 实现 | 一致 |
|---|---|---|
| `_record_update_audit` docstring：「payload 只记字段名，不记字段值」 | payload 仅 `skill_id/changed/origin` 或启停 5 键 | ✅ |
| docstring：「changed（实际变更字段名列表，**不含 enabled**）」 | `plain = [f for f in changed if f != "enabled"]` | ✅ |
| docstring：「审计失败（抛异常或返回 None）只写 WARNING 并返回，不向上抛」 | try/except + `entry is None` 两个 WARNING 分支，无 `raise` | ✅ |
| `update` docstring：「同值不改不算变更，不写记录」 | `changed` 由旧/新值 diff 得出，`if changed:` 才入链 | ✅ |
| `update` docstring：「审计 best-effort，不影响更新与返回值」 | `return updated` 语句未被改动（见 §2 hunk：改动全在它之前） | ✅ |
