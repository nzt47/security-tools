# F3-1 · 把系统提示词的「易变尾簇」搬到请求尾部（让稳定前缀尽量长）

- 卡号：**F3-1**（性能/成本），基线 HEAD = `5c9ace10a4ca4bb96860db3a48debf9ddcf496bf`
- 上游裁决：**F3 = 方案 A（工具宣告行保持现状）**。F3 §5.2/§6.1 明确：真正的损耗在宣告行**门口的易变尾簇**，
  并建议"把这块移到 prompt 尾部，收益大于挪宣告行"。本卡只执行这一件事，**不碰宣告行**。
- 结论：**达成**。同一组用例下，首个差异字符从 system prompt 内部（char 2045）后移到**整条请求的尾部**；
  同用例命中率 **5.04% → 86.6%/87.6%**。无需回滚；逃生开关保留。

---

## 0. 一句话机制

改动前 `system_prompt` = `[稳定块: 身份/原则/技能指令/工具宣告行] + [易变块: 记忆线索/最近对话/ContextAssembler 注入]`。
前 3 次相同请求实测：**宣告行恒在 char 689**，但**首个差异字符落在 char 2045**（易变块内）——
前缀一断，其后的 **tools 段（本部署 ~6k token）+ 全部历史消息** 每轮全部 miss。

改动后：易变块从 system message **整块搬出**，作为整条请求的**最后一条消息**；
system message 只剩稳定块（**模板一字未改**，稳定块顺序与内容逐字保持）。

```text
改前：[稳定块][易变块]                     + tools + 历史 + user
改后：[稳定块]                             + tools + 历史 + user + [易变块 ← 最后一条]
       └──────────── 可命中前缀（本卡把它从 ~1.2k token 拉到 ~7.5k token）────────────┘
```

### 3.2 为什么 ident 组的 Σ 反而降了（诚实归因）

- 改后 Σ 59.44% 的分母里，**#1 是冷启动**（512/7950 = 6.44%）：它的可命中前缀只能来自
  别人的历史缓存条目，搬移救不了它（改前同样只有 640）。
- 改后 #2/#3 = **81.7% / 84.2%**：命中 = 稳定 system + tools 段 + 历史 + 用户输入，
  少算的只有**易变尾簇本身**（1603 / 1441 token ≈ 尾簇 1652 字符 + 本轮新增）。
  这正是本卡要达到的形态：**唯一 miss 的就是"本来就必须重算"的那块**。
- 改前 #2/#3 的 95% 不是旧顺序的功劳，而是**陈旧缓存条目**（sys16 `CF638F2FE89CCEDD`
  与 F3 §9.3 22:30:41 那条同 sha，相隔 2.5 小时）恰好逐字吻合。
  ⇒ **两组 Σ 不可直接比**；可比的是 §4 的"同用例、同措辞变化模式"对照。

### 4.1 同用例基准对照

| 布局 | 用例 | 实测命中率 | 来源 |
|---|---|---|---|
| **旧顺序** | `--cases vary`（3 次同意图不同表述） | **5.039%**（512/512/512） | **F3 §5.1 实测**（同探针、同用例；本卡按"不重跑 F3 已跑过的实验"未重跑，见 §8） |
| **新顺序** | `--cases vary`（同 3 条问题） | **87.62%** / **86.57%**（6 条记录 85.84%–91.01%） | 本卡两次实跑 |

⇒ **同一组用例：5.04% → 86.6% / 87.6%（约 17 倍）**；且**每一次**请求都 ≥85.8%，
不再依赖"上一次的 memory 恰好一样"这种运气。

### 4.2 结论

- **首个差异字符偏移**：从 system prompt **内部**（char 2045，稳定前缀 1235 cl100k token）
  后移到**整条请求的尾部**（char 3574/4004，稳定前缀 2694/3071 cl100k token；本部署 provider
  侧同口径命中 7168–8448 token）。
- **命中率**：在可比用例上 **5.04% → 86.6%/87.6%**。
- ⇒ 按卡点判据「偏移显著后移且命中率显著上升」**成立**，**不回滚**。
