## 1. 结论（一句话）

> 触发词以前用**「字」**当切分单位，而 `admission.MIN_TRIGGER_CHARS = 2`（S10-01「单字无区分度」）
> 会过滤掉全部单字 ⇒ **任何纯中文任务的 `trigger_patterns` 恒为 `[]`** ⇒ 一律判
> `NO_DISCRIMINATIVE_TRIGGER` ⇒ 一律草稿、连**原样复述**都命中不了（F11 §4.3）。
> F11-B **把中文的切分单位从「字」改成「2 字滑窗(bigram)」**（复用 F11 已实现的
> `learner.signature_tokens`，不写第二套分词），**政策一个字都没改**：
> `MIN_TRIGGER_CHARS` 仍是 2，单字**仍然不得**成为触发词。
> 结果：同一句话学出来的条目 `draft → active`、`trigger_patterns [] → ["统计","计当","当前","前工","工作"]`、
> `matcher.match(同一句话) [] → [(条目, 0.6832)]`、`try_execute` 直接命中（§4 有 A/B 原始输出）。

**这不是放宽门槛，是修正分词口径**：单字单位在这条政策下**必然全灭**，它度量的是错的东西；
把它换成「最小成词单位（2 字）」后，政策第一次能对中文产出它本来想要的结果
（「有区分度的触发词」），而不是「一条都产不出」。

## 3. 修复设计

### 3.1 改了什么（`learner.py`，4 处）

| # | 位置 | 改动 |
|---|---|---|
| 1 | 模块 docstring | 新增 §「触发词口径(F11-B 修复)」；把「学习方法」第 4 条的「按字切分」改成「与签名同一分词口径」 |
| 2 | `TRIGGER_TOKENS_MAX = 5` | 新增常量（= 旧 `_extract_keywords(..., top_k=5)` 的同一个 5，**不引入新阈值**） |

| 4 | `trigger_tokens()` + `learn()` 第 3 步 | 触发词改取自 `signature_tokens`：中文 = 2 字滑窗、英文 = 整词（小写、≥2 字符、去 `_STOP_WORDS`），首现序取前 5 |

**没有第二套分词**：`trigger_tokens` 只是对 `signature_tokens` 的输出做「滤英文停用词 + 截断」
（签名要的是"输入的函数"，所以 `signature_tokens` 不过滤停用词；触发词是**匹配特征**，
停用词必须滤掉 —— 这一步旧口径 `_extract_keywords` 也做，属回归保持）。

`_extract_keywords` **保留**：它仍是 `_templatize_params`（参数模板化）的分词器，不是死代码。

### 3.2 为什么**没有**改 `admission.py`

`admission.py` 是仓库里**唯一**的政策源（`MIN_STEPS` / `MIN_TRIGGER_CHARS` /
`MIN_CROSS_SESSION_SUPPORT` + 机器可读拒绝码），供 `matcher` / `learner` / `skill_converter` /
`service` 四处复用。本卡要修的是**写入方产出的形态**（中文写进去的根本不是"有区分度的词"），
不是**判定标准**：

- `MIN_TRIGGER_CHARS = 2` 依据（"中文里 2 字是最小成词单位，单字歧义率最高"）在 F11-B 后
  **依然成立且被强化** —— 现在写入方真的按 2 字成词产出，政策与写入方契约第一次**对齐**；
- 改阈值（如降到 1）会让单字重新入库，那才是本卡明令禁止的"放宽门槛"；
- 实测：`admission.py` 未被本卡触碰（`git diff` 空、mtime 仍是 `2026-09-14 00:37:45`、
  sha256[:16] = `c990f71aab8d85f7`）。

## 5. 近似复述的判定标准（实测，含**边界如实披露**）

### 5.1 判定标准（可复算）

> **近似复述能否命中，取决于查询里是否出现了该条目索引文本中没有的字符** ——
> 不是取决于语序、也不取决于"是不是同一个任务"。
> 成因：`matcher._idf` 的平滑下界在**单文档**索引下把"未知字"的 idf 顶到 0.693、
> 而"已知字"只有 0.001（**相差 693 倍**），于是查询里每多一个索引里没有的字，
> 相似度就被拉低一个数量级。

### 5.2 实测数据（同一条目，tmp 仓库）

| 查询 | 索引文本未覆盖的字符 | raw sim | 是否过 `min_similarity=0.3` |
|---|---|---|---|
| 原样复述 | 无 | 0.854 | ✅ 命中（combined 0.6832） |
| 语序调换（同字符集）`当前工作目录下有多少个 py 文件，统计` | 无 | **0.854** | ✅ **命中** |
| 语序调换+拆句 `有多少个 py 文件？当前工作目录下统计` | 无 | 0.854 | ✅ 命中 |
| 加虚词/语气词 `请帮我统计一下当前工作目录下有多少个 py 文件` | `请` `帮` `一` `我` | 0.0025 | ❌ 不命中 |
| 换同义词 `总计一下当前工作目录里有几个 py 文件` | `里` `一` `总` `几` | 0.002 | ❌ 不命中 |
| 短问法 `统计 py 文件数量` | `数` `量` | 0.0012 | ❌ 不命中 |
| **无关句** `帮我把明天下午的会议改到周五上午十点` | 14 个 | 0.0001 | ❌ 不命中（防误召 OK） |

**索引规模的影响（同一实验，再学一条无关工作流让索引变成 2 文档）**：

```
=== index docs = 1 ===   exact 0.854 ✅ / R1 语序 0.854 ✅ / R5 短问法 0.0012 ❌ / R4 换同义词 0.002 ❌ / FAR 0.0001 ❌
=== index docs = 2 ===   exact 0.879 ✅ / R1 语序 0.879 ✅ / R5 短问法 0.2642 ❌ / R4 换同义词 0.4466 ✅ / FAR 0.0087 ❌
```

⇒ **多文档**索引下未知字的权重优势从 693× 降到 ~2.7×，"换同义词"这类改写就能命中；
单文档（刚学完第一条）时不能。这是 `matcher` 层的既有性质，**与触发词口径无关**
（F11-B 之前中文条目根本不进索引，连 0.854 这一半都拿不到），登记为 §8.1 遗留。
单测把这条判定标准**钉成了可复算断言**（见 `TestNearParaphrase`，含"若将来被修好请更新遗留、
不要放宽断言"的注释）。

### 5.3 不该命中的不命中（防误召，实测）

- 无关中文句：`match() == []`、`search() == []`、`try_execute().matched is False`（raw sim 0.0001）；
- 触发词进索引后仍与无关句保持 **>10 倍**差距（`near(0.854) > far(0.0001) × 10`）；
- 英文回归：`触发词与旧口径逐项相同`（`I am a Python user`、`the python and the files`
  两例都断言 `trigger_tokens(text) == 旧实现结果`）；唯一差异是**重复词的排序**
  （`alpha beta beta`：旧 `[beta, alpha]` / 新 `[alpha, beta]`，**集合相同**，
  而索引是词袋 ⇒ 对匹配无影响），已被单测固化为显式对照。

## 7. 为什么选「2 字滑窗」而不是别的口径

| 备选 | 取舍 |
|---|---|
| 降低 `MIN_TRIGGER_CHARS` 到 1 | ❌ 就是"放宽门槛"，本卡明令禁止；且单字确实无区分度 |
| 引入 `jieba` 等分词器 | ❌ 新增依赖 + 让产物依赖环境（跨机不可复算），F11 §8.1 已明确不引入 |
| 只取"跨词滑窗"或按频率挑 bigram | ❌ 没有词典就无法判断词边界，且会**引入第二套口径**；频率在短输入上恒为 1，等于没筛 |
| **复用 `signature_tokens` 的 2 字滑窗** | ✅ 与任务签名**同一个分词器**（仓库里只有一处"怎么切词"），政策同源（每 token ≥ 2 字符），改动面最小 |

已知代价（F11 §8.1 已登记、本卡继承）：2 字滑窗会含少量**跨词噪声** bigram
（本例的 `计当`/`前工`/`作目`）。它们对**去重与区分无害**（同一输入恒得同一集合），
但对"给人看的触发条件/工作流名"不够干净 ⇒ §8.2。

## 8. 遗留与建议

1. **`matcher` 单文档索引的 idf 效应**（§5.2）：未知字 idf=0.693 vs 已知字 0.001（693×），
   使"引入新字的改写"在只有 1 条工作流时几乎不可能命中。这**不是**本卡引入的，
   但它是"中文工作流能不能被真实用户的不同措辞召回"的下一个瓶颈，**建议单开卡**
   （方向：查询侧/文档侧一致的分词口径，或把 idf 下界从 0.001 改为可解释的下界）。
2. **触发词里的跨词噪声 bigram**（`计当`/`前工`）：要真正干净需要词典/分词器（见 §7）。
   现状对匹配是无害的（噪声只稀释、不误召：无关句 raw sim 0.0001），建议保留观察。
3. **存量 8 条中文触发词为空 = 历史数据，本卡不回填（只给建议）**：
   它们不会被本卡改动影响（改动只作用于**新学习**的条目）。若需要回填，建议**单开一张卡**
   用「`learner.trigger_tokens` 重算 + `admission.effective_trigger_patterns` 清洗」的迁移脚本
   离线跑一次，并**只对新学的条目**生效（F11 §6.2 给过同样的建议）；
   注意存量条目大多是 `archived`，回填不会让它们进候选池（结构性准入与统计门槛仍在）。
4. `orchestrator._sid` 兜底、`config.workflow_learning.learner.*` 无人读取、
   `memory_abstractor` 调用不存在的 `list_recent` —— 均为 F11 已登记的遗留，**不在本卡范围**。
