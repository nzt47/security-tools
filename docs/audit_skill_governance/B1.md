## 2. 做法：唯一事实源放在哪

### 2.1 生产路径（编排器 / 工作台）的真相

```
orchestrator._call_llm:
  _whitelist = self._get_enabled_tools_whitelist()      # ① tools_config 启用白名单（本机 None）
  _line_tools, _line_res = line_whitelist(_whitelist)   # ② 主线装配（engineering，max_tools=26）
  _tool_defs = get_tool_defs(whitelist=_whitelist)      # ③ 真正下发的定义
  tools=_tool_defs  →  上游
```

修复前，系统提示词的宣告行走的是**另一条**统计：`len(list_tools())`（注册表全量 = 生产上 86），
与 ③ 的下发集（26）不是同一个集合，也与 `data/tool_definitions/*.yaml`（91）不是同一个东西。

### 2.2 现在的唯一事实源

```
_build_tool_status_text(expose_tools=True, tool_defs=None)
   ├─ tool_defs 给了  → 直接用（调用方拿到收窄后的下发集时走这条）
   └─ 没给            → resolve_dispatch_tool_defs(self._get_enabled_tools_whitelist())
                          = ① → ② → get_tool_defs(whitelist=…)      ← 与 ③ 同一个函数
   渲染：render_tool_advert_line(tool_defs)   ← 数字与名字同源于**同一个入参**
```

* 宣告行格式：`【工具】本轮向模型下发(N 个): 名字, 名字, …`；N 为空 ⇒ `TOOL_ADVERT_EMPTY_LINE`（含 `0 个`）。
* 渲染函数与判定标记 `TOOL_ADVERT_MARKERS`（`【工具】`）**住在同一个模块**，
  所以"改了渲染忘了改标记"在结构上不可能发生；单测 `test_渲染格式仍被根因标记覆盖` 再钉一道。
* 删除了工具侧的「已禁用(N)」行：那是一处**独立统计**（tools_config ∩ 注册表），
  与"本轮下发多少"无关，留着就是第二个会漂移的数字。

### 3.1 要求 1：宣告值由真实下发集实算 ✅

### 3.2 要求 2：消除 `plugins/chat.py` 的错误估算与失真注释 ✅

  缺 tiktoken 时打印「token 未实测（缺 tiktoken）」，**绝不退回另一种口径冒充同一个数字**。
