## 3 「证据 / 偏好」两分语义（③+④）

**③ 行为改动**（唯一算式出处：`matcher.score_candidate`）：

```text
confidence_factor = 1.0 if success_count == 0 else wf.confidence    # 冷启动口径保持原样
priority_factor   = 0.5 + wf.priority / 200.0                       # ∈ [0.5, 1.0]

evidence = sim × confidence_factor                     # ← 门槛：与 executor.min_score 比较
combined = sim × confidence_factor × priority_factor   # ← 排序：候选之间的相对顺序
```

- `priority` 是**偏好/排序权重**（默认 50，0~100），**不是证据**：它不再进入门槛，
  因此不再把候选的整体分数压低 25%（prio=50）~50%（prio=0）。
- 因为 `priority_factor ∈ (0.5, 1.0]`，同一候选恒有 `evidence ≥ combined` ⇒
  门槛**单调放宽**，不会出现"新口径反而更严"的候选。
- **排序键逐字未改**（仍是 combined，排序表达式一字未动）⇒ 候选顺序与改前逐位相同（§5）。
- 两个分数**各自显式算出并显式返回**（`MatchScore.evidence` / `MatchScore.combined`），
  **没有任何 `evidence = combined / priority_factor` 式的除法还原**。

**④ 文档语义**（写进 `matcher.py` 模块 docstring、`executor.py` 模块与 `try_execute` docstring、
`service.py` 的 `try_execute`/`search` docstring）：

> 自动执行**只在「高相似 + 有一定信心」的重复场景成立**；改写场景（换词/换句式 ⇒ 相似度中等）
> **默认交给 LLM**，只有近乎逐字重放或已养熟的条目才短路。返回 `matched=False` 即"降级给 LLM"的显式信号。

**门槛决策可审计**：一次 `try_execute` 的 `ctx`（`traced_action` 上下文）现在含
`similarity / confidence / confidence_factor / priority / priority_factor / evidence / combined /

## 10 未验证项与残留风险

1. **死锁未被完全消除（最重要的一条）**。③ 只拆掉 `priority` 在门槛里的 25%~50% 惩罚；
   `evidence = sim × confidence` 仍是乘性的，**confidence 仍只能靠成功执行增长**。
   实测：§1a 的改写句 sim=0.3492 **改后依然被卡**（`reason="evidence 0.175 < 0.25"`），
   §1b 自举后的改写句 sim=0.3531 也依然被卡（evidence 0.248 < 0.25，**只差 0.002**）。
   改后 conf=0.5 的条目仍需 `sim ≥ 0.5`（改前 prio=80 时需 0.5556、prio=50 时需 0.6667）。
   彻底闭环需要另一条卡另行裁定（候选：探索预算/一次性首跑、`observed_count` 参与信心、
   降低 `min_score`、或对 `success_count==0` 单独定策），**本卡不做**。
2. **冷启动口径仍是"信心因子 = 1.0"**（`success_count==0`）。它让新条目的门槛退化为
   "只看 sim"（`evidence = sim`）。我**故意保留**（若在门槛里改用条目自身 confidence=0.4，
   冷启动条目需要 `sim ≥ 0.625`，首跑必被卡，会打断 F11-C 之前的既有修复）；
   但这条口径本身语义可疑（"没执行过"却按最高信心计），**已在此登记，未改**。
3. **误执行面扩大**（§4.4）：5 个不同意图查询由"卡住"变为"执行"，其中
   `"删除本周销售周报并通知团队"` 在 `min_score=0.3` 下会执行含 `send_email` 的工作流。
   本卡不动召回闸门，故这类风险只能靠语义层（意图极性/rerank）或提高 `min_score` 解决。
4. **真实语料的可见效果很小**（11 条里只有 1 条合规条目，5→5），
