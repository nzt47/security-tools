## 3. 实现设计（含为什么这样落点）

### 3.1 写入点选择：主轨落 `enhancer`，文件轨落 `registry`

写链实测是 `registry.set_enabled(:126) → service.set_enabled(:1981) → enhancer.set_enabled(:679-692)`，
但**主轨还有一条绕过 `SkillRegistry` 的路**：`agent/server_routes/routes_skills_mgmt.py:770-776`
（`POST /api/skills-mgmt/<id>/toggle`）直接调 `_svc().set_enabled(...)` → `enhancer.set_enabled`。

因此：

- **主轨**：唯一落库点 `SkillEnhancer.set_enabled` 入链 → 覆盖 registry / service / UI 路由 / extensions 全部调用方，且**一次启停只有一条记录**；
- **文件轨**：`file_store.update_meta` 不经过 enhancer，故由 `SkillRegistry._set_enabled` 文件轨分支直接入链；
- **不双写**：`SkillRegistry` 在主轨分支只做「透传动作名 + 调用来源」（`enabled_audit_origin` ContextVar 包住 `svc.set_enabled` 调用），本身不再写第二条。

```python
# agent/skills_mgmt/registry.py（主轨分支）
with audit_origin(action, origin):      # 透传 (skill.registry.toggle, "skill_registry.toggle")
    svc.set_enabled(skill_id, enabled)
# agent/skills_mgmt/enhancer.py（主轨唯一写入点）
action, origin = _enabled_audit_origin.get()
record_enabled_audit(action or AUDIT_ACTION_ENABLED_SET, skill_id, ...,
                     track="main", origin=origin or "skills_mgmt.enhancer")
```

### 3.2 调用（严格按 Q7 §1.1 的门面签名，未自造参数名）

```python

    str(action),                       # 位置参数：action
    subject=f"skill:{skill_id}",       # 与 service.py:827 skill.assess 同口径

# actor 不显式传 → 由门面 resolve_actor 解析（UI 请求上下文 / Agent TraceContext / system），
```

### 3.3 payload 字段（**不含任何密钥 / 用户原文**）

```json

 "track": "main", "origin": "skill_registry.set_enabled"}
```

门面在其外层再包 `{payload, status, actor_source, schema}`（`facade.py:309-322`，实测见 §4.3 原始记录）。
单测 `test_payload_contains_no_skill_text` 断言技能描述/正文的标记串不出现在审计载荷里，且业务字段集合恰为上述 5 个。

### 3.4 注释与实现一致性（本卡未新增「注释失真」）

- `enhancer.record_enabled_audit` docstring 写明「失败只写 WARNING 并返回，不向上抛」→ 实现就是 `try/except + return`；返回 `None`（门面 best-effort 静默吞掉）也会 WARNING，**不是完全静默**；
- `registry._audit_hooks` docstring 写明「导入失败 → ("", "", None, None)，启停照常」→ 实现即 `except: return "", "", None, None`，两个分支各有 `if audit_origin is not None` / `if audit_record is not None` 守卫；
- `registry._set_enabled` docstring 写明 `toggle=True` 时才取 `skill.registry.toggle` → 实现 `action = action_toggle if toggle else action_set`；
- 惰性导入的理由（`agent/skills_mgmt/__init__.py` 的「轻量子模块不被 service→models(pydantic) 重依赖绑架」不变量）与实现一致：钩子只在 `_set_enabled` 首次调用时导入，模块顶层仍只依赖 `logging_utils`。

## 5. 要求 5：技能**描述变更**是否也无留痕？（实测，仅给结论与落点）

### 5.1 结论：**是，且存在第二条无留痕的启停路径**

即：`svc.update(skill_id, {"description": ...})` 与 `svc.update(skill_id, {"enabled": False})`

全函数无 `facade.record`；且白名单里**含 `enabled`**（`service.py:1512`），
