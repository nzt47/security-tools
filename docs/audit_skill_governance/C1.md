## 1. 修复 (1)：名义 2s 的超时真正生效

### 1.1 改了什么

`vector_adapter._search_with_timeout` 从 `with ThreadPoolExecutor(...) as executor:` 改为**手动管理 + `finally: executor.shutdown(wait=False)`**（照抄同仓库 `agent/skills_mgmt/reranker.py:741-756` 的既有正确写法），超时/异常分支附加 `future.cancel()` 尽力取消，并在注释里写明并发语义。

### 1.2 并发语义（卡片要求明确回答）

- **超时后是否回落到非向量路**：是。超时 → `search()` 返回**空结果**（`SkillVectorSearchResult`，`degraded=True`、`degrade_reason="timeout"`）⇒ 外层 `SkillLoader._try_vector_match` 返回 `None` ⇒ 回落 TF-IDF；RRF 路则回落 `tfidf+bm25` 两路融合（`fallback_used=True`）。语义与修复前一致，**只是不再隐形**。
- **被放弃的工作线程**：Python 线程无法终止，它会继续跑完（占用 1 个线程；若走到编码则同时持有该 query 的 per-key 锁）。这是**有界**的资源占用，相比「阻塞请求线程无界久」是明确取舍；后台线程若最终成功只会写入 query 缓存等内部状态，不影响已返回结果。
- **`_search_impl` 内部已持锁吗**：不。`self._lock` 只在 `ensure_indexed` / `_remove_skill_vector` / 状态读写处持有，`_search_impl` 全程不持 `self._lock`，故后台线程不会把索引锁带进"僵尸"状态。

## 2. 修复 (2)：LLM 客户端显式 timeout / max_retries

### 2.1 改了什么

`OpenAIAdapter.__init__` 新增关键字参数 `timeout` / `max_retries`（默认 `None` = 走模块默认解析），`_get_client()` 在 `OpenAI(**kwargs)` 上追加 `kwargs.update(self._client_options())`。新增 `_client_options()` 与 `_env_float/_env_int` 两个环境变量读取器。

取值（审计 F5 初值，采纳）：`Timeout(connect=5, read=45, write=45, pool=5)` + `max_retries=1`。理由：
- `connect=5s`：建连失败必须快；
- `read=45s`：默认 600s；本系统实测单工具端到端 p90 ≈ 3.2s、最慢 8.17s ⇒ 45s 仍有 5~10 倍余量；
- `max_retries=1`（原 2）：SDK 只对连接错误/超时/5xx/429 重试，1 次可覆盖瞬时抖动；最坏占用 `(5+45)×2 ≈ 100s`，相比 `600×3 = 1800s` 收敛约 **18 倍**。
- 可部署级调参：`LLM_ADAPTER_CONNECT_TIMEOUT` / `LLM_ADAPTER_READ_TIMEOUT` / `LLM_ADAPTER_MAX_RETRIES`（非法值回退默认并打 WARN）。

### 2.2 不改变"调用方已显式传 timeout"的语义（证据：SDK 源码）

```text
$ python -c "import inspect,re,openai._base_client as bc; [print(m.group(0)) for m in re.finditer(r'[^\n]*(timeout|max_retries)[^\n]*', inspect.getsource(bc.BaseClient))]"  # 摘录关键两行
timeout = self.timeout if isinstance(options.timeout, NotGiven) else options.timeout
max_retries = options.get_max_retries(self.max_retries)
```

`options` 来自请求级参数 ⇒ 调用方在 `generate()/chat()` 的 `**kwargs` 里传的 `timeout`/`max_retries` 经 `safe_kwargs` 透传给 `chat.completions.create`，**优先级高于客户端默认值**。单测 `test_request_level_kwargs_still_pass_through` 用桩客户端断言这两个参数确实到达了请求层。

## 4. 修复 (4)：`ensure_indexed` 改为内容哈希判增量

### 4.1 策略（全量 vs 增量 vs 阈值触发）与代价

| 路径 | 触发条件 | 代价 |
|---|---|---|
| **增量**（默认） | 脏条数 < `max(8, 40% × 总数)` | 只重编码变更项：`脏数 × 单条编码` + 一次 numpy 行删除/堆叠；典型 0~2 条 |
| **阈值触发全量** | 脏条数 ≥ `max(8, 40% × 总数)` | 整批重编码 `总数 × 单条编码`（一次性），换取不做大量单条 numpy 行操作 |
| **强制全量** | `force=True` 或首次构建 | 同上 |

- 哈希源 = `_build_vector_text(meta, sid)` 的**返回值**（name + description + tags + category + body 前 500 字符）⇒「哈希变了」严格等价于「送进 BGE-m3 的文本变了」，不会出现"哈希判新但文本相同"的无谓重编码；文本只在同一次调用里算一次，不重复读盘。
- **重编码代价的诚实说明**：BGE-m3 为 4.25 GB、CPU 推理，**单条编码耗时本卡未实测**（加载该模型不在本卡资源预算内，也不在"只跑 targeted 测试"的允许范围）。因此阈值**只用「条数」作判据**，不使用任何未实测的时间估计。按审计 Q3 的测算口径：全量 = 技能总数 × 单条耗时，增量 = 变更数 × 单条耗时，阈值取 40% 是"何时不再值得逐条删除/堆叠"的经验拐点，可由 `_CONTENT_HASH_FULL_REBUILD_MIN_DIRTY` / `_CONTENT_HASH_FULL_REBUILD_DIRTY_RATIO` 调整。
- **删除清理**：源里消失的技能，其向量会被真正删除（旧实现不清理，残留向量会继续被召回）。
- **失败即重试**：只有「编码 + 入列」都成功才写哈希 ⇒ 失败项下次仍会被重编码（旧实现会把 `new_ids` 整批标记为已索引，即使 `batch_add` 抛错）。
- 顺带修掉一个真 bug：维度不匹配重建分支以前只清 `_indexed_skill_ids`，在内容哈希判据下会被误判为"内容没变"从而跳过重编码 → 索引永久为空；现改为走 `_reset_index_locked()`（同时清哈希）。单测 `test_dimension_mismatch_rebuilds_and_reencodes` 守卫。

## 5. 修复 (5)：`SkillIndexCache` 覆盖主轨（在 `index_cache.py` 内解决）

### 5.1 设计

- **主轨路径**：`<repo_path>/../skills_mgmt.json`（默认布局 `<root>/data/skills_mgmt.json`）；可用 `SKILLS_INDEX_MAIN_TRACK_PATH` 显式覆盖，`SKILLS_INDEX_MAIN_TRACK=0` 关闭补位（回滚开关）。
- **主轨条目 → front matter 同构 dict**：只取 `_META_FIELDS` 白名单字段 ⇒ 主轨记录里的 `content` / `versions` / `metrics` / `review` 等大字段**不进索引**（否则 `cache.json` 会膨胀数十倍），并保留 `_track="main"` 内存标记。
- **合并视图**：`主轨打底 + 文件轨覆盖`，即**文件轨优先**。重合的 15 个 id 取值与修复前**逐字一致**（现有 Layer-1 语义零变化）；只有文件轨缺失的 id 才会由主轨补上（= 审计 Q3 S2 的 7 项缺口）。「主轨优先」的收敛属于 G1「描述唯一事实源」，不在本卡范围。
- **持久化分区分开**：`skills`（文件轨，不变）+ `meta` + **新增** `main_track` / `main_track_meta`。分开的理由是 S1 巡检门按 `skills` vs 文件轨比对，混在一起会把主轨独有技能误报成"多余"。`cache_version` 保持 `1.0`：旧读者读到新键只会忽略，新读者读到旧文件会把 `main_track` 缺失视为"主轨尚未索引"并在首次访问时刷新并落盘（升级路径）。
- **失效判据**：主轨文件级 `mtime + md5` 双校验（与文件轨同一套思路）；变化即刷新补位并重建合并视图。
- **`id()` 契约**：合并视图只在**内容真的变化**时替换对象（`_merged_dirty`），未变化时 `get_all_metadata()` 返回同一 dict —— 守 loader 倒排索引的 `id(index)` 失效检测契约。
- **单技能查询**：`get_metadata(id)` 在文件轨不存在时回主轨（旧实现直接 `None`），两轨都无才清理并返回 `None`。

### 12.2 根因定位（按复核者列的 3 个怀疑点逐一排除）

### 13.7 裁决 2 落实：低覆盖降级库 => 显式 degraded + 可配阈值（默认 50%）

- 新增 `SKILL_VECTOR_FALLBACK_MIN_COVERAGE`（默认 **0.5**，夹到 [0,1]；非法值回退默认并打 WARN）。

- **S3 门保持 FAIL 不动**（事实就是 8/30），不粉饰。
