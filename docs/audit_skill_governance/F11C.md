## 0. 一句话结论

F11-B 登记的遗留**成立且已复现**：同一句中文改写，在索引里只有 1 条工作流时
raw sim **0.0028**（判不命中），索引变成 2 条后 **0.5481**（判命中）——召回结论
取决于"系统里存了几条工作流"，而不是查询与工作流有多像。

但 F11-B 对**成因**的表述不完整：真正让它塌陷的不是"引入了索引文本里没有的字符"，
而是两处**可分别证伪**的机制：

1. `_idf` 的 `max(..., 0.001)` **只抵消了文档侧**。查询里 df=0 的词权重仍是
   `log(N+1)`（单文档 **0.693**），是已见词 0.001 的 **693 倍** ⇒ 查询向量被
   "没见过的词"主导。原注释"下界会相互抵消、退化为纯 TF 余弦"**不成立**。
2. `matcher._tokenize` 把中文**切回单字**（`[\u4e00-\u9fff]`），而
   `register` 拼进索引文本的触发词/签名是 F11-B 的**2 字滑窗** ⇒ 索引里的
   bigram 特征**永远不可能被查询命中**（F11-B 对匹配面的贡献 ≈ 0），
   并且单字索引下"任意两段中文都有字重叠"，只能靠 idf 压误召 ——
   而那正是召回塌陷的来源。**两者是一件事的两面。**

修法：`_idf` 改**加 1 平滑**（下界从 0 平移到 1，最坏比值 693 倍 → **1.69 倍**），
`_tokenize` 与 `learner.term_stream` **同源**（索引侧/查询侧同一个分词器）。
零新增依赖。

## 2. 定性：三个问题

### 2.1 Q1 —— 会不会随语料增长而改变行为？**会，且方向是"翻转结论"**

- 证据 A（§1.2）：`加虚词` N=1 → `无候选`，N=2 → `0.5481 / 候选`。
  `换同义词` N=1 → `无候选`，N=2 → `0.4202 / 候选`。**同一输入、同一代码，只改了索引里有几条。**
- 证据 B（§1.3）：生产真实语料 N=1，一条等价改写的 raw sim 0.0023/0.0013，
  与原样 0.9215 差 **400~700 倍**。
- 机制可复算：`_idf(N,df)=max(ln((N+1)/(1+df)), 0.001)`。
  - N=1, df=1（文档里所有词）→ `ln(2/2)=0` → 下界 **0.001**；
  - N=1, df=0（查询里的新词）→ `ln(2/1)=0.693`；**比值 693**。
  - N=2 起 `ln(3/2)=0.405` vs `ln(3/1)=1.099`，比值降到 2.7 ⇒ 塌陷消失。
  即**病态只出现在小语料**，随语料增长自愈——但它今天正处在病态区。
- 另一处同源不稳定：**对抗性填充**（新学一条与目标同话题的工作流）也会改变
  top1 身份（探针 `probe_b.py` §part2：idx 1→13 时 top1 从目标换成另一个近义条目，
  原样 0.8532 → 0.9460 → 0.8361 非单调）。这一条**是正确行为**（近重复条目本就该
  竞争），单列以示区分。

### 2.2 Q2 —— 会不会造成误召？**目前没有；但 F11-B 测到的"0.0001 防误召"本身不稳定**

- **结论：四档语料下都没有误召。**
  - 探针 `probe_a`：`无关句` 在 N=1/2/5/20 全部 `无候选`（0.0001 / 0.0315 / 0.0307 / 0.1203，阈值 0.3）。
  - 真实语料：8 条日常请求（"帮我写请假邮件""解释一下什么是机器学习"…）最大 **0.0449**，
    0 条 ≥ 0.3（探针 `probe_h`）。
- **但余量不是语料规模无关的。** F11-B 的 0.0001 是 **N=1** 的值；同一个无关句
  在 N=20 是 **0.1225**、N=60 是 **0.1322**（探针 `probe_b`）——涨了 **1300 倍**，
  距 0.3 门槛的余量从 **3000 倍缩到 2.3 倍**。用不同填充池的 `diff_probe`
  在同一档量到 **0.1763**（余量 1.7 倍）。
  ⇒ "防误召做得好"是**小语料的假象**，不是结构性性质。
- 修复后（探针 `probe_b`/`probe_g`）：同一无关句在 N=1..60 **恒为 0.0000**
  （bigram 口径下无关中文句几乎不共享特征）；
  长无关句（30+ 字）最大 0.0414→**0.0863**（对照 HEAD 的 0.0447→**0.1765**，
  修复后**只有 HEAD 的一半**）。

## 3. 裁定：**改**

三条依据，按权重排序：

1. **卡面把"行为不稳定性"排在召回率之前**，而 §2.1/§2.2 证明不稳定出现在**两侧**：
   召回侧会翻转结论，防误召侧的余量随语料缩水 1000 倍以上。
   只有同时改 `_idf` 与分词口径才能把两侧都变成**语料规模无关**（见 §4.2 的对照）。
2. **该缺陷此刻正在生产上生效**（索引 N=1，§1.3）；且它是 F11-B 自己登记、
   并在测试里写明"若将来被修好…请更新那条遗留，不要在这里放宽断言"的项。
3. **修法零新依赖、代价可量化、且方向安全**：
   误召压力**下降**（N=60 长无关句 0.1765 → 0.0863；短无关句恒 0），
   召回**上升且稳定**，英文路径不变（§4.2）。

**被否掉的两种"只改一半"**（探针 `probe_e2`/`probe_g`，均在真实生产入口下）：

## 5. 未验证项与残留风险

1. **executor 综合分门槛是第二道独立过滤，F11-C 没动它。**
   `combined = sim × conf_factor × priority_factor`，其中已执行过的条目
   `conf_factor = confidence ∈ [0.4, 1.0)`、`priority_factor ∈ [0.5, 1.0]`。
   实测：目标条目执行 3 次后 `换同义词` sim=0.4136 但 combined=0.2152 < `min_score` 0.25
   ⇒ **matcher 层召回了，端到端仍不执行**。
   即"修好 matcher"**不等于**"端到端召回变好"；弱改写（sim 0.3~0.5）基本只在
   `success_count==0` 的冷启动那一次能过。该门槛属 executor 策略，**不在本卡范围**，
   已在新测试 `test_执行器综合分门槛仍是第二道独立过滤_登记为遗留` 里钉成可复算事实。
2. **填充语料是合成的**。60 条中文任务是我手写的，不是真实学到的工作流；
   真实 `description`/`source_user_input` 更长更杂，bigram 碰撞的概率未被完全覆盖。
   长查询压力测试（`probe_g`，10 条 30+ 字无关句）覆盖了一部分，仍不等于生产分布。
3. **对抗性填充下 top1 身份会变**（§2.1 证据 C）。我判定为"正确行为"，
   但**没有独立验证**"新 top1 是否真的是更好的答案"——只验证了 sim 数值。
4. **`换同义词` 在 N≥1 仍随语料小幅漂移**（0.4136 → 0.4998，N=1→20）。
   方向单调且恒 > 阈值，**结论不变**，但"数值完全不变"并不成立；
   本卡只承诺"**决策**与**数量级余量**与语料规模无关"。
5. **只验证了中文与英文两条路径**。数字/纯符号 token 在新分词器下会被丢弃
   （`_SIG_RUN_RE` 要求 ASCII 段以字母开头且长度 ≥ 2；旧 `[a-zA-Z0-9_]+` 会保留
   `3000`、`_x`、单字母）。索引文本里只拼了 `tool_name` 不含数值参数，
   且英文回归全绿，但**含数字的查询/描述**这一路我**没有**单独做端到端实验。
6. **所有实测都在进程内、临时仓库里做的**，没有起服务、没有真实 LLM 调用。
   `data/learned_workflows.json` 全程只读（复制到 TEMP 再读）。
   探针未覆盖 orchestrator 的 DST 补全（`routing_input` 与用户原话可能不同），
   即"生产真实输入"与本卡输入之间仍有未知差异。
7. **`_idf` 的 +1 平滑对其他消费者无影响**这个判断只覆盖了 `TfidfIndex`
   （`_idf` 唯一调用点）。全仓 grep 未见第二处引用。
8. **`config.workflow_learning.*` 大部分配置无人读取**（见 §6），
   本卡**没有**去接线，也没有改动 `config.py`/`config.yaml`。
