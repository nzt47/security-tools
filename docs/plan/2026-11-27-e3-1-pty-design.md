## 1. 为什么是「一个工具 + action 枚举」而不是 6 个工具

路线图写的是 `terminal_open/send/read/signal/close/list` 六个工具。但它们是**同一个会话对象的六个动作**，
做成 6 个会让「新增工具」的 5 处连锁（工具索引 / 能力清单 / BM25 半饱和点 / 路由基线 / 路由冲突 τ）
连着改 6 次，而且模型要学 6 条描述。收成 1 个 `terminal` 工具 + `action` 枚举后：

- 连锁只发生 1 次（索引 103→104、清单 153→154、S0 5.8269→5.8606、v1 τ 0.0297→0.0296）；
- 错误文案能就地说清缺哪个参数（`action=read 需要 id`）；
- 以后加 `resize` 之类动作只改 enum，不动工具面。

## 2. 安全边界（三层，顺序不可换）

| 层 | 判据 | 失败姿态 |
|---|---|---|
| 开关 | `CP_TERMINAL_ENABLED`（B 级，**默认 0**） | 回「需要 CP_TERMINAL_ENABLED=1」，不降级成管道 |
| 权限预设 | `agent.sandbox.is_confined()` 为真 ⇒ 拒绝 | fail-closed；判不了也拒绝 |
| 审计 | open/send/signal 记 `terminal_*`，只记命令**摘要与长度** | 审计失败只记 debug，不影响会话 |

为什么默认关：raw PTY 是一条**完整交互 shell**，绕过 `shell_execute` 的一次性命令模式匹配，也绕过
权限预设对子进程的限制。**不要把「终端」当成「更好用的 shell_execute」**。

【与「新工具默认 enabled: false」的关系（口径 §3.4）】本工具的 YAML 写的是 `enabled: true`，
原因是**可用性判定只留一处**：如果 YAML 也关掉，用户就要同时打开「工具页启用」和
`CP_TERMINAL_ENABLED` 两个开关，而且关掉 YAML 会让它从工具页消失（无法在界面上看到/审计）。
现在的语义是：工具**始终登记**（可审计、可在工具页看到），**能不能用**由 `CP_TERMINAL_ENABLED`
+ 权限预设一处判定；调用被拒时返回的文案直接告诉你该开哪个开关。

## 3. 平台与降级

- Windows：`pywinpty` 的 ConPTY（`PtyProcess.spawn`）。pywinpty 声明为**可选依赖** `.[pty]`
  （`pywinpty>=3.1.0; sys_platform == "win32"`），`agent/pty_session.py` **延迟 import**；
  缺失时 open 回「缺少 pywinpty：pip install pywinpty 后重试」，**不静默降级成管道**
  （管道不是 TTY，REPL/进度条行为会变，那会让人以为能用）。
- POSIX：标准库 `pty.openpty()` + `subprocess.Popen(preexec_fn=os.setsid)`，读线程 `os.read`。
- 终止：先 `terminate()`，再 `agent/proc_tree.kill_tree(pid)`（PTY 会话常带孙进程，只杀直接子进程会漏）。

## 4. 输出缓冲与会话生命周期

- 每个会话一个读线程（PTY 输出不读会把子进程写阻塞），缓冲是**有上限的环形窗口**
  （`CP_TERMINAL_BUFFER_CHARS`，默认 200k）。被裁掉的部分用 `trimmed_from` 如实告知，
  `read(offset=0)` 会返回 `trimmed: true` 并把 offset 对齐到当前窗口起点 —— 不假装读到了。
- 会话上限 `CP_TERMINAL_MAX_SESSIONS`（默认 4）；空闲 `CP_TERMINAL_IDLE_SECONDS`（默认 1800s）自动回收。
- 会话**只存进程内存**（重启即失），不做持久化：PTY 进程本来也活不过重启。

## 5. 交互语义（实测坑）

- `send` 默认补 **`\r`**（PTY 的 Enter），不是 `\n`：Windows ConPTY 收 `\n` 不认为一行结束
  （实测：子进程的 stdin 迭代拿不到整行）；POSIX cooked 模式把 `\r` 经 ICRNL 转成 `\n`。
- 终端**会回显**输入：read 里能看到自己发的内容，判断"程序有没有响应"要看回显之后的部分。
- 不提供 `resize`：改窗口大小对多数脚本无意义，等真有需求再加（加 enum 值即可，不动工具面）。

## 7.5 启用开关之后还要做的一步（重要）

工作台对话的工具集来自**主线装配**（`agent.lines.line_whitelist` + `data/agent_lines/engineering.yaml`
的 boost 与 `max_tools` 截断），不是注册表全集。本轮实测：注册表里有 `docx_read` 但没进 boost 时，
模型直接回答「工具列表里没有它」。

所以**打开 `CP_TERMINAL_ENABLED` 之后，还要**：
1. 把 `terminal` 加进 `data/agent_lines/engineering.yaml` 的 `boost`（否则它可能被名额截断）；
2. 先 `POST /api/agent-lines/preview` 量「加/丢」，按结果调 `max_tools`（本轮 docx 的实测：30 会挤掉
   run_sandbox、31 零丢失、32 还能找回 run_tests）；
3. 重派生 `data/capability_manifest.json`（`by_main_line_status.visible` 会变）。

**本轮故意没有**把 terminal 放进 boost：默认关时它只会占名额并回「未启用」，对模型是噪声。
`terminal` 不在 boost 时仍可能被"智能选择"选中（它在 code 分类里），所以开关打开后即时可用；
要稳定可见再按上面三步加。
