## 1. E0-2④ token-meter 驱动压缩

**为什么**：压缩触发与 `/api/context/status` 此前量的是同一个**代理指标**——本会话最近
`COMPRESS_TRIGGER_WINDOW`(200) 条正文。同源没错，但「记忆池里的正文」≠「真正装进请求的上下文」
（系统提示 + 工具 schema + 历史 + 摘要，实测主线光固定开销就上万 token）。DSH 的 token-meter 用实测装配量。

**做法**（`memory/token_meter.py`）：

| 环节 | 口径 |
|---|---|
| 读数入口 | 只有 `usage()` 一个；`should_compress()`（触发）与 `/api/context/status`（界面）都调它 |
| 写样本 | `record()` 由装配方写**实测值**（`plugins/chat.py` = 系统+工具+历史；`orchestrator._check_context_usage` = 记忆上下文），本模块不做估算 |
| 触发 | `prompt >= limit * compress_threshold`，**且** `prompt >= watermark * growth(1.10)` |
| 水位 | 压缩成功后 `note_compaction()` 记当时实测值（压缩只写摘要、不删消息 ⇒ 量值不降，不记水位就每条消息压一次，口径 §7） |
| 分母 | 优先编排窗口（与 `/api/context/status.token_limit` 同一个数），缺省用样本自带窗口 |
| 开关 | `CP_TOKEN_METER`（默认开，A 级）：关掉 = 只按记忆窗口口径触发，读数仍在 |

**界面口径不合并**：`percentage` 仍是 `compress_trigger_window`（记忆窗口），实测值另列
`metered` / `metered_percentage` / `compression_trigger`。面板同时显示「实测装配」与「最近触发：
实测 / 工具结果 / 记忆窗口」，两个数各自可复核，不互相冒充。

**边界（如实声明）**：
- 实测样本是**内存态**，进程重启即清空（不落盘造第二份状态）；无样本时界面显示 `—`，不折算成 0。
- 实测值在工作台链路上会随历史预算**饱和**（`_select_within_budget` 把历史裁到刚好装下），
  所以它的作用不是"无限逼近窗口"，而是"代理指标偏冷时补一刀"；重复压缩由水位挡住。

## 2. E0-2③ 图片/截图 offload

**为什么**：`browser_screenshot` 回的是 base64 PNG，上限 500000 字符（≈ 十几万 token，比整个窗口还大）。
图片内容没坏，只是不该进上下文。

**做法**（`agent/context/image_offload.py`，挂在 `agent/tools/__init__.py` 的 spill **之前**）：
- 只处理键名像图片（`*_base64` / `base64` / `*_image_b64`）、带 PNG/JPEG/GIF/WebP **魔数**且超过阈值的字段；
  普通长文本、坏 base64、短图一律不动（宁可不过滤，不误删正文）。
- 落盘到 `agent/data/images/<16hex>.<ext>` + 同名 `.json` 元数据；locator = `image:<16hex>`（按内容摘要派生，同图同 id）。
- 结果保留字段名、值换成一行占位，并补 `image_offloaded/image_locator/image_bytes/image_mime/image_size`（dict 契约不破）。
- **再读**：`read_spill(locator="image:...")` 分派到 `read_image_locator()`，只回元数据 + 尽力 OCR
  （OCR 不可用时如实 `available:false` + note）；二进制原文不进上下文。
- 开关：`CP_IMAGE_OFFLOAD`（默认开）/ `CP_IMAGE_OFFLOAD_MIN_CHARS`（默认 4000）。

## 3. E0-4① 每步时钟（time-context）

**注入点只有一个**：`plugins/chat.py` 的 `_volatile_parts`（既有「易变尾簇」→ 落到请求最后一条用户消息）。
时间每轮都变，放进 system prompt 会把整条请求的缓存前缀钉死（2026-11-08 同类事故）。

- 内容：`【时间上下文】现在 YYYY-MM-DD HH:MM:SS（周X）；本轮已进行 N.Ns（仅供判断先后与等待；不是硬约束）`。
- 默认**关**（`CP_TIME_CONTEXT`）：时间戳会改变「同一问题同一答案」的复现性。
- 只做提示：不打断工具、不参与超时判定。
- 刷新粒度如实说明：**每次请求**刷新（不是每个工具步），因为尾簇只在装配时拼一次；再加第二个注入点会违反「一处 helper」。

## 4. E0-4② 子进程硬超时：杀整棵进程树

**缺口**：`run_sandboxed` 超时走 `proc.kill()`，只 TerminateProcess 直接子进程。
`cmd /c python -m pytest` 这类命令的**孙进程**继续跑并占住 SQLite/日志文件锁（下一轮撞「文件被占用」）。

**做法**（`agent/proc_tree.py`）：
- Windows：`taskkill /F /T /PID`（系统自带，无需 psutil；返回 128 = 进程已不存在，按幂等算成功）；
- POSIX：从 `/proc` 建父子表，**叶子优先** SIGKILL；拿不到 /proc 才用 psutil，再不行只杀直接子进程并返回 False；
- **不用 `killpg`**：父进程没建新会话时 `os.killpg(os.getpgid(pid))` 会连服务自己一起杀——那是最坏的「修」。
- `run_sandboxed` 超时分支：先杀树，失败退回 `proc.kill()`；收管道加 5s 宽限，仍不关就如实回空输出（绝不无限阻塞）。

**线程内工具不会中断**（已写进 `agent/timeout_budget.py` 的常量注释）：Python 没有安全抢占线程的手段，
`CP_TOOL_HANDLER_TIMEOUT_SEC` 到点只是「调用方拿到超时错误」，handler 仍在后台跑完。写新工具时若不可杀，
必须在 docstring 里写明，别让人以为超时=停止。

## 5. E0-1② 压缩/解压接写围栏

`compress` / `decompress` 此前只有 `safe_resolve_path`（穿不过 `..`/保护目录）+ `is_protected_path`，
但**没有权限预设的写档闸**：`workspace-write` 档下把 `output_path`/`output_dir` 指到工作区外照样落盘，
而 `write_file`/`edit` 在同一档下会被拒（同一件事两套边界）。现在两者都走 `fs_fence.check_write`：
- 拒绝文案固定 `[sandbox: file access denied under <mode> mode]`，审计事件 `sandbox_fs_denied`（只记工具名 + 路径指纹）；
- 拒绝发生在**建目录之前**（不留半成品目录/文件）；
- `full-access`（默认档）行为逐字不变。

## 6. E0-1① 受限档 bash：结论与探针

**结论：维持 fail-closed，不给 bash 预置宿主服务/共享内存授权。**

证据（本机实测，`python scripts/sandbox_grant.py --probe-shell --json`，探针按 `workspace-write` 档执行 `echo ok`）：

```json
{ "available": ["cmd", "powershell"], "unavailable": ["bash"] }
```

- WSL 的 `bash.exe` 走 LxssManager 服务、Git Bash 的 MSYS2 运行时建共享内存段，两者都被受限令牌的 pass-2 拒绝；
  这是**结构性**限制，不是多给一条 ACL 能修的；给它开授权等于给受限令牌打洞。
- 受限档下仍有两个 shell 可用（cmd / powershell），且 `_detect_shell` 在受限档把**无特征命令**默认切到 cmd，
  带 unix 特征的命令回「可执行提示」（`bash_unavailable` 标记），不会静默降级。
- 使用频率：`shell_execute` 在近 18 个使用台账文件里 50/1353 次（第 3 常用）⇒ 切档会改变它的可用 shell，
  切前必须告知，切后看审计 `sandbox_shell_confined` 与失败率。

**④ 生产切档仍未做**（Owner 拍板的 B 级操作）。前置清单：
1. `python scripts/sandbox_grant.py --status` 的 `granted=true`；
2. `python scripts/sandbox_grant.py --probe-shell` 里 cmd/powershell 至少可用（bash 预期 false）；
3. 切档后用审计 `sandbox_shell_confined` 与工具页 `shell_execute` 失败率观察 24h；回滚 = 设置中心 B 级切回 `full-access`。
