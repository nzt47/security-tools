## 0. 现状事实（2026-11-27 实测）

| 物 | 位置 | 性质 |
|---|---|---|
| 每会话消息 | `data/sessions/<session_id>/messages.jsonl`（75 个会话目录） | **追加写**，行 = `{role, content, timestamp[, 工具字段]}` |
| 冻结池 | `data/messages.jsonl` 无 `session_id` 的行 | **不迁移、不改写**（口径 §13）；**2026-11-27 实测该文件 0 字节 / 0 行**（`/api/context/status.legacy_pool` 也是 0，口径里"约 305 条"是历史读数） |
| 会话索引 | `agent/context/session_index.py` 的 SQLite | 可从 `messages.jsonl` **全量重建**（已如此设计） |
| 审计链 | `data/audit/audit_chain.db`（seq 单调） | 系统动作台账，**不是**对话事实 |
| 摘要/压缩 | `data/summaries*` + `messages.jsonl` 内的摘要消息 | 只写摘要、不删原文（口径 §7） |

**缺口**：行里没有「事件类型 / 版本 / 会话内序号」，也没有工具调用与结果的成对关系 —— 读方只能按
`role` 猜语义；换格式（例如工具消息结构化）时没有版本位可依。

## 1. 目标与不变量（先写死，后面每条都受它约束）

1. **append-only**：新事件只追加，**从不**就地改写已有行；`messages.jsonl` 在 Phase C 之前**一个字节都不动**。
2. **历史可回放**：给定任一 `session_id`，能从事件投影重建出与 `messages.jsonl` 等价的对话视图。
3. **冻结池不碰**：`data/messages.jsonl` 只读；投影器**跳过**无 `session_id` 的行并计数上报。
4. **读取方不变直到显式切换**：Phase A/B 期间对话链路仍读 `messages.jsonl`；切换是**一个开关**的事。
5. **失败不堵塞对话**：投影器任何异常只记日志 + 指标，绝不让聊天 500。

## 2. 事件模型（v1，最小够用）

每行一个事件，字段固定：

```json
{"v":1,"type":"message.assistant","sid":"<session_id>","seq":42,"id":"evt_...",
 "ts":"2026-11-27T05:00:00.000+00:00","payload":{...},"src":"legacy|live"}
```

- `type`：`message.user` / `message.assistant` / `message.tool_call` / `message.tool_result` /
  `message.summary` / `session.meta`（首批只做前五类；`session.meta` 留给标题/工作目录）。
- `seq`：**会话内**单调递增（投影器按 `timestamp` 排序后编号；同一毫秒用 `id` 兜底稳定排序）。
- `id`：`evt_` + 内容摘要（`sha256(sid|ts|role|content)` 前 16 hex）——用于**幂等去重**，不依赖原行有没有 id。
- `src`：`legacy`（从 messages.jsonl 投影而来）或 `live`（切换后实时写）。
- **不做哈希链**：审计链已承担防篡改；对话事件的诉求是「可回放」而不是「可举证」，哈希链会让追加写变复杂
  且对既有行不可追溯（历史行没有 prev_hash）。

## 3. 迁移四阶段（每阶段都有回滚）

| 阶段 | 动作 | 读取方 | 回滚 |
|---|---|---|---|
| **A 影子投影（只读）** | 扫 `data/sessions/*/messages.jsonl` → 写 `data/session_events/<sid>.jsonl`；产出 `data/session_events/_migration_report.json`（每会话行数/序号/跳过/隔离计数）。**报告落在运行期目录、不进 git**（它是可重派生的状态，不是门禁产物） | 不变（仍读 messages.jsonl） | 删 `data/session_events/`；**零副作用** |
| **B 双写对照** | 新消息在**同一次写盘**里追加到两处（先 messages.jsonl 后事件），事件写失败只记指标、不回滚消息 | 不变 | 关 `CP_SESSION_EVENTS_WRITE=0`；事件目录可删 |
| **C 读取切换（灰度）** | `CP_SESSION_EVENTS_READ=shadow|events`：`shadow` = 读 events 但结果与 messages 对拍（不一致记差异、用 messages）；`events` = 以 events 为准 | 灰度按会话白名单 | 开关改回 `off`（默认）即回 messages |
| **D 收尾（≥30 天且零差异）** | messages.jsonl 降级为「兼容副本」，不再作为读源；**不删除**（保留一个发布周期） | events | 同 C |

判据：**A 阶段报告的「跳过行数」必须恰好等于冻结池行数**（当前实测 0；不为 0 时说明有人又往池里写了，
脚本要如实报告而不是静默跳过）；**B/C 的差异数必须为 0 才允许进下一阶段**。

## 4. 幂等、校验与规模

- 幂等键 = `(sid, id)`；重跑投影器跳过已存在事件（`id` 命中即跳过），**不重排、不改 seq**。
- 校验三件：① 每会话 `events 行数 == messages 行数`（跳过冻结池）；② 首尾 `ts` 与内容 sha256 清单一致；
  ③ 随机抽 5 个会话做全文对拍（`transcript` 级）。
- 规模（2026-11-27 首次实测）：76 个会话目录、**合计 989 行**消息（含 E2E 探针会话）；投影全量 < 1s（脚本，不进请求链路）。
- 存储：`data/session_events/` 与 `data/sessions/` 同盘同权限；**不进 git**（运行期状态）。

## 5. 回滚（一条命令 + 三个开关）

1. `CP_SESSION_EVENTS_READ=off`（默认）→ 读回 messages.jsonl，**行为与今天完全一致**；
2. `CP_SESSION_EVENTS_WRITE=0` → 停止双写；
3. 删 `data/session_events/` + 报告 → 回到「从未引入」。
> 不变量 1 保证：**任何阶段都不需要恢复 messages.jsonl**（它没被改过）。这也是「禁止重写历史会话」的落实方式。

## 6. 失败姿态

- 投影器：读到坏行（非法 JSON / 缺 timestamp）→ 记入 `quarantine` 计数 + 跳过，不中断整批；
  报告里给 `file:line`，人工可复核（不静默吞掉）。
- 双写：事件写失败只记 `session_events_write_failed` 指标（含会话 id 摘要，不含内容），消息照常落盘。
- 读切换：events 读不到/损坏 → **回退读 messages** 并在响应里带 `events_fallback: true`（可观测，不假装成功）。

## 7. 判据（实现完成时逐条验）

1. A 阶段：`reports/session_events_migration.json` 里 `skipped_legacy` 等于冻结池行数（当前 0，以脚本实测为准），
   `sessions == 75`，每会话行数对拍全 0 差异。
2. 幂等：连跑两次投影器，第二次 `written == 0`，文件 sha256 不变。
3. 冻结池：`data/messages.jsonl` 的 mtime 与 bytes 在一次完整迁移后**不变**（测试断言）。
4. 双写：一条新消息 → 两处都出现；人为让事件写抛错 → 消息仍在、指标 +1、对话 200。
5. 回滚演练：`READ=events` 读 3 个会话与 messages 对拍一致后，改回 `off`，同一会话输出逐字节相同。
6. 新 env 全部登记 `agent/settings/registry.py`（`scan_settings --check` 零缺口）；不新增工具/路由（否则按口径 §3 走连锁）。

### 10.1 接线点（只有两处）

| 点 | 动作 | 失败姿态 |
|---|---|---|
| `SessionManager.add_message` | **先**写 messages.jsonl，**再** `append_live_event(sid, msg)`（事件 payload = 同一行 dict） | 事件写失败只记 `session_events_write_failed` 计数 + WARNING（含会话 id 摘要，不含正文），消息照常落盘、不抛 |
| `SessionManager.get_messages` | `READ=shadow` 时读 events **全量对拍**（切片之前比），差异只记日志/计数 | 返回的**仍是 messages**；对拍异常只 debug |

另：`clear_messages` 会同时清空该会话事件文件 —— 清空是用户显式动作，只清 messages 会让
Phase C 的 events 读把已删消息"复活"、shadow 永远对不上（append-only 保护的是"后台不改写历史"，
不是"禁止用户删自己的对话"）。

### 10.2 判据（对方案 §7）

1. **双写**：一条新消息 → messages / events 各一条，`payload` 逐字段相同，`seq` 1,2,… 单调，
   `src=live`，`id` = 共用算法（用例逐条锁定）。
2. **失败不堵对话**：把 events 根目录换成**普通文件**（必失败）⇒ 消息仍落盘、`write_failure_count()≥1`。
3. **幂等/接续**：已有 `seq=7` 的 legacy 事件 ⇒ 新事件从 8 开始（按文件 mtime 失效缓存，
   投影器原子替换后不会写出重复 seq）。
4. **回滚演练（shadow）**：`READ=shadow` 与 `off` 的 `get_messages` 输出逐字节相同
   （差异计数 0）；人为篡改事件内容 ⇒ `mismatched=1`、`first_mismatch.reason=content`，输出不变。
5. **默认关**：两个开关都不设 ⇒ 不建事件文件、读路径零变化（与今天逐字节一致）。
6. **零缺口**：两个 env 已在 `agent/settings/registry.py` 登记，`scan_settings --check` 干净 worktree 零缺口。
