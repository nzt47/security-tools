# 后台执行能力边界（shell_execute background）

> 适用范围：`shell_execute` 的 `background=true` 分支（能力声明见
> `data/tool_definitions/shell_execute.yaml`）。本文只描述**当前实现真实成立**的边界，
> 不描述期望。

## 1. 是什么

`shell_execute(command, ..., background=true)` 是 fire-and-forget 形态：

1. 先**同步**跑完危险命令检查与权限检查（与前台完全同一套：`PermissionSystem.check_text`
   / `check_action`）——命中 critical 直接拒绝，**不会**启动任何后台任务；
2. 通过既有 `AsyncExecutor` 线程池提交一次 `shell_execute`（`background` 参数**不透传**，
   见下），立即返回：

   ```json
   {"ok": true, "background": true, "task_id": "task_xxx", "status": "pending",
    "shell": "powershell", "hint": "命令已在后台启动。用 get_task_status(task_id) ..."}
   ```

3. 后续取结果走既有工具面：`get_task_status` → `get_task_result`；取消用 `cancel_task`；
   列表用 `list_async_tasks`；Web 侧对应 `/api/background/tasks*` 路由。

## 2. 边界（逐条对应实现）

| 边界 | 当前口径 | 依据 |
| --- | --- | --- |
| 并发 | 线程池 `max_workers`，默认 3；超出**排队**而非拒绝 | `agent/async_executor.py` |
| 结果保鲜 | 仅存内存，默认 TTL 3600s | 同上 |
| 进程重启 | 内存任务丢失；`data/async_tasks.jsonl` 只留痕、不用于恢复 | 同上 |
| 取消 | 只改状态；线程池无法中断已在运行的子进程 ⇒ 命令可能继续跑到自己的 timeout | `AsyncExecutor.cancel` |
| 输出 | 仍受 `execute_shell` 的 100KB 截断 | `agent/tools/shell_tools.py` |
| 单条时长 | 仍受 `execute_shell` 的 timeout 上限 120s（默认 30s） | 同上 |
| 沙箱 | 与前台同一条执行路径（`_legacy_execute` / `_sandboxed_execute`，受 `CP_SANDBOX_SHELL_MODE` 控制） | 同上 |
| 二次过闸 | 工作线程内经 `agent.tools.call` 再走一遍 `tool_gate` 与权限检查（与既有的 `submit_task` 同口径） | `agent/async_executor.py::_run_task` |
| 身份透传 | 来源（session_source）与身份（identity）在 submit 时**显式**传入 —— ThreadPoolExecutor 不继承 contextvars | TASK-05 / TASK-06 |
| 命令原文 | 会随 `params` 落进 `data/async_tasks.jsonl`（运行时台账、不入库）；与 shell 审计只记摘要的口径不同 | `AsyncExecutor._save_task` |

## 3. 明确**不**覆盖

- **不延长单条命令时长**：`background` 解决的是「不阻塞对话」，不是「跑过 120 秒」。
  需要长时间驻留的进程用 `run_program`（白名单程序，fire-and-forget 且返回 PID）。
- **不能真正终止**：`cancel_task` 停不掉已经跑起来的子进程；要终止需按 PID 处理。
- **不是持久化作业**：进程重启即丢，没有重启续跑。
- **不适合需要交互式审批的命令**：二次过闸发生在工作线程，那里没有弹窗面。

## 4. 为什么复用 AsyncExecutor、且不新增工具

「句柄 + 状态 + 结果 TTL + 取消」这套语义已由 `agent/async_executor.py` 与四个既有工具
（`submit_task` / `get_task_status` / `get_task_result` / `cancel_task`）提供；自建一套
必然与它漂移。因此本能力只是给 `shell_execute` 加一个 `background` 参数，
**能力清单条目数保持不变**（仍是 119 条）。
