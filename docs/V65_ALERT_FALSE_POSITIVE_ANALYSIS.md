## 2. 详细分析与修订

### 2.1 【高风险】P1-2 P99 延迟突增 — 冷启动误报

**原始表达式**：
```promql
P99 > 2 * P99 offset 1h AND P99 > 300
```

**误报场景**：
- 服务刚启动（部署/重启后 1h 内），`offset 1h` 前无数据
- Prometheus 对缺失数据按 0 处理：`2 * 0 = 0`
- 任何 `P99 > 300` 都满足 `P99 > 0`，告警误触发
- 实测：服务启动后 P99 258ms → 不触发；但若有 CPU 预热期 P99 短暂超 300ms → 误报

**修订后表达式**：
```promql
P99 > 2 * P99 offset 1h
AND P99 > 300
AND sum(rate(yunshu_rerank_duration_ms_count[5m] offset 1h)) > 0.5  -- 冷启动保护
AND sum(rate(yunshu_rerank_duration_ms_count[5m])) > 0.5             -- 低流量保护
```

**修订原理**：
- `offset 1h count > 0.5`：1h 前必须有至少 150 次请求（30 次/min），确保基线有效
- `current count > 0.5`：当前 5min 内必须有至少 150 次请求，确保 P99 分位数稳定

### 2.2 【中风险】P1-1 P99 SLO 违规 — 低流量误报

**原始表达式**：
```promql
histogram_quantile(0.99, ...) > 500
```

**误报场景**：
- 低流量时段（如凌晨），5min 内仅 3-5 次请求
- 1 次慢请求（如 600ms）→ P99 = 600ms > 500ms → 误报
- `histogram_quantile` 在样本数少时极度不稳定

**修订后表达式**：
```promql
histogram_quantile(0.99, ...) > 500
AND sum(rate(yunshu_rerank_duration_ms_count[5m])) > 0.5  -- 至少 150 次/5min
```

### 2.3 【中风险】P1-3 推理失败率 — 低流量误报

**原始表达式**：
```promql
failed / (completed + failed) > 0.05
```

**误报场景**：
- 5min 内仅 10 次请求，1 次失败 → 失败率 10% > 5% → 误报
- 实际上 1 次失败可能是偶发网络抖动，不需告警

**修订后表达式**：
```promql
failed / (completed + failed) > 0.05
AND (completed + failed) > 1  -- 至少 300 次/5min（1 req/s）
```

### 2.4 【中风险】P1-4 降级率 — 低流量误报

**误报场景**同 2.3，1 次降级在 10 次请求中占 10% > 阈值。

**修订**：同 2.3，增加 `(completed + fallback) > 1` 最小样本数保护。

### 2.5 【低风险】P0-2 双后端全挂 — 重启瞬间

**误报场景**：
- 进程重启时，ONNX 和 PyTorch 可能同时加载失败（模型文件暂时不可用）
- `for: 0m` 立即触发 P0 告警

**分析**：
- 此场景虽可能误报，但 P0 告警宁可信其有（双后端全挂是严重故障）
- 重启后 1-2s 内模型加载成功，告警会自动恢复
- **不修订**，保持 `for: 0m` 的立即响应能力

## 3. 修订前后对比

### 3.1 误报率预估

| 场景 | 修订前误报率 | 修订后误报率 | 说明 |
|------|------------|------------|------|
| 冷启动（部署后 1h） | ~80% | ~0% | P99 突增规则冷启动保护生效 |

| 修订项 | 漏报风险 | 说明 |

## 4. 阈值设计依据

### 4.1 最小样本数 `0.5 req/s`（150 次/5min）

| 依据 | 数据 |
|------|------|
| P99 分位数稳定性 | 样本数 > 100 时 P99 误差 < 5% |
| 生产流量基线 | 实测日均 ~2 req/s，凌晨低谷 ~0.8 req/s |
| 误报率目标 | < 5%（业界 SRE 标准） |

### 4.2 P99 突增倍数 `2x`

| 依据 | 数据 |
|------|------|
| 基线 P99 | 258ms（ONNX quantized） |
| 2x 阈值 | 516ms（接近 SLO 500ms，提前预警） |
| 警戒线 300ms | 1.16x 基线，过滤正常波动 |

---

## 5. 持续优化建议

1. **动态阈值**：未来可引入 `recording_rules` 计算 7 天 P99 中位数，动态调整突增倍数
2. **流量分级**：按 `candidate_count` 分桶统计 P99，避免大 batch 拖累小 batch 的 P99
3. **告警聚合**：P1-1 和 P1-2 同时触发时，优先展示 P1-1（SLO 违规更严重）
4. **回顾周期**：每月 review 一次误报率，若 > 5% 则上调最小样本数阈值
