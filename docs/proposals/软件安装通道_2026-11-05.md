# 软件安装通道（不在云枢复活 software_* 空壳）· 2026-11-05

## 为什么不能"恢复原样"

2026-09-17 的 `36e4a09b1` 写得很清楚：`software_*`（search/install/list/uninstall）底层
`SoftwareManager` 是**空壳**，`install()` 恒返回 `True` —— 会**谎报安装成功**。
模型据此认为软件已装好并继续下一步，比"没有这个工具"更糟。

因此本设计只保留"能力诉求"（我要装/我要确认装没装），**不复用旧实现、不复用旧名字**。

## 目标

1. `software_probe`：**只读**探测（是否已安装 + 版本 + 路径），永远可以安全调用；
2. `software_install`：受控安装（winget 优先，choco 备选），**四道闸**：
   白名单源 → 显式确认 → 退出码 → 事后探测；失败如实报失败，绝不返回 True；
3. 不做 `uninstall`（删除软件风险高于安装，且没有可回滚语义）；确需卸载，人来做。

## 接口（草案）

```python
software_probe(name: str) -> {"ok": bool, "installed": bool, "version": str, "path": str, "source": str}
software_install(package_id: str, *, confirm: bool = False) -> {
    "ok": bool, "exit_code": int, "installed_after": bool, "version_after": str,
    "package_id": str, "installer": "winget|choco", "log_tail": str, "denied_reason": str
}
```

## 安全闸（缺一不可）

| 闸 | 做法 | 为什么要 |
|---|---|---|
| 包源白名单 | 只认 `winget search` 命中的**精确 package_id**；choco 只认 `--exact` | 防"模糊匹配装错包" |
| 显式确认 | `confirm=true` 才执行；无确认只回"将执行什么" | 装软件改机器状态 |
| 超时与静默 | `--silent --accept-package-agreements --accept-source-agreements`；硬超时 | 防交互挂死 |
| 事后探测 | 装完**再 probe 一次**，版本/路径对不上就 `ok=false` + `installed_after=false` | 根治"谎报成功" |
| 审计 | 每次 install 落审计（package_id/退出码/是否验证通过/耗时） | 可追溯 |
| 权限 | 走既有工具权限与审批（medium 风险）；默认 **disabled**，Owner 显式启用 | 与 tools.disabled 口径一致 |

## 与环境的关系

- 需要 `winget`（Windows 10+）。没有 winget 时 `software_install` 返回
  `{"ok": false, "denied_reason": "winget-not-found"}`，**不回退到"假装安装"**。
- 不新增环境变量读取点（避免 settings 注册表缺口）；如需白名单文件，放
  `config/software_allowlist.json`（数据文件，不是 env）。
