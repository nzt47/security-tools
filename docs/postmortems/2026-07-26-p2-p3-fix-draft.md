## 一、P2: lazy_loader shutdown() 注册到 atexit

### 1.1 问题分析

**现状**（[lazy_loader/__init__.py:41-43](file:///c:/Users/Administrator/agent/agent/lazy_loader/__init__.py#L41-L43)）：

```python
def shutdown(self):
    """关闭线程池"""
    self.executor.shutdown(wait=True)
```

**风险**：
- `shutdown()` 方法存在，但**无 atexit 注册**
- 进程退出时不会自动调用 `shutdown()`，线程池中的未完成任务会丢失
- `ThreadPoolExecutor` 的 daemon 线程会被强终止，正在执行的模块加载可能中断

**风险等级**：LOW（模块加载通常在启动阶段完成，退出时残留任务概率低，但存在数据不一致风险）

### 1.2 不变量识别【三义】

| 三义 | 约束 |
|------|------|
| 不易 | shutdown(wait=True) 必须在进程退出前执行，确保线程池任务完成 |
| 变易 | atexit 钩子须幂等（多次调用不报错），须捕获异常避免影响退出流程 |
| 简易 | 最小侵入：仅新增 atexit.register，不改 shutdown 方法签名 |

### 1.3 修复方案

**修改文件**：[agent/lazy_loader/__init__.py](file:///c:/Users/Administrator/agent/agent/lazy_loader/__init__.py)

**修改点**：

1. **导入 atexit**（L36 区域）：

```python
import atexit
import logging
```

2. **`LazyModuleLoader.__init__` 末尾注册 atexit**（L130 区域）：

```python
def __init__(self, max_workers: int = 4):
    # ... 原有初始化代码 ...
    self.executor = ThreadPoolExecutor(max_workers=max_workers)
    # [TLM-AUDIT-P2] 注册 atexit 钩子，确保进程退出时清理线程池
    # Why: ThreadPoolExecutor 的 daemon 线程在进程退出时会被强终止，
    # 正在执行的模块加载可能中断导致状态不一致
    atexit.register(self._atexit_shutdown)
```

3. **新增 `_atexit_shutdown` 方法**（紧邻 `shutdown` 方法）：

```python
def _atexit_shutdown(self):
    """atexit 钩子：进程退出时安全清理线程池

    [不易] 守数据完整性：确保线程池中的模块加载任务完成
    [变易] 幂等 + 异常隔离：多次调用不报错，异常不影响退出流程
    [简易] 复用现有 shutdown()，仅加 try-except 包裹
    """
    try:
        self.shutdown()
    except Exception as e:
        logger.warning("[LazyLoader] atexit shutdown 失败: %s", e)
```

### 1.5 风险评估

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| atexit 钩子在模块卸载时误触发 | 低 | 低 | `_atexit_shutdown` 幂等 + try-except |

## 二、P3: chaos_injector cleanup_monitor 线程补充 join

### 2.1 问题分析

**现状**（[chaos_injector.py:339-348](file:///c:/Users/Administrator/agent/agent/monitoring/chaos_injector.py#L339-L348)）：

```python
if duration_ms:
    def cleanup_monitor():
        """监控并清理CPU压力进程"""
        set_trace_id(self._chaos_trace_id)
        time.sleep(duration_ms / 1000.0 + 1)
        for p in processes:
            if p.is_alive():
                p.terminate()
        logger.info(...)
    
    threading.Thread(target=cleanup_monitor, daemon=True).start()  # ⚠ 无引用保存，无 join
```

**风险**：
- `cleanup_monitor` 线程未保存引用，无法 join
- 线程内部 `time.sleep(duration_ms/1000 + 1)` 无法被唤醒
- 如果进程在 cleanup_monitor 执行前退出：
  - CPU 压力子进程（multiprocessing.Process）可能成为僵尸进程
  - 系统资源（CPU）持续被占用

**风险等级**：LOW（chaos_injector 是测试工具，生产环境不启用；但僵尸进程风险存在）

### 2.2 不变量识别【三义】

| 三义 | 约束 |
|------|------|
| 不易 | cleanup_monitor 必须完成子进程 terminate，避免僵尸进程 |
| 变易 | cleanup_monitor 可被 stop 唤醒（Event.wait 替代 time.sleep） |
| 简易 | 复用现有 `_memory_pressure_thread` 的 join 模式，新增 `_cleanup_threads` 列表 |

### 2.3 修复方案

**修改文件**：[agent/monitoring/chaos_injector.py](file:///c:/Users/Administrator/agent/agent/monitoring/chaos_injector.py)

**修改点**：

1. **`__init__` 新增 `_cleanup_threads` 列表**（L115 区域）：

```python
def __init__(self, ...):
    # ... 原有初始化 ...
    self._memory_pressure_thread: Optional[threading.Thread] = None
    # [TLM-AUDIT-P3] 追踪 cleanup_monitor 线程，支持 stop 时 join
    self._cleanup_threads: list[threading.Thread] = []
    # [TLM-AUDIT-P3] cleanup 停止信号，支持立即唤醒
    self._cleanup_stop_event = threading.Event()
```

2. **修改 `inject_cpu_pressure` 中的 cleanup_monitor**（L339-348）：

```python
if duration_ms:
    # [TLM-AUDIT-P3] 用 Event 替代 time.sleep，支持 stop 时立即唤醒
    stop_event = self._cleanup_stop_event
    
    def cleanup_monitor():
        """监控并清理CPU压力进程"""
        set_trace_id(self._chaos_trace_id)
        # 用 Event.wait 替代 time.sleep，stop 时立即唤醒
        if stop_event.wait(timeout=duration_ms / 1000.0 + 1):
            # 收到停止信号，提前清理
            logger.info(log_dict({...,'msg': '[Chaos] cleanup_monitor 提前唤醒'}))
        for p in processes:
            if p.is_alive():
                p.terminate()
        logger.info(log_dict({...,'msg': '[Chaos] 所有CPU压力进程已终止'}))
    
    cleanup_thread = threading.Thread(
        target=cleanup_monitor, daemon=True, name="chaos-cleanup"
    )
    cleanup_thread.start()
    # [TLM-AUDIT-P3] 保存引用，stop 时 join
    self._cleanup_threads.append(cleanup_thread)
```

3. **新增 `stop_cleanup_threads` 方法**（紧邻 `clear_all` 方法）：

```python
def stop_cleanup_threads(self, timeout: float = 5.0) -> None:
    """等待所有 cleanup_monitor 线程完成或超时

    [不易] 守资源完整：确保 CPU 压力子进程被 terminate，避免僵尸进程
    [变易] stop_event 唤醒 + join timeout 兜底
    [简易] 复用 _memory_pressure_thread 的 join 模式
    """
    # 唤醒所有阻塞在 wait 的 cleanup_monitor
    self._cleanup_stop_event.set()
    
    for t in self._cleanup_threads:
        if t.is_alive():
            t.join(timeout=timeout)
            if t.is_alive():
                logger.warning(
                    "[Chaos] cleanup_monitor 线程 %s join 超时(%ss)",
                    t.name, timeout
                )
    
    self._cleanup_threads.clear()
    # 重置 stop_event（支持后续注入）
    self._cleanup_stop_event.clear()
```

4. **`clear_all` 末尾调用 `stop_cleanup_threads`**（L598 区域）：

```python
def clear_all(self):
    # ... 原有清理逻辑 ...
    # [TLM-AUDIT-P3] 清理 cleanup_monitor 线程
    self.stop_cleanup_threads()
```

### 2.4 测试计划

| 测试用例 | 验证点 |
|---------|--------|
| `test_cleanup_thread_saved_after_inject` | inject_cpu_pressure 后 `_cleanup_threads` 非空 |
| `test_stop_cleanup_threads_joins_all` | stop_cleanup_threads 后所有线程退出 |
| `test_stop_cleanup_threads_wakes_up_sleep` | stop 能立即唤醒 `time.sleep`（Event.wait） |
| `test_cleanup_terminates_child_processes` | stop 后子进程被 terminate |
| `test_stop_cleanup_threads_idempotent` | 二次调用不报错 |
| `test_clear_all_calls_stop_cleanup` | clear_all 触发 stop_cleanup_threads |

### 2.5 风险评估

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| stop_event 误触发导致提前 terminate | 低 | 中 | stop_event 仅在 stop_cleanup_threads 时 set |
| join 超时阻塞 clear_all | 低 | 低 | timeout=5.0 兜底 |
| _cleanup_threads 列表无限增长 | 中 | 低 | stop_cleanup_threads 后 clear() |
| 并发 inject 导致 stop_event 状态混乱 | 低 | 中 | 每次注入创建独立 stop_event（方案 B） |

### 2.6 方案 B（可选优化）：每次注入独立 stop_event

如果并发注入场景常见，可为每次注入创建独立 Event：

```python
if duration_ms:
    stop_event = threading.Event()  # 每次注入独立
    
    def cleanup_monitor():
        if stop_event.wait(timeout=duration_ms / 1000.0 + 1):
            ...
        ...
    
    cleanup_thread = threading.Thread(target=cleanup_monitor, daemon=True)
    cleanup_thread.start()
    # 保存 (thread, stop_event) 元组
    self._cleanup_threads.append((cleanup_thread, stop_event))
```

**权衡**：方案 B 更安全但更复杂。当前 chaos_injector 是测试工具，单次注入场景多，方案 A（共享 stop_event）已足够。
