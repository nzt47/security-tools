# 任务 T2.4：Profile 配置驱动完善（order / hidden / 回退默认值）

## 目标

让 `profile.json` 成为界面的**唯一组装配置**：插槽条目顺序、显隐全部由 profile 决定；profile 缺失/损坏时优雅回退到代码内默认挂载。阶段 2 收尾。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-2-frontend-slots.md`（§2、§3）。
- 前置：T2.3 已完成（插槽体系 + 面板切换器已生效）。

## 设计契约（必须满足）

1. **回退语义**：
   - `profile.json` 缺失或解析失败 → 使用代码内 `DEFAULT_PROFILE`（在 `slotRegistry.ts` 中定义，与当前 profile.json 内容一致）；
   - 插槽在 profile 中未出现 → 该插槽渲染**全部已挂载条目**（默认 order 100）；
   - 某条目在 profile 中缺失 → 用组件默认 order/hidden；
   - 某条目在 profile 中声明但未挂载 → 忽略（不报错）。
2. **加载时机**：`SlotProvider` 挂载时 `loadProfile()`；新增 `reloadProfile()` 支持运行时重载（供调试/后续动态装载用）。
3. **profile.json 注释与文档**：在 `src/plugins/profile.json` 旁建 `PROFILE.md`，说明每个插槽、每个条目 id 的用途与可选字段（order/hidden），作为「界面组装」文档。
4. **验证**：提供至少 2 个 profile 变体（如 `profile.alt.json`：交换 sidebar 顺序 / 隐藏某面板），`npm run dev` 下切换验证生效。

## 步骤

1. 阅读 T2.1–T2.3 产物，梳理当前 profile 生效路径。
2. 在 `slotRegistry.ts` 实现回退逻辑与 `DEFAULT_PROFILE`、`reloadProfile`。
3. 更新 `SlotProvider`；写 `PROFILE.md`；建 `profile.alt.json` 验证变体。
4. 单测补充：profile 缺失、条目缺失、插槽缺失三种回退场景。

## 验收标准

- [ ] 删除/改名 `profile.json` 后启动，界面仍完整（回退生效，无报错）
- [ ] `profile.alt.json` 生效时顺序/显隐符合预期；切回默认 profile 恢复
- [ ] `npx tsc -b --noEmit` 通过；`npx vitest run` 通过（含回退单测）
- [ ] `PROFILE.md` 完成（每个插槽/条目有说明）
- [ ] 提交信息：`feat(ui): profile-driven slot assembly with fallback defaults`

## 风险与注意事项

- 回退逻辑要**静默**：任何配置异常不得抛错阻断渲染，日志 warn 即可。
- `profile.alt.json` 是验证变体，可保留在仓库（`src/plugins/` 下），供后续插件生态演示。
- 完成后 git 提交；阶段 2 全部任务完成。
