# 任务 T4.1：后端插件目录扫描自动加载 + reload 端点

## 目标

把阶段 1 的显式 import 清单改为**目录扫描自动加载**：新插件丢进 `plugins/` 即生效；新增 `POST /api/plugins/reload` 支持不重启进程刷新清单；单插件损坏不阻断整体。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-4-dynamic-loading.md`（先读，§1）。
- 前置：阶段 1 完成（`plugins/` 含 8 个域插件 + `plugin_api.py`）。

## 设计契约（必须满足）

1. 新建 `plugins/loader.py`：
   - `load_all()`：用 `pkgutil.iter_modules` 扫描 `plugins/` 目录下所有 `.py` 模块，跳过 `_` 开头与 `plugin_api` / `services` / `loader` 本身；逐个 `importlib.import_module` 触发 `register_plugin`；单个失败记日志（`print` 或 logging）不阻断；返回成功数。
   - `refresh_manifest()`：清空 `_REGISTRY` → `load_all()` → 返回 `manifest()`。
2. 装配器改造（`app_server.py`）：
   - 启动时调用 `loader.load_all()` 替代（或合并）显式 import 清单；
   - 新增 `POST /api/plugins/reload`（需 `require_token`）：返回新 manifest；失败时返回 500 + 错误摘要，且**保留旧注册表**（先清空会导致失败后无插件——先加载到临时注册表，成功再替换；实现时注意）。
3. **错误隔离验证**：写一个故意损坏的临时插件 `plugins/_broken_tmp.py`（含语法错误），确认启动不受影响、`/api/plugins` 不含它；验证后删除。
4. 保留 `plugins/__init__.py` 显式清单作为「内置插件」可选路径（可保留不动，loader 扫描时跳过重复注册——`register_plugin` 幂等已保证）。

## 步骤

1. 阅读 `PLAN-4` §1 与现有 `plugins/__init__.py`、`plugin_api.py`。
2. 实现 `loader.py`（注意临时注册表替换策略防失败清空）。
3. 改装配器 + 新增 reload 端点。
4. 演示：新增 `plugins/demo_plugin.py`（仿 example，含 `name="demo"` 与一条路由），启动后出现在 `/api/plugins`；`POST /api/plugins/reload` 后新插件可发现。

## 验收标准

- [ ] 新增 `demo_plugin.py` 无需改任何代码即被 `/api/plugins` 发现
- [ ] `POST /api/plugins/reload` 不重启进程刷新清单
- [ ] 损坏插件不影响启动与其余插件（验证后删除损坏文件与 demo 插件）
- [ ] `python -m pytest tests/ -x -q`（或相关子集）通过
- [ ] 提交信息：`feat(plugins): directory scanning + reload endpoint`

## 风险与注意事项

- **注册表原子性**：reload 失败必须保留旧清单（先构建新列表，成功后再替换 `_REGISTRY`）。
- 扫描只加载新模块，不负责卸载已删除插件的路由（Flask 已注册 blueprint 不可注销）——文档中说明：删除插件需重启生效。
- 完成后 git 提交。
