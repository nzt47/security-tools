# 任务 T3.1：后端插件 Schema 协议落地（Plugin.schema + 示例）

## 目标

让阶段 1 预留的 `Plugin.schema` 字段真正启用：协议校验 + 给 2–3 个真实插件补上 Schema，并确认 `/api/plugins` 输出含 schema。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-3-schema-ui.md`（先读，§2 协议）。
- 前置：阶段 1 完成（`plugins/plugin_api.py` 存在，`schema` 字段已预留）。
- 目标：后端成为「自解释数据源」——插件声明即文档。

## 设计契约（必须满足）

1. **协议校验**（`plugins/plugin_api.py`）：`register_plugin` 时校验 `schema`：
   - 必须为 `dict` 或 `None`；
   - 若为 dict，必须含 `type: "object"`（顶层）；
   - 非法时 `raise ValueError(f"plugin {name}: invalid schema")`（开发期早失败）。
2. **Schema 编写**：为以下插件补 `schema`（示例见 PLAN-3 §2）：
   - `status`（推荐含：刷新频率、传感器开关等）——至少 3 个属性，覆盖 string/enum/integer/boolean 至少 3 种类型；
   - `safety`（关键词管理类：字符串数组）；
   - `skills`（可选，若时间紧可只做前两个）。
3. **输出核对**：`GET /api/plugins` 每个插件含 `schema` 字段（无 schema 的插件输出 `schema: {}` 或 null，统一约定为空 dict）。
4. 不修改任何路由行为；不引入新依赖。

## 步骤

1. 阅读 `PLAN-3` 与 `plugins/plugin_api.py`、`plugins/status.py`、`plugins/safety.py`。
2. 改 `plugin_api.py` 校验；补 `status.py` / `safety.py` 的 `Plugin(schema={...})`。
3. 验证。

## 验收标准

- [ ] `register_plugin` 非法 schema 抛 ValueError（写一个 pytest 单测验证，放 `tests/` 下，命名 `test_plugin_schema.py`）
- [ ] `GET /api/plugins` 中 status/safety 插件含合法 schema；其余插件 schema 为空 dict
- [ ] `python -m pytest tests/ -x -q`（或相关子集）通过
- [ ] 提交信息：`feat(plugins): schema protocol for self-describing plugins`

## 风险与注意事项

- Schema 属性名应尽量与插件真实配置项对齐（供阶段 3 的 SchemaRenderer 提交使用），先对齐 `status` 的 `_get_sensor_categories` 等真实配置维度。
- 完成后 git 提交。
