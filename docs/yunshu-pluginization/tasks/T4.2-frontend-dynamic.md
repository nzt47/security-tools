# 任务 T4.2：前端运行时发现新插件 + 刷新（阶段 4 完成）

## 目标

前端插件中心支持「运行时发现」：刷新按钮调 `POST /api/plugins/reload` 后重新拉取清单，新插件立即可见；进阶能力（可选）：manifest 声明 `clientSlot` 的插件可被动态 `import()` 加载并挂入插槽。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-4-dynamic-loading.md`（先读，§2）。
- 前置：T4.1（后端扫描 + reload）、T3.3（PluginPanel）、T2.4（插槽体系）。

## 设计契约（必须满足）

1. 新建 `yunshu-ui/src/plugins/pluginDiscovery.ts`：

```ts
export interface PluginInfo {
  name: string;
  version: string;
  description: string;
  schema: Record<string, any> | null;
  routes: string[];
  submitUrl?: string;
  clientSlot?: { slotId: string; module: string } | null;
}
export async function fetchPlugins(): Promise<PluginInfo[]> { ... }   // GET /api/plugins
export async function reloadPlugins(): Promise<PluginInfo[]> { ... }  // POST /api/plugins/reload 后重新拉取
```

2. 改造 `PluginPanel`（T3.3 产物）：
   - 顶部「刷新」按钮 → `reloadPlugins()`，成功后列表更新 + Toast；
   - 刷新失败：Toast 错误 + 保留旧列表；
   - 加载态（spinner / 禁用按钮）。
3. **进阶（可选，作为加分项）**：manifest 声明 `clientSlot` 的插件：
   - 列表项显示「加载 UI」按钮；
   - 点击后 `import(/* @vite-ignore */ info.clientSlot.module)`，调用模块导出的 `register(registry)`（约定导出 `register(slotRegistry)` 或默认导出组件直接 `mountToSlot`）；
   - 动态加载失败：Toast 错误，不影响其他功能。
4. 演示：后端放一个带 `clientSlot` 的示例插件（`demo_plugin.py` 声明 `clientSlot: { slotId: "panels", module: "/plugins/demo-ui.js" }`，前端 `public/plugins/demo-ui.js` 提供 `register`），完成「新增插件 → 刷新 → 加载 UI」全链路（若动态 import 复杂，可只做到「刷新后 Schema 面板可见」并说明）。

## 步骤

1. 阅读 `PLAN-4` §2；确认 T4.1、T3.3 产物。
2. 实现 `pluginDiscovery.ts`；改造 `PluginPanel`。
3. （可选进阶）动态 import 链路 + 示例插件。
4. 单测：`fetchPlugins`/`reloadPlugins`（mock fetch）、刷新失败保留旧列表。

## 验收标准

- [ ] `npx tsc -b --noEmit` 通过；`npx vitest run` 通过
- [ ] 启动前后端：后端新增插件 → 前端点「刷新」→ 新插件出现在列表（Schema 面板可用）
- [ ] 刷新失败不崩溃、保留旧列表
- [ ] （进阶）clientSlot 插件可被动态加载并挂入插槽
- [ ] 提交信息：`feat(ui): runtime plugin discovery and reload`

## 风险与注意事项

- 动态 `import()` 的路径受 Vite `public/` 或后端静态目录约束，先做 Schema 面板刷新（必做），动态 JS 装载（选做）失败不阻塞本任务验收。
- 完成后 git 提交；阶段 4 全部任务完成 → 四阶段改造路线全部交付。
