# 任务 T3.2：前端通用 SchemaRenderer（字段组件 + 单测）

## 目标

实现前端通用 Schema 渲染器 `SchemaRenderer`：给定 JSON Schema 子集 + 当前值，自动渲染完整表单（含嵌套、校验、降级），**不绑定任何具体业务**。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-3-schema-ui.md`（先读，§3）。
- 前置：T2.1（插槽体系，本任务不依赖但可挂演示）。
- 现状：各页面手写表单（如 PromptLab 21KB、SkillCreator 15KB）。

## 设计契约（必须满足）

1. 新建 `yunshu-ui/src/plugins/schema/` 目录：
   - `types.ts` — Schema 子集类型（`SchemaField`：type/title/description/default/enum/minimum/maximum/items/format）
   - `SchemaRenderer.tsx` — 主组件，签名：

```tsx
export interface SchemaRendererProps {
  schema: Record<string, any>;
  value: Record<string, any>;
  onChange: (next: Record<string, any>) => void;
  onSubmit?: (values: Record<string, any>) => void; // 可选
}
```

   - `fields/` — 独立受控字段组件，每个可单独 import（第三方插件复用）：
     - `SelectField.tsx`（string+enum）
     - `InputField.tsx`（string）
     - `TextareaField.tsx`（string+format:textarea）
     - `NumberField.tsx`（integer/number，min/max）
     - `SwitchField.tsx`（boolean）
     - `TagsField.tsx`（array of string）
     - `ObjectGroup.tsx`（嵌套 object 折叠分组）
     - `JsonFallbackField.tsx`（未知类型 → textarea + JSON 解析校验，错误红字提示）
   - `index.ts` — 汇总导出。
2. **行为要求**：
   - 渲染时用 `schema.default` 填充缺失字段；
   - `required` 字段标星号；
   - 未知 `type` / 缺失 `properties` → 整个 schema 用 `JsonFallbackField` 降级；
   - 嵌套 object 折叠展开（默认展开第一层）；
   - 纯受控：不直接发请求。
3. **样式**：复用现有 Tailwind 类与主题变量（参考 `styles/theme.css`），不引入新 UI 库。

## 步骤

1. 阅读 `PLAN-3` §3、`styles/theme.css` 与现有表单（`components/SkillsMgmt/SkillCreator.tsx`）的样式习惯。
2. 实现全部字段组件与 `SchemaRenderer`。
3. 单测（vitest + testing-library）覆盖：每种类型字段、default 填充、required 标记、嵌套 object、未知类型降级、onChange 回调正确性。

## 验收标准

- [ ] `npx tsc -b --noEmit` 通过；`npx vitest run src/plugins/schema` 全部通过
- [ ] 用 PLAN-3 §2 的「性格微调」schema 在 Storybook/临时页面渲染出完整表单（临时页面验证后删除）
- [ ] 未知类型 schema 不崩溃，降级 textarea 可编辑
- [ ] 提交信息：`feat(ui): generic SchemaRenderer for schema-driven forms`

## 风险与注意事项

- 字段组件必须**受控**（value/onChange），不要内部状态导致提交丢失。
- 数值字段的 min/max 校验在提交层提示，不阻断输入。
- 完成后 git 提交。
