# 任务 T1.2：拆分 chat 插件（chat / sessions / history / voice / news / clear）

## 目标

把 `app_server.py` 中的对话域路由迁移到 `plugins/chat.py`（作为 Flask Blueprint 插件）。路由路径与行为 100% 不变。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-1-backend-pluginization.md`（先读，重点 §2 插件模板、§4 共享依赖策略）。
- 前置：T1.1 已完成（`plugins/plugin_api.py` 存在，装配器已注册插件 blueprint）。
- 共享依赖约定：插件视图函数内 `from app_server import xxx` 延迟 import，插件模块**顶层**不得 import `app_server`。

## 步骤

1. 创建 `plugins/chat.py`，按 `PLAN-1` §2 的插件模板：`bp = Blueprint("chat", __name__)`，**不设 url_prefix**，路由路径保持 `/api/...` 原样。
2. 把上述路由函数体整体搬入（含它们私有依赖的 helper；若 helper 被多个域共用则**留在 app_server.py**，函数内 import）。
3. 共享依赖（`require_token`、`log_request`、`_save_conversation_record`、会话存储等）在视图函数内部 `from app_server import ...` 延迟 import。
4. 声明 `PLUGIN = register_plugin(Plugin(name="chat", version="1.0.0", description="对话、会话、历史记录", blueprint=bp, routes=[...]))`，routes 列出全部迁移路径。
5. 在 `plugins/__init__.py` 追加 `from . import chat`。
6. 删除 `app_server.py` 中已迁移的路由与不再被引用的私有 helper（**确认无其他路由引用后再删**；被共享的留在原文件）。

## 验收标准

- [ ] `python -m py_compile app_server.py plugins/chat.py` 通过；`python -c "import app_server"` 无循环导入
- [ ] 启动服务后冒烟：`POST /api/chat`（简单输入）、`GET /api/sessions`、`GET /api/history`、`GET /api/voice/status` 响应与迁移前一致（可先用 git stash 对比迁移前行为，或对照测试快照）
- [ ] `GET /api/plugins` 中 chat 插件的 routes 与实际一致
- [ ] 迁移前后 `@app.route` 与 `@bp.route` 路径集合一致（页面/静态/测试路由除外）
- [ ] `python -m pytest tests/ -x -q`（或 API 相关子集）通过

## 风险与注意事项

- 若某路由函数依赖的模块级全局在 `app_server.py` 中是**延迟初始化的单例**，函数内 import 后直接使用即可（与现有 SingletonManager 风格一致）。
- `/api/chat/stream` 若涉及 SSE/流式响应，搬移时保持 response 类型与 header 不变。
- 不要顺手"优化"或"重构"搬移的代码——**行为等价优先**。
- 完成后 git 提交：`refactor(plugins): extract chat domain into plugins/chat.py`。
