# 任务 T1.3：拆分 memory 插件（context / memory / vector / windows）

## 目标

把 `app_server.py` 中的记忆/上下文域路由迁移到 `plugins/memory.py`。路由路径与行为 100% 不变。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-1-backend-pluginization.md`（重点 §2、§4）。
- 前置：T1.1 已完成。与 T1.2/T1.4–T1.9 相互独立，可并行。
- 共享依赖约定：函数内延迟 import；模块顶层不得 import `app_server`。

## 待迁移路由（以实际代码为准）

| 路径 | 方法 | 说明 |
|---|---|---|
| `/api/context/status` | GET | 上下文状态 |
| `/api/context/config` | POST | 上下文配置 |
| `/api/context/compress` | POST | 上下文压缩 |
| `/api/memory/overview` | GET | 记忆总览 |
| `/api/memory/manual` | POST | 手动记忆 |
| `/api/memory/compress` | POST | 记忆压缩 |
| `/api/memory/<int:index>` | DELETE | 删除记忆 |
| `/api/memory/clear-summary` | POST | 清空摘要 |
| `/api/memory/summary` | PUT | 更新摘要 |
| `/api/vector/search` | POST | 向量检索 |
| `/api/memory/windows/events` | GET | 窗口事件 |
| `/api/memory/windows/stats` | GET | 窗口统计 |
| `/api/memory/windows/current` | GET | 当前窗口 |
| `/api/memory/windows/config` | GET/POST | 窗口配置 |
| `/api/memory/windows/clear` | POST | 清空窗口 |

## 步骤

1. 创建 `plugins/memory.py`，模板同 T1.2（`bp = Blueprint("memory", __name__)`，不设 url_prefix）。
2. 迁移上述路由函数体；`/api/memory/<int:index>` 的 converter 写法保持 `@bp.route("/api/memory/<int:index>", methods=["DELETE"])`。
3. 共享依赖（记忆单例、上下文管理器、向量库等）函数内 `from app_server import ...` 延迟 import。
4. 声明 `PLUGIN = register_plugin(Plugin(name="memory", version="1.0.0", description="记忆与上下文管理", blueprint=bp, routes=[...]))`。
5. `plugins/__init__.py` 追加 `from . import memory`。
6. 删除 `app_server.py` 中已迁移的路由与不再被引用的私有 helper。

## 验收标准

- [ ] `py_compile` 通过；`import app_server` 无循环导入
- [ ] 冒烟：`GET /api/context/status`、`GET /api/memory/overview`、`GET /api/memory/windows/stats` 响应与迁移前一致
- [ ] `GET /api/plugins` 含 memory 插件且 routes 正确
- [ ] 迁移前后路径集合一致；`python -m pytest tests/ -x -q`（或相关子集）通过

## 风险与注意事项

- memory 域路由可能涉及重 IO（向量检索、文件读写），冒烟时注意耗时，不要误判为卡死。
- 若 `_get_token_counter` 等计数 helper 同时被 chat 域使用，**留在 app_server.py**，两插件函数内 import。
- 完成后 git 提交：`refactor(plugins): extract memory domain into plugins/memory.py`。
