# 任务 T2.2：App 外壳插槽化（topbar / sidebar / main）

## 目标

把 `App.tsx` 的外壳布局改为插槽渲染：顶栏（StatusIndicator 等）、侧栏（Mascot / HistoryPanel / SessionsDropdown）、主区（ChatWindow / ChatInput）全部挂进对应插槽。**视觉与交互行为不变**。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-2-frontend-slots.md`（§3、§4）。
- 前置：T2.1 已完成（`src/plugins/` 存在）。
- 现状：`yunshu-ui/src/App.tsx`（381 行）手写布局；聊天状态（messages/sessions/mood/toasts）都在 App 内。

## 设计契约（必须满足）

1. 定义插槽（在 `App.tsx` 或 `src/plugins/slots.ts` 集中声明）：
   - `topbar`：StatusIndicator（+ 模式切换如存在）
   - `sidebar`：Mascot、HistoryPanel（如当前在侧栏渲染）、SessionsDropdown
   - `main`：ChatWindow、ChatInput
2. 改造 `App.tsx`：
   - 布局区替换为 `<SlotHost slotId="topbar"/>` `<SlotHost slotId="sidebar"/>` `<SlotHost slotId="main"/>`
   - **状态提升策略**：聊天相关状态与逻辑（messages、send、reset、sessions 加载等）保留在 App，通过 props 传给插槽组件；或迁移到已有 `store/useChatStore.ts`（如可行）。二选一，但必须保持现有交互（流式回复、会话切换、Toast）不变。
   - `profile.json` 填充真实条目（见 §3 参考）。
3. 挂载代码：在 `App.tsx` 顶层（或 `SlotProvider` 内）调用 `mountToSlot(...)` 挂入真实组件。
4. 保持 `main.tsx` 的 React 根渲染不变（`SlotProvider` 包在 `App` 外或内均可，二选一，说明理由）。

## profile.json 参考

```json
{
  "slots": {
    "topbar":  [{ "id": "status", "order": 10 }],
    "sidebar": [{ "id": "mascot", "order": 10 }, { "id": "history", "order": 20 }],
    "main":    [{ "id": "chat", "order": 10 }],
    "panels":  []
  }
}
```

## 步骤

1. 通读 `App.tsx`（381 行）与 `components/Chat/*`、`components/Mascot`、`components/Status`，画出当前布局与数据流。
2. 创建 `src/plugins/slots.ts`（插槽 id 常量 + 挂载函数），改造 `App.tsx`。
3. 逐个核对交互：流式回复、会话切换、消息加载、Toast、Mascot 情绪联动。
4. 运行测试与构建。

## 验收标准

- [ ] `cd yunshu-ui && npx tsc -b --noEmit` 通过；`npx vitest run` 既有用例通过（若 App 相关测试存在需更新，注明）
- [ ] `npm run dev` 冒烟：聊天、流式回复、会话切换、Toast、Mascot 行为与改造前一致
- [ ] 修改 `profile.json`（如调整 order、hidden）能实际影响渲染顺序/显隐
- [ ] `App.tsx` 行数明显下降（目标 < 250 行），布局代码被插槽替代
- [ ] 提交信息：`refactor(ui): render app shell via slot hosts`

## 风险与注意事项

- 聊天状态迁移到 zustand 是**可选**项；若迁移风险大，保持状态在 App、props 下传即可，不强制。
- Mascot 情绪（mood）由聊天流驱动，插槽化后要保证回调链路不断。
- 完成后 git 提交。
