# 任务 T3.3：插件面板接入 /api/plugins + 演示验证（阶段 3 完成）

## 目标

实现「插件中心」面板：从 `/api/plugins` 拉取清单，列表展示插件（名称/版本/描述），点击后用 `SchemaRenderer` 渲染其配置表单并提交。用至少一个真实插件验证「Schema 声明 → UI 自动生成」闭环。

## 背景

- 方案：`docs/yunshu-pluginization/PLAN-3-schema-ui.md`（§4、§5）。
- 前置：T3.1（后端 schema 协议）、T3.2（SchemaRenderer）。
- 现有 API 客户端：`yunshu-ui/src/lib/apiClient.ts`（可复用或直接用 fetch）。

## 设计契约（必须满足）

1. 新建 `yunshu-ui/src/plugins/PluginPanel.tsx`：
   - 挂载时 `GET /api/plugins`；
   - 左侧插件列表（name + description，自解释）；右侧详情 + `SchemaRenderer`；
   - schema 为空 → 显示「该插件暂无可配置界面」+ 其 routes 列表；
   - 提交：插件声明 `submitUrl`（后端 Plugin 增加可选字段，默认由前端映射表兜底）→ POST 到对应端点；成功/失败 Toast。
2. **后端小改动**：`plugins/plugin_api.py` 的 `Plugin` 增加可选字段 `submit_url: str = ""`（写入 manifest）；给 `status` 插件的 schema 声明 `submit_url`（指向其真实配置端点，若无则指向 `/api/config` 或标空并提示）。
3. 挂载：`PluginPanel` 挂入 `panels` 插槽（`src/plugins/panels.ts` 追加），profile.json `panels` 增加 `plugin-center` 条目（`hidden: true`）。
4. **演示验证（关键验收）**：
   - 选 `status` 插件（T3.1 已写 schema），在插件中心**不写任何手写表单**，仅靠 SchemaRenderer 完成「查看 → 修改参数 → 提交 → 后端生效」闭环；
   - 对比：改造前该配置如需手写表单（如 PromptLab 相关区），确认体验等价或更优。

## 步骤

1. 阅读 `PLAN-3` §4；确认 T3.1/T3.2 产物。
2. 后端加 `submit_url` 字段 + `status` 插件声明；前端实现 `PluginPanel` + 挂载。
3. 演示验证 + 单测（PluginPanel 列表渲染、空 schema 降级、提交调用）。

## 验收标准

- [ ] `npx tsc -b --noEmit` 通过；`npx vitest run` 通过（含 PluginPanel 测试）
- [ ] 启动后端 + `npm run dev`：插件中心列出全部 8 个插件，含 schema 的插件渲染出表单
- [ ] status 插件闭环验证成功（改参 → 提交 → 生效）
- [ ] `python -m pytest tests/ -x -q`（或相关子集）通过（submit_url 改动无回归）
- [ ] 提交信息：`feat(ui): plugin center with schema-driven config forms`

## 风险与注意事项

- 提交端点不确定时，`submit_url` 留空并在 UI 提示「该插件暂不支持在线修改」，不要硬凑端点。
- PluginPanel 挂在 panels 插槽，入口按钮由 PanelSwitcher 自动出现（title 设为「插件中心」）。
- 完成后 git 提交；阶段 3 全部任务完成。
