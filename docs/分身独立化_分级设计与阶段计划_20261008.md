# 分身独立化 —— 分级设计与阶段计划（2026-10-08）

> 一句话：**"每个分身独立角色 / 独立系统提示词 / 独立 LLM / 独立记忆 + 可带走独立运行 + 能通信"
> 这件事在本仓不是没设计过，而是设计（P0–P6）只落地了一半** —— 字段在、消费者不在。
> 本文把"现状 vs 设计"逐条对齐，并给出**分级 + 显式开启**的落地口径与阶段顺序。

相关：`docs/superpowers/design/P2_分身容器与工具装配.md`（分身容器/全选配/协同）、
`P3_记忆抽象与提供商适配.md`（记忆抽象层）、`docs/分身装配单.md`（装配单唯一权威）、
`docs/主线装配指南.md`（主线档案）。

## 1. 现状 vs 设计（逐条，带证据）

| 设计项（P2/P3 原文） | 现状 | 证据 | 缺口 |
|---|---|---|---|
| `P2 §2.2.1` 每分身**异构模型** | **本轮已接线**（2026-10-08） | 新增 `agent/subagent/llm_factory.py::resolve_subagent_llm()`；唯一构造口 `memory/llm_service.py::LLMService.with_model()`；温度由 `TemperaturePinnedLLM` 在**调用面**钉住（只碰 temperature）；路由 `agent/server_routes/routes_subagent.py` 具名委派 + `/api/subagent/list` 的 `llm` 段 | `llm_provider` **刻意未加**：跨 provider 需要 per-分身 凭据（`credentials.py`），属 §4 P5；加了字段却没有消费者就是又一处"字段在、没人读" |
| `P2 §2.2.2` + `P3` 每分身**独立记忆** | 地基很厚、**未接线** | `agent/memory/router.py`（5 类任务路由 + L1/L2/L3 分层）、`agent/memory/adapters/holographic_adapter.py` 与 `mem0_adapter.py` 已落地、`agent/memory/tenancy.py` 有 tenant/workspace/subject 隔离矩阵与写入决策 | `SubagentConfig.memory_provider` **全仓无消费方**；且 `agent/security/actor_matrix.py` 对 `sub_agent` 的 `view.memory` / `memory.write` **恒 ❌**，`agent/subagent/toolset.py` 把记忆工具列入硬禁 |
| `P2 §2.2.3` 每分身**工具/组件选配** | 同名问题 | `SubagentConfig.tool_sources` 只出现在状态 dict 与热更差异日志里；真正的装配权威是**主线档案 + `SubAgentToolset`**（`agent/subagent/assembly.py`） | "分身带模块 / 带插件"没有入口：`Plugin.client_slot` / `Plugin.schema`（扩展中心）与分身装配之间没有接线 |
| **独立角色 / 独立系统提示词** | 契约里**没有**字段，且有一条硬不变量 | 创建契约（`routes_subagent.py` create）无 role / prompt 字段；`agent/subagent/executor.py::DELEGATE_SYSTEM_PROMPT` 是云枢自有固定文本，§5.7 机制 1/2 禁止外来文本进 system prompt；注入点仅 `LlmChannelExecutor(system_prompt=)` 构造参数 | 角色必须做成**受控角色模板 + 提示词角色层新角色**（有来源、可审计），见 §3 分级 |
| `P2 §2.4` **多分身协同** | 只有"并行一次性委派 + 结果回父体" | `agent/tools/fan_out_tools.py`（并行、逐任务信封）、`SubagentLifecycleManager.delegate_many`、`POST /api/subagent/delegate` | 设计里的 `SendMessageTool` / `TaskCreate·Update` **任务看板**未落地；**无**分身间直连、无黑板 |
| `P2 §2.3` **独立运行 / 复制** | 有运输层、无打包、无反向通道 | 外部 CLI 通道 `<cli> -p task_file.json --output-format json --max-turns N` + JSONL 四级降级（`agent/subagent/channel.py`）；结果回投 `callback_dispatcher`（`agent/subagent/executor.py`，默认 `ui://workbench/sync` 不外呼）；临时凭据 TTL（`agent/subagent/credentials.py`） | 无**分身包**格式、无导出/导入端点、无对端发现与心跳、无离线依赖打包；`pages/hub/workshop/replicate.tsx` 至今是**纯说明页**（零 API 调用） |
| 可观测 / 沙箱 / RBAC | **已落地**（本仓强项） | Trace（`trace_route` / `TraceContext`）、租户隔离、工具权限矩阵、成本记账、回收三件套 | —— |

**一句话结论**：本仓的分身是"**受治理的并行一次性委派**"（生命周期/权限/隔离/成本/Trace 齐全），
但"独立角色、独立记忆、可带走、能协同"四项此前都是**声明字段或完全缺失**；本轮补上了"独立 LLM"。

## 2. 三条不可协商的边界（先定边界，再谈功能）

1. **§5.7 机制 1/2：外来文本永不进 system prompt。** 分身 system prompt 是云枢自有固定文本。
   ⇒ "独立系统提示词"**只能**做成**云枢自有的角色模板**（人可审、有来源标注），经提示词角色层
   （`agent/prompt_manager/roles.py`）合成；自由文本一律进 ②约束 / user 槽位。
2. **§5.7 机制 3：子代理不含记忆读写。** 现状是硬禁（`actor_matrix` ❌ + `toolset` 硬禁）。
   ⇒ 默认档**保持硬禁**；要放开必须走 §3 的 `scoped` 档（显式开启 + 配额 + 审计 + 熔断），
   并同步改 `actor_matrix` / `toolset` / 装配单三处**同一份判定**（不许只改一处）。
3. **部署级权威不可被分身覆盖：provider / api_key / base_url 恒取部署配置。**
   本轮 `llm_factory` 已按此实现（分身只能选同 provider 下的**模型名**）。
   ⇒ 跨 provider / 自带密钥属于"凭据"问题，必须走 `credentials.py` 的 TTL 凭据 + 审计，不得让
   分身配置直接携带明文密钥。

## 3. 分级口径（"不同场境都做"的正确做法：分级 + 显式开启 + 审计）

沿用本仓既有先例：主线档案的 `allow_govern`（治理平面 = 审批边界，**必须显式开启**，
见 `agent/lines/models.py`）。三处分级一律遵守同一形状：
**默认最小权限 → 高等级需显式开关 → 开关状态与理由进审计与 UI 徽章**。

| 面 | 档位 | 语义 | 默认 | 开启条件 |
|---|---|---|---|---|
| 提示词 | `template` | 只用云枢自有角色模板（受控词表 + 来源标注） | ✅ | —— |
| | `template+text` | 模板 + 自由文本，但自由文本**只进 ②约束 / user 槽位** | | 每分身显式开启 |
| | `full-system` | 自由文本进 system prompt | | 显式开启 + 审计留痕 + UI 红档徽章（**会打破机制 1/2**，需人工确认） |
| 记忆 | `none` | 现状：不含记忆读写（§5.7 机制 3） | ✅ | —— |
| | `brokered` | **母体代管**：母体按 tenancy 注入"只读、限定域"上下文，结果由母体回写；分身侧仍无记忆工具 | | 每分身显式开启 + 域声明（tenant/workspace/subject） |
| | `scoped` | 分身自带私人记忆域（`memory_provider` 真正生效，放开硬禁） | | 显式开启 + 配额（条数/字节）+ 熔断 + 审计；三处判定同改 |
| 执行后端 | `inproc` | 同进程容器（现状） | ✅ | —— |
| | `subprocess` | 外部 agent CLI（`CP_SUBAGENT_AGENT_CLI`，已在 `channel.py` 成体系） | | 配置 CLI 即可 |
| | `container` / `bundle` | 容器镜像 / 可带走独立包 | | 见 §4 P5 |

**共同要求**（三条，缺一不可）：
① 开关进 `SubagentConfig` 且**有消费者**（拒绝"加了字段没人读"）；
② 生效情况**随响应与列表回显**（本轮 `llm.source` 就是这个形状的样板：`explicit` / `inherit` / `fallback-after-error`）；
③ 每个档位有**可证伪守卫**（回退实现 ⇒ 立刻红），并在 4 处之一登记（`docs/分身装配单.md` §9 表）。

## 4. 阶段计划（按依赖顺序，每阶一个 PR，CI 全绿 squash）

### P1（本轮已交付）主线档案 + 四面并入装配车间；`model_id` 真正生效
- `pages/hub/workshop/agents.tsx` 三视图；`features/line-assembly` 去 manifest 防双入口。
- `agent/subagent/llm_factory.py` + `LLMService.with_model()` + 列表 `llm` 段 + UI 来源徽章。

### P2 角色（受控模板）
- `agent/prompt_manager/roles.py`：新增 `delegate_role`（或复用 `line`）角色 + 硬/可裁标注。
- 新模块 `agent/subagent/role_templates.py`：**受控模板词表**（云枢自有文本，进仓可审）+
  `compose_role_fragment(template_id, extra_text)`，只产 `PromptFragment`，不直接拼 system prompt。
- `SubagentConfig` 加 `role_template`（`template` 档的唯一入口）+ `role_text`（`template+text` 档，
  只进 ②约束，由 `DelegationContext.constraints` 承载）。
- 守卫：①模板词表里没有自由文本直通 system prompt 的路径；②`full-system` 未显式开启时
  `role_text` 绝不出现在 system prompt（对 `executor.execute` 的 system_prompt 做断言）。

### P3 记忆（先 `brokered`，再视需要 `scoped`）
- `brokered`：`SubagentConfig.memory_scope`（tenant/workspace/subject）+ 母体侧装配
  "只读上下文"并注入 ③已有成果 / ②约束；**分身侧不加记忆工具**（保持机制 3）。
- `scoped`（需显式开启）：把 `memory_provider` 接到 `agent/memory/router.py`（按 provider 取 adapter）
  + `tenancy.py` 的域；同时改 `actor_matrix` / `toolset` / `assembly` 三处判定（同一份口径）。
- 守卫：①默认档下分身 `tools` 里仍无记忆工具；②`scoped` 未开启时提供 provider 不改变任何行为；
  ③域越界写入被拒（复用 tenancy 既有 `scope_workspace_mismatch` 路径）。

### P4 协同（母体为中枢，先不做分身间直连）
- 共享**任务看板**：新表/文件 + 端点（`TaskCreate/Update` 语义），母体汇总；fan_out 逐任务写板。
- 结果聚合与二次派发：`fan_out` 结果进板 + 可指定"校验/修正"第二轮（复用同一 `DelegationContext`）。
- 守卫：①板上的每条都能追到 `delegation_id` 与 Trace；②分身**不直接**写板（只能经母体回报），
  防止"分身之间互相改状态"这类不可审计路径。

### P5 独立 bundle 与通信（A → B/C 可切换）
- **bundle 契约（三件事）**：①身份与装配（id / 角色模板 / 主线 / 工具子集 / 记忆档）；
  ②密钥**只存引用不存明文**（复用 `credentials.py`）；③幂等启动入口（`<cli> -p task.json ...` 复用既有契约）。
- 后端：`GET /api/subagent/<name>/bundle`（导出，落盘前过密钥闸）+ `POST /api/subagent/import`。
- 执行后端适配器：`inproc`（现状）/ `subprocess`（`channel.py` 已有）/ `container` / `bundle` —— 同一个
  bundle + 同一份 task_file 协议，**换后端不改协议**（这就是"先 A 以后能改 B/C"的技术保证）。
- 反向通道：把 `callback_dispatcher` 从"只写审计"接成可选 HTTP 投递 + `require_token` 鉴权入站路由；
  对端发现/心跳先做**静态配置**（不做服务发现），离线回退明确登记为未做。
- 守卫：①导出的 bundle 里**不含**任何密钥形态（对整包做 `sk-` / 已知键名扫描）；
  ②导入后 `resolve_subagent_assembly` 与 `resolve_subagent_llm` 的结论与母体一致（同源对拍）；
  ③一个真进程来回一条 JSON Lines 消息（含鉴权、失败显式报错）。

## 5. 明确不做（本轮及近期的边界，避免"以为做了"）

- 不做跨机**服务发现 / 集群 / 自动扩缩**；不做记忆**双向同步**（P5 只做单向注入与结果回写）。
- 不做模型目录（**硬编码模型名被 P0 自检明令禁止**）：可选模型只列"有出处"的名字（部署默认 + 已声明）。
- 不做"分身自带明文密钥"；不做不审计的高等级档位（`full-system` / `scoped` 必须留痕）。
- `pages/hub/workshop/replicate.tsx` 在 P5 之前保持"说明页"身份，**不假装**已实现复制。
