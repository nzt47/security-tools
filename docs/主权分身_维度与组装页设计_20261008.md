# 一人独立的主权 Agent：维度模型与「组装台」页面设计（2026-10-08）

> 一句话：**主权 ≠ 功能多**。主权 = 这个 Agent 的每一个"命脉"都由**你一个人**拥有——
> 看得见、改得动、换得了、带得走、断网也能跑。
>
> 这不是新主张：本仓起源设计就是 [主权AI多Agent系统](superpowers/design/原：主权AI多Agent系统 .txt)，
> 其 [架构合规性终极审核](superpowers/design/11_架构合规性终极审核.md) 已把"本地可用 / 工作流优先 /
> 零硬编码 / 可追溯 / 沙箱护栏 / 认知闭环"写成交付红线。本文做两件事：
> **① 把红线拆成可勾选的"主权维度"并与现状逐面对齐；② 设计一个把这些维度真正"装出来"的页面**
> （改造现有「装配车间」，不新建入口）。

---

## 0. 起源宣言（本仓自己的主权七条）

来自 `docs/superpowers/design/` 的各阶段设计与 §11 审核清单，逐条是主权判据：

| # | 起源要求 | 主权含义 |
|---|---|---|
| 1 | 工作流优先，LLM 仅兜底 | 确定性归你，不确定性才交给模型——模型的"自由裁量"是**可选项**而非默认 |
| 2 | 本地可用性与端到端闭环 | 断网断云仍能跑完整链路（本地推理 + 本地记忆 + 原生工具） |
| 3 | 极致可观测与可追溯 | 每一步都能复算：Trace_ID + 追加写入审计链 |
| 4 | 自解释 UI | 界面直接映射执行轨迹，区分"工作流节点 / LLM 兜底节点" |
| 5 | 声明式配置与零硬编码 | 行为在配置里，能改；凭证不落码 |
| 6 | 解耦设计与模块化 | 每一层可被独立替换（换模型/换记忆/换后端不牵一发动全身） |
| 7 | 安全沙箱与边界控制 | 最小权限 + 护栏 + 熔断，越权即失败而非静默 |
| 8 | 高阶认知闭环 | 规划 / 反思 / 学习是独立模块，不是散落在主流程里 |
| 9 | 全面测试与质量保障 | 守卫可证伪：回退产品逻辑，测试立刻红 |

## 1. 主权 Agent 的六层二十面

分层从内到外：**主体（它是谁）→ 大脑（怎么想）→ 记忆（记得什么）→ 手脚（能做什么）→ 身体（在哪跑、能否搬家）→ 治理（谁说了算、看得见吗）**。
每面回答一个"归属"问题，并附本仓现状（拥有 / 声明未接线 / 未做）与证据。

### A. 主体层 —— 它是谁

| # | 面 | 主权问题 | 本仓现状 | 证据 / 缺口 |
|---|---|---|---|---|
| 1 | 身份与命名 | 它是不是稳定可追溯的实体？ | ✅ 拥有 | `SubagentConfig.name` + 容器 `sa-<hex>`；缺口：临时分身名复用即回收，"长期身份"仍靠 name |
| 2 | 角色与人格 | 它"是谁"由谁定、能不能改？ | ✅ 拥有（2026-10-08 接入） | `agent/subagent/role_templates.py` 受控词表 + 提示词角色 `delegate_role`；主线侧人格走 `persona` 角色 |
| 3 | 系统提示词底稿 | 它的底稿是不是你自己的、可审的？ | ✅ 拥有 | `DELEGATE_SYSTEM_PROMPT` 云枢自有 + 角色片段拼在基座之后；§5.7 机制 1/2 禁止外来文本进 system prompt |

### B. 大脑层 —— 它怎么想

| # | 面 | 主权问题 | 本仓现状 | 证据 / 缺口 |
|---|---|---|---|---|
| 4 | 模型 | 用哪个大脑、能不能换？ | ◐ 同 provider 拥有 | `agent/subagent/llm_factory.py::resolve_subagent_llm`（inherit/explicit/fallback）+ `LLMService.with_model` + 温度在调用面钉住；**缺口**：跨 provider / 自带密钥（须 per-分身 TTL 凭据，P5） |
| 5 | 本地推理 | 断网还能不能想？ | ◐ 主智能体侧有 | `core/local_llm.py` 存在；**缺口**：分身执行后端没有"本地推理"档，委派默认走部署 LLM 或外部 CLI |
| 6 | 认知闭环（规划/反思/学习） | 它会不会自我纠错、越用越聪明？ | ○ 分身未接线 | 主智能体侧有 planning / 反思素材；分身侧只有一次性委派 + 云枢复评（`collection.CloudReviewer`）；**缺口**：P4 认知闭环 |

### C. 记忆层 —— 它记得什么

### D. 手脚层 —— 它能做什么

| 19 | 声明式配置 / 零硬编码 | 行为在配置还是代码？ | ✅ 拥有 | `agent/settings/registry.py` 473 开关（`scan_settings.py --check` 零缺口）+ `data/agent_lines/*.yaml` + `data/tool_definitions/*.yaml` |
| 20 | 测试 / 守卫 | 回退了会不会红？ | ✅ 拥有 | 可证伪守卫（回退产品逻辑 ⇒ 立刻红）+ 失败基线回归门禁（只允许收缩） |

> 编号 1–20（正文按六层分组：主体 1–3 / 大脑 4–7 / 记忆 8–10 / 手脚 11–13 / 身体 14–17 / 治理 18–20）。

### 1.1 主权成熟度：L0 → L3

| 档 | 判定 | 一句话 | 本仓位置 |
|---|---|---|---|
| **L0 借用型** | 跑在别人云上，身份/记忆/密钥都不在你手里 | 你只有使用权 | 已超越 |
| **L1 声明型** | 有字段、有界面、**没有消费者** | 填了不生效（本仓最恨"字段在、没人读"） | `memory_provider` / `tool_sources` 当前在此 |
| **L2 拥有型** | 每面都有消费者 + 随响应回显 + 可审计 | 你说了算，且看得见 | 工具/权限/凭据/生命周期/审计/配置 **已到**；角色与模型本轮补齐 |
| **L3 可带走型** | 断网换机仍能完整运行（bundle + 本地推理 + 本地记忆） | 你走到哪它跟到哪 | **未到**（P5 + P3） |

结论：本仓不是"缺主权意识"，而是**主权不均衡**——治理面（权限/审计/配置）极强，
记忆面与可带走面停在 L1/L0。所以"组装台"页面的第一职责不是堆更多开关，
而是**把每一面的主权状态（拥有 / 声明未接线 / 未做）如实摆出来**。

## 2. 「组装台」页面设计（改造装配车间）

### 2.1 为什么改造现有页而不是新建

1. 装配车间已经是分身的入口（`pages/hub/workshop/agents.tsx`，三视图：分身 / 主线档案 / 主线 × 四面），
   `hubNav.tsx` 已有导航项；新建第二入口 = 同一个页面两个门（本仓明令避免，`line-assembly` 就是因此删掉 manifest 的）。
2. 现在的"创建分身"是**一张四格表单**（名称/模型/记忆/工具源），它把"主权二十面"压成了四个输入框，
   且其中两个（memory/tool_sources）还没接线——这正是最该被"主权清单"纠正的误导。
3. 本轮已把 `role` 与 `llm` 的自举载荷（词表 + 生效来源）挂到 `GET /api/subagent/list`，
   组装台**零新增路由**即可拿到大部分候选与生效事实。

### 2.2 视图结构（4 视图，顺序即使用顺序）

| 视图 | 状态 | 内容 |
|---|---|---|
| ① 分身 | 保留 | 存活分身列表 + 历史（现有表格：模型/角色/记忆/状态/销毁） |
| ② **组装台（新）** | **新增，取代原"创建分身"弹表单** | 六步向导 + 主权清单 + 装配预览 + 生成 |
| ③ 主线档案 | 保留 | 权重/保底/效果上限/技能包/提示词 + 实时装配预览 |
| ④ 主线 × 四面 | 保留 | 一条主线在工具/技能/提示词/分身四面的横向对比 |

### 2.3 组装台布局

### 2.4 主权清单（页面的灵魂）

右侧常驻一张**三态清单**，每一态都由**后端字段**驱动，前端不自己判：

| 态 | 含义 | 颜色 | 数据来源（当前可得） |
|---|---|---|---|
| ● 拥有 | 有配置字段 + 有消费者 + 随响应回显 | 绿 | `subagent.role` / `subagent.llm` 投影；工具的 `needs_approval`；凭据的 `credentials_destroyed` |
| ◐ 声明未接线 | 字段在、消费者不在 | 黄 | `memory_provider` / `tool_sources`（页面已如实标注） |
| ○ 未做 | 机制不存在 | 灰 | `replicate.tsx` 的"规划中"事项（bundle / 通信看板） |

点击任一行弹出**"这一项凭什么"**：字段名、端点、文档章节、守卫用例名。
这就是起源设计第 4 条"自解释 UI"的最小落地：**界面直接映射后端事实，而不是映射一份前端愿望**。

### 2.5 装配预览 = 真实请求体（同源）

预览里的 JSON 必须与实际 `POST /api/subagent/create` 的 body **逐字一致**（同一个序列化函数产出）。
理由：预览若自己拼一份，迟早与实际请求分叉；而"分叉的预览"比没有预览更坏——它会让人以为已经看过了。
守卫：把"序列化函数"抽成纯函数，测试对"预览对象 === 请求 body"做断言；回退（两者分开拼）立刻红。

### 2.6 起点模板（不是玄学 prompt，是受控组合）

| 模板 | 只填这些（且只填**已接线**的） |
|---|---|
| 空白 | 名称 + 默认档（`role_mode=template`，无角色） |
| 代码审查 | `role_template=code_review` + 只读工具 + 需审批项高亮 |
| 资料调研 | `role_template=research` + 只读 + 禁止外发 |
| 隔离执行 | `trusted=false` + 最小权限 + 短 TTL（执行后端若未接线则标黄，不假装） |

模板是"起点"，不是"锁定"：选中后每一项仍可改，右侧主权清单实时重算。

### 2.7 数据契约（能不加路由就不加）

| 需要的事实 | 来源 | 状态 |
|---|---|---|
| 角色模板词表 + 三档语义 | `GET /api/subagent/list` 的 `role` 段（`role_templates.role_catalog()`） | ✅ 本轮已有 |
| 可选模型 + 部署模型 | 同上的 `llm` 段（`llm_factory.llm_options`） | ✅ 已有 |
| 主线 / 平面 / 工具元数据 | `GET /api/agent-lines`、`GET /api/agent-lines/planes` | ✅ 已有 |
| 逐分身"生效来源三档" | 行内 `llm.source` / `role.tier` | ✅ 已有 |
| 主权清单三态的**权威事实** | 需要一份只读投影（否则前端要硬编码"哪项未接线"——正是要避免的第二份口径） | ⏳ 建议新增 `GET /api/subagent/capabilities`（只读、无副作用） |
| 可带走 bundle 导出/导入 | P5 契约 | ○ 未做 |

**纪律**：S1 先用现有载荷做清单（未接线项由前端从"字段存在但无 `role`/`llm` 对应"推导会引入第二份口径，
故 S1 的清单**只覆盖后端已明确回显的三态**；完整三态等 S2 的 capabilities 投影，落一次权威）。

## 3. 分期计划（每期一个 PR，CI 全绿 squash）

| 期 | 范围 | 交付物 | 守卫（可证伪） |
|---|---|---|---|
| **S1** | 纯前端 | 组装台视图（六步 + 主权清单 + 装配预览 + 生成），保留现有三视图；删除原四格弹表单 | ①装配预览与请求 body 同源；②未接线项显示为黄（回退成绿立刻红）；③角色/模型徽章由后端字段驱动 |
| **S2** | 后端只读投影 | `GET /api/subagent/capabilities`：把主权二十面的三态做成**单一权威**（含 `why` 证据字段） | 清单每一项都有 `evidence`；回退成前端硬编码立刻红；contract_diff 允许一次**声明式**新增路由 |
| **S3** | P3 记忆 | `brokered`（母体代管只读上下文）先落地，`scoped` 走显式开启 + 配额 + 熔断；三处判定同改（actor_matrix / toolset / assembly） | 默认档分身 `tools` 里仍无记忆工具；`scoped` 未开时提供 provider 不改变任何行为；域越界写入被拒 |
| **S4** | P4 协同 | 共享任务看板（母体中枢，fan_out 逐任务写板）+ 二次派发 | 板上每条可追到 `delegation_id` 与 Trace；分身**不直接**写板 |
| **S5** | P5 可带走 | bundle 契约（身份与装配 / 引用式密钥 / 幂等启动）+ 导出导入端点 + `replicate.tsx` 从说明页转为真实导出面 | 导出包不含任何密钥形态（全包扫描）；导入后装配/LLM 结论与母体一致；一个真进程来回一条 JSON Lines |

依赖顺序：S1/S2 独立可做 → S3（记忆）→ S4（协同）→ S5（可带走，依赖 S3 的记忆档声明）。

## 4. 守卫与边界（不假装）

1. **主权清单必须后端驱动**：前端不得自造"已生效"。未接线就标黄并给去向（P3/P5），这是本页存在的理由。
2. **装配预览与请求同源**：抽成纯函数 + 同源断言；分叉即红。
3. **不新增路由**：S1 复用现有载荷；S2 若必须加，只加一个只读、无副作用、进 `contract_diff` 声明的投影。
4. **模板只用已接线字段**：模板里出现未接线字段即视为"假绿"，测试拦。
5. **现有三视图不删**：主线档案 / 主线 × 四面 仍是对账依据；只把"创建"从弹窗搬进组装台。

### 明确不做（避免过度承诺）

* 不做"一键克隆整个系统"（`replicate.tsx` 在 S5 之前保持说明页身份）；
* 不做跨机服务发现 / 集群 / 自动扩缩；
* 不做前端自维护的能力清单（与后端清单分叉）；
* 不在组装台里塞"人格编辑器"（人格在主智能体侧，分身只承接受控角色模板）。
