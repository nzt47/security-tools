# UI 封装规范（给人和 agent 的短版，≤80 行）

> 目的：**不要靠"记得"**。每条规则都有一条会红的守卫或一个会失败的基线；
> 写错就会在 `npm run ui:check` / CI 里红，而不是靠 review 抓。
> 全量清单以 `yunshu-ui/src/components/ui/index.ts` 的导出为准。

## 1. 先查表：这个场景该用什么

| 场景 | 必须用 | 禁止 / 注意 |
|---|---|---|
| 按钮 | `Button`（variant / size） | 原生 `<button>`；**满宽 / flex-1 的行按钮必须显式 `justify-start`**（基类居中，`text-left` 管不到 flex 子项） |
| 输入 | `Input` / `Textarea` / `Select` / `Checkbox` / `Switch` / `Slider` / `Radio` | 原生输入控件（基线只降不升） |
| 提示条 | `Notice`（自带图标） | 旧图标要么进 `icon` 槽，要么 `icon={null}` |
| 代码/预格式 | `CodeBlock` | 页面里写死 `<pre>` 常量 |
| 菜单 | `Menu` | 自造 `role="menu"` |
| 弹窗 | `ModalBase` | 页面自己写遮罩；**Esc 必须捕获阶段**，迁移时删掉页面自己那份监听 |
| 页签 | `Tabs`（pill / segmented / folder） | 手写 `role="tab"` |
| 表格 | `ui/Table`（hub 页面用 `DataTable` 薄封装） | 手写 `<table>` 样式 |
| 叶子页头（带页签） | `PageTabsHeader` | **标题必须在 Tab 上面**（守卫 `pageHeaderOrder`） |
| 叶子页头（无页签） | `PageHeader` | 再手拼 `<h1>` + 说明 |
| 区块标题（Tab 内容 / 卡片群） | `SectionTitle`（h2 = 14） | 手写 `<h2 className="text-title">`（16） |
| 字号 | 只用 9 档 token：`text-micro/caption/body/body-lg/ui/title/h2/h1/display` | `text-[13px]`（守卫 `arbitrary_text`=0）；**标题字号必须写在标签的 className 上**（守卫 `headingScale`），不许交给 CSS 类 |
| 颜色 | 语义 token / 调色板类（四套 `--wbp/--pl/--dc/--ve` 用语义名，见 `docs/ui/调色板语义命名表.md`） | 规则里写 `#hex`/`rgb()`（守卫 `css_hardcoded_color`）；字面值只允许出现在 `--*` 色板定义 |
| 圆角/间距 | `--radius-control/card/panel` 等 token | 再发明一套 `rounded-[7px]` |

## 2. 每次改前端的四步

1. **先读本文件 + `src/components/ui/index.ts`**，确认没有现成原语；
2. 找不到原语时先问"这是不是该进 ui/ 的第 3 个重复"（见 §4），**不要先写一份页面私有版**；
3. 改完在 `yunshu-ui/` 跑 `npm run ui:check`（tsc + eslint + 3 个守卫 + 量具）；
4. 红了改代码，**不改基线**；确实要改基线 → PR 里写清"为什么这条规则不适用"，Owner 点头。

## 3. 这轮踩过的反例（都已有守卫）

- 满宽 Button 用 `w-full` 不写对齐 ⇒ 内容居中；`text-left` 救不了（`Button.alignment.guard`）。
- 把 `<Tabs>` 放在 `<PageHeader>` 前面 ⇒ 标题落到 Tab 下面；引擎/实例干脆没标题（`pageHeaderOrder.guard`）。
- 标题字号写在 `.pl-*` / `.kb-*` CSS 里 ⇒ 同一个 h2 是 20/16/14/13 四种（`headingScale.guard`）。
- Tab 容器和子模块各渲染一个页级标题 ⇒ "TAB 的小标题"字号取决于子模块作者（改用 `PageTabsHeader` + `SectionTitle`）。
- 请求体：新增"前端可能不带 body"的写端点一律 `request.get_json(silent=True) or {}`（后端同口径，见 `docs/handoff/口径.md`）。

## 4. 新原语准入（防止"封装了还乱"）

- 同一形态在 **≥3 处**重复才进 `components/ui/`；否则先留在调用方。
- 进 `ui/` 必须**同时**给：① 1 条组件契约测试（尺寸/顺序/无障碍语义）；② 1 条守卫或量具（防回退）；③ `index.ts` 导出。
- 一个场景只允许一个原语；要换掉旧的，先删旧再合新的，不许两套并存。
- 新增字号档位必须同批登记 `src/lib/cn.ts`（tailwind-merge 否则吞字号，见口径 §14）。

## 5. 一条命令 + 守卫清单

```bash
cd yunshu-ui && npm run ui:check
# = tsc --noEmit + eslint src --quiet
#   + vitest run guard（Button.alignment / pageHeaderOrder / headingScale）
#   + python ../scripts/audit/ui_primitive_convergence.py --check
```

量具读数（基线 `data/ui_primitive_baseline.json`，**只降不升**；CI 的"代码质量检查"已跑）：
`raw_button / raw_select / raw_input / raw_textarea / arbitrary_text / raw_heading / css_hardcoded_color`。

同一套规则还有两个入口（与 `ui:check` 同源，不用记新口径）：

- **对话里**：`ui_guard_check`（只读）→ 返回 file:line / 规则 / 修复建议 / 基线回归；
- **界面上**：治理与运营 → **规范守卫**（概览 / 违规明细 / 自动修复预览与落盘；
  自动修复只碰字面量 className 的两类：Button 对齐、标题 token；概览带近 12 次检查趋势）。
- **工作流**：`tpl-ui-guard-sweep`（内置模板，默认停用）= 检查 → LLM 判断/出补丁 →
  `apply_patch(dry_run=true)` 校验 → 复检 → 报告；只预览、不写盘。
