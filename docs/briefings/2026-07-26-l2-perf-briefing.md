# 团队简报：L2 冷数据加载性能优化决策

**日期**: 2026-07-26
**主题**: 回退异步 IO 方案，确认同步串行 + 路径缓存为 L2 最优方案
**受众**: 全体研发团队
**状态**: 已完成，CI 已集成

---

## 一句话结论

异步 IO（`asyncio.to_thread`）实测 **P50 变慢 21 倍**，同步串行 + 路径缓存是当前最优方案，已回退异步 IO 代码并纳入 CI 性能护栏。

## 背景

TLM 三层上下文组装中，L2 冷数据层通过 `MarkdownSyncer.read_fragment` 从 `.md` 归档懒加载片段。`read_fragment` 是同步阻塞调用（`glob` + `open/read`）。

**初始假设**：同步调用阻塞事件循环 → 高并发 P99 恶化 → 异步 IO 应能解决。

## 实测数据（300 条 × 30 子目录 × 20 并发）

| 指标 | 同步串行（场景 C） | 异步 IO（场景 E） | 变化 |
|------|-------------------|------------------|------|
| P50 | 16.81ms | 370.64ms | **变慢 21 倍** |
| P99 | 99.75ms | 541.54ms | **变慢 5 倍** |

**结论**：假设被数据证伪。异步 IO 有害无益。

## 根因分析

| 根因 | 说明 |
|------|------|
| 路径缓存已优化 | 缓存命中时单次 `read_fragment` 仅 0.8ms，无需异步化 |
| 线程池调度开销 | `asyncio.to_thread` 调度 1-2ms/次，超过操作本身 |
| 并发 glob 竞争 | 多线程同时 glob，磁盘 IO 竞争加剧 |
| GIL 限制 | `glob` 目录遍历持 GIL，无法真正并行 |

## 最佳实践（已纳入 CI）

| 实践 | 说明 |
|------|------|
| **同步串行 read_fragment** | `_build_l2` for 循环串行调用，零线程池开销 |
| **路径缓存（O(1) 命中）** | `_fragment_path_cache` 缓存 key→filepath |
| **限量读取** | `f.read(max_chars*4)` 只读前 N 字节 |
| **锁竞争监控** | `_cache_lock` 等待占比 0.0%（实测非瓶颈） |

## CI 性能护栏（4 个回归测试）

| 测试 | 阈值 | 守护目标 |
|------|------|---------|
| 冷启动 P99 | < 2s | 路径缓存优化失效告警 |
| 热启动 P99 | < 1s | 缓存命中 + 限量读取失效告警 |
| 并发(10) P99 | < 2s | 同步 IO 串行化恶化告警 |
| 缓存有效性 | 热启动 ≤ 2×冷启动 | 缓存未生效告警 |

CI 日志已加标记：`echo "方案: 同步串行 read_fragment + 路径缓存（最优方案）"`

## 经验教训

1. **不要盲目异步化**：异步 IO 在缓存命中率高、单次操作快的场景下反而更慢
2. **用数据驱动决策**：通过对照实验验证假设，而非凭直觉
3. **路径缓存是关键优化**：O(1) 命中是性能基石，异步化无法替代
