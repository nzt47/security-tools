### 2.2 修复的真实缺陷

| # | 缺陷 | 落地 |
|---|---|---|
| 1 | **abort/timeout 跨会话串扰**：`_abort_event`/`_timeout_event` 是**实例共享字段** ⇒ 一次 `abort()` 掐断该实例上**所有并发 run**；且新 run 启动会 `clear()` 掉他人未消费的信号 | 改为每 run 一份 `_RunControl` + 栈式活动指针；`_abort_event` 改由 property 暴露（4 个既有测试文件的断言全部继续成立） |
| 2 | **一行死导入废掉全部配置校验**：`config.py:26 from pydantic.error_wrappers import ErrorWrapper`（v2 已移除，**且全仓从未使用**）⇒ `_PYDANTIC_AVAILABLE=False` ⇒ `ConfigModel` 从不构造；日志还谎报"Pydantic 未安装"（实装 2.12.5） | 删死导入；**两种校验改为合并**（`ConfigModel` 每节都有 default_factory，只跑它会丢掉"必填节缺失"检测）；失败原因如实打印 |
| 3 | **`_basic_validation` 用 `%d` 格式化用户传入值** ⇒ 非法值（字符串）输入时**当场 TypeError 崩溃**——本该"报告非法值"却变成"抛异常"。此前被上面那行死导入掩盖，从未执行到 | 改 `%s`，如实报出原始值 |
| 4 | `allow_population_by_field_name` 在 pydantic v2 被**重命名** ⇒ 旧名被忽略、别名字段填充静默失效 | 改 `ConfigDict(populate_by_name=True)`（不用 `validate_by_name`，它在 pydantic 2.11+ 才存在，而 pyproject 下限是 ≥2.0） |
| 5 | `provider` 校验值域只有 `openai/anthropic`，而仓库实际支持并配置的是 `deepseek` ⇒ 校验一生效就对**正确配置**报假错 | 值域补 `deepseek/azure/ollama` |
| 6 | **SSRF**：`HttpClient.download` 直调 `self._session.get` ⇒ requests 默认跟随重定向，跳转目标**绕过策略层**（"公网 URL 302 到 169.254.169.254"经典链） | 改走既有的 `_send_with_redirects`（逐跳复检），与 `request()` 同一条路径 |
| 7 | 容器内 `FLASK_API_TOKEN` 为空 ⇒ 所有 `@require_token` 端点**不校验**（宿主 401、容器放行，"一码两态"） | `docker-compose.yml` 显式注入；并确认 `.dockerignore` 已排除 `.env`（20 个明文密钥**未**进镜像层） |
| 8 | 全局鉴权闸门默认停在 `shadow`（只记不拦）；且"**已配令牌却停在 shadow**"这一最易忽略的组合**完全静默** | 代码默认改 `enforce`；新增 `enforce_all` 档覆盖 GET/HEAD；shadow+已配令牌时显式告警 |
