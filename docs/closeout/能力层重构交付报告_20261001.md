### 9.7 CI 在 Linux 上抓到的一个跨平台回归（已修，并记入常设约束）

**现象**：`可观测性质量保障 / 全项目测试覆盖率 (Shard 2/6)` 失败：

    FAILED tests/unit/test_system_tools_platform.py::TestErrorHandling::test_invalid_path_characters

**根因**：我给 `safe_resolve_path` 加的 symlink 加固在 realpath 抛错时 `raise` 了自己的
ValueError，改掉了「畸形输入返回字符串」这一既有契约。而该差异**只在 Linux 暴露**：
Linux 的 `os.path.realpath` 对含 NUL 的路径抛错，**Windows 不抛** ⇒
本地 `test_system_tools_platform.py` 是 **125 passed**，此回归在本地完全不可见。

**修法**：realpath 失败时**跳过本项检查、保持改动前行为**（返回字符串），不再新增异常与拒绝。
取舍理由：本加固的目标是「符号链接绕过」而非「畸形输入」；畸形输入自有下游 `open()` 处理，
其错误契约不该被本函数顺手改掉，且原实现同样不做这一检查 ⇒ 安全性不受影响。
验证：monkeypatch `os.path.realpath` 令其抛 Linux 同款异常，确认 `safe_resolve_path`
**返回 str 且不抛**；本地全量重跑后该失败消失。提交 `24080e0d`。

**由此确立的常设约束（本项目应长期遵守）**：

> **本仓的 CI 是 Linux，而开发/验证环境是 Windows。凡涉及路径语义（大小写、分隔符、
> NUL 字符、realpath 行为）、文件系统行为、编码或信号处理的改动，
> 本地全绿**不构成** Linux 上的通过证据。**
> 对这类改动，必须：① 用 monkeypatch 显式模拟 Linux 语义做一次反证；
> 或 ② 直接以 CI 结果为准，不得仅凭本地结果宣称已通过。**

本次即为该约束的实例：本地全量分块跑（6 块全收尾、0 丢失）**未能**发现它。

（`tests/unit/test_handoff_generator.py`，含三处脱敏 + `llm.chat → llm.summarize → 规则提取` 降级链），
而这条路由是它**唯一**的 HTTP 入口 —— 不接线 = 整条能力不可达（前端从不调用它，故长期无人发现）。
接线时补了一个 `_HandoffStateAdapter`：`generate_handoff` 要求 `state.session_mgr` / `state.Yunshu`，
插件里没有 `ServerState`，但 app_server 的同名模块级全局就是同一批对象（属性延迟取，规避循环导入红线 PLAN-1 §4）。
