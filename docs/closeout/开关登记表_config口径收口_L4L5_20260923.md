## 六、L4：显示口径 —— 让 UI 分得清「未提供」与「显式 false/空」

**问题**：源只有四个 token（env / ui_override / config / default），于是这两种处境在 UI 上都显示「代码默认值」：
- 该键**没有** config.yaml 口径（登记表 `config_path` 为空）；
- 该键**有** config 口径，但 config.yaml 里**没写**这一行。

而运维的动作完全不同（后者写一行就能改）。反向也有盲点：ObservabilityConfig 运行态的值**恰好等于登记默认值**时，
旧口径把 `config_present` 判成 False —— "配置层提供了但与默认相同"被折叠进"未提供"。

**改法（纯显示口径，不改任何生效值）**：

- `resolver` 新增 `config_provided`（配置层有没有这一项，值等于默认值也算有）与
  `config_state` ∈ `provided | absent | no_path`，并透出到 `to_public_dict()`
  （`config_state` / `config_state_label`）。★ `config_present` 与**全部取值分支一字未改**。
- 前端 `settings.tsx` 的来源行：**仅当 source=default** 时多一枚说明芯片，文案**逐字用后端** `config_state_label`
  （前端不另造说法）；source=config 时不重复（来源本身已说明），source=env/ui_override 时由 `shadowed_by` 说明。
- 契约类型 `cpPanelsTypes.ts` 同步补齐三个字段。

**用例**：resolver 侧 7 条（no_path / absent / 显式 false / 显式空串 / C 级空值 / 运行态等于默认值仍算"提供了" /
参数化三键断言三态只跟配置层走且 source+value 不变）；前端 3 条（default 上屏且两态文案必须不同、config 不上屏、env 不上屏）。
