## 2. 一处**测量口径订正**（本轮差点据此排错期）

### 2.1 现象：同一个量，三种数法得到 39 / 19 / 17

我先后用三种方式数"还剩多少处 `pickObj/pickList`"，得到三个不同答案：

| 数法 | 结果 | 错在哪 |
|---|---|---|
| `\b(pickObj|pickList)\b` 全文件计数 | 46 处 / 17 文件 | **把 import 行与注释里的提及都算成了调用** |
| 同上，去掉 import 行 | 19 处 / 14 文件 | 仍算了**注释里的提及** |
| 去掉 import 行 **且先剥注释** | **17 处 / 12 文件** | ← 正确 |

其中 `components/ui.tsx` 的 2 处是**这两个 helper 自己的定义**，不是待迁移的调用点。
故**真正待迁移的是 11 个文件 / 15 处**。

### 2.2 为什么会错，以及它在本仓的"前科"

前两种数法把**文档/注释里的提及**当成代码。我本轮正在给每个迁移过的文件加解释性注释
（例如"迁移前用 `pickObj` 猜形状……"）—— **我的注释本身把计数推高了**，
而 `module-list.tsx` 当时已经迁完，却仍被数出 1 处"未迁移"。

这正是 §6 第 19 条与 §9 的镜像：**盘点工具的输入过滤决定了它的结论**。
本仓对这件事早有记录（#1002 给计数面加"先剥注释再扫"就是这个原因），
但**盘点脚本要复用同一套剥离**这一点没有写在纪律里 —— 本轮补上：

> **凡是数"还剩多少处代码"的脚本，一律先剥注释**，并且不要用它自己新加的注释去解释
> 它正在数的东西（那会自我污染）。可直接复用 `scripts/audit/contract_diff.py::strip_comments`。

## 4. 新增的两条可继承经验

### 4.1 迁移守卫**不要导入 `app_server`**

第一批的守卫初版用 `import app_server` 取真实 app（理由正当：只有真实 app 才证明得了路由接上了 `ok()`）。
实测该导入**本机 80–100s**，在 CI 覆盖率分片（多 worker xdist + coverage）下**超过 300s 预算**，
把 `全项目测试覆盖率 (Shard 4/6)` 拖红（5 条 `Failed: Timeout (>300.0s)`）。

**改法**：把"有没有接上"与"接上后长什么样"拆开证明，两者都不需要导入 app_server ——
  · 响应契约 ⇒ 把被测 blueprint/`register_routes` 挂到**最小 Flask app**（`import plugins.status` 实测 **0.48s**）；
  · 生产接线 ⇒ **静态**断言（blueprint 非空 / `url_prefix` 正确 / `app_server.py` 里有该模块的接线）。

实测：第一批守卫 6 条 **2.32s**；第二批守卫 6 条 **2.32s**。

### 4.2 迁移信封时，**不要删业务键**

第二批的工作流列表把 `total` **同时**放进 envelope 的 `meta`，但**保留** `data` 里原有的 `ok/items/total`。
理由：`meta` 是信封层的通用信息（将来统一分页用），而 `data` 里那些键是**既有业务契约**。
两个都留 = "只加不改"；删一个就是"迁移里夹带契约变更"，而这类变更**不会报错，只会让某处静默取到 undefined**。

### 4.3 **每一批动手前都要用运行期 `url_map` 确认"活体是谁"**

本仓已**三次**出现"同一路径两份实现、活体只在其中一份"：

| 路径 | 活体 | 死副本 |
|---|---|---|
| `/api/heartbeat*` | `plugins/status.py`（Blueprint） | `agent/server_routes/routes_monitoring.py`（未接线，在 `KNOWN_UNREGISTERED` 清单里） |
| `/api/mcp/services` | `plugins/mcp_scheduler.py` | `agent/server_routes/routes_config.py`（未接线） |
| （同类清单） | — | `routes_chat`/`routes_panorama`/`routes_personality`/`routes_sessions` 等 11 个模块 |

**改错那一份不生效、也不报错** —— 是"看起来改完了"的最坏形态。
`test_server_routes_registration_inventory.py::KNOWN_UNREGISTERED` 只记录**模块级**未接线，
**不记录"某条具体路径由谁提供"**，所以不能替代这一步。动手前先跑：

```powershell
python -c "import sys;sys.path.insert(0,'.');import app_server;[print(str(r.rule), r.endpoint, sorted(r.methods-{'HEAD','OPTIONS'})) for r in app_server.app.url_map.iter_rules() if '<片段>' in str(r.rule)]"
```

**并且**：同路径同时挂 GET 与 POST **不是**"重复注册" —— 运行期 url_map 显示为两条规则、两个端点
（如 `/api/schedules`、`/api/mcp/services`），方法不同、互不遮蔽；迁移时**只迁本次要迁的那一侧**。

### 4.4 迁移**响应形状**时，先扫一遍"谁读了它的响应体"

第三批有两处既有断言被打红，**都在我上一批"动手前已查过测试"的审查面之外**：

| 报错 | 文件 | 它读的是 |
|---|---|---|
| `KeyError: ok` / `KeyError: channel` | `tests/unit/test_subagent_delegate_route.py` | `body["ok"]`、`body["channel"]`（旧**顶层**形状） |

教训不是"下次记得查"，而是**审查面要机械化**。可复算的做法：

```powershell
# 对**每一批**要迁的端点，找出"同一文件引用了该端点 且 对 get_json()[...] 做顶层键访问"的地方
# （本次实测：8 条已迁端点共 14 处候选，逐条核对后 2 处需改、其余属**别的端点**或**死副本**）
```

两条判定要点：
  · 命中的 `body["error"]` / `body["error_code"]` 可能属于**别的端点**（如 delegate 的错误契约）—— 不要顺手改；
  · 命中的文件可能在测**死副本**（`tests/integration/test_routes_config_integration.py` 自建 app 注册
    `routes_config.py`，而活体在 `mcp_scheduler.py`）—— 那不受迁移影响，别去改它。

**下一批的已知命中（已预先扫出）**：`/api/agent-lines/planes` 在
`tests/unit/test_tool_callability.py:722` 读了响应体的 `["tools"]`；同文件还读
`/api/agent-lines` 的 `["lines"]` 与 `/preview` 的 `["preview"]`。迁这些端点时必须一并更新。

`NETCFG-FLOOR`（conftest 地板）的修复（PR #1022）。但那个地板在 CI 上**没有生效**，
我关掉了 PR #1022 并把诊断留在了它的关闭说明与分支提交里。

### 4.5 测试里的**进程级**开关必须经 `monkeypatch`，且 fixture 得是 function 作用域

第三批我自己引入了**跨测试状态泄漏**，并被 CI 的「失败基线回归」抓出（该作业把 2.3 万条用例
放进**单进程**跑，是唯一能暴露它的地方）：

```python
sa._AUTH_DISABLED_FOR_TEST = True      # ❌ 直接赋值：永久改模块全局，分片跑看不出、单进程泄漏
monkeypatch.setattr(sa, "_AUTH_DISABLED_FOR_TEST", True)   # ✅ 用例结束自动还原
```

**两者是同一个错误的两半**：我把 fixture 声明成 `scope="module"` ⇒ 拿不到 function 级的 `monkeypatch`
⇒ 退化成直接赋值 ⇒ 泄漏。下游 `test_experience_plugin::test_mutating_routes_require_token`
因此 fail-open（本该 401 却放行）。

本仓其余 20 余处**一律**用 `monkeypatch.setattr` —— 那条约定就是为了防这个。
现已加机械守卫 `tests/unit/test_test_isolation_hooks.py`（5 条）：禁止直接赋值、
禁止非 function 作用域 fixture 引用这些钩子、豁免范围自检、判据对合成样例成立。
