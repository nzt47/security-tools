## 4. `_metrics_fallbacks` 标签口径不一致 —— 只加注释，未改代码

### 4.1 核实命令

```bash
git grep -n '_metrics_fallbacks\|encoding_fallbacks'
```

| 处 | 标签集合 |
|---|---|
| `utils/file_reader.py:90-93`（`_metrics_fallbacks`） | `['from_encoding', 'to_encoding', 'file_path']`（3 个） |
| `agent/monitoring/prometheus.py:612-616` | `['file_path']`（1 个） |

### 4.2 实测：这不只是"口径差异"，是一个**已存在的静默失效**

我跑了两种导入顺序的探针，结论如下：

```
# 探针 A：模拟生产装配序（app_server.py:1557 → routes_logging.py:50-54 → prometheus.py 先注册）
REGISTRY labelnames: ('file_path',)
prometheus.py obj labelnames: ('file_path',)
file_reader obj labelnames : ('file_path',)
same object? True                       # 两处拿到同一个 collector
3-label .labels() RAISED: ValueError Incorrect label names

# 探针 B：反向顺序（先 import utils.file_reader）
REGISTRY labelnames: ('from_encoding', 'to_encoding', 'file_path')
same object? True
prometheus.record_encoding_fallback RAISED: ValueError Incorrect label names

# 探针 C：直接 import app_server（真实装配序）
APP_SERVER_IMPORT_OK
production import order -> REGISTRY labelnames: ('file_path',)
```

**机制**：`prometheus_client` 同名指标只允许注册一次；后者命中 `ValueError` 后经
`_names_to_collectors` **复用先注册的同一个 collector** ⇒ 先注册方的标签集合获胜，另一方的 `.labels()` 抛异常。

**后果（生产装配序下）**：`utils/file_reader.py:135` 的 3 标签 `.labels()` 抛 `ValueError`，
被 `:136` 的 `except Exception: pass` **静默吞掉** ⇒ 编码降级事件不会计入该指标。

### 4.3 为什么**不改代码**（按派单要求"优先只加注释"）

1. 派单明确："除非差异确属缺陷**且有测试能钉住**，否则不要改代码"。
2. 唯一相关测试 `tests/unit/test_safe_file_reader_alerts.py:135` 调 `get_metric_value(_metrics_fallbacks)` **不传 labels**，
   函数体遇到 `labels is None` 就返回**第一个样本的值** ⇒ **无论标签是 1 个还是 3 个都会通过**，钉不住。
3. 该模块**无生产调用方**（§0），这条记录路径线上永不执行；改它收益为 0。
4. "统一标签"要**同时**改两处定义，而 `prometheus.py` 那处有生产 import（见其 :546-555）⇒ 属独立立项。
