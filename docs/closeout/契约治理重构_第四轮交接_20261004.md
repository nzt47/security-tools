## 5. 本仓的硬约束（违反会被 CI 挡）

1. **新增环境变量必须登记** `agent/settings/registry.py`（「开关零缺口」门禁是机械 AST 比对）。安全姿态类用 `_b`。
2. **新增 CI 作业必须自己装依赖**：本仓 job 默认无依赖。参考 `settings-registry-gap-guard.yml` 的最小集
   （`pyyaml pydantic prometheus-client psutil pytest pytest-timeout pytest-asyncio`）。
   **不要**在轻量 job 里装全套 `requirements.txt`（含 torch/chromadb ≈ 3GB）。
3. **CI 作业不要用窄 `paths:` 过滤，不要用 `-m <marker>` 选测试**（前者"改动未命中就不验证"，后者可能静默选中 0 个用例）。
4. **文件读写用文件工具**（read/write/edit），不要用 `cat`/shell 重定向。
5. **提交信息用中文、带"为什么"**（先触发与根因，再改法，再验证）。
6. **提交时只 `git add` 你自己的文件**，不要 `git add -A`（有并发写入者共用工作树；`data/system_prompt*` 被运行中的服务持续改写）。
7. **不要提交到 master**：开分支 → PR → CI 全绿 → squash 合并。
8. **重启服务**：`Start-Process python -ArgumentList 'app_server.py' -WorkingDirectory <repo> -RedirectStandardOutput logs\x.out.log -RedirectStandardError logs\x.err.log -WindowStyle Hidden -PassThru`。
   新实例自检就绪后**接管端口并杀掉旧实例**（冷启动 60–90s）；失败则不杀旧实例（安全）。
9. 前端改动要 `cd yunshu-ui; npm run build:flask`，并把 `templates/yunshu.html` **同提交**
   （`static/assets/` 在 .gitignore:448，只有模板入库）。
10. 本机控制台 GBK：跑会打印中文/符号的脚本前先 `$env:PYTHONUTF8='1'; $env:PYTHONIOENCODING='utf-8'`。
11. **本机跑不了可信的全量 pytest**（H-10）：`pytest.ini` 的 `--timeout-method=thread` 超时会
    `os._exit(1)` 杀掉整个进程且无摘要。全量请用 `python scripts/run_full_pytest.py`，或依赖 CI。

## 6. 本轮踩过、值得继承的坑（每条都是真金白银）

1. **守卫要锚在机制上，不要锚在"今天的数值"上**。我给"注释不计入"写的守卫断言
   `stray[callability.ts] == 1`，而下一个 PR 恰好把该文件迁走 ⇒ 该数**合法地**变 0，
   于是 CI 上**三条作业同时红**，功能却完全正确。改用**合成输入 + 全仓单调性**命题后不再失效。
2. **断言消息必须覆盖它实际能失败的所有方向**。上面那条只写了"大于 1 说明注释又被算进来了"，
   而实际失败是 `0 == 1`（往**下**偏）—— 排查者会顺着"注释没剥干净"去找，真相却是"文件被迁走了"。
3. **看到用例失败先读失败原因，区分「断言失败」与「超时失败」**。本仓已两次因此归因错误；
   本轮 Shard 5 的 `Failed: Timeout (>60.0s)` 若当成断言失败，会去查一个不存在的登记缺口。
4. **全树扫描是超时的头号来源，且修法已固化**：`rglob` **会先把整棵树走完**，"之后过滤"省不到走树的钱
   （实测 15,822 路径 / 35.17s，过滤后只需读 3,263 个 / 0.49s）。修法二选一：
   **① 正则预筛**（文本子串只能"多留"不能"少留"，AST 仍是唯一事实源）；**② `os.walk` 就地剪枝**（改写 `dirnames`）
   ＋ **记忆化**（多个用例共享一次扫描）。已用此修法解决 3 处。
5. **批量改写脚本在找不到锚点时必须"整文件不写回"**。迁移 10 个文件时首版正则要求 import 行以分号结尾
   （本仓多数不带），6 个文件报 `NO IMPORT ANCHOR` —— 若当时选择"先替换再补 import"，
   就会产出 6 个引用未导入标识符的坏文件，而 `tsc` 要到下一步才告诉你。
6. **批量改写的完备性不能只靠脚本自查，要由结果指标兜底**。迁移脚本第三次漏项（MAP 表没列早已存在的常量），
   而**脚本不报 MISS**（那个字面量根本不在它的表里）—— 发现它的是"逐文件核对最终 stray 数"。
7. **改写脚本要先剥注释再替换**。用"整段反引号匹配"替换模板串时，**注释里描述端点的反引号代码跨同样被匹配到**，
   两处 JSDoc 被改成常量名。（与 #1002 为"计数"加的注释剥离是同一件事的两面。）
8. **改完记得看 lint**：普通串形态漏迁时只有 eslint 的 unused-import 警告能发现它（`tsc` 不报未使用导入）。
9. **写 Python 时中文引号一律用「」**：本轮我**三次**把 `"…"` 写进 Python 双引号字符串导致语法错误。
10. **扫描器的输入清单必须覆盖全集**：我曾把文件集写成 `app_server.py + plugins/*.py + agent/server_routes/*.py`，
    于是把 `/logs/dashboard` 误判为"陈旧豁免"——它其实是 `agent/log_system/dashboard.py` 的真实路由。**运行期 `url_map` 才是权威输入**。
11. **门禁"有信息但不拦"等于漏报**：`audit_dependency_drift` 早已算出 `ONLY_IN_PYPROJECT = 4`，
    但 CI 只跑 `--fail-on-conflict`（只判 CONFLICT）⇒ "Windows 生产会丢 WMI"可以全绿合入。已补开关。
12. **别把实现细节当契约**：一个守卫断言"必须出现 `return jsonify`"，把 401 改走 `_problem(...)` 后立刻假红 ——
    它守的是"用哪个 helper"，而它想守的是"必须拒绝"。结构边界要用 **AST** 表达（文本切片会把相邻分支算进来）。
13. **行号不能进基线键**：给 `admin_api._require_admin` 加 5 行，基线里的 `/api/auth/login` 从 `:360` 变 `:365`，
    守卫随即报出**一条形状与"安全洞"完全相同的假警报**。
14. **"先量再决定"救过两次**：① 嵌套副本是否已在掩盖缺失 → 实测 `only_nested = 0`（今天零影响，不说成"正在漏报"）；
    ② 是否该在 Linux 上重生成锁文件 → 实测会丢 4 个 win32 依赖（故不做）。
