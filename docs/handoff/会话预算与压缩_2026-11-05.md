# 会话预算与自动压缩（2026-11-05 实测）

## 结论

- 界面文案说「超过 80% 才压缩」，但**实际触发点不是 80%**：本机 W=1,000,000、模型单次最大输出 O=256,000、
  安全余量 headroom=65,536，代入 Harness 的公式
  `floor(min(W × thresholdRatio, W − O − headroom))` = `min(800,000, 678,464)` = **678,464（67.8%）**。
- 实测证据：上一个长会话（session-01463242…）在 `compaction/start` 前的最后一次 usage 是
  `input 254 + cacheRead 678,016 ≈ 678,270 tokens` —— 与公式算出的 678,464 只差 200 tokens（就是当轮增量）。
- 也就是说：**80% 在这个模型上不可达**（W−O = 744,000 = 74.4% 是理论上限，余量再压也只能到 74.4%）。
- 一次会话通常只发生 **1 次**整段压缩（`compaction/start → summary → end`），
  伴随多次 `compaction/prune`（超长工具结果被裁剪）；「感觉频繁」主要来自这些裁剪提示与多次会话累加。
- 本会话当前用量：约 **513,122 / 1,000,000（51.3%）**，尚未触发压缩。

## 想「晚点压」或「早点提醒」怎么办

| 目标 | 做法 | 代价 |
|---|---|---|
| 让压缩晚一点 | 调小 `headroomTokens`（默认 65,536） | 最多推到 74.4%（受模型最大输出 256k 限制），再高会撞上下文溢出 |
| 完全手动 | 组合里 `dsh-compaction-basic` 设 `auto: false`，用 `/compact` 手动压 | 需要人盯着用量，忘了就溢出 |
| **65% 提醒换会话** | `python scripts/session_budget_watch.py`（本次新增） | 需要以计划任务/手动方式定期跑 |

## 新增脚本：session_budget_watch.py

- 只读最新 `~/.dsh/sessions/*/*/session.v4.jsonl.zstd` 的最后一次 usage，算占比；
- 从 `~/.dsh/profiles/desktop/cordis.patch.yml` 读 `contextWindow`（读不到回落 1,000,000）；
- 超过 `--warn`（默认 65%）时 **exit code = 1**，便于挂计划任务；
- 输出示例（本机当前）：
  ```
  会话 session-cb15f0bb…：约 513,122 / 1,000,000 tokens（51.3%）
  自动压缩实际触发点在 67.8%（W - 最大输出 256k - 余量 64k），不是 80%
  还有余量：到 65% 我会提示换会话
  ```

## 与交接的配合

到 65% 时：`python scripts/handoff_snapshot.py` 生成交接卡 → 开新会话 → 新会话只读
**口径（口径.md）+ 最近 2 轮 + 交接卡**，不再全文重读。这样"换会话"的成本从"读 900 行"
降到"读 60 行"。
