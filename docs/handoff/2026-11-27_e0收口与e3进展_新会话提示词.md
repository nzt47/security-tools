## 2. 本轮踩到的坑（写下来省下一轮）

1. **UI 量具连注释里的字面量也算**：`raw_input` 的判据是正则 `<input\b`，我在注释里写了「不是裸 `<input>`」就被计 1 处（`ui:audit` 红）。写注释别放标签字面量。
2. **新路由要重派生 coverage**：`route_ui_coverage.py --check` 会报 hash 漂移，跑一次不带 `--check` 的即可（本次 `pending_backlog` ceiling **没**抬高）。
3. **本地扫描会把运行期产物当代码**：`agent/data/checkpoints/**/files/**` 里有源码副本、根目录 `.ci_watch*.py` 是未跟踪脚本 ⇒ `scan_settings.py --check` / `test_tool_definitions_yaml` 在**脏工作区**必红；判绿必须在干净 worktree（本轮就是这么做的）。
4. **pip 在这台机器上极慢**（~5 kB/s）：`pywinpty` 2.1MB 下了 2m45s。装依赖要放后台作业，不要阻塞在主流程里等。
5. **CI 多次被新 push 取消**（同 concurrency 组）：想拿终判就别连续推；文档类提交请带 `[skip ci]`。
6. **`/api/feedback/submit` 不是 v2 信封**（返回 `{success,data}`）：前端用裸 fetch + `res.ok`，别用 `postEnvelope`（会在成功响应上抛错）。
7. **已知本地红（与本轮无关，别追）**：`tests/unit/test_chat_tool_usage_ledger.py` 有 4 条在本机红。
   已用三个干净 worktree 交叉验证：**在接手时的 8efb5c75b 上同样红** ⇒ 环境/既有问题，不是本轮回归；
   CI 侧（干净 checkout + 独立 tmp）历史上是绿的。花时间修它之前先确认 CI 是否也红。
8. **CI 排队很慢**（今晚 5–10 分钟才开跑）：想拿终判就别连续推；任何 push 都会取消排队中的 run。
9. **「新增一个工具」实测要动的清单（本轮 terminal 一次全踩了一遍，按这个顺序做最快）**：
   ① `data/tool_definitions/<name>.yaml`（schema 必须与 `@_tools.register` **逐字**一致）→
   ② `scripts/backfill_tool_planes.py::PLANE_MAP` 补 (plane, effect, risk, tags) → ③ 三个 `backfill_*` 的 `--check` 过 →
   ④ `agent/tool_router.py::_DEFAULT_TOOL_CATEGORIES` 的分类工具表按序插入 → ⑤ 干净 worktree 派生
   `sync_tool_index` / `sync_capability_manifest` / `gen_baseline_bm25_raw`（S0 会变）/ `run_routing_reliability` →
   ⑥ 改**计数契约**（本轮踩到 6 处）：`test_capability_spec`、`test_capregistry_core`（含 remote 分布与探针 total）、
   `test_confirm_level`（L2+L3）、`test_tool_router_hybrid_real_index_l28`、`test_tool_pruning`（高危误裁基线）、
   `test_det2_stable_sort_determinism`（分类工具数）→ ⑦ `eval_route_conflict` 的 v1 τ 期望值。
10. **跨盘 relpath 会抛**：Windows 上仓库在 D:、附件/临时目录在 C: 时 `os.path.relpath` 直接 ValueError。
    任何「把绝对路径转成仓库相对路径」的地方都要 catch ValueError 回绝对路径（CI 的 windows 腿就这么红的）。
