**C. 本轮踩的坑（务必先看）**

1. **不要忘了先开分支再提交**：U3 我直接在 master 上 commit+push（`f45140f79`）。来源守卫是 dry-run 所以没拦，
   但这是流程违规——**动手前 `git branch --show-current`，不是目标分支就先 `checkout -b`**。
2. **新增后端路由必红 `sync_capability_manifest`**：清单/盘点表/依赖图是**派生物**，必须在**干净 worktree**
   （`git worktree add .worktrees/x HEAD --detach`）里跑 `python scripts/sync_capability_manifest.py`。
   本机 `data/*.py` 这些 untracked 草稿会被静态扫描计入 unresolved ⇒ 产物与 CI 不一致。修法见 #1367。
3. **主轨 content 必须经运行中的服务写**：另起 `SkillStore`/`service` 写盘会被服务进程的缓存覆盖回去
   （U5 首轮 `test_body_is_verbatim_main_track_content[real]` 就是这么红的）。正确入口：
   `PATCH /api/skills-mgmt/<id> {"content": ...}`（或服务进程内调用）。
4. **shard 5 的“order-dependent 假红”**：本轮多次出现 `AttributeError: 'userbase'`（coverage 的 unraisable hook 里
   `sysconfig.get_paths()` 失败）+ 大量无关用例连坐（test_system_tools_platform / dashboard / tool_trace …），
   同一批用例**本地单跑 215 passed**。判据：失败集中在同一 worker 的 50–90% 区间、错误是 sysconfig/coverage 内部异常、
   单跑绿 ⇒ 环境/顺序问题，不是本改动。处理：先重跑；仍红且确认无关后，才考虑 `gh pr merge --admin` 并写清依据。
5. **`deploy_workbench.py --no-fetch` 仍会 `merge --ff-only origin/master`**：在特征分支上跑它会把工作区切到 master，
   出现「backend=分支 commit / build=master」的错位（本次发生过一次）。**部署前先 `git checkout master` 并拉平。**

**E. 后续（2026-10-31 18:00 收尾）：假红已修（PR #1370 → `73ccf81a5`）**

- **根因（WSL 3.12 复现，不是猜测）**：Linux 上只要 sysconfig **首次**初始化落在某个把 `os.name` 打成 `nt` 的用例窗口里，
  `_init_config_vars` 会走 `_init_non_posix` 并访问 `sys._vpath`（Linux 没有）⇒ AttributeError，
  留下**缺 userbase 的半成品**；此后 `get_config_vars()` 见非 None 不再初始化 ⇒ 整个进程的 coverage 每次
  `should_trace` 都抛 `AttributeError: 'userbase'` ⇒ 整片无关用例连坐 + xdist worker INTERNALERROR。
- **修法**：`tests/conftest.py` 导入期单线程预热 sysconfig + 预导入 tracemalloc；真正的 `pytest_configure` 调
  `_ensure_sysconfig_guard()`（补 `userbase` 键 + 给 `sysconfig.get_paths` 套一层缺失时自愈）。
  **注意**：该文件后面另有同名 `pytest_configure`，同名会覆盖 ⇒ 兜底函数必须**唯一命名**（第一版就栽在这）。
- **另一个假红**：`test_generate_visibility_trend` 的 sleep 计数——`time` 是进程级单例，patch 模块属性仍命中全局
  （实测 3416/3737 次）。已改成模块级缝 `_sleep = time.sleep`，测试只 patch `generate_visibility_trend._sleep`。
