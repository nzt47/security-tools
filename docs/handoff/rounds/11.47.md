**C. 口径与教训（写代码前必读）**

1. **业务 4xx**：固定文案（常量表）+ `error_code`，原文进 `logger.info`；需要回显字段名就做成
   `_FieldError(field, reason)`（`routes_subagent.py` 已有）。
2. **CodeQL 只认这三种"断链"**（§8 陷阱 14）：
   ① 列目录 + 名字等值匹配（通用版 = `agent/safe_paths.enumerate_path`，逐段、Windows 大小写不敏感）；
   ② 常量键 → 常量路径的字典查表；③ sha256 摘要命名（`replay_storage`）。
   **正则清洗 / resolve+前缀 / realpath+dirname 校验都不被认**。
3. **异常对象属性不被报**：`str(e)` / `e.args` / traceback 会被报，`e.code` / `e.message` / `to_dict()` 不会。
4. **属性分诊已做的一次**：`agent/tools/file_tools.py` 22 条按 `won't fix` dismiss（契约就是按路径读写；
   理由写在每条告警的 dismissed_comment）。恢复：`gh api -X PATCH .../alerts/<n> -f state=open`。
5. **派生产物必须在干净 worktree 重派生**：`capability_manifest.json` / `云枢能力清单盘点表.md` /
   `route_ui_coverage.json` / `ui_reachability.json`；本机 untracked 草稿会污染（本会话踩两次）。
6. **Windows `datetime.now()` 只有 ~15ms 粒度**：连续写入会拿到相同时间戳 ⇒ 排序要加 `rev`（jobs.py 已做）。
7. **测试跨模块污染**：`_registry_version` 回退会与之后状态**撞号**，`list_tools()` 命中旧缓存
   （已在 `test_injection_end_to_end` 夹具修为只增不减）。
8. **worktree 里跑测试会污染 `data/assets/*.json`**（相对路径），出现"多出 N 条"的假红时先清。
9. **CI 覆盖率 Shard 3 可能卡死**：pytest 已出汇总但 job 不结束（日志被
   `memory_manager._execute_compression` 的 `I/O operation on closed file` 刷屏）⇒
   `gh api -X POST .../runs/<id>/cancel` 后重跑该 run，别干等。
10. **本机沙箱**：受限模式（workspace-write）下所有子进程 `0xC0000142`；本会话用 danger-full-access。
11. **部署纪律**：先 `Stop-Process python` → `git checkout -- data/logs/yunshu_logs.db*` →
    `python scripts/deploy_workbench.py --no-fetch --smoke`（**不要 --no-build**；先停后端再构建，
    否则前端 rolldown 会 OOM）。冒烟报 `/api/version 无响应` 是冷启动竞态，带 token 复测即可。
