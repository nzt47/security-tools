### 11.8 ✅ 已结案（2026-10-28 00:30，PR #1328 → `238f033a`）：运行时工具 vs「清单可从干净 checkout 复算」
- 问题（2026-10-27 19:50 发现）：`data/capability_manifest.json` 是**提交产物**，由 `scripts/sync_capability_manifest.py`
  从 `data/tool_definitions/*.yaml` 派生、CI `--check` 守门；而吞噬「登记为工具」把 YAML 写进**同一个目录**、
  并把名字记进 `data/dynamic_tools.json` 台账 —— 两者都是 .gitignore 的运行时状态 ⇒
  「提交产物」与「本机运行时来源」混在一个目录里，**没有忽略机制**。
- 后果（2026-10-27 实测）：本机每登记一个工具，**18 条**守卫用例红、CI 全绿 —— 本地常态红、红了没人看：
  `test_tool_callability` 8 条（清单一致性 / 声明完整性 / 两个 `--check`）、
  `test_capregistry_core` 6 条（127 / 91 / 126 / 索引 127）、`test_confirm_level` 4 条（91 个 YAML / L2+L3=20）。
- **口径定案（沿用 ①，并补上缺失的忽略机制）**：清单 = **仓库可复现的能力面**；运行时登记的工具只在 REST 侧
  现算标注（`runtime_only_tool_entries`，`scope=runtime`，#1322 已有 ⚠️ 徽章）。两者必须能**显式分开**：
  - `agent/lines/callability.py`：新增 `runtime_registered_tool_names()`（**缺文件 / 坏 JSON / 结构不符一律空集**）、
    `load_tool_docs(skip_names=)`、`build_manifest(exclude_runtime_tools=False)` —— **默认 False = 不读运行时台账**，
    所以模块语义与 CI 行为**逐字节不变**；排除在**入口**做（若在结果里删条目，counts/main_line/同名冲突会各算一份口径）。
  - `scripts/sync_capability_manifest.py` 默认传 True（提交口径）、`--runtime` 传 False（本机看全貌），并打印被排除名单；
    `scripts/backfill_tool_callability.py --check` 同口径跳过（否则报「缺可调用性字段」）。
  - 能力注册表 6 条「钉提交基线」的数值断言：本机 `skipif(runtime_registered_tool_names())` 并写明理由
    （注册表 = 基线 + 运行时登记；干净 checkout / CI 里没有这些文件 ⇒ 照旧全跑）。
- 结果：本机两个 `--check` 从红转 **0**；相关 8 个测试文件 **398 passed / 0 failed**；
  **干净 worktree（等价 CI）** 289 passed / 6 skipped（6 条全是既有 `--runslow`）⇒ skip 标记在 CI 不触发。
- 仍成立的结构性选择（未变）：**AI 生成的工具代码不入库**。若将来要把某几个生成工具纳入仓库，
  正确做法是人工评审后把 YAML + 实现入库并从 `data/dynamic_tools.json` 台账里摘掉名字（否则本机 `--check` 会红，
  这个「只在有台账的机器上红」正是提醒清理的**信号**，不要反过来放宽 `--check`）。
