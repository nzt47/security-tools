**B. 三条新口径（写代码前必读）**

1. **真凭据不许出现任何派生串**：不只是原文 —— `sha256(secret)` 会被 `py/weak-sensitive-data-hashing` 判 high（"拿口令做弱哈希"），
   `len(secret)` / `bool(secret)` 仍会被 `py/clear-text-logging-sensitive-data` 追成明文（#1431 实测：第一版指纹方案一次新增 16 条）。
   **唯一稳妥写法：日志表达式里根本不出现那个值**（只写常量、条数、异常类名）。指纹只适用于**非凭据**（路径 / 任务文本，见 file_tools `_path_fp`）。
2. **派生产物与代码静态扫描绑定**：`capability_manifest.json` + `云枢能力清单盘点表.md` 的 location 证据来自**注册点静态扫描**（external_calls / unresolved 计数）。
   **任何改到调用点的代码变更都会让 `test_tool_callability::test_清单同步_check_通过` 变红**（本轮 #1430 的 Shard 2 与覆盖率 Shard 5 同时红）。
   正确做法：`git worktree add .worktrees/xxx HEAD --detach`（干净 worktree）→ `python scripts/sync_capability_manifest.py` → 拷回两份产物一起提交。
   验证派生确定性：在 master 的干净 worktree 里重派生，`git diff` 应**只有 generated_at 一行**。
3. **GitHub 侧偶发不靠谱**：`gh pr merge` 可能回 502 / `GraphQL: Something went wrong` / `Merge already in progress`，`git push` 也可能 `Permission denied (publickey)`。
   前者等 1–2 分钟重试即可；后者用 `git push https://x-access-token:$(gh auth token)@github.com/... HEAD:refs/heads/<branch>` 绕过（API 侧正常，说明只是 SSH 通道问题）。
