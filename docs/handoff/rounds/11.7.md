### 11.7 新发现（2026-10-27 05:20，未实证修法）：动态工具是**惰性加载**
- 现象：重启后 `/api/tools/config` = **91**，台账里 2 个动态工具（byted_bp_cdn_pagesdeploy /
  byted_seedream_image_generate）都**不在**列表里；单独进程 `load_dynamic_tools()` 可加载 2/3（第 3 个是
  `scripts/subscribe_cdn.py`，跳过）并注册成功。
- 代码路径：`load_dynamic_tools()` 只在 `lifecycle_manager._get_ext_manager()` 里调用，而后者只被
  `agent/tools/ext_tools.py`（6 处）与 `notify_tools.py` 调用；`app_server._extension_mgr` 是**另一个**
  ExtensionManager，不触发加载。故「登记后重启仍在」实际是「重启 + 某次扩展工具调用后才在」。
- 影响：重启后模型看不到自生成工具（装配器也不会选它），直到有人调用扩展工具；对「登记即可用」是隐性违约。
- ✅ 修法已在 PR **#1322**：`_register_builtin_tools` 末尾无条件 init+load；`_iter_custom_modules` 跳过
  `<id>/scripts/`；`load_dynamic_tools` 幂等（`_loaded_modules` 去重，避免 `name_2` 别名）；
- 另修一个隐患：`_get_ext_manager` 的台账路径少上溯一级（指向 `agent/data/`），一旦它先跑，
  动态工具台账会写进另一个目录、与登记那份分叉。
  现状：重启后 `/api/tools/config` = **94**（91 静态 + 3 动态），三个都在。
