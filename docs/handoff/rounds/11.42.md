**B. 本轮定下的口径（写代码照这个来）**

1. **业务 4xx 也回固定文案 + `error_code`**：业务异常（我们自己 raise、消息给人看）不许再 `str(e)`；
   文案来自常量表 `_BIZ_TEXT`（按 code 查），原文进 `logger.info`。
   **要回显字段名**就把它做成校验结果里的字段，不要回异常文本。
2. **`_FieldError(ValueError)`**（`routes_subagent.py`）：携带 `field`/`reason` 两个**调用点常量**，
   只有它允许回「参数不合法：llm_temperature 越界（须在 0.0–2.0）：3.0」。
   已覆盖：llm_temperature / budget_tokens·timeout_seconds / role_template / autonomy_level。
3. **chat 不是把 stdout 捕获进 `logs`**（B2-a 结论）：方向相反 —— `logs` 显式 append、
   随响应体返回、同时被 `print`。所以改法是「控制台只打摘要」+「上游错误文本进 logger」。
4. **CodeQL 的 python 分析**：`str(e)` / `e.args` / traceback 是源；**异常对象的自定义属性**
   （`e.code` / `e.message` / `_FieldError.field`）与 `to_dict()` 返回的 `self.message` **不被报**
   （workflow 的 `_err(e)` 一直如此）。
