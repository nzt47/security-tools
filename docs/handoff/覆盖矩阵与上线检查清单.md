# 感知 / 监控覆盖矩阵 与 新功能上线检查清单

> 2026-11-12（第五十九轮）。回答 Owner 两问：
> 「现在真的能做到全域感知、全域监控了吗？」「开发出新功能也能自动被感知和监控吗？」
>
> **结论先说**：
> 1. **监控面**：六个事件源 + 五层健康探针 + 单位看板 + 拓扑 + 审计链都有真实读数，
>    但"全域"仍不成立 —— 16 条告警规则只有 6 条可求值（10 条 blocked，逐条原因在
>    `/api/alarms/coverage.rules.blocked`），且缺外部服务存活 / 日志异常聚合 / 外发通道。
> 2. **感知面**：本轮之前**近乎空转**（无周期采集、FileWatcher 未启、CI 源离线 7h）。
>    本轮接上三个真实输入面（文件监听 → learning、周期快照 diff、CI 同步），
>    但"全域"仍不成立 —— 感知只覆盖已注册的 18 个传感器 + 两条采集触发，不覆盖新功能。
> 3. **新功能自动化**：只有**拓扑**是自动的（声明一行 `MODULE_STATUS_SOURCE` 即上图），
>    单位看板 / 告警规则 / 事件源 / 传感器**全部手写**。第 4 节是"上线要补哪几处"的清单。

## 2. 两个「静默缺口」怎么读（本轮从"无声"变"可见"）

`GET /api/alarms/coverage` 新增两个块（页面：健康仪表盘 → 告警 Tab 顶部「监控覆盖」卡片）：

```text
ci:         {available, last_sync_at, age_seconds, stale(>2h), max_age_seconds, runs, detail}
perception: {available, watch_dirs[], watcher_running, last_tick_at, last_file_event_at,
             last_file_event_age_seconds, last_change_at, last_novelty_at,
             last_novelty_age_seconds, long_silent, detail}
```

口径：
- **读不到 = `available:false` + 说明**，不返回 0 岁（"刚刚同步过"是假的）；
- CI `stale:true` 表示采集层本轮按「不可用」处理（既不报警也不判恢复）；
- 感知 `long_silent`（>24h 无文件事件）只是**标注**，不是故障 —— 没人往监听目录写东西很正常；
- 页面上 `formatAge(null)` 显示「—」，不是「刚刚」（L5：没读到 ≠ 刚刚发生）。

## 3. 本轮补的三处接线（可回滚）

| 接线 | 位置 | 开关 / 回滚 |
|---|---|---|
| watch_dirs 真的被读到（env > Config overrides > config.yaml > 默认） | `agent/sensor_config.py` + `lifecycle_manager` | `SENSOR_WATCH_DIRS` 置空 + `config.yaml sensor.watch_dirs: []` ⇒ 走默认；要彻底不监听就把默认也改空（或让目录不存在）——**改后需重启** |
| 感知周期采集（5 min drain 文件事件 / 30 min 快照 diff / 落状态） | `agent/learning/perception_cycle.py` + `app_server` 注册 | `SENSOR_PERCEPTION_ENABLED=false`（重启后不再注册） |
| CI 结果周期同步（30 min，gh → status.json） | `agent/monitoring/ci_status.py` + `app_server` 注册 | `CP_CI_SYNC_ENABLED=false` |

## 4. 新功能上线检查清单（"能不能自动被感知/监控"的答案就在这张表）

新功能 = 新包 / 新工具 / 新路由 / 新后台任务。上线前逐项对：

1. **拓扑声明**（自动，必做）
   - 在包的 `__init__.py` 写 `MODULE_NAME` / `MODULE_DOMAIN` / `MODULE_STATUS_SOURCE`；
   - 判据：`/api/modules/topology` 出现该节点，且 `unregistered == 0`；
   - 只写 `MODULE_NAME` 不写 source ⇒ 进"未登记"，**不参与健康分**（看起来"有节点"其实没读数）。
2. **单位看板**（手写，可选但建议）
   - `agent/monitoring/unit_probes.py` 加 `probe_xxx()` + `_all()` 里 `Unit(...)` 一行；
   - 纪律：**只读、不创建单例**（读探针不得 `get_scheduler()/get_singleton()`，§11.93 实证）；
     无数据返回 `status="never"`（不计分），不要造 0。
3. **告警规则 + 指标**（手写，必须成对）
   - `monitoring/alerts.yml` 加一条 PromQL 子集规则，**同时**确认它引用的指标真有写入点；
   - 指标族不存在 = `no_data`（不是 0 增量）；族存在但子集为空 = 0 增量 = ok；
   - 判据：`/api/alarms/rules` 里该条 `evaluable`（不是 blocked）。
4. **埋点**（手写）
   - 新的"调用/失败/拦截"计数要写在**真实执行点**（例：LLM 收口在 `LLMMonitor.record()`、
     工具台账在 `plugins/chat.py::_record_tool_usage`）；写在钩子上多半收不到（§11.91 实证）。
5. **传感器 / 感知输入**（手写）
   - 新传感器：写类 + registry 注册；**还要有人周期 collect**（否则 enabled 也是空转）；
   - 新"外部输入面"：把目录加进 `sensor.watch_dirs`（或 `SENSOR_WATCH_DIRS`），
     **不要**包含 `data/learning` 或仓库根。
6. **文档与派生产物**（半自动）
   - 派生产物必须**干净 worktree 重派生**（capability_manifest / 盘点表 / tool_index / BM25 /
     路由基线 / route_ui_coverage / ui_reachability）；
   - 新 env 必须进 `agent/settings/registry.py`（`python scripts/scan_settings.py --check` 零缺口）；
   - 新增前端端点先写 `src/api/endpoints.ts`（React 侧 `/api` 字面量必须恰好 0）。

## 5. 自动化候选：本轮做了什么、没做什么

| 候选 | 决定 | 理由 |
|---|---|---|
| CI 同步周期化 | ✅ 做了（30 min） | 报表最便宜、缺口最真（实测离线 7h）；失败只记警告不制造噪音 |
| 感知周期化 | ✅ 做了（5 min drain / 30 min diff） | 不做则 FileWatcher 与 ChangeDetector 依旧无人调用；diff 节流避免进程噪音 |
| 单位看板自动登记 | ❌ 没做 | 自动登记会改变健康分分母（新增单位默认 never/ok 各半），且需要"包声明自己是单位"的新协议；先做**可见缺口**（本文件第 1 节 + 拓扑对拍） |
| 缺埋点报表 | ✅ 部分做了 | `/api/alarms/coverage.rules.blocked` 已逐条给缺失指标名；跨面"规则族 × 注册表"对拍未做成新端点（避免再造一个报表页） |
| 外部端口存活 | ❌ 没做 | 属**新数据面**（要探端口 + 定义存活语义），与 §11.89 方案 C 的"不引入外部服务"边界相邻，必须 Owner 点头 |
| 日志异常聚合 | ❌ 没做 | 需新的日志读源与基线口径；先修"感知/CI 静默"这两个更贵的缺口 |

## 6. 验收与巡检

```powershell
# 三处一致 + 卡片数字
python scripts/handoff_snapshot.py
# 覆盖读数（两个静默缺口）
curl -H "Authorization: Bearer $env:FLASK_API_TOKEN" http://127.0.0.1:5678/api/alarms/coverage
# 感知状态（last_file_event_at / watcher_running / watch_dirs）
Get-Content data/learning/perception_status.json
# CI 状态新鲜度
Get-Item data/ci/status.json | Select-Object LastWriteTime
```

感知验收（每次改动 watch_dirs / 周期任务后做一次）：
1. 启动日志有 `[BodySensor] 正在初始化 FileWatcher，监听目录: …`；
2. 往监听目录建/改一个文件 ⇒ 5 分钟内 `data/learning/novelty_memory/novelty_memory.jsonl`
   出现 `event_type=file_change`（低置信 → 只写记忆，不产草稿）；
3. `coverage.perception.last_file_event_at` 跟着变新；
4. **无自激**：`data/learning/` 不在 `watch_dirs` 里，且长跑后 file_event 次数不随 tick 递增而暴涨。
