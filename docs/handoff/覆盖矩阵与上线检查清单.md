# 感知 / 监控覆盖矩阵 与 新功能上线检查清单

> 2026-11-12（第五十九～六十轮）。回答 Owner 两问：
> 「现在真的能做到全域感知、全域监控了吗？」「开发出新功能也能自动被感知和监控吗？」
>
> **结论（第六十轮收口后）**：
> 1. **监控面**：六个事件源 + 五层健康探针 + 单位看板（12 手写 + 5 声明 = 17）+ 拓扑 +
>    审计链都有真实读数；本轮又补了**外部端口存活**（TCP 探活，不引入 Prometheus）与
>    **日志异常聚合**（尾窗 ERROR 密度）。16 条告警规则仍只有 6 条可求值（10 条 blocked，
>    逐条原因在 `/api/alarms/coverage.rules.blocked`）；仍缺告警外发通道。
> 2. **感知面**：文件监听 → learning、周期快照 diff（贵/便宜分片分频）、CI 同步三条输入面都在跑；
>    快照 diff 的调度阻塞从 ~29s/30min 降到 ~1s/30min + ~4s/1h。仍不覆盖"新功能"本身。
> 3. **新功能自动化**：**拓扑**（`MODULE_STATUS_SOURCE`）与**单位看板**（`MODULE_UNITS`）
>    现在都是**声明式**；告警规则 / 事件源 / 传感器仍须手写。第 4 节是上线清单。

## 2. 两个「静默缺口」怎么读（从"无声"变"可见"）

`GET /api/alarms/coverage` 的两个块（页面：健康仪表盘 → 告警 Tab 顶部「监控覆盖」卡片）：

```text
ci:         {available, last_sync_at, age_seconds, stale(>2h), max_age_seconds, runs, detail}
perception: {available, watch_dirs[], watcher_running, last_tick_at, last_file_event_at,
             last_file_event_age_seconds, last_change_at, last_novelty_at,
             last_novelty_age_seconds, long_silent, detail}
```

口径：
- **读不到 = `available:false` + 说明**，不返回 0 岁（"刚刚同步过"是假的）；
- CI `stale:true` 表示采集层本轮按「不可用」处理（既不报警也不判恢复）；
- 感知 `long_silent`（>24h 无文件事件）只是**标注**，不是故障 —— 没人往监听目录写东西很正常；
- 页面上 `formatAge(null)` 显示「—」，不是「刚刚」（L5：没读到 ≠ 刚刚发生）。

## 4. 新功能上线检查清单

新功能 = 新包 / 新工具 / 新路由 / 新后台任务。上线前逐项对：

1. **拓扑声明**（声明式，必做）
   - 包 `__init__.py` 写 `MODULE_NAME` / `MODULE_DOMAIN` / `MODULE_STATUS_SOURCE`；
   - 判据：`/api/modules/topology` 出现该节点，`unregistered == 0`。
2. **单位看板**（声明式，推荐）
   - 同一处 `__init__.py` 写 `MODULE_UNITS = [{"id","label","family","probe":"模块:函数"}]`；
   - probe 是"调用时才 import"的字符串 ⇒ 启动期零副作用；返回体按单位形状
     （`{status, summary, metrics, issues, last_activity}`）；
   - 纪律：**只读、不建单例**（不得 `get_scheduler()/get_singleton()`，§11.93/§11.95 两次实证）；
     没有数据就返回 `never`（不计分），不要造 0；
   - 判据：`/api/system/units` 里出现该 id（数量哨兵在 `test_unit_monitor.py`）。
3. **告警规则 + 指标**（手写，必须成对）
   - `monitoring/alerts.yml` 加一条 PromQL 子集规则，**同时**确认它引用的指标真有写入点；
   - 指标族不存在 = `no_data`（不是 0 增量）；族存在但子集为空 = 0 增量 = ok；
   - 判据：`/api/alarms/rules` 里该条 `evaluable`。
4. **埋点**（手写）
   - "调用/失败/拦截"计数写在**真实执行点**（LLM 收口 `LLMMonitor.record()`、
     工具台账 `plugins/chat.py::_record_tool_usage`）；写钩子上多半收不到（§11.91 实证）。
5. **传感器 / 感知输入**（手写）
   - 新传感器：写类 + registry 注册；**还要有人周期 collect**（否则 enabled 也空转）；
   - **不打算被周期采集**的感知文件（屏幕 OCR 这类按需触发的）：在模块里声明
     `SENSOR_CONTRACT = "on_demand"` 并写明"谁按需调它" —— 否则覆盖缺口自检会把它记成缺口；
   - 新"外部输入面"：加进 `sensor.watch_dirs`（或 `SENSOR_WATCH_DIRS`），
     **不要**包含 `data/learning` 或仓库根。
6. **覆盖缺口自检**（自动，交付判据）
   - 上线后看 `GET /api/alarms/coverage.gaps`：你的新包/新工具/新传感器/新路由**不该**出现在
     `gaps` 里；单位 `ops.coverage_gaps` 应回到 ok（gap=0）。
   - 出现了 ⇒ 按该条的 `fix` 补一处（声明面优先：`MODULE_STATUS_SOURCE` / `MODULE_UNITS`）。

7. **文档与派生产物**（半自动）
   - 派生产物**干净 worktree 重派生**（capability_manifest / 盘点表 / tool_index / BM25 /
     路由基线 / route_ui_coverage / ui_reachability）；
   - 新 env 必须进 `agent/settings/registry.py`（`python scripts/scan_settings.py --check` 零缺口）；
   - 新增前端端点先写 `src/api/endpoints.ts`（React 侧 `/api` 字面量必须恰好 0）。

### 5.1 覆盖缺口自检（monitoring-gap-detector，2026-11-12）

回答"**新增了什么能力、它有没有被感知/监控/告警覆盖**"。判据（一条能力只要有任意一条
感知/监控/告警路径覆盖就不算缺口）：

```text
GET /api/alarms/coverage.gaps
{available, count, by_kind, gaps[{kind,id,why,fix}], truncated, degraded,
 generated_at, age_seconds, stale, interval_seconds, pushed, last_push, excluded[], surfaces{}}
```

| kind | 声明面 | 算缺口的情形 |
|---|---|---|
| package | `agent/<pkg>/__init__.py` 的 `MODULE_*` | 有元数据但**无状态源也无单位**；或状态源路径不在 `route_domains.json` 前缀里 |
| unit | `MODULE_UNIT(S)` | probe 的 `模块:函数` 静态解析不到（文件/函数不存在）；声明格式非法被忽略 |
| sensor | `sensor/*.py` 的 `*Sensor` 类 | 该模块里没有一个 `*Sensor` 带 `collect()`（自发现静默跳过）；声明 `SENSOR_CONTRACT="on_demand"` 的除外（按需驱动，见 §4.5） |
| scheduler | `def register_*scheduler` + 调度器活体任务 | 注册函数没有调用点；任务被停用 |
| route | `config/route_domains.json` 前缀 | 前缀在活体路由报告里一条都没命中（支持 `/*` 通配） |
| tool | `data/tool_index.json` | 索引条目在 `data/tool_definitions` 下没有同名 YAML |

口径：
- **只报不注册**：不自动加单位/规则/探针（会改健康分分母，且须 Owner 点头）；
- **不重复计数**：规则 blocked（10 条）仍在 `coverage.rules.blocked`；工具 YAML→索引由
  `sync_tool_index.py --check` 守门；路由 UI 标注由 `route_ui_coverage` 守门 —— 三条都在
  `gaps.excluded[]` 里写明理由；
- **读不到 ≠ 0 条**：任一检查抛异常 ⇒ `degraded:true`（清单不完整），单位看板同时 warn；
- 单位 `ops.coverage_gaps`：gap=0 ⇒ ok；>0 ⇒ warn（逐条 issue）；自检超过 3 个周期未跑 ⇒ warn；
- 外发：同一缺口只在**首次出现**时推一次（warning 级；不受 `CP_ALARM_NOTIFY_WARNING` 过滤，
  因为它按指纹去重、一辈子只走一次），推送成功才记指纹（没通道下一轮重试；缺口消失后
  指纹被修剪，再次出现会再推一次）。

**2026-11-12 首轮实测（未覆盖 2 条）→ 同日修正为 0 条**：

| 缺口 | 修正方式 | 为什么这样修 |
|---|---|---|
| `sensor/ocr_sensor.py` | 模块里声明 `SENSOR_CONTRACT = "on_demand"`（类仍是 `OcrSensor`，调用方不变） | 它的调用方都是**按需**触发（记录时截屏 / 问"屏幕上是什么"），补 `collect()` 只会让自发现每 60s 截一次屏（隐私+开销）。声明比"豁免清单"好：声明与类在同一份源码里，改类的人一定会看到 |
| `/api/voice` | 从 `config/route_domains.json` 与 `config/route_ui_intent.json` 删掉该前缀/标注，并在**干净 worktree** 重派生 `reports/route_ui_coverage.json` | 该组路由 2026-10-20 已删（triage 台账有记录），表里留着会让"功能区"指向不存在的东西 |

口径：`SENSOR_CONTRACT` 只认两个值 —— `periodic`（缺省，必须 `collect()`）/ `on_demand`（按需）；
写别的值会被判成缺口（"无法判定它是周期传感器还是按需引擎"），不会被静默放行。

感知验收（每次改动 watch_dirs / 周期任务后做一次）：
1. 启动日志有 `[BodySensor] 正在初始化 FileWatcher，监听目录: …`；
2. 往监听目录建/改一个文件 ⇒ 5 分钟内 `novelty_memory.jsonl` 出现 `event_type=file_change`
   （低置信 → 只写记忆，不产草稿）；
3. `coverage.perception.last_file_event_at` 跟着变新；
4. **无自激**：`data/learning/` 不在 `watch_dirs` 里，长跑后 file_event 次数不随 tick 递增暴涨；
5. **心跳不被拖慢**：`data/task_history.jsonl` 里「系统心跳」间隔中位数 ≈60s，
   感知任务只在 30 min/1h 边界出现 ~1s/4s 的耗时（不再是 25–29s）。
