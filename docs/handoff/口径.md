## 1. 部署

| 事项 | 口径 |
|---|---|
| 命令 | `python scripts/deploy_workbench.py --no-fetch --smoke`（**不要** `--no-build`：会让构建戳落后于 backend commit） |
| 前置 | **先停后端 python**（本机内存不够，先构建再停旧后端 = rolldown OOM） |
| 收尾 | 部署后核对 `/api/version` 的 commit **等于目标 master**（deploy 会自己 fetch，可能停在旧 HEAD）；三处（backend / frontend.build_commit / master）必须一致 |
| 假红 | deploy 自带 smoke 常报「/api/version 无响应」（冷启动 / 无 token）= 假红，带 `Authorization: Bearer $FLASK_API_TOKEN` 复测 |
| 令牌 | 只从 `.env` 读，**不打印**、不进命令、不进日志 |

## 3. 新增能力（工具 / 技能 / 路由）

1. **新增一个工具会同时动 5 处**（2026-11-05 实测连锁三轮才齐）：索引篇数、清单+盘点表、
   **BM25 半饱和点** `_BM25_HALF_SATURATION`（= calib 中位数的重标定）、路由基线产物、**路由冲突 v1 的 τ**。
2. **新增 env 读取点必须同时进 `agent/settings/registry.py`**，否则「开关零缺口」必红；判绿要在**干净 worktree**。
3. 工具 YAML 的治理字段用脚本补，不手写：`backfill_tool_planes.py`（plane/effect/risk/tags）、
   `backfill_tool_callability.py`（可调用性，`--check` 会对拍 permission_level）、
   `backfill_capability_spec.py`（location/location_reason）。三者的 `--check` 都要 0 退出。
4. 新工具默认写到 `enabled: false`（先停用观察），YAML 的 description/schema 必须与 `@_tools.register` **逐字一致**。
5. 新路由的异常返回：`jsonify(error=exc.message)`（**自定义属性**），不要 `str(exc)`；未知异常回固定文案 + 日志。

## 4. 安全与可观测（CodeQL 三条铁律）

1. **异常原文不进响应体**（`py/stack-trace-exposure`）：要么在**返回值产生处**就不放异常派生串
   （`f"{type(e).__name__}（详见服务日志）"`），要么已知领域异常走 `exc.message`。`str(exc)`/`f"{e}"` 必被判。
2. **真凭据不进日志**：原文 / 指纹 / 长度 / 布尔**全都不行**（`sha256(secret)` → weak-hash，`len/bool` → 明文日志）。
   唯一稳妥写法：日志表达式里根本不出现那个值。指纹只用于**非凭据**（路径、任务文本）。
3. **路径类**：CodeQL 只认三种断链 —— 列目录+名字等值匹配（`agent/safe_paths.enumerate_path`）、
   常量键→常量路径字典、sha256 摘要。正则、resolve+前缀、realpath+dirname **都不被认**。
4. **定位告警用 SARIF codeFlows，不靠猜**：`python scripts/audit/codeql_flows.py --sources-only`
   取最近一次分析的 SARIF（`gh api -H "Accept: application/sarif+json" .../analyses/<id>`；**默认 setup
   也能取**，无需切 advanced）并按 sink 列出**去重后的源**。共享 sink（`ok()`/`problem()`）的告警只要
   还剩一条源就还在 ⇒ 必须按 flow **起点**改 producer；改 sink 附近或猜 producer 都是白改（C-6 两轮教训）。

另外：新增路由/工具/设置项后跑 `python scripts/check_hardcoded_boundaries.py`，
调用参数里别塞数字字面量（模块级常量不算）。

## 5. 技能双轨

- `global-core-principles` / `skill` **只留主轨**，不要给它们建文件轨（`materialize` 会 409）。
- 入轨：`python scripts/intake_skill.py <id> --execute --fix-meta --fix-baselines`（失败自动回滚目录）。
- **基线默认不动**（2026-11-08）：界面/REST 入轨默认 `fix_baselines=false`（`DEFAULT_FIX_BASELINES`），
  基线是「干净 worktree 重派生」的哨兵，要改必须在界面勾「同时刷新基线」或 CLI 显式 `--fix-baselines`，
  否则等于绕过 review 挪哨兵（R-1 事故）。
- 巡检：`check_skills_dual_track.py`（0 孤儿）/ `validate_skill_md.py`（0 error 0 warning）/
  `audit/skill_layer_coverage.py`（步骤与触发均 100%）。三项都已进交接卡，不需要手抄。
- **「执行」只有带脚本的技能才是一个数（2026-11-09）**：技能台账 `stage=exec` 只由
  `SkillExecutor.execute`（子进程跑 `scripts/*.py`）写入；指令型技能**不存在执行这件事** ⇒
  界面/看板显示「不适用」（`—`），不写 0（L5）。判据叶子 `file_store.skill_ids_with_scripts()`。
- **「加载」按来源分列（2026-11-09）**：`stage=load` 的 `source` = `semantic`/`inject` 才是
  「模型取用」，`ui`（人点开技能详情）单列，历史 `loader` 记作**未分源**、不并进注入。
  改任一写入点必须同批改 `usage_log.stats` 与本条。
- **L1 装配灰度（C-8）**：`CP_SKILL_LAYER_MODE=full|l1`（默认 full）+ `CP_SKILL_LAYER_L1_IDS`
  （逗号分隔；默认 pdf / gh-cli / code-refactor / engineering-test-delivery / handoff）。只对名单内
  技能把上下文注入的「使用说明」由 L2 全文换成 L1 能力卡（L1 不含示例，实测省 51.7%）；
  缺卡 / 目录缺失 / 开关拼错一律回落 L2（灰度坏一条只赔 token，不赔能力）。
  **回滚 = MODE 改回 full**（或清空白名单）：L2 全文随时 `GET /api/skills-mgmt/<id>/card?layer=L2` 取回。

## 6. 推理模型与 LLM 调用

- 需要**正文**的调用必须关 thinking：`thinking: {"type": "disabled"}` + 预算 8000 + 超时 180s
  （`deepseek-flash` 的 reasoning 会吃掉全部预算，content 为空）。
- 给 `LLMService.chat` 加参数要同步三处：`_do_chat`、监控钩子 `llm_monitor._patched_do_chat`（按需透传）、
  `_fallback_after_failure` 的 lambda。漏一处 = shard5/6 红。

## 7. 「到 X% 就做事」类判断

必须自己记住**上次做过时的水位**（压缩/告警/提示都一样）。云枢压缩只写摘要、不删消息 ⇒ 水位不降，
不记水位就会每条消息做一次（`_last_compaction_watermark` 就是这么来的）。

- **界面占用率与压缩触发同源**（2026-11-09）：分子 = 本会话最近 `COMPRESS_TRIGGER_WINDOW`(200) 条正文 token，
  工具结果不计入；会话「收+发」累计另给 `session_total_tokens`。改任一侧必须同批改另一侧 + 用例。

## 8. 运行期状态与台账

- `data/` 下大量文件是**运行期状态**（gitignored）：`descriptors.json`、`skills_mgmt.json`、
  `tool_definitions/custom`、`logs/*.db`…。**没有版本可回**，写坏只能靠「快照 + 生产写路径」重建。
- 判绿先看**运行时口径**（`/api/version`、`DescriptorRegistry.load()` 的 loaded/invalid、`/api/tools/config`），
  再看脚本报的覆盖率 —— 覆盖 ≠ 可用。
- `data/feedback/feedback.db`（反馈中心「开发随记」）是**有意**的 tracked 改动：不要 checkout、不要提交。
- `data/handoff_state.json` 由 `handoff_snapshot.py` 自己写（跑一次就会 dirty），属正常。

## 9. CI 判读

- **覆盖率 Shard 3 常慢/挂**：`gh api .../jobs/<id>` 看 steps 全 completed（或等它自己绿）再 merge；别按「代码坏了」处理。
- 「失败基线回归」等 job 走 skipping 是正常的。
- 合并后 code scanning 要等 master 上对应语言的**分析完成**（python 比 actions/js 晚几分钟）才更新，别拿 PR 绿当告警已关。

## 11. 2026-11-06 新增

- **多种 embedding / 多个后端 = 一个 enum 单选**，不要做成三个布尔：维度与语义空间不同，同时开会把分数混排序。
  选项说明写 `Validator.choice_notes`（UI 按当前值显示），设置中心自动渲染成单选下拉。
- **弹窗/面板组件别放 `src/pages/**`**：`reports/ui_reachability.json` 按页面文件集派生，多一个 .tsx 就漂移（CI 红）。
  组件放 `src/components/`（口径同 TransformQueueDialog）。
- **跨模块共用的口径函数下沉到叶子模块**（如 `transform/compare.facet_body`）：放任任一调用方都会形成循环依赖，
  arch_rules 判高严重度；本地可先跑 `python scripts/ci_run_module.py agent.observability.arch_rules --check ...`。
- **提交一律按路径**：`git commit -- <paths>`（或 `git commit -F msg -- <paths>`）。本机 index 里
  经常有运行时/别人预暂存的文件（`data/skills_repo/<新技能>/` 两次被裸 commit 带进来），裸 `git commit` 会一起扫走。
- **调用参数里的数字字面量会被判硬编码**（`batch_size=8` / `timeout=60`）⇒ 提成模块常量；
  本地自检：`python scripts/check_hardcoded_boundaries.py --target agent/ --json --output x.json` 看 `details` 里自己那几个文件。
