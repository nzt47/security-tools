## 7. 增订二（2026-10-10 后续）：镜内全离线 E2E 实测 —— 3 个真缺陷已修

> 起因：执行 §6.1 caveat 1（"全离线"此前只做到接线）。结论：**机制可跑，但容器档有 3 个真缺陷**；
> 修复后经容器后端（`ContainerChannelExecutor` + `run_channel`）真跑，产出
> `status=done / channel_meta.llm_used=true`，退出码 0。

- **构建成本（未变）**：canonical `docker/subagent-peer/Dockerfile.local` 需在构建期下 ollama 二进制
  **1.44GB**（实测 GitHub release 资产 ~33 kB/s ⇒ ~12h）+ 模型 397MB，故本轮改用"本机已有 ollama+模型"
  组装**同运行时契约**的镜像做实测；Dockerfile.local 仍不入 CI。
- **缺陷 1（entrypoint）**：`entrypoint.local.sh` 把 ollama 日志写 `/tmp/ollama.log`，而容器档是
  `--read-only` + 仅 tmpfs `/work`（实测 `/tmp` 报 EROFS）⇒ `ollama serve` 起不来、对端必然非零退出。
  改为落可写 `$HOME`（镜像里 = `/work`），不可写再退 `/dev/null`。
- **缺陷 2（编码）**：`container_backend.py` 与 `channel.py` 的 `subprocess.run(text=True)` 未指定
  `encoding`，Windows(GBK) 下读取容器 UTF-8 输出会在读取线程抛 `UnicodeDecodeError`、stdout 变空，
  假报 `E_UPSTREAM_FORMAT/empty`。已按 `sandbox.py` 既有约定补 `encoding="utf-8", errors="replace"`。
- **缺陷 3（配额）**：`ContainerSpec.run_prefix()` 用裸 `IsolationQuota()`，只取类默认值 256MiB，
  完全忽略 `CP_DIGESTION_ISOLATION_MEMORY_MB`（该变量只有 `from_env()` 读）。0.5B 模型在 256MiB
  cgroup 下被 OOM kill（`llama-server ... signal: killed`）；改走 `IsolationQuota.from_env()` 后
  以 `CP_DIGESTION_ISOLATION_MEMORY_MB=1024` 真跑通过。
- **可复算入口（新增 gated 测试）**：`CP_SUBAGENT_OFFLINE_E2E=1` + 已构建带模型镜像 +
  `CP_DIGESTION_ISOLATION_MEMORY_MB=1024`
  `python -m pytest tests/unit/test_subagent_peer_entrypoint.py -q`。
- **仍未做**：canonical 镜像在 CI/目标机的真构建（下载成本）；caveat 2/3（cognitive_loop 跨 workspace、环境清理）不变。
