# 工作台「怎么打开」的口径（2026-11-04）

> 结论先行：**不用内置无头浏览器打开本机工作台**。它省不了资源，而且会退化交互。
> 右坞「可交互浏览器」继续只服务**外部站点取证/演示**，不用于日常使用工作台。

## 1. 为什么不能用内置无头浏览器打开工作台

内置浏览器有两条实现，都是**服务端**跑的：

| 实现 | 引擎 | 用途 |
|---|---|---|
| agent/tools/browser_tools.py | Selenium + Chrome --headless=new | 一次性抓取：导航 + 整页截图 + 关闭 |
| agent/browser_remote.py | Playwright Chromium headless=True | 右坞「可交互浏览器」：截图流 + 坐标/键盘输入 |

把 http://127.0.0.1:5678 交给它们，会撞上三件事：

1. **SSRF 守卫默认拒绝环回**（实测）：check_url('http://127.0.0.1:5678/') 返回
   allowed=False，理由「目标 IP 127.0.0.1 属禁止网段（环回）」。要放行必须显式配
   CP_BROWSER_REMOTE_ALLOW_HOSTS=127.0.0.1 —— 这等于给「人点着看」的界面开一个本机可达面
   （5678 工作台、9093 Alertmanager、Prometheus…）。
2. **它不是窗口**：右坞是 1280×800 的截图流，输入只接受「坐标 / 文本 / 白名单按键 / 滚动 / 导航」
   （browser_remote.ALLOWED_KINDS），**不暴露 evaluate**；单会话、空闲 10 分钟自动关闭。
3. **资源不省反升**：无头 Chromium 仍是完整引擎（browser + renderer 约 150–350 MB/页面），
   再加 Playwright driver 与每步截图的编码/传输；而本机 RAM 14.9 GB、空闲仅约 5.8 GB，
   历史上构建期 rolldown 就因内存不足 OOM 过（§8 陷阱 / §11.40 K）。把 Chromium 塞进后端是**加重** OOM 风险。

## 2. 交互上会丢什么（为什么「能跑」不等于「能用」）

文本选择与复制粘贴、文件选择/上传/下载、拖拽、右键菜单、Ctrl+F / 开发者工具 / 缩放、
中文输入法组合键、无障碍树、多标签；再加上截图 round-trip 带来的滚动/动画卡顿。

## 3. 推荐做法（按代价从低到高）

1. **已有的浏览器 + 应用窗口**：msedge --app=http://127.0.0.1:5678/?token=…（无地址栏、
   独立任务栏图标、复用同一浏览器进程与缓存，通常只多 100–200 MB）；
2. **仓库自带 Electron 壳**（yunshu-ui/electron/main.ts，npm run dev:electron / 打包产物）：
   量级相当，能把入口 URL 与 token 注入固定下来；
3. **自动化 / CI / 截图回归**：继续用无头（Selenium / Playwright）—— 这是它们的主场。

## 4. 什么情况下才值得默认无头

无人值守、CI、被远程调用、批量截图对比。桌面日常使用**不在此列**。
