# 鉴权迁移（RFC）—— 从"未配令牌即放行"到 fail-closed

> 归属：**TASK-06**（身份体系与工具侧 L0–L3 确认分级）§3 第 5 步第 2 项 / 交付物 #11
> 状态：**第 ① 步已落地**（告警 + 健康面暴露），②③ 待做，④ 留给下一个发布周期
> 原则：**分步、每步可回退、不做破坏性变更**（TASK-03 标准 / TASK-06 E12）

---

## 1. 问题（已核实的现状）

| 项 | 现状 | 证据 |
|---|---|---|
| 发证 | 唯一一把共享令牌 `FLASK_API_TOKEN` | `agent/server_auth.py:47-48,88` |
| 可选映射 | `CP_UI_TOKENS`（每使用者映射表） | `server_auth.py:90-95`、`agent/security/identity.py` |
| **本部署实际状态** | **`.env` 未设 `CP_UI_TOKENS`** ⇒ 只有一把共享令牌，**无用户区分** | 审计实测 |
| TTL / 轮换 / 吊销 | 全部没有（只有 `secrets.compare_digest` 比对） | `server_auth.py:88` |
| **未配置令牌时** | **直接放行不校验**（fail-**open**） | `server_auth.py:96-98`（`SRC_NO_TOKEN_CONFIGURED`） |
| 鉴权方式 | **逐个装饰器**（`@require_token`），非默认拒绝 | `routes_approval.py` 等 |
| 无令牌的状态变更端点（实证） | `POST /api/assets/restore`、`POST/DELETE /api/assets/<c>`、`POST /api/replay/upload`、`POST /api/replay/cleanup`、`POST /api/llm-monitor/clear`、`POST /api/feedback/submit`、`GET /api/audit/logs` | `routes_assets.py`、`routes_replay.py`、`routes_llm_monitor.py`、`routes_feedback.py`、`plugins/admin.py:779-781` |

**为什么不能直接改成 fail-closed**：本机 UI 与全部脚本**都没有带令牌**（`.env` 未配）。
一次性改成"未配令牌即拒绝"会当场 401 掉本机所有调用 —— 那是 E12 明确要避免的
"迁移不停机"。故按下面四步走。

## 2. 四步迁移路径（每步都可单独回退）

| 步 | 动作 | 开关 / 回退 | 状态 |
|---|---|---|---|
| ① | 启动时检测令牌未配置 ⇒ **明确告警**（不阻断）+ `/api/health` 暴露 `auth` 状态 | 无开关（只读暴露，不改判定）；回退 = 不改 | **✅ 已落地（本任务）** |
| ② | 提供 `scripts/gen_api_token.py` 一键生成强随机令牌并写 `.env` | 脚本本身无副作用（不改 `.env` 除非显式 `--write`） | **⏳ 未做**（见 §3） |
| ③ | 文档更新：本机 UI / 脚本如何带令牌（`Authorization: Bearer` 或 `X-API-Token`） | 无 | **⏳ 未做**（本文档是起点） |
| ④ | **下一个发布周期**改为 fail-closed（未配令牌 ⇒ 拒绝），并提供 `CP_AUTH_FAIL_OPEN=1` 的显式逃生阀 | 逃生阀即为回退路径 | **⏳ 未做（刻意的）** |

> **④ 为什么现在不做**：TASK-06 的完成判据与 E12 都要求"不一次性打挂本机调用"。
> 先让 ①②③ 在真实部署里跑一个周期，观察 `/api/health` 是否长期显示
> `unconfigured`，再收口。**这是排期决定，不是遗漏** —— 报告里如实标注。

## 3. 第 ① 步的落地内容（本任务实际交付）

1. `app_server.py` 启动链路在 `.env` 加载完成后检查 `FLASK_API_TOKEN` / `CP_UI_TOKENS`：
   - 两者皆空 ⇒ **WARNING 级告警**（写明"当前所有端点不做令牌校验"与补救动作），
     **不阻断启动**（D4）。
2. `/api/health`（`agent/server_routes/routes_panorama.py`）返回一个 `auth` 字段：

   ```json
   {"auth": {"configured": false, "source": "no_token_configured",
             "shared_token": false, "token_map": false,
             "require_authoritative": false,
             "note": "未配置令牌 ⇒ 端点不校验（fail-open，见 docs/rfc/鉴权迁移.md）"}}
   ```

   - **只读暴露**：不参与任何判定，因此不改行为、不需要迁移。
   - 判据复用 `agent/server_auth.py::authorize_token` 的同一套常量
     （`SRC_NO_TOKEN_CONFIGURED` / `SRC_SHARED_TOKEN`），**不新建第二份口径**（D1）。

## 6. Webhook 场景（TASK-06 §3 第 3 步第 3 项要求核查）

**实测：本仓不存在任何 webhook 端点。**

```
git grep -n 'route([^)]*webhook' -- agent/ plugins/ app_server.py   → 0 命中
```

⇒ 按任务书要求**明确标注为"无此场景，接口预留"**，不凭空实现：

- `agent/tool_gate.py::NON_INTERACTIVE_SOURCES` 已含 `"webhook"` ⇒ 一旦接入，
  该来源的调用会自动走"非交互 ⇒ 拒绝且不挂单"的正确分支；
- `agent/security/actor_matrix.py::ACTOR_TYPE_ALIASES` 已把 `webhook` 映射到
  `service_account`，`_SERVICE_ACCOUNT_NAME_PREFIXES` 也含 `webhook:` ⇒
  该场景的身份可被如实推断；
- v1.4 §10.1 铁律（"Webhook 验签后**换发短效内部 token**"）是**接入时**的实现要求，
  已记在此处作为接口预留的验收点。
