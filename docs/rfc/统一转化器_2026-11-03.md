# 统一转化器（Capability Synthesizer）—— 设计草案 2026-11-03

> 状态：S1 已落地（作业台账 + 三个钩子）；S2–S5 待做。本文是**口径**，实现跟进时先读这里。

## 0. 目标（用户原话转写）

> 做一个转化器，把外来的技能 / 工具 / 插件 / 经验想法，经过**去重、合并、优化、合规安全审核**，
> 转化成云枢自身的能力（技能 / 工具 / 工作流 / 规则）。新入能力要与原有能力对比，**只提取不重复的部分**。
> 取外来的内涵、重写成自身的能力；**原件读完即弃**，只留一条记录。技能加载要**分层按需**逐渐加载。

## 1. 为什么现在要收（现状问题）

三套入口各写一套状态与「下一步」：

| 入口 | 产物 | 现在的断点 |
|---|---|---|
| 能力获取 → 草稿评审 | `data/ingestion/drafts/<id>/` | 登记为工具后只有一句 toast；行状态不变；按钮还在（再点 409）；无回滚 |
| 技能中心 → 转化队列 | `data/ingestion/transforms/<tid>/` | 有回滚与 LLM 重写，但与另外两套不共享状态 |
| 技能中心 → 入轨助手 | `data/skills_repo/<id>/` + PR | 只出 PR，不追踪「已登记/已启用」 |

## 2. 统一模型（S1，已实现）

一条**作业（job）**一个稳定 id：`<source>:<source_ref>`，落在 `data/transforms/jobs.json`。

```
candidate → normalized → reviewed → registered → enabled
旁路终态：archived / failed（failed 可回 candidate 重试）
```

- 只存**元数据**：来源、形态（skill/tool/workflow/rule）、标题、产物目录、目标（kind+id）、状态流转历史；
- **不存外来正文**（与「读完即弃」一致）；
- 三个来源适配器只负责「造作业 + 推进状态」，判定逻辑不动（ingestion / transform / intake 各自保留）；
- 台账坏了按空台账处理：**不许让摄取/登记失败**（best-effort 钩子）。

排序用 `(updated_at, rev)`：Windows 的 `datetime.now()` 只有 ~15ms 粒度，连续写入会拿到相同时间戳（已实测）。

## 4. 「读完即弃」的存储口径（待拍板）

- 保留：`sha256` 指纹、来源元数据（路径/URL/时间）、抽取要点、重写时的**逐字引用**（P5 已有严格引用校验）；
- 不保留：外来原文正文（`archive` 里的 `raw.md`、draft 的 material 副本）；
- 回滚语义随之改变：只能回到**我们自己能力的旧版本**，回不到外来原文；
- 待定：是否允许「人工确认后 7 天隔离副本」（查纠纷用）。
