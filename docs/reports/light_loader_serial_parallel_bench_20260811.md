# light_loader 串行 vs 并行性能基准报告（规模-耗时曲线）

- 生成时间：2026-08-11
- 规模点：1000 / 2000 / 4000 / 6000 / 8000 / 10000 卡
- 每模式扫描 3 次取中位数（不包含库构造耗时）
- 损坏率：10%（每 10 张 1 张损坏，模拟真实库）
- 环境：Python 3.12.0，win32
- 解析器：libyaml C 扩展（CSafeLoader）优先，无则回退 SafeLoader

## 二、趋势分析

1. **线性增长**：规模 1000 → 10000 卡，串行耗时 206.39ms → 2022.38ms（放大 9.8 倍，卡片数放大 10 倍），每卡串行成本 0.2022ms，符合逐文件读盘 + 解析的线性模型。
2. **并行收益有限**：最大规模 10000 卡下并行 1965.90ms，提速 1.03x。线程池只对 IO 等待生效；文件 read 已被系统页缓存覆盖，解析为 CPU 密集（受 GIL 约束），故收益随规模增长趋缓。
3. **保序契约不受影响**：并行结果与串行完全一致（ex.map 按提交顺序收集），数千损坏卡并存场景由 nightly 压力测试（stress_light_loader_parallel.py）守护。

## 三、结论

10000 卡规模下单次全量扫描约 1.5~2s（串行/并行差异 <10%）。对审计场景（每次变更扫描一次），串行即可满足；并行可在多核 + 冷缓存 IO 场景下获得小幅收益，代价为零（保序契约不变）。优化重心仍是单次解析成本（libyaml C 扩展，约 7.6x 提速），而非线程并发。
