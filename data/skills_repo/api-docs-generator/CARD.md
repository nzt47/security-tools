## 何时使用

- 当被要求文档化 API、生成 API 文档、创建 API 文档、为端点或路由制作文档时使用。

## 步骤

- 第一步发现：扫描项目结构以识别 API 端点/路由。
- 检测项目使用的框架，如 Express、FastAPI、Flask、Next.js、Django、Spring 等。
- 定位路由定义、控制器与处理器。
- 识别输入校验 schema 与模型。
- 第二步提取：对每个端点提取 HTTP 方法与路径（REST API）。
- 提取输入参数：路径参数、查询参数、请求体、请求头。
- 提取响应格式：状态码与响应体结构。
- 提取认证/授权要求。
- 提取所应用的中间件或守卫。
- 提取内联注释或文档字符串（JSDoc、Sphinx 等）。
- 提取函数签名上的类型注解。
- 支持 Markdown 格式输出。
- 支持自定义格式，适配用户指定的模板。
- 第四步输出：写入项目根目录或 docs/ 目录下的文件。
- 若已存在 API 文档则更新它。
- 若已存在 OpenAPI 规范，则合并变更而非覆盖。
- 生成文档时可考虑为快速参考生成 README 的 API 章节。
- 可创建 docs/api/ 目录，每个资源组一个文件。
- 对 OpenAPI 可包含 servers 章节，列出 dev/staging/prod 的 URL。
- 标注已弃用的端点及建议的替代方案。
