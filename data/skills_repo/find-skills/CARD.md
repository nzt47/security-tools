# find-skills

> LLM 整理，逐条经**原文引用校验**：verified 29 / 29（未通过的已丢弃）。

## 何时使用

- 用户询问“如何做X”且X可能是已有技能的常见任务时使用。
- 用户说“找一个X的技能”或“有没有X的技能”时使用。
- 用户问“你能做X吗”且X是专门能力时使用。
- 用户表达想扩展代理能力时使用。
- 用户想搜索工具、模板或工作流时使用。
- 用户提到希望在特定领域（设计、测试、部署等）获得帮助时使用。

## 步骤

- 第一步：识别用户需求的领域、具体任务，以及该任务是否常见到可能已有技能。
- 第二步：在运行 CLI 搜索前，先查看 skills.sh 排行榜，看该领域是否已有知名技能。
- 第三步：若排行榜未覆盖需求，运行 find 命令搜索技能。
- 第四步：推荐前必须验证质量，不能仅凭搜索结果推荐。
- 第五步：向用户展示技能名称与用途、安装量与来源、安装命令及 skills.sh 链接。
- 第六步：用户同意后，可代为安装技能。
- 若未找到相关技能，应告知未找到，提出直接用通用能力帮忙，并建议用户自行创建技能。

## 参数

- find 命令用于交互式或按关键词搜索技能。
- add 命令用于从 GitHub 或其他来源安装技能。
- check 命令用于检查技能更新。
- update 命令用于更新所有已安装技能。
- 安装时 -g 表示全局（用户级）安装，-y 表示跳过确认提示。

## 约束 / 反例

- 优先选择安装量 1K+ 的技能，对低于 100 的要谨慎。
- 官方来源比未知作者更可信。
- 应检查源仓库，星数少于 100 的技能需持怀疑态度。
- 搜索时使用具体关键词效果更好。
- 若某个词搜不到，可尝试替代词。

## 示例

- 搜索技能的命令示例。
- 用户问如何让 React 应用更快时，搜索 react performance。
- 用户问能否帮忙做 PR 审查时，搜索 pr review。
- 用户需要创建变更日志时，搜索 changelog。
- 向用户展示找到的技能时的回复示例。
- 未找到技能时的回复示例。
