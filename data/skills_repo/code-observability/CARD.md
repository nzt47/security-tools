# code-observability

> LLM 整理，逐条经**原文引用校验**：verified 10 / 10（未通过的已丢弃）。

## 何时使用

- 生成核心业务逻辑模块代码时使用
- 生成后端 API 接口时使用
- 涉及网络请求、数据校验等可能失败分支的代码时使用
- 涉及关键用户交互点（提交、筛选、支付等）的代码时使用

## 步骤

- 所有核心业务逻辑节点必须输出 JSON 格式的 console.log，且必须包含 trace_id、module_name、action、duration_ms 字段
- 对可能失败的分支必须抛出带明确业务错误码的 Error，而不是静默返回 null
- 在关键用户交互点预留 trackEvent 函数调用占位符
- 生成后端 API 时必须附带 /health 或 /status 接口，返回依赖的数据库/缓存连接状态
