# subagent-driven-development

> LLM 整理，逐条经**原文引用校验**：verified 22 / 25（未通过的已丢弃）。

## 何时使用

- 在当前会话中执行包含独立任务的实施计划时使用
- 触发条件为 subagent、driven、development

## 步骤

- 在同一会话中执行，不切换上下文
- 每个任务使用全新的子代理，避免上下文污染
- 每个任务后做两阶段审查：先查规格符合性，再查代码质量
- 任务之间无需人工介入，迭代更快
- 派发实现者子代理
- 派发规格符合性审查子代理
- 派发代码质量审查子代理

## 参数

- 只涉及 1-2 个文件且有完整规格时，使用低成本模型
- 涉及多个文件且有集成顾虑时，使用标准模型
- 需要设计判断或广泛理解代码库时，使用最强模型

## 约束 / 反例

- 若是上下文问题，补充更多上下文并用同一模型重新派发
- 若任务需要更多推理，改用更强模型重新派发
- 若任务过大，拆分为更小的部分
- 若计划本身有误，升级给人类处理

## 示例

- 示例：子代理自然遵循 TDD
- 示例：每个任务使用全新上下文，避免混淆
- 示例：子代理之间互不干扰，可并行安全执行
- 示例：子代理可在工作前和工作期间提问
- 示例：同一会话内进行，无需交接
- 示例：持续进展，无需等待
