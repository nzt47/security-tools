## 何时使用

- 当被要求改进提示、优化系统提示、重写代理提示、调整提示措辞、提高提示可靠性、在 OpenAI/Claude/Gemini 之间移植提示或构建提示评测时使用。

## 步骤

- 若缺少成功标准或示例，先创建一个小型评测集。
- 若瓶颈在模型选择、检索、工具 schema 或缺少评测，应在改写前先说明。
- 对仓库或代理提示，按精确路径列出稳定上下文，如代理规则、规格、策略与示例文件。
- 选择模型策略：已知模型族则针对该族优化；未知则写可移植基础加简短适配说明；快照变化则重跑评测；跨族分歧只特化失败层。
- 塑造提示：稳定策略放 system 或 developer，任务局部事实、检索上下文与变量放面向用户的部分。
- 每条行为规则只保留一个负责人。
- 标题或标签只用于分隔内容类型。
- 工具策略写在提示文本中，schema 保留在提供商原生工具里。
- 除非能改变行为，否则保持轻量人设。
- 使用能保留约束的最短措辞。
- 删除填充内容、重复提醒、失效示例以及不影响评测的说理。
- 优化流程：在同一评测切片上建立基线，按根因聚类失败，写出具体编辑批评。
- 生成两到四个候选：最小差异修复、结构优先重写、示例优先或工具规则变体、必要时提供商适配。
- 在同一批用例上比较候选，保留简短优化日志，并在留出用例上验证胜出者。
- 返回包包含目标、成功标准、外部上下文、优化后提示、适配说明、评测集、优化日志与残余风险。
- 对已有提示，附上主要行为变化的简洁差异式说明。

## 约束 / 反例

- 用仓库相对路径引用稳定文件，而不是复制它们。
- 只粘贴提示或评测用例所需的片段。
- 标记文件是已加载、被引用还是超出范围。
- 避免“读文档”这类含糊的上下文指引。
- 在平台期、震荡、过拟合、成本过高或非提示瓶颈时停止。
- 失败模式：未定义评测目标就编辑。
- 失败模式：混合策略、示例与原始上下文而无边界。
- 失败模式：跨层重复规则。
- 失败模式：把持久策略放进用户载荷。
- 失败模式：要求思维链。
- 失败模式：保留相互矛盾的遗留指令。
- 失败模式：过拟合到一两个示例。
- 失败模式：保留不再提升评测的示例。
- 失败模式：工具描述或 schema 薄弱时只在提示文本里修工具使用失败。
- 失败模式：添加不减少歧义的标记。
- 失败模式：用人设替代行为规则。
