# verification-before-completion

> LLM 整理，逐条经**原文引用校验**：verified 34 / 34（未通过的已丢弃）。

## 何时使用

- 在准备宣称工作已完成、已修复或已通过之前，以及在提交代码或创建 PR 之前使用。
- 要求在做任何成功断言之前先运行验证命令并确认输出；永远先有证据再断言。
- 触发条件包括 verification、before、completion。

## 步骤

- 第一步：确定哪条命令能证明该断言。
- 第二步：执行完整命令，要求是新鲜、完整的运行。
- 第三步：阅读完整输出，检查退出码，统计失败数。
- 第四步：判断输出是否证实该断言。
- 若否：带证据陈述实际状态。
- 若是：带证据陈述断言。
- 只有到这时才做出断言。

## 约束 / 反例

- 禁止使用“应该”“大概”“似乎”这类措辞。
- 禁止在验证之前表达满意（如“太好了！”“完美！”“完成！”等）。
- 禁止未经验证就提交、推送或创建 PR。
- 不要轻信代理的成功报告。
- 不要依赖部分验证。
- 不要抱有“就这一次”的想法。
- 不要因为疲惫、想尽快结束工作而跳过验证。
- 任何暗示成功却未运行验证的措辞都不允许。
- 当人类伙伴说“我不信你”时，说明信任已破裂。
- 未定义函数被发布出去会导致崩溃。
- 缺失需求被发布出去会导致功能不完整。
- 虚假完成会浪费时间，导致返工重做。
- 这违反“诚实是核心价值，若你撒谎就会被替换”。
- 适用于任何形式的成功/完成断言。
- 适用于任何满意表达。
- 适用于任何关于工作状态的正面陈述。
- 适用于提交、创建 PR、任务完成等场景。
- 适用于进入下一个任务之前。
- 适用于委派给代理时。
- 覆盖精确措辞。
- 覆盖改写和同义词。
- 覆盖暗示成功的含义。
- 覆盖任何暗示完成/正确的沟通。
