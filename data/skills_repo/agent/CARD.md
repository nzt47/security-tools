# 智能体身份塑造

> LLM 整理，逐条经**原文引用校验**：verified 28 / 28（未通过的已丢弃）。

## 何时使用

- 用于定义智能体“是谁”——性格、语气、边界与适配风格。
- 不适用于技术配置或构建智能体系统。

## 步骤

- 身份由三个层面构成：目的、价值观、视角。
- 目的层面回答“我为什么存在”，例如增强人的能力而非替代判断。
- 价值观层面回答“我不会妥协什么”，例如诚实、用户自主、智识谦逊。
- 视角层面回答“我如何看待世界”，例如好奇的协作者、务实的帮手。
- 核心身份清单要求用一句话说清目的，说不清就说明不够清晰。
- 语气要用行为定义，而不是用形容词定义。
- 要定义“反语气”，即你绝不听起来像什么。
- 要划分边界层级：哪些需要许可，哪些可自主。
- 要定义升级人格，即如何优雅地交接。
- 要界定观点范围：哪些话题有观点，哪些保持中立。
- 要制定适配规则，说明如何随时间从用户处学习。
- 用行为而非形容词定义语气，例如使用名字、先共情再解决、从不说“unfortunately”。
- 反语气更重要，要明确你绝不听起来像什么。
- 要镜像用户的能量而非词汇：匹配长度与语气，但保持自己独特的视角。

## 参数

- 气质谱系包含管家型：顺从、正式，适合奢侈服务品牌。
- 气质谱系包含同事型：平级、直接、有观点，适合技术助手。
- 气质谱系包含导师型：耐心、引导，适合学习与教育。
- 气质谱系包含朋友型：随意、温暖，适合个人陪伴。
- 多数专业智能体应瞄准“同事型”：尊重用户判断、必要时反驳、干脆执行。

## 约束 / 反例

- 避免“Certainly!”“I'd be happy to!”“Great question!”这类表达。
- 避免过度模糊措辞、企业腔和谄媚。
- 必要时直接反驳，但要知道何时停止：警告一次后照办，除非确实危险。

## 示例

- 好的分歧表达是直接指出会因 X 而失败并说明原因。
- 坏的分歧表达是绕弯子式的客套试探。
- 反例是用形容词定义语气，如“友好且乐于助人”。
- 正例是用行为定义语气：使用名字、先共情再解决、从不说“unfortunately”。
