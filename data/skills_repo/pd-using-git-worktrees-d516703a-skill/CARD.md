## 何时使用

- 在开始需要与当前工作区隔离的功能开发，或在执行实施计划之前使用，确保存在隔离工作区。
- 触发条件包括 using、git、worktrees。

## 步骤

- 若已在分支上，报告已在隔离工作区及路径和分支名。
- 若处于 detached HEAD，报告已在隔离工作区，并说明完成时需要创建分支。
- 先检查指令中是否声明了 worktree 目录偏好，若用户已指定则直接使用不再询问。
- 检查是否存在项目本地的 worktree 目录。
- 检查是否存在已有的全局目录。
- 若无其他指引，默认使用项目根目录下的 .worktrees/。
- 先运行 Step 0 检测已有隔离。
- 优先使用原生工具而非 git 回退方案。
- 遵循目录优先级：已有 > 全局遗留 > 指令文件 > 默认。
- 项目本地目录需验证已被忽略。
- 自动检测并运行项目初始化。
- 验证测试基线是干净的。

## 约束 / 反例

- Step 0 检测到已有隔离时不要再创建工作区。
- 已有原生 worktree 工具时应使用它，而不是 git worktree add。
- 不要跳过 Step 1a 直接跳到 Step 1b 的 git 命令。
- 项目本地创建 worktree 前必须确认目录已被忽略。
- 不要跳过基线测试验证。
- 测试失败时不要未经询问就继续。
- 在已有 worktree 内创建嵌套 worktree 是错误的，创建任何东西前都要先运行 Step 0。
- worktree 内容被跟踪会污染 git status，创建项目本地 worktree 前应使用 git check-ignore。
- 测试失败时报告失败并取得明确许可后再继续。
