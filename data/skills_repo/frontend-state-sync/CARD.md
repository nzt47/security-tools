## 何时使用

- 生成列表加载、搜索联想、多 Tab 切换、表单提交等涉及异步请求的前端代码时使用。
- 采用乐观更新（Optimistic UI）的交互场景。
- 输入框触发搜索/过滤的高频交互场景。
- 生成 WebSocket 实时通信相关代码时使用。
- React/Vue 框架下的状态管理与副作用处理。

## 步骤

- 列表加载、搜索联想、多 Tab 切换等代码必须内置请求序号或版本号校验，只有返回 ID 等于当前最新请求 ID 时才更新 UI。
- 在 React/Vue 中生成异步请求代码时默认使用 AbortController，在组件卸载、依赖项变更或用户连续触发时取消前一个未完成请求。
- 采用乐观更新时必须显式实现 try/catch，并在 catch 块中利用闭包缓存的旧状态精准回滚，同时提供友好错误提示。
- 写操作成功后，若业务允许，优先通过重新拉取或后端推送的权威数据刷新本地状态，而非仅依赖前端数组本地增删。
- 生成输入框触发搜索/过滤的代码时，默认集成 debounce 或 throttle 逻辑。
- 生成 WebSocket 代码时必须包含断线指数退避重连、心跳检测以及重连后的全量快照补齐逻辑。
- Vue 环境中，在数据变更后读取 DOM 或执行依赖 DOM 尺寸的逻辑前，必须使用 await nextTick()。
- React 环境中严禁在 setState 后立即读取状态或 DOM，必须使用 useEffect 监听状态变化。
- 避免在 useEffect 中产生未清理的异步副作用，必须返回清理函数。
- 生成按钮点击事件时默认包含 loading 状态控制或按钮禁用逻辑，直到请求完成。
- 每次生成涉及数据交互的代码后，必须在注释中简要说明使用了哪种机制来保证状态同步。
