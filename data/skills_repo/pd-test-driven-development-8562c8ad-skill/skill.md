# test-driven-development

Use when implementing any feature or bugfix, before writing implementation code。由 1 份素材蒸馏生成

## 触发条件
- `test`
- `driven`
- `development`

## 步骤清单
### 步骤 1: （纯指令）
- New features

### 步骤 2: （纯指令）
- Bug fixes

### 步骤 3: （纯指令）
- Refactoring

### 步骤 4: （纯指令）
- Behavior changes

### 步骤 5: （纯指令）
- Throwaway prototypes

### 步骤 6: （纯指令）
- Generated code

### 步骤 7: （纯指令）
- Configuration files

### 步骤 8: （纯指令）
- Don't keep it as "reference"

### 步骤 9: （纯指令）
- Don't "adapt" it while writing tests

### 步骤 10: （纯指令）
- Don't look at it

### 步骤 11: （纯指令）
- Delete means delete

### 步骤 12: （纯指令）
- One behavior

### 步骤 13: （纯指令）
- Clear name

### 步骤 14: （纯指令）
- Real code (no mocks unless unavoidable)

### 步骤 15: （纯指令）
- Test fails (not errors)

### 步骤 16: （纯指令）
- Failure message is expected

### 步骤 17: （纯指令）
- Fails because feature missing (not typos)

### 步骤 18: （纯指令）
- Test passes

### 步骤 19: （纯指令）
- Other tests still pass

### 步骤 20: （纯指令）
- Output pristine (no errors, warnings)

### 步骤 21: （纯指令）
- Remove duplication

### 步骤 22: （纯指令）
- Improve names

### 步骤 23: （纯指令）
- Extract helpers

### 步骤 24: （纯指令）
- Might test wrong thing

### 步骤 25: （纯指令）
- Might test implementation, not behavior

### 步骤 26: （纯指令）
- Might miss edge cases you forgot

### 步骤 27: （纯指令）
- You never saw it catch the bug

### 步骤 28: （纯指令）
- No record of what you tested

### 步骤 29: （纯指令）
- Can't re-run when code changes

### 步骤 30: （纯指令）
- Easy to forget cases under pressure
