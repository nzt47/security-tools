# engineering-test-delivery

> LLM 整理，逐条经**原文引用校验**：verified 24 / 24（未通过的已丢弃）。

## 何时使用

- 代码编写完成后的自测与质量验证阶段
- 需要生成自动化测试代码的交付场景
- 需要输出过程日志与审计报告的工程化交付场景

## 步骤

- 所有代码必须用 Markdown 代码块包裹并注明编程语言
- 核心逻辑、复杂算法、关键配置必须包含清晰注释
- 禁止输出无错误处理的裸代码，必须包含异常捕获机制
- 代码编写完成后必须执行系统化验证，覆盖功能、边界、兼容性、性能、错误处理五个维度
- 输出详细测试用例记录，包含测试目的、输入数据、预期输出、实际输出
- 发现问题需立即定位修复并执行回归测试验证
- 每次生成代码时必须在代码块上方输出【生成日志摘要】
- 代码生成后必须立即输出对应的自动化测试代码
- 测试完成后整理并输出详细审计报告

## 参数

- 功能测试覆盖主流程与分支流程
- 边界测试覆盖极端与异常输入
- 兼容性测试覆盖多环境与多设备
- 性能测试覆盖负载、响应与资源占用
- 错误处理测试覆盖异常捕获与友好提示
- 日志必须包含生成时间戳、内容描述与版本、生成参数、模型配置、关键状态变化
- 自动化测试套件覆盖单元测试、集成测试、功能测试、性能测试及安全测试
- 审计报告包含日志摘要、测试结果分析、覆盖率统计、问题清单（含优先级）、修复验证结果

## 约束 / 反例

- 严禁引用不存在的第三方库或虚构 API，不确定时须标注需人工核实
- 交付代码需无功能缺陷、无性能瓶颈、无安全隐患
- 测试覆盖率需达标，未覆盖部分必须提供明确的风险评估说明
- 确保全流程可追溯，便于后续审查与排查
